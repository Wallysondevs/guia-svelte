Svelte · use: (actions)

A padaria da Ana tem três lugares em que a tela precisa de um empurrãozinho que nada tem a ver com dado novo: o campo do troco tem de abrir com o cursor já dentro, o preço tem de aparecer com vírgula e o painel de encomendas tem de fechar quando ela clica fora dele. Ela já sabe resolver cada um com bind:this e $effect, mas o código é sempre o mesmo — e copiar o mesmo bloco na quarta tela é receita de esquecimento. O Svelte guarda esse tipo de comportamento num lugar só, colado no próprio elemento: a action, que se escreve com use:.

Você vai aprender
  • O que é uma action e por que ela recebe o elemento.
  • A escrever a primeira: function marcar(node) e <p use:marcar>.
  • O segundo argumento e o objeto com update.
  • A função de limpeza devolvida no fim da action.
  • Quando cada pedaço roda: ao montar, ao mudar o parâmetro, ao sair do DOM.
  • Por que a action não roda no servidor e o que isso muda na saída.
  • Guardar as actions num .js e importar em várias telas.
  • Os três erros reais do compilador que aparecem com use:.
  • use:, onclick e {@attach} lado a lado.

1. Um comportamento colado no elemento

Até aqui, quase tudo o que a Ana fez foi sobre dado: o total da compra, a lista de pães, o nome do cliente. O template mostra o dado e o Svelte mantém a tela em dia. Só que algumas coisas não são dado nenhum. Dar foco a um campo, medir a largura de uma barra, ouvir o clique na página inteira para fechar um painel: isso é conversa direta com o DOM, e o DOM só existe no navegador, depois que o elemento foi criado.

O jeito sem action é guardar o elemento numa variável e mexer nele num $effect:

<script>
  let campo = $state();

  $effect(() => {
    campo?.focus();
  });
</script>

<input bind:this={campo} />

Funciona. E funciona tão bem que você vai repetir esse bloco em cada componente que tiver um campo de troco — e no dia em que precisar de um segundo detalhe (selecionar o texto todo ao focar, por exemplo) vai corrigir em um lugar e esquecer dos outros. Pior: o bind:this exige a variável, o ?. exige o guarda, e o $effect roda de novo quando qualquer coisa lida dentro dele mudar. Para um comportamento fixo, é cerimônia demais.

A action junta as três peças numa função só. Você escreve a função, pendura o nome dela no elemento com use: e pronto: o Svelte entrega o elemento para a sua função no momento em que ele entra na tela, e chama a sua função de limpeza quando ele sai. Nada de variável intermediária, nada de $effect.

O que a Ana precisaComo fica com action
O cursor já dentro do campo do troco<input use:focar />
O preço escrito com vírgula<p use:moeda={preco}></p>
O painel que fecha ao clicar fora<div use:fora={fechar}>
A barra que se ajusta à largura da janela<div use:largura>
Um atalho de teclado só enquanto a caixa está aberta<section use:atalho={'s'}>
O elemento que rola sozinho para o fim<ul use:fim>

Repare no padrão: o nome depois de use: é o nome de uma função que você escreveu (ou importou). Não é uma palavra reservada do Svelte, como transition: ou bind:. use:marcar só funciona porque existe uma função chamada marcar no arquivo.

Action não é componente

Uma action não desenha nada, não tem template e não recebe props. Ela é uma função com dois argumentos: o elemento e, opcionalmente, um parâmetro seu. Se você precisa de marcação nova, é componente; se precisa de comportamento num elemento que já existe, é action.

2. A anatomia de uma action

O menor programa desta aula tem uma função que recebe um elemento e escreve nele. O parâmetro opcional chega no segundo argumento:

<script>
  function graus(node, inicial) {
    node.textContent = inicial + ' graus';
    return {
      update(valor) {
        node.textContent = valor + ' graus';
      }
    };
  }
  let temperatura = $state(10);
</script>

<p use:graus={temperatura}></p>
<button onclick={() => temperatura = 20}>esquentar</button>
<p></p> <button>esquentar</button>

O parágrafo sai vazio do servidor, e isso não é bug: quem escreve o texto é a action, e action só roda no navegador. No navegador, o mesmo componente mostra 10 graus esquentar na hora em que aparece, e depois do clique mostra 20 graus esquentar. Guarde essa saída vazia; ela volta no item 7 com nome e sobrenome.

function graus(node, inicial)
a action. node é o elemento de verdade, já dentro da página; inicial é o que veio depois do =. Os dois nomes são escolha sua.
use:graus={temperatura}
a diretiva. O nome depois dos dois-pontos tem de ser o da função; o valor entre chaves é o parâmetro, recalculado a cada mudança de temperatura.
return { update(valor) { … } }
o contrato de atualização. Toda vez que o parâmetro mudar, o Svelte chama update com o valor novo.
node.textContent = …
o trabalho em si. Aqui é texto; poderia ser atributo, classe, escuta de evento, medição — qualquer coisa que se faça com um elemento.

O segundo argumento é opcional de verdade: sem o =, ele chega como undefined e a função continua válida. É por isso que muitas actions se contentam com function focar(node) e mais nada.

3. O nó é o elemento de verdade

O primeiro argumento não é uma cópia, não é um objeto do Svelte e não é um componente: é o elemento do DOM, o mesmo que apareceria no inspetor do navegador. Tudo o que você faria com document.querySelector você faz com ele: node.focus(), node.title = 'pronto', node.classList.add('ativo'), node.getBoundingClientRect().width, node.addEventListener('keydown', …).

Isso também quer dizer que a action pode brigar com o template. Se ela escreve em node.textContent e o template também desenha texto dentro do elemento, o Svelte não fica sabendo da escrita e pode sobrescrevê-la no próximo ciclo. A regra prática: use action para o que o template não faz — atributos, foco, medidas, escutas, formatação de um valor que veio por parâmetro.

E há outra consequência: a action roda uma vez por elemento. Num {#each} com dez itens, dez execuções, cada uma com o seu node. Com {#if}, a action roda de novo a cada vez que o bloco volta a aparecer — o elemento é outro.

Missão: o contador de montagens travou em 1. A action está pendurada no cabeçalho, que nunca sai da tela. Mova o use:avisar para o parágrafo que entra e sai pelo {#if}, e dois cliques em "abrir/fechar" devem levar o contador a 2.

<script>

  let montagens = $state(0);
  function avisar(node) {
    montagens += 1;

</script>

<p use:avisar>cabecalho fixo</p>

O contador não é enfeite: ele mostra a diferença entre "a action roda quando o parâmetro muda" e "a action roda quando o elemento nasce". Neste caso o parâmetro nem existe, então só a montagem conta.

4. O segundo argumento vira update

Quando o parâmetro muda, o Svelte não chama a sua função de novo: chama o update que ela devolveu. É por isso que a action do item 2 tem dois caminhos para escrever no parágrafo — o do começo, para o primeiro valor, e o do update, para os seguintes. Se você esquecer o update, o primeiro valor fica congelado na tela.

Missão: o parágrafo mostra 10 graus e não acompanha o botão. Faça a action receber o valor inicial e devolver um update que reescreva o texto, para o clique em "esquentar" mostrar 20 graus.

<script>
  function graus(node) {
    node.textContent = '10 graus';
  }
  let temperatura = $state(10);
</script>

<p use:graus></p>
<button onclick={() => temperatura = 20}>esquentar</button>

  function graus(node, inicial) {
    node.textContent = inicial + ' graus';
    return {
      update(valor) {
        node.textContent = valor + ' graus';
      }
    };
  }

<p use:graus={temperatura}></p>
<button onclick={() => temperatura = 20}>esquentar</button>
update(valor)
chamado quando a expressão do parâmetro muda. Recebe o valor novo; o elemento continua o mesmo, então não recrie escutas aqui.
destroy()
a outra chave do objeto: roda quando o elemento sai do DOM. É equivalente a devolver uma função solta, e o Svelte 5 aceita as duas formas.
return () => { … }
a forma curta, que só serve para limpar. Use quando não há update.
use:graus
sem =, o parâmetro é undefined e o update nunca é chamado: nada muda para ele.

Um detalhe que morde: o parâmetro é reativo, mas a expressão é avaliada no componente. Se você escrever use:graus={temperatura + 1}, o update recebe o resultado já somado — a action não tem como saber de onde veio. E se escrever um objeto literal, use:moeda={{ valor: preco }}, cada recálculo cria um objeto novo e o update roda de novo; é o comportamento esperado, mas vale lembrar quando a action faz trabalho pesado.

5. A função que a action devolve

Toda action que abre alguma coisa para fora do elemento precisa fechar essa coisa quando o elemento sai. Escuta em document, setInterval, ResizeObserver, IntersectionObserver: nada disso morre sozinho quando o elemento é removido. O Svelte resolve isso com o retorno da função:

export function fora(node, aoSair) {
  const ouvir = (evento) => {
    if (!node.contains(evento.target)) aoSair();
  };
  document.addEventListener('click', ouvir);
  return () => document.removeEventListener('click', ouvir);
}

Essa é a action que fecha o painel de encomendas da Ana. Ela guarda a função da escuta numa constante justamente para poder remover exatamente a mesma função depois — removeEventListener exige a mesma referência, e uma arrow function escrita duas vezes não serve. O padrão é sempre esse: cria, guarda, devolve o desfazer.

No projeto da padaria, as duas pontas ficam a duas linhas de distância:

ana@notebook:~/loja$ grep -rn "addEventListener" src
src/lib/acoes.js:14:  document.addEventListener('click', ouvir);
ana@notebook:~/loja$ grep -rn "return () =>" src
src/lib/acoes.js:15:  return () => document.removeEventListener('click', ouvir);

A linha 14 abre, a linha 15 fecha. Quem esquece a segunda descobre o problema do jeito chato: abre e fecha o painel três vezes, e o clique fora passa a disparar três vezes. O sintoma não é erro no console, é comportamento duplicado — por isso a limpeza é a parte da action que mais merece revisão.

Nem tudo precisa de limpeza

Mudar textContent, um atributo ou uma classe não deixa nada pendurado: quando o elemento sai, aquilo vai junto. Limpeza é para o que você registrou fora do elemento — escutas em window e document, timers, observers, bibliotecas que criaram instâncias próprias.

6. Quando cada pedaço roda

A action tem três momentos, e confundir um com o outro é a origem de quase todo bug de use::

MomentoO que rodaO que costuma ser feito ali
O elemento entra no DOMa função da actionfocar, medir, criar escuta, iniciar timer
O parâmetro mudaupdate(valorNovo)reescrever texto, trocar atributo, recalcular
O elemento sai do DOMdestroy() ou a função devolvidaremover escuta, parar timer, desconectar observer
O componente é renderizado no servidornada—

Repare no que não está na tabela: não existe "a action roda quando um estado qualquer muda". Ela não é um $effect. Se a sua action lê três variáveis e você quer que ela reaja a todas, passe as três como parâmetro — ou escreva um $effect, que é a ferramenta certa para isso.

Missão: o botão muda a cor, mas o parágrafo continua verde e a contagem fica em 1. Acrescente um update na action para que o clique em "azul" mostre azul (2) e o contador chegue a 2.

<script>
  let cor = $state('verde');
  let rodadas = $state(0);
  function pintar(node, valor) {
    rodadas += 1;
    node.textContent = valor + ' (' + rodadas + ')';
  }
</script>

<button onclick={() => cor = 'azul'}>azul</button>
<p use:pintar={cor}></p>
<p>rodadas: {rodadas}</p>
<script>
  let cor = $state('verde');
  let rodadas = $state(0);
  function pintar(node, valor) {
    rodadas += 1;
    node.textContent = valor + ' (' + rodadas + ')';
    return {
      update(novo) {
        rodadas += 1;
        node.textContent = novo + ' (' + rodadas + ')';
      }
    };
  }
</script>

<button onclick={() => cor = 'azul'}>azul</button>
<p use:pintar={cor}></p>
<p>rodadas: {rodadas}</p>

O contador rodadas é o que prova a diferença: com a action sem update, o número fica parado enquanto a cor do estado muda. É a assinatura do problema — o estado andou, o DOM não.

7. No servidor, nada acontece

Agora a saída vazia do item 2 faz sentido. Quando o componente é renderizado no servidor, não existe DOM, não existe elemento para entregar à action e, portanto, a função nunca é chamada. O HTML sai com a marcação do template e nada mais:

<script>
  function marcar(node) {
    node.title = 'pronto';
    node.textContent = node.textContent.toUpperCase();
  }
</script>

<p use:marcar>pão quentinho</p>
<p>pão quentinho</p>

Sem title, sem maiúsculas. No navegador, o mesmo arquivo produz outra coisa: o parágrafo vira <p title="pronto">PÃO QUENTINHO</p>, porque aí o elemento existe e a action rodou. As duas saídas estão certas; elas descrevem momentos diferentes.

Isso não é limitação, é a divisão de trabalho do Svelte: o servidor entrega HTML, o navegador entrega comportamento. Também explica por que um teste de página que só olha o HTML do servidor não vê o efeito de nenhuma action — e por que o guia usa caixas interativas quando o assunto é use:, como nas três desta aula.

Se você precisa que o conteúdo exista sem JavaScript (buscadores, impressão, e-mail), ele tem de vir do template ou dos dados, nunca da action. Action é camada de cima: foco, medida, escuta, enfeite.

8. Onde guardar as actions

Action é função comum, então mora em arquivo comum. No projeto da Ana, as duas actions do dia a dia ficam em src/lib/acoes.js e são importadas pelas telas que precisam delas:

export function graus(node, inicial) {
  node.textContent = inicial + ' graus';
  return {
    update(valor) {
      node.textContent = valor + ' graus';
    }
  };
}

export function fora(node, aoSair) {
  const ouvir = (evento) => {
    if (!node.contains(evento.target)) aoSair();
  };
  document.addEventListener('click', ouvir);
  return () => document.removeEventListener('click', ouvir);
}

Do outro lado, cada componente importa o que usa e pendura no elemento. Duas telas, a mesma action, nenhuma linha repetida:

9. Quando dá errado

As três mensagens abaixo são do compilador desta versão, copiadas da execução. Todas aparecem antes de a página abrir.

Erro 1 — use: num componente

Diretiva de action vale para elementos do DOM, não para componentes. Um componente pode desenhar dez elementos, e o Svelte não saberia qual receber:

<script>
  import Cartao from './Cartao.svelte';
  function focar(node) {
    node.focus();
  }
</script>

<Cartao use:focar />
Erro de compilação (linha 8, coluna 8): This type of directive is not valid on components

"Este tipo de diretiva não é válido em componentes." A correção é levar a action para dentro do componente, no elemento que deve receber o comportamento — ou envolver o componente num elemento e pendurar a action nele.

Erro 2 — espaço entre use: e o nome

Um espaço parece inofensivo, mas encerra a diretiva antes de ela ter nome:

<script>
  function grudar(node) {
    node.title = 'pronto';
  }
</script>

<p use: grudar>pão quentinho</p>
Erro de compilação (linha 7, coluna 3): `use:` name cannot be empty

"O nome de use: não pode ficar vazio." O compilador leu use: sem nome e parou ali. Tire o espaço: use:grudar.

Erro 3 — action no <svelte:head>

Os elementos especiais do Svelte aceitam só o que faz sentido para eles. O <svelte:head> recebe os elementos que vão para o <head> e não aceita diretiva nenhuma:

<script>
  function focar(node) {
    node.focus();
  }
</script>

<svelte:head use:focar>
  <title>Padaria da Ana</title>
</svelte:head>
<p>pão quentinho</p>
Erro de compilação (linha 7, coluna 13): `<svelte:head>` cannot have attributes nor directives

"<svelte:head> não pode ter atributos nem diretivas." Elementos especiais desse tipo servem para dizer onde o conteúdo vai, não para receber comportamento. A action vai no elemento comum que precisa dela.

10. use:, onclick e {@attach}

As três ferramentas parecem parentes, e a escolha entre elas é mais simples do que o nome sugere:

FerramentaServe paraExemplo
onclick, oninputreagir a um evento do próprio elemento<button onclick={somar}>
bind:this + $effectmexer no elemento porque um estado mudou$effect(() => barra.style.width = pct)
use:acaoinstalar um comportamento no elemento, com parâmetro e limpeza<input use:focar>
{@attach fn}a versão moderna: a própria expressão devolve a função<input {@attach focar}>

{@attach} é o assunto da próxima aula e resolve o mesmo problema por outro caminho: em vez de um nome de função que o Svelte procura no arquivo, você escreve uma expressão que devolve a função de comportamento. Ganha-se poder (dá para passar argumentos com clareza e usar dentro de snippets) e perde-se a forma curta de use:. Para o que a Ana faz — um comportamento fixo, reaproveitado em várias telas — use: continua sendo o caminho mais curto.

11. Antes de escrever a sua

Um punhado de decisões evita a maior parte dos problemas:

  • Um trabalho por action. fora fecha ao clicar fora; graus escreve a temperatura. Quando o nome precisa de "e", são duas actions.
  • Passe o que a action precisa como parâmetro. Ela não enxerga as variáveis do componente; se precisa do valor, recebe pelo segundo argumento.
  • Devolva a limpeza sempre que abrir algo fora do elemento. Escuta, timer e observer sem desfazer são vazamento — e comportamento duplicado.
  • Não escreva onde o template escreve. Se o texto vem do template, deixe-o lá; use a action para atributos, foco e medidas.
  • Não conte com a action no servidor. O que precisa existir sem JavaScript tem de vir dos dados.
  • Mantenha o teclado funcionando. Uma action que torna um <div> clicável precisa também tratar keydown e tabindex; o contrário disso é uma armadilha de acessibilidade.
  • Prefira o simples quando basta. Se o comportamento é só reagir a um clique, onclick na veia, sem action nenhuma.
O teste do "e se eu apagar"

Apague o use: do elemento e veja o que quebra. Se nada quebrar, a action não está fazendo nada e pode sair. Se quebrar só a conveniência (o cursor não aparece no campo), está no tamanho certo.

Resumo

  • use:acao instala um comportamento num elemento do DOM; a ação é uma função que você escreve ou importa.
  • A função recebe (node, parametro): o elemento de verdade e o valor que veio depois do =.
  • Se a função devolver um objeto com update(valor), ele roda a cada mudança do parâmetro; destroy() roda quando o elemento sai.
  • Devolver uma função solta é a forma curta de limpeza — equivalente a destroy.
  • A action roda uma vez por elemento: dez itens num {#each} são dez execuções.
  • Action não é $effect: ela não reage a estado que não chegue por parâmetro.
  • No servidor não há DOM e a action não roda: o HTML sai só com o template.
  • Escuta em document, timer e observer precisam de limpeza; texto, atributo e classe não.
  • Os erros desta aula: diretiva em componente, espaço depois de use: e diretiva em <svelte:head>.
  • Para comportamento ligado a evento simples, onclick basta; para a versão moderna com expressão, {@attach}.
