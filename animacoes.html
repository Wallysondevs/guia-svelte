Svelte · Animações

A Ana pendura os cartazes de preço numa ordem: pão, bolo, café. Quando o pão entra em promoção, o cartaz dele vai para o começo da fila — e ela não descola e recoloca: ela desliza o cartaz pela parede, um lugar de cada vez. Na tela, a mesma coisa: quando a ordem de uma lista muda, os itens podem deslizar até a posição nova em vez de desaparecer e reaparecer. O Svelte faz isso com uma diretiva só, animate:, e ela tem três exigências que o compilador cobra sem piedade.

1. A ideia: o cartaz que desliza

Uma transição cuida de um elemento que entra ou sai. Uma animação cuida de um elemento que muda de lugar sem sair: o item que era o segundo vira o primeiro, o que era o último sobe três posições. Sem animação, a lista pisca: os itens trocam de posição de um quadro para o outro e o olho perde o fio.

Com animação, o Svelte mede onde cada item estava antes da mudança, aplica a mudança e depois leva cada item da posição antiga para a nova, em alguns milissegundos. O conteúdo não é recriado; o elemento é o mesmo, só deslocado. É por isso que a chave no {#each} é obrigatória: sem ela, o Svelte não sabe qual elemento é qual e não tem como medir nada.

Essa é a diferença que mais confunde. Transição é sobre existir e deixar de existir. Animação é sobre estar em outro lugar. Você pode ter as duas na mesma lista: um item novo entra com transition:fade e os antigos deslizam com animate:flip.

No servidor, nenhuma das duas roda. O HTML sai na ordem final, e a animação é um efeito que só quem vê a página no navegador aproveita — o mesmo princípio das transições.

3. animate:flip: a lista que muda de ordem

O caso mais comum é reordenar. O flip existe justamente para isso — o nome vem de "first, last, invert, play": mede a posição inicial, mede a final, inverte o deslocamento e anima até zero.

<script>
  import { flip } from 'svelte/animate';

  let itens = $state([{ id: 1, n: 'Pão' }, { id: 2, n: 'Bolo' }]);
</script>

<ul>
  {#each itens as it (it.id)}
    <li animate:flip={{ duration: 250 }}>{it.n}</li>
  {/each}
</ul>
<button onclick={() => itens = itens.slice().reverse()}>inverter</button>
<ul><li>Pão</li><li>Bolo</li></ul> <button>inverter</button>

4. As três condições para animate: funcionar

O compilador é rígido com animate: porque a animação depende de saber exatamente qual elemento se moveu. Três condições, todas verificadas na compilação:

1. O elemento tem de estar dentro de um {#each} com chave. Sem chave, cada item é identificado pela posição, e posição é justamente o que muda. O compilador recusa a lista e pede a chave na mensagem.

2. O elemento com animate: tem de ser o filho direto do bloco. Nada de um {#if} no meio, nem de um <span> dentro de um <li>: a diretiva vai no elemento que o {#each} cria.

3. Tem de ser um elemento do DOM, não um componente. Um componente pode desenhar dez elementos; o Svelte não teria como medir "o componente". Se precisar animar um componente, envolva-o num elemento e ponha a diretiva no elemento.

Missão: a diretiva está dentro de um {#if}, e o compilador recusa. Coloque a diretiva no <li>, que é o filho direto do bloco, e o clique deve inverter para b a.

<script>
  import { flip } from 'svelte/animate';

  let itens = $state([{ id: 1, n: 'a' }, { id: 2, n: 'b' }]);
</script>

<ul>
  {#each itens as it (it.id)}
    {#if it.n}
      <li animate:flip={{ duration: 300 }}>{it.n}</li>
    {/if}
  {/each}
</ul>
<button onclick={() => itens = itens.slice().reverse()}>inverter</button>

Repare que a solução não mudou de ideia sobre o conteúdo: o {#if} saiu porque ele não fazia nada além de atrapalhar. Quando a condição é real — mostrar só os itens ativos, por exemplo — o caminho é filtrar a lista antes do {#each}, e não esconder itens dentro dele.

5. Uma animação escrita à mão

Assim como a transição, a animação é uma função. Ela recebe o elemento e um objeto com from e to — as posições medidas antes e depois da mudança — e devolve duration e css:

<script>
  function meuFlip(node, { from, to }) {
    const dy = from.top - to.top;
    return { duration: 300, css: (t) => `transform: translateY(${dy * (1 - t)}px)` };
  }
  let itens = $state([{ id: 1, n: 'a' }, { id: 2, n: 'b' }]);
</script>

<ul>
  {#each itens as it (it.id)}
    <li animate:meuFlip>{it.n}</li>
  {/each}
</ul>
<button onclick={() => itens = itens.slice().reverse()}>inverter</button>
<ul><li>a</li><li>b</li></ul> <button>inverter</button>
from
um retângulo com top, left, width e height medidos antes da mudança.
to
o mesmo retângulo medido depois. A diferença entre os dois é o deslocamento que você precisa desfazer.
dy
from.top - to.top: a diferença vertical entre as duas posições. Positivo quer dizer que o elemento estava mais abaixo e subiu; negativo, que estava mais acima e desceu.
css: (t) => …
roda a cada quadro com t de 0 a 1. Em t = 0 o estilo desfaz o deslocamento; em t = 1, o elemento está no lugar final.

É esse truque que dá a sensação de movimento: o Svelte reposiciona o elemento no lugar novo e, no mesmo instante, aplica um transform que o empurra de volta para onde ele estava. A animação, então, vai levando esse transform a zero. O elemento nunca "pula": ele começa deslocado e termina exato.

Numa lista vertical, o deslocamento que importa é o vertical — from.top - to.top. Medindo de verdade numa lista de dois itens de 24 pixels, o valor dá -24 para o item que desceu e +24 para o que subiu. Usar left numa lista vertical dá zero, e a animação não aparece: o item só reaparece no lugar novo. É um erro silencioso, do tipo que a gente demora a achar.

Missão: o elemento tem duas diretivas animate: e o compilador recusa. Deixe só o flip e o clique deve inverter a lista para b a.

<script>
  import { flip } from 'svelte/animate';

  function meuVira(node, { from, to }) {
    return { duration: 200, css: (t) => `opacity: ${t}` };
  }

  let itens = $state([{ id: 1, n: 'a' }, { id: 2, n: 'b' }]);
</script>

<ul>
  {#each itens as it (it.id)}
    <li animate:flip={{ duration: 300 }} animate:meuVira>{it.n}</li>
  {/each}
</ul>
<button onclick={() => itens = itens.slice().reverse()}>inverter</button>
<script>

  let itens = $state([{ id: 1, n: 'a' }, { id: 2, n: 'b' }]);

Se você quiser dois efeitos ao mesmo tempo — deslizar e aparecer —, o caminho é somar os estilos dentro do mesmo css, e não empilhar diretivas. Duas diretivas no mesmo elemento não somam: uma delas é escolhida e a outra é recusada.

6. flip com parâmetros

O flip de fábrica aceita os mesmos parâmetros de uma transição: duration, delay e easing. Também aceita uma função key própria, para quando o elemento não muda de posição mas você quer animar mesmo assim.

<script>
  import { flip } from 'svelte/animate';

  let { itens } = $props();
</script>

<ul>
  {#each itens as item (item)}
    <li animate:flip={{ duration: 250 }}>{item}</li>
  {/each}
</ul>

Nesse componente a chave é o próprio texto do item — funciona porque a lista da Ana não tem dois itens iguais. Quando houver repetição, use uma chave única de verdade, como um id: texto repetido faz o Svelte confundir dois elementos diferentes.

ParâmetroPara que serve
durationtempo da animação, em milissegundos (padrão 300)
delayespera antes de começar
easingcurva de velocidade, de svelte/easing
keyfunção que devolve um identificador por item, para listas sem chave natural

7. Quando dá errado

As três mensagens abaixo são do compilador desta versão, copiadas da execução. Todas acontecem antes de a página abrir, o que é uma boa notícia: o erro de animação nunca chega ao leitor.

Erro 1 — lista sem chave

O caso mais comum, e o único em que a mensagem traz a dica completa:

<script>
  import { flip } from 'svelte/animate';

  let itens = $state([{ id: 1, n: 'a' }, { id: 2, n: 'b' }]);
</script>

<ul>
  {#each itens as it}
    <li animate:flip>{it.n}</li>
  {/each}
</ul>
Erro de compilação (linha 9, coluna 8): An element that uses the `animate:` directive must be the only child of a keyed `{#each ...}` block. Did you forget to add a key to your each block?

"Um elemento que usa a diretiva animate: precisa ser o único filho de um bloco {#each ...} com chave. Você esqueceu de pôr a chave no seu bloco each?" A tradução é literal: falta o (it.id).

Erro 2 — duas animações no mesmo elemento

A diretiva aparece uma vez, porque ela anima o deslocamento do elemento. Duas não somam: a segunda é recusada:

<script>
  import { flip } from 'svelte/animate';
  function outro(node, { from, to }) {
    return { duration: 200, css: (t) => `opacity: ${t}` };
  }
  let itens = $state([{ id: 1, n: 'a' }]);
</script>

<ul>
  {#each itens as it (it.id)}
    <li animate:flip animate:outro>{it.n}</li>
  {/each}
</ul>
Erro de compilação (linha 11, coluna 21): An element can only have one 'animate' directive

"Um elemento só pode ter uma diretiva 'animate'." Para combinar deslocamento e opacidade, escreva uma função só, que devolva os dois estilos no mesmo css.

Erro 3 — animate: num componente

Diretiva de animação vale para elementos do DOM. Componentes não têm retângulo único para medir:

<script>
  import { flip } from 'svelte/animate';
  import Cartao from './Cartao.svelte';

  let itens = $state([{ id: 1, n: 'a' }]);
</script>

<ul>
  {#each itens as it (it.id)}
    <Cartao animate:flip n={it.n} />
  {/each}
</ul>
Erro de compilação (linha 10, coluna 12): This type of directive is not valid on components

"Este tipo de diretiva não é válido em componentes." A correção é envolver: <li animate:flip><Cartao n={it.n} /></li>. Aí quem anima é o li, que tem posição própria.

Uma lista pode usar as duas primeiras ao mesmo tempo: o item novo entra com transition: e os que já estavam deslizam com animate:. É a combinação que dá a sensação de lista "viva" sem exagero.

9. Quando animar uma lista — e quando não

Animação é açúcar, e açúcar em excesso empacha. Três perguntas resolvem a decisão:

A lista muda de ordem com frequência? Se sim, animar ajuda: o leitor acompanha o que se moveu. Se a ordem é fixa e só o conteúdo muda, não há o que animar.

Quantos itens se movem? Animar dois ou três itens é barato. Animar cinquenta é caro: cada elemento ganha um transform recalculado a cada quadro. Em listas longas, anime só o que mudou de posição ou não anime.

O movimento diz alguma coisa? Uma animação que só enfeita cansa depois da terceira vez. Uma que explica — "este item subiu porque ficou mais importante" — continua útil na centésima.

A chave é o contrato com o leitor

Chave errada estraga a animação de um jeito difícil de diagnosticar: os elementos animam com o texto trocado, ou pulam de posição sem deslizar. Se a lista tem identificadores, use-os. Se não tem, crie um ao montar a lista — um contador que não se repete resolve.

    11. O que a caixa verifica e o que ela não verifica

    Vale ser honesto sobre o limite das caixas desta aula. A verificação confere três coisas na solução: que o componente compila, que a lista aparece na ordem certa e que o clique inverte a ordem. O que ela não confere é o movimento em si — a animação é visual e acontece nos 300 milissegundos entre um quadro e outro.

    Isso não é uma limitação do guia, é da natureza do teste: verificar animação de verdade exige comparar quadros, e isso é trabalho de ferramenta de captura de tela, não de asserção de texto. Por isso as missões atacam o que dá para provar — a chave, o filho direto, a diretiva única —, que é justamente onde as pessoas erram.

    Na prática, o seu teste de animação é o olho: rode o projeto, inverta a lista, veja se o item desliza. Se ele piscar em vez de deslizar, o problema está numa das três condições da seção 4.
