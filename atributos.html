Svelte · Atributos Dinâmicos

Na padaria da Ana, cada caixa tem uma etiqueta: "pão francês", "500 g", "validade 12/03". A etiqueta não é o pão, mas sem ela ninguém sabe o que tem dentro. No HTML, o atributo é essa etiqueta: fica dentro da tag, ao lado do nome do elemento, e diz algo sobre ele. A diferença é que a etiqueta da Ana é escrita à mão uma vez, e a do componente pode vir de um valor que muda. Nesta aula você aprende a colocar valor de estado dentro de atributo — e o que o Svelte faz quando esse valor é falso ou não existe.

Você vai aprender
  • A diferença entre atributo com valor fixo e atributo com expressão.
  • Quando as aspas são obrigatórias e quando podem sair.
  • O que são atributos booleanos e por que disabled não tem valor.
  • O que acontece quando o valor é false, null ou undefined.
  • Por que checked="false" marca a caixa em vez de desmarcar.
  • class e style como texto, e a armadilha do objeto no style.
  • Como espalhar vários atributos de uma vez com {...props}.
  • Por que eventos como onclick não são atributos comuns.
  • O aviso de acessibilidade do <img> sem alt.
  • Os três casos desta aula que compilam e mesmo assim estão errados.

1. A ideia: a etiqueta na caixa

Um elemento HTML tem três partes: o nome, os atributos e o conteúdo. Em <a href="/cardapio">cardápio</a>, o nome é a, o atributo é href com valor /cardapio, e o conteúdo é o texto "cardápio". O atributo nunca aparece na tela: ele instrui o navegador. O conteúdo é o que o cliente lê.

Essa separação confunde no começo, porque os dois parecem "coisas escritas na tag". Mas o atributo tem função: href diz para onde o link leva, src diz qual imagem carregar, disabled diz que o botão não pode ser clicado. Se você apagar o valor do atributo, o comportamento muda; se apagar o conteúdo, o texto some mas o comportamento fica.

Até aqui, nada de novo em relação ao HTML que existe desde os anos 1990. A novidade do Svelte é poder escrever um valor de estado no lugar do valor fixo, e o compilador cuidar da atualização. Quando o estado muda, o atributo muda — e você não escreve setAttribute em lugar nenhum.

2. Valor fixo × valor de estado

Um atributo com valor fixo usa aspas e texto. Um atributo ligado ao estado usa chaves e uma expressão. Os dois podem conviver na mesma tag, e a diferença é só o sinal:

<script>
  let ativo = $state(true);
  let preco = $state(0.9);
  let id = $state('pao');
</script>

<button disabled={ativo}>comprar</button>
<button disabled={!ativo}>pagar</button>
<p data-preco={preco} id="preco-{id}">R$ {preco.toFixed(2)}</p>
<input tabindex={0} value={preco} />
<button disabled="">comprar</button> <button>pagar</button> <p data-preco="0.9" id="preco-pao">R$ 0.90</p> <input tabindex="0" value="0.9"/>

Quatro coisas para observar. Primeiro: o botão com disabled={ativo} saiu com disabled="" — atributo presente, valor vazio. Segundo: o segundo botão, com disabled={!ativo}, saiu sem o atributo nenhum. Terceiro: data-preco recebeu o número como texto, e o id misturou texto fixo com valor entre chaves. Quarto: tabindex={0} virou tabindex="0", porque no HTML todo atributo é texto.

disabled
o nome do atributo. Tem de existir no elemento: disabled vale em button, input e select, e não vale em div.
=
o sinal que liga o nome ao valor. Em HTML, atributo sem valor é permitido; em Svelte, você sempre liga a uma expressão.
{ }
as chaves dizem que o valor vem do JavaScript. Sem elas, o compilador entende texto literal.
!ativo
a expressão. Pode ser uma variável, uma negação, uma comparação ou uma chamada de função.

Essa última parte é a chave para entender o resto: o HTML não tem tipos. 0.9 e "0.9" chegam iguais ao navegador. Quem dá sentido ao valor é o elemento: para input, o navegador interpreta value como texto; para disabled, interpreta a presença do atributo como "desabilitado", independentemente do valor.

3. Aspas: quando são obrigatórias

Se o valor do atributo é só uma expressão, as aspas podem sair: disabled={ativo} é a forma preferida. Se o valor mistura texto e expressão, as aspas são obrigatórias: id="preco-{id}". Escrever id=preco-{id} sem aspas quebra o arquivo, com uma mensagem comprida que explica a regra.

A regra é fácil de lembrar: chaves sozinhas dispensam aspas; chaves no meio de texto pedem aspas. O compilador não tem como saber onde termina o texto e começa o valor quando não há aspas, então ele recusa em vez de adivinhar.

Dentro das aspas, o texto é texto: acentos, espaços e pontuação valem como estão. O valor da expressão é escapado na hora de virar atributo, como vimos na aula de escape — inclusive aspas dentro do valor, que seriam um problema se não fossem escapadas.

4. Atributos booleanos

Alguns atributos não têm valor: a presença deles já significa "sim". disabled, checked, readonly, required, selected, multiple e autofocus são assim. Em HTML puro, você escreve disabled ou disabled=""; no Svelte, você escreve disabled={expressão}, e o compilador decide se coloca ou tira o atributo.

O código gerado mostra que ele não escreve o atributo como texto: escreve a propriedade do elemento.

import * as $ from 'svelte/internal/client';

var root = $.from_html(``);

export default function App($$anchor) {
	let ativo = true;
	var button = root();

	button.disabled = ativo;
	$.append($$anchor, button);
}

button.disabled = ativo é uma propriedade do DOM, que aceita verdadeiro ou falso. É por isso que disabled={false} faz o atributo sumir, enquanto disabled="false" mantém o botão desabilitado: a string "false" é verdadeira em HTML, porque o atributo existe. Guarde essa diferença — ela é a origem de muitos bugs silenciosos.

5. Quando o valor é falso, nulo ou vazio

O Svelte remove o atributo quando o valor é false, null ou undefined. Isso vale para qualquer atributo, não só os booleanos. Uma âncora sem endereço, por exemplo:

<script>
  let link = $state(null);
</script>

<a href={link}>cardápio</a>
<input type="checkbox" checked={false} />
<a>cardápio</a> <input type="checkbox"/>

O a ficou sem href e a caixa ficou sem checked. É um comportamento útil: você pode representar "não tem endereço" com null e o HTML sai limpo, sem href="null" nem href="undefined". Também é um comportamento perigoso: se você esperava que o link funcionasse e o valor ainda não chegou, o link fica inerte sem aviso.

Valor vazio ('') é diferente: ele mantém o atributo com valor vazio. E o número zero também: tabindex={0} aparece, porque zero é um valor válido. A regra é só para false, null e undefined.

Missão: sem estoque, o botão ainda reserva. Use o atributo booleano disabled com a condição estoque === 0 para impedir o clique, e a tela deve continuar em "Reservas: 0".

<script>
  let estoque = $state(0);
  let reservas = $state(0);
</script>

<button onclick={() => reservas++}>reservar</button>
<p>Reservas: {reservas}</p>
<script>
  let estoque = $state(0);
  let reservas = $state(0);
</script>

<button disabled={estoque === 0} onclick={() => reservas++}>reservar</button>
<p>Reservas: {reservas}</p>

A meta clica no botão e confere que o contador continua em zero. Se o atributo não estiver certo, o clique passa e a reserva acontece. É uma forma de testar comportamento de atributo sem olhar o HTML.

6. Propriedade do DOM × atributo

Existe uma distinção técnica que explica vários comportamentos estranhos: no navegador, cada elemento tem atributos (o que está escrito no HTML) e propriedades (o que está no objeto JavaScript daquele elemento). Muitas vezes os dois têm o mesmo nome e valores parecidos, mas não são a mesma coisa.

Para atributos conhecidos, como disabled, value e checked, o Svelte escreve a propriedade — como você viu em button.disabled = ativo. Propriedade aceita booleano de verdade, e por isso false desabilita o atributo em vez de escrever a palavra. Já para atributos que o navegador não conhece, como data-preco, ele usa setAttribute e o valor vira texto.

Na prática, isso significa que value de um input se comporta como valor do campo, e não como texto congelado no HTML: quando você digita, a propriedade muda, mas o atributo continua com o valor antigo. É por isso que ler o HTML pelo inspetor às vezes mostra um valor diferente do que está na tela — e é mais uma razão para não confiar no HTML gerado como se fosse o código-fonte.

Para quem está começando, a regra é simples: use o atributo que o elemento conhece, com o tipo que ele espera. Booleano para booleanos, texto para texto, número para número — e não tente inventar atributo para guardar dado. Para dado, use data-*, que é o lugar combinado para isso.

7. class e style são texto

Os dois atributos que mais aparecem no dia a dia são class e style, e os dois recebem texto. Uma classe é uma palavra (ou várias, separadas por espaço); um estilo é uma lista de propriedades CSS separadas por ponto e vírgula. Você pode montar os dois com chaves e texto:

<script>
  let cor = $state('green');
</script>

<p style="color: {cor}; padding: 4px">pão</p>
<p style={ { color: cor, padding: '4px' } }>bolo</p>
<p style="color: green; padding: 4px">pão</p> <p style="[object Object]">bolo</p>

O primeiro parágrafo saiu certo. O segundo, que tentou passar um objeto, virou [object Object] — a conversão padrão de objeto para texto em JavaScript. Nada de erro, nada de aviso: só um estilo que não funciona. Para estilo dinâmico existe a diretiva style:, com aula própria; para classe condicional existe class:, também com aula própria.

Com class, a mesma regra: é texto. class="preco {cor}" funciona e junta as palavras; class={cor} funciona e usa o valor sozinho. O que não funciona é passar objeto ou lista — o resultado seria [object Object] ou palavras coladas por vírgula.

Missão: o campo tem value={nome}, mas digitar não muda o estado. Acrescente o evento oninput que copia o valor do campo para nome.

<script>
  let nome = $state('');
</script>

<input value={nome} />
<p>Olá, {nome}</p>
<script>
  let nome = $state('');
</script>

<input value={nome} oninput={(e) => (nome = e.currentTarget.value)} />
<p>Olá, {nome}</p>

Aqui está a diferença entre atributo e evento. value é uma via de mão única: o estado manda no campo, mas o campo não manda no estado. Para a via de volta, é preciso escutar oninput e atualizar o estado. Quando as duas vias existem, o campo e o texto ficam sincronizados — e é isso que a diretiva bind:value faz em uma linha, com aula própria mais adiante.

8. Espalhar vários atributos: {...props}

Quando você tem um objeto com vários atributos, pode espalhá-lo na tag com três pontos. Cada chave do objeto vira um atributo:

<script>
  let props = $state({ type: 'text', placeholder: 'nome' });
</script>

<input {...props} />
<input type="text" placeholder={props.placeholder} />
<input type="text" placeholder="nome"/> <input type="text" placeholder="nome"/>

As duas linhas produzem o mesmo HTML. A primeira é mais curta e serve quando o objeto é grande ou vem pronto de outro lugar; a segunda é mais explícita e serve quando você quer deixar claro quais atributos importam. O custo do spread é que o leitor não vê a lista de atributos na tag: precisa saber o que tem no objeto.

Atributos fixos podem conviver com o espalhamento. Se o objeto tiver a mesma chave de um atributo escrito na tag, o último vence — então a ordem importa. Para quem está começando, prefira o explícito e use spread quando o objeto vier de um componente pai, assunto do Nível 2.

9. Eventos não são atributos comuns

onclick, oninput, onsubmit e companhia parecem atributos, mas não são: O valor deles precisa ser uma função, e o compilador liga essa função ao evento do navegador. Escrever o código dentro de aspas não funciona — é o erro que vimos na aula de erros de compilação, e vale repetir a regra: evento em chaves, com função.

A diferença aparece no código compilado: um atributo comum vira elemento.atributo = valor; um evento vira elemento.addEventListener. São mecanismos diferentes, com custos diferentes. O evento fica registrado e é chamado muitas vezes; o atributo é aplicado quando muda.

Existe ainda uma confusão de nomes: o atributo HTML se chama onclick em minúsculas, mas a propriedade do DOM se chama onclick também. No Svelte 5, os dois são escritos do mesmo jeito, e o compilador decide o que fazer pelo tipo de valor: função vira evento; texto vira erro. Não existe on:click nas aulas deste guia — essa é a forma antiga, que ainda compila com aviso de depreciação e vai sair em versões futuras.

Uma consequência prática: não use atributo para "chamar uma função". onclick={() => soma()} é evento; value={soma()} é atributo e chama a função a cada desenho — o que pode ser caro ou até criar um laço. Se o valor depende de uma conta, calcule antes; se depende de um clique, use evento.

10. Acessibilidade: o alt que falta

Alguns atributos não mudam o visual, mas mudam quem consegue usar a página. O mais conhecido é alt, o texto alternativo de uma imagem, lido por leitores de tela e mostrado quando a imagem não carrega. O compilador avisa quando ele falta:

<img src="pao.jpg">
<img src="pao.jpg"/>

E, junto com a saída, vem o aviso:

aviso: a11y_missing_attribute (linha 1): `<img>` element should have an alt attribute
https://svelte.dev/e/a11y_missing_attribute

Para listar os avisos de um arquivo sem abrir o navegador, dá para pedir só os códigos:

ana@notebook:~/loja$ node -e "const {compile}=require('svelte/compiler');const r=compile(require('fs').readFileSync('src/App.svelte','utf8'),{filename:'src/App.svelte'});console.log(r.warnings.map(w=>w.code).join('\n'))"
a11y_missing_attribute

A correção é simples: alt="pão francês na vitrine" quando a imagem tem conteúdo informativo, ou alt="" quando ela é só decoração. O valor vazio é uma escolha consciente: diz ao leitor de tela "pode pular". O que não vale é esquecer — e o aviso existe para lembrar.

11. Quando dá errado

Os três casos abaixo são reais. O primeiro é erro de compilação; os outros dois compilam e produzem HTML errado, que é pior, porque não aparece no terminal.

Erro 1 — valor com expressão sem aspas

A tag mistura texto e chaves sem aspas. O compilador não sabe onde termina o texto.

<script>
  let nome = $state('Ana');
</script>

<h1 class=titulo{nome}>oi</h1>
Erro de compilação (linha 5, coluna 4): Attribute values containing `{...}` must be enclosed in quote marks, unless the value only contains the expression

A mensagem diz exatamente a regra: valor com {...} precisa de aspas, a não ser que o valor seja só a expressão. Escreva class="titulo {nome}" ou class={nome}.

Erro 2 — "false" entre aspas

Como string, "false" é um valor presente. Para o HTML, o atributo existe e o botão está desabilitado.

<input type="checkbox" checked="false" />
<button disabled="false">comprar</button>
<input type="checkbox" checked="false"/> <button disabled="false">comprar</button>

O navegador marca a caixa e desabilita o botão, porque em HTML o que conta é a presença do atributo. Use chaves: checked={false} e disabled={false}, e os dois desaparecem.

Erro 3 — atributo que não existe naquele elemento

disabled e href não fazem sentido em uma div. O compilador não reclama: ele só escreve os atributos.

<div disabled href="/cardapio">cardápio</div>
<div disabled="" href="/cardapio">cardápio</div>

O resultado é uma div que parece um link desabilitado e não é nem uma coisa nem outra. Atributo pertence ao elemento: para link, a; para botão desabilitado, button. Quando algo "não funciona" sem dar erro, confira se o atributo existe no elemento usado.

Missão: o botão está sempre desabilitado, porque o atributo disabled foi escrito sozinho. Ligue-o ao estado com disabled={!ativo}, para que o clique conte.

<script>
  let ativo = $state(true);
  let cliques = $state(0);
</script>

<button disabled onclick={() => cliques++}>somar</button>
<p>Cliques: {cliques}</p>
<script>
  let ativo = $state(true);
  let cliques = $state(0);
</script>

<button disabled={!ativo} onclick={() => cliques++}>somar</button>
<p>Cliques: {cliques}</p>

Com ativo valendo verdadeiro, !ativo vale falso, e o atributo some. O botão volta a responder e o contador sobe para 1 — exatamente o que a meta confere.

Resumo

  • Atributo é a etiqueta do elemento e não aparece na tela.
  • Valor fixo usa aspas; valor de estado usa chaves.
  • Texto com expressão exige aspas: id="preco-{id}".
  • Atributos booleanos usam a presença: disabled={condição}.
  • false, null e undefined removem o atributo.

  • onclick é evento, não atributo: recebe função.
  • O compilador avisa quando falta alt em uma imagem.
