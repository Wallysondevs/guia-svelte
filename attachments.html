Svelte · {@attach}

Na padaria da Ana, cada etiqueta de preço é um papel colado na prateleira: o valor está escrito nele, e quem lê não precisa perguntar nada. No código dela, a etiqueta é um <p data-valor="3,50"> e o comportamento é uma função que transforma aquele atributo em texto bonito. Com use:, ela escreve use:preco e o Svelte procura a função pelo nome. Só que a Ana quer entregar o comportamento pronto, com o valor já combinado — e é aí que entra {@attach}: em vez do nome, você escreve uma expressão que devolve a função.

Você vai aprender

  • A anatomia: o bloco, a função que ele devolve e o node.
  • Attachment escrita na hora, como arrow function, direto no elemento.
  • Ler atributos do próprio elemento com node.dataset.
  • A fábrica que recebe parâmetros e devolve a attachment.
  • Por que a attachment roda de novo quando o valor muda — e a ação não.
  • A função de limpeza devolvida no fim.
  • Attachment em componente: quando funciona e quando não faz nada.
  • Os três erros reais do compilador desta aula.
  • {@attach} e use: lado a lado, para escolher.

1. O comportamento que vai pronto

Uma action precisa de nome. Você escreve function preco(node) e pendura use:preco no elemento; para passar um valor, usa use:preco={3.5} e a função recebe esse valor no segundo argumento. É um contrato simples, mas com três peças: o nome, o segundo argumento e o objeto de update.

A attachment faz o mesmo trabalho com outra gramática. Em vez de pedir um nome, ela aceita qualquer expressão cujo resultado seja uma função. Essa função recebe o elemento e faz o que tiver de fazer. Nada de segundo argumento, nada de update: se você precisa de um valor, ele entra na expressão por closure — a função já nasce sabendo o valor, porque foi criada com ele dentro.

<p data-valor="3,50" {@attach preco}></p>

Leia em voz alta: "neste parágrafo, anexe o resultado de preco". A diretiva não é use: — é um bloco, com chaves, como {@html} e {@render}. Isso tem uma consequência prática: o bloco pode aparecer em qualquer lugar onde caberia um atributo, e a expressão pode ser uma chamada de função, um $derived, um item de {#each}, o que você quiser.

Na padariaNo Svelte

O adesivo em branco, preenchido na hora{@attach (node) => …}
A máquina que imprime adesivos de qualquer corfunction pintar(cor) { return (node) => … }
Usar a máquina com a cor escolhida{@attach pintar('verde')}
Descolar o adesivo ao tirar o cartaza função devolvida pela attachment

2. A anatomia de uma attachment

O exemplo mínimo: uma função que recebe o elemento e escreve um atributo nele.

<script>
  function marcar(node) {
    node.title = 'pronto';
  }
</script>

<p {@attach marcar}>pão quentinho</p>
<p>pão quentinho</p>

A saída do servidor não tem title nenhum. Isso é esperado e é o assunto do item 7: attachment precisa de elemento de verdade, e no servidor não existe elemento. No navegador, o mesmo arquivo entrega <p title="pronto">pão quentinho</p>: a função rodou uma vez, quando o parágrafo entrou na página.

{@attach marcar}
o bloco. Ele vale para o elemento em que está escrito, como um atributo; pode haver mais de um no mesmo elemento.
marcar
a expressão. O compilador não sabe o que ela vale; em tempo de execução o Svelte chama o resultado. Se não for uma função, o componente quebra ao montar.
function marcar(node)
a attachment em si: uma função que recebe o elemento montado. Ela pode escrever atributos, texto, classes e escutar eventos.
node.title = 'pronto'
o trabalho. Nada aqui é reativo por si: o que a função fizer, fica, até alguém desfazer.

Repare que não existe update no contrato. Se a attachment precisa de um valor que muda, ela não recebe esse valor por parâmetro — ela lê o valor do componente, e o Svelte reexecuta a attachment quando esse valor muda. É uma diferença de filosofia: a ação pede o valor; a attachment fecha em cima dele.

3. Escrita na hora, sem nome

Como o bloco aceita qualquer expressão, uma arrow function serve. É o jeito mais direto quando o comportamento é de um elemento só e não vale a pena dar nome a ele:

<p {@attach (node) => { node.textContent = node.textContent.toUpperCase(); }}>pão quentinho</p>

Essa linha transforma o texto em maiúsculas na montagem. Nada de função no <script>, nada de nome para inventar — e nada de reaproveitamento também: se a segunda etiqueta precisar do mesmo comportamento, você copia a linha. Para um caso único, é a melhor relação tamanho/benefício do guia; para três ou mais, dê nome à função e importe.

Missão: a attachment só marca o title; o texto continua em minúsculas. Escreva a attachment na hora, direto no bloco {@attach …}, para o parágrafo mostrar PÃO QUENTINHO.

<script>
  function marcar(node) {
    node.title = 'pronto';
  }
</script>

<p {@attach marcar}>pão quentinho</p>
<p {@attach (node) => { node.textContent = node.textContent.toUpperCase(); }}>pão quentinho</p>

O parêntese em volta de node não é enfeite de estilo: ele deixa claro onde a arrow começa dentro do bloco. Sem ele, {@attach node => …} também funciona, mas fica mais difícil de ler quando a expressão cresce.

4. O nó é o elemento — inclusive os atributos

O primeiro argumento é o elemento montado, o mesmo que você vê no inspetor. Então a attachment pode ler o que o HTML já traz: atributos data-*, href, value, o texto que veio do servidor. Isso permite um padrão útil: a marcação carrega o dado e a attachment só o transforma em algo apresentável.

<p data-valor="3,50" {@attach preco}></p>

Com function preco(node) { node.textContent = 'R$ ' + node.dataset.valor; }, a etiqueta nasce com o valor no HTML e vira texto formatado no navegador. Se o JavaScript não carregar, o atributo continua ali — feio, mas presente. É a mesma ideia de <progress value="70">: o dado está na marcação, o enfeite vem depois.

Missão: o parágrafo tem data-valor="3,50", mas a attachment procura outro atributo e escreve R$ null. Leia o atributo certo, pelo node.dataset.valor, para a etiqueta mostrar R$ 3,50.

<script>
  function preco(node) {
    node.textContent = 'R$ ' + node.getAttribute('data-preco');
  }
</script>

<p data-valor="3,50" {@attach preco}></p>
<script>
  function preco(node) {
    node.textContent = 'R$ ' + node.dataset.valor;
  }
</script>

<p data-valor="3,50" {@attach preco}></p>

Vale saber a tradução: node.dataset.valor é o mesmo que node.getAttribute('data-valor'), só que sem o prefixo data- e com nome em camelCase para atributos compostos (data-preco-final vira dataset.precoFinal). Quando o atributo não existe, os dois caminhos dão undefined — e é por isso que a versão errada escreve R$ undefined em vez de estourar.

5. Parâmetros: a fábrica

Este é o ponto em que mais gente tropeça. A attachment não tem segundo argumento. Se você quer passar um valor, escreva uma função que devolve a attachment — uma fábrica:

function pintar(cor) {
  return (node) => {
    node.textContent = cor;
  };
}

Aí o bloco chama a fábrica com o valor e o Svelte anexa o resultado: {@attach pintar('verde')}. Ler a expressão de dentro para fora ajuda: pintar('verde') devolve uma função que já sabe que a cor é verde; o bloco anexa essa função ao parágrafo.

Vale dar nome às duas peças com cuidado: pintar é a fábrica, e o resultado de pintar('verde') é a attachment. Por isso o bloco pode chamar a fábrica à vontade — pintar('verde'), pintar('azul') — que cada chamada produz uma função independente, com o seu próprio valor guardado.

O erro clássico é escrever a attachment com dois parâmetros, como se fosse uma action: function pintar(node, cor) e depois {@attach pintar}. O Svelte chama pintar(node), o segundo parâmetro chega undefined e o texto sai undefined — sem erro no console, o que torna o diagnóstico mais chato.

Missão: o parágrafo mostra undefined porque pintar espera dois argumentos. Transforme pintar numa fábrica que recebe a cor e devolve a attachment, e passe pintar(cor) no bloco: o clique em "azul" deve trocar o texto para azul.

<script>
  let cor = $state('verde');
  function pintar(node, qual) {
    node.textContent = qual;
  }
</script>

<button onclick={() => cor = 'azul'}>azul</button>
<p {@attach pintar}></p>
<script>
  let cor = $state('verde');
  function pintar(qual) {
    return (node) => {
      node.textContent = qual;
    };
  }
</script>

<button onclick={() => cor = 'azul'}>azul</button>
<p {@attach pintar(cor)}></p>

O clique em "azul" muda cor, que muda a expressão pintar(cor), que devolve uma função nova — e o Svelte roda a attachment de novo com essa função. Não há update: há reexecução. É o que o item seguinte destrincha.

6. Quando roda, quando roda de novo

Uma attachment roda quando o elemento é montado. E roda de novo, antes de tudo, quando alguma coisa que ela lê muda. O Svelte rastreia as leituras feitas dentro da função — as mesmas regras de $derived e $effect — e trata a attachment como um efeito que pertence ao elemento.

MomentoO que aconteceObservação
O elemento entra no DOMa expressão é avaliada e a attachment rodauma vez por elemento
Um valor lido pela attachment mudaa limpeza anterior roda e a attachment roda de novosem update: é reexecução
Um valor lido pela expressão mudaa expressão é reavaliada e a nova função é anexadao caso da fábrica pintar(cor)
O elemento sai do DOMa função de limpeza rodase você devolveu uma
O componente é renderizado no servidornada dissosem DOM, sem attachment

Essa reexecução explica por que a attachment pode ler estado diretamente, sem receber por parâmetro: ela é reavaliada quando o estado muda. O preço é que ela precisa ser idempotente — rodar duas vezes não pode duplicar escutas nem somar duas vezes o mesmo valor. Daí o hábito de sempre devolver a limpeza do que foi aberto fora do elemento.

Cuide do que a attachment lê

Se ela lê cor e tamanho, ela roda de novo quando qualquer um dos dois muda. Se ela lê um objeto inteiro, qualquer mudança de propriedade conta. Ler menos é rodar menos.

7. A limpeza devolvida

A attachment pode devolver uma função. Essa função roda quando o elemento sai do DOM — e também antes de cada reexecução. É o lugar de remover escutas, parar timers e desconectar observers:

export function fora(aoSair) {
  return (node) => {
    const ouvir = (evento) => {
      if (!node.contains(evento.target)) aoSair();
    };
    document.addEventListener('click', ouvir);
    return () => document.removeEventListener('click', ouvir);
  };
}

Três níveis de função, e cada um tem um papel: fora é a fábrica (recebe o que fazer ao sair), a arrow de dentro é a attachment (recebe o elemento e abre a escuta) e a função devolvida é a limpeza. Esse empilhamento é o jeito de dar parâmetros a uma attachment sem quebrar o contrato.

ana@notebook:~/loja$ grep -rn "return () =>" src/lib/attachments.js
11:    return () => document.removeEventListener('click', ouvir);

A linha 11 é a única do arquivo que desfaz alguma coisa, e ela existe porque a linha 9 registrou uma escuta em document. Sem ela, cada montagem do painel deixaria uma escuta pendurada, e o clique fora passaria a fechar três painéis de uma vez.

Só a função conta. Devolver um objeto com update — o formato que a ação usa — não faz a limpeza ser chamada: o Svelte guarda o retorno, e na hora de limpar só chama o que for função. Se você vem de use:, é aqui que a memória atrapalha.

8. No servidor, nada acontece

Como toda diretiva que mexe no DOM, a attachment não roda na renderização do servidor. A saída mostra só a marcação:

<script>
  function pintar(cor) {
    return (node) => {
      node.textContent = cor;
    };
  }
  let cor = $state('verde');
</script>

<p {@attach pintar(cor)}></p>
<button onclick={() => cor = 'azul'}>azul</button>
<p></p> <button>azul</button>

O parágrafo sai vazio. No navegador ele mostra verde e passa a azul depois do clique — a diferença entre as duas saídas é o assunto desta aula inteira. Para quem testa, isso significa que um teste de HTML do servidor nunca vai ver o texto que a attachment escreveu; para quem publica, significa que o conteúdo essencial não pode depender dela.

E há uma consequência de projeto: a attachment serve ao enfeite e à conveniência (formatação, foco, medida), não ao conteúdo. Se o texto precisa aparecer sem JavaScript, ele vem do template ou dos dados — como a Ana faz com o data-valor, que também funciona como fallback.

9. Attachment em componente

Aqui aparece a maior diferença em relação ao use:. Diretiva de ação em componente é erro de compilação; {@attach} em componente compila. O compilador transforma o bloco num adereço especial, e o componente só o aplica se repassar os adereços ao seu elemento raiz:

Componente<Cartao {@attach marcar} />
<p>cartão raiz</p>compila; nada acontece — o adereço não chega ao parágrafo
let { ...resto } = $props() + <p {...resto}>compila e funciona: o adereço é aplicado no parágrafo

As duas linhas acima foram medidas num projeto real, com o build de produção: no componente que só desenha o seu HTML, o parágrafo final saiu <p>cartao raiz</p>; no componente que repassa os adereços, saiu <p title="do componente">cartao raiz</p>. Nada de erro em nenhum dos casos — o que torna o silêncio perigoso: se a attachment não aparecer, o problema pode ser o componente que não repassa.

O compilador deixa esse mecanismo à vista. Compilando <Cartao {@attach marcar} /> para o navegador, a chamada do componente sai assim:

Cartao($$anchor, { [$.attachment()]: marcar });

É um adereço com uma chave especial — não um evento, não um onclick. Quem decide o que fazer com ele é o componente: sem repasse, o adereço fica guardado e ninguém o aplica.

Para o dia a dia, o caminho seguro é o mais chato: envolva o componente num elemento e pendure a attachment nele. <div {@attach marcar}><Cartao /></div> não depende de o componente saber nada sobre adereços.

10. Onde guardar

Attachment é função, então mora em arquivo comum. No projeto da Ana, as que se repetem ficam em src/lib/attachments.js e são importadas pelas telas:

export function preco(node) {
  node.textContent = 'R$ ' + node.dataset.valor;
}

export function fora(aoSair) {
  return (node) => {
    const ouvir = (evento) => {
      if (!node.contains(evento.target)) aoSair();
    };
    document.addEventListener('click', ouvir);
    return () => document.removeEventListener('click', ouvir);
  };
}

Do outro lado, a etiqueta repete a attachment em duas linhas, cada uma com o seu valor no atributo:

ana@notebook:~/loja$ grep -rln "@attach" src
src/lib/Troco.svelte
ana@notebook:~/loja$ grep -rn "@attach" src/lib/Troco.svelte
5:<p data-valor="3,50" {@attach preco}></p>
6:<p data-valor="12,00" {@attach preco}></p>

Duas etiquetas, uma função, nenhum parâmetro passado — o valor vem do HTML de cada uma. Repare que a fábrica fora ficaria assim no uso: <div {@attach fora(() => aberto = false)}>. A chamada devolve a attachment; a arrow de dentro é o "o que fazer" da padaria.

11. Quando dá errado

As três mensagens abaixo são do compilador desta versão, copiadas da execução. Todas aparecem antes de a página abrir.

Erro 1 — o bloco sem expressão

Quem cola o bloco e esquece a função recebe uma reclamação sobre espaço, o que confunde bastante:

<script>
  function marcar(node) {
    node.title = 'pronto';
  }
</script>

<p {@attach}>pão quentinho</p>
Erro de compilação (linha 7, coluna 11): Expected whitespace

"Esperava um espaço." O compilador quer uma expressão depois de @attach e encontrou a chave de fechamento; a falta de espaço é só o primeiro sintoma. Escreva {@attach marcar} ou {@attach (node) => …}.

Erro 2 — dois valores no bloco

A intenção é passar um parâmetro, mas o bloco aceita uma expressão só:

<script>
  function marcar(node) {
    node.title = 'pronto';
  }
</script>

<p {@attach marcar 'pronto'}>pão quentinho</p>
Erro de compilação (linha 7, coluna 19): Expected token }

"Esperava a chave de fechamento." O compilador leu marcar, achou que a expressão tinha acabado e tropeçou no 'pronto'. Para passar valor, use a fábrica: {@attach marcar('pronto')}, com a função devolvendo a attachment.

Erro 3 — attachment no <svelte:head>

Os elementos especiais do Svelte aceitam só o que faz sentido para eles. O <svelte:head> não aceita atributo nem diretiva:

<script>
  function marcar(node) {
    node.title = 'pronto';
  }
</script>

<svelte:head {@attach marcar}>
  <title>Padaria da Ana</title>
</svelte:head>
<p>pão quentinho</p>
Erro de compilação (linha 7, coluna 13): `<svelte:head>` cannot have attributes nor directives

"<svelte:head> não pode ter atributos nem diretivas." O bloco vai no elemento comum que precisa do comportamento; o <svelte:head> serve para dizer o que vai para o <head>.

12. {@attach} ou use:?

Os dois resolvem o mesmo problema com gramáticas diferentes. A escolha, na prática, é sobre como você quer passar valores e onde o comportamento vai ser usado:

use:acao{@attach expressão}
O que se escreveum nome de funçãouma expressão que devolve função
Parâmetrosegundo argumentoclosure, com fábrica
Atualizaçãoupdate(valor)reexecução quando o valor lido muda
Limpezafunção devolvida ou destroyfunção devolvida
Em componenteerro de compilaçãocompila; precisa de repasse de adereços
Quando brilhacomportamento fixo, reaproveitado por nomecomportamento montado na hora, com valor embutido

Se você já escreveu a função e vai usá-la em cinco telas, use: é mais curto de ler. Se o comportamento depende de um valor que está ali do lado, {@attach} evita o segundo argumento e o objeto de atualização. E se o que você quer é só reagir a um clique, nenhum dos dois: onclick basta.

Resumo

  • {@attach expressão} anexa ao elemento a função que a expressão devolver.
  • A attachment recebe o elemento montado: pode escrever atributos, texto e classes, e escutar eventos.
  • Uma arrow function serve como attachment escrita na hora, sem nome.
  • node.dataset.valor lê o atributo data-valor do próprio elemento.
  • Valores vão por closure: a fábrica function pintar(cor) { return (node) => … } devolve a attachment.
  • Não existe update: quando um valor lido muda, a attachment roda de novo.
  • Devolver uma função é a limpeza; devolver um objeto com update não faz nada ser chamado.
  • No servidor não há DOM e a attachment não roda: o HTML sai só com a marcação.
  • Em componente compila, mas só funciona se o componente repassar os adereços ao elemento raiz.
  • Os erros desta aula: bloco sem expressão, dois valores no bloco e attachment em <svelte:head>.
