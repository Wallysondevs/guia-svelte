Svelte · Checkbox, Radio e Select

Nem todo pedido da Ana se escreve com letras. "Aceito os termos" é um sim ou não; "pão ou leite" é uma escolha entre poucas opções; "forma de pagamento" é uma escolha entre várias, mas só uma vale. Cada uma dessas ideias tem um elemento de formulário próprio no HTML, e cada um devolve um tipo diferente de valor. Esta aula mostra qual binding usar em cada caixa, o que chega na variável e o que o servidor manda antes de qualquer clique.

Você vai aprender
  • Como ligar uma caixa de seleção com bind:checked.
  • Por que o valor de uma caixa marcada é true e não texto.
  • Como mostrar ou esconder um bloco usando a caixa como condição.
  • Como ligar uma lista suspensa com bind:value.
  • A diferença entre <option value="pao"> e <option>pão</option>.
  • Por que rádio não usa bind:checked e usa bind:group.
  • O que o servidor manda no HTML de cada tipo de caixa.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como inspecionar os arquivos do projeto no terminal.

1. A ideia: cada caixa guarda um tipo de resposta

No balcão, a Ana faz três perguntas diferentes. A primeira é "você aceita o pedido assim?" — a resposta é sim ou não. A segunda é "pão ou leite?" — uma escolha entre poucas opções. A terceira é "como vai pagar?" — uma escolha entre várias, mas só uma pode valer. Três perguntas, três formatos de resposta, três elementos no HTML.

A caixa de seleção (checkbox) guarda um sim ou não. Ela é um interruptor: marcada vale true, desmarcada vale false. O botão de rádio (radio) guarda uma escolha entre opções do mesmo grupo: marcar uma desmarca as outras, e o valor guardado é o da opção escolhida. A lista suspensa (select) também guarda uma escolha, só que escondida atrás de um clique.

O Svelte tem um binding para cada um. bind:checked para caixas de marcar; bind:value para listas; bind:group para grupos de rádio e para grupos de caixas que somam vários valores. Usar o binding errado não é questão de gosto: o compilador recusa alguns pares e os outros simplesmente não fazem o que você espera.

Uma dica de usabilidade que vale desde já: envolva a caixa e o texto num <label>. Assim, clicar na palavra "aceito" também marca a caixa, e quem usa celular ganha uma área de toque maior. O compilador do Svelte chega a avisar quando um rótulo não está associado a nenhum controle. É um aviso de acessibilidade, não de sintaxe, mas o efeito prático é imediato: menos cliques errados no balcão.

Outra dica: uma caixa de marcar sozinha não é uma escolha "sim ou não" na tela. Quem lê vê um quadradinho vazio e precisa saber o que ele significa. O texto ao lado é parte do controle, não enfeite. Se o texto desaparecer, a caixa deixa de comunicar qualquer coisa.

Repare que bind:group aparece duas vezes, com resultados diferentes. Em rádio, ele guarda um valor só, porque só um pode estar marcado. Em caixas de marcar, guarda uma lista, porque várias podem estar marcadas. O elemento decide o formato; o binding só transporta. A aula seguinte é toda sobre bind:group; aqui ele aparece para fechar o trio.

3. bind:checked na caixa de seleção

<script>
  let aceito = $state(true);
</script>

<input type="checkbox" bind:checked={aceito}>
<p>Aceito: {aceito ? 'sim' : 'não'}</p>

O estado começa marcado, então o servidor manda a caixa já marcada. O parágrafo usa uma expressão condicional para transformar o booleano em palavra: se aceito for verdadeiro, mostra "sim"; senão, "não". Essa tradução é só de exibição; o valor guardado continua sendo true.

<input type="checkbox" checked=""/> <p>Aceito: sim</p>
type="checkbox"
o tipo da caixa. Sem esse atributo, o bind:checked nem compila — o compilador exige que o elemento seja uma caixa de marcar.
bind:checked
liga o estado de marcação, não o texto. O valor é sempre booleano: true ou false.
{aceito}
mostra o booleano como texto (true ou false). Para mostrar palavra, use a condicional.
checked=""
o atributo que o servidor manda quando o estado começa verdadeiro. A presença do atributo marca a caixa; o valor dele é irrelevante.

Existe uma confusão clássica aqui. O atributo HTML se chama checked, mas o valor que o JavaScript lê é input.checked, um booleano. Quem escreve checked="false" no HTML pensando em desmarcar se engana: a presença do atributo já marca a caixa. No Svelte você não escreve esse atributo à mão; o binding cuida disso a partir do estado.

Missão: a caixa não está ligada ao estado, então marcar não muda o parágrafo. Ligue a caixa com bind:checked para que um clique mostre Aceito: sim.

<script>
  let aceito = $state(false);
</script>

<p>Aceito: {aceito ? 'sim' : 'não'}</p>
<input type="checkbox">
<script>
  let aceito = $state(false);
</script>

<p>Aceito: {aceito ? 'sim' : 'não'}</p>
<input type="checkbox" bind:checked={aceito}>

A missão mostra uma coisa importante: sem o binding, a caixa continua marcando e desmarcando na tela, porque isso é comportamento do navegador. O que não acontece é a variável mudar. A tela mentiria: a caixa parece marcada e o estado diz que não.

4. A caixa que decide o que aparece

Como o valor é booleano, ele serve direto como condição de um bloco. O componente abaixo mostra uma mensagem diferente conforme a caixa esteja marcada ou não.

<script>
  let aceito = $state(false);
</script>

<input type="checkbox" bind:checked={aceito}>
{#if aceito}
  <p>Pode enviar o pedido</p>
{:else}
  <p>Marque o aceite primeiro</p>
{/if}
<input type="checkbox"/> <p>Marque o aceite primeiro</p>

Com o estado inicial falso, o servidor manda o ramo {:else}. Marcar a caixa troca o parágrafo sem recarregar nada. Esse padrão é comum em aceite de termos, em "mostrar senha" e em qualquer interruptor que muda o que está na tela. A condição não precisa ser uma comparação: um booleano já é verdadeiro ou falso por definição.

Se você quiser o contrário — mostrar algo enquanto a caixa está desmarcada —, inverta com o ponto de exclamação: {#if !aceito}. O ! lê-se "não". É o mesmo operador que aparece em if (!pronto) no JavaScript comum.

Esse booleano também serve para desabilitar um botão. Em vez de esconder o botão de enviar, você pode deixá-lo visível e desligado com disabled={!aceito}. O atributo disabled aceita uma expressão, como qualquer atributo dinâmico do Svelte. O leitor vê o botão e entende que falta marcar a caixa; se o botão sumisse, ele ficaria procurando o que fazer. Mostrar e desabilitar costuma comunicar melhor do que esconder.

Cuidado com um detalhe: um botão desabilitado não dispara evento de clique. Se você testar o fluxo com o botão desligado e um onclick que grava o pedido, o teste nunca vai acontecer. Ligue a caixa primeiro, depois clique. Parece bobo, mas é a razão de muitos "não funciona" em formulários de aceite.

5. <select> com bind:value

A lista suspensa guarda uma escolha entre opções. O binding é bind:value, o mesmo dos campos de texto, porque o que interessa é o valor da opção escolhida.

<script>
  let escolha = $state('pao');
</script>

<select bind:value={escolha}>
  <option value="pao">pão</option>
  <option value="leite">leite</option>
</select>
<p>Escolha: {escolha}</p>

O HTML gerado marca a opção que corresponde ao estado inicial. Repare no atributo selected="", que é o jeito de o HTML dizer "esta é a escolhida".

<select><option value="pao" selected="">pão</option><option value="leite">leite</option></select> <p>Escolha: pao</p>
<select>
o elemento da lista. Ele contém <option> e nada mais; texto solto dentro dele é ignorado.
bind:value
liga o valor escolhido à variável. A lista dispara change, não input — o binding já sabe disso.
value="pao"
o valor que vai para a variável quando esta opção é escolhida. É diferente do texto visível.
{escolha}
mostra o valor guardado, não o rótulo. Se os dois forem diferentes, a tela mostra o valor.

Essa distinção entre valor e rótulo é o ponto mais útil da lista. A Ana vê "pão" e "leite"; o programa guarda pao e leite, sem acento e em minúsculas, prontos para virar chave de banco de dados ou comparação. O rótulo é para o olho, o valor é para o código.

Missão: a lista mostra as opções, mas escolher não muda o parágrafo. Ligue a lista ao estado com bind:value para que escolher leite mostre Escolha: leite.

<script>
  let escolha = $state('pao');
</script>

<p>Escolha: {escolha}</p>
<select>
  <option value="pao">pão</option>
  <option value="leite">leite</option>
</select>
<script>
  let escolha = $state('pao');
</script>

<p>Escolha: {escolha}</p>
<select bind:value={escolha}>
  <option value="pao">pão</option>
  <option value="leite">leite</option>
</select>

6. option com valor e sem valor

O atributo value da opção é opcional. Quando ele falta, o navegador usa o texto da opção como valor. O componente abaixo guarda leite e marca a segunda opção sem escrever valor nenhum.

<script>
  let escolha = $state('leite');
</script>

<select bind:value={escolha}>
  <option>pão</option>
  <option>leite</option>
</select>
<p>Escolha: {escolha}</p>
<select><option>pão</option><option selected="">leite</option></select> <p>Escolha: leite</p>
HTMLValor guardado ao escolherQuando usar
<option value="pao">pão</option>"pao"o valor precisa ser estável e sem acento
<option>pão</option>"pão"o valor é o próprio rótulo
<option value="">escolha…</option>""a opção vazia de "nada escolhido"
<option value={codigo}>{nome}</option>o valor da variávellista que vem de dados

A terceira linha é um truque útil: uma opção vazia no topo serve de "escolha uma opção" e deixa o estado como string vazia até a pessoa decidir. A quarta mostra que o valor pode vir de uma variável, o que permite montar a lista com {#each}. Nos dois casos, quem decide o que vai para o estado é o atributo value.

Uma armadilha frequente é misturar os dois estilos na mesma lista. Se a primeira opção tem value="pao" e a segunda não tem valor, a variável pode receber "pao" ou "leite", dependendo do rótulo. Funciona, mas obriga quem lê a conferir caso por caso. Escolha um estilo e siga com ele.

Existe uma variação da lista que merece menção: <select multiple>. Com o atributo multiple, a pessoa escolhe várias opções com Ctrl ou Shift, e o bind:value passa a devolver uma lista em vez de um valor só. É o mesmo elemento, o mesmo binding e um tipo de resultado diferente. Se a lista é de formas de pagamento e só uma vale, não use multiple; se é de ingredientes e várias valem, use.

Para o dia a dia da padaria, a lista simples resolve quase tudo. Ela ocupa pouco espaço, mostra a escolha atual sem abrir nada e funciona bem no celular, onde o navegador troca a lista por um seletor nativo. A desvantagem é que as opções ficam escondidas até o clique; quando são poucas e importantes, os rádios comunicam melhor.

7. Rádio: conhecendo o bind:group

Botões de rádio andam em grupo: marcar um desmarca os outros. O binding é bind:group, e o valor guardado é o value do escolhido.

<script>
  let pagamento = $state('');
</script>

<input type="radio" value="pix" bind:group={pagamento}>
<input type="radio" value="cartao" bind:group={pagamento}>
<p>Pagamento: {pagamento}</p>
<input type="radio" value="pix"/> <input type="radio" value="cartao"/> <p>Pagamento: </p>

Com o estado vazio, nenhum dos dois aparece marcado no HTML do servidor, e o parágrafo fica sem valor. Quando a Ana escolhe cartão, a variável recebe "cartao" e o outro rádio é desmarcado pelo próprio grupo. Não existe bind:checked em rádio: o compilador recusa e ainda sugere o binding certo.

Missão: os dois rádios não estão ligados ao estado. Use bind:group para que escolher cartão mostre Pagamento: cartao.

<script>
  let pagamento = $state('');
</script>

<p>Pagamento: {pagamento}</p>
<input type="radio" id="pix" value="pix">
<input type="radio" id="cartao" value="cartao">
<script>
  let pagamento = $state('');
</script>

<p>Pagamento: {pagamento}</p>
<input type="radio" id="pix" value="pix" bind:group={pagamento}>
<input type="radio" id="cartao" value="cartao" bind:group={pagamento}>

Repare que os dois rádios apontam para a mesma variável. É isso que os torna um grupo: não o name do HTML, mas o binding compartilhado. O navegador também agrupa rádios pelo atributo name, mas o Svelte não depende disso: ele mantém a marcação de cada rádio a partir do valor da variável. Por isso os exemplos acima funcionam sem name — e por isso dois rádios ligados a variáveis diferentes podem ficar marcados ao mesmo tempo, mesmo com o mesmo name.

9. Quando dá errado

Erro 1 — bind:checked em campo de texto

O binding de marcação só vale em caixa de marcar. Um campo de texto não tem estado de marcado.

<script>
  let ok = $state(false);
</script>

<input type="text" bind:checked={ok}>
Erro de compilação (linha 5, coluna 19): `bind:checked` can only be used with `<input type="checkbox">`

A mensagem diz exatamente o que fazer: use type="checkbox". Se o campo é de texto e você quer o conteúdo, o binding é bind:value. O nome do binding precisa combinar com a natureza do elemento.

Erro 2 — bind:checked em rádio

Rádio não guarda um booleano próprio: guarda o valor escolhido dentro de um grupo. O compilador recusa e indica o binding certo na própria mensagem.

<script>
  let ok = $state(false);
</script>

<input type="radio" bind:checked={ok}>
Erro de compilação (linha 5, coluna 20): `bind:checked` can only be used with `<input type="checkbox">` — for `<input type="radio">`, use `bind:group`

É uma das mensagens mais gentis do compilador: além de recusar, ensina. Troque por bind:group={variavel}, com uma variável que guarde o valor do escolhido, e dê um value a cada rádio.

Erro 3 — binding sem nome

Depois dos dois-pontos vem o nome do binding. Um bind: solto não diz o que ligar.

<script>
  let x = $state(0);
</script>

<input bind:={x}>
Erro de compilação (linha 5, coluna 7): `bind:` name cannot be empty

"O nome do bind: não pode ser vazio". Escreva bind:value, bind:checked ou bind:group, conforme o elemento. Se você chegou aqui por um erro de digitação, o número da coluna mostra onde o nome deveria começar.

Exercícios

1. Qual binding guarda o estado de uma caixa de marcar?

2. Numa <option value="leite">leite</option>, o que a variável recebe ao escolher essa opção?

3. Por que rádio usa bind:group e não bind:checked?

Complete o código

let escolha = $state('pao');

<select >
  <option value="pao">pão</option>
  <option value="leite">leite</option>
</select>

// escolher leite guarda a string "leite"

Resumo

  • bind:checked liga a marcação de uma caixa e guarda true ou false.
  • Um booleano serve direto como condição de {#if}, sem comparação.
  • bind:value em <select> guarda o valor da opção escolhida.
  • option com value guarda o atributo; sem ele, guarda o texto.
  • Rádio usa bind:group e guarda o valor do escolhido.
  • Vários rádios ligados à mesma variável formam um grupo de verdade.
  • O servidor manda checked="" e selected="" conforme o estado inicial.
  • Erros desta aula: bind:checked em texto, bind:checked em rádio e bind: sem nome.
  • O compilador sugere bind:group na mensagem de erro do rádio; ler a mensagem economiza tempo.
