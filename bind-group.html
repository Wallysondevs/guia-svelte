Svelte · bind:group

A lista de compras da Ana tem quadradinhos: pera, uva, leite, pão. Ela marca o que precisa e a lista cresce sem que ninguém escreva o nome de cada item duas vezes. Do outro lado do balcão, a pergunta "como vai pagar?" tem quadradinhos parecidos, mas só um pode ficar marcado. O bind:group é o binding que entende essa diferença: nas caixas de marcar ele guarda uma lista, nos rádios guarda um valor só. Esta aula mostra os dois casos, o papel do atributo value e os erros que o compilador devolve quando a conta não fecha.

Você vai aprender
  • Como um grupo de caixas de marcar vira uma lista de valores.
  • Por que cada <input> precisa do seu value.
  • Como marcar e desmarcar atualiza a lista na hora.
  • Como grupos de rádio guardam um valor único.
  • Como começar o componente com itens já marcados.
  • Como montar as caixas a partir de uma lista de opções.
  • O que a variável recebe quando o value falta.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como conferir o tamanho de uma lista no terminal.

1. A ideia: vários marcadores, uma variável

Na aula passada, cada caixa tinha a sua variável: uma para o aceite, uma para a forma de pagamento. Quando as caixas pertencem a uma mesma pergunta — "quais frutas?" —, criar uma variável por caixa vira trabalho sem fim. A lista de compras pode ter três itens hoje e trinta amanhã. O bind:group resolve isso guardando todas as respostas em um lugar só.

O nome diz o que faz: liga um grupo de elementos a uma variável. O tipo da variável decide o formato do resultado. Se for uma lista, o grupo aceita várias marcações — é o caso das caixas de marcar. Se for um valor simples, o grupo aceita uma só — é o caso dos rádios, em que marcar um desmarca o anterior.

Existe uma terceira peça, que passa despercebida: o atributo value de cada caixa. É ele que diz o que entra na lista quando aquela caixa é marcada. Sem ele, a caixa não tem identidade e o grupo não sabe o que guardar. Boa parte dos problemas com bind:group é, no fundo, um value esquecido.

2. No dia a dia × no componente

Na padariaNo componente
A pergunta "quais frutas?"Um grupo de checkbox com bind:group
O nome de cada fruta no marcadorO atributo value de cada caixa
A lista do que foi marcadoUma variável $state([])
A pergunta "como pagar?"Um grupo de radio com bind:group
A resposta únicaUma variável $state('')
Marcar um rádio e desmarcar o outroO grupo troca o valor da variável

Repare que a diferença entre a terceira e a quinta linha é o formato inicial da variável: lista vazia para várias respostas, texto vazio para uma resposta. O binding não escolhe por você; ele segue o que a variável já é. Errar o formato inicial é o segundo motivo mais comum de confusão com grupos.

3. bind:group nas caixas de marcar

<script>
  let frutas = $state([]);
</script>

<label><input type="checkbox" value="pera" bind:group={frutas}> pera</label>
<label><input type="checkbox" value="uva" bind:group={frutas}> uva</label>
<p>{frutas.length} fruta(s)</p>

O estado começa como lista vazia. Cada caixa aponta para a mesma variável e declara o seu valor. O HTML gerado mostra as caixas sem marcação e o contador em zero:

<label><input type="checkbox" value="pera"/> pera</label> <label><input type="checkbox" value="uva"/> uva</label> <p>0 fruta(s)</p>
type="checkbox"
o elemento do grupo. bind:group só vale em <input>: caixas de marcar ou rádios.
value="pera"
o valor que entra na lista quando a caixa é marcada. É a identidade da caixa dentro do grupo.
bind:group={frutas}
liga todas as caixas de mesmo grupo à lista. Marcar acrescenta o valor; desmarcar tira.
{frutas.length}
quantos itens estão marcados. A lista é reativa: muda a marcação, muda o número.
<label>
torna o texto clicável. Clicar em "pera" marca a caixa ao lado, o que ajuda no celular.

O que acontece por dentro é simples de descrever: quando uma caixa é marcada, o grupo procura o valor dela na lista e acrescenta se não estiver lá. Quando é desmarcada, procura e remove. O resultado é uma lista na ordem em que os itens foram marcados, não na ordem em que aparecem na tela — um detalhe que só importa quando você exibe a lista em vez de contar.

Missão: as caixas estão soltas: marcar não muda o contador. Ligue as duas ao mesmo grupo para que marcar pera e uva mostre 2 fruta(s).

<script>
  let frutas = $state([]);
</script>

<p>{frutas.length} fruta(s)</p>
<label><input type="checkbox" id="pera" value="pera"> pera</label>
<label><input type="checkbox" id="uva" value="uva"> uva</label>
<script>
  let frutas = $state([]);
</script>

<p>{frutas.length} fruta(s)</p>
<label><input type="checkbox" id="pera" value="pera" bind:group={frutas}> pera</label>
<label><input type="checkbox" id="uva" value="uva" bind:group={frutas}> uva</label>

Sem bind:group, as caixas ainda marcam e desmarcam na tela, porque isso é comportamento do navegador. O contador, que depende do estado, fica parado. É o mesmo sintoma da aula passada, com uma diferença: aqui a lista inteira decide o resultado, e não uma caixa só.

4. O value de cada caixa e a ordem da lista

O valor guardado é o que está no atributo value, não o texto ao lado. Isso permite separar o que a Ana lê do que o programa guarda.

HTML da caixaO que entra na listaQuando usar
value="pera" + texto "pera""pera"o mais comum
value="1" + texto "pera""1"o valor é um código
value={fruta.id} + texto {fruta.nome}o id do itemlista que vem de dados
sem valuenada previsívelnunca

A ordem da lista segue a ordem das marcações. Se a Ana marcar uva e depois pera, a lista fica ['uva', 'pera'], mesmo que na tela pera apareça primeiro. Para exibir na ordem da tela, você ordena a lista na hora de mostrar; para guardar, a ordem das marcações costuma ser suficiente.

Existe também a possibilidade de o item ser um objeto inteiro, e não um texto. Nesse caso o value aponta para o objeto e o grupo compara por identidade: o mesmo objeto que está na lista de opções é o que entra na lista de escolhidos. É o que a seção 7 mostra.

5. bind:group nos rádios

O rádio é um grupo por natureza: marcar um desmarca os outros. Com bind:group, a variável guarda o valor do escolhido, e não uma lista.

<script>
  let pagamento = $state('pix');
</script>

<input type="radio" value="pix" bind:group={pagamento}>
<input type="radio" value="cartao" bind:group={pagamento}>
<p>Pago com {pagamento}</p>
<input type="radio" value="pix" checked=""/> <input type="radio" value="cartao"/> <p>Pago com pix</p>

O estado inicial escolhe o primeiro rádio, e o servidor manda o atributo checked="" nele. Trocar para cartão muda a variável para "cartao" e desmarca o primeiro. Não existe lista aqui: existe um valor, que é sempre o do rádio marcado.

Uma consequência prática: se o estado começar vazio ($state('')), nenhum rádio aparece marcado, e o parágrafo mostra o rótulo sem valor. Isso é útil para forçar uma escolha consciente, mas exige validação antes de enviar o formulário. Formulários de pagamento costumam começar vazios justamente para não induzir o cliente a escolher o primeiro item por preguiça.

Missão: os rádios estão no grupo, mas não têm value: escolher cartão deixa o parágrafo sem valor. Dê um valor a cada rádio para que a escolha mostre Pago com cartao.

<script>
  let pagamento = $state('');
</script>

<p>Pago com {pagamento}</p>
<input type="radio" id="pix" bind:group={pagamento}>
<input type="radio" id="cartao" bind:group={pagamento}>
<script>
  let pagamento = $state('');
</script>

<p>Pago com {pagamento}</p>
<input type="radio" id="pix" value="pix" bind:group={pagamento}>
<input type="radio" id="cartao" value="cartao" bind:group={pagamento}>

Sem value, o rádio não tem o que entregar ao grupo e a variável recebe undefined. O parágrafo então mostra o rótulo e nada depois. O sintoma é silencioso — nenhum erro, nenhum aviso —, e por isso vale conferir o value antes de culpar o binding.

6. Começando com itens já marcados

Quando o estado já tem itens, as caixas correspondentes aparecem marcadas no HTML do servidor. Basta que o valor da lista seja igual ao valor da caixa.

<script>
  let frutas = $state(['pera']);
</script>

<label><input type="checkbox" value="pera" bind:group={frutas}> pera</label>
<label><input type="checkbox" value="uva" bind:group={frutas}> uva</label>
<p>{frutas.length} fruta(s)</p>
<label><input type="checkbox" value="pera" checked=""/> pera</label> <label><input type="checkbox" value="uva"/> uva</label> <p>1 fruta(s)</p>

É assim que um formulário de edição abre com os dados salvos: a lista vem do armazenamento, cada caixa confere se o seu valor está nela e se marca. Nada de percorrer o DOM procurando caixas; o binding faz a conferência a cada render.

O mesmo vale para desmarcar: se a lista muda por fora — um botão "limpar tudo", por exemplo —, as caixas se desmarcam sozinhas na próxima atualização. Você não precisa avisar cada caixa. Basta escrever frutas = [] e a tela obedece.

Missão: a lista começa com pera, mas a caixa não está de fato ligada ao valor dela: desmarcar não limpa a lista. Faça o grupo funcionar para que desmarcar pera mostre nenhuma.

<script>
  let frutas = $state(['pera']);
</script>

<p>{frutas.length === 0 ? 'nenhuma' : frutas.join(', ')}</p>
<label><input type="checkbox" id="pera" bind:group={frutas}> pera</label>
<label><input type="checkbox" id="uva" bind:group={frutas}> uva</label>
<script>
  let frutas = $state(['pera']);
</script>

<p>{frutas.length === 0 ? 'nenhuma' : frutas.join(', ')}</p>
<label><input type="checkbox" id="pera" value="pera" bind:group={frutas}> pera</label>
<label><input type="checkbox" id="uva" value="uva" bind:group={frutas}> uva</label>

O detalhe que faz a solução funcionar é o value: sem ele, a caixa não corresponde ao item 'pera' que já estava na lista, e desmarcar não remove nada. Com ele, a caixa reconhece o próprio valor e o grupo consegue tirar da lista. É o mesmo value da seção 4, agora fazendo diferença visível.

7. As opções vêm de uma lista

Quando as frutas estão num array, o componente monta as caixas com {#each}. O value de cada caixa aponta para o item, e o grupo guarda o item escolhido.

<script>
  let escolhidos = $state([]);
  const opcoes = [
    { id: 1, nome: 'pão' },
    { id: 2, nome: 'leite' }
  ];
</script>

{#each opcoes as opcao}
  <label><input type="checkbox" value={opcao} bind:group={escolhidos}> {opcao.nome}</label>
{/each}
<p>{escolhidos.length} escolhido(s)</p>
<label><input type="checkbox" value="[object Object]"/> pão</label><label><input type="checkbox" value="[object Object]"/> leite</label> <p>0 escolhido(s)</p>

O [object Object] no HTML é o que o navegador escreve quando o atributo recebe um objeto: ele converte para texto. Não é erro, e não impede o binding de funcionar, porque o Svelte guarda a referência do objeto em outro lugar. No navegador, marcar "leite" acrescenta o objeto inteiro à lista, e o contador mostra 1.

Essa é a forma mais prática quando os itens têm identificador, preço ou qualquer outro dado além do nome. Você guarda o objeto e tem tudo à mão; o texto do rótulo é só o que aparece. O custo é que a lista de escolhidos não é uma lista de strings: para comparar com o que veio do servidor, você precisa comparar os ids, não os objetos.

Para ver o efeito de uma lista no terminal, sem navegador, o comando abaixo mostra tamanho e pertinência:

ana@notebook:~/loja$ node -e "const f = ['pera', 'uva']; console.log(f.length, f.includes('uva'))"
2 true

É esse tipo de operação que o bind:group faz por baixo: verificar se o valor está na lista e agir de acordo. Saber o nome das operações ajuda a depurar quando o grupo não se comporta como esperado.

O build do projeto com os grupos no arquivo mostra o peso do conjunto. Cada caixa a mais custa alguns bytes, e o motor do Svelte já está no pacote desde o primeiro componente:

Trinta e sete kilobytes para um componente com dois grupos. Se a padaria tivesse cinquenta frutas, o tamanho mal mudaria: o que cresce é a lista de dados, não o código do binding. Essa é a vantagem de escrever o grupo uma vez e repetir com {#each}, em vez de copiar o atributo cinquenta vezes com nomes diferentes.

Uma última observação sobre desempenho, que vale para qualquer formulário: cada marcação percorre a lista para achar o valor. Com três ou trinta itens isso é instantâneo. Com milhares, o custo aparece — e aí a solução não é trocar o binding, é repensar a tela, porque ninguém marca mil caixas de uma vez.

8. O que a variável recebe em cada caso

ElementoEstado inicialDepois de marcar
checkbox com value="pera"[]['pera']
checkbox com value="pera" já marcado['pera'][] ao desmarcar
radio com value="cartao"'''cartao'
radio sem value''undefined
checkbox com estado de texto'pera'o valor deixa de ser texto e a tela esvazia

A última linha é a que mais surpreende. O grupo de caixas espera uma lista; se você começar com texto, o binding trata o valor como se fosse uma lista e o resultado não é o que você imaginava. O sintoma é a tela esvaziar depois do primeiro clique. A correção é sempre começar com $state([]) quando o grupo é de caixas, e com $state('') quando é de rádios.

Vale destacar também o caso do rádio sem value: a variável recebe undefined, e o Svelte mostra vazio onde você esperava texto. Nenhum erro aparece, porque tecnicamente nada deu errado. Esse é o tipo de problema que só se encontra lendo o código com atenção — ou testando com um valor visível na tela.

9. Quando dá errado

Erro 1 — bind:group em select

Grupo é coisa de <input>. A lista suspensa tem binding próprio: bind:value.

<script>
  let x = $state([]);
</script>

<select bind:group={x}>
  <option value="a">a</option>
</select>
Erro de compilação (linha 5, coluna 8): `bind:group` can only be used with `<input>`

A mensagem diz "só pode ser usado com <input>". Troque por bind:value={x} e ajuste o tipo da variável para o que a lista devolve. Se você quer várias escolhas numa lista suspensa, use <select multiple> com bind:value e uma variável de lista.

Erro 2 — grupo ligado a uma constante

O grupo escreve na variável a cada marcação. Uma constante não aceita escrita.

<script>
  const frutas = ['pera'];
</script>

<label><input type="checkbox" value="pera" bind:group={frutas}> pera</label>
<p>{frutas.length}</p>
Erro de compilação (linha 5, coluna 43): Cannot bind to constant

A coluna aponta para o nome dentro das chaves. Troque const por let e acrescente a runa: let frutas = $state(['pera']). Sem $state, o binding compila mas a tela não acompanha.

Erro 3 — dois grupos no mesmo elemento

Um input pertence a um grupo só. Dois atributos iguais deixam o compilador sem saber qual variável recebe o valor.

<script>
  let a = $state([]);
  let b = $state([]);
</script>

<input type="checkbox" bind:group={a} bind:group={b}>
Erro de compilação (linha 6, coluna 38): Attributes need to be unique

A saída é escolher um grupo. Se a intenção era uma caixa que alimenta duas listas, escreva um handler que atualize as duas, em vez de dois bindings. O compilador está protegendo você de uma ambiguidade que não teria resposta certa.

Exercícios

1. Qual estado combina com um grupo de caixas de marcar?

2. O que o grupo guarda quando um rádio é marcado?

3. O que costuma acontecer quando a caixa não tem value?

Complete o código

let frutas = $state([]);

<label><input type="checkbox" value="pera" > pera</label>
<p>{frutas.length} fruta(s)</p>

// marcar a caixa acrescenta "pera" à lista

Resumo

  • bind:group liga várias caixas de uma mesma pergunta a uma variável.
  • Grupo de checkbox com lista: cada marcação acrescenta o value; cada desmarcação tira.
  • Grupo de radio com valor simples: a variável guarda o value do escolhido.
  • O value de cada caixa é a identidade dela dentro do grupo; sem ele, o resultado é imprevisível.
  • A ordem da lista é a ordem das marcações, não a ordem da tela.
  • Estado inicial com itens já marcados faz o servidor mandar checked="" nas caixas certas.
  • Com {#each}, o value aponta para o item e o grupo guarda o item inteiro.
  • Erros desta aula: bind:group fora de input, grupo em constante e dois grupos no mesmo elemento.
  • Rádio sem value deixa a variável undefined, sem erro nenhum na tela.
