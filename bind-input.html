Svelte · bind:value

O balcão da Ana tem dois campos que ela usa o dia inteiro: um para a quantidade de pães e outro para a observação do pedido ("sem sal", "bem assado"). Ela quer que os dois estejam ligados ao caderno de pedidos, mas existe uma diferença entre eles: quantidade é número, observação é texto. O bind:value funciona nos dois, mas o que ele entrega muda conforme o tipo do campo. Esta aula passa campo por campo, com a saída de verdade do compilador.

Você vai aprender
  • Como o bind:value se comporta em campo de texto comum.
  • Por que type="number" entrega número e o campo sem tipo entrega texto.
  • O que acontece quando a pessoa apaga tudo de um campo numérico.
  • Como ligar uma área de texto sem usar o conteúdo das tags.
  • Como funciona o controle deslizante (range) com binding.
  • Como ligar um campo por item de uma lista, usando o índice.
  • Por que ligar em item não compila e o que fazer no lugar.
  • O aviso que o compilador dá quando o estado não é reativo.
  • Os três erros reais desta aula, com a mensagem do compilador.

1. A ideia: cada campo guarda um tipo de coisa

Um campo de texto e um campo de número parecem iguais na tela: uma caixinha branca onde se digita. Por dentro, são coisas diferentes. O campo de texto devolve uma sequência de caracteres; o campo de número devolve um valor numérico, ou nada, quando está vazio. Quem decide é o atributo type, não o binding. O bind só transporta o que o campo produz.

Essa diferença importa porque o JavaScript trata texto e número de formas diferentes. Somar dois números dá uma soma; somar texto com número dá colagem. Se a Ana digita 7 no campo de quantidade e o valor chega como texto, o dobro aparece como 77 em vez de 14. O erro não está no bind: está no tipo do campo.

Existe também a questão do vazio. Num campo de texto, vazio é uma string vazia — um valor válido. Num campo de número, vazio não é zero: é ausência de valor, representada por null. Confundir os dois faz a conta virar NaN e a tela mostrar "NaN" para o cliente, o que nunca é boa notícia.

A tabela inteira cabe numa frase: o binding entrega o que o campo vale, e o campo vale conforme o tipo. Se você lembrar disso, metade dos problemas de formulário desaparece. A outra metade é o binding em listas, que tem seção própria aqui.

3. bind:value no campo de texto

<script>
  let apelido = $state('Ana');
</script>

<input bind:value={apelido}>
<p>Apelido: {apelido}</p>

O valor inicial aparece no campo e no parágrafo. Cada tecla muda os dois ao mesmo tempo, porque existe uma variável só. O HTML que o servidor manda já vem com o valor no atributo:

<input value="Ana"/> <p>Apelido: Ana</p>
<input>
sem atributo type, o navegador assume texto. É o campo mais simples e o mais usado.
bind:value
liga o conteúdo do campo à variável. O compilador gera o evento que lê o campo e o efeito que reescreve o campo quando o estado muda.
{apelido}
o lugar onde o valor aparece. Tudo o que está em $state pode ser mostrado nas chaves.
value="Ana"
o que o servidor manda. Se o JavaScript falhar, a pessoa ainda vê o valor inicial — uma vantagem discreta do Svelte sobre montar tudo no navegador.

Repare que o atributo do HTML se chama value, sem bind:. O prefixo é uma instrução para o compilador, não um atributo que vai para o navegador. O navegador só entende value; o Svelte entende bind:value e traduz.

Esse detalhe explica uma confusão frequente ao inspecionar a página: você procura bind:value no HTML do navegador e não acha. Não é erro de digitação nem de compilação. O atributo que chega ao navegador é sempre value, e a ligação em duas vias vive no JavaScript do componente.

4. Número não é texto

Para receber número, o campo precisa declarar que é numérico. O binding é o mesmo; o tipo muda o que chega na variável.

<script>
  let quantidade = $state(1);
</script>

<input type="number" bind:value={quantidade}>
<p>Pães: {quantidade}</p>
<input type="number" value="1"/> <p>Pães: 1</p>

O HTML mostra o tipo e o valor. Se a Ana digitar 12, a variável recebe o número 12, e não a string "12". Isso permite somar, comparar com zero e formatar com toFixed sem conversão. O build deste componente pesa pouco mais do que o anterior:

Trinta e sete kilobytes, um pouco acima do componente de texto porque o campo numérico carrega a conversão embutida. No terminal, a diferença entre os dois tipos fica clara:

ana@notebook:~/loja$ node -e "console.log('7' + 7, 7 + 7)"
77 14

A primeira conta usou texto e colou os caracteres; a segunda usou números e somou. É exatamente a diferença entre um campo sem tipo e um campo type="number". Note que o navegador também muda o teclado no celular: com type="number", abre o teclado numérico, o que já é um ganho de usabilidade.

Existe um detalhe do HTML que confunde: o campo numérico aceita a letra e (para notação científica) e os sinais + e -, porque fazem parte de números válidos. Se você precisa de inteiros positivos, combine o tipo com min="0" e step="1" e valide no handler. O tipo ajuda, mas não substitui a validação.

5. O campo vazio vira null

Apagar tudo de um campo numérico não produz zero. Produz ausência de valor, que o Svelte entrega como null.

<script>
  let gramas = $state(null);
</script>

<input type="number" bind:value={gramas}>
<p>Gramas: {gramas}</p>
<input type="number"/> <p>Gramas: </p>

No HTML, um valor null simplesmente não vira atributo: o campo sai vazio, sem value. No parágrafo, {gramas} com null não imprime nada. Isso é conveniente para "ainda não preencheu", mas é uma armadilha para contas: null + 1 dá 1 em JavaScript, e null * 2 dá 0. O resultado não é o que a Ana espera.

Duas saídas comuns. A primeira é começar com zero e tratar o campo como obrigatório: let gramas = $state(0). A segunda é checar antes de calcular: {gramas === null ? '—' : gramas * 2}. O importante é escolher uma e ser consistente; metade dos bugs de formulário nasce de um campo que às vezes é número e às vezes é null.

Missão: o campo é numérico, mas o valor chega como texto e o dobro sai colado (77). Troque o evento por bind:value para o dobro virar 14 quando a pessoa digitar 7.

<script>
  let n = $state(0);
</script>

<p>Dobro: {n + n}</p>
<input type="number" oninput={(e) => (n = e.target.value)}>
<script>
  let n = $state(0);
</script>

<p>Dobro: {n + n}</p>
<input type="number" bind:value={n}>

A missão parece pequena, mas ela mostra o motivo de o binding existir: o campo sabe qual é o tipo do valor, e o bind pergunta ao campo. O oninput só sabe que houve uma alteração e devolve o texto cru. Quem escreve evento.target.value está pegando o texto, não o número — mesmo num campo numérico.

6. Área de texto e controle deslizante

A área de texto tem uma peculiaridade de HTML: o valor dela fica entre as tags, não num atributo. Por isso value={texto} não funciona nela; o certo é o binding.

<script>
  let observacao = $state('');
</script>

<textarea bind:value={observacao}></textarea>
<p>Observação: {observacao}</p>
<textarea></textarea> <p>Observação: </p>

O compilador gera uma área de texto vazia e liga o conteúdo ao estado. Se você escrever texto entre as tags, ele serve de valor inicial apenas enquanto o estado não manda nada; com o binding, quem manda é a variável. Para a observação da Ana, é o campo certo: aceita várias linhas e preserva as quebras.

O controle deslizante é o inverso: o valor é sempre numérico e sempre dentro de uma faixa. Ele combina com min, max e step.

<script>
  let intensidade = $state(3);
</script>

<input type="range" min="0" max="10" bind:value={intensidade}>
<p>Força: {intensidade}</p>
<input type="range" min="0" max="10" value="3"/> <p>Força: 3</p>

O valor inicial 3 aparece como value="3" e posiciona o botão no meio da faixa. Arrastar atualiza a variável com um número; não existe texto no meio do caminho. Bom para escolher a força do forno, a quantidade de açúcar ou o nível de dificuldade de um jogo.

Missão: a área de texto não está ligada ao estado. Faça o parágrafo mostrar o que for escrito nela: digitando oi, deve aparecer Observação: oi.

<script>
  let observacao = $state('');
</script>

<p>Observação: {observacao}</p>
<textarea id="obs"></textarea>
<script>
  let observacao = $state('');
</script>

<p>Observação: {observacao}</p>
<textarea id="obs" bind:value={observacao}></textarea>

A tag textarea no HTML não tem atributo value; quem tenta usar um recebe uma área vazia e um estado parado. O binding resolve porque o compilador sabe que, nesse elemento, o valor é o conteúdo e gera o código certo. Esse é um exemplo de decisão que o Svelte toma por você e que seria fácil errar à mão.

7. Um campo por item da lista

A lista de compras da Ana tem itens que ela quer editar na tela. O caminho é um campo para cada item, ligado à posição, não à variável do laço.

<script>
  let itens = $state(['pão', 'leite']);
</script>

{#each itens as item, i}
  <input bind:value={itens[i]}>
{/each}
<p>{itens.join(', ')}</p>
<input value="pão"/><input value="leite"/> <p>pão, leite</p>

O bloco {#each} repete o campo duas vezes, e o índice i diz qual posição cada campo deve editar. O binding aponta para itens[i], um endereço dentro da lista. Quando a Ana digita no primeiro campo, o primeiro item muda e o parágrafo se atualiza.

O caminho que parece mais natural — bind:value={item} — não compila em modo de runas. O compilador explica que a variável do laço é uma cópia do valor, não um lugar onde se pode gravar. A mensagem é longa e aparece na íntegra na seção 9, porque vale ler uma vez na vida.

Missão: só existe um campo, ligado a uma variável solta, e a lista nunca muda. Crie um campo por item, ligado à posição, para que digitar uva no primeiro campo deixe Lista: uva, leite.

<script>
  let itens = $state(['pão', 'leite']);
  let avulso = $state('');
</script>

<p>Lista: {itens.join(', ')}</p>
<input bind:value={avulso}>
<script>
  let itens = $state(['pão', 'leite']);
</script>

<p>Lista: {itens.join(', ')}</p>
{#each itens as item, i}
  <input bind:value={itens[i]}>
{/each}

Existe uma alternativa que você vai encontrar em código de terceiros: ligar em uma propriedade do item, como bind:value={item.nome}. Funciona quando o item é um objeto, porque aí a variável do laço aponta para o mesmo objeto da lista. Com texto puro, não funciona: texto é imutável, e trocar o texto de uma variável não troca o texto da lista. O índice resolve os dois casos.

8. Quando o estado não é reativo

O binding escreve na variável. Se ela não foi criada com $state, o valor muda e a tela não acompanha. O compilador percebe isso em muitos casos e avisa:

non_reactive_update — "`nome` is updated, but is not declared with `$state(...)`. Changing its value will not correctly trigger updates". A tradução: a variável é atualizada, mas não foi declarada com $state; mudar o valor não dispara atualização.

O aviso não impede o componente de rodar. No primeiro momento parece tudo certo: o campo mostra o valor inicial, a pessoa digita, o valor da variável muda. O que não acontece é o redesenho do resto da tela. Você vê o campo mudando (o navegador cuida dele) e o parágrafo parado, e conclui que o binding está quebrado quando o problema é a declaração.

Vale a pena entender por que o campo continua mudando. O texto que aparece dentro do campo é responsabilidade do navegador: ele recebe a tecla, escreve o caractere e não pede licença para ninguém. O Svelte só é avisado do evento e copia o valor para a variável. Se a variável não é reativa, a cópia acontece e ninguém é notificado. O campo, que não depende do Svelte para se desenhar, continua certo; o resto da tela, que depende, fica para trás.

Essa diferença entre aviso e erro também merece atenção. Um erro impede a compilação: nada é gerado e a página não abre. Um aviso deixa o projeto compilar e aponta um risco. non_reactive_update é aviso, e o risco é exatamente o parágrafo parado que descrevi. Trate aviso como pergunta: "eu quis isso mesmo?". Quando a resposta é não, corrija antes de seguir.

DeclaraçãoO que o binding fazA tela acompanha?
let nome = $state('')grava e avisasim
let nome = ''grava, sem avisarnão
const nome = 'Ana'não compila—
let nome = $derived(x)grava em valor calculado, sem sentidonão deveria nem tentar

A última linha merece um comentário. $derived é para valores que vêm de outros valores; um campo ligado a ele é uma contradição: a pessoa digita e o valor é recalculado a partir da fonte. O compilador não impede em todos os casos, mas o comportamento não vai ser o que você quer. Aula própria, mais adiante, trata de $derived.

9. Quando dá errado

Erro 1 — binding sem variável declarada

A forma curta bind:value procura uma variável chamada value. Se ela não existe, o compilador não tem onde gravar.

<script>
  let nome = $state('Ana');
</script>

<input bind:value>
Erro de compilação (linha 5, coluna 12): Can only bind to state or props

"Can only bind to state or props" quer dizer "só posso ligar a estado ou a propriedades". Escreva a forma longa com o nome da variável: bind:value={nome}. Se você realmente quer a curta, a variável precisa se chamar value.

Erro 2 — esqueceu as chaves

O valor do binding é uma expressão entre chaves, como no onclick. Escrever o nome da variável entre aspas não vale.

<script>
  let grupo = $state([]);
</script>

<input type="checkbox" bind:group="grupo">
Erro de compilação (linha 5, coluna 35): Directive value must be a JavaScript expression enclosed in curly braces

A mensagem é comprida porque vale para qualquer diretiva, não só para bind: "o valor da diretiva precisa ser uma expressão JavaScript entre chaves". Troque "grupo" por {grupo}. Aspas são para texto no HTML; chaves são para valores do script.

Erro 3 — binding na variável do laço

Em {#each}, a variável depois do as é uma cópia. O compilador recusa gravar nela e indica o caminho com índice.

<script>
  let lista = ['pão', 'leite'];
  let item = $state('');
</script>

{#each lista as nome}
  <input bind:value={nome}>
{/each}
Erro de compilação (linha 7, coluna 9): Cannot reassign or bind to each block argument in runes mode. Use the array and index variables instead (e.g. `array[i] = value` instead of `entry = value`, or `bind:value={array[i]}` instead of `bind:value={entry}`)

É uma das mensagens mais úteis do compilador: ela não só proíbe como mostra o código certo. Troque o laço por {#each lista as nome, i} e o campo por bind:value={lista[i]}. Só lembre de declarar a lista com $state, senão a tela não acompanha.

Resumo

  • bind:value entrega o valor do campo conforme o tipo dele.
  • Campo de texto devolve string; type="number" devolve número ou null.
  • Vazio num campo numérico é null, não zero: cuide da conta antes de multiplicar.
  • Em <textarea> o valor é o conteúdo, não o atributo; use bind:value.
  • range devolve número dentro de min e max, e também usa bind:value.
  • Em lista, ligue por índice: bind:value={itens[i]}, nunca em item.
  • O estado precisa de $state; sem isso o compilador avisa non_reactive_update.
  • Erros desta aula: binding sem variável, valor entre aspas e binding na variável do laço.
  • O tipo do campo abre teclado numérico no celular e ajuda na usabilidade, mas não substitui validação.
