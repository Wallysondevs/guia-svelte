Svelte · class: e Estilo por Condição

A Ana usa etiquetas coloridas nos potes da cozinha: verde para o que está pronto, amarelo para o que está acabando. A etiqueta não muda o conteúdo do pote — muda o que ela vê de longe e o que os funcionários entendem sem abrir. Em CSS, a classe é essa etiqueta, e o Svelte tem uma diretiva para colar e descolar a etiqueta conforme uma condição: class:verde={acabando}. Nesta aula você aprende a ligar e desligar classes, o que o compilador gera por baixo e quando vale usar estilo direto.

Você vai aprender
  • O que é uma classe e por que ela é a etiqueta do CSS.
  • A forma abreviada class:verde, que usa a variável de mesmo nome.
  • A forma completa class:verde={condição}.
  • Como combinar uma classe fixa com várias condicionais.
  • O que o compilador gera: $.set_class com um objeto de classes.
  • Como a classe condicional convive com o CSS escopado do componente.
  • Quando usar class={expressão} em vez da diretiva.
  • A diretiva style: para um ajuste pontual.
  • Os erros reais: valor vazio, valor entre aspas e nome de classe ausente.

1. A ideia: a etiqueta que muda de cor

Na padaria da Ana, cada pote tem uma etiqueta com o nome do conteúdo. Alguns potes ganham uma segunda etiqueta, colorida, que muda conforme a situação: verde quando está cheio, amarela quando está acabando. A segunda etiqueta não tem texto novo, não muda o pote, não muda o conteúdo — muda a leitura de quem passa.

Em CSS, a classe é a etiqueta: um nome que aparece no atributo class e que as regras de estilo procuram. Um elemento pode ter várias classes, separadas por espaço. Quem decide quais regras valem é a combinação de classes, não a ordem em que aparecem.

A diferença no Svelte é que a etiqueta pode ser colada e descolada por uma condição, sem você escrever a lista de classes à mão. A diretiva class: faz isso com uma sintaxe curta e um comportamento previsível: se a condição é verdadeira, a classe entra; se é falsa, a classe sai.

2. A forma abreviada: class:verde

Quando a variável tem o mesmo nome da classe, você pode omitir o valor. O compilador entende que a condição é a própria variável:

<script>
  let ativo = $state(true);
  let grande = $state(false);
</script>

<p class:verde={ativo} class:grande={grande}>pão</p>

<style>
  .verde { color: #2e7d32; }
  .grande { font-size: 24px; }
</style>
<p class="svelte-1n46o8q verde">pão</p>

A saída tem duas classes: svelte-1n46o8q, o selo do escopo que o compilador colocou, e verde, a classe que a condição liberou. grande não apareceu porque a variável vale falso. Não há class="svelte-1n46o8q" vazia sobrando: o atributo é montado com o que vale.

As três partes da diretiva, uma por uma:

class:
o prefixo que avisa o Svelte de que aquilo não é um atributo comum. Tudo o que vem depois dos dois-pontos é nome de classe.
verde
o nome da classe, escrito sem ponto. No CSS ele aparece como .verde, com ponto; no HTML e na diretiva, sem. É a mesma palavra nos dois lugares.
={condição}
o valor, opcional. Sem ele, o Svelte procura uma variável com o mesmo nome da classe e usa o valor dela. Com ele, usa a expressão que você escreveu.

Quando o valor não é escrito, a regra é simples: existe uma variável com o mesmo nome, e ela decide. Por isso class:verde só funciona se houver um verde no script — se não houver, o compilador reclama que o nome não existe, do mesmo jeito que reclamaria de {verde} solto no HTML.

Vale saber o que conta como verdadeiro. O Svelte usa a regra do JavaScript: são falsos false, 0, a string vazia '', null e undefined. Todo o resto é verdadeiro — inclusive a string 'false', que é texto e não o valor falso. Esse detalhe já confundiu muita gente: uma variável que veio de um campo de formulário chega como texto, e 'false' liga a classe.

Missão: o parágrafo tem a classe destaque, mas a etiqueta certa é verde e ela deve ser condicional. Use a forma abreviada class:verde — sem chaves, sem valor — para o HTML gerado ficar com class="verde".

<script>
  let verde = $state(true);
</script>

<p class="destaque">pão</p>
<script>
  let verde = $state(true);
</script>

<p class:verde>pão</p>

Repare que a solução não tem = nem chaves: só o nome da classe. Se você escrevesse class:verde={verde}, o resultado seria idêntico — a forma longa é o que a abreviada significa. Escolha uma e mantenha o estilo no arquivo inteiro; misturar as duas formas na mesma página só dificulta a leitura de quem vem depois.

O limite da forma abreviada aparece quando a condição não cabe no nome de uma variável. Uma comparação, uma negação, uma chamada de função: nada disso tem nome de classe. Para esses casos existem as chaves, que é o assunto do próximo capítulo.

3. A forma completa: class:verde={condição}

Com chaves, o valor pode ser qualquer expressão que resulte em verdadeiro ou falso: uma comparação, uma negação, uma chamada de função. É o caso mais comum no dia a dia:

<script>
  let preco = $state(2.5);
</script>

<p class:caro={preco > 2}>R$ {preco.toFixed(2)}</p>
<p class="caro">R$ 2.50</p>

O HTML gerado mostra a classe caro no elemento, porque 2.5 é maior que 2. O preço aparece como R$ 2.50 por causa do toFixed(2), que fixa duas casas decimais. Se o preço caísse para 1.9, a classe sumiria do atributo e o texto ficaria R$ 1.90.

Aqui a classe caro entra quando o preço passa de 2. Se o preço mudar para 1.90, a classe sai e a etiqueta muda sozinha. Você não escreve if nem manipula o atributo: descreve a condição e o Svelte cuida do resto.

Uma coisa que a diretiva não faz é calcular o estilo. Ela só liga e desliga a classe; quem pinta é o CSS. Isso parece detalhe e é o que mantém o componente legível: a regra visual fica no bloco <style>, e a condição fica no HTML. Quando alguém quiser mudar a cor do "caro", mexe no CSS; quando quiser mudar o limite, mexe na condição.

4. Combinando classe fixa e condicional

Você pode ter uma classe que sempre existe e outra que aparece conforme a situação. Basta usar os dois atributos na mesma tag:

<script>
  let caro = $state(true);
</script>

<p class="preco" class:destaque={caro}>R$ 2</p>
<p class="preco destaque">R$ 2</p>

O resultado é class="preco destaque": a classe fixa vem primeiro, a condicional é acrescentada. Se caro fosse falso, sobraria só preco. Essa mistura é a forma mais comum de usar a diretiva, porque quase todo elemento já tem uma classe base.

Ordem das classes no atributo não muda o resultado visual, mas ajuda na leitura: coloque primeiro a classe que identifica o componente, depois as condicionais. E tome cuidado com duas fontes de verdade — se a classe fixa também for controlada por uma variável, você terá o mesmo nome em dois lugares e um deles vai vencer sem aviso.

Missão: o parágrafo tem a classe fixa preco e precisa receber destaque quando caro for verdadeiro. Use a diretiva class:destaque={caro}.

<script>
  let caro = $state(true);
</script>

<p class="preco">R$ 2</p>
<script>
  let caro = $state(true);
</script>

<p class="preco" class:destaque={caro}>R$ 2</p>

A meta desta caixa confere o HTML gerado, e não o texto: é a única forma de verificar que a classe entrou. Repare que o HTML esperado é exatamente <p class="preco destaque">R$ 2</p>, com as duas classes na ordem em que o compilador as escreve.

5. O que o compilador gera

A diretiva não vira uma lista de if no seu código. O compilador gera uma chamada só, com um objeto que descreve as classes condicionais:

ana@notebook:~/loja$ node -e "const {compile}=require('svelte/compiler');console.log(compile(require('fs').readFileSync('src/App.svelte','utf8'),{generate:'client',filename:'src/App.svelte'}).js.code)"
import 'svelte/internal/init-operations';
import 'svelte/internal/disclose-version';
import * as $ from 'svelte/internal/client';

var root = $.from_html(`
pão
`);

export default function App($$anchor) {
	let ativo = true;
	let grande = false;
	var p = root();

	$.set_class(p, 1, 'svelte-1n46o8q', null, {}, { verde: ativo, grande });
	$.append($$anchor, p);
}

A linha importante é $.set_class(p, 1, 'svelte-1n46o8q', null, {}, { verde: ativo, grande }). O último argumento é o mapa de classes condicionais: verde vale ativo, grande vale grande. O motor percorre esse mapa e liga as classes cujo valor é verdadeiro. Como o estado nunca muda neste exemplo, o compilador até simplificou os valores para constantes.

O 1 e o 'svelte-1n46o8q' são o selo do escopo. Eles aparecem porque o componente tem <style>: o motor precisa manter a classe do selo junto com as condicionais, sem nunca removê-la. Se o componente não tivesse estilo, essa parte seria diferente.

6. A classe condicional e o CSS escopado

O bloco de estilo do componente é escopado, e as classes que você usa nele também recebem o selo. O CSS gerado para o exemplo anterior:

.verde.svelte-1n46o8q { color: #2e7d32; }
  .grande.svelte-1n46o8q { font-size: 24px; }

Repare na forma: .verde.svelte-1n46o8q significa "elemento que tem a classe verde e o selo". É por isso que a classe condicional funciona: no HTML gerado, o elemento recebe os dois quando a condição é verdadeira, e a regra encontra exatamente ele.

Depois do build, o CSS vira um arquivo comprimido com o mesmo conteúdo, e o seletor continua com o selo:

Repare também no que não aparece: o selo não é escrito no bloco de estilo por você. Você escreve .verde e o compilador acrescenta .svelte-1n46o8q. Fazer isso à mão, além de trabalhoso, daria errado na primeira vez que o arquivo fosse renomeado — o hash muda com o caminho do arquivo, e a aula sobre erros de compilação mostra isso acontecendo.

Uma consequência prática: classe condicional que não existe no bloco de estilo não pinta nada. Ela aparece no HTML, mas nenhuma regra a usa — e o compilador avisa com css_unused_selector quando é o contrário, isto é, quando uma regra do estilo nunca encontra elemento. Nos dois casos, o sintoma é o mesmo: a tela não muda, e o problema está na ligação entre a classe e a regra.

7. class={expressão} em vez da diretiva

A diretiva é conveniente para uma classe condicional. Quando a lista de classes é montada como texto — por exemplo, com uma função que devolve a lista inteira —, o atributo comum com chaves resolve:

<script>
  let cor = $state('green');
</script>

<p class="preco {cor}">R$ 2</p>
<p class="preco green">R$ 2</p>

Aqui a classe vem de uma variável que contém o nome, e o texto fixo preco convive com ele. Funciona, mas exige disciplina: se cor vier vazia, sobra um espaço no atributo; se vier com espaços, viram duas classes. A diretiva não tem esse problema porque trabalha com nomes, não com texto.

Existe uma diferença de comportamento que vale conhecer. Na diretiva, o Svelte guarda o nome da classe como um identificador e liga ou desliga sem tocar no resto do atributo. No atributo comum com chaves, todo o texto é recalculado quando qualquer pedaço muda. Para o navegador o resultado é parecido; para quem depura, a diretiva é mais previsível, porque cada classe tem um nome e um lugar só.

A regra que o guia usa: uma ou duas classes condicionais, use class:; lista dinâmica que vem pronta de uma função ou de um objeto, use class={...}. E nunca os dois para a mesma classe — o resultado fica imprevisível e difícil de depurar.

8. style: para um ajuste pontual

Existe uma diretiva irmã, para quando você precisa mudar uma propriedade de estilo direto no elemento, sem criar uma classe. Ela se chama style: e recebe o nome da propriedade CSS:

<script>
  let cor = $state('green');
</script>

<p style:color={cor} style:padding="4px">pão</p>
<p style="color: green; padding: 4px;">pão</p>

Duas diretivas na mesma tag geram um único atributo style, com as propriedades separadas por ponto e vírgula — inclusive o ponto e vírgula final. Se o valor for nulo ou falso, a propriedade é removida. Se você escrever style:color sem valor e existir uma variável color, a forma abreviada funciona como na classe.

O custo do style: é que o estilo sai do bloco <style> e vai para o HTML, onde é mais difícil de achar depois. Use para o que realmente é dinâmico e pontual: uma cor que vem de configuração, uma largura calculada, uma posição de arraste. Para o resto, classe — de preferência condicional.

Missão: o parágrafo não tem estilo nenhum. Use a diretiva style:color={cor} para que o HTML gerado fique com style="color: green;".

<script>
  let cor = $state('green');
</script>

<p>pão</p>
<script>
  let cor = $state('green');
</script>

<p style:color={cor}>pão</p>

A meta confere o atributo style no HTML, com o ponto e vírgula que o compilador acrescenta. Se você escrevesse style="color: {cor}" — o atributo comum — o resultado seria parecido, mas sem o ponto e vírgula final, e a conferência falharia. Detalhe bobo que obriga a olhar a saída real em vez de adivinhar.

9. Quando a classe não aparece

O sintoma mais comum com class: é a classe não aparecer. Três causas cobrem quase todos os casos. A primeira: a condição é falsa sem você perceber — um undefined, uma string vazia, um zero. Vale imprimir o valor na tela por um instante para conferir, ou usar uma comparação explícita.

A segunda: a classe aparece no HTML, mas não há regra para ela. Confira se o nome está escrito igual nos dois lugares — verde no HTML e .verde no CSS. O compilador não sabe que você queria outra coisa; ele só liga e desliga o nome que você deu.

A terceira: a regra existe, mas perde na disputa de especificidade. Uma regra com !important em outro lugar vence a sua, e a cor não muda. Para investigar, abra o inspetor do navegador e veja quais regras estão riscadas — as riscadas são as que perderam. É mais rápido do que tentar adivinhar.

Quando duas regras do mesmo componente disputam o mesmo elemento, quem vence é a que aparece depois no bloco de estilo, desde que a especificidade seja igual. Duas classes no mesmo seletor, como .preco.destaque, vencem uma classe sozinha. Saber disso evita a tentação de espalhar !important pelo arquivo — sinal de que a ordem das regras precisa de atenção, não de força.

Existe ainda o caso de a classe ser removida pelo próprio Svelte: se você usa class:verde e também escreve class="verde" fixo na mesma tag, o compilador pode ficar com as duas fontes de verdade e o resultado depende da ordem. Não misture: escolha uma.

10. Quando dá errado

As três mensagens abaixo saíram do compilador desta versão. Todas são erros de sintaxe da diretiva, e nenhuma é óbvia na primeira leitura.

Erro 1 — valor vazio entre chaves

As chaves existem, mas não têm expressão dentro. O compilador esperava um valor.

<script>
  let ativo = $state(true);
</script>

<p class:verde={}>pão</p>
Erro de compilação (linha 5, coluna 16): Unexpected token

Apague as chaves e use a forma abreviada, ou coloque uma expressão: class:verde={ativo}. Chaves vazias costumam sobrar de uma edição pela metade.

Erro 2 — valor entre aspas

A diretiva espera uma expressão JavaScript, não texto. Com aspas, o compilador recusa e diz exatamente o que queria.

<script>
  let ativo = $state(true);
</script>

<p class:verde="sim">pão</p>
Erro de compilação (linha 5, coluna 16): Directive value must be a JavaScript expression enclosed in curly braces

A tradução é "o valor da diretiva precisa ser uma expressão JavaScript entre chaves". Escreva class:verde={ativo} ou class:verde={true} — e lembre de que "sim" seria verdadeiro de qualquer forma, então a aspa só atrapalhava.

Erro 3 — nome da classe ausente

Os dois-pontos ficaram sem nome depois. Não existe classe anônima.

<script>
  let ativo = $state(true);
</script>

<p class:={ativo}>pão</p>
Erro de compilação (linha 5, coluna 3): `class:` name cannot be empty

Escreva o nome: class:verde={ativo}. A posição aponta o dois-pontos, que é onde o compilador percebeu que faltava o nome.

Resumo

  • Classe é a etiqueta que o CSS procura; um elemento pode ter várias.
  • class:verde usa a variável de mesmo nome como condição.
  • class:verde={condição} é a forma completa, com expressão.
  • A classe fixa convive com as condicionais: class="preco" class:destaque={caro}.
  • O compilador gera $.set_class com um objeto de classes.
  • Com CSS escopado, a classe ganha o selo: .verde.svelte-1n46o8q.
  • class={lista} serve para listas prontas; não misture com a diretiva na mesma classe.
  • style:propriedade={valor} aplica estilo pontual e aceita a forma abreviada.
  • Os erros desta aula: chaves vazias, valor entre aspas e nome de classe ausente.
