Svelte · Componentes Dinâmicos

A Ana tem dois cartões impressos para a vitrine: o normal, com o preço cheio, e o de promoção, com o preço riscado. Ela não imprime os dois toda manhã — ela escolhe qual pendurar, conforme o dia. Na tela é a mesma ideia: às vezes o componente que aparece depende de um valor, e esse valor só é conhecido quando a página já está rodando. No Svelte 5 isso ficou mais simples do que era: um componente pode morar numa variável, e um elemento pode trocar de tag sozinho.

Você vai aprender

  • O que acontece com tag vazia, tag desconhecida e tag inválida.
  • Guardar um componente numa variável e desenhá-lo com <Atual />.
  • Passar props para o componente que está na variável.
  • Escolher conteúdo com {@render} e uma variável de snippet.
  • Por que <svelte:component> ficou para trás e o que usar no lugar.
  • Proteger a tela quando a escolha ainda é vazia.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • O que o terminal mostra ao procurar tags dinâmicas no projeto.
  • Quando escolher tag, quando escolher conteúdo e quando escolher componente.

1. A ideia: o cartão que muda de forma

Todo texto na tela tem uma tag em volta: um título é h1 ou h2, um parágrafo é p, um item de lista é li. Na maioria das vezes a tag é fixa, porque o papel do texto na página não muda. Mas existem casos em que muda: um mesmo componente de "título de seção" pode ser usado como h1 na capa e como h2 dentro de um bloco, para a página não ter dois títulos principais.

Antes de o Svelte ter tags dinâmicas, a saída era escrever o mesmo HTML três vezes dentro de um {#if}. Funciona e é ruim: o conteúdo aparece duplicado, e mudar uma classe exige lembrar dos três lugares. O <svelte:element> resolve isso deixando a tag vir de uma variável — um lugar só para o conteúdo, um valor para a forma.

Existe um segundo tipo de escolha, mais profundo: não é a forma do texto, é o componente inteiro que aparece. O cartão normal e o cartão de promoção têm marcações diferentes, props diferentes, talvez comportamentos diferentes. Ali a variável não guarda uma tag; guarda um componente. E o Svelte 5 permite isso sem nenhum componente especial, só escrevendo o nome da variável com maiúscula.

A terceira forma é a mais nova e a mais usada no dia a dia: escolher um pedaço de conteúdo — um snippet — e desenhá-lo com {@render}. Serve para quando as duas opções são parecidas e não valem um arquivo cada.

3. <svelte:element>: a tag vinda de um valor

A sintaxe é uma tag só, com o atributo this apontando para a variável que guarda o nome do elemento:

<script>
  let tag = $state('h2');
</script>

<svelte:element this={tag} class="titulo">Pão francês</svelte:element>
<button onclick={() => tag = 'p'}>virar p</button>
<h2 class="titulo">Pão francês</h2> <button>virar p</button>
<svelte:element>
um elemento que decide o próprio nome em tempo de execução. Não é um componente: é uma tag com nome variável.
this={tag}
a expressão que devolve o nome. Pode ser uma variável, um item de lista, uma função — desde que resulte em texto.
class="titulo"
os outros atributos funcionam normalmente. Se o atributo não existir na tag escolhida, ele fica no HTML do mesmo jeito.
Pão francês
o conteúdo é o mesmo para qualquer tag. É justamente por isso que ele não se repete no código.

No navegador, o clique troca o h2 por um p sem perder o texto: o Svelte desmonta o elemento antigo e monta o novo com os mesmos atributos e o mesmo conteúdo. A saída acima é a do servidor, antes de qualquer clique — o compilador não sabe qual tag vai estar lá quando a página abrir, então ele desenha a que o estado inicial aponta.

Trocar a tag não é trocar um atributo: é trocar o elemento. O Svelte desmonta o h2 inteiro e monta um p novo com o mesmo conteúdo. Para texto isso é invisível, mas tem um efeito colateral que vale saber: se o elemento tinha foco (um campo de formulário, por exemplo), ele perde o foco, porque é outro elemento no DOM. Se você precisa apenas mudar a aparência e manter o mesmo elemento, use class: em vez de svelte:element.

Use para títulos, listas e botões

O caso clássico é o título de seção que muda de nível. O segundo caso é o link que às vezes é botão: <svelte:element this={temLink ? 'a' : 'button'}>. Nos dois, o ganho é ter o conteúdo escrito uma vez só.

4. Quando a tag é vazia ou inválida

Duas armadilhas rondam o this. A primeira: se o valor for null ou uma string vazia, o elemento simplesmente não é desenhado. Nada de erro, nada de aviso — some o elemento e o conteúdo com ele:

<script>
  let tag = $state(null);
</script>

<svelte:element this={tag}>sumiu</svelte:element>
<p>depois</p>
<p>depois</p>

A segunda armadilha: um nome que não é um elemento válido do HTML. Um nome desconhecido mas plausível, como minha-tag, é aceito — o navegador desenha um elemento personalizado, sem estilo e sem comportamento:

<script>
  let tag = $state('minha-tag');
</script>

<svelte:element this={tag}>oi</svelte:element>
<minha-tag>oi</minha-tag>

Já um nome que não pode ser elemento — começando com número, por exemplo — derruba a renderização com uma mensagem própria, que aparece na seção 10. A diferença entre os dois casos é a gramática do HTML: nome de elemento não pode começar com dígito.

5. O componente numa variável

Para escolher entre componentes inteiros, o caminho é guardar o próprio componente numa variável e usar a variável como se fosse uma tag. Componentes importados são valores: dá para guardá-los, passá-los como prop e trocá-los.

<script>
  let { titulo } = $props();
</script>

<p>{titulo}</p>
<script>
  let { titulo } = $props();
</script>

<p>{titulo} (promoção)</p>
<script>
  import Cartao from './Cartao.svelte';
  import Promo from './Promo.svelte';

  let Atual = $state(Cartao);
</script>

<Atual titulo="Pão francês" />
<button onclick={() => Atual = Atual === Cartao ? Promo : Cartao}>trocar</button>

Três detalhes fazem esse código funcionar. Primeiro: o nome da variável começa com maiúscula — é assim que o compilador sabe que <Atual /> é um componente e não uma tag desconhecida do HTML. Segundo: a variável é $state, porque ela muda. Terceiro: as props funcionam normalmente, porque o componente escolhido recebe tudo o que está escrito na tag.

Para saber qual componente está na variável, compare com a referência: Atual === Cartao. Componentes importados são objetos únicos, então a comparação é segura — diferente de comparar texto, que sempre tem o risco de uma letra diferente.

Minúscula muda tudo

<Atual /> é o seu componente. <atual /> é uma tag HTML chamada atual, que o navegador desenha como um elemento vazio e sem estilo. O erro não dá mensagem: a tela fica em branco. Se um componente dinâmico "não aparece", a primeira coisa a conferir é a maiúscula.

6. {@render} com uma variável: o conteúdo escolhido

Nem toda escolha merece um arquivo. Se as duas opções são parecidas e vivem no mesmo componente, um snippet resolve: ele é um pedaço de marcação com nome, e o nome pode ficar numa variável. O {@render} desenha o que a variável apontar.

{#snippet Cartao(titulo)}
  <p>{titulo}</p>
{/snippet}

{#snippet Promo(titulo)}
  <p>{titulo} (promoção)</p>
{/snippet}

<script>
  let Mostrar = $state(Cartao);
</script>

{@render Mostrar('Pão francês')}
<button onclick={() => Mostrar = Mostrar === Cartao ? Promo : Cartao}>trocar</button>
<p>Pão francês</p> <button>trocar</button>

A saída é idêntica à da seção anterior, o que é o ponto: para o leitor da tela, tanto faz se a escolha foi entre componentes ou entre snippets. A diferença está no custo. Componente é um arquivo, com o seu script e a sua fronteira; snippet é uma função dentro do mesmo arquivo. Escolha componente quando as opções crescem sozinhas; escolha snippet quando são duas variações de uma coisa só.

Há um ganho escondido no snippet: como o código está no mesmo arquivo, as variáveis do componente estão no escopo. Um snippet consegue ler o estado da tela sem receber prop nenhuma; um componente separado precisaria de prop para tudo. É por isso que variações pequenas de layout costumam ficar em snippets e só as peças realmente independentes viram arquivo.

Repare que o snippet aceita parâmetros — Mostrar('Pão francês') passa o título. Isso é o que permite usar o mesmo snippet em vários lugares com valores diferentes, e é o assunto da aula de snippets.

Missão: o botão leva para a promoção e não volta mais. Faça ele alternar: um clique mostra a promoção, outro volta ao cartão normal.

{#snippet Cartao(titulo)}
  <p>{titulo}</p>
{/snippet}

{#snippet Promo(titulo)}
  <p>{titulo} (promoção)</p>
{/snippet}

<script>
  let Mostrar = $state(Cartao);
</script>

{@render Mostrar('Pão francês')}
<button onclick={() => Mostrar = Promo}>trocar</button>
{#snippet Cartao(titulo)}
  <p>{titulo}</p>
{/snippet}

{#snippet Promo(titulo)}
  <p>{titulo} (promoção)</p>
{/snippet}

<script>
  let Mostrar = $state(Cartao);
</script>

{@render Mostrar('Pão francês')}
<button onclick={() => Mostrar = Mostrar === Cartao ? Promo : Cartao}>trocar</button>

A solução troca a atribuição fixa por uma comparação: "se estou mostrando o cartão, mostre a promoção; senão, volte". É o mesmo padrão de alternância da aula do primeiro componente, agora com conteúdo em vez de texto.

7. <svelte:component> ficou para trás

Se você procurar o assunto em tutoriais antigos, vai encontrar <svelte:component this={Atual} />. Ele existia porque, no Svelte 4, um componente numa variável precisava ser desembrulhado por essa tag. No Svelte 5, componentes já são dinâmicos por padrão, e a tag antiga virou um aviso:

<script>
  import Cartao from './Cartao.svelte';

  let Atual = $state(Cartao);
</script>

<svelte:component this={Atual} titulo="Pão" />
aviso: svelte_component_deprecated (linha 7): `<svelte:component>` is deprecated in runes mode — components are dynamic by default
https://svelte.dev/e/svelte_component_deprecated

A tradução: "está em desuso no modo runas — componentes já são dinâmicos por padrão". Não é erro; o código compila e funciona. Mas quem lê o arquivo vê uma tag que não serve para nada, e a documentação nova já não a menciona. Se encontrar num projeto, a troca é apagar a tag e usar a variável direto: <Atual titulo="Pão" />.

Três escolhas, três ferramentas
  • Forma muda, conteúdo é o mesmo: <svelte:element>.
  • Componente inteiro muda: variável com maiúscula, <Atual />.
  • Pedaço de conteúdo muda: variável de snippet, {@render}.

8. Props e atributos no que é dinâmico

Um componente dinâmico recebe props como qualquer outro. O cuidado é não passar prop que o componente escolhido não conhece — ele recebe assim mesmo, e o valor fica sem uso. Uma forma comum de resolver é ter um objeto de props e espalhá-lo:

<script>
  import Cartao from './Cartao.svelte';

  let Atual = $state(Cartao);
  let props = $derived({ titulo: 'Pão francês', preco: 0.9 });
</script>

<Atual {...props} />

Os três pontinhos espalham as propriedades do objeto como atributos. Se amanhã a variável Atual apontar para outro componente que também aceita titulo e preco, nada muda em quem chama. É a mesma ideia dos três pontinhos de listas, agora com nomes.

Com <svelte:element> a história é outra: os atributos vão para o HTML, sem validação. Passar href quando a tag é p produz um atributo href num parágrafo — inofensivo, mas errado. Não há como o compilador saber, porque a tag só existe em tempo de execução.

9. Proteger a tela quando a escolha é vazia

As duas armadilhas desta aula têm a mesma cura: perguntar antes de desenhar. Uma escolha pode ser null, uma tag pode ser '', e nos dois casos o Svelte não reclama — só não desenha. Quem garante que a tela não fique em branco é você, com {#if} e um {:else} que explique a situação:

Missão: a tag chega vazia e o aviso desaparece da tela. Faça aparecer aviso: sem tag quando não houver tag para desenhar.

<script>
  let tag = $state('');
</script>

<svelte:element this={tag}>Pão francês</svelte:element>
<button onclick={() => tag = 'p'}>trocar</button>
<script>
  let tag = $state('');
</script>

{#if tag}
  <svelte:element this={tag}>Pão francês</svelte:element>
{:else}
  <p>aviso: sem tag</p>
{/if}
<button onclick={() => tag = 'p'}>trocar</button>

O mesmo vale para o conteúdo escolhido: uma variável de snippet que ainda não recebeu valor não desenha nada. Um estado vazio explícito — "escolha um cartão" — é melhor que uma área em branco, porque diz ao leitor que a tela está funcionando:

Missão: antes de escolher, a área do cartão fica vazia e a tela parece quebrada. Mostre escolha um cartão enquanto nada foi escolhido.

{#snippet Cartao(titulo)}
  <p>Cartão: {titulo}</p>
{/snippet}

<script>
  let Mostrar = $state(null);
</script>

{#if Mostrar}
  {@render Mostrar('Pão francês')}
{/if}
<button onclick={() => Mostrar = Cartao}>escolher</button>
{#snippet Cartao(titulo)}
  <p>Cartão: {titulo}</p>
{/snippet}

<script>
  let Mostrar = $state(null);
</script>

{#if Mostrar}
  {@render Mostrar('Pão francês')}
{:else}
  <p>escolha um cartão</p>
{/if}
<button onclick={() => Mostrar = Cartao}>escolher</button>

Repare que a solução não precisa mudar o botão: ele já atribuía o snippet certo. O que faltava era o caminho do "ainda não". Esse é o tipo de detalhe que separa uma tela que funciona de uma tela que parece quebrada no primeiro segundo.

10. Quando dá errado

As mensagens abaixo são reais. A primeira e a terceira vêm do renderizador; a segunda é um aviso do compilador, não um erro.

Erro 1 — a variável não é um componente

Guardar texto numa variável e usá-la como tag com maiúscula faz o Svelte tentar chamar aquele valor como função:

<script>
  let Atual = $state('p');
</script>

<Atual />
Erro ao renderizar: Atual is not a function

"Atual não é uma função." Componentes, no fundo, são funções — e uma string não é. A correção é guardar o componente importado, nunca o nome dele em texto: let Atual = $state(Cartao).

Erro 2 — nome de elemento inválido

Nome de elemento HTML não pode começar com dígito. O Svelte avisa e não desenha o elemento:

<script>
  let tag = $state('2colunas');
</script>

<svelte:element this={tag}>oi</svelte:element>
Erro ao renderizar: dynamic_element_invalid_tag
`<svelte:element this="2colunas">` is not a valid element name — the element will not be rendered
https://svelte.dev/e/dynamic_element_invalid_tag

A mensagem vem em três linhas: o código do erro, a explicação com o nome que falhou, e o endereço da documentação. "não é um nome de elemento válido — o elemento não será renderizado". Se a tag vem de dados do usuário, valide antes: uma lista de tags permitidas resolve mais rápido do que adivinhar.

Aviso — a tag antiga

Este não é erro e o componente funciona. É o compilador dizendo que <svelte:component> não é mais necessário:

<script>
  import Cartao from './Cartao.svelte';

  let Atual = $state(Cartao);
</script>

<svelte:component this={Atual} titulo="Pão" />
aviso: svelte_component_deprecated (linha 7): `<svelte:component>` is deprecated in runes mode — components are dynamic by default

A correção é de uma linha: apague <svelte:component this={Atual} /> e escreva <Atual />. O aviso aparece no terminal durante o desenvolvimento e não entra no build final, mas código sem aviso é código mais fácil de ler.

Resumo

  • <svelte:element this={x}> troca a tag em tempo de execução, mantendo atributos e conteúdo.
  • Uma tag null ou '' não desenha nada e não avisa; nome inválido derruba a renderização.

  • Tag, componente e snippet resolvem problemas diferentes: forma, peça inteira e pedaço de conteúdo.
  • Sempre ofereça um estado vazio explícito com {:else} em vez de deixar a área em branco.
  • Os casos desta aula: Atual is not a function, dynamic_element_invalid_tag e o aviso svelte_component_deprecated.
