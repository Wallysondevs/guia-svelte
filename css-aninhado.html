Svelte · CSS Aninhado e :global

O caderno de pedidos da Ana tem uma estrutura simples: cada pedido é uma caixa, e dentro da caixa ficam o nome do cliente, os itens e o total. No CSS, ela escrevia .pedido .cliente { … }, .pedido .total { … } — repetindo o nome da caixa em toda linha só para dizer "isto está dentro daquilo". O CSS aninhado permite escrever a regra na mesma forma do HTML: a caixa por fora, os filhos por dentro. E o Svelte entende isso sem perder o escopo que você aprendeu na aula anterior.

Você vai aprender
  • O que é aninhamento de regras e por que ele deixa o CSS na forma do HTML.
  • Como o seletor aninhado sai do compilador, com o selo do componente.
  • O que o :where(…) faz nos seletores de dentro.
  • Para que serve o & e quando ele é obrigatório.
  • A diferença entre p e & > p dentro da regra.
  • Por que uma regra aninhada pode virar /* (unused) … */.
  • Como colocar @media dentro de uma regra.
  • Como :global(…) funciona no meio do aninhamento.
  • O que o build faz com o aninhamento e o que ele achata.
  • Os três erros reais de aninhamento, com a mensagem do compilador.

1. A ideia: escrever o CSS na forma do HTML

O HTML de um componente é uma árvore: uma caixa que contém um título, um parágrafo, uma lista. O CSS sempre foi uma lista de caminhos até essas peças, e o caminho repete o nome de cada degrau. Para pintar o título que está dentro da caixa, você escreve .cartao h1. Para pintar o parágrafo da mesma caixa, .cartao p. O nome .cartao aparece em todas as linhas, e é fácil esquecer um.

O CSS aninhado resolve isso deixando você escrever a árvore uma vez só:

CSS planoCSS aninhado
.cartao { padding: 8px; }
.cartao h1 { color: #b8860b; }
.cartao p { margin: 0; }		.cartao {
  padding: 8px;
  h1 { color: #b8860b; }
  p { margin: 0; }
}
o nome da caixa se repete em cada seletoro nome da caixa aparece uma vez, e os filhos ficam dentro
fácil esquecer um .cartao e a regra vaza para a páginanão há como esquecer: a regra está fisicamente dentro

Durante muito tempo isso foi coisa de pré-processador — Sass, Less, Stylus. Você escrevia aninhado e a ferramenta achatava antes de entregar ao navegador. Hoje o próprio CSS aceita aninhamento, e o Svelte o aceita de fábrica: nada de instalar plugin, nada de arquivo .scss. Você escreve dentro do bloco <style> e o compilador cuida de aplicar o selo do componente em cada pedaço.

Repare na palavra "cada pedaço". Um seletor aninhado não é uma regra só: é uma regra composta, e o selo precisa aparecer no pai e no filho. É aí que a saída do compilador começa a ficar interessante — e é o que você vai ver na próxima seção.

2. A primeira regra aninhada

O cartão de pedido da Ana, com o título dentro da caixa:

<div class="cartao">
  <h1>Padaria da Ana</h1>
  <p>Pão francês: R$ 0,90</p>
</div>

<style>
  .cartao {
    padding: 8px;
    border: 1px solid #eee;

    h1 {
      color: #b8860b;
      font-size: 20px;
    }
  }
</style>
.cartao.svelte-1n46o8q {
    padding: 8px;
    border: 1px solid #eee;

    h1:where(.svelte-1n46o8q) {
      color: #b8860b;
      font-size: 20px;
    }
  }

O compilador não achatou nada: o aninhamento continua lá, exatamente na posição em que você escreveu, inclusive a linha em branco. O que ele fez foi acrescentar o selo svelte-1n46o8q em dois lugares — no .cartao e no h1, este último dentro de um :where(…). As declarações padding e border ficaram onde estavam, antes da regra de dentro.

O HTML gerado mostra a outra metade do trabalho: <div class="cartao svelte-1n46o8q"> e <h1 class="svelte-1n46o8q">. O parágrafo, que não é citado por nenhuma regra, sai limpo: <p>Pão francês: R$ 0,90</p>. Sem regra que possa atingi-lo, sem selo.

Esse é o ponto que costuma confundir: o aninhamento não muda o alcance da regra. .cartao { h1 { … } } atinge exatamente os mesmos elementos que .cartao h1 { … } atingiria — os títulos dentro de uma caixa com a classe cartao. A diferença é de leitura e de manutenção, não de resultado na tela.

Missão: a regra do h1 está solta, então ela marca também o título que está fora da caixa. Aninhe a regra dentro de .cartao para o selo ir só no título de dentro.

<div class="cartao">
  <h1>A</h1>
</div>
<h1>B</h1>

<style>
  h1 { color: #b8860b; }
</style>
<div class="cartao">
  <h1>A</h1>
</div>
<h1>B</h1>

<style>
  .cartao {
    h1 { color: #b8860b; }
  }
</style>

Antes da correção, os dois títulos recebem a classe: <div class="cartao"><h1 class="svelte-n50uah">A</h1></div> <h1 class="svelte-n50uah">B</h1>. Depois, só o de dentro: o h1 de fora fica sem classe, porque nenhuma regra do componente pode alcançá-lo. A caixa também ganha o selo, já que ela é o pai do seletor.

3. O selo e o :where(…) do filho

Vale abrir o seletor gerado peça por peça, porque ele tem uma forma que você vai encontrar em todo CSS aninhado do Svelte:

.cartao
a classe que você escreveu, o pai da regra.
.svelte-1n46o8q
o selo do componente colado no pai, do jeito que você já conhece.
h1
o seletor de dentro, o filho. Continua sendo descendente do pai, sem >.
:where(.svelte-1n46o8q)
o selo do filho, envolvido por :where. Esse invólucro tem peso zero na especificidade.
{ … }
as declarações do filho, no lugar em que você as escreveu.

O :where(…) existe para o selo não inflar a força da regra. Sem ele, cada nível de aninhamento somaria uma classe à especificidade, e uma regra de dois níveis venceria qualquer regra de um nível só. Com :where, o seletor marca o elemento sem participar da briga: .cartao h1 e .cartao { h1 { … } } têm exatamente a mesma força.

E por que marcar o filho, se o pai já tem o selo? Porque o pai pode conter componentes de fora. Se um componente filho renderizar um h1 dentro do seu .cartao, esse título não tem o selo svelte-1n46o8q e a sua regra não o atinge — ele pertence ao componente dele, com o estilo dele. O selo no filho é o que impede o aninhamento de virar uma porta aberta para dentro dos outros componentes.

Você não escreve :where

Ele aparece só na saída do compilador. Se você digitar :where no seu CSS, o Svelte respeita o que você escreveu e ainda acrescenta o selo dele. Não há motivo para isso: escreva o seletor simples e deixe o invólucro para o compilador.

4. O &: o pai como referência

Até aqui, os seletores de dentro eram descendentes — coisas dentro do pai. Mas há um caso diferente: quando você quer falar do próprio elemento, num outro estado. O botão de comprar da padaria muda de cor quando o mouse passa por cima. O estado :hover não é um filho do botão; é o botão mesmo. Para dizer isso, o CSS aninhado usa o &, que significa "o seletor do pai, aqui":

<button class="botao">Comprar</button>

<style>
  .botao {
    padding: 6px 12px;
    border-radius: 4px;

    &:hover {
      background: #b8860b;
    }
  }
</style>
.botao.svelte-1n46o8q {
    padding: 6px 12px;
    border-radius: 4px;

    &:hover {
      background: #b8860b;
    }
  }

O & foi mantido na saída, colado no :hover, sem espaço entre os dois. Isso quer dizer "este mesmo elemento, quando o mouse estiver em cima" — e não "um filho em estado de hover". Sem o &, o compilador entenderia :hover como um descendente e a regra nunca casaria com nada.

&
o pai naquele ponto. Vale por .botao.svelte-1n46o8q inteiro.
:hover
uma pseudo-classe, um estado do elemento. Outras comuns: :focus, :disabled, :first-child.
&:hover
sem espaço entre & e : — o pai no estado hover. Com espaço (& :hover) seria um descendente.
background
a declaração que só vale nesse estado.

O & também serve para grudar uma classe: &.ativo significa "o botão que tem as classes botao e ativo ao mesmo tempo". É o mesmo que escrever .botao.ativo por fora, mas sem repetir o nome do pai. E serve para combinar com outras coisas: & + & é "um botão logo depois de outro", &:not(:last-child) é "todo botão que não é o último".

Uma observação prática: dentro de uma regra aninhada, o & é opcional quando o seletor começa por uma tag, uma classe ou um id. h1 { … } e & h1 { … } dão no mesmo. Mas ele é obrigatório quando o seletor começa por :, ::, [ ou > — porque aí não há como saber se você quer o pai ou um descendente. Na dúvida, use &: ele nunca erra o alvo e deixa a intenção explícita.

5. & > p: só o filho direto

Um cartão de pedido pode ter caixas dentro de si — o miolo do pão, o recheio, os acompanhamentos. A regra p dentro de .cartao atinge todos os parágrafos descendentes, inclusive os que estão dentro dessas caixas internas. Se a Ana quer zerar a margem só do primeiro nível, o seletor precisa dizer "filho direto", com >:

<div class="cartao">
  <p>Pão francês</p>
  <div class="miolo">
    <p>Miolo do pão</p>
  </div>
</div>

<style>
  .cartao {
    & > p {
      margin: 0;
    }
  }
</style>
.cartao.svelte-1n46o8q {
    & > p:where(.svelte-1n46o8q) {
      margin: 0;
    }
  }

E o HTML gerado confirma o alcance: <div class="cartao svelte-1n46o8q"><p class="svelte-1n46o8q">Pão francês</p> <div class="miolo"><p>Miolo do pão</p></div></div>. O parágrafo de dentro do .miolo saiu sem classe, porque nenhuma regra pode alcançá-lo. É o selo funcionando como espelho do seletor: se a regra não chega, o elemento fica limpo.

Repare que o & > p virou & > p:where(…), com o & preservado. O compilador não troca o & pelo seletor do pai — ele entrega o aninhamento ao navegador, que hoje sabe ler &. Quem faz a expansão final é o navegador, na hora de aplicar o estilo.

Missão: o margin: 0 está pegando também no parágrafo que mora dentro da caixa interna. Restrinja a regra ao filho direto, usando & > p.

<div class="cartao">
  <p>Pão</p>
  <div><p>Miolo</p></div>
</div>

<style>
  .cartao {
    p { margin: 0; }
  }
</style>
<div class="cartao">
  <p>Pão</p>
  <div><p>Miolo</p></div>
</div>

<style>
  .cartao {
    & > p { margin: 0; }
  }
</style>

Antes, o HTML é <div class="cartao svelte-n50uah"><p class="svelte-n50uah">Pão</p><div><p class="svelte-n50uah">Miolo</p></div></div> — os dois parágrafos marcados. Depois, o de dentro perde a classe. A diferença na tela é de alguns pixels de margem; a diferença no código é saber quem manda em quem.

6. Quando a regra aninhada não casa

Uma armadilha do &: escrever um estado ou uma classe que o HTML não tem. O CSS compila, o navegador não aplica nada e a página fica igual. O compilador percebe e avisa. Aqui a Ana escreveu &.ativo para o botão em destaque, mas o botão do HTML só tem a classe botao:

<button class="botao">Comprar</button>

<style>
  .botao {
    padding: 6px 12px;
    &:hover {
      background: #b8860b;
    }
    &.ativo {
      font-weight: bold;
    }
  }
</style>
.botao.svelte-1n46o8q {
    padding: 6px 12px;
    &:hover {
      background: #b8860b;
    }
    /* (unused) &.ativo {
      font-weight: bold;
    }*/
  }

O aviso, na linha da regra, é "Unused CSS selector "&.ativo"" com o código css_unused_selector. Repare no detalhe: o compilador cita o seletor como você o escreveu, com o &, e não como ele apareceria expandido. É uma boa pista de onde olhar — a linha 9 deste arquivo.

O que aconteceu é que &.ativo pede um elemento com as duas classes. O único botão do componente tem só botao. Como nenhum elemento casa, a regra vira comentário no CSS gerado, e o HTML sai sem o selo no botão — o mesmo HTML de antes. A correção tem duas saídas honestas: acrescentar ativo à classe do botão, ou tirar a regra que ninguém usa. As duas são melhores do que deixar o CSS mentindo.

Aviso não é erro: a página funciona. Mas cada css_unused_selector é uma linha de CSS que você acha que está fazendo algo e não está. Em um projeto grande, eles se acumulam e viram um capítulo de arqueologia.

7. @media dentro da regra

O preço do café muda de tamanho conforme a largura da tela. Em CSS plano, você repete o seletor dentro do @media. Com aninhamento, o @media pode ficar dentro da regra, junto do que ele afeta:

<p class="preco">R$ 0,90</p>

<style>
  .preco {
    font-size: 18px;

    @media (min-width: 600px) {
      font-size: 24px;
    }
  }
</style>
.preco.svelte-1n46o8q {
    font-size: 18px;

    @media (min-width: 600px) {
      font-size: 24px;
    }
  }

O @media continua dentro do .preco e o selo aparece uma vez só, no seletor de fora. Por dentro, as declarações herdam o seletor do pai — é como se o @media fosse um envelope transparente para o seletor. Na tela, isso significa 18 pixels no celular e 24 no computador, sem repetir .preco.

As demais regras de grupo funcionam do mesmo jeito: @supports, @container, @starting-style. O que não pode ficar dentro de uma regra é @import e @font-face — eles precisam estar no nível de fora, porque descrevem coisas que não pertencem a nenhum elemento.

O HTML do exemplo é <p class="preco svelte-1n46o8q">R$ 0,90</p>. O selo é um só, porque a regra também é uma só: o @media não é um seletor novo, é uma condição sobre a mesma regra.

8. :global(…) dentro do aninhamento

Às vezes a caixa embrulha conteúdo que não é seu: um texto vindo de uma biblioteca, o HTML de um campo de formulário, o conteúdo de um componente filho. Nesse caso, o seletor de dentro precisa ficar de fora do escopo — e :global(…) faz isso dentro do aninhamento também:

<div class="cartao">
  <p>Pão francês</p>
</div>

<style>
  .cartao {
    :global(p) {
      margin: 0;
    }
  }
</style>
.cartao.svelte-1n46o8q {
    p {
      margin: 0;
    }
  }

A saída perde o :global e mantém o p sem selo: .cartao.svelte-1n46o8q p. O pai continua escopado, o filho não. Na prática, a regra vale para qualquer parágrafo dentro da sua caixa, inclusive os que vieram de fora. É a porta aberta, mas do lado de dentro da caixa — bem mais contida do que um :global(p) no nível de fora, que atingiria a página inteira.

No HTML, o efeito é direto: <div class="cartao svelte-1n46o8q"><p>Pão francês</p></div>. O parágrafo fica sem classe, porque o seletor dele é global e não precisa de selo. É a assinatura do :global: elementos limpos e regras amplas.

Missão: o parágrafo de dentro da caixa é conteúdo de fora, e o selo do componente está indo nele. Deixe a regra do p global, sem tirar o escopo da caixa: o HTML tem de sair com selo no div e sem selo no p.

<div class="cartao">
  <p>A</p>
</div>
<p>B</p>

<style>
  .cartao {
    p { margin: 0; }
  }
</style>
<div class="cartao">
  <p>A</p>
</div>
<p>B</p>

<style>
  .cartao {
    :global(p) { margin: 0; }
  }
</style>

O resultado parece o mesmo do começo, e não é: antes, o p de dentro tinha o selo e a regra valia só para ele; agora o p não tem selo nenhum e a regra vale para qualquer parágrafo dentro da caixa, inclusive um que venha de um componente filho. A escolha entre os dois é a escolha entre proteger e alcançar.

Primeira: o CSS que você lê no dist/ nunca é igual ao que você escreveu — não tente comparar linha por linha. Segunda: o selo viaja junto na expansão, e continua batendo com as classes do HTML.

10. Quando dá errado

Os três erros abaixo são todos de aninhamento mal posicionado. Repare que os três acontecem na linha 4 ou 5 — o começo do bloco de estilo, onde a estrutura é decidida.

1. & no nível de fora. O & precisa de um pai. Solto no começo do arquivo, não há a que se referir:

<h1>Padaria</h1>

<style>
  & { color: red; }
</style>
Erro de compilação (linha 4, coluna 2): Nesting selectors can only be used inside a rule or as the first selector inside a lone `:global(...)`

"Seletores de aninhamento só podem ser usados dentro de uma regra, ou como o primeiro seletor dentro de um :global(...) sozinho". A mensagem até entrega a exceção: :global(&) no nível de fora é aceito. Para o caso comum, a correção é envolver o & numa regra — h1 { & { … } } funciona, embora seja redundante.

2. :global como bloco, com declarações. A Ana quis deixar tudo global e escreveu :global sem parênteses, com uma declaração dentro:

<h1>Padaria</h1>

<style>
  :global { color: red; }
</style>
Erro de compilação (linha 4, coluna 12): A top-level `:global {...}` block can only contain rules, not declarations

"Um bloco :global {...} de nível superior só pode conter regras, não declarações". Um bloco :global é um envelope para seletores; color: red não é um seletor. Ou você usa :global(h1) { color: red; }, ou coloca as declarações dentro de uma regra.

3. & sem nada depois. Um dois-pontos digitado no lugar errado:

<h1>Padaria</h1>

<style>
  h1 {
    &: { color: blue; }
  }
</style>
Erro de compilação (linha 5, coluna 6): Expected a valid CSS identifier

"Esperava um identificador CSS válido". Depois de &: tem de vir o nome do estado — &:hover, &:focus, &:first-child. Sozinho, o dois-pontos não forma nada.

Três hábitos resolvem quase tudo:

Um. Mantenha as declarações do pai antes das regras aninhadas. O compilador preserva a ordem em que você escreveu, e uma declaração perdida depois de duas regras aninhadas é difícil de achar às duas da manhã. Declarações primeiro, filhos depois, é a leitura que todos esperam.

Dois. Não aninhe mais do que dois ou três níveis. Se você chegou em .cartao { .lista { li { .preco { … } } } }, o problema provavelmente não é o seletor: é o componente fazendo coisa demais. Dividir em dois componentes resolve o estilo e a leitura de uma vez.

Três. Prefira & quando o seletor começa por : e prefira & > quando você sabe que quer só o filho direto. O primeiro evita o erro de achar que :hover é descendente; o segundo evita pintar netos sem querer.

A ideia final: o aninhamento é uma forma de escrever, não um recurso a mais. A regra vale o mesmo que valeria escrita por extenso — o que muda é quantas vezes você repete o nome do pai e quantas chances tem de esquecer o escopo. Escreva na forma do HTML, deixe o & explicar os estados e lembre que :global continua sendo a porta que se abre de propósito.

Exercícios

1. O que & significa dentro de uma regra aninhada?

2. Qual a diferença entre .cartao { p { … } } e .cartao { & > p { … } }?

3. Por que o compilador envolve o selo do filho em :where(…)?

Complete o código

<button class="botao">Comprar</button>

<style>
  .botao {
    padding: 6px 12px;
     { background: #b8860b; }
  }
</style>

// o estado do próprio botão, quando o mouse está em cima

Resumo

  • O aninhamento deixa o CSS na mesma forma do HTML: o pai por fora, os filhos dentro.
  • O compilador mantém o aninhamento e acrescenta o selo no pai e no filho.
  • O selo do filho vem em :where(…), que tem peso zero na especificidade.
  • Marcar o filho impede que a regra vaze para dentro de componentes de fora.
  • & significa "o seletor do pai aqui": &:hover, &.ativo, & + &.
  • & é obrigatório quando o seletor de dentro começa por :, ::, [ ou >.
  • p atinge todos os descendentes; & > p atinge só o filho direto.
  • Regra aninhada que não casa vira /* (unused) … */ e avisa css_unused_selector.
  • @media pode ficar dentro da regra; @import e @font-face, não.
  • :global(p) dentro do aninhamento deixa o filho sem selo e mantém o pai escopado.
  • O build achata o aninhamento e minifica; o resultado na tela é o mesmo.
