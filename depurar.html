Svelte · Depurando

A Ana passou uma tarde inteira atrás de um erro de três letras. O botão não somava, e ela trocou de tudo: o nome da função, a ordem das linhas, o $state de lugar. Quando cansou e colocou um console.log no lugar certo, viu em dois segundos que a função recebia texto em vez de número. Nesta aula ela aprende a fazer perguntas pequenas em vez de mexer em tudo.

1. A ideia: depurar é perguntar, não adivinhar

Existe uma diferença grande entre consertar e adivinhar. Adivinhar é trocar uma linha, salvar, olhar a tela e repetir. Consertar é formular uma pergunta que tenha resposta sim ou não: “o valor que chega na função é número ou texto?”.

A pergunta bem feita tem duas qualidades. Primeira: é pequena — dá para responder olhando uma linha. Segunda: a resposta aparece em algum lugar que você consegue ver — a tela, o console, o terminal. Pergunta cuja resposta está na sua cabeça não serve.

Na padaria, a Ana faz isso com o forno: “a resistência está quente?” é uma pergunta que se responde com a mão perto, não com palpite. No código, o equivalente é imprimir o valor. Toda esta aula é sobre imprimir o valor no lugar certo.

2. As quatro ferramentas

Não é preciso mais do que quatro coisas para depurar um componente Svelte. Cada uma responde a um tipo de pergunta:

FerramentaRespondeOnde fica
console.log“qual é o valor agora, neste ponto?”no seu código, dentro de função ou evento
$inspect(estado)“quanto vale este estado e quando ele muda?”no <script> do componente
Busca no arquivo“onde este nome aparece no projeto?”no editor ou com grep no terminal
Reduzir o caso“qual pedaço de código é o culpado?”no próprio arquivo, comentando metade

Repare que nenhuma delas é um programa novo para instalar. Depurar é uma habilidade de leitura, não uma assinatura de ferramenta. O que muda entre pessoas experientes é a ordem das perguntas: quem já viu o erro muitas vezes vai direto ao ponto.

Antes de usar qualquer ferramenta, porém, leia a mensagem. Um erro que já diz preco.toFixed is not a function não precisa de console.log nenhum: ele conta que o valor é texto. A ferramenta serve quando o código roda sem erro e o resultado está errado — o caso mais difícil.

3. O console.log no lugar certo

A função abaixo soma um clique e registra o valor no console. O registro está dentro da função, então roda a cada clique:

<script>
  let contador = $state(0);

  function somar() {
    contador++;
    console.log('contador agora vale', contador);
  }
</script>

<button onclick={somar}>Cliques: {contador}</button>

Depois de um clique, o console do navegador mostra uma linha:

console do navegador:

contador agora vale 1

Uma linha, com o texto que você escreveu e o valor. Repare que console.log aceita vários pedaços separados por vírgula: o texto entre aspas aparece literalmente, e o valor da variável é resolvido na hora. Essa mistura de texto e valor é o que torna o registro legível.

console
o objeto de registro do navegador. Ele existe em qualquer página, sem importar nada.
.log
o tipo de registro. Também existem console.warn (amarelo) e console.error (vermelho), que se destacam na lista.
'contador agora vale'
o texto, entre aspas. O que está entre aspas não é avaliado — aparece como está escrito.
, contador
o valor. Vai separado por vírgula e é avaliado no momento da chamada: aqui, o contador já incrementado.

O lugar do registro é o que decide o que ele mostra. Dentro da função, ele roda quando a função roda. No corpo do script, ele roda uma vez, quando o componente é criado — e nunca mais. Essa diferença é a origem do erro mais chato de depuração, e é o assunto da próxima seção.

4. O registro que mostra o valor de ontem

A Ana quis ver o nome sempre que ele mudasse, e colocou o registro no topo do script:

<script>
  let nome = $state('Ana');
  console.log('nome agora é', nome);
</script>

<input bind:value={nome} />
<p>{nome}</p>

O console mostra nome agora é Ana uma única vez. Digitando no campo, a frase da tela muda — e o console fica parado. Isso não é bug: o corpo do script roda uma vez, na criação do componente. O que muda depois é o valor, não o script.

Ao compilar esse arquivo, o Svelte ainda deixa um aviso apontando o problema:

aviso na compilação:

state_referenced_locally (linha 3): This reference only captures the initial value of `nome`. Did you mean to reference it inside a closure instead?

“Esta referência só captura o valor inicial de nome. Você quis dizer que era para referenciar dentro de uma função?” A palavra closure aqui quer dizer “um trecho que roda depois” — uma função, um handler, um efeito. É exatamente a diferença entre o registro no topo e o registro dentro da função.

Aviso de valor inicial é quase sempre bug de depuração

Se o seu console.log mostra o valor de antes, o registro está no lugar errado. Mova para dentro da função que muda o valor, ou use $inspect, que acompanha as mudanças sozinho.

5. $inspect: o registro que acompanha o estado

Quando o que você quer observar é um estado reativo, o Svelte tem uma runa própria. Ela registra o valor na criação e a cada mudança:

<script>
  let contador = $state(0);
  $inspect(contador);
</script>

<button onclick={() => contador++}>Cliques: {contador}</button>

Na criação, o console mostra 0. Depois de cada clique, mostra o valor novo:

console do navegador:

0
1

Junto de cada registro, o navegador oferece a pilha de chamadas — o caminho de funções que levou até ali. Nos testes desta aula, essa pilha aparece como uma entrada separada, com o rótulo stack trace, que você abre clicando na setinha. É por ali que se descobre quem mudou o valor, e não só qual é o valor novo.

A diferença prática entre $inspect e console.log: o $inspect não precisa ser chamado de dentro de uma função. Você declara uma vez, no topo, e ele acompanha. Em produção, o $inspect não gera nada — o compilador remove a chamada —, então ele não deixa registro sobrando no site publicado.

Lembre de apagar depois

Nenhum dos dois é para ficar. console.log esquecido polui o console de quem visita a página; $inspect some sozinho no build, mas continua no código. Depure, responda a pergunta e remova o registro.

6. Quando o valor é um objeto

Objetos e listas criados com $state são proxies: uma camada que avisa o Svelte quando algo dentro muda. Registrar um proxy com console.log tem um efeito colateral estranho — e o próprio Svelte avisa:

console do navegador:

[svelte] console_log_state
Your `console.log` contained `$state` proxies. Consider using `$inspect(...)` or `$state.snapshot(...)` instead
https://svelte.dev/e/console_log_state

“Seu console.log continha proxies de $state. Considere usar $inspect(...) ou $state.snapshot(...).” O motivo é que o argumento que chega ao console é o proxy, não uma fotografia do valor: se você clicar na setinha depois, pode ver um valor já diferente do que existia na hora do registro. $state.snapshot(objeto) tira uma foto comum, sem proxy.

Na prática, para ver o conteúdo de um objeto agora, as duas formas funcionam: $inspect(objeto) para acompanhar, console.log($state.snapshot(objeto)) para fotografar. O que não funciona é registrar o proxy e acreditar no que aparece meia hora depois.

7. Ler o que a tela mostra: NaN, undefined e [object Object]

Nem todo bug tem mensagem. Alguns aparecem como texto esquisito no lugar do valor certo, e cada texto esquisito aponta para uma causa diferente:

Na telaO que costuma serPrimeira pergunta
NaNconta com algo que não é número, ou função chamada sem argumentotodos os argumentos foram passados?
undefinednome que existe mas não tem valor: propriedade não passada, item fora da listaquem deveria dar esse valor?
[object Object]um objeto inteiro usado onde se esperava textofaltou escolher uma propriedade com ponto?
nada (vazio)o bloco não rodou, ou a lista estava vaziaa condição é verdadeira?
o valor de antesvariável sem $state, ou registro no lugar erradoquem avisa a tela?

NaN quer dizer not a number — “não é um número”. Ele nasce quando uma conta recebe algo que não consegue converter. Não é erro que para o programa: é um valor que se espalha. Uma vez NaN, toda conta que depende dele também vira NaN, e a tela inteira fica estranha.

Missão: a tela mostra Total: R$ NaN. A função comDesconto precisa de dois valores: o preço e o desconto. Descubra qual faltou e acerte a chamada para o total dar R$ 2.25.

<script>
  let preco = $state(2.5);

  function comDesconto(valor, desconto) {
    return valor - valor * desconto;
  }

  let total = $state(comDesconto(preco));
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<script>
  let preco = $state(2.5);

  function comDesconto(valor, desconto) {
    return valor - valor * desconto;
  }

  let total = $state(comDesconto(preco, 0.1));
</script>

<p>Total: R$ {total.toFixed(2)}</p>

O caminho para achar isso sem sorte é perguntar: “quais valores a função recebe?”. Um console.log(valor, desconto) na primeira linha da função mostraria 2.5 undefined — e a resposta apareceria antes de qualquer tentativa de conserto.

8. Busca no arquivo: onde este nome aparece?

Metade dos bugs de estado vem de um nome usado em dois lugares com intenções diferentes. Antes de entender o fluxo, é bom ver todos os pontos onde ele aparece. No terminal, grep -n faz isso e mostra o número da linha:

ana@notebook:~/loja$ grep -n contador src/App.svelte
2:  let contador = 0;
5:    contador++;
10:<button onclick={somar}>Cliques: {contador}</button>

Três aparições: a declaração, o incremento dentro da função e o uso na tela. Com isso na frente, a pergunta fica fácil: o incremento está antes do uso, mas o valor não aparece na tela — então o problema é de reatividade, não de ordem. O grep -n mostra também que a declaração é let contador = 0, sem $state.

grep
o comando que procura texto dentro de arquivos. Ele imprime as linhas que casam com o padrão.
-n
a opção que acrescenta o número da linha no começo de cada resultado.
contador
o que você procura. Pode ser um pedaço de palavra: preco também acha precoUnitario.
src/App.svelte
onde procurar. Um arquivo, ou uma pasta inteira com src/ no lugar.

O editor faz o mesmo com Ctrl + Shift + F e mostra o resultado agrupado por arquivo. O terminal é útil quando você quer um resultado limpo, que dá para copiar e colar numa anotação.

9. Reduzir o caso pela metade

Quando o arquivo tem trinta linhas, a busca visual funciona. Com trezentas, não. A técnica é sempre a mesma: apague (ou comente) metade e veja se o problema continua. Se continuar, ele está na metade que sobrou; se desaparecer, está na que você tirou.

Em duas ou três rodadas o problema fica do tamanho de uma linha — e uma linha se lê inteira. O cuidado é não misturar: reduza o HTML primeiro, depois o script, nunca os dois na mesma rodada. Cada rodada responde uma pergunta e muda seu palpite.

Existe uma variação mais rápida dessa técnica: trocar o valor por um fixo. Se a tela mostra o certo com o valor fixo, o problema está em quem produz o valor, não em quem desenha. Essa única troca separa “a conta está errada” de “a tela está errada” e economiza meia hora.

Missão: o componente não desenha nada e não mostra erro — o pior tipo de bug. A lista está dentro de um objeto chamado dados, e o {#each} está apontando para o objeto inteiro. Faça ele percorrer a lista certa.

<script>
  let dados = $state({ itens: [1, 2, 3] });
</script>

{#each dados as item}
  <p>{item}</p>
{/each}
<script>
  let dados = $state({ itens: [1, 2, 3] });
</script>

{#each dados.itens as item}
  <p>{item}</p>
{/each}

Vale guardar este caso: {#each} sobre um objeto não dá erro. Objeto não é lista, e o resultado é uma tela vazia, sem mensagem no console. É o exemplo perfeito de bug que só o console.log(dados) resolve — imprimir o valor mostra que ele é um objeto com a lista dentro.

Missão: o componente quebra com preco.toFixed is not a function. O preço chegou como texto. Descubra onde está o problema e faça a placa mostrar R$ 0.90.

<script>
  let preco = $state('0.90');
</script>

<p>R$ {preco.toFixed(2)}</p>
<script>
  let preco = $state(Number('0.90'));
</script>

<p>R$ {preco.toFixed(2)}</p>

A solução usa Number('0.90') em vez de apagar as aspas. As duas funcionam aqui; a diferença aparece quando o valor vem de um campo de texto, onde você não controla o que a pessoa digita e precisa converter na entrada.

10. Quando dá errado

As três saídas abaixo saíram do compilador e do renderizador desta versão, copiadas como estão. As duas primeiras não geram erro: geram um valor esquisito na tela, que é o tipo de problema que a aula inteira tenta encurtar.

Caso 1 — NaN na conta

A função espera dois números e recebeu um. O JavaScript não reclama: devolve NaN, e a tela mostra o resultado da conta com ele.

<script>
  let preco = $state(2.5);

  function somar(a, b) {
    return a + b;
  }
</script>

<p>Total: R$ {somar(preco)}</p>
<p>Total: R$ NaN</p>

“R$ NaN” na tela quer dizer que a conta recebeu undefined. Contar os argumentos da chamada resolve; contar os parâmetros da função confirma. Um console.log(a, b) na primeira linha mostraria os dois valores lado a lado.

Caso 2 — [object Object] na tela

Chaves duplas: o Svelte entende a de fora como expressão e a de dentro como um objeto literal vazio com uma propriedade dentro. O resultado é um objeto, e todo objeto vira esse texto quando é obrigado a virar texto.

<script>
  let contador = $state(0);
</script>

<p>{{contador}}</p>
<p>[object Object]</p>

É um erro de digitação com consequência silenciosa: nenhum aviso, nenhum erro, só um texto feio. Sempre que aparecer [object Object], procure chaves dobradas ou um objeto usado sem ponto.

Caso 3 — {@render} de algo que não é chamada

{@render} espera uma chamada de snippet, com parênteses. Passar um nome solto é recusado na compilação.

<script>
  let nome = $state('Ana');
</script>

{@render nome}
Erro de compilação (linha 5, coluna 9): `{@render ...}` tags can only contain call expressions

“As tags {@render ...} só podem conter expressões de chamada.” A coluna 9 é onde começa o nome dentro das chaves. A correção é chamar o snippet: {@render linha()}, com os parênteses.

Resumo

  • Depurar é fazer perguntas pequenas com resposta visível — não trocar linha até funcionar.
  • Quatro ferramentas bastam: console.log, $inspect, busca no arquivo e reduzir o caso.
  • console.log aceita texto e valores separados por vírgula.
  • O corpo do script roda uma vez; registro ali mostra o valor inicial para sempre.
  • state_referenced_locally avisa exatamente esse caso.
  • $inspect(estado) acompanha as mudanças e não existe no build de produção.
  • $state.snapshot(objeto) tira a foto sem proxy; o Svelte avisa quando você registra o proxy.
  • NaN é conta com valor que não é número; undefined é nome sem valor; [object Object] é objeto virando texto.
  • grep -n lista todas as linhas em que um nome aparece, com o número.
  • Reduza pela metade, uma mudança por vez, e anote o que viu.
