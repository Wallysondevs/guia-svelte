Svelte · $derived.by

A Ana resolveu dar desconto para quem leva três pães ou mais, e a conta do desconto não é uma linha só: primeiro o bruto, depois a regra do desconto, depois o valor final. O $derived aceita uma expressão; quando a conta precisa de parágrafos, entra a versão com função, $derived.by. É a mesma ideia da aula passada, com espaço para pensar.

Você vai aprender
  • Quando uma conta deixa de caber numa expressão só.
  • A escrever let x = $derived.by(() => { … }).
  • Por que o return é obrigatório e o que acontece sem ele.
  • Como usar if dentro de um valor derivado.
  • Como devolver um objeto com várias contas prontas.
  • Como derivar listas e totais sem repetir cálculo.
  • Por que escrever estado dentro de um derivado quebra o componente.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como o projeto da Ana roda com npm run dev e npm run build.

1. A ideia: a conta que precisa de parágrafos

Na lousa da padaria, "três pães ou mais, dez por cento de desconto" é uma regra com etapas. A Ana não calcula de cabeça em uma passada: ela olha a quantidade, decide se o desconto vale, calcula o bruto, aplica o desconto e escreve o resultado. Quatro passos, uma decisão no meio.

Um $derived comum aceita uma expressão: qtd * unitario. Se você tentar espremer a regra do desconto ali, vai escrever uma linha comprida com dois operadores ternários aninhados — funciona, mas ninguém consegue ler nem corrigir depois. O $derived.by existe para esse caso: ele aceita uma função, com quantas linhas você precisar, desde que ela devolva o resultado.

A diferença entre os dois é de forma, não de conceito. Nos dois casos você tem um valor que se recalcula quando as dependências mudam. O que muda é o espaço para explicar a conta — e, num time, o espaço para explicar é o que separa código que envelhece bem de código que assusta.

Existe um custo em escolher a versão longa, e ele é pequeno: a função tem chaves, um return e mais linhas para ler. O ganho é maior quando a regra muda com o tempo. A Ana já mudou a regra do desconto duas vezes — primeiro era dez por cento em qualquer quantidade, depois passou a valer a partir de três pães. Na versão com if, a mudança foi numa linha e ninguém precisou decifrar a expressão.

2. $derived ou $derived.by?

Os dois criam valores derivados. A escolha é sobre legibilidade e sobre o que a conta precisa no meio do caminho.

SituaçãoUsePor quê
qtd * unitario$derived(…)uma expressão, sem variáveis intermediárias
conta com if$derived.by(…)expressão não tem if com várias etapas
vários passos com nomes$derived.by(…)as const do meio explicam a conta
devolver objeto com totais$derived.by(…)o return monta o pacote
uma comparação: a > 10$derived(…)cabe e se lê de uma vez

Uma regra prática: se você precisa de reticências para descrever a conta em voz alta ("primeiro isso, aí se…, então…"), use .by. Se a conta é uma frase só, use a versão curta. Nada impede converter uma na outra depois — é uma mudança de três linhas.

Vale saber que os dois aceitam as mesmas dependências: estado, props, outros derivados e até valores de contexto. O que o .by não aceita é deixar de ser função. Na dúvida entre as duas formas, comece pela curta: quando a linha passar de umas sessenta letras, a versão longa paga o espaço que ocupa.

3. O primeiro $derived.by da Ana

A função entra entre parênteses, e o resultado sai no return:

<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let total = $derived.by(() => {
    const bruto = qtd * unitario;
    return bruto;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 1.80</p>

O resultado é o mesmo do $derived da aula anterior, e é isso que você deve guardar: .by não é um recurso diferente, é a mesma runa com espaço para uma função. A função roda quando alguma dependência muda — e as dependências são descobertas executando a função, não lendo o texto dela.

A anatomia da função derivada

$derived.by(
a runa com o sufixo .by, que avisa: o argumento é uma função.
() => { … }
a função que calcula. Sete caracteres que dizem "recebo nada, devolvo alguma coisa".
const bruto = …
uma variável intermediária, só para dar nome a um passo. Não é estado: é conta.
return bruto
a entrega. O valor do derivado é exatamente o que o return devolve.
});
fecha a função e a chamada. Os dois sinais precisam estar na ordem: } fecha o corpo, ) fecha a runa.
Uma função, não uma chamada imediata

Repare que () => { … } é a função em si, não o resultado dela. Quem chama é o Svelte, na hora certa. Se você escrever $derived.by((() => 1)()), está chamando você mesmo e o derivado recebe um número — o que quebra em tempo de execução, porque a runa espera uma função.

4. O return é a entrega

Um erro que aparece toda semana: escrever a conta inteira e esquecer de devolver. A função roda, o valor é calculado, e ninguém recebe nada.

<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let total = $derived.by(() => {
    const bruto = qtd * unitario;
  });
</script>

<p>Total: R$ {total}</p>
<p>Total: R$ </p>

O texto aparece cortado porque total é undefined — a função terminou sem devolver nada. Numa função de JavaScript, chegar ao fim sem return significa "devolvo undefined", e é exatamente isso que o derivado recebe.

Repare que o compilador não reclama: para ele, devolver nada é permitido. Quem denuncia é a tela vazia. Esse é o motivo de o guia insistir no hábito de terminar toda função derivada com return, mesmo quando parece óbvio.

Cuidado também com o return que só existe dentro de um if. Se a condição for falsa, a função chega ao fim sem devolver nada, e o derivado fica vazio naquele caso. A regra do desconto da seção 6 escapa disso porque tem um segundo return no fim, fora de qualquer condição — o caminho de fuga está sempre aberto.

5. O primeiro experimento: devolva a conta

A função abaixo calcula o bruto e esquece de devolver. Sua missão é terminar a conta com um return que entregue o valor já formatado.

Missão: faça a tela mostrar Total: 1.80, devolvendo da função o valor com duas casas.

<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let total = $derived.by(() => {
    const bruto = qtd * unitario;
  });
</script>

<p>Total: {total}</p>
<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let total = $derived.by(() => {
    const bruto = qtd * unitario;
    return bruto.toFixed(2);
  });
</script>

<p>Total: {total}</p>

A meta compara o texto inteiro e espera Total: 1.80. Se você devolver o número 1.8, a tela mostra Total: 1.8 e a verificação falha — não por maldade, mas porque a formatação faz parte do que a tela promete.

6. A regra do desconto, com if

Agora o caso que motivou a runa: uma condição no meio da conta. Três pães ou mais ganham dez por cento; menos que isso, nada.

<script>
  let qtd = $state(3);
  let desconto = $derived.by(() => {
    if (qtd >= 3) return 0.1;
    return 0;
  });
</script>

<p>Desconto: {desconto * 100}%</p>
<p>Desconto: 10%</p>

>= quer dizer "maior ou igual"; com três pães a condição é verdadeira e o desconto é dez por cento. Com dois pães, a condição é falsa e a segunda linha devolve zero. Cada return encerra a função, então não é preciso else: quando o primeiro dispara, o segundo nem é lido.

Isso é uma comodidade que a expressão não tem. Numa linha só, você precisaria de qtd >= 3 ? 0.1 : 0 — o operador ternário, que serve para o caso simples e vira um ninho ilegível quando a regra tem três faixas.

Com três faixas (nenhum desconto, dez por cento, quinze por cento), a versão com if continua legível: um teste por faixa, do mais generoso para o menos. A versão ternária precisaria de um ternário dentro do outro, e aí a regra do desconto vira um quebra-cabeça que ninguém quer abrir seis meses depois.

Repare que a função não recebe parâmetro nenhum. Ela lê qtd direto do componente, e o Svelte registra essa leitura como dependência. É por isso que a mesma função pode ser chamada de novo sem argumentos: as informações de que ela precisa já estão no escopo.

Missão: o desconto está fixo em 10%. Faça a regra funcionar: 0% no começo e 10% só a partir de três pães (dois cliques).

<script>
  let qtd = $state(1);
  let desconto = $derived.by(() => {
    return 0.1;
  });
</script>

<p>Desconto: {desconto * 100}%</p>
<button onclick={() => qtd++}>mais um pão</button>
<script>
  let qtd = $state(1);
  let desconto = $derived.by(() => {
    if (qtd >= 3) return 0.1;
    return 0;
  });
</script>

<p>Desconto: {desconto * 100}%</p>
<button onclick={() => qtd++}>mais um pão</button>

A verificação olha três momentos: antes do clique, depois de um e depois de dois. Só o terceiro mostra dez por cento. Esse tipo de meta, com vários passos, é o jeito de provar que uma condição funciona nos dois lados.

7. Devolvendo mais de um valor

Quando a conta produz três números que a tela usa, o derivado pode devolver um objeto com os três. É melhor que três derivados separados: a conta é feita uma vez e os valores saem consistentes entre si.

<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let conta = $derived.by(() => {
    const bruto = qtd * unitario;
    return { bruto, desconto: bruto * 0.1 };
  });
</script>

<p>Bruto: R$ {conta.bruto.toFixed(2)}</p>
<p>Desconto: R$ {conta.desconto.toFixed(2)}</p>
<p>Bruto: R$ 1.80</p> <p>Desconto: R$ 0.18</p>

O return { bruto, desconto: … } usa a forma curta do objeto: quando o nome da variável é igual ao nome do campo, basta escrever uma vez. E o resultado é lido com ponto, como qualquer objeto: conta.bruto.

O objeto é novo a cada recálculo — e isso é bom. Nada dentro dele muda por fora, então a tela nunca vê um valor pela metade: ou o objeto antigo com os dois números, ou o novo com os dois atualizados. Devolver objeto também economiza runas: um derivado só, três leituras.

Missão: a função devolve só o número do bruto, e a tela espera um objeto. Faça conta.bruto valer 1.80.

<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let conta = $derived.by(() => {
    const bruto = qtd * unitario;
    return bruto;
  });
</script>

<p>Bruto: R$ {conta.bruto.toFixed(2)}</p>
<script>
  let qtd = $state(2);
  let unitario = $state(0.9);
  let conta = $derived.by(() => {
    const bruto = qtd * unitario;
    return { bruto, desconto: bruto * 0.1 };
  });
</script>

<p>Bruto: R$ {conta.bruto.toFixed(2)}</p>

Antes da correção, a caixa mostra o erro Cannot read properties of undefined (reading 'toFixed'): um número não tem a propriedade bruto, então ler conta.bruto devolve undefined. É o mesmo tropeço da aula de props, com outra roupa.

8. Dentro do derivado não se escreve estado

Um derivado existe para calcular. Se ele também mudar estado, vira uma conta que se alimenta de si mesma: o valor que ele escreve pode ser uma das dependências que fazem a conta rodar de novo. O Svelte bloqueia isso quando o projeto está em modo de desenvolvimento.

<script>
  let qtd = $state(2);
  let total = $derived.by(() => {
    qtd = 3;
    return qtd * 0.9;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 2.70</p>

Na renderização do servidor isso passa e mostra 2,70. No navegador, rodando npm run dev, o componente nem aparece — o console registra:

Svelte error: state_unsafe_mutation
Updating state inside `$derived(...)`, `$inspect(...)` or a template expression is forbidden. If the value should not be reactive, declare it without `$state`
https://svelte.dev/e/state_unsafe_mutation

Traduzindo: "atualizar estado dentro de $derived(...), $inspect(...) ou de uma expressão do template é proibido. Se o valor não deve ser reativo, declare sem $state". A mensagem ainda dá a saída: se a variável intermediária é só conta, ela não precisa de runa nenhuma.

Vale distinguir dois tipos de escrita que parecem a mesma coisa. Escrever numa variável local da função (const bruto = …, ou um acumulador com let soma = 0 e soma += item.preco) é permitido e comum: nada ali é estado, é conta. O que o Svelte bloqueia é escrever numa variável reativa — $state, prop, campo de classe com runa. A diferença está em quem observa o valor: se alguém observa, a escrita vira dependência.

Derivado calcula; efeito faz

Se a sua ideia é "quando a quantidade mudar, manda o pedido para o servidor", isso não é derivado — é efeito, com $effect, que roda depois que a tela é desenhada e pode fazer coisas acontecer. Misturar os dois é o caminho mais curto para um componente que roda em círculo.

10. Quando dá errado

Três erros de compilação colhidos do compilador de verdade, todos na mesma família: a runa .by com o argumento errado.

1. A runa sem parênteses. $derived.by também é uma chamada; sem os parênteses, não há função para rodar:

<script>
  let qtd = $state(2);
  let total = $derived.by;
</script>

<p>Total: {total}</p>
Erro de compilação (linha 3, coluna 14): Cannot use rune without parentheses

"Não posso usar a runa sem parênteses". A correção é $derived.by(() => { … }) — a função sempre dentro dos parênteses.

2. Duas funções. A runa aceita uma função; a segunda vira erro:

<script>
  let qtd = $state(2);
  let total = $derived.by(() => 1, () => 2);
</script>

<p>Total: {total}</p>
Erro de compilação (linha 3, coluna 14): `$derived.by` must be called with exactly one argument

"$derived.by precisa ser chamado com exatamente um argumento". Para dois resultados, devolva um objeto — é o que a seção 7 fez.

3. A runa no HTML. Calcular direto na marcação não é permitido:

<script>
  let qtd = $state(2);
</script>

<p>Total: {$derived.by(() => qtd * 0.9)}</p>
Erro de compilação (linha 5, coluna 11): `$derived.by(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

"$derived.by(...) só pode ser usado como valor inicial de uma declaração de variável…". A runa precisa de nome, no script. No HTML entra o nome dela.

O critério final é o mesmo do $derived: um valor derivado é consequência, nunca fonte de verdade. Se a conta precisa de uma decisão sua no meio, ela continua sendo derivada — desde que a decisão seja só uma leitura (if, filtro, soma), e não uma escrita.

Exercícios

1. Quando vale a pena usar $derived.by em vez de $derived?

2. A função do $derived.by termina sem return. O que o derivado recebe?

3. Por que não escrever estado dentro de um derivado?

Complete o código

let qtd = $state(3);
let desconto = $derived.by(() => {
  if (qtd >= 3) ;
  return 0;
});

// três pães ou mais ganham dez por cento

Resumo

  • $derived.by(função) é a versão do derivado que aceita várias linhas.
  • Use quando a conta tem if, variáveis intermediárias ou devolve mais de um valor.
  • O valor do derivado é exatamente o que o return devolve; sem ele, é undefined.
  • Cada return encerra a função, então a regra do desconto dispensa else.
  • Devolver um objeto (return { bruto, desconto }) mantém os valores consistentes entre si.
  • As dependências são descobertas executando a função — não é preciso declarar uma lista.
  • Escrever estado dentro do derivado é proibido: em desenvolvimento o Svelte para com state_unsafe_mutation.
  • O compilador não avisa quando falta return; quem avisa é a tela vazia.
  • Erros desta aula: runa sem parênteses, dois argumentos e runa dentro do HTML.
  • Derivado é consequência, não fonte de verdade: se a regra precisa de decisão sua, ela é efeito.
