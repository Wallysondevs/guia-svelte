Svelte · Índice e chave do {#each}

A Ana tem um caderno de pedidos e, ao lado de cada linha, escreve um número: 1, 2, 3. Esse número é a posição da linha no caderno, e ele muda quando uma folha é arrancada. O pedido em si tem outro número, o do recibo, que nunca muda. O bloco {#each} oferece as duas coisas: um índice, que é a posição do item na lista naquele momento, e uma chave, que é a identidade que você escolhe para o item. Nesta aula você vai aprender a usar os dois — e a saber quando cada um resolve o problema.

Você vai aprender
  • Como receber a posição de cada item com as item, i.
  • Por que o índice começa em 0 e como mostrar a partir de 1.
  • A usar o índice para filtrar, numerar e marcar o último item.
  • O que é a chave de um {#each} e como se escreve (item.id).
  • Quando a chave muda o comportamento da lista e quando não muda nada.
  • O que acontece com chave duplicada e com chave que não existe.
  • A combinar índice e chave no mesmo bloco.
  • Os três erros de sintaxe desta aula, com a mensagem do compilador.
  • O que o build do projeto da Ana mostra quando o índice entra.
  • Como escolher a chave certa para uma lista de pedidos.

1. A ideia: posição não é identidade

Existem duas perguntas diferentes que você pode fazer sobre um item de uma lista. A primeira: "em que posição ele está agora?". A segunda: "qual é a identidade dele, independente de onde esteja?". Parecem a mesma coisa enquanto a lista não muda. Deixam de ser no instante em que alguém remove um item do começo.

No caderno da Ana, a linha 2 vira linha 1 quando a primeira é riscada. O pedido, porém, continua sendo o pedido do recibo 47. Se a tela usa a posição para tudo, ela vai confundir um pedido com outro assim que a lista mexer. Se a tela conhece a identidade, ela move a linha 47 para cima sem trocar o conteúdo dela.

O Svelte dá nomes às duas coisas. O índice é a posição, um número que vai de zero até o tamanho da lista menos um, e muda a cada volta do bloco. A chave é uma expressão que você escreve entre parênteses depois do item, e serve para o Svelte reconhecer "este item é o mesmo de antes". Com a chave, ele reaproveita a linha que já existia em vez de criar outra.

No caderno da AnaNo componente
A posição da linha: 1ª, 2ª, 3ªo índice i, contando de 0
O número do recibo, que não mudaa chave: (pedido.id)
Riscar a primeira linha e renumeraro índice muda, a chave não
"Esta é a última linha da página"{#if i === lista.length - 1}
"Este é o mesmo pedido de antes"a chave que o Svelte compara

Uma coisa importante antes de continuar: índice e chave são opcionais. A aula anterior mostrou o {#each} só com o item, e isso resolve a maioria dos casos. Você acrescenta o índice quando precisa do número na tela ou de uma decisão baseada na posição, e acrescenta a chave quando a lista é mexida com frequência e as linhas têm identidade própria.

2. O índice: as pedido, i

O índice vem depois de uma vírgula, no mesmo lugar onde você dá nome ao item.

<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ol>
  {#each pedidos as pedido, i}
    <li>{i} — {pedido}</li>
  {/each}
</ol>

O compilador gera um <li> por item, e o número dentro de cada um é a posição:

<ol><li>0 — pão</li><li>1 — leite</li><li>2 — café</li></ol>
0 — pão 1 — leite 2 — café

A anatomia da linha de abertura

{#each pedidos
a lista que será percorrida. Tem de ser algo que o JavaScript consiga percorrer: array, texto, conjunto.
as pedido
o item: um nome novo, que vale um elemento por vez.
, i
o índice: outro nome novo, que vale a posição daquela volta. i é só uma convenção; pode ser indice, posicao, o que você quiser.
}
fecha a abertura. A ordem importa: primeiro o item, depois a vírgula, depois o índice.

O índice não é uma cópia da lista nem um contador que você precisa cuidar. É um valor que o bloco calcula a cada volta e entrega pronto. Dentro do bloco, pedido e i valem para aquela repetição; fora dele, nenhum dos dois existe.

Nomeie pelo que é

Uma letra só, i, é o padrão da comunidade e funciona bem quando o bloco tem quatro linhas. Se o bloco crescer, troque por posicao ou indice: quem lê o código depois de você agradece.

3. Experimente: contar de um em um

A caixa abaixo mostra a posição de cada pedido começando em 0. Sua missão é fazer a lista parecer a do caderno da Ana: 1º, 2º, 3º.

Missão: o índice começa em zero, então a lista mostra 0º, 1º, 2º. Faça a contagem começar em 1, mantendo o traço e o nome do pedido.

<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ol>
  {#each pedidos as pedido, i}
    <li>{i}º — {pedido}</li>
  {/each}
</ol>
<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ol>
  {#each pedidos as pedido, i}
    <li>{i + 1}º — {pedido}</li>
  {/each}
</ol>

O {i + 1} é uma conta normal dentro das chaves, como o toFixed das aulas anteriores. O valor guardado no índice não muda: ele continua sendo 0 na primeira volta. O que muda é o que aparece na tela. Essa separação — guardar de um jeito, mostrar de outro — vale para toda a programação, e volta sempre que a Ana precisa mostrar dinheiro ou data.

4. Por que o índice começa em zero

Essa é a pergunta que todo mundo faz na primeira lista. A resposta curta: porque o JavaScript conta assim, e o Svelte não esconde a regra. A resposta longa envolve a história das linguagens e o jeito como a memória do computador é endereçada — assunto para outro dia.

Na prática, você precisa lembrar de três coisas. A primeira: o primeiro item tem índice 0. A segunda: o último tem índice lista.length - 1, porque length é o tamanho (três itens) e o último índice é dois. A terceira: para mostrar na tela, some um.

<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ul>
  {#each pedidos as pedido, i}
    <li>{pedido}{#if i === pedidos.length - 1} (último){/if}</li>
  {/each}
</ul>
<ul><li>pão</li><li>leite</li><li>café(último)</li></ul>

O último item ganhou a marca "(último)" porque a condição i === pedidos.length - 1 só é verdadeira na última volta. Repare que colou no texto, sem espaço: o bloco {#if} está encostado no {pedido} dentro do <li>. Se você quiser espaço, escreva o espaço.

ListaÍndicesÚltimo índice
['pão']00 (ou length - 1)
['pão', 'leite']0, 11
['pão', 'leite', 'café']0, 1, 22
[] (vazia)nenhum-1: o bloco não roda

A última linha explica um erro comum: numa lista vazia, o bloco não executa nenhuma volta, então não existe índice 0. O -1 aparece só se você calcular length - 1 fora do bloco. Lista vazia é assunto da próxima aula, mas já vale saber que ela não cria um item "vazio".

5. Experimente: só as posições pares

O índice serve também para decidir. Na caixa abaixo, os três pedidos aparecem. Sua missão é mostrar só os que estão nas posições pares (0 e 2), usando o índice.

Missão: mostre apenas os pedidos das posições pares. Use o índice dentro de um {#if}: a conta é i % 2 === 0 (o resto da divisão por 2 é zero).

<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ul>
  {#each pedidos as pedido, i}
    <li>{pedido}</li>
  {/each}
</ul>
<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ul>
  {#each pedidos as pedido, i}
    {#if i % 2 === 0}
      <li>{pedido}</li>
    {/if}
  {/each}
</ul>

O operador % devolve o resto de uma divisão: 4 % 2 é 0, 5 % 2 é 1. Por isso i % 2 === 0 é a forma padrão de dizer "posição par". Com isso, o bloco de dentro é avaliado três vezes e só duas produzem um <li>.

Deu certo, mas repare no custo: o {#if} roda em todas as voltas, mesmo nas que não mostram nada. Para três itens é irrelevante; para dez mil, o ideal é filtrar a lista antes, com pedidos.filter(...), e deixar o {#each} só desenhar. Guarde a ideia: filtre o dado quando a lista é grande, filtre na marcação quando a regra é visual.

6. A chave: (produto.id)

Agora a segunda informação. A chave vai entre parênteses, depois do índice (se houver), e diz qual valor identifica cada item:

<script>
  let produtos = $state([
    { id: 1, nome: 'pão' },
    { id: 2, nome: 'leite' }
  ]);
</script>

<ul>
  {#each produtos as produto (produto.id)}
    <li>{produto.id}: {produto.nome}</li>
  {/each}
</ul>
<ul><li>1: pão</li><li>2: leite</li></ul>

Na tela, nada muda: a chave não aparece, não vira atributo, não entra no HTML. Ela é uma instrução para o motor do Svelte, não uma informação para o leitor. O que ela faz é permitir que o motor reconheça um item quando a lista é reordenada, filtrada ou acrescentada.

A anatomia da chave

(produto.id)
a chave: uma expressão que devolve um valor único por item. Parênteses, não chaves.
produto.id
a identidade escolhida por você. Precisa ser única na lista e estável: o mesmo item tem de devolver o mesmo valor sempre.
(produto)
também é aceito: aí a identidade é o próprio objeto, comparado por referência. Funciona, mas é frágil quando você recria os objetos.
(i)
o índice como chave. Compila, mas é o oposto do que a chave serve para fazer — a posição muda quando a lista muda.

Sem chave, o Svelte atualiza a lista comparando posições: o primeiro item da lista nova ocupa o primeiro lugar, o segundo ocupa o segundo, e assim por diante. Com chave, ele compara identidades: procura o item de chave 7 onde ele estiver, reaproveita a linha que já existia e move o nó no lugar.

Por que isso importa? Porque cada <li> pode ter uma vida própria: um campo de texto com o que o cliente digitou, uma animação em andamento, uma imagem carregando. Sem chave, mover um item de posição significa recriar a linha e perder o que estava dentro. Com chave, a linha viaja inteira.

7. Índice e chave juntos

As duas informações convivem, nesta ordem: item, índice, chave.

<script>
  let produtos = $state([
    { id: 7, nome: 'pão' },
    { id: 9, nome: 'leite' }
  ]);
</script>

<ul>
  {#each produtos as produto, i (produto.id)}
    <li>{i + 1}. {produto.nome} (id {produto.id})</li>
  {/each}
</ul>
<ul><li>1. pão (id 7)</li><li>2. leite (id 9)</li></ul>

Este é o formato completo do bloco. Se você trocar a ordem — chave antes do índice —, o compilador reclama, porque a posição dos pedaços é fixa. Vale decorar a sequência como uma frase: "para cada item como nome , posição (identidade)".

Agora veja o caso em que a chave faz diferença. O botão remove o primeiro pedido da lista, e a chave é o próprio texto do pedido:

<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<button onclick={() => (pedidos = pedidos.slice(1))}>entregar o primeiro</button>

<ul>
  {#each pedidos as pedido, i (pedido)}
    <li>{pedido}</li>
  {/each}
</ul>
<button>entregar o primeiro</button> <ul><li>pão</li><li>leite</li><li>café</li></ul>

Depois de um clique, a lista vira ['leite', 'café']. Sem chave, o Svelte reaproveitaria o primeiro <li> para escrever "leite" e o segundo para escrever "café", apagando o terceiro. Com a chave (pedido), ele reconhece "leite" e "café" como os mesmos de antes e só remove o nó do "pão". O resultado visível é o mesmo nos dois casos; o que muda é o que acontece dentro de cada linha.

Chave duplicada e chave que falta

A chave precisa ser única. Se dois itens devolverem o mesmo valor, o motor do Svelte acusa no console uma mensagem que começa com Keyed each block has duplicate key e informa os dois índices em conflito. Se a chave não existir no objeto — (produto.codigo) num item que só tem id —, todos os itens devolvem undefined e o efeito é o mesmo de uma chave duplicada. Confira o nome do campo.

8. Experimente: conserte a chave

A caixa abaixo tem uma chave escrita pela metade. O compilador recusa o arquivo, então nem a lista aparece. Sua missão é fechar a chave para a tela mostrar os dois produtos com o seu id.

Missão: falta um parêntese na chave do {#each}. Conserte a pontuação para o componente compilar e mostrar 1: pão e 2: leite.

<script>
  let produtos = $state([
    { id: 1, nome: 'pão' },
    { id: 2, nome: 'leite' }
  ]);
</script>

<ul>
  {#each produtos as produto (produto.id}
    <li>{produto.id}: {produto.nome}</li>
  {/each}
</ul>
<script>
  let produtos = $state([
    { id: 1, nome: 'pão' },
    { id: 2, nome: 'leite' }
  ]);
</script>

<ul>
  {#each produtos as produto (produto.id)}
    <li>{produto.id}: {produto.nome}</li>
  {/each}
</ul>

Enquanto a chave está aberta, o componente não roda: você vê a mensagem do compilador no lugar da tela. Repare que a mensagem aponta a coluna exata do problema — o fim da linha, onde o ) deveria estar. Consertar pontuação em bloco é sempre a mesma tarefa: conte os pares de parênteses e de chaves.

9. Como escolher a chave

Chave boa tem três propriedades: é única, é estável e existe em todos os itens. Vamos ver as opções comuns para a lista de pedidos da Ana.

ChaveÚnica?Estável?Quando usar
(pedido.id)sim, se o banco garantesimo caso normal, com dados que vêm de um cadastro
(pedido.nome)só se não houver nome repetidosim, até alguém renomearlistas de textos sem repetição
(pedido)sim, pelo objetonão, se você recria o objeto a cada mudançalistas que nunca são recriadas
(i)sim, por definiçãonão: a posição mudaquase nunca; é o mesmo que não ter chave
sem chavenão se aplicanão se aplicalistas que só crescem no fim ou que nunca guardam estado

Se você não tem um identificador, dá para criar um na hora de montar a lista. Um contador que nunca repete, guardado fora do array, resolve:

let proximo = 3;

function novoPedido(nome) {
  return { id: proximo++, nome };
}

O detalhe que importa: o id nasce junto com o item e não muda depois. Se você calcular o id na hora de desenhar — com o índice, por exemplo —, ele muda junto com a posição e a chave perde o sentido. Chave é identidade, e identidade não se recalcula.

11. Quando dá errado

As três mensagens abaixo saíram do compilador desta versão, copiadas como estão. Todas são de pontuação: o bloco aceita exatamente um item, um índice e uma chave, e nada além disso.

Erro 1 — dois índices

O bloco aceita um índice. Escrever as item, i, j parece razoável e não é: depois da vírgula vem a posição, e depois dela só pode vir a chave entre parênteses.

<script>
  let lista = $state([1, 2]);
</script>

{#each lista as item, i, j}
  <p>{item}</p>
{/each}
Erro de compilação (linha 5, coluna 23): Expected token }

"Expected token }" quer dizer "eu esperava fechar a abertura aqui". A coluna 23 é o j. Se você precisa de duas informações por item, elas vêm de dentro do item (um objeto com duas partes), não de dois nomes no bloco.

Erro 2 — chave sem parêntese de fechamento

A chave é sempre um par de parênteses. Abrir e não fechar deixa o compilador esperando o resto da expressão.

<script>
  let lista = $state([1, 2]);
</script>

{#each lista as item (item}
  <p>{item}</p>
{/each}
Erro de compilação (linha 5, coluna 26): Expected token )

A mensagem aponta a coluna 26, que é o } da abertura do bloco — o lugar onde o ) deveria estar. É um erro fácil de ver quando o arquivo tem poucas linhas e difícil quando a chave é comprida; nesse caso, quebre a expressão em uma variável.

Erro 3 — vírgula sobrando antes da chave

Depois da vírgula vem um nome de índice. Sem nome, a vírgula ficou pendurada e o compilador não sabe o que criar ali.

<script>
  let lista = $state([1, 2]);
</script>

{#each lista as item, (item)}
  <p>{item}</p>
{/each}
Erro de compilação (linha 5, coluna 22): Expected an identifier

"Expected an identifier" é "eu esperava um nome". Se você quer só a chave, escreva {#each lista as item (item.id)}, sem vírgula nenhuma. A vírgula só existe para separar o item do índice.

Exercícios

1. Qual é o índice do primeiro item de um {#each}?

2. Para que serve a chave (item.id)?

3. O que acontece se dois itens tiverem a mesma chave?

Complete o código

{#each pedidos pedido, i}
  <li>{i + 1}º — {pedido}</li>
{/each}

// mostre a posição de cada pedido, começando em 1

Resumo

  • O índice vem depois da vírgula: {#each lista as item, i}.
  • O índice começa em 0; para mostrar a partir de 1, use {i + 1}.
  • lista.length - 1 é o índice do último item; i % 2 === 0 seleciona posições pares.
  • A chave fica entre parênteses, depois do item e do índice: {#each lista as item (item.id)}.
  • A chave não aparece na tela: é uma instrução para o motor reconhecer itens.
  • A chave precisa ser única e estável; (i) compila, mas muda junto com a posição.
  • Chave duplicada não é erro de compilação: o motor acusa no console em desenvolvimento.
  • Sem chave, o motor compara posições e recria linhas quando a lista muda.
  • Os erros desta aula: dois índices, chave sem parêntese e vírgula sem nome.
  • Filtre o dado antes quando a lista é grande; use o índice quando a regra é visual.
