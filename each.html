Svelte · Listas: {#each}

A Ana anota os pedidos num caderno de espiral: uma linha por pedido, e a quantidade de linhas muda todo dia. Quando o caderno vira uma tela, o problema aparece: o HTML é fixo, e a Ana não sabe hoje quantos pedidos terá amanhã. Escrever dez <li> e torcer para não passar de dez não é solução. Nesta aula você vai conhecer o bloco que repete HTML a partir de uma lista: {#each}. É ele que transforma três nomes guardados num array em três linhas na tela.

Você vai aprender
  • O que é um array (lista) e como guardar vários valores nele.
  • A repetir HTML com {#each lista as item}.
  • A ler a saída real, com uma linha de HTML por item.
  • O que acontece quando você usa a lista em vez do item dentro do bloco.
  • Como listas de objetos deixam cada linha com nome e preço.
  • Por que um objeto mostrado direto vira [object Object].
  • Como acrescentar itens com um clique e ver a tela crescer.
  • Listas dentro de listas, e a estrutura de tabela que o Svelte aceita.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • O que o build do projeto da Ana mostra quando a lista entra.

1. A ideia: uma linha para cada coisa

Existe uma diferença entre "um valor" e "vários valores". O nome da Ana é um valor. A lista de pedidos do dia é outra coisa: um valor que contém vários, na ordem em que chegaram. Em JavaScript, essa coleção ordenada se chama array (você vai ler "arrei"). Escreve-se entre colchetes, com vírgula entre os itens:

Um array é para a programação o que o caderno de espiral é para a padaria: um lugar onde as coisas ficam em ordem e onde você pode acrescentar mais uma linha no fim sem refazer as anteriores. O HTML, infelizmente, não tem essa ideia: uma tag <li> é uma linha, e pronto. Quem faz a ponte entre os dois é o bloco {#each}, que pega cada item do array e repete o HTML do bloco uma vez para cada um.

Repare no desenho: você escreve o HTML de um item, e o Svelte o repete quantas vezes forem necessárias. Dez pedidos, dez linhas; um pedido, uma linha; zero pedidos, nenhuma linha. O arquivo continua com as mesmas quatro linhas de HTML, o que significa que você não precisa saber hoje quantos pedidos virão amanhã.

O nome each vem do inglês "cada". O bloco se lê "para cada pedido em pedidos, repita isto". Duas palavras parecidas de propósito: a lista no plural, o item no singular. Essa escolha não é obrigatória, mas é o padrão que todo mundo usa, e você vai ler código assim em qualquer projeto Svelte.

2. O primeiro {#each} da Ana

Comece com três pedidos numa lista e um <li> só, dentro do bloco.

<script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedido}</li>
  {/each}
</ul>

O compilador gera três <li>, um para cada item, na ordem do array:

<ul><li>pão</li><li>leite</li><li>café</li></ul>

E o texto que aparece na tela é a sequência dos três:

pão leite café

A anatomia do bloco

{#each pedidos as pedido}
a abertura. Antes do as vai a lista; depois, o nome que cada item recebe dentro do bloco.
as pedido
a palavra as ("como") é obrigatória quando você quer usar o item. pedido é uma variável nova, criada pelo bloco, que vale um item por vez.
  • {pedido}
    • o modelo da linha: o HTML que se repete. Dentro dele, {pedido} muda a cada repetição.
    {/each}
    o fechamento. O HTML entre a abertura e o fechamento é o que se repete — nada mais.

    O bloco não cria elemento nenhum em volta: os três <li> ficam irmãos dentro do <ul> que já existia. Se você escrevesse o mesmo HTML à mão, o resultado seria idêntico — a diferença é que o bloco se adapta quando a lista muda de tamanho.

    each não é for

    Quem vem de outras linguagens procura o for. Em Svelte a repetição na marcação se chama each, e fecha com {/each}. O for normal do JavaScript continua existindo dentro do <script>, mas não serve para repetir HTML.

    3. Experimente: a linha certa

    A caixa abaixo repete a linha três vezes, mas mostra a lista inteira em cada linha. Sua missão é mostrar um item por linha.

    Missão: cada linha está mostrando o array todo. Troque o que aparece dentro do <li> para mostrar um pedido por linha.

    <script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedidos}</li>
  {/each}
</ul>
    <script>
  let pedidos = $state(['pão', 'leite', 'café']);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedido}</li>
  {/each}
</ul>

    Antes da correção, o texto da tela é pão,leite,café repetido três vezes. Isso acontece porque o bloco repetiu o HTML, mas o HTML falava da lista, não do item. O nome pedido é criado a cada volta e vale só dentro do bloco; a lista pedidos continua visível de qualquer lugar.

    Esse é o erro mais comum de quem começa: usar o plural dentro do bloco. Se a tela mostra a lista inteira repetida, olhe para o que está entre as chaves e pergunte: "isto é o item ou a lista?".

    4. De onde vem a lista

    Um array pode ser guardado em $state, como qualquer outro valor. O que muda é que agora existem duas operações do dia a dia: acrescentar e remover. A mais comum é acrescentar no fim, e ela se escreve copiando a lista antiga e pondo o novo item no fim, com a sintaxe dos três pontos.

    <script>
  let pedidos = $state(['pão']);
</script>

<button onclick={() => (pedidos = [...pedidos, 'leite'])}>adicionar leite</button>

<ul>
  {#each pedidos as p}
    <li>{p}</li>
  {/each}
</ul>
    <button>adicionar leite</button> <ul><li>pão</li></ul>

    Esse é o estado inicial: um pedido. Depois do clique, o array vira ['pão', 'leite'] e a lista ganha a segunda linha — sem você escrever um segundo <li>. A expressão [...pedidos, 'leite'] se lê "uma lista nova com tudo o que havia em pedidos, mais o leite".

    Você querEscrevaO que acontece na tela
    acrescentar no fimpedidos = [...pedidos, 'café']uma linha nova no fim
    acrescentar no começopedidos = ['café', ...pedidos]uma linha nova no topo
    tirar o primeiropedidos = pedidos.slice(1)a primeira linha some
    trocar tudopedidos = []todas as linhas somem
    acrescentar sem copiarpedidos.push('café')funciona com $state, porque ele observa o array

    A última linha merece um aviso. Com $state, o array é observado em profundidade, então push também avisa a tela. Muitos guias antigos mandam sempre copiar, porque no Svelte 4 a reatividade dependia de atribuição. Aqui as duas formas funcionam; a cópia é mais previsível e é a que você vai ver na maioria dos exemplos deste guia.

    5. Experimente: o botão que acrescenta

    Na caixa abaixo o botão existe, mas não faz nada. Sua missão é fazer cada clique acrescentar um leite à lista.

    Missão: o botão está vazio de ação. Faça o clique acrescentar leite no fim da lista, de modo que a tela fique adicionar leite pão leite.

    <script>

  {/each}

    <script>

</script>

    <li>{p}</li>
  {/each}

    Clique duas ou três vezes depois de resolver: a lista cresce a cada clique, e o bloco repete o <li> quantas vezes forem necessárias. O código do HTML continua com uma linha só. É esse tipo de economia que faz diferença num projeto grande — a Ana nunca vai precisar saber quantos pedidos o dia vai ter.

    A função do onclick precisa atribuir um valor novo. Escrever () => pedidos só devolve a lista e joga o resultado fora; nada muda. É a diferença entre apontar para o caderno e escrever nele.

    6. Listas de objetos: cada item com partes

    Uma lista de textos serve para nomes. Para pedidos com preço, cada item precisa de duas informações. A solução é um array de objetos: cada item é um conjunto de valores com nomes, escrito entre chaves.

    <script>
  let pedidos = $state([
    { nome: 'pão', preco: 0.9 },
    { nome: 'leite', preco: 4.5 }
  ]);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedido.nome} — R$ {pedido.preco.toFixed(2)}</li>
  {/each}
</ul>
    <ul><li>pão — R$ 0.90</li><li>leite — R$ 4.50</li></ul>

    Cada volta do bloco recebe um objeto inteiro em pedido, e você escolhe o que mostrar com o ponto: pedido.nome, pedido.preco. O ponto é a mesma ideia do toFixed da primeira aula: "pegue esta parte de dentro".

    E o que acontece se você esquecer o ponto? O componente compila, roda, e mostra um texto estranho:

    <script>
  let pedidos = $state([
    { nome: 'pão', preco: 0.9 },
    { nome: 'leite', preco: 4.5 }
  ]);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedido}</li>
  {/each}
</ul>
    <ul><li>[object Object]</li><li>[object Object]</li></ul>

    [object Object] é o JavaScript dizendo "isto é um objeto e eu não sei como transformar em texto". Não é erro de compilação: o programa roda, mas a informação não chega. Quando você vir esse texto na tela, a causa é sempre a mesma — falta um ponto e o nome da parte que você quer mostrar.

    A solução tem dois pontos e uma chamada de método dentro do HTML. Nada disso é novidade: o toFixed(2) já apareceu na aula do primeiro componente, e o ponto já apareceu lá também. O que a aula de hoje acrescenta é que agora essas expressões rodam uma vez por item, com um objeto diferente em pedido a cada volta.

    Uma consequência prática: se um item não tiver preco, o toFixed quebra e o componente inteiro para. Lista de objetos é ótima, mas cada item precisa ter as partes que o HTML usa. Você vai ver como proteger esse caso na aula de lista vazia.

    8. Listas dentro de listas

    Um bloco {#each} pode morar dentro de outro, e um {#if} pode proteger uma lista inteira. Na padaria, cada dia tem a sua própria lista de itens.

    <script>
  let dias = $state([
    { nome: 'segunda', itens: ['pão', 'leite'] },
    { nome: 'terça', itens: ['café'] }
  ]);
</script>

{#each dias as dia}
  <h3>{dia.nome}</h3>
  <ul>
    {#each dia.itens as item}
      <li>{item}</li>
    {/each}
  </ul>
{/each}
    <h3>segunda</h3> <ul><li>pão</li><li>leite</li></ul><h3>terça</h3> <ul><li>café</li></ul>

    São dois níveis: o de fora percorre os dias, o de dentro percorre os itens de cada dia. Repare nos nomes — dia no primeiro, item no segundo — e na indentação, que mostra quem está dentro de quem. O bloco de dentro enxerga as duas variáveis: item e dia.

    Proteger a lista com uma condição é ainda mais comum do que aninhar duas listas:

    <script>
  let pedidos = $state(['pão', 'leite']);
  let aberto = $state(true);
</script>

{#if aberto}
  <ul>
    {#each pedidos as pedido}
      <li>{pedido}</li>
    {/each}
  </ul>
{/if}
    <ul><li>pão</li><li>leite</li></ul>

    Com aberto em true, a lista aparece normalmente. Com false, o <ul> inteiro sai da tela, com os itens dentro. Os dois blocos se combinam sem nenhum truque: cada um fecha com o seu próprio nome.

    Tabela tem regra própria

    Dentro de <table>, o Svelte exige a estrutura que o HTML aceita: as linhas precisam estar dentro de <tbody>. Um {#each} que gera <tr> direto no <table> é recusado pelo compilador, com uma mensagem que você vai ver no fim desta aula. A forma certa fica assim:

    <script>
  let itens = $state(['pão', 'leite']);
</script>

<table>
  <tbody>
    {#each itens as item}
      <tr><td>{item}</td></tr>
    {/each}
  </tbody>
</table>
    <table><tbody><tr><td>pão</td></tr><tr><td>leite</td></tr></tbody></table>

    10. Quando dá errado

    As três mensagens abaixo saíram do compilador desta versão, copiadas como estão. A primeira e a segunda tratam do fechamento do bloco; a terceira, de uma regra do HTML que o Svelte resolve por você ao compilar.

    Erro 1 — fechou com o nome de outro comando

    Cada abertura tem um fechamento com o mesmo nome. {/for} não existe em Svelte: quem repete na marcação é o each.

    <script>
  let pedidos = $state(['pão']);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedido}</li>
  {/for}
</ul>
    Erro de compilação (linha 8, coluna 4): Expected token each

    "Expected token each" quer dizer "eu esperava a palavra each depois da barra". Repare que a linha apontada é a do fechamento errado, não a da abertura: o compilador sabe qual bloco está aberto e cobra o nome certo.

    Erro 2 — o bloco ficou aberto

    Aqui a tag </ul> aparece antes do {/each}. O compilador tenta fechar a lista e descobre que ainda está dentro do bloco.

    <script>
  let pedidos = $state(['pão']);
</script>

<ul>
  {#each pedidos as pedido}
    <li>{pedido}</li>
</ul>
    Erro de compilação (linha 8, coluna 0): `</ul>` attempted to close an element that was not open

    A mensagem fala da </ul> porque é ali que a estrutura deixa de fazer sentido. Traduzindo: "você está fechando um elemento que, para mim, nunca foi aberto neste ponto". O conserto é pôr o {/each} antes do </ul>.

    Erro 3 — <tr> direto dentro de <table>

    O HTML moderno não aceita uma linha solta dentro da tabela: ela precisa estar num <tbody>. O Svelte prefere recusar a entregar uma página que o navegador vai "consertar" por conta própria.

    <script>
  let itens = $state(['pão', 'leite']);
</script>

<table>
  <tr><th>Item</th></tr>
  {#each itens as item}
    <tr><td>{item}</td></tr>
  {/each}
</table>
    Erro de compilação (linha 6, coluna 2): `<tr>` cannot be a child of `<table>`. `<table>` only allows these children: `<caption>`, `<colgroup>`, `<tbody>`, `<thead>`, `<tfoot>`, `<style>`, `<script>`, `<template>`. The browser will 'repair' the HTML (by moving, removing, or inserting elements) which breaks Svelte's assumptions about the structure of your components.

    A mensagem é comprida porque explica o motivo: o navegador moveria, removeria ou inseriria elementos para consertar o HTML, e isso quebraria as contas que o Svelte faz sobre a sua marcação. O conserto é embrulhar o {#each} num <tbody>, como no exemplo da seção 8.

    Exercícios

    1. O que o texto '{#each pedidos as pedido}' significa?

    2. O que aparece na tela quando o array tem um objeto e o bloco mostra {pedido}?

    3. Quantos <li> o bloco gera para o array ['pão', 'leite', 'café']?

    Complete o código

    {#each pedidos pedido}
      <li>{pedido}</li>
    {/each}

    // dê um nome a cada item da lista

    Resumo

    • {#each lista as item} repete o HTML do bloco uma vez por item da lista.
    • A lista vem antes do as; o nome do item vem depois e só existe dentro do bloco.
    • O bloco fecha com {/each} — não existe {/for} na marcação.
    • O bloco não cria elemento em volta: os itens ficam irmãos, dentro da tag que você já escreveu.
    • Use o item dentro do bloco; usar a lista mostra o array inteiro repetido.
    • Array de objetos deixa cada linha com partes: {pedido.nome}, {pedido.preco}.
    • Mostrar um objeto direto na tela imprime [object Object].
    • Acrescentar item: lista = [...lista, 'novo']; com $state, push também avisa a tela.
    • Listas podem ficar dentro de condicionais e dentro de outras listas, cada bloco com o seu fechamento.
    • Dentro de <table>, as linhas precisam de <tbody>: o compilador recusa o resto.
