Svelte · $effect

A Ana quer um relógio na parede da padaria: a cada segundo, o número muda. Isso não é conta nem valor guardado — é uma ação que precisa acontecer quando a página já está desenhada. No Svelte, ações desse tipo moram numa runa chamada $effect. Ela é a peça que faz, enquanto $state guarda e $derived calcula.

Você vai aprender
  • O que é um efeito e por que ele não roda no servidor.
  • Como escrever $effect(() => { … }).
  • Quando o efeito roda: depois do desenho, e de novo a cada dependência.
  • Como limpar o que o efeito criou, devolvendo uma função.
  • Por que o return de um efeito não devolve valor.
  • Como o Svelte descobre de quais valores o efeito depende.
  • A diferença entre $effect e $effect.pre.
  • Por que calcular dentro de um efeito é quase sempre um erro.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como o projeto da Ana compila um componente com relógio.

1. A ideia: guardar, calcular e fazer

Três verbos organizam um componente. Guardar é o que o estado faz: o número de pães, o preço, o nome do cliente. Calcular é o que o derivado faz: o total, o desconto, o troco. Fazer é tudo o que mexe no mundo fora do valor: ligar um relógio, escutar o teclado, avisar o título da aba, guardar no navegador.

O terceiro verbo precisa de um lugar próprio porque tem regras próprias. Fazer algo durante o desenho da tela é arriscado; fazer algo toda vez que qualquer valor muda é caro; fazer algo e esquecer de desfazer é vazamento. O $effect existe para dar a essas ações um momento certo (depois do desenho) e um escopo certo (o componente que as criou).

Na padaria, o relógio é o exemplo perfeito. Ele não é um dado da Ana, nem uma conta dos dados dela: é um aparelho que precisa ser ligado quando a parede está pronta e desligado quando a parede sai. É exatamente esse o par que o efeito oferece: a ação e a limpeza.

Efeito é a runa mais cara das três, e por um motivo honesto: ele mexe no mundo. O mundo tem tempo, tem aparelhos, tem memória que não é devolvida sozinha. Cada execução precisa ser barata e cada recurso criado precisa de um caminho de volta. Quando o assunto pode ser resolvido com estado e derivado, resolva com eles — o efeito é para o que não tem outro lugar.

Na padariaNo componente
O caderno de pedidos$state: guarda
A conta do total$derived: calcula
Ligar o relógio da parede$effect: faz, depois do desenho
Desligar o relógio quando a parede saiA função devolvida pelo efeito
Conferir as horas a cada segundoO efeito roda de novo quando uma dependência muda

2. O primeiro $effect da Ana

Um efeito é uma função que o Svelte chama por você. No exemplo abaixo, ele muda o título da aba do navegador sempre que o número de pães muda:

<script>
  let paes = $state(0);

  $effect(() => {
    document.title = 'Pães: ' + paes;
  });
</script>

<p>Pães: {paes}</p>
<button onclick={() => paes++}>mais um</button>

O HTML gerado não tem nenhuma marca do efeito:

<p>Pães: 0</p> <button>mais um</button>

Isso é esperado e é uma das coisas mais importantes da aula: efeito não aparece no HTML. Ele não desenha nada; ele age no ambiente. Quem desenha continua sendo a marcação com as chaves. O título da aba, que é onde o efeito trabalha, vive fora do corpo da página e não faz parte do HTML gerado.

A anatomia do efeito

$effect(
a runa. Ela registra a função e diz quando chamá-la.
() => { … }
a ação. Não recebe parâmetros; o que ela precisa está no escopo do componente.
document.title = …
o mundo fora. Aqui, o título da aba. Poderia ser um setInterval, um addEventListener, uma biblioteca de gráficos.
paes
a dependência. O efeito lê paes, então o Svelte o reinscreve quando paes muda.
return () => { … }
a limpeza, opcional. Roda antes da próxima execução e quando o componente sai da tela.
Efeito é coisa de navegador

O Svelte renderiza componentes também no servidor, para entregar HTML pronto. Nesse caminho não existe aba, não existe document, não existe relógio — e os efeitos simplesmente não rodam. Por isso a saída acima mostra Pães: 0 sem nenhum sinal do título. O efeito começa a viver quando a página chega ao navegador.

3. Quando o efeito roda

A ordem é sempre esta: o Svelte desenha o HTML, o navegador mostra, e só então os efeitos rodam. Isso evita o efeito medir uma tela que ainda não existe. Depois da primeira execução, o efeito fica de pé esperando uma dependência mudar — e roda outra vez quando isso acontece.

Há uma diferença visível entre o HTML do servidor e a tela do navegador. Veja o componente do relógio:

<script>
  let tiques = $state(0);
  $effect(() => {
    const id = setInterval(() => tiques++, 100);
    return () => clearInterval(id);
  });
</script>

<p>Tiques: {tiques}</p>
<p>Tiques: 0</p>

No HTML gerado, zero. No navegador, o número começa a subir sozinho algumas dezenas de milissegundos depois de a página aparecer, porque o setInterval só foi ligado quando o efeito rodou. Se você recarregar, o zero volta a aparecer por um instante: é o intervalo entre o desenho e a primeira batida do relógio.

MomentoO que já aconteceu
Renderização (servidor ou navegador)o HTML está pronto; nenhum efeito rodou
Depois do desenhoprimeira execução de cada $effect
Uma dependência mudalimpeza da execução anterior e nova execução
Componente sai da telalimpeza da última execução

4. O primeiro experimento: ligue o relógio

O componente abaixo mostra o texto "esperando" e nunca muda. Sua missão é usar um efeito com setTimeout para trocar o texto para "pronto" meio segundo depois de a página aparecer.

Missão: a tela deve começar em esperando e virar pronto depois de um tempo, sem clique nenhum.

<script>
  let pronto = $state(false);
</script>

<p>{pronto ? 'pronto' : 'esperando'}</p>
<script>
  let pronto = $state(false);
  $effect(() => {
    const id = setTimeout(() => (pronto = true), 300);
    return () => clearTimeout(id);
  });
</script>

<p>{pronto ? 'pronto' : 'esperando'}</p>

A meta confere o texto antes (esperando), espera 600 milissegundos e confere de novo (pronto). Sem o efeito, o texto nunca sai do primeiro estado. Note que a solução também devolve a limpeza: se o componente sair da tela antes dos 300 milissegundos, o clearTimeout cancela o relógio e nada tenta desenhar numa tela que não existe.

5. A limpeza: o que o efeito devolve

Todo efeito que cria algo precisa saber destruir o que criou. Um intervalo sem clearInterval continua rodando para sempre, consumindo bateria e memória. Um addEventListener sem removeEventListener segura o componente inteiro na memória. O Svelte resolve isso aceitando uma função de limpeza como retorno do efeito:

<script>
  let segundos = $state(0);

  $effect(() => {
    const id = setInterval(() => segundos++, 1000);
    return () => clearInterval(id);
  });
</script>

<p>Na tela há {segundos} segundos.</p>
<p>Na tela há 0 segundos.</p>

A função devolvida não é chamada por você: o Svelte a chama na hora certa — antes da próxima execução do efeito e quando o componente é destruído. Isso mantém a regra simples: cada execução limpa a anterior, e nada fica acumulado.

Pense num ouvinte de evento que filtra a lista de produtos conforme a Ana digita. O efeito lê o texto da busca, então roda a cada letra. Sem limpeza, cada letra deixaria um ouvinte antigo para trás; depois de vinte letras, vinte ouvintes responderiam à mesma tecla. Com a limpeza, o ouvinte da execução anterior sai antes de o novo entrar, e o componente tem sempre exatamente um.

Missão: faça o contador de tiques andar sozinho. O número começa em 0 e precisa passar de zero em menos de meio segundo.

<script>
  let tiques = $state(0);
</script>

<p>Tiques: {tiques}</p>
<script>
  let tiques = $state(0);
  $effect(() => {
    const id = setInterval(() => tiques++, 100);
    return () => clearInterval(id);
  });
</script>

<p>Tiques: {tiques}</p>

Um detalhe de quem escreve isso pela primeira vez: () => clearInterval(id) é uma função que ainda não rodou. Se você escrever return clearInterval(id), o intervalo é cancelado imediatamente e o contador nunca sai do zero. A limpeza precisa ser entregue para o Svelte chamar depois.

6. As dependências do efeito

O Svelte descobre as dependências do efeito do mesmo jeito que faz com o derivado: executando a função e anotando cada valor reativo que ela lê. Isso tem uma consequência direta: o que o efeito não lê, não o faz rodar de novo.

É por isso que, às vezes, um efeito parece "morto": ele mexe na tela uma vez e nunca mais. Quase sempre falta a leitura de alguma coisa dentro da função.

Missão: o efeito roda uma vez e para. Faça execuções chegar a 2 no primeiro clique e a 3 no segundo, sem escrever o número à mão.

<script>
  let qtd = $state(0);
  let execucoes = $state(0);
  let conta = 0;

  $effect(() => {
    conta = conta + 1;
    execucoes = conta;
  });
</script>

<p>Cliques: {qtd} · execuções: {execucoes}</p>
<button onclick={() => qtd++}>mais um</button>
<script>
  let qtd = $state(0);
  let execucoes = $state(0);
  let conta = 0;

  $effect(() => {
    qtd;
    conta = conta + 1;
    execucoes = conta;
  });
</script>

<p>Cliques: {qtd} · execuções: {execucoes}</p>
<button onclick={() => qtd++}>mais um</button>

A linha qtd; sozinha parece inútil, e para o JavaScript é: ela só lê o valor. Para o Svelte, é a diferença entre um efeito que observa e um efeito que roda uma vez. Em código de produção, prefira ler o valor fazendo algo com ele — document.title = 'Cliques: ' + qtd — em vez de uma linha solta só para marcar presença.

Atenção ao contador do exemplo: conta é uma variável comum, sem runa. Se ela fosse $state, o incremento conta = conta + 1 leria conta dentro do efeito, criando uma dependência de si mesma. O resultado seria um laço infinito, com a mensagem que aparece na seção 8.

Quando você precisa ler um valor sem que ele vire dependência, existe untrack: uma função que recebe uma conta e executa sem registrar leituras. É útil para ler um valor de configuração que nunca muda dentro do efeito, ou para consultar um estado antigo sem reagendar a execução. Use com parcimônia: cada untrack é uma dependência que você esconde de quem lê o código.

7. $effect.pre e as outras formas

O $effect tem irmãos para casos específicos. Nenhum é obrigatório no começo; existem para quando você precisa de controle fino.

FormaQuando rodaPara que serve
$effect(…)depois do desenhoo caso normal: relógios, assinaturas, bibliotecas
$effect.pre(…)antes do desenhomedir algo antes de a tela mudar
$effect.root(…)cria um efeito fora da árvoreiniciar um serviço que vive por conta própria
$effect.tracking()dentro de um efeitosaber se você está num contexto reativo (true/false)
$effect.pending()durante awaitsaber se há promessa pendente

O pre é o mais usado dos irmãos. Imagine medir a altura de um elemento antes de trocar o conteúdo: com $effect, a medição aconteceria depois da troca; com $effect.pre, antes. É uma diferença de milissegundos que decide se a conta vê o estado antigo ou o novo.

Já o $effect.root raramente aparece numa aula introdutória: ele serve para criar um efeito que não pertence a nenhum componente, como um serviço global que precisa ser limpo à mão. Se você não sabe se precisa, não precisa.

8. O efeito não é lugar de calcular

Como o efeito roda quando um valor muda, é tentador usá-lo para atualizar outro valor. O código abaixo parece funcionar e é uma armadilha:

<script>
  let n = $state(0);

  $effect(() => {
    n = n + 1;
  });
</script>

<p>Contagem: {n}</p>
<p>Contagem: 0</p>

O efeito lê n e escreve n. Cada escrita muda a dependência, o que agenda outra execução, que escreve de novo. Em desenvolvimento, o Svelte interrompe o laço com uma mensagem clara no console:

Svelte error: effect_update_depth_exceeded
Maximum update depth exceeded. This typically indicates that an effect reads and writes the same piece of state
https://svelte.dev/e/effect_update_depth_exceeded

"Profundidade de atualização excedida: isso normalmente indica que um efeito lê e escreve o mesmo pedaço de estado." Quando o que você quer é o valor calculado, a runa é $derived; quando é fazer algo no mundo, a runa é $effect. Um efeito que só muda estado para a tela mostrar quase sempre deveria ser um derivado.

Existe uma terceira saída, e ela é a mais comum de todas: o valor não precisa ser estado. Se o número só serve para a tela mostrar e nunca é lido por um clique, por uma conta ou por outra parte do componente, ele pode ser uma variável comum calculada no próprio HTML. Menos runas, menos reações, menos lugares para errar.

Três usos honestos do efeito

Mexer no que está fora da página (título, localStorage, foco do teclado); ligar e desligar aparelhos (intervalos, ouvintes de evento, gráficos, mapas); chamar código de terceiros que precisa de um elemento já desenhado. Se a sua ação não é um desses três, desconfie.

10. Quando dá errado

As três mensagens abaixo são de compilação. Existe ainda um erro de execução, effect_orphan, que aparece quando um efeito é criado fora da inicialização do componente:

Svelte error: effect_orphan
`$effect` can only be used inside an effect (e.g. during component initialisation)
https://svelte.dev/e/effect_orphan

Ele acontece, por exemplo, quando você chama $effect dentro de uma função que só roda no clique. O efeito precisa de um componente vivo para pertencer; criado depois, não tem onde se pendurar.

1. Efeito sem função. A runa precisa de uma função para chamar depois:

<script>
  $effect();
</script>

<p>Pães: 0</p>
Erro de compilação (linha 2, coluna 2): `$effect` must be called with exactly one argument

"$effect precisa ser chamado com exatamente um argumento". E esse argumento tem de ser uma função: $effect(() => { … }).

2. Efeito guardado numa variável. O efeito não devolve valor; ele é uma instrução, não uma expressão:

<script>
  let x = $effect(() => {});
</script>

<p>Pães: 0</p>
Erro de compilação (linha 2, coluna 10): `$effect()` can only be used as an expression statement

"$effect() só pode ser usado como instrução de expressão". Em outras palavras: escreva a chamada sozinha, numa linha, sem let nem return. Se você precisa guardar algo do efeito, guarde o que ele criou (como o id do intervalo).

3. A runa sem parênteses. Escrever só $effect não registra nada:

<script>
  $effect;
</script>

<p>Pães: 0</p>
Erro de compilação (linha 2, coluna 2): Cannot use rune without parentheses

"Não posso usar a runa sem parênteses". Toda runa é chamada: $effect(função), $state(valor), $derived(conta).

Uma última regra de bolso, que resolve a maioria das dúvidas: se o resultado da sua ação pode ser lido na tela, ele provavelmente devia ser derivado; se o resultado é algo fora da tela, é efeito. E todo efeito que cria algo ganha uma função de limpeza — sem exceção.

Exercícios

1. Quando o $effect roda pela primeira vez?

2. Para que serve a função devolvida pelo efeito?

3. Um efeito que lê e escreve o mesmo estado provoca qual erro?

Complete o código

$effect(() => {
  const id = setInterval(() => segundos++, 1000);
  return ;
});

// o relógio precisa ser desligado quando o componente sair

Resumo

  • $effect é a runa do fazer: ela age fora do valor, ao contrário de $state e $derived.
  • O efeito roda depois do desenho e de novo a cada mudança das dependências que ele lê.
  • Efeitos não rodam no servidor: o HTML gerado não mostra nada do que eles fazem.
  • Devolver uma função do efeito registra a limpeza; ela roda antes da próxima execução e na destruição.
  • O que o efeito não lê, não o faz rodar de novo — daí a importância da leitura de dependências.
  • $effect.pre roda antes do desenho; $effect.root cria efeito fora da árvore.
  • Escrever o estado que o efeito lê gera effect_update_depth_exceeded; para cálculos, use $derived.
  • Criar efeito fora da inicialização gera effect_orphan.
  • Erros de compilação desta aula: $effect() sem função, efeito guardado em variável e runa sem parênteses.
  • Todo efeito que cria algo precisa de limpeza — intervalo, ouvinte, conexão, gráfico.
