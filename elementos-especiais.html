Svelte · svelte:element e Afins

A Ana tem um caderno de pedidos com títulos de tamanhos diferentes: o nome da padaria é grande, o nome do cliente é médio, o item é pequeno. No HTML, isso são h1, h2 e h3 — tags diferentes para o mesmo tipo de conteúdo. Escrever três {#if} só para trocar a tag é feio. O Svelte tem uma família de tags que começam com svelte: justamente para esses casos: elas não são HTML, são instruções para o compilador.

Você vai aprender
  • O que são as tags svelte: e por que elas não aparecem no HTML.
  • Como trocar a tag de um elemento em tempo de execução com svelte:element.
  • Por que o elemento dinâmico sempre recebe o selo do componente.
  • O que são as âncoras <!----> que aparecem no navegador.
  • Como colocar o título da aba com svelte:head.
  • Como ouvir eventos de window, document e body.
  • Para que serve o svelte:options e as opções deste arquivo.
  • O que aconteceu com svelte:self e svelte:component.
  • Como segurar um erro com svelte:boundary.
  • Os três erros reais destas tags, com a mensagem do compilador.

1. Tags que o compilador lê antes de desenhar

Todo arquivo .svelte já tem tags especiais: <script> e <style> não viram elementos na página, viram código. As tags svelte: seguem a mesma ideia, com um detalhe: elas são instruções para o compilador, e cada uma mexe numa parte diferente da página.

svelte:elementdesenha um elemento cuja tag vem de uma expressãosim, a tag que você escolher
svelte:headpõe conteúdo no <head> da páginanão no corpo

Duas diferenças em relação a um componente comum: você não importa nada para usar essas tags — elas fazem parte do compilador — e o nome delas nunca chega ao navegador. Se você abrir o inspetor de elementos e procurar por <svelte:head>, não vai achar: vai achar o que ela colocou lá.

A lista completa, como o próprio compilador a escreve: svelte:head, svelte:options, svelte:window, svelte:document, svelte:body, svelte:element, svelte:component, svelte:self, svelte:fragment e svelte:boundary. Guarde essa lista: ela aparece inteira numa mensagem de erro da seção 10.

2. <svelte:element>: a tag que vem de uma variável

O caso da Ana: o título do pedido precisa ser h1, h2 ou h3 conforme o nível. Em vez de escrever três blocos e repetir o conteúdo, ela guarda o nome da tag numa variável e usa svelte:element:

<script>
  let tag = $state('h2');
</script>

<svelte:element this={tag}>Padaria da Ana</svelte:element>
<h2>Padaria da Ana</h2>

O atributo this é obrigatório e recebe uma expressão, sempre entre chaves. Ele é o único atributo com esse nome no Svelte, e é o que diz ao compilador "a tag deste elemento está aqui". O conteúdo entre as tags é o conteúdo do elemento, como em qualquer outra tag.

this
o nome fixo do atributo que recebe a tag. Não é uma variável sua: é do Svelte.
{tag}
uma expressão que resulta numa string: 'h2', 'li', 'button'.
Padaria da Ana
o conteúdo do elemento, que pode ter texto, outras tags e expressões.
class="…"
qualquer outro atributo funciona normalmente, inclusive class e onclick.
</svelte:element>
o fechamento. Como qualquer tag, precisa ser fechada.

Como o this aceita qualquer expressão, dá para montar o nome da tag na hora: this={'h' + nivel} com nivel valendo 3 vira h3. Também dá para escolher entre tags que não são títulos — 'li' numa lista, 'button' num menu, 'div' quando não há tag melhor.

Missão: o título está fixo em h2, mas o nível vem do estado. Escreva a tag a partir da variável nivel, usando svelte:element. A meta mostra as âncoras <!----> porque o elemento é dinâmico — o Svelte precisa de um lugar para trocar a tag.

<h2>Padaria</h2>
<script>
  let nivel = $state(3);
</script>

<svelte:element this={'h' + nivel}>Padaria</svelte:element>

Antes, o HTML é <h2>Padaria</h2>. Depois, é <!----><h3>Padaria</h3><!---->: o texto é o mesmo, a tag mudou e apareceram dois comentários vazios. Eles são as âncoras do elemento dinâmico, e você vai entender o papel delas na próxima seção.

Um aviso que vale conhecer: se você escrever o valor como texto, this="h2", o compilador avisa svelte_element_invalid_this com a mensagem "`this` should be an `{expression}`. Using a string attribute value will cause an error in future versions of Svelte". Hoje ainda funciona; amanhã, não. Use chaves desde já.

3. O selo e as âncoras do elemento dinâmico

Um componente com estilo e um elemento dinâmico levantam uma pergunta: o selo vai no elemento? O compilador não sabe qual tag virá, então ele não tem como decidir pelo seletor. A resposta é que o selo vai sempre:

<script>
  let tag = $state('h2');
</script>

<svelte:element this={tag}>Padaria da Ana</svelte:element>

<style>
  h2 { color: #b8860b; }
</style>
<h2 class="svelte-1n46o8q">Padaria da Ana</h2>

Aqui o selo até parece fazer sentido, porque a tag é h2 e existe uma regra para h2. Mas teste trocar o valor para 'div': o elemento continua recebendo class="svelte-1n46o8q", mesmo sem nenhuma regra para div. O compilador marca o elemento dinâmico por precaução — quem decide se a regra vale é o seletor inteiro, no navegador: h2.svelte-1n46o8q não casa com um div, então nada muda na tela.

Isso tem uma consequência prática boa: o estilo do componente vale para o elemento dinâmico quando a tag escolhida casa com a regra. Se a sua regra é .cartao { … } e o elemento dinâmico tem class="cartao", ele é pintado normalmente, qualquer que seja a tag.

Agora as âncoras. Um elemento dinâmico pode mudar de tag a qualquer momento — de h2 para h3, por exemplo. Trocar um elemento por outro no meio da árvore não é simples: o navegador precisa saber onde o antigo estava para colocar o novo no mesmo lugar. É para isso que servem os comentários vazios. No navegador, com o componente da Ana rodando no servidor de desenvolvimento, o HTML do bloco é este:

<!----><h2>Padaria da Ana</h2><!----> <p>Pão quentinho todo dia</p>

As duas âncoras marcam o começo e o fim do espaço que o elemento dinâmico ocupa. Quando a Ana mudou a variável para 'h1' e salvou o arquivo, o navegador trocou só aquele pedaço: <!----><h1>Padaria da Ana</h1><!---->. O parágrafo seguinte não foi tocado.

E quando o valor é null? O Svelte simplesmente não desenha nada — nem a tag, nem o conteúdo:

<script>
  let tag = $state(null);
</script>

<svelte:element this={tag}>Padaria</svelte:element>
<p>fim</p>
<p>fim</p>

Isso é útil: uma lista de opções vazia pode render nada em vez de um div fantasma. Só não confunda com undefined escrito como texto — o valor precisa ser null de verdade, ou uma string com nome de tag válido.

4. <svelte:head>: o título da aba

O título que aparece na aba do navegador mora no <head> do documento, não no corpo. Se você escrever <title> no meio do componente, ele é desenhado no corpo — e o navegador ignora o título da aba. O svelte:head resolve isso: o conteúdo dele é levado para o <head>:

<svelte:head>
  <title>Padaria da Ana</title>
</svelte:head>

<h1>Padaria da Ana</h1>
<h1>Padaria da Ana</h1>

Repare no que o corpo não tem: o título. Ele foi para o head, onde o compilador o entrega separado do resto. Nesta renderização, o head recebe <meta name="description" content="Pão quentinho todo dia"/> e <title>Padaria da Ana</title> — as duas tags que estavam dentro do bloco.

Nada impede vários componentes de terem o seu svelte:head: o Svelte junta os pedidos e atualiza o documento. É assim que uma página de produto troca o título da aba sem recarregar o site. Como o head é um lugar só, o último que escrever vence — então evite dois componentes disputando o mesmo <title>.

Missão: o <title> está no corpo do componente, e por isso não vira o título da aba. Mova-o para um <svelte:head>, deixando o corpo só com o h1.

<title>Padaria da Ana</title>
<h1>Padaria</h1>
<svelte:head>
  <title>Padaria da Ana</title>
</svelte:head>

<h1>Padaria</h1>

Antes, o HTML do componente é <title>Padaria da Ana</title><h1>Padaria</h1> — o título está no lugar errado. Depois, sobra <h1>Padaria</h1> no corpo, e o título assume o seu posto no head.

5. <svelte:window>, <svelte:document> e <svelte:body>

A Ana quer mostrar a última tecla que o cliente digitou. Escrever isso exigiria pegar o objeto window e adicionar um ouvinte de evento na mão, com cuidado para remover quando o componente sair da tela. O svelte:window faz o trabalho: você declara o evento como se fosse um atributo de uma tag:

<script>
  let tecla = $state('');
</script>

<svelte:window onkeydown={(e) => tecla = e.key} />
<p>Última tecla: {tecla}</p>
<p>Última tecla: </p>

O elemento não desenha nada: o corpo tem só o parágrafo, e o valor de tecla está vazio porque ninguém digitou ainda. Quando alguém digita, o Svelte chama a função, o estado muda e o parágrafo se atualiza. Na tela, o texto passa a ser Última tecla: a, depois Última tecla: b.

O mesmo padrão vale para os outros dois: <svelte:document> ouve eventos do documento — onvisibilitychange quando a aba perde ou ganha foco, onpointerlockchange — e <svelte:body> ouve eventos do body, como onmouseenter e onmouseleave. Os três desenham zero elementos.

Há regras de lugar para eles. Todos precisam estar no nível de fora do componente: não podem ficar dentro de uma <div> nem de um {#if}. Se você tentar, o compilador responde "`<svelte:window>` tags cannot be inside elements or blocks". E cada componente aceita um só: dois svelte:window no mesmo arquivo dão o erro "A component can only have one `<svelte:window>` element". Para vários eventos, junte tudo na mesma tag.

6. <svelte:options>: as opções do arquivo

O svelte:options é a única tag svelte: que não tem a ver com a página: ela configura como o arquivo é compilado. A mais usada hoje é runes={true}, que força o modo das runas:

<svelte:options runes={true} />

<script>
  let n = $state(0);
</script>

<p>Contador: {n}</p>
<p>Contador: 0</p>

Como você pode ver, a tag não desenha nada: o corpo tem só o parágrafo. O que ela fez foi dizer ao compilador "este arquivo usa runas" — e com isso let n = $state(0) passa a ser reagente de verdade, e $: deixa de ser aceito.

As outras opções raramente aparecem num projeto de aprendizado: immutable (diz que o estado nunca é mutado, só trocado), accessors (cria getters e setters para props), namespace (para gerar SVG ou MathML por padrão) e customElement (empacota o componente como um elemento HTML de verdade). Esta última tem uma pegadinha: ela só vale quando o projeto compila com customElement: true; sem isso, o compilador avisa options_missing_custom_element com "The `customElement` option is used when generating a custom element. Did you forget the `customElement: true` compile option?".

No dia a dia, você quase não escreve svelte:options. Vale saber que existe para não estranhar quando um arquivo de exemplo começar com ela.

7. <svelte:self> e <svelte:component>: o que era e o que virou

Duas tags desta família entraram em desuso no Svelte 5. Elas continuam funcionando, mas o compilador avisa — e você vai encontrar as duas em código antigo.

<svelte:self> servia para um componente desenhar a si mesmo: uma árvore de pastas, um comentário com respostas. Hoje o compilador avisa svelte_self_deprecated: "`<svelte:self>` is deprecated — use self-imports (e.g. `import App from './App.svelte'`) instead". A receita nova é literalmente importar o próprio arquivo: import App from './App.svelte' e usar <App n={n - 1} /> dentro do {#if}. O svelte:self antigo também tinha uma exigência chata: só podia existir dentro de {#if}, {#each} ou de um {#snippet} — fora deles, o erro é "`<svelte:self>` components can only exist inside `{#if}` blocks, `{#each}` blocks, `{#snippet}` blocks or slots passed to components". Sem esse limite, o componente se chamaria para sempre.

<svelte:component> servia para escolher qual componente desenhar numa variável. No Svelte 5 isso ficou desnecessário: uma variável que guarda um componente já pode ser usada direto na tag, e o compilador avisa svelte_component_deprecated: "`<svelte:component>` is deprecated in runes mode — components are dynamic by default". O "dynamic by default" é a chave: <qual /> já funciona, sem tag especial.

A terceira aposentada é <svelte:fragment>, substituída pelos {#snippet} que você já usa. Nenhuma delas quebra de imediato; todas pedem uma migração quando você tiver tempo.

8. <svelte:boundary>: quando um pedaço quebra

Um erro dentro de um componente derruba a página inteira: a tela fica em branco e o console mostra o motivo. O svelte:boundary existe para limitar o estrago: se algo dentro dele quebrar, o Svelte desenha um trecho alternativo no lugar — e o resto da página continua de pé.

O trecho alternativo é um {#snippet failed}. Ele recebe o erro e uma função para tentar de novo:

Missão: este componente quebra de propósito — a expressão lança um erro durante o desenho. Envolva tudo num <svelte:boundary> com um {#snippet failed(erro)} que mostre Deu erro: {erro.message}.

<p>{ (function () { throw new Error('sem tempero') })() }</p>
<svelte:boundary>
  <p>{ (function () { throw new Error('sem tempero') })() }</p>

  {#snippet failed(erro)}
    <p>Deu erro: {erro.message}</p>
  {/snippet}
</svelte:boundary>

Antes, o componente quebra: o erro sem tempero sobe até a raiz e não há o que desenhar. Depois, o boundary segura o erro e a tela mostra Deu erro: sem tempero — a mensagem que o snippet montou a partir de erro.message.

Esse é um recurso de Nível 2 e não é para envolver tudo: use onde há risco real — conteúdo que vem de fora, um componente de terceiros, um trecho que depende de dados que podem faltar. Um boundary em volta da aplicação inteira só troca a tela em branco por uma mensagem em branco.

10. Quando dá errado

As três mensagens abaixo são todas sobre o lugar ou a forma das tags svelte:. Repare que duas delas listam o que é válido — mensagens assim são um mapa, não um castigo.

1. svelte:element sem this. A tag precisa saber qual elemento desenhar:

<script>
  let tag = $state('h2');
</script>

<svelte:element>{tag}</svelte:element>
Erro de compilação (linha 5, coluna 0): `<svelte:element>` must have a 'this' attribute with a value

"<svelte:element> precisa de um atributo 'this' com um valor". O conteúdo do elemento não serve como tag: {tag} ali dentro só desenharia o texto h2. A correção é <svelte:element this={tag}>.

2. Nome de tag que não existe. Um svelte:janela, traduzido do inglês:

<svelte:janela />
Erro de compilação (linha 1, coluna 1): Valid `<svelte:...>` tag names are svelte:head, svelte:options, svelte:window, svelte:document, svelte:body, svelte:element, svelte:component, svelte:self, svelte:fragment or svelte:boundary

A mensagem lista os dez nomes válidos. Note que todos são em inglês e em minúsculas: svelte:window, não svelte:janela.

3. svelte:window no lugar errado. Dentro de um {#if}, o compilador não aceita:

<script>
  let ativo = $state(true);
</script>

{#if ativo}
  <svelte:window onkeydown={() => {}} />
{/if}
Erro de compilação (linha 6, coluna 2): `<svelte:window>` tags cannot be inside elements or blocks

"Tags <svelte:window> não podem ficar dentro de elementos ou blocos". Tire a tag do {#if} e controle o evento pela função: onkeydown={(e) => { if (ativo) { … } }}.

O resumo da ideia: as tags svelte: são atalhos para coisas que o HTML não sabe expressar — uma tag decidida em tempo de execução, um conteúdo que pertence a outro lugar do documento, um evento da janela, um erro contido. Elas não são componentes e não são importadas; são parte da linguagem que o compilador entende.

2. Onde o conteúdo de <svelte:head> é desenhado?

3. Por que o elemento dinâmico recebe o selo do componente mesmo quando a tag não casa com nenhuma regra?

Complete o código

<script>
  let tag = $state('h2');

Resumo

  • As tags svelte: são instruções para o compilador; não são componentes e não são importadas.
  • <svelte:element this={…}> desenha a tag que a expressão devolver.
  • this precisa ser uma expressão entre chaves; string solta gera svelte_element_invalid_this.
  • O elemento dinâmico recebe o selo sempre; o seletor é quem decide se a regra casa.
  • As âncoras <!----> marcam onde o elemento dinâmico pode ser trocado.
  • this={null} não desenha nada.
  • svelte:head manda o conteúdo para o <head>; é assim que se muda o título da aba.
  • svelte:window, svelte:document e svelte:body ouvem eventos e precisam ficar no nível de fora do componente.
  • svelte:options configura o arquivo (runes, customElement) e não desenha nada.
  • svelte:self e svelte:component estão em desuso; svelte:boundary segura erros com um {#snippet failed}.
