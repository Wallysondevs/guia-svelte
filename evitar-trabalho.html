Svelte · Evitando Trabalho Repetido

A Ana tem um forno a lenha e um problema de conta: para cada cliente que pergunta o total da compra, ela acende o forno, assa um pão de teste e só então soma os itens do pedido. Funciona, mas o forno não tem nada a ver com a soma. No componente acontece o mesmo quando a mesma conta é feita em dois lugares da tela, ou quando uma ferramenta cara é criada a cada item da lista. Esta aula mostra como calcular uma vez, guardar o resultado e usar quantas vezes precisar — com um contador na tela provando a diferença.

Você vai aprender
  • Por que repetir a mesma conta é caro mesmo quando cada conta é rápida.
  • Como o $derived guarda o resultado e evita o recálculo.
  • Quando a função chamada no template trabalha mais que o necessário.
  • Como usar $derived.by para cálculos de várias linhas.
  • Como criar ferramentas caras — formatador, expressão regular — uma vez só.
  • Como manter o cabeçalho e a lista mostrando o mesmo número.
  • O que untrack faz e quando ele é necessário.
  • O que não pode acontecer dentro de um derivado.
  • Como medir o trabalho com um contador de execuções.
  • Os três erros reais desta aula, com a mensagem do compilador.

1. A ideia: o forno e a soma

Existe uma diferença entre trabalho necessário e trabalho repetido. Somar os itens de um pedido é necessário: sem a soma, não há total. Acender o forno para somar é repetido: o forno não participa da conta e poderia muito bem ficar apagado. O programador que não presta atenção faz as duas coisas ao mesmo tempo, e o programa funciona — só que mais devagar.

Em componente, o trabalho repetido aparece de três jeitos. O primeiro é a mesma conta escrita em dois lugares: o cabeçalho conta os achados de um jeito e a lista filtra de outro, e os dois números discordam. O segundo é a ferramenta criada a cada uso: um formatador de dinheiro construído dentro de um laço, uma vez por item. O terceiro é o cálculo que depende de tudo: uma conta que lê cinco estados e é refeita quando qualquer um deles muda, mesmo quando o resultado seria o mesmo.

O Svelte tem uma ferramenta para cada caso, e todas se chamam pelo mesmo nome: derivado. Um derivado é um valor calculado a partir de outros, guardado até que uma das fontes mude. O resto desta aula é aprender a usar essa ferramenta sem abusar dela.

O vocabulário: derivado é o valor calculado a partir de outro; cache é o resultado guardado para não ser refeito; dependência é o dado que, ao mudar, obriga o cálculo a rodar de novo; e contador de execuções é o número que mostra quantas vezes o cálculo aconteceu. Quatro palavras, e a aula inteira é sobre a relação entre elas.

2. O cálculo repetido no template

Comece com o jeito ingênuo: uma função que soma uma lista fixa, multiplica por um fator que vem do estado e, de brinde, incrementa um contador de execuções. A função é chamada em dois lugares da tela, porque as duas informações são úteis.

<script>
  const base = [1, 2, 3, 4];
  const execucoes = { n: 0 };

  let fator = $state(1);

  function somaComFator() {
    execucoes.n += 1;
    return base.reduce((a, b) => a + b, 0) * fator;
  }
</script>

<p>total: {somaComFator()}</p>
<p>resumo: {somaComFator()} reais</p>
<p>execuções: {execucoes.n} · fator {fator}</p>

<button onclick={() => (fator += 1)}>mudar fator</button>

O HTML do servidor já mostra o problema: o painel diz que a função rodou duas vezes para produzir o mesmo número.

<p>total: 10</p> <p>resumo: 10 reais</p> <p>execuções: 2 · fator 1</p> <button>mudar fator</button>
const base = [1, 2, 3, 4]
a lista de onde vem a soma. Constante, porque o conteúdo não muda enquanto o componente vive.
const execucoes = { n: 0 }
o contador de diagnóstico. Não é estado: ele não precisa avisar a tela, só ser lido quando a tela já vai desenhar.
somaComFator()
a função chamada duas vezes, uma em cada parágrafo. Cada chamada é trabalho de verdade.
fator
a dependência: quando muda, os dois parágrafos que chamam a função são redesenhados e a função roda de novo.
{execucoes.n} · fator {fator}
o parágrafo que mostra a contagem. Ele lê fator, então é atualizado junto com os outros.

Com um clique no botão, o número dobra. É o teste mais honesto que existe: a mesma tela, o mesmo resultado visível, o dobro de trabalho.

3. $derived: calcule uma vez, use quantas quiser

A correção é transformar a função em valor derivado. A regra do Svelte é esta: um $derived roda no máximo uma vez por mudança de dependência, não importa quantos lugares leiam o resultado. Dez leitores, um cálculo.

<script>
  const base = [1, 2, 3, 4];
  const execucoes = { n: 0 };

  let fator = $state(1);

  let total = $derived.by(() => {
    execucoes.n += 1;
    return base.reduce((a, b) => a + b, 0) * fator;
  });
</script>

<p>total: {total}</p>
<p>resumo: {total} reais</p>
<p>execuções: {execucoes.n} · fator {fator}</p>

<button onclick={() => (fator += 1)}>mudar fator</button>

Agora o contador diz uma vez, e não duas:

<p>total: 10</p> <p>resumo: 10 reais</p> <p>execuções: 1 · fator 1</p> <button>mudar fator</button>
let total = $derived.by(() => { … })
o valor passa a ser calculado e guardado. O bloco roda quando o Svelte precisa do valor e alguma dependência mudou.
execucoes.n += 1
a marca de que o cálculo rodou. Repare: a contagem fica dentro do derivado, não no template.
return …
o que o derivado entrega. Todo derivado precisa devolver alguma coisa; sem return, o valor é undefined.
{total}
as duas leituras usam o mesmo valor guardado. A segunda não recalcula nada.

No navegador, a diferença fica ainda mais clara: um clique no botão leva o contador de 2 para 4 na versão com função, e de 1 para 2 na versão com derivado. Mesmo resultado na tela, metade do trabalho — e a diferença cresce com o número de lugares que mostram o valor.

Missão: depois de um clique, o painel mostra execuções: 4 porque a conta é feita duas vezes. Guarde o resultado num derivado e faça o mesmo clique terminar em execuções: 2, com o total certo.

4. $derived.by para o cálculo de várias linhas

Quando o cálculo cabe numa linha, $derived(expressão) é o suficiente. Quando precisa de variáveis intermediárias, laços ou condicionais, o jeito é $derived.by, que recebe uma função e deixa o corpo à vontade.

<script>
  let itens = $state([
    { nome: 'Pão francês', preco: 0.9, quantidade: 3 },
    { nome: 'Bolo de fubá', preco: 12.5, quantidade: 1 }
  ]);

  let resumo = $derived.by(() => {
    const total = itens.reduce((soma, i) => soma + i.preco * i.quantidade, 0);
    const maisCaro = [...itens].sort((a, b) => b.preco - a.preco)[0];
    return `${itens.length} itens, ${maisCaro.nome} é o mais caro, total R$ ${total.toFixed(2)}`;
  });
</script>

<p>{resumo}</p>

O resumo sai numa linha, calculado uma vez e lido uma vez:

<p>2 itens, Bolo de fubá é o mais caro, total R$ 15.20</p>

O $derived.by é a forma mais legível para três ou quatro passos. O custo é que o corpo é uma função: quem lê precisa entender que o return é o valor final e que nada depois dele roda. Um erro comum é esquecer o return e receber undefined na tela — o componente desenha, mas o texto some.

Missão: o resumo só conta os itens. Calcule também o total — preço vezes quantidade — e mostre 1 item(ns), total R$ 2.70.

<script>
  let itens = $state([{ nome: 'Pão', preco: 0.9, quantidade: 3 }]);

  let resumo = $derived.by(() => {
    return `${itens.length} item(ns)`;
  });
</script>

<p>{resumo}</p>
<script>
  let itens = $state([{ nome: 'Pão', preco: 0.9, quantidade: 3 }]);

  let resumo = $derived.by(() => {
    const total = itens.reduce((soma, i) => soma + i.preco * i.quantidade, 0);
    return `${itens.length} item(ns), total R$ ${total.toFixed(2)}`;
  });
</script>

<p>{resumo}</p>

5. Ferramentas caras: crie uma vez

Algumas coisas em JavaScript são objetos com configuração: o formatador de dinheiro, a expressão regular, o mapa de conversão. Criar um desses é barato uma vez e caro mil vezes. O formatador de moeda, por exemplo, precisa consultar a tabela de idiomas do navegador toda vez que nasce.

<script>
  const produtos = [
    { nome: 'Pão francês', preco: 0.9 },
    { nome: 'Bolo de fubá', preco: 12.5 }
  ];

  function formatar(preco) {
    return new Intl.NumberFormat('pt-BR', {
      style: 'currency',
      currency: 'BRL'
    }).format(preco);
  }
</script>

<ul>
  {#each produtos as p}
    <li>{p.nome}: {formatar(p.preco)}</li>
  {/each}
</ul>

O resultado na tela é o esperado, com vírgula e símbolo:

<ul><li>Pão francês: R$ 0,90</li><li>Bolo de fubá: R$ 12,50</li></ul>

O problema não aparece na saída: aparece no custo. Um formatador novo por item, e a lista da Ana tem quarenta. A correção é criar o formatador fora do laço, uma vez por componente, e guardar só a função que formata:

<script>
  const produtos = [
    { nome: 'Pão francês', preco: 0.9 },
    { nome: 'Bolo de fubá', preco: 12.5 }
  ];

  const reais = new Intl.NumberFormat('pt-BR', {
    style: 'currency',
    currency: 'BRL'
  });
</script>

<ul>
  {#each produtos as p}
    <li>{p.nome}: {reais.format(p.preco)}</li>
  {/each}
</ul>
<ul><li>Pão francês: R$ 0,90</li><li>Bolo de fubá: R$ 12,50</li></ul>

Os dois HTML são idênticos — é isso que torna esse tipo de desperdício difícil de ver. A diferença está no trabalho: um formatador contra dois, no exemplo de dois produtos; um contra quarenta no catálogo de verdade.

FerramentaCriar dentro do laçoCriar uma vez
Intl.NumberFormatconsulta a tabela de idiomas por itemuma consulta por componente
Intl.DateTimeFormatidem, e a de datas é maioridem
new RegExp(…)compila o padrão por itemcompila uma vez
new Map() preenchidorecria a tabela por itemreaproveita a tabela
lista de opções fixarecria o array por itemdeclara fora do componente

6. A mesma lista em dois lugares

O caso mais comum de trabalho repetido não é lento, é errado. O cabeçalho conta todos os produtos, a lista mostra só os filtrados, e os dois números discordam na tela. O usuário vê "3 achados" acima de duas linhas.

Missão: o cabeçalho conta a lista inteira e diz 3, mas só dois produtos aparecem. Faça o número e a lista saírem do mesmo resultado, mostrando 2 achado(s).

<script>
  let busca = $state('pão');
  let produtos = ['Pão francês', 'Bolo de fubá', 'Pão de queijo'];
</script>

<p>{produtos.length} achado(s)</p>

<ul>
  {#each produtos.filter((p) => p.toLowerCase().includes(busca)) as p}
    <li>{p}</li>
  {/each}
</ul>

<button onclick={() => (busca = 'pão')}>buscar pão</button>
<script>
  let busca = $state('pão');
  let produtos = ['Pão francês', 'Bolo de fubá', 'Pão de queijo'];
  let achados = $derived(produtos.filter((p) => p.toLowerCase().includes(busca)));
</script>

<p>{achados.length} achado(s)</p>

<ul>
  {#each achados as p}
    <li>{p}</li>
  {/each}
</ul>

<button onclick={() => (busca = 'pão')}>buscar pão</button>

A correção resolve duas coisas de uma vez: o número passa a bater com a lista e o filtro roda uma vez só, em vez de uma para o cabeçalho e outra para o {#each}. Quando você se pegar escrevendo a mesma expressão em dois lugares da tela, esse é o sinal: transforme em derivado e leia o derivado nos dois.

7. untrack: ler sem virar dependência

Um derivado pode ler estado sem querer. Toda leitura de estado dentro do cálculo conta como dependência, mesmo quando o valor lido não deveria obrigar o recálculo. O untrack desliga esse registro para o pedaço de código que ele envolve.

<script>
  import { untrack } from 'svelte';

  let quantidade = $state(2);
  const precoUnitario = 4.5;

  let total = $derived(untrack(() => precoUnitario) * quantidade);
</script>

<p>total: R$ {total.toFixed(2)}</p>
<button onclick={() => (quantidade += 1)}>mais um</button>
<p>total: R$ 9.00</p> <button>mais um</button>

No exemplo, o preço unitário é constante, então o untrack não muda nada visível — ele só deixa claro que o total depende da quantidade e do preço, nessa ordem. O uso de verdade aparece quando o valor lido é $state e você não quer que ele dispare o cálculo: um contador de visitas lido para exibir, um filtro global lido uma vez na montagem.

untrack é exceção, não regra

Se o valor deve atualizar a tela quando muda, ele é dependência e precisa ser rastreado. Usar untrack para "resolver" um recálculo indesejado costuma esconder um problema de desenho: o dado está no lugar errado, ou o estado tem duas fontes. Prefira arrumar a estrutura a silenciar o rastreamento.

8. O que não fazer dentro de um derivado

Derivado é para calcular, não para agir. Escrever estado, chamar fetch, mexer no DOM ou disparar um evento dentro de um derivado transforma o cálculo numa ação — e ação repetida é o começo de um laço. O derivado pode rodar mais de uma vez, em momentos que você não controla; qualquer efeito colateral vai junto.

A regra prática: se o corpo do derivado precisa de await, de setTimeout ou de uma atribuição a $state, ele não é derivado. Use $effect para o que precisa acontecer, e deixe o derivado só com contas. Essa separação é o que torna o cache confiável: um cálculo puro pode ser repetido à vontade sem consequência.

O outro cuidado é a dependência ampla demais. Um derivado que lê a lista inteira é recalculado quando qualquer item muda, mesmo que o resultado mostrado seja o mesmo. Se a conta é pesada, considere derivar primeiro a parte estável — o total por item, por exemplo — e só então juntar. Duas contas pequenas com dependências diferentes trabalham menos que uma conta grande com todas.

9. Medir antes de acreditar

Contador de execuções é a forma mais barata de provar que o trabalho diminuiu. Ele não precisa ficar na versão final: entra durante a investigação e sai quando a dúvida acaba. O painel de desempenho do navegador mostra o tempo; o contador mostra a causa.

10. Quando dá errado

As três mensagens abaixo saíram do renderizador desta versão, copiadas como estão.

Erro 1 — $derived.by sem função

O .by existe justamente para receber uma função. Passar um número ou um valor direto faz o Svelte tentar chamar o que não é chamável.

<script>
  let itens = $state([1, 2, 3]);
  let total = $derived.by(42);
</script>

<p>{total}</p>
Erro ao renderizar: get_value is not a function

"get_value is not a function" é uma mensagem interna, e o nome não ajuda. A tradução: o valor passado para a runa não é uma função. O certo é $derived.by(() => { … }), com a função inteira dentro dos parênteses.

Erro 2 — chamar o derivado como função

Um derivado é um valor, não uma função. Quem escreve {total()} está pedindo para chamar um número.

<script>
  let itens = $state([1, 2, 3]);
  let total = $derived(itens.reduce((a, b) => a + b, 0));
</script>

<p>{total()}</p>
Erro ao renderizar: total(...) is not a function

A mensagem aponta a chamada: total(...) is not a function. No template, use {total} sem parênteses. Parênteses só aparecem quando o que está guardado é uma função de verdade.

Erro 3 — reduce no que não é lista

reduce, filter e map são funções de lista. Um objeto com campos não tem nenhuma delas, e a conta para na hora de desenhar.

<script>
  let itens = $state({ a: 1, b: 2 });
  let total = $derived(itens.reduce((a, b) => a + b, 0));
</script>

<p>{total}</p>
Erro ao renderizar: itens.reduce is not a function

"is not a function" de novo, agora apontando o valor errado. Para somar campos de um objeto, use Object.values(itens).reduce(…), que primeiro transforma os valores em lista.

Exercícios

1. O que o $derived faz de diferente de uma função chamada no template?

2. Quando usar $derived.by em vez de $derived?

3. Por que criar o formatador de dinheiro fora do {#each}?

Complete o código

let total = $derived(() => {
  const soma = itens.reduce((a, i) => a + i.preco, 0);
  return soma.toFixed(2);
});

Resumo

  • Trabalho necessário produz o resultado; trabalho repetido só gasta tempo.
  • $derived guarda o resultado e roda no máximo uma vez por mudança de dependência.
  • Função chamada em dois lugares do template roda duas vezes; derivado lido em dois lugares roda uma.
  • $derived.by serve para cálculos de várias linhas, com return obrigatório.
  • Formatadores, expressões regulares e tabelas fixas se criam uma vez, fora do laço.
  • Cabeçalho e lista devem sair do mesmo derivado, para os números nunca discordarem.
  • untrack lê sem criar dependência, e é exceção — não conserto para todo recálculo.
  • Derivado calcula; não escreve estado, não busca dados, não mexe no DOM.
  • Contador de execuções prova a economia; o painel de desempenho mostra o tempo.
