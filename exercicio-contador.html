Svelte · Exercício: o Contador

Na padaria da Ana existe um placar de giz para contar quantos pães saíram do forno. Cada fornada soma, cada venda tira, e no fim do dia ela zera para começar de novo. O placar é o exercício perfeito para juntar tudo o que você viu até aqui: estado, evento, condição, cálculo e lista. Nesta aula você monta o contador em cinco passos, cada um com uma missão para resolver na caixa.

Você vai aprender
  • Como montar um contador com somar, subtrair e zerar.
  • Como impedir que o número fique negativo.
  • Como usar uma variável de passo para somar de tantos em tantos.
  • Como mostrar um valor calculado a partir do contador.
  • Como guardar um histórico de cliques numa lista.
  • Como o {#each} exibe a lista na tela.
  • Como o compilador reclama de bloco aberto e de bloco fechado errado.
  • Como testar uma conta no terminal antes de escrever o componente.

1. A ideia: o placar de giz

Um placar de giz tem três operações: somar, subtrair e apagar tudo. Simples assim. A dificuldade não está nas operações, e sim nas regras em volta delas: o número não pode ficar negativo, o passo pode variar, o histórico precisa registrar a ordem, e o total do dia precisa bater com o que foi vendido.

Cada uma dessas regras é uma decisão de projeto, e cada decisão cabe numa função pequena. O contador é um bom exercício porque permite começar com duas linhas e ir acrescentando comportamento sem reescrever o que já funciona. É assim que software cresce na vida real: um passo de cada vez, com o anterior funcionando.

Nesta aula, os cinco passos são cumulativos. O passo 1 é o contador que soma. O passo 2 impede o negativo. O passo 3 permite somar de cinco em cinco. O passo 4 mostra um segundo número calculado. O passo 5 registra o histórico. No fim, você tem o componente completo e sabe explicar cada linha dele.

Contador é o primeiro programa de quase todo mundo que aprende interface, e não é por acaso. Ele tem uma entrada (o clique), um estado (o número) e uma saída (o texto na tela), que são as três peças de qualquer tela interativa. Quem entende o contador entende o esqueleto; o resto é acrescentar regras.

3. Passo 1: o estado e os botões

<script>
  let cliques = $state(0);

  function somar() {
    cliques = cliques + 1;
  }

  function zerar() {
    cliques = 0;
  }
</script>

<p>Cliques: {cliques}</p>
<button onclick={somar}>+1</button>
<button onclick={zerar}>zerar</button>

Dois botões, duas funções, um estado. O HTML gerado mostra o número inicial e os rótulos dos botões:

<p>Cliques: 0</p> <button>+1</button> <button>zerar</button>
let cliques = $state(0)
o placar. Começa em zero e avisa a tela a cada mudança.
function somar()
a regra de somar. Não recebe nada porque o passo é fixo neste momento.
cliques = cliques + 1
lê o valor atual, soma um e grava de volta. O cliques++ faz o mesmo em menos letras.
function zerar()
a regra de limpar. Uma atribuição direta, sem conta.
onclick={somar}
o nome da função, sem parênteses. O navegador chama no clique, como você viu na aula de handler.

Esse é o mínimo que funciona. Antes de acrescentar regra, clique nos dois botões e confira: somar aumenta, zerar volta ao zero. Se algo não funcionar aqui, não adianta seguir; os passos seguintes assumem que este está certo.

4. Passo 2: não descer de zero

O placar da Ana não pode ficar negativo: não existe fornada de menos um pão. A regra é uma condição dentro da função que subtrai.

<script>
  let cliques = $state(0);

  function menos() {
    if (cliques > 0) {
      cliques = cliques - 1;
    }
  }
</script>

<p>Cliques: {cliques}</p>
<button onclick={menos}>-1</button>
<p>Cliques: 0</p> <button>-1</button>

A condição if (cliques > 0) só deixa a subtração acontecer quando há o que subtrair. Se o contador está em zero, a função termina sem fazer nada e a tela não muda. Não é erro: é a regra funcionando.

Existe uma segunda forma de escrever a mesma regra, com Math.max. Ela é mais curta e não precisa de if:

ana@notebook:~/loja$ node -e "console.log(Math.max(0, 0 - 1), Math.max(0, 3 - 1))"
0 2

O Math.max devolve o maior entre os números recebidos. Passando zero e o resultado da subtração, o pior caso é zero. cliques = Math.max(0, cliques - 1) cabe em uma linha e faz a mesma coisa. As duas versões são boas; o if é mais fácil de ler para quem começa, e o Math.max é mais fácil de testar.

Missão: o botão -1 deixa o contador em -1. Corrija a função para que clicar com o contador em zero mantenha Cliques: 0.

<script>
  let cliques = $state(0);
</script>

<p>Cliques: {cliques}</p>
<button id="menos" onclick={() => cliques--}>-1</button>
<script>
  let cliques = $state(0);

  function menos() {
    if (cliques > 0) {
      cliques = cliques - 1;
    }
  }
</script>

<p>Cliques: {cliques}</p>
<button id="menos" onclick={menos}>-1</button>

Depois de resolver, teste também o caminho feliz: some dois e subtraia um. O resultado deve ser um. Uma regra que só é testada no caso limite não prova nada; o comportamento normal precisa continuar funcionando.

5. Passo 3: o passo configurável

Nem toda fornada tem o mesmo tamanho. Em vez de somar sempre um, o contador pode somar o valor guardado numa variável de passo. A função muda uma palavra; o botão mostra o valor para quem olha.

<script>
  let cliques = $state(0);
  let passo = $state(5);

  function somar() {
    cliques = cliques + passo;
  }
</script>

<p>Cliques: {cliques}</p>
<button onclick={somar}>+{passo}</button>
<p>Cliques: 0</p> <button>+5</button>

O rótulo do botão usa {passo}: o texto acompanha a variável. Se o passo mudar para 10, o botão passa a dizer +10 e a função soma 10. Uma decisão de interface embutida no código: mostrar o passo no rótulo evita que a pessoa clique sem saber quanto está somando.

O passo também pode vir de um campo, e aí você usa o que aprendeu na aula de bind:value:

<script>
  let cliques = $state(0);
  let passo = $state(5);
</script>

<p>Cliques: {cliques}</p>
<input type="number" min="1" max="100" bind:value={passo}>
<button onclick={() => (cliques = cliques + passo)}>+{passo}</button>
<p>Cliques: 0</p> <input type="number" min="1" max="100" value="5"/> <button>+5</button>

O min e o max limitam o campo na interface, mas não no estado: alguém pode digitar um número fora da faixa e o navegador só marca o campo como inválido. Se o passo precisa mesmo ficar entre 1 e 100, valide na função antes de somar. É a mesma lição da aula de formulários: atributo ajuda, regra garante.

Missão: o botão diz +5, mas soma um. Faça a função somar o valor de passo para que dois cliques mostrem Cliques: 10.

<script>
  let cliques = $state(0);
  let passo = $state(5);
</script>

<p>Cliques: {cliques}</p>
<button id="mais" onclick={() => (cliques = cliques + 1)}>+{passo}</button>
<script>
  let cliques = $state(0);
  let passo = $state(5);
</script>

<p>Cliques: {cliques}</p>
<button id="mais" onclick={() => (cliques = cliques + passo)}>+{passo}</button>

Esse erro — rótulo diferente da conta — é mais comum do que parece. A tela promete uma coisa e o código faz outra. O teste do exercício pega exatamente isso: se o botão diz cinco e o número sobe um, a promessa está quebrada.

Há uma lição de projeto aí: o rótulo deve ser calculado a partir do mesmo valor que a conta usa. Quando o botão mostra {passo} e a função soma passo, não existe como os dois discordarem. Quando você escreve "5" à mão no rótulo e "5" à mão na função, os dois podem divergir no dia em que alguém mudar um só.

6. Passo 4: um valor calculado

O placar também pode mostrar quantas metades de fornada aquilo representa, ou o dobro de cliques por algum motivo. O importante é que esse segundo número não seja um estado separado: ele vem do primeiro.

<script>
  let cliques = $state(3);
  let dobro = $derived(cliques * 2);
</script>

<p>Cliques: {cliques} · Dobro: {dobro}</p>
<button onclick={() => cliques++}>+1</button>
<p>Cliques: 3 · Dobro: 6</p> <button>+1</button>

O $derived recalcula o dobro sempre que cliques muda. Não existe o risco de o dobro ficar desatualizado, porque não existe uma cópia guardada. Se você tivesse escrito let dobro = $state(0), precisaria lembrar de atualizar o dobro em todas as funções que mexem em cliques — e um dia esqueceria.

Essa é a diferença entre um valor de entrada e um valor de saída. Entrada é o que a pessoa digita ou clica; saída é o que o programa calcula. Misturar os dois é a origem de muitos bugs de placar: o total mostra um número que não corresponde à soma dos itens porque alguém esqueceu de recalcular.

Para três ou mais valores derivados, a regra se mantém: um $derived para cada um. O compilador cuida de recalcular na ordem certa quando a fonte muda. Você só precisa garantir que a fonte seja reativa, ou seja, criada com $state.

Formatação também é papel da exibição, não do estado. Se o placar precisa mostrar 03 em vez de 3, você formata na chave: {String(cliques).padStart(2, '0')}. O estado continua sendo o número 3, porque é com ele que você faz contas. Guardar texto para "ficar bonito" obriga a converter de volta antes de somar, e aí aparecem os "3" + 1 = "31" da vida.

7. Passo 5: o histórico com {#each}

O placar de giz apaga, mas a Ana quer saber em que ordem os números apareceram. Uma lista guarda o histórico; o bloco {#each} mostra.

<script>
  let cliques = $state(0);
  let historico = $state([]);

  function somar() {
    cliques = cliques + 1;
    historico.push(cliques);
  }
</script>

<p>Cliques: {cliques}</p>
<p>Histórico: {historico.join(', ')}</p>
<button onclick={somar}>+1</button>
<p>Cliques: 0</p> <p>Histórico: </p> <button>+1</button>

O push acrescenta no fim da lista. Como a lista foi criada com $state, o Svelte percebe a mudança e atualiza o parágrafo. O join(', ') transforma a lista em texto separado por vírgula; sem ele, a lista apareceria colada, sem espaços.

A versão com {#each} é melhor quando você quer um item por linha, com marcador ou estilo próprio:

<script>
  let cliques = $state(0);
  let historico = $state([]);

  function somar() {
    cliques = cliques + 1;
    historico.push(cliques);
  }
</script>

<p>Cliques: {cliques}</p>
<ul>
  {#each historico as numero}
    <li>{numero}</li>
  {/each}
</ul>
<button onclick={somar}>+1</button>
<p>Cliques: 0</p> <ul></ul> <button>+1</button>

Com a lista vazia, o bloco não gera item nenhum e o <ul> sai com espaços entre as tags. No navegador, cada clique acrescenta um <li>. Para listas que mudam de ordem, vale dar uma chave a cada item com {#each historico as numero (numero)}; para um histórico que só cresce, o índice já basta.

A chave entre parênteses precisa ser única. No histórico do contador, os números não se repetem, então o próprio número serve. Se dois cliques pudessem gerar o mesmo valor — num contador que volta ao zero, por exemplo —, use o índice: {#each historico as numero, i (i)}. O Svelte recusa a lista com chave repetida e mostra o código each_key_duplicate. Vale saber o nome para reconhecer no console.

Missão: o contador sobe, mas o histórico fica vazio. Registre cada clique na lista para que dois cliques mostrem Histórico: 1, 2.

<script>

  let historico = $state([]);
</script>

<p>Cliques: {cliques}</p>
<p>Histórico: {historico.join(', ')}</p>
<button id="mais" onclick={() => (cliques = cliques + 1)}>+1</button>

Note a ordem dentro da função: primeiro soma, depois registra. Se você registrasse antes, o histórico guardaria o valor anterior — o primeiro clique gravaria zero. Ordem importa, e é uma das poucas coisas que o compilador não confere para você.

8. O contador completo

Juntando os cinco passos, o componente fica assim. Todas as peças já foram vistas; o que muda é a convivência entre elas.

<script>
  let cliques = $state(0);
  let historico = $state([]);

  function somar() {
    cliques = cliques + 1;
    historico.push(cliques);
  }

  function zerar() {
    cliques = 0;
    historico = [];
  }
</script>

<p>Cliques: {cliques}</p>
<p>Histórico: {historico.join(', ')}</p>
<button onclick={somar}>+1</button>
<button onclick={zerar}>zerar</button>
<p>Cliques: 0</p> <p>Histórico: </p> <button>+1</button> <button>zerar</button>

O zerar agora limpa duas coisas: o contador e o histórico. Se limpasse só o contador, o histórico continuaria mostrando os números antigos e o próximo clique geraria uma sequência estranha. Sempre que você zera um estado, pergunte quais outros estados dependem dele.

9. Quando dá errado

Erro 1 — parêntese que não fecha no handler

Dentro de uma seta, a expressão precisa terminar antes do fecha-chaves. Um parêntese aberto deixa o compilador esperando o resto do arquivo.

<script>
  let total = $state(0);
</script>

<button onclick={() => total++>Total: {total}</button>
Erro de compilação (linha 5, coluna 36): Expected token }

A linha apontada é o fim do arquivo, porque foi ali que o compilador desistiu de esperar. Sempre que a mensagem falar de }, procure um parêntese ou uma chave sem fechar por perto. Contar os pares resolve mais rápido do que reler o arquivo inteiro.

Erro 2 — bloco aberto e não fechado

Todo {#if} precisa do seu {/if}. Sem ele, o bloco fica aberto até o fim do arquivo.

<script>
  let contador = $state(0);
</script>

{#if contador > 0}
  <p>positivo</p>
Erro de compilação (linha 5, coluna 0): Block was left open

"Block was left open" quer dizer "o bloco ficou aberto". A posição é a linha do {#if}, e não a do fim do arquivo — uma diferença útil em relação ao erro anterior. Feche com {/if} e o componente compila.

Erro 3 — bloco fechado com o nome errado

Cada tipo de bloco tem o seu fechamento. Fechar um {#if} com {/each} faz o compilador procurar o {#each} que não existe.

<script>
  let cliques = $state(0);
</script>

{#if cliques > 0}
  <p>positivo</p>
{/each}
Erro de compilação (linha 7, coluna 2): Expected token if

"Expected token if" significa "eu esperava um if aqui". O compilador chegou ao fim do arquivo com um {#if} aberto e um {/each} fechando. A correção é trocar por {/if}. Repare que a mensagem cita o que falta, não o que sobra — e isso vale para qualquer bloco.

Exercícios

1. Qual é a forma mais direta de impedir que o contador fique negativo?

2. O que o {#each} faz no histórico?

3. O que Block was left open quer dizer?

Complete o código

function menos() {
   {
    cliques = cliques - 1;
  }
}

// o contador não desce de zero

Resumo

  • Contador é estado + funções + botões ligados por onclick.
  • cliques++ soma um; cliques = cliques - 1 subtrai.
  • A condição if (cliques > 0) impede o negativo; Math.max(0, …) faz o mesmo sem if.
  • O passo configurável deixa a função genérica e o rótulo honesto: +{passo}.
  • Valor calculado é $derived; nunca um $state mantido à mão.
  • Histórico é uma lista com push, exibida com join ou {#each}.
  • Zerar o contador exige zerar os estados que dependem dele.
  • Erros desta aula: parêntese aberto, bloco aberto e bloco fechado com o nome errado.
  • Testar é percorrer a tabela de regras: caso normal e caso limite.
