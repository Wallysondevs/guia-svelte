Svelte · Funções Handler

A Ana escreve as receitas da padaria num caderno, com nome e passo a passo: "pão de queijo — misturar, modelar, assar". Quando alguém pede, ela não recita a receita de memória no meio do balcão; ela abre o caderno e segue. Na aula passada, o que rodava no clique era uma conta solta dentro do atributo. Agora a Ana vai dar nome ao que acontece no clique, guardar num lugar só e chamar pelo nome quando precisar. Esse pedaço de código com nome é a função handler.

Você vai aprender

  • Como ligar essa função ao onclick sem chamá-la na hora errada.
  • Por que onclick={somar} e onclick={somar()} não são a mesma coisa.
  • Como passar um valor para o handler usando uma seta no meio.
  • Como o handler recebe o objeto do evento e lê evento.target.value.
  • Quando vale a pena uma função nomeada e quando a seta curta resolve.
  • O que o compilador gera para uma função que ninguém chama no arquivo.
  • Os três erros reais desta aula e o que cada mensagem quer dizer.
  • Como testar uma função no terminal, sem abrir o navegador.

1. A ideia: a receita no caderno

Existem duas maneiras de ensinar alguém a fazer pão de queijo. A primeira é ficar ao lado e ir falando cada passo na hora, do começo ao fim, toda vez que alguém pede. A segunda é escrever a receita uma vez, dar um nome a ela e dizer "quando alguém pedir, faça a receita de pão de queijo". A segunda maneira tem três vantagens óbvias: você pode repetir sem se cansar, pode corrigir em um lugar só e pode mandar outra pessoa executar.

Uma função é a receita escrita. Ela tem nome, tem passos e pode receber ingredientes — os parâmetros. Quando o navegador avisa que o botão foi clicado, ele chama a função pelo nome. A função faz o trabalho e devolve o controle. Quem escreveu o HTML não precisa saber o que tem dentro; só precisa saber o nome.

No Svelte, o handler é uma função JavaScript comum, declarada no bloco <script> do componente. Ela pode ler e escrever qualquer variável criada com $state naquele mesmo componente. Não existe API especial, não existe this mágico, não existe registro de eventos: é uma função de JavaScript, e o atributo onclick só guarda a referência para ela.

3. A primeira função com nome

O componente começa igual ao da aula passada: um estado, um parágrafo que mostra o valor e um botão. A novidade é que o botão não carrega a conta; ele carrega o nome de uma função declarada acima.

<script>
  let total = $state(0);

  function somar() {
    total = total + 1;
  }
</script>

<p>Total: {total}</p>
<button onclick={somar}>+1</button>

O HTML que sai do compilador é este. O botão chega ao navegador sem atributo nenhum, como sempre; a ligação com a função acontece depois, no navegador.

<p>Total: 0</p> <button>+1</button>
function
a palavra que declara uma função. Tudo o que está entre as chaves pertence a ela e só roda quando alguém chama.
somar
o nome. Escolha verbos no infinitivo: somar, zerar, enviar, conferir. Nome de função diz o que ela faz, não como.
()
a lista de parâmetros, vazia aqui. Os parênteses fazem parte do nome quando você chama: somar().
{ … }
o corpo: as instruções que rodam em ordem, de cima para baixo.
onclick={somar}
sem parênteses. Você está entregando a função, não o resultado dela. O navegador guarda essa referência e chama quando o clique acontecer.

Uma função declarada assim pode ser usada antes de ser declarada no arquivo, porque o JavaScript iça as declarações de função para o topo do bloco. Na prática, ninguém escreve o botão antes do script, mas o conhecimento evita sustos quando você mover código de lugar.

4. O que o compilador fez com a sua função

Se você pedir só o texto da tela, o compilador devolve o que o olho vê. Note que o +1 do botão também é texto visível: ele é o rótulo do botão.

Total: 0 +1

A função somar não aparece nesse texto porque função não é conteúdo de tela. Ela existe no JavaScript do componente e só produz efeito quando é chamada. Esse é um bom momento para lembrar a divisão de trabalho: o HTML descreve o que está na tela; o script descreve o que pode acontecer; o navegador junta os dois.

O comando de build mostra o peso desse componente no projeto da Ana. Ele é o mesmo de sempre, e o número de módulos continua 111 — o que muda é o tamanho do arquivo final, que cresce um pouco a cada função e a cada atributo.

Trinta e cinco kilobytes é menos do que uma foto tirada com o celular. O Svelte é um dos frameworks que menos entregam JavaScript para o navegador, e isso importa numa padaria com internet ruim: menos bytes, menos espera.

Enquanto o build roda, quem está desenvolvendo usa o servidor de desenvolvimento, que recompila cada arquivo salvo e recarrega a página. O endereço é sempre o mesmo, http://localhost:5173/, e o número de módulos aparece a cada mudança. Se você quiser ver esse servidor funcionando na máquina da Ana, a aula Seu Primeiro Componente mostra a sessão completa, linha por linha.

Um detalhe que economiza tempo: o build não verifica se o seu handler faz sentido. Ele só compila. Um botão ligado à função errada passa no build sem uma palavra e falha só quando alguém clica. Por isso testar no navegador, com o dedo no mouse, continua sendo parte do trabalho.

5. Por que separar o handler

Você poderia continuar escrevendo onclick={() => total++} para sempre. Para um botão, funciona. Quando a padaria cresce, a diferença aparece: a mesma regra passa a valer para três botões, e você precisa mudar a regra em um lugar só.

Uma função nomeada resolve isso porque o nome é uma referência. Três botões apontando para somar continuam apontando para a mesma receita; mudar o corpo da função muda os três de uma vez. Com a seta escrita em cada botão, você tem três cópias da regra e três lugares para corrigir.

Tem também o custo de leitura. Um atributo com cinco linhas de conta no meio do HTML esconde a estrutura da tela. O nome somar diz o que acontece sem obrigar quem lê a decifrar a conta. O HTML volta a ser uma lista de elementos, e o comportamento fica no script, onde é fácil de achar.

Missão: o botão não conta nada. Escreva uma função chamada contar que some 1 e ligue o botão nela, para que dois cliques mostrem Cliques: 2.

<script>
  let cliques = $state(0);
</script>

<button>Cliques: {cliques}</button>
<script>
  let cliques = $state(0);

  function contar() {
    cliques = cliques + 1;
  }
</script>

<button onclick={contar}>Cliques: {cliques}</button>

O botão da solução não tem parênteses depois de contar. Isso é intencional e vale conferir no seu código antes de clicar em Verificar: se você escrever onclick={contar()}, a função roda uma vez quando o componente aparece e o clique fica sem função nenhuma.

6. Função com parâmetro

Nem toda receita é igual para todo pedido. Uma função pode receber um valor entre os parênteses e usar esse valor no corpo. O nome dado ao valor é livre; o que importa é a posição.

<script>
  let total = $state(0);

  function somar(valor) {
    total = total + valor;
  }
</script>

<button onclick={() => somar(5)}>Total: {total}</button>
<button>Total: 0</button>

Aqui aparece uma seta de novo, mas com outro papel. () => somar(5) é uma função sem parâmetros que, quando chamada, chama somar(5). A seta existe porque o atributo precisa de uma função, e somar(5) sozinho é o resultado de uma chamada — um número. A seta embrulha a chamada para o momento certo.

Para ver a diferença entre a função e o resultado dela, dá para usar o terminal. O comando abaixo declara uma função e imprime duas coisas: o nome da função e o que ela devolve quando recebe 4.

ana@notebook:~/loja$ node -e "function somar(n) { return n + 1 } console.log(somar); console.log(somar(4))"
[Function: somar]
5

O [Function: somar] é a própria função impressa. O 5 é o valor que ela devolve. São coisas de tipos diferentes: uma pode ser guardada para depois, a outra é um número que já aconteceu. Todo o mistério dos parênteses está aí.

Missão: a função somar já recebe um valor, mas o botão passa 1. Faça cada clique valer 5, sem mexer na função, para que dois cliques mostrem Total: 10.

<script>
  let total = $state(0);

  function somar(n) {
    total = total + n;
  }
</script>

<button onclick={() => somar(1)}>Total: {total}</button>
<script>
  let total = $state(0);

  function somar(n) {
    total = total + n;
  }
</script>

<button onclick={() => somar(5)}>Total: {total}</button>

A função não mudou uma linha. Mudou só o argumento que o botão entrega. É essa separação que permite a mesma função servir para o botão de +5 e para o botão de +10, cada um passando o seu valor.

7. O handler recebe o evento

Quando o navegador chama a função, ele passa um argumento que você não pediu explicitamente: o objeto do evento. Se a sua função declarar um parâmetro, ele recebe esse objeto. É assim que se chega ao texto digitado, à tecla pressionada e ao formulário que está sendo enviado.

<script>
  let digitado = $state('');

  function guardar(evento) {
    digitado = evento.target.value;
  }
</script>

<input oninput={guardar}>
<p>Guardado: {digitado}</p>
<input/> <p>Guardado: </p>
function guardar(evento)
o parâmetro tem o nome que você quiser. evento é legível; e é curto; os dois funcionam.
oninput={guardar}
o atributo aponta para a função, sem chamá-la. O navegador chama com o evento como primeiro argumento.
evento.target
o elemento que disparou o evento. Num input, é o campo.
evento.target.value
o texto atual do campo. Muda a cada tecla e chega como string.

Existe uma diferença de comportamento entre oninput e onchange que confunde. oninput dispara a cada alteração, até quando a pessoa apaga uma letra. onchange dispara quando o campo perde o foco, e só se o valor mudou desde a última vez. Para mostrar algo em tempo real, use oninput; para conferir um valor quando a pessoa termina de digitar, onchange evita trabalho repetido.

Também é possível parar o comportamento padrão do navegador dentro do handler. Um link que não deve navegar, um formulário que não deve recarregar a página: em todos os casos a função recebe o evento e chama evento.preventDefault(). A aula de formulários mostra isso em detalhe, porque é lá que o problema aparece de verdade.

8. Passar a função × chamar a função

Esta é a seção que salva o seu fim de semana. Os dois atributos abaixo parecem iguais e fazem coisas diferentes:

Você escreveO que o navegador recebeO que acontece no clique
onclick={somar}a funçãochama a função uma vez
onclick={() => somar(5)}uma função nova que chama a outrachama somar(5) uma vez
onclick={somar()}o resultado da chamada, já calculadotenta usar um número como função e quebra

Para ver o terceiro caso quebrando de verdade, o componente abaixo chama a função dentro do atributo. O HTML que o servidor manda é inofensivo:

<script>
  let total = $state(0);

  function somar() {
    return total + 5;
  }
</script>

<button onclick={somar()}>Total: {total}</button>
<button>Total: 0</button>

No navegador, clicar nesse botão soma 5 ao total e, no mesmo instante, escreve uma mensagem de erro no console. A mensagem é esta, copiada do navegador:

$.get(...)?.apply is not a function

Traduzindo: o Svelte guardou o resultado de somar(), que é o número 5, e tentou chamar esse número como se fosse uma função. O trecho apply é o jeito interno de chamar funções; o que importa para você é o fim da frase: não é uma função. A correção é tirar os parênteses do atributo.

Missão: o botão chama a função dentro do atributo: cada clique soma e estoura um erro no console. Faça o clique somar 5 sem erro nenhum, mostrando Total: 5.

<script>
  let total = $state(0);

  function somar() {
    return total + 5;
  }
</script>

<button onclick={somar()}>Total: {total}</button>
<script>
  let total = $state(0);

  function somar() {
    total = total + 5;
  }
</script>

<button onclick={somar}>Total: {total}</button>

A solução resolve dois problemas de uma vez. Ela tira os parênteses do atributo, entregando a função em vez do resultado. E ela faz a função mudar o estado em vez de devolver uma conta nova, que é o que handlers fazem: efeito, não cálculo. Função que devolve valor serve para calcular; função que muda estado serve para reagir a evento.

9. Quando dá errado

Erro 1 — tentar mudar uma constante

Um handler que escreve numa variável declarada com const não compila. O valor não pode ser trocado depois da criação, e o compilador sabe disso.

<script>
  const total = $state(0);

  function somar() {
    total = total + 1;
  }
</script>

<button onclick={somar}>Total: {total}</button>
Erro de compilação (linha 5, coluna 4): Cannot assign to constant

"Cannot assign to constant" quer dizer "não posso atribuir a uma constante". Troque const por let. A runa $state funciona nas duas, mas só a variável let aceita um valor novo depois.

Erro 2 — duas funções com o mesmo nome

Nome de função é único no bloco. Duas declarações iguais fazem o compilador parar na segunda.

<script>
  let total = $state(0);

  function somar() {
    total = total + 1;
  }

  function somar() {
    total = total + 2;
  }
</script>

<button onclick={somar}>Total: {total}</button>
Erro de compilação (linha 8, coluna 11): Identifier 'somar' has already been declared

A linha apontada é a segunda declaração, não a primeira. A mensagem repete o nome que está sobrando. Corrija renomeando uma das duas ou apagando a que não é usada — o computador não tem como adivinhar qual você quis manter.

Erro 3 — parêntese que não fecha

Dentro de uma seta, cada parêntese que abre precisa fechar. O compilador espera o fecha-chaves da expressão até o fim do arquivo e reclama no ponto onde desistiu.

<script>
  let total = $state(0);
</script>

<button onclick={() => total++>Total: {total}</button>
Erro de compilação (linha 5, coluna 36): Expected token }

"Expected token }" significa "eu esperava uma chave de fechamento aqui". A posição aponta para o fim da linha, onde o compilador percebeu a falta. A dica prática: feche o par antes de escrever o conteúdo, e conte os pares quando a mensagem aparecer.

3. Por que uma função nomeada é melhor do que repetir a conta em cada botão?

Resumo

  • Handler é uma função que responde a um evento; ela vive no <script> do componente.
  • function somar() { … } declara; onclick={somar} entrega; o navegador chama.
  • onclick={somar()} chama na hora errada e entrega um valor no lugar de uma função.
  • Para passar um argumento, embrulhe a chamada: onclick={() => somar(5)}.
  • O primeiro parâmetro do handler é o objeto do evento; evento.target.value lê o campo.
  • oninput dispara a cada tecla; onchange só quando o campo perde o foco.
  • evento.preventDefault() cancela o comportamento padrão do navegador.
  • Função nomeada deixa a regra em um lugar só e o HTML mais fácil de ler.
  • Erros desta aula: mudar constante, repetir nome de função e esquecer um parêntese.
  • No terminal, console.log(somar) mostra a função; console.log(somar(4)) mostra o resultado.
