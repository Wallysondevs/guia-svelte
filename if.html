Svelte · Condicionais: {#if}

A Ana tem uma padaria e uma placa virada para a rua. De manhã ela escreve "PÃO QUENTINHO" e pendura; quando o forno esfria, ela desliga a placa. O problema é que a placa da parede não sabe quando o forno está quente — quem sabe é a Ana, e ela vive esquecendo de trocar. Nesta aula você vai ensinar o componente a decidir sozinho: mostrar um pedaço da tela só quando uma condição for verdadeira, e não mostrar nada quando não for. O nome disso é condicional, e em Svelte ela se escreve {#if}.

Você vai aprender
  • O que é uma condição e por que a tela precisa de uma.
  • A escrever {#if …}{/if} e ver o HTML real dos dois casos.
  • O que o Svelte considera verdadeiro e falso — a lista completa.
  • Que bloco escondido não deixa lixo na tela, mas deixa um espaço.
  • Como esconder vários elementos de uma vez, sem inventar uma tag nova.
  • Como uma condição pode nascer de uma conta com comparações.
  • Como aninhar um {#if} dentro de outro sem se perder.
  • Como o clique no botão muda o valor e a tela acompanha.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • O que o terminal do projeto da Ana imprime ao compilar tudo isso.

1. A ideia: uma decisão escrita no meio do HTML

Um componente que mostra sempre a mesma coisa é fácil. O difícil é o componente que mostra às vezes. "Se tem pão, mostre o aviso de pão quentinho; se não tem, não mostre nada." Você já escreve frases assim o dia inteiro, e a estrutura é sempre a mesma: uma condição ("se tem pão"), uma consequência ("mostre o aviso") e, às vezes, um caminho alternativo ("senão, mostre o aviso de forno vazio").

O Svelte aceita essa estrutura no meio do HTML, com uma marca própria. A marca começa com {#if e termina com {/if}, e tudo o que estiver entre as duas só vai para a tela quando a condição for verdadeira. Não existe função para chamar nem elemento para esconder: você escreve a decisão onde ela acontece, no lugar exato do HTML em que o pedaço deve aparecer.

O ganho aparece no dia a dia. Sem condicional, você resolve o aviso de duas formas ruins: escreve o aviso sempre (e ele mente quando o forno está frio) ou esconde com CSS (e o texto continua na página, invisível, ocupando lugar e aparecendo para quem lê a página com um leitor de tela). Com {#if}, o pedaço simplesmente não existe no HTML enquanto a condição for falsa. É a diferença entre uma placa virada para a parede e uma placa que não foi pendurada.

Na padariaNo componente
"Se tem pão, pendure o aviso"{#if temPao}
O aviso penduradoo HTML entre {#if} e {/if}

Repare no vocabulário: a condição é a pergunta ("tem pão?"), o bloco é o pedaço de HTML que depende dela, e estado é a variável onde a resposta mora. A condição não é avaliada uma vez só: sempre que o estado muda, o Svelte pergunta de novo e ajusta a tela. É isso que faz o aviso aparecer no instante em que a Ana tira o último pão da prateleira.

2. O primeiro {#if} da Ana

Comece pelo caso mais simples possível: uma variável de estado que guarda "tem pão ou não", e um parágrafo que só aparece quando ela é verdadeira.

<script>
  let temPao = $state(true);
</script>

<p>Tem pão quentinho saindo do forno.</p>

{#if temPao}
  <p>Pão francês na prateleira.</p>
{/if}

Se você pedir ao compilador o HTML que esse arquivo produz, ele devolve duas linhas: o parágrafo de fora, que está sempre lá, e o parágrafo de dentro do bloco, porque a condição é verdadeira.

<p>Tem pão quentinho saindo do forno.</p> <p>Pão francês na prateleira.</p>

O texto que aparece na tela é este:

Tem pão quentinho saindo do forno. Pão francês na prateleira.

Agora troque true por false e peça o HTML de novo. O parágrafo de dentro do bloco desaparece — não fica escondido, não fica com display: none: ele não está mais no HTML.

<script>
  let temPao = $state(false);
</script>

<p>Tem pão quentinho saindo do forno.</p>

{#if temPao}
  <p>Pão francês na prateleira.</p>
{/if}

<p>Fim.</p>
<p>Tem pão quentinho saindo do forno.</p>  <p>Fim.</p>
Tem pão quentinho saindo do forno. Fim.

Duas coisas para notar nessa segunda saída. A primeira: o texto de dentro do bloco sumiu por completo, e o "Fim." que vinha depois continuou no lugar. A segunda: sobraram dois espaços entre um parágrafo e outro, no lugar onde o bloco estava. É o espaço em branco do arquivo, que continua contando. Isso não atrapalha nada na tela, mas explica por que o HTML gerado às vezes tem espaços a mais — e por que comparar HTML "no olho" engana.

A anatomia do bloco

{#if temPao}
a abertura: a cerquilha (#) avisa que começa um bloco, e o que vem depois é a condição.
temPao
a condição em si: o nome de uma variável, uma comparação, uma conta — qualquer expressão que resulte em verdadeiro ou falso.

Pão francês…

o corpo do bloco: o HTML que só aparece quando a condição é verdadeira. Pode ter uma linha ou cinquenta.
{/if}
o fechamento: a barra (/) avisa que o bloco acabou. Sem ele, o compilador reclama.

O par {#if} / {/if} é como uma moldura: o HTML de dentro pertence ao bloco, e o de fora não. Se você esquecer o fechamento, metade da página vira parte do bloco — e aí o erro aparece longe de onde você errou, o que é a pior parte de trabalhar com blocos.

Bloco não é tag

{#if} não cria nenhum elemento no HTML final. Não existe <if> na página, e o CSS não tem como selecionar "o bloco". O que você estiliza são as tags de dentro dele, como o <p> do exemplo.

3. Experimente: acenda e apague o aviso

A caixa abaixo compila o componente de verdade e mostra o resultado. O valor começa em false, então o aviso não aparece. Sua missão é fazer o aviso aparecer.

Missão: o balcão está fechado (o aviso não aparece). Troque o valor inicial para o aviso aparecer e clique em Verificar.

<script>
  let aberto = $state(false);
</script>

<button onclick={() => (aberto = !aberto)}>Abrir a padaria</button>

{#if aberto}
  <p>Bom dia! O balcão está aberto.</p>
{/if}
<script>
  let aberto = $state(true);
</script>

<button onclick={() => (aberto = !aberto)}>Abrir a padaria</button>

{#if aberto}
  <p>Bom dia! O balcão está aberto.</p>
{/if}

Antes da mudança, o texto da tela é só o do botão: Abrir a padaria. Depois, o parágrafo entra no fim. Repare que o botão continua ali o tempo todo — ele está fora do bloco, então nada nele depende da condição.

Enquanto você edita, cada Rodar compila o arquivo com o compilador de verdade do Svelte. Se você escrever algo que o compilador recusa, a caixa mostra a mensagem dele, não um aviso inventado pelo guia.

4. O que conta como verdadeiro

Em português, "verdadeiro" é uma palavra só. Em JavaScript, qualquer valor pode ocupar o lugar da condição, e o Svelte aproveita a regra da linguagem: alguns valores contam como falsos e todo o resto conta como verdadeiro. A lista dos falsos é curta e vale memorizar: false, 0, '' (texto vazio), null, undefined e NaN (o resultado de uma conta impossível).

Isso cria armadilhas gostosas de descobrir. Um texto com um zero dentro ('0') é verdadeiro, porque é um texto com conteúdo. Uma lista vazia ([]) também é verdadeira, porque é um objeto — o JavaScript não olha para dentro dela para decidir. Veja os quatro casos no mesmo componente:

<script>
  let texto = $state('');
  let zero = $state(0);
  let lista = $state([]);
  let textoZero = $state('0');
</script>

{#if texto}<p>texto conta</p>{/if}
{#if zero}<p>zero conta</p>{/if}
{#if lista}<p>lista conta</p>{/if}
{#if textoZero}<p>texto zero conta</p>{/if}
<p>lista conta</p> <p>texto zero conta</p>
lista conta texto zero conta

Dos quatro blocos, só dois apareceram. O texto vazio e o zero ficaram de fora, como esperado. A lista vazia entrou, e o texto '0' entrou. Se a Ana quisesse "lista vazia não conta", a condição teria de ser explícita: {#if lista.length > 0}. Essa é a regra prática: quando o valor não é um booleano de verdade, escreva a comparação você mesma, para quem lê o código não precisar decorar a tabela.

5. Experimente: um clique, dois estados

Condição parada não muda nada na vida real. O que a Ana precisa é de um botão que feche o balcão e outro estado que reflita isso na hora. Na caixa abaixo, o botão sempre fecha — clique duas vezes e veja o problema.

Missão: o botão só fecha. Faça ele alternar: um clique fecha, o outro abre. Use !aberto em vez de false.

<script>
  let aberto = $state(true);
</script>

<button onclick={() => (aberto = false)}>Fechar ou abrir</button>

{#if aberto}
  <p>O balcão está aberto.</p>
{/if}

{#if !aberto}
  <p>O balcão está fechado.</p>
{/if}
<script>
  let aberto = $state(true);
</script>

<button onclick={() => (aberto = !aberto)}>Fechar ou abrir</button>

{#if aberto}
  <p>O balcão está aberto.</p>
{/if}

{#if !aberto}
  <p>O balcão está fechado.</p>
{/if}

O ponto importante não é o botão: é que os dois parágrafos nascem da mesma variável, um com a condição direta e outro com a condição negada. O ! na frente é o "não" do JavaScript: inverte o valor. Enquanto aberto for verdadeiro, o primeiro bloco aparece e o segundo não; quando o valor vira falso, acontece o contrário, no mesmo desenho da tela.

Na próxima aula do guia você vai ver que existe um jeito mais curto de escrever esse par, com {:else}. Aqui a versão de dois blocos separados serve para você enxergar que cada bloco é independente: o Svelte avalia um, avalia o outro, e nenhum sabe da existência do vizinho.

6. Condições que nascem de contas

Até agora a condição foi uma variável solta. Na prática ela quase sempre é uma comparação. As ferramentas são seis, e todas devolvem verdadeiro ou falso:

EscritaPergunta que fazExemplo verdadeiro
a === bé igual (mesmo valor e mesmo tipo)?2 === 2
a !== bé diferente?'pão' !== 'bolo'
a > b, a < bé maior / menor?5 > 3
a >= b, a <= bé maior ou igual / menor ou igual?4 <= 4
a && bos dois são verdadeiros?2 > 1 && 3 > 2
a || bpelo menos um é verdadeiro?0 > 1 || 3 > 2

Com elas dá para escrever a regra da padaria com precisão: avisar quando a quantidade vendida alcança a quantidade assada, e avisar também quando há pão na prateleira e a venda já começou.

<script>
  let paes = $state(4);
  let vendidos = $state(6);
</script>

{#if vendidos >= paes}
  <p>O forno precisa de mais pão.</p>
{/if}

{#if vendidos > 0 && paes > 0}
  <p>A prateleira tem pão e a venda já começou.</p>
{/if}
<p>O forno precisa de mais pão.</p> <p>A prateleira tem pão e a venda já começou.</p>
O forno precisa de mais pão. A prateleira tem pão e a venda já começou.

Quatro pães assados, seis vendidos: a primeira conta dá verdadeiro e o primeiro aviso aparece. E como ainda há pão na prateleira e a venda já começou, o segundo também aparece. As duas perguntas são independentes — nenhuma sabe da existência da outra, e as duas podem ser verdadeiras ao mesmo tempo. Se a Ana assar mais dez pães, paes vira 14, a primeira condição fica falsa e o primeiro aviso sai da tela sozinho, sem ninguém tocar no HTML.

= não é ===

Um sinal de igual guarda um valor; três sinais comparam. Escrever {#if paes = 0} não compila, e a mensagem do compilador fala de atribuição em posição inesperada. Dentro de {#if}, você quer sempre ===, !==, > ou <.

7. Esconder vários elementos de uma vez

Uma condição pode proteger mais de uma tag. Não é preciso embrulhar tudo numa <div> só para o bloco ter um dono: o corpo do {#if} aceita quantos elementos você quiser, um embaixo do outro.

<script>
  let chovendo = $state(true);
</script>

{#if chovendo}
  <h2>Entrega com guarda-chuva</h2>
  <p>O pão vai protegido.</p>
{/if}
<h2>Entrega com guarda-chuva</h2> <p>O pão vai protegido.</p>

Isso importa mais do que parece. Em muitos frameworks você é obrigado a criar um elemento extra para agrupar, e esse elemento extra aparece no HTML atrapalhando o CSS. Aqui não: se a condição for falsa, as duas tags somem juntas; se for verdadeira, as duas entram juntas. O bloco é invisível — só as tags de dentro têm existência na página.

O mesmo vale para tags soltas e para componentes inteiros. Um bloco pode proteger um <li> dentro de uma lista, uma linha de tabela, um formulário de dez campos ou um componente que você escreveu. A regra é uma só: o que está entre {#if} e {/if} pertence à condição.

Aninhar sem se perder

Um {#if} pode morar dentro de outro. Na padaria, "está aberta?" e "tem pão?" são perguntas diferentes, e o aviso de pão só faz sentido se a padaria estiver aberta.

<script>
  let aberto = $state(true);
  let temPao = $state(false);
</script>

{#if aberto}
  <p>A padaria está aberta.</p>
  {#if temPao}
    <p>Tem pão.</p>
  {:else}
    <p>O pão acabou.</p>
  {/if}
{/if}
<p>A padaria está aberta.</p> <p>O pão acabou.</p>

O segundo bloco usou {:else}, que é o assunto da próxima aula — aqui ele só está de visita, para o exemplo ficar completo. O que interessa é a indentação: cada nível de bloco ganha dois espaços a mais. O compilador não liga para isso, mas quem lê o arquivo liga, e você vai voltar a esse arquivo muitas vezes.

Quantos níveis cabem?

Não existe limite técnico, mas três níveis já são difíceis de ler. Quando a condição fica comprida, o caminho é calcular antes: let podeAvisar = $derived(aberto && temPao) e usar {#if podeAvisar}. O bloco fica curto e a regra ganha nome.

8. Experimente: o forno vazio

Falta uma decisão na caixa abaixo: quando os pães acabam, nada aparece. Sua missão é acrescentar o aviso de forno vazio, com a condição certa.

Missão: clique três vezes para vender os três pães. Falta um aviso quando o estoque chega a zero: acrescente um bloco que mostre Forno vazio.

<script>
  let paes = $state(3);
</script>

<button onclick={() => paes--}>vender um pão</button>

{#if paes > 0}
  <p>Ainda temos {paes} pães.</p>
{/if}
<script>
  let paes = $state(3);
</script>

<button onclick={() => paes--}>vender um pão</button>

{#if paes > 0}
  <p>Ainda temos {paes} pães.</p>
{/if}

{#if paes === 0}
  <p>Forno vazio.</p>
{/if}

Repare que a solução acrescenta um bloco em vez de mexer no primeiro. A primeira condição já fazia o trabalho dela: some quando não há pão. A segunda responde outra pergunta: "o estoque zerou?". Duas perguntas, dois blocos, cada um com uma responsabilidade. Quando você tiver {:else} na mão, vai poder juntar os dois em um só — e vai saber escolher entre as duas formas.

Teste também o que acontece se você clicar uma quarta vez: paes vira -1, o aviso de forno vazio desaparece, e a tela fica só com o botão. Nada quebra, mas a padaria vendeu um pão que não tinha. Esse tipo de decisão ("o que fazer no limite?") é conversa de regra de negócio, não de Svelte — mas é bom ver a tela reagindo antes de o problema virar prejuízo.

10. Quando dá errado

As três mensagens abaixo saíram do compilador desta versão (5.59.2), copiadas como estão. Todas acontecem com quem está começando, e todas apontam linha e coluna do problema.

Erro 1 — o nome do bloco escrito errado

O bloco é {#if}, sem acento e sem abreviação. Quem escreve {#se}, pensando em português, recebe uma lista do que o compilador aceita naquele lugar.

<script>
  let temPao = $state(true);
</script>

{#se temPao}
  <p>tem pão</p>
{/se}
Erro de compilação (linha 5, coluna 2): Expected 'if', 'each', 'await', 'key' or 'snippet'

A mensagem não diz "você errou a palavra": ela lista as cinco aberturas de bloco que existem em Svelte 5 — if, each, await, key e snippet. As três primeiras você vai ver neste nível do guia.

Erro 2 — fechou com o nome de outro bloco

Cada abertura tem um fechamento com o mesmo nome. Um {#if} fechado com {/each} é recusado na hora.

<script>
  let lista = $state([1, 2]);
</script>

{#if lista.length > 0}
  <p>tem item</p>
{/each}
Erro de compilação (linha 7, coluna 2): Expected token if

Traduzindo: "eu esperava a palavra if depois da barra". O compilador sabe qual bloco está aberto, então a mensagem é bem específica. Se você tivesse escrito {/each} no lugar de {/if} em um arquivo grande, o erro apareceria na linha do fechamento errado — não na linha da abertura.

Erro 3 — bloco aberto e nunca fechado

O caso mais comum de todos: o {/if} ficou para depois e nunca chegou.

<script>
  let nome = $state('Ana');
</script>

{#if nome === 'Ana'}
  <p>oi</p>
Erro de compilação (linha 5, coluna 0): Block was left open

A linha apontada é a da abertura, não a do fim do arquivo: 5, coluna 0. É uma boa notícia — o compilador mostra onde o bloco começou, e você procura o fechamento a partir dali. Quando o arquivo tem vários blocos, conte os pares: cada {#if} precisa de um {/if}.

Exercícios

1. O que acontece com o HTML que está dentro de um {#if} quando a condição é falsa?

2. Qual destes valores faz o bloco aparecer?

3. Para que serve o {/if}?

Complete o código

{#if }
  <p>Pão na prateleira.</p>
{/if}

// o bloco só aparece quando a variável temPao for verdadeira

Resumo

  • {#if condição} abre um bloco e {/if} fecha; só o que está entre os dois depende da condição.
  • Condição falsa remove o HTML da página — não é CSS escondendo.
  • Contam como falsos: false, 0, '', null, undefined e NaN.
  • Lista vazia ([]) e o texto '0' contam como verdadeiros: escreva a comparação quando importa.
  • O corpo do bloco aceita várias tags, sem precisar de uma <div> em volta.
  • Blocos podem ficar dentro de blocos; cada nível ganha dois espaços de indentação.
  • === compara; = guarda. Dentro de {#if} use sempre a comparação.
  • Trocar o estado muda a tela na hora: é o mesmo $state da primeira aula.
  • Os erros desta aula: nome do bloco errado, fechamento com outro nome e bloco sem fechar.
  • Terminal: npm run dev serve em localhost:5173; npm run build gera dist/ com 111 módulos.
