Svelte · Limpando o que Criou

A Ana fecha a padaria às sete da noite e apaga a luz da vitrine. Se ela esquecer, a lâmpada fica queimando a noite inteira e a conta de energia chega maior no fim do mês. Um componente tem o mesmo dever: tudo o que ele liga — um relógio, um ouvinte de evento, uma assinatura — precisa ser desligado quando ele sai da tela. Nesta aula você aprende onde escrever esse desligamento e o que acontece quando ele falta.

Você vai aprender
  • Por que um componente precisa desfazer o que fez, e quando isso acontece.
  • O que a função devolvida pelo onMount faz.
  • Como limpar setInterval, setTimeout e ouvinte de evento.
  • Quando usar onDestroy em vez de devolver a função.
  • Que a limpeza roda também quando o $effect se repete, não só ao sair da tela.
  • Como provar um vazamento de temporizador contando os que estão vivos.
  • O que o compilador faz quando você tenta guardar o retorno do $effect.
  • Os três erros reais desta aula, com a mensagem copiada do compilador.
  • Por que removeEventListener precisa da mesma função do addEventListener.

1. A ideia: apagar a luz ao fechar

Na padaria, cada abertura tem um fechamento. A Ana liga o forno e o desliga, abre a porta e a fecha, começa a bater o ponto do pão e para. Nada disso é burocracia: é o que mantém a loja funcionando amanhã. Quem esquece de desligar não tem um problema hoje, e sim uma conta no fim do mês.

Em programação acontece o mesmo. Quando o componente aparece na tela, ele pode ligar coisas que vivem fora dele: um relógio que dispara a cada segundo, um ouvinte do evento de redimensionar a janela, uma ligação aberta com o servidor. Essas coisas não desaparecem quando o componente desaparece. Elas continuam funcionando, gastando memória e escrevendo em variáveis que ninguém está mais vendo. Esse é o vazamento, ou leak.

O Svelte oferece dois lugares para desligar. O primeiro é a função devolvida: se o código que você entrega ao onMount devolver uma função, o Svelte a chama quando o componente sai da tela. O segundo é o onDestroy, que registra a limpeza separadamente. Os dois funcionam; a diferença é de estilo e de escopo, e você vai ver as duas formas nesta aula.

Na padariaNo componente
Ligar a luz da vitrine ao abrironMount(() => { … })
Apagar a luz ao fechara função devolvida no fim do onMount
Parar o relógio da paredeclearInterval(id)
Cancelar a encomenda que ainda não saiuclearTimeout(id)
Tirar o cartaz de promoção do muralremoveEventListener('resize', fn)
Fechar a loja e ir dormiro componente sair da tela

Uma palavra nova aparece no meio do caminho: desmontar (em inglês, unmount) é o contrário de montar. É o momento em que o Svelte tira o componente do DOM — porque o usuário trocou de página, porque uma condição {#if} deixou de valer, ou porque o aplicativo inteiro foi fechado. Desmontar é o "fechar a padaria" do componente.

2. O primeiro cronômetro e a função devolvida

O componente abaixo mostra há quantos segundos a padaria está aberta. Ele liga um setInterval na montagem e devolve, no fim, uma função que desliga o mesmo intervalo.

<script>
  import { onMount } from 'svelte';

  let segundos = $state(0);

  onMount(() => {
    const id = setInterval(() => {
      segundos++;
    }, 1000);

    return () => {
      clearInterval(id);
    };
  });
</script>

<p>Na padaria há {segundos} segundos.</p>
<p>Na padaria há 0 segundos.</p>

O HTML gerado fora do navegador mostra o valor inicial, como sempre: o onMount não roda ali. No navegador, o número começa a subir de segundo em segundo, e para no instante em que o componente sai da tela — porque a função devolvida chama clearInterval.

A anatomia da limpeza

const id = setInterval(…)
o identificador do relógio. setInterval devolve um número ou objeto que representa aquele relógio; sem guardar esse valor, você não tem como desligá-lo depois.
segundos++
o que o relógio faz a cada segundo. Como segundos é $state, a tela acompanha.
return () => { … }
a função de limpeza. O return dentro do onMount não devolve um valor de negócio: ele registra o que fazer na saída. O Svelte guarda essa função e chama na hora certa.
clearInterval(id)
desliga o relógio daquele id e apenas daquele. Um clearInterval sem argumento não faz nada; um com o id errado desliga o relógio de outro componente.

Repare no detalhe que mais confunde: o onMount devolve uma função, não o resultado dela. Quem chama é o Svelte, no momento da desmontagem. Se você escrever return clearInterval(id) em vez de return () => clearInterval(id), o intervalo é desligado imediatamente, na montagem, e o cronômetro nunca começa a contar. É um erro silencioso: nenhuma mensagem, só um número parado em zero.

Uma variável por recurso

Se o componente liga um relógio e um ouvinte, guarde um identificador para cada e limpe os dois na mesma função devolvida. A limpeza é uma só, com várias linhas dentro — como fechar a loja: apagar a luz, trancar a porta, desligar o forno.

3. Ouvinte de evento: tirar o que pendurou

O segundo caso clássico é o ouvinte de evento. O componente da Ana mede a largura da janela e se atualiza quando o usuário redimensiona o navegador. Para isso, ele pendura uma função no evento resize da window.

<script>
  import { onMount } from 'svelte';

  let largura = $state(0);

  onMount(() => {
    function medir() {
      largura = window.innerWidth;
    }

    medir();
    window.addEventListener('resize', medir);

    return () => {
      window.removeEventListener('resize', medir);
    };
  });
</script>

<p>A janela tem {largura} pixels.</p>
<p>A janela tem 0 pixels.</p>

A função medir é declarada dentro do onMount de propósito. O removeEventListener só remove o ouvinte se receber exatamente a mesma função que foi adicionada — mesma referência, não apenas o mesmo código. Uma função criada de novo, mesmo com o corpo idêntico, é outra função para o navegador, e o ouvinte antigo continua lá.

A anatomia do ouvinte

function medir() { … }
a função que reage ao evento. Precisa ter nome (ou estar guardada numa variável) para que a remoção use a mesma referência.
medir();
uma chamada imediata, para a tela não começar em zero. O resize só dispara quando a janela muda; sem essa chamada, o primeiro valor ficaria errado.
window.addEventListener('resize', medir)
pendura a função no evento. A partir daqui, cada redimensionamento chama medir.
window.removeEventListener('resize', medir)
despendura. Sem esta linha, cada montagem do componente deixaria um ouvinte a mais na janela.

Existe um atalho do Svelte para esse caso: <svelte:window onresize={medir} /> registra o ouvinte e o remove sozinho quando o componente sai. Ele é ótimo para eventos da janela e do corpo da página, e não serve para tudo — um IntersectionObserver ou uma conexão de dados continuam exigindo limpeza escrita à mão. Por isso vale aprender a forma manual primeiro: ela é a que funciona em qualquer recurso.

4. Quando usar onDestroy

Devolver a função é o caminho mais curto quando a limpeza está colada na criação. Existe um segundo caminho, o onDestroy, que registra a limpeza como um bloco separado:

<script>
  import { onDestroy } from 'svelte';

  let segundos = $state(0);

  const id = setInterval(() => {
    segundos++;
  }, 1000);

  onDestroy(() => {
    clearInterval(id);
  });
</script>

<p>Aberta há {segundos} segundos.</p>
<p>Aberta há 0 segundos.</p>

As duas formas desligam o relógio. A diferença é onde o código mora. Na versão com onMount, quem lê o arquivo de cima para baixo vê a criação e a destruição no mesmo bloco, uma embaixo da outra. Na versão com onDestroy, a criação fica no meio do script e a destruição no fim. Para um recurso só, tanto faz; para cinco, a primeira forma costuma ser mais fácil de conferir.

O onDestroy ganha quando a limpeza precisa acontecer mesmo que a criação tenha falhado no meio, ou quando o recurso é criado fora do onMount — por exemplo, um $effect que abre uma conexão a cada mudança de filtro. Nesse caso, a limpeza natural é a do próprio $effect, como você vê na seção 7.

FormaOnde a limpeza ficaQuando é chamada
return () => { … } no onMountno fim do próprio onMountao desmontar o componente
onDestroy(() => { … })em qualquer lugar do scriptao desmontar o componente
return () => { … } no $effectno fim do próprio efeitoantes de cada nova execução do efeito e ao desmontar

Uma descoberta real, que surpreende: o onDestroy também roda no servidor. Ao renderizar o componente fora do navegador, o Svelte cria e destrói a instância na mesma passada, e a limpeza é chamada. Se você puser um console.log dentro dela, ele aparece no terminal antes do HTML. Isso é útil para depurar e é uma armadilha para quem coloca ali algo que só faz sentido no navegador.

5. Experimente: dois temporizadores onde devia haver um

A caixa abaixo liga um temporizador sempre que o ritmo muda. Sem a limpeza, o primeiro continua rodando e a tela passa a contar o dobro. O componente conta os temporizadores vivos para você ver o vazamento acontecendo.

Missão: clique em trocar ritmo duas vezes: o contador de temporizadores sobe para 3. Deixe exatamente um vivo, limpando o anterior.

<script>
  let ritmo = $state(100);
  let vivos = 0;
  let naTela = $state(0);
  let tiques = $state(0);

  $effect(() => {
    const ms = ritmo;
    const id = setInterval(() => { tiques++; }, ms);
    vivos++;
    naTela = vivos;
  });
</script>

<button onclick={() => (ritmo = ritmo === 100 ? 200 : 100)}>trocar ritmo</button>
<p>temporizadores: {naTela}</p>
<p>tiques: {tiques}</p>
<script>
  let ritmo = $state(100);
  let vivos = 0;
  let naTela = $state(0);
  let tiques = $state(0);

  $effect(() => {
    const ms = ritmo;
    const id = setInterval(() => { tiques++; }, ms);
    vivos++;
    naTela = vivos;

    return () => {
      clearInterval(id);
      vivos--;
      naTela = vivos;
    };
  });
</script>

<button onclick={() => (ritmo = ritmo === 100 ? 200 : 100)}>trocar ritmo</button>
<p>temporizadores: {naTela}</p>
<p>tiques: {tiques}</p>

Duas coisas para observar. A primeira: a limpeza roda antes de o efeito rodar de novo, e não só na saída da tela. É por isso que o número de temporizadores vivos se mantém em um. A segunda: a contagem usa uma variável comum (vivos) espelhada numa variável de tela (naTela). O motivo é técnico e vale saber: escrever num $state que o próprio efeito lê cria uma dependência circular, e o Svelte aborta com erro de profundidade. O espelho evita isso.

6. Experimente: cancelar a encomenda que ainda não saiu

Nem todo recurso é um relógio que repete. Um setTimeout dispara uma vez, depois de um tempo, e também precisa ser cancelado — senão a mensagem atrasada chega depois que o cliente já desistiu.

Missão: peça, cancele e espere. A mensagem atrasada chega e sobrescreve o "cancelado". Guarde o identificador do setTimeout e cancele de verdade.

<script>
  let aviso = $state('nada');

  function pedir() {
    setTimeout(() => { aviso = 'pão no forno'; }, 250);
    aviso = 'pedido enviado';
  }

  function cancelar() {
    aviso = 'cancelado';
  }
</script>

<button onclick={pedir}>pedir</button>
<button id="cancelar" onclick={cancelar}>cancelar</button>
<p>{aviso}</p>
<script>
  let aviso = $state('nada');
  let id;

  function pedir() {
    id = setTimeout(() => { aviso = 'pão no forno'; }, 250);
    aviso = 'pedido enviado';
  }

  function cancelar() {
    clearTimeout(id);
    aviso = 'cancelado';
  }
</script>

<button onclick={pedir}>pedir</button>
<button id="cancelar" onclick={cancelar}>cancelar</button>
<p>{aviso}</p>

O id fica fora das funções, no escopo do componente, porque as duas precisam do mesmo valor: uma guarda, a outra usa. Se você declarar let id dentro de pedir, o cancelar não vê nada e o cancelamento vira uma linha morta.

O mesmo raciocínio vale para o ouvinte do resize: o identificador é o par função + evento, e o removeEventListener precisa dos dois. Guardar a função numa variável do componente, e não dentro de uma função que cria outra a cada chamada, é o que garante a referência certa.

7. A limpeza do $effect e o vazamento de ouvintes

O $effect também aceita uma função de limpeza, e ela roda em dois momentos: antes de cada nova execução do efeito e na desmontagem. Isso resolve um problema que o onMount não resolve — quando o efeito se repete muitas vezes e cada repetição pendura um ouvinte novo.

Imagine um componente que escuta um evento e, a cada mudança de configuração, registra o ouvinte outra vez. Sem limpeza, depois de três mudanças existem quatro ouvintes. Um único evento disparado faz o contador subir quatro. É o vazamento clássico, e ele não aparece em um teste rápido: aparece quando o usuário fica na tela e mexe nos filtros.

Missão: clique três vezes no botão. Cada clique deveria somar 1, mas o contador chega a 9: os ouvintes antigos continuam pendurados. Remova o ouvinte antes de registrar o próximo.

<script>
  let contador = $state(0);
  let versao = $state(0);

  $effect(() => {
    versao;
    const aoSinal = () => { contador++; };
    window.addEventListener('sinal', aoSinal);
  });
</script>

<button onclick={() => { versao++; window.dispatchEvent(new Event('sinal')); }}>sinal</button>
<p>contador: {contador}</p>
<script>
  let contador = $state(0);
  let versao = $state(0);

  $effect(() => {
    versao;
    const aoSinal = () => { contador++; };
    window.addEventListener('sinal', aoSinal);
    return () => window.removeEventListener('sinal', aoSinal);
  });
</script>

<button onclick={() => { versao++; window.dispatchEvent(new Event('sinal')); }}>sinal</button>
<p>contador: {contador}</p>

A linha versao; sozinha parece inútil e é o coração do exemplo: ler a variável ali dentro é o que cria a dependência, então o efeito roda de novo a cada clique. Sem essa leitura, o efeito rodaria uma vez e nenhum vazamento apareceria.

8. O que não precisa de limpeza

Depois de aprender a limpar, é comum exagerar e tentar desligar tudo. Vale saber o que o próprio Svelte já resolve, para não escrever código à toa.

O primeiro item é o onclick escrito no HTML. Quando você escreve <button onclick={pedir}>, o Svelte registra esse ouvinte e o remove sozinho na desmontagem. Você nunca precisa de removeEventListener para ele. O mesmo vale para oninput, onsubmit e todos os atributos de evento em elementos do componente: eles pertencem ao componente e morrem com ele.

O segundo item são as variáveis. Um $state ou um $derived não é um recurso externo: quando o componente sai da tela, o Svelte larga as referências e o coletor de lixo do navegador faz o resto. Ninguém precisa "zerar" o estado na saída.

O terceiro item é o <svelte:window>, que registra ouvintes da janela e os remove na desmontagem, como o <svelte:body> faz com os do corpo da página. É a forma curta do exemplo da seção 3.

O que éPrecisa limpar?Quem limpa
onclick e outros eventos no HTMLnãoo Svelte, na desmontagem
$state e $derivednãoo coletor de lixo do navegador
<svelte:window onresize={…} />nãoo Svelte
setInterval, setTimeoutsimvocê, na limpeza
addEventListener em window ou documentsimvocê, na limpeza
observador, conexão, assinaturasimvocê, na limpeza

O critério é sempre o mesmo: se o recurso vive fora do componente e guarda uma referência a uma função de dentro dele, você precisa desligá-lo. Se ele nasce e morre junto com o HTML do componente, o Svelte cuida.

9. Quando dá errado

As três mensagens abaixo foram copiadas da execução real dos componentes quebrados. O compilador desta versão escreve exatamente assim.

Erro 1 — tentar guardar o retorno do $effect

Quem vem do onMount tenta o mesmo truque no $effect: guardar o retorno para chamar depois. Não existe esse retorno.

<script>
  let segundos = $state(0);

  const parar = $effect(() => {
    const id = setInterval(() => segundos++, 1000);
  });
</script>

<p>{segundos}</p>
Erro de compilação (linha 4, coluna 16): `$effect()` can only be used as an expression statement

"Can only be used as an expression statement" quer dizer que o $effect precisa ser uma linha sozinha, sem const nem atribuição na frente. Para parar um efeito, você não chama função nenhuma: a limpeza é a função devolvida, chamada pelo próprio Svelte.

Erro 2 — ouvinte pendurado no topo do script

O código roda no navegador, e o servidor quebra na primeira linha: não existe window fora do navegador.

<script>
  let largura = $state(0);

  window.addEventListener('resize', () => {
    largura = window.innerWidth;
  });
</script>

<p>{largura}</p>
Erro ao renderizar: window is not defined

Além de quebrar no servidor, esse ouvinte nunca seria removido: ele é criado a cada montagem e não tem limpeza associada. A correção é mudar para dentro do onMount e devolver a remoção, como no componente da seção 3.

Erro 3 — onDestroy sem import

O nome parece parte da linguagem, mas é uma função importada. Sem a linha de importação, o componente compila e falha ao executar.

<script>
  onDestroy(() => {
    console.log('saiu da tela');
  });
</script>

<p>oi</p>
Erro ao renderizar: onDestroy is not defined

A pista está no nome da função dentro da mensagem: quando o erro cita algo que começa com on e maiúscula, quase sempre falta import { … } from 'svelte'.

Exercícios

1. O que a função devolvida dentro do onMount faz?

2. Por que removeEventListener precisa receber a mesma função do addEventListener?

3. Quando a função de limpeza de um $effect é chamada?

Complete o código

onMount(() => {
  const id = setInterval(() => segundos++, 1000);
   
});

Resumo

  • Todo recurso ligado precisa ser desligado: temporizador, ouvinte, observador, conexão.
  • Desmontar é o momento em que o componente sai da tela.
  • return () => { … } no onMount registra a limpeza chamada na desmontagem.
  • onDestroy(() => { … }) faz o mesmo, com a limpeza em outro lugar do script.
  • A limpeza do $effect roda antes de cada nova execução e na desmontagem.
  • Guardar o id do setInterval ou do setTimeout é o que permite cancelar.
  • removeEventListener exige a mesma referência de função usada no addEventListener.
  • Escrever num $state que o efeito também lê pode gerar erro de profundidade de atualização.
  • Os erros desta aula: $effect guardado numa constante, window no topo e onDestroy sem import.
  • O onDestroy também roda no servidor, durante a renderização.
