Svelte · localStorage

A Ana fecha a padaria às sete, e o caderno de pedidos fica no balcão. No dia seguinte, ela abre o caderno e continua de onde parou. Um componente, sozinho, não tem esse caderno: quando a página recarrega, todo o estado volta ao começo. O navegador oferece um caderno chamado localStorage, que sobrevive ao fechamento da aba. Nesta aula você aprende a guardar pedidos nele, a lidar com a primeira visita e a não perder dados quando o armazenamento falha.

Você vai aprender
  • O que o localStorage guarda e por quanto tempo.
  • Por que ele só aceita texto e como o JSON resolve isso.
  • Como ler na montagem e salvar quando o estado muda.
  • O que o getItem devolve na primeira visita e como tratar o null.
  • Como escolher nomes de chave que não se atropelam.
  • Por que o armazenamento pode falhar e como proteger o componente.
  • O risco de salvar antes de carregar.
  • Os três erros reais desta aula, com a mensagem copiada do compilador.

1. A ideia: o caderno que não some

Estado de componente vive na memória do navegador, e memória de navegador é como lousa: some quando a aba fecha. Para guardar algo entre uma visita e outra existe um armazenamento simples, preso ao endereço do site, com dois métodos: getItem para ler e setItem para escrever. Há também removeItem para apagar uma chave e clear para apagar tudo — este último, use com muito cuidado.

O localStorage tem três características que definem o uso. A primeira: ele guarda texto, e só texto. Número vira texto, objeto vira [object Object] — e aí está a razão de o JSON aparecer nesta aula. A segunda: os dados ficam no seu navegador, não no servidor. Limpar os dados do site apaga tudo, e outro computador não vê nada. A terceira: ele é síncrono, ou seja, a leitura acontece na hora, no meio do seu código — e por isso não existe no servidor.

Para a Ana, isso é perfeito para as preferências e para a lista de pedidos do dia: dados pequenos, que ela quer ver de novo ao reabrir a página, e que não precisam ir para lugar nenhum. Não serve para dado sensível (senha, cartão), porque qualquer script da mesma origem lê o conteúdo.

2. Só texto: o JSON resolve

Se você guardar um número, ele vira texto e a leitura devolve texto. Se guardar um objeto, o navegador chama String nele e grava a palavra [object Object] — inútil. A solução é converter para JSON, um formato de texto que representa listas e objetos.

<script>
  let itens = $state(['pão', 'leite']);

  function guardar() {
    localStorage.setItem('pedidos', JSON.stringify(itens));
  }
</script>

<button onclick={guardar}>guardar</button>
<button>guardar</button>

A saída mostra só o botão, e está certa: guardar não muda o que aparece na tela. O que muda é o valor que o navegador passa a ter para a chave pedidos, e que a próxima visita vai ler.

A conversão de ida é JSON.stringify: pega a lista ['pão', 'leite'] e devolve o texto ["pão","leite"]. A conversão de volta é JSON.parse: pega o texto e devolve a lista. As duas precisam combinar — quem guarda com stringify lê com parse. Misturar os dois é a origem do erro mais comum da aula, que aparece na seção 10.

A anatomia do armazenamento

localStorage
o objeto global do navegador. Não vem de import e não existe fora do navegador: no servidor, tocar nele é erro.
setItem('pedidos', texto)
grava o texto na chave. Se a chave já existir, o valor antigo é substituído sem aviso. A chave é uma string e é única no site inteiro.
getItem('pedidos')
devolve o texto guardado, ou null quando não existe nada naquela chave. null não é lista vazia: é ausência.
JSON.stringify(itens)
converte a lista em texto. É a etapa que permite guardar estrutura, e não só palavras.

Repare que o getItem devolve null e não undefined nem ''. Essa diferença parece detalhe de linguagem e não é: JSON.parse(null) devolve null, e tentar ler .length de null quebra o componente. Você vai ver esse erro na seção 10 e vai corrigi-lo na seção 3, com o operador ??.

3. Ler na montagem, com valor padrão

A leitura acontece no onMount, porque o localStorage não existe no servidor. Junto dela vai o valor padrão, que protege a primeira visita.

<script>
  import { onMount } from 'svelte';

  let itens = $state([]);

  onMount(() => {
    const bruto = localStorage.getItem('pedidos');
    itens = JSON.parse(bruto ?? '[]');
  });
</script>

<p>{itens.length} pedido(s) guardado(s)</p>
0 pedido(s) guardado(s)

O ?? é o operador de coalescência nula: ele usa o valor da direita quando o da esquerda é null ou undefined. Sem ele, a primeira visita quebraria o componente, porque não há nada guardado. Com ele, a lista começa vazia e a tela mostra zero — verdadeiro e sem susto.

Existe uma escolha de projeto escondida nessa linha: o valor inicial do estado ([]) e o valor padrão do JSON ('[]') são o mesmo tipo. Isso mantém o resto do componente simples, porque ele nunca lida com "lista ou null". O guia recomenda essa simetria sempre que possível: normalize o dado logo na entrada e trabalhe com um tipo só.

Erro comum de sintaxe

JSON.parse(bruto ?? '[]') parece estranho por causa dos parênteses. A regra de precedência resolve: ?? tem precedência menor que a chamada de função, então o valor padrão é aplicado antes do parse. Sem os parênteses de fora, o compilador ainda aceita, mas misturar ?? com || na mesma expressão é erro de sintaxe — outro motivo para preferir parênteses explícitos.

4. Salvar quando o estado muda

Guardar é um efeito: escreve fora do componente. Por isso o $effect é o lugar natural. O componente abaixo lê na montagem e grava a cada mudança da lista.

<script>
  import { onMount } from 'svelte';

  let itens = $state([]);

  onMount(() => {
    const bruto = localStorage.getItem('pedidos');
    itens = JSON.parse(bruto ?? '[]');
  });

  $effect(() => {
    localStorage.setItem('pedidos', JSON.stringify(itens));
  });
</script>

{#each itens as item}
  <p>{item}</p>
{:else}
  <p>nenhum pedido salvo</p>
{/each}
nenhum pedido salvo

No servidor, nada é lido nem gravado, e o {:else} do {#each} mostra o aviso. No navegador, o onMount carrega o que houver e o efeito passa a gravar a cada mudança.

Há um detalhe de ordem aqui, e ele já causou perda de dados em muita gente. O efeito roda na montagem também, antes de qualquer mudança. Se a leitura falhar — JSON corrompido, por exemplo — o efeito ainda grava a lista vazia por cima do dado antigo. A versão abaixo se protege com uma bandeira de "carregado":

<script>
  import { onMount } from 'svelte';

  let itens = $state([]);
  let carregado = $state(false);

  onMount(() => {
    const bruto = localStorage.getItem('pedidos');
    itens = JSON.parse(bruto ?? '[]');
    carregado = true;
  });

  $effect(() => {
    if (!carregado) return;
    localStorage.setItem('pedidos', JSON.stringify(itens));
  });
</script>

{#each itens as item}
  <p>{item}</p>
{:else}
  <p>nenhum pedido salvo</p>
{/each}
nenhum pedido salvo

A bandeira custa uma variável e três linhas, e compra uma garantia: o armazenamento só é escrito depois que a leitura terminou. Num caderno de verdade, é a diferença entre "só apago a página depois de copiar o conteúdo" e "apago primeiro, copio depois".

5. Experimente: a primeira visita

Na caixa abaixo, o armazenamento é um objeto de memória com a mesma API do localStorage — a caixa roda num quadro isolado que começa vazio a cada Rodar, então o comportamento é o da primeira visita. O componente tenta ler uma lista que ainda não existe.

Missão: o componente quebra com Cannot read properties of null porque não há nada guardado. Faça ele mostrar 0 pedido(s) na primeira visita.

<script>
  const memoria = {};
  const armazem = {
    getItem: (k) => (k in memoria ? memoria[k] : null),
    setItem: (k, v) => (memoria[k] = String(v))
  };

  const pedidos = JSON.parse(armazem.getItem('pedidos'));
</script>

<p>{pedidos.length} pedido(s)</p>
<script>
  const memoria = {};
  const armazem = {
    getItem: (k) => (k in memoria ? memoria[k] : null),
    setItem: (k, v) => (memoria[k] = String(v))
  };

  const pedidos = JSON.parse(armazem.getItem('pedidos') ?? '[]');
</script>

<p>{pedidos.length} pedido(s)</p>

A correção é o ?? '[]'. Sem ele, JSON.parse(null) devolve null e o .length estoura. Com ele, a lista vazia entra no lugar do nada — e o componente passa a ter sempre uma lista.

6. Experimente: gravar sem perder a tela

Agora o outro lado: o estado muda, mas ninguém escreve no armazenamento. A tela mostra dois itens e o armazém continua com um.

Missão: clique em adicionar. A tela mostra 2 itens, mas só 1 foi gravado. Faça o armazém acompanhar o estado.

<script>
  let memoria = $state({});
  const armazem = {
    getItem: (k) => memoria[k] ?? null,
    setItem: (k, v) => { memoria[k] = String(v); }
  };

  let itens = $state(['pão']);

  function adicionar() {
    itens = [...itens, 'leite'];
  }
</script>

<button onclick={adicionar}>adicionar</button>
<p>na tela: {itens.length}</p>
<p>gravados: {(JSON.parse(armazem.getItem('pedidos') ?? '[]')).length}</p>

Note que o memoria da caixa é $state, e não um objeto comum. É um recurso do exemplo: a tela precisa acompanhar a escrita no armazém para você ver o número mudar. O localStorage de verdade não é reativo — a tela só acompanha porque o estado do componente mudou, e o efeito apenas escreveu.

7. Nomes de chave e versões

O localStorage é um espaço único por endereço, compartilhado por todas as páginas do site. Duas telas que usem a chave itens vão brigar pelo mesmo dado. Por isso, nome de chave é decisão de arquitetura, não detalhe.

ChaveProblemaAlternativa
itensqualquer tela pode sobrescreverpadaria:pedidos
dadosnão diz o que é nem de quem épadaria:preferencias
pedidos-v2versão no nome funciona, mas espalha númerospadaria:pedidos com um campo versao no JSON
temacolide com outro site no mesmo domíniopadaria:tema

Um detalhe prático que economiza muita depuração: antes de sair gravando, decida se o dado é do site inteiro ou de uma tela. Preferências como tema e idioma são do site; a lista de pedidos do dia é da tela. Quando a chave pertence a uma tela, o prefixo deve dizer isso — padaria:pedidos não, mas padaria:caixa:pedidos sim. Assim, quando a tela for reescrita, você sabe exatamente qual chave pode apagar sem medo.

Versão no nome da chave resolve o caso em que o formato muda: se a lista deixar de ser ['pão'] e passar a ser [{ nome: 'pão', qtd: 1 }], dados antigos vão quebrar a leitura. Duas saídas: trocar a chave (perde os dados velhos) ou guardar um campo de versão dentro do JSON e migrar na leitura. Para um projeto de estudo, trocar a chave basta; num sistema em produção, migrar é o certo.

8. Quando o armazenamento falha

O localStorage não é garantido. Pode falhar por três motivos comuns: o navegador está em modo privado com armazenamento bloqueado, a cota do site encheu (cerca de 5 MB, varia por navegador), ou uma política de privacidade bloqueia o acesso. Nos três casos, o acesso lança uma exceção — e um componente sem try quebra inteiro.

A proteção é simples e vale para escrita e leitura:

<script>
  import { onMount } from 'svelte';

  let itens = $state([]);
  let aviso = $state('');

  onMount(() => {
    try {
      const bruto = localStorage.getItem('pedidos');
      itens = JSON.parse(bruto ?? '[]');
    } catch (erro) {
      aviso = 'não consegui ler o caderno';
    }
  });
</script>

<p>{itens.length} pedido(s)</p>
{#if aviso}<p>{aviso}</p>{/if}
<p>0 pedido(s)</p>

O aviso fica vazio no servidor, então o bloco {#if} não desenha nada. No navegador, se a leitura falhar, o componente continua funcionando com a lista vazia e mostra a mensagem — em vez de desaparecer.

Missão: este armazém está cheio e lança erro ao gravar. Proteja a gravação para que a tela continue funcionando e o item novo apareça.

<script>
  const armazemQuebrado = {
    getItem: () => null,
    setItem: () => { throw new Error('cota cheia'); }
  };

  let itens = $state(['bolo']);

  function salvar() {
    armazemQuebrado.setItem('pedidos', JSON.stringify(itens));
    itens = [...itens, 'café'];
  }
</script>

<button onclick={salvar}>salvar</button>
<p>itens: {itens.join(', ')}</p>
<script>
  const armazemQuebrado = {
    getItem: () => null,
    setItem: () => { throw new Error('cota cheia'); }
  };

  let itens = $state(['bolo']);

  function salvar() {
    try {
      armazemQuebrado.setItem('pedidos', JSON.stringify(itens));

    }
    itens = [...itens, 'café'];

</script>

<button onclick={salvar}>salvar</button>
<p>itens: {itens.join(', ')}</p>

A lição vale além do armazenamento: toda chamada que pode falhar por motivo fora do seu controle pede try. Rede, arquivo, permissão do navegador — o padrão é o mesmo: tente, trate, siga com a tela viva.

Há um limite que surpreende: o conteúdo do localStorage não tem prazo de validade. Dado gravado em 2019 continua lá em 2026, a menos que alguém apague. Se o seu formato mudar nesse meio-tempo, a leitura vai encontrar dados antigos e pode quebrar. Guardar a data da gravação dentro do JSON e descartar o que for muito velho é uma defesa barata e eficaz.

Se você abrir duas abas do mesmo endereço, cada uma tem seu próprio estado na memória e as duas escrevem no mesmo armazenamento — a última que gravar vence. O evento storage da janela avisa quando outra aba muda o valor, e sincronizar as abas é um exercício para depois desta aula.

10. Quando dá errado

As três mensagens abaixo saíram da execução real dos componentes quebrados.

Erro 1 — localStorage no topo do script

O armazenamento é do navegador. Fora dele, o nome não existe.

<script>
  const bruto = localStorage.getItem('pedidos');
</script>

<p>{bruto ?? 'vazio'}</p>
Erro ao renderizar: localStorage is not defined

A correção é mover a leitura para o onMount, com valor inicial no estado, como nos componentes desta aula.

Erro 2 — o null da primeira visita

getItem devolve null quando a chave não existe, e JSON.parse(null) devolve null. Ler .length de null quebra o componente.

<script>
  const bruto = null;
  const pedidos = JSON.parse(bruto);
</script>

<p>{pedidos.length}</p>
Erro ao renderizar: Cannot read properties of null (reading 'length')

A mensagem aponta a propriedade e o tipo: reading 'length' de null. A correção é o valor padrão, JSON.parse(bruto ?? '[]').

Erro 3 — JSON escrito à mão, sem aspas nas chaves

JSON não é JavaScript: as chaves precisam de aspas duplas e as strings também. Um objeto "quase certo" não passa.

<script>
  const pedidos = JSON.parse('{itens: 3}');
</script>

<p>{pedidos.itens}</p>
Erro ao renderizar: Expected property name or '}' in JSON at position 1 (line 1 column 2)

A posição 1 é logo depois da chave de abertura: o parser esperava o nome de uma propriedade, entre aspas. O texto certo seria '{"itens": 3}'. Sempre que você puder, gere o JSON com JSON.stringify em vez de escrever à mão.
