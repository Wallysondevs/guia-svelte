Svelte · let e o Modo Antigo

A Ana encontrou um caderno de receitas escrito pela avó: mesmas ideias, outra caligrafia. Com código acontece igual. Antes das runas, o Svelte já fazia tela reativa — com let, $:, export let e on:click. Esta aula mostra o mundo antigo com as regras dele, para você reconhecer o que encontra por aí e saber traduzir para o modo novo.

Você vai aprender
  • O que é o modo antigo e por que ele ainda existe.
  • Como um componente let x = 0 já era reativo.
  • O que $: fazia e o que usar no lugar.
  • Como eram as props com export let.
  • Como eram os eventos com on:click.
  • O que era <slot /> e o que usar hoje.
  • Como forçar o modo antigo com <svelte:options runes={false} />.
  • Por que misturar os dois modos dá erro.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como o projeto da Ana compila um componente no modo antigo.

1. A ideia: dois mundos no mesmo compilador

O Svelte 5 nasceu com runas, mas não jogou fora o que existia. Um componente escrito sem nenhuma runa continua sendo compilado do jeito antigo, e tudo o que ele fazia em 2023 continua funcionando. Isso permitiu que projetos grandes migrassem aos poucos, arquivo por arquivo.

O modo antigo tem uma regra central diferente: atribuição é o sinal de mudança. Quando você escreve paes = 3 dentro de um componente antigo, o compilador entende que aquele valor mudou e marca a tela para atualizar. Não é preciso embrulhar nada em $state — o próprio ato de atribuir avisa.

O modo novo trocou essa regra por outra: só o que nasceu com $state avisa. É mais explícito, e por isso mais previsível em código grande. Saber os dois é útil por dois motivos: você entende projetos antigos e entende as mensagens de erro que aparecem quando os dois mundos se cruzam.

Modo antigoModo runas
let paes = 0let paes = $state(0)
$: total = qtd * 0.9let total = $derived(qtd * 0.9)
export let nomelet { nome } = $props()
on:click={…}onclick={…}
<slot />{@render children()}

O guia inteiro ensina o modo novo, e é o que você deve usar em código novo. Esta aula é uma ponte — não um convite para voltar.

2. O componente antigo da Ana

Este é o mesmo contador de pães, escrito do jeito antigo. Repare que não há runa nenhuma:

<script>
  let paes = 0;
</script>

<p>Pães: {paes}</p>
<button on:click={() => paes++}>mais um</button>
<p>Pães: 0</p> <button>mais um</button>

No navegador, esse componente funciona: o clique soma um e a tela mostra o número novo. O compilador antigo transforma a atribuição paes++ numa chamada que invalida o valor. Você não vê, mas cada = no script vira um aviso para a tela.

A anatomia do modo antigo

let paes = 0
uma variável comum que o compilador observa. Toda atribuição a ela invalida o valor.
paes++
a atribuição que avisa. Sem atribuição, nada acontece — mutações em objetos e listas precisam de reatribuição.
on:click
o evento com dois-pontos. O nome do evento vem depois de on:, sem on na frente.
sem runas
a ausência de runa é o que coloca o arquivo neste modo. Uma única runa muda tudo.

Repare numa limitação que o modo novo resolveu: no modo antigo, itens.push('pão') não atualizava a tela, porque não havia atribuição. Era preciso escrever itens = [...itens, 'pão']. No modo runas, com $state, o push funciona — você viu isso na aula de objetos e listas.

3. $: — a reatividade com rótulo

No modo antigo, cálculo derivado se escrevia com um rótulo de dólar e dois-pontos. O compilador observava as variáveis lidas à direita e reexecutava a linha quando alguma mudava:

<script>
  let qtd = 1;
  let unitario = 0.9;
  $: total = qtd * unitario;
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 0.90</p>

A linha $: total = qtd * unitario lê qtd e unitario; quando qualquer um dos dois muda, ela roda de novo e total recebe o resultado. É a mesma ideia do $derived, com outra roupa e algumas pegadinhas: o rótulo também servia para blocos de efeito ($: { … }), e a ordem das linhas importava mais.

Missão: este componente está no modo antigo e o total nunca é calculado. Faça a conta reagir à quantidade, do jeito antigo, para mostrar 0.90 e depois 1.80.

<script>
  let qtd = 1;
  let total = 0;
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<button onclick={() => qtd++}>mais um</button>
<script>
  let qtd = 1;
  $: total = qtd * 0.9;
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<button onclick={() => qtd++}>mais um</button>

Repare que a solução usa onclick (o modo novo de evento) dentro de um componente antigo. Isso é permitido: atributo de evento não é runa, então não muda o modo do arquivo. O que não pode é usar uma runa — aí o componente inteiro passa para o modo novo e o $: vira erro.

4. export let — as props antigas

No modo antigo, declarar prop era exportar uma variável. O pai passava o valor como atributo, e o filho recebia na variável exportada:

<script>
  export let nome = 'pão francês';
  export let preco = 0.9;
</script>

<p>{nome}: R$ {preco.toFixed(2)}</p>
<p>pão francês: R$ 0.90</p>

Aqui o pai não passou nada, então os valores padrão aparecem. Quando passa, o valor do pai entra no lugar do padrão. A sintaxe é mais curta que a do $props(), e é por isso que ela aparece tanto em código de tutorial antigo.

O custo aparece quando o componente tem muitos valores. Cada prop vira uma linha de export let, e não existe um lugar único onde ver a lista do que o componente aceita. O $props() junta tudo numa desmontagem só, e ainda permite separar o que sobra com ...resto.

5. on:click e <slot />

Duas marcas do mundo antigo ainda aparecem muito em exemplos na internet: o evento com dois-pontos e o slot para conteúdo do pai.

O evento antigo escreve o nome depois de on::

<script>
  let paes = 0;
</script>

<p>Pães: {paes}</p>
<button on:click={() => paes++}>mais um</button>
<p>Pães: 0</p> <button>mais um</button>

No modo novo, o mesmo botão se escreve com onclick — o nome do evento colado ao on, em minúsculas, como um atributo comum do HTML. Misturar os dois no mesmo elemento é erro de compilação, com uma mensagem específica sobre misturar sintaxes.

O slot fazia o papel de "buraco para o conteúdo do pai". O componente filho escrevia <slot /> e o pai preenchia com o que colocasse entre as tags. No modo novo, esse buraco é uma prop especial chamada children, renderizada com {@render children()}.

No modo antigoNo modo runasObservação
on:click={…}onclick={…}não misture os dois no mesmo elemento
<slot />{@render children()}children vem do $props()
<slot name="rodape">snippet passado como propaula de snippets
createEventDispatcherfunção passada como prop (callback)aula de eventos de componente

6. Forçar o modo antigo: runes={false}

Existe uma opção de componente que diz ao compilador para tratar o arquivo como antigo, mesmo que ele tenha cara de novo. É útil durante uma migração, para deixar um arquivo no mundo antigo enquanto o resto do projeto avança:

<svelte:options runes={false} />

<script>
  let paes = $state(0);
</script>

<p>Pães: {paes}</p>

Aqui está o perigo. No modo antigo, $state não é runa: o compilador lê o cifrão como leitura de store. A página quebra na hora de desenhar:

Erro ao renderizar: state is not defined

O compilador não avisa antes porque, para ele, aquilo é sintaxe válida — só que significa outra coisa. O resultado é uma variável chamada state que ninguém declarou.

Missão: a opção runes={false} desliga as runas e o componente quebra. Faça a tela mostrar Pães: 0.

<svelte:options runes={false} />

<script>
  let paes = $state(0);
</script>

<p>Pães: {paes}</p>
<script>
  let paes = $state(0);
</script>

<p>Pães: {paes}</p>

A solução mais direta é apagar a linha da opção. A outra — válida se o arquivo precisar mesmo ficar no modo antigo — é escrever let paes = 0, sem runa nenhuma, e cuidar para que nenhum outro trecho use runas.

7. Misturar os dois mundos

A regra é dura e vale a pena repetir: um componente é de um mundo só. A primeira runa que aparece coloca o arquivo no modo novo, e a partir dali toda a sintaxe antiga vira erro de compilação. Veja o caso mais comum, um arquivo que ganhou $state e manteve export let:

<script>
  export let nome = 'Ana';
  let paes = $state(0);
</script>

<p>{nome}: {paes} pães</p>
Erro de compilação (linha 2, coluna 2): Cannot use `export let` in runes mode — use `$props()` instead

E o mesmo com a reatividade antiga, num arquivo que também tem uma runa:

<script>
  let a = $state(1);
  $: b = a * 2;
</script>

<p>{b}</p>
Erro de compilação (linha 3, coluna 2): `$:` is not allowed in runes mode, use `$derived` or `$effect` instead

Missão: o componente tem uma runa e uma prop antiga, e por isso não compila. Faça a tela mostrar Ana: 0 pães no modo novo.

<script>
  export let nome = 'Ana';
  let paes = $state(0);
</script>

<p>{nome}: {paes} pães</p>
<script>
  let { nome = 'Ana' } = $props();
  let paes = $state(0);
</script>

<p>{nome}: {paes} pães</p>

Como decidir qual mundo escolher num arquivo que você abriu? Se ele já tem runas, fique no modo novo e traduza o que sobrar. Se não tem nenhuma, o arquivo está no modo antigo e continua funcionando — não é urgente mexer. Migrar sem pressa, um arquivo por vez, é mais seguro do que reescrever o projeto inteiro num fim de semana.

9. Um plano de migração em cinco passos

Migrar um componente antigo não é reescrever do zero. É traduzir linha por linha, conferindo a tela a cada passo. A ordem abaixo evita o efeito colateral mais comum: mexer em cinco coisas de uma vez e não saber qual delas quebrou a página.

  1. Troque as props primeiro. Cada export let vira um campo da desmontagem de $props(). Rode a página: os valores que o pai passa têm de continuar aparecendo.
  2. Depois o estado. Cada let que aparece no HTML vira $state. Valores que nunca mudam podem ficar como const.
  3. Por último a reatividade. Cada $: vira $derived (se calcula) ou $effect (se faz algo).
  4. Eventos e conteúdo. on:click vira onclick; <slot /> vira {@render children()}.
  5. Rode de novo. Se a página funcionar, o arquivo está no modo novo. Se algo parou, a mensagem do compilador aponta a linha que ainda está no mundo antigo.

A ordem importa porque a primeira runa que você introduz já muda o modo do arquivo — e a partir dali todo o resto que era antigo vira erro. Se você começar pelo estado, o export let que sobrou vai reclamar; se começar pelas props, o arquivo continua antigo até a primeira runa de estado entrar. Não existe mágica: é uma escada, um degrau por vez.

PassoAntesDepoisComo saber se deu certo
1export let precolet { preco } = $props()os valores do pai aparecem
2let qtd = 1let qtd = $state(1)o clique muda a tela
3$: total = qtd * 0.9let total = $derived(qtd * 0.9)o total acompanha
4on:click={…}onclick={…}o clique continua funcionando

Uma dica prática: faça a migração com o servidor de desenvolvimento aberto ao lado. Cada salvamento mostra o resultado em menos de um segundo, e o erro — quando aparece — vem com linha e coluna. Migrar às cegas, num arquivo de duzentas linhas, é o caminho mais longo.

10. O que mais sobrou do mundo antigo

Além das cinco marcas principais, o modo antigo tem vizinhos que você vai encontrar em projetos reais. Nenhum deles é runa, e todos têm equivalente no mundo novo:

Stores. Antes das runas, estado compartilhado entre componentes se fazia com stores: objetos com subscribe, lidos no HTML com o cifrão. Hoje, um módulo .svelte.js com $state resolve o mesmo problema com menos cerimônia. Stores continuam existindo e funcionando — e são a razão de o cifrão ser reservado.

$$props e $$restProps. No modo antigo, essas duas variáveis especiais davam acesso a todas as props recebidas. No modo novo, o mesmo papel é do objeto devolvido por $props() e do resto com ...resto.

createEventDispatcher. Era a forma de o filho avisar o pai. Hoje, o caminho mais direto é passar uma função como prop (um callback): o filho chama, o pai decide o que fazer.

slot com let:. Passava dados do filho para o conteúdo do pai. Hoje isso se faz com snippets recebidos como prop — um recurso que parece complicado no começo e simplifica muito depois.

Reconhecer essas peças é o que permite ler um tutorial de 2022 sem se perder. A ideia por trás é sempre a mesma: um valor que muda, uma tela que acompanha. O que mudou foi a forma de escrever — e a forma nova é a que este guia ensina.

11. Quando dá errado

As três mensagens abaixo resumem os tropeços de quem mistura os dois mundos. As duas primeiras param a compilação; a terceira só aparece na tela.

1. Prop antiga num componente novo. Basta uma runa para o export let virar erro:

<script>
  export let nome = 'Ana';
  let paes = $state(0);
</script>

<p>{nome}: {paes} pães</p>
Erro de compilação (linha 2, coluna 2): Cannot use `export let` in runes mode — use `$props()` instead

Troque a linha por let { nome = 'Ana' } = $props(). Se preferir manter export let, tire todas as runas do arquivo — mas aí você está no modo antigo de propósito.

2. Reatividade antiga num componente novo. O $: também é recusado:

<script>
  let a = $state(1);
  $: b = a * 2;
</script>

<p>{b}</p>
Erro de compilação (linha 3, coluna 2): `$:` is not allowed in runes mode, use `$derived` or `$effect` instead

O substituto depende do que a linha faz: cálculo vira $derived; ação vira $effect.

3. Runas desligadas por opção. O compilador aceita e a página quebra ao desenhar:

<svelte:options runes={false} />

<script>
  let paes = $state(0);
</script>

<p>Pães: {paes}</p>
Erro ao renderizar: state is not defined

No modo antigo, $state é lido como acesso à store state. A correção é remover a opção ou trocar a declaração por let paes = 0.

A tradução de um arquivo antigo é mecânica: cada export let vira uma prop no $props(), cada let que aparece na tela vira $state, cada $: vira $derived ou $effect, cada on: vira atributo de evento. Faça um por vez, rode a página, confira. Migração aos poucos é o que o próprio Svelte recomenda.

Resumo

  • Componente sem nenhuma runa é compilado no modo antigo, e continua funcionando.
  • No modo antigo, cada atribuição (x = 3, x++) avisa a tela; mutações em listas não.
  • $: era a reatividade: cálculo virava $derived, ação virava $effect.
  • export let era a prop; hoje é let { nome } = $props().
  • on:click era o evento; hoje é onclick, e misturar os dois é erro.
  • <slot /> era o buraco do pai; hoje é {@render children()}.
  • Uma única runa coloca o arquivo no modo novo e invalida a sintaxe antiga.
  • <svelte:options runes={false} /> força o modo antigo; usar runa ali quebra a página com state is not defined.
  • Migre um arquivo por vez, traduzindo item por item da tabela.
  • Código novo: sempre o modo runas.
