Svelte · mount() e flushSync

A Ana comprou um quadro novo para a parede da padaria, mas o quadro estava apoiado no chão: bonito, pronto, e ninguém via. Um componente .svelte é assim — ele descreve a tela, mas não aparece em lugar nenhum até alguém pendurar na página. Quem pendura é a função mount(), e é ela que o arquivo main.js do projeto chama. Esta aula mostra o caminho completo: o alvo, as props, o que fazer para desmontar e como medir a tela no instante certo com flushSync.

Você vai aprender
  • O que mount() faz e por que ele não é opcional num app Svelte.
  • Como é o main.js e o que cada pedaço dele significa.
  • Como passar props para um componente montado à mão.
  • O que mount() devolve e como usar unmount().
  • Por que o DOM não muda na mesma linha em que o estado muda.
  • Como flushSync() aplica as mudanças antes da próxima leitura.
  • Quando trocar mount por hydrate.
  • Por que mount() não existe no servidor.
  • Os três erros reais desta aula, com a mensagem do compilador.

1. A ideia: pendurar o quadro na parede

Um componente pronto não é uma tela. Ele é uma receita de tela: diz que existe um título, um botão e uma lista, mas não sabe onde isso vai ficar. O lugar é uma tag vazia na página, quase sempre uma div com um id. Pendurar o quadro nessa parede é o trabalho do mount.

A palavra vem do inglês e quer dizer "montar". Montar é criar os elementos de verdade no documento, ligar os eventos, guardar o estado e deixar o componente vivo. Antes do mount existe a descrição; depois dele existe a tela. Se o componente nunca é montado, nada acontece — nenhum erro, nenhum aviso, nenhuma tela.

Quem faz esse trabalho num projeto com SvelteKit é o próprio framework, e você nunca escreve mount na mão. Num projeto sem SvelteKit — o da Ana — esse trabalho é seu, e cabe em cinco linhas de main.js. As duas situações usam a mesma função; só muda quem chama.

Na padariaNo projeto
O quadro pronto, apoiado no chãoo arquivo App.svelte
O prego na parede<div id="app"></div>
Pendurar o quadro no pregomount(App, { target })

O vocabulário: alvo (target) é o elemento onde o componente vive; montar é criar a tela; desmontar é removê-la e limpar o que ela criou; e flush é o ato de aplicar as mudanças pendentes de uma vez. Quatro palavras que explicam o resto da aula.

2. O main.js de sempre

O projeto da Ana tem dois arquivos no caminho da montagem: a página HTML, que traz a parede, e o main.js, que traz o prego. A página é a mesma que você já viu em qualquer site:

<!doctype html>
<html lang="pt-BR">
  <head>
    <meta charset="utf-8" />
    <title>Loja da Ana</title>
  </head>
  <body>
    <div id="app"></div>
    <script type="module" src="/src/main.js"></script>
  </body>
</html>

Repare na div vazia: ela é o alvo. Repare também que a página carrega main.js como módulo — o navegador precisa desse tipo de script para aceitar import. O arquivo em si é curto:

import { mount } from 'svelte';
import App from './App.svelte';

const app = mount(App, { target: document.getElementById('app') });

export default app;
import { mount } from 'svelte'
a função vem do pacote svelte. Ela é a única peça do framework que o main.js precisa.
import App from './App.svelte'
o componente em si. O Vite transforma o .svelte em JavaScript antes de o navegador ver.
mount(App, { … })
a montagem. O primeiro argumento é o componente; o segundo é um objeto de opções, com pelo menos o target.
target: document.getElementById('app')
o elemento onde a tela vai viver. Precisa existir no documento antes desta linha rodar.
export default app
o resultado da montagem, exportado para quem precisar desmontar ou conversar com o componente.

O id="app" da página e o getElementById('app') do script precisam combinar. Se um dos dois mudar sem o outro, o mount recebe null e o componente não aparece — sem mensagem clara na tela, só um erro no console.

O type="module" da tag de script não é enfeite: sem ele, o navegador trata o arquivo como script antigo, recusa os import e a página fica em branco com um erro de sintaxe. Todo projeto Svelte com Vite usa módulos, e é por isso que você vê esse atributo em todo index.html da internet moderna.

3. Props: o recado que vai junto

Montar com props é como pendurar o quadro com um bilhete: o mesmo componente serve para vários casos, e o recado diz qual. As props são o primeiro argumento do componente, do lado de dentro, e um objeto no mount, do lado de fora.

<script>
  let { nome = 'Ana', cidade = 'São Paulo' } = $props();
</script>

<p>Olá, {nome}! Pães frescos em {cidade}.</p>

Sem props vindas de fora, o componente usa os valores padrão que ele mesmo declara:

<p>Olá, Ana! Pães frescos em São Paulo.</p>

Do lado do main.js, o recado vai num objeto chamado props:

import { mount } from 'svelte';
import Saudacao from './Saudacao.svelte';

const app = mount(Saudacao, {
  target: document.getElementById('app'),
  props: { nome: 'Bia', cidade: 'Campinas' }
});

O nome da chave no objeto precisa ser igual ao nome que o componente espera. nome com nome, cidade com cidade. Um erro de digitação não dá erro: o componente usa o valor padrão, e a pessoa vê "Ana" onde deveria ver "Bia".

Missão: o componente espera a prop nome, mas o valor não chegou e a tela mostra "Olá, !". Dê um valor padrão para a prop e mostre Olá, Ana!.

<script>
  let { nome } = $props();
</script>

<p>Olá, {nome}!</p>
<script>
  let { nome = 'Ana' } = $props();
</script>

<p>Olá, {nome}!</p>

4. O que o mount devolve

O mount devolve a instância do componente. Guardar essa instância numa variável serve para dois usos: desmontar depois e conversar com o componente por meio do que ele exporta. O primeiro é o mais comum.

import { mount, unmount } from 'svelte';
import App from './App.svelte';

const app = mount(App, { target: document.getElementById('app') });

// mais tarde, ao fechar o painel:
unmount(app);

Desmontar não é esconder. Esconder deixa os elementos na página e os eventos ligados; desmontar remove os elementos, cancela efeitos, limpa temporizadores registrados com as funções certas e libera a memória. Num app de página única, isso raramente aparece; num widget que abre e fecha dentro de um site antigo, é a diferença entre um site leve e um site que engorda a cada clique.

O unmount é assíncrono na versão atual: ele devolve uma promessa que resolve quando a limpeza termina. Se você precisa saber que a área já está vazia antes de montar outra coisa no mesmo lugar, use await unmount(app) dentro de uma função assíncrona.

A instância também serve para conversar com o componente. Um componente pode expor funções e valores para quem o montou; elas ficam disponíveis no objeto devolvido. É o caminho para um site antigo mandar um comando para a ilha Svelte — abrir o painel, trocar o produto — sem passar por props e sem recriar a tela.

5. flushSync: medir na hora certa

Aqui está o detalhe que pega todo mundo. Quando você muda um estado, o Svelte não redesenha na mesma linha: ele anota a mudança e desenha no fim do trabalho atual. Isso é ótimo para desempenho — dez mudanças viram um desenho — e péssimo quando você precisa ler o DOM logo depois.

<script>
  import { flushSync } from 'svelte';

  let itens = $state(['pão', 'bolo', 'broa']);
  let antes = $state(0);
  let depois = $state(0);

  function medir() {
    itens = [...itens, 'sonho', 'torta'];
    antes = document.querySelectorAll('li').length;
    flushSync();
    depois = document.querySelectorAll('li').length;
  }
</script>

<p>antes: {antes} · depois: {depois}</p>
<button onclick={medir}>medir</button>

<ul>
  {#each itens as item}
    <li>{item}</li>
  {/each}
</ul>

Na primeira renderização, nenhuma medição aconteceu, e o HTML mostra zeros:

<p>antes: 0 · depois: 0</p> <button>medir</button> <ul><li>pão</li><li>bolo</li><li>broa</li></ul>

No navegador, depois de um clique em "medir", a tela mostra a diferença que dá nome à função:

antes: 3 · depois: 5 medir pão bolo broa sonho torta
itens = [...itens, …]
a mudança de estado. A lista em memória já tem cinco itens no instante seguinte — o DOM não.
document.querySelectorAll('li')
a leitura do DOM. Antes do flushSync, ela vê os três elementos antigos.
flushSync()
aplica agora as mudanças pendentes. Depois desta linha, o DOM reflete o estado novo.
depois = …
a segunda medição, agora com cinco. É a prova de que o flush aconteceu no meio da função.

Missão: o botão acrescenta dois itens e mede duas vezes, mas as duas medidas dão 3. Faça a segunda medida acontecer depois do desenho e mostrar depois: 5.

O flushSync também aceita uma função e devolve o que ela devolver: flushSync(() => { … }). Serve para marcar que aquele bloco precisa do DOM atualizado e para agrupar as mudanças de uma vez. O custo é real: aplicar no meio do handler quebra o agrupamento automático, então use quando a leitura é necessária — medir altura, posicionar um tooltip, dar foco — e não por hábito.

Missão: o botão abre dois avisos e mede zero, porque o DOM ainda não mudou. Aplique as mudanças antes da medição e mostre itens na tela: 2.

<script>

  function abrir() {
    aberto = true;

6. hydrate: quando o HTML já vem pronto

Existe uma segunda forma de colocar o componente na página, e ela serve para quando o HTML já chegou desenhado do servidor. Em vez de criar tudo do zero, o Svelte hidrata: aproveita o HTML existente e liga o comportamento a ele.

import { hydrate } from 'svelte';
import App from './App.svelte';

hydrate(App, {
  target: document.getElementById('app'),
  props: { nome: 'Ana' }
});

A diferença importa. Com mount, o conteúdo do alvo é substituído pelo que o componente desenhar. Com hydrate, o conteúdo é preservado e só ganha vida — o que evita a tela piscar e mantém o que o servidor já entregou. Usar hydrate sem HTML do servidor funciona, mas não ganha nada; usar mount sobre HTML do servidor joga fora o trabalho de renderizar no servidor.

FunçãoO que faz com o conteúdo do alvoQuando usar
mount(App, { target })substituiapp no navegador, sem HTML pronto
hydrate(App, { target })aproveita e ligaHTML vindo do servidor
unmount(app)remove e limpawidget que fecha, teste que termina
flushSync()aplica mudanças pendentesler o DOM logo após mudar estado

7. Quando usar mount na mão

Num projeto SvelteKit, nunca: o framework monta o componente da rota por você, e um main.js extra montaria a mesma tela duas vezes. Num projeto Vite puro, como o da Ana, sempre — é o main.js. Existem ainda três situações em que esse conhecimento aparece fora do comum.

A primeira é a ilha: um site antigo, feito em outra tecnologia, que ganha um pedaço interativo em Svelte. Você monta o componente numa div específica da página e o resto do site continua como estava. A segunda é o widget que abre e fecha: monta quando o painel abre, desmonta quando fecha, e o site não engorda. A terceira é o teste: montar o componente num alvo de teste, interagir e medir é o que a maioria das ferramentas de teste faz por baixo.

Em todos os casos, o cuidado é o mesmo: o alvo precisa existir antes, e a montagem precisa acontecer uma vez só. Montar duas vezes no mesmo alvo cria duas telas sobrepostas, com dois estados independentes e eventos duplicados — o tipo de bug que parece fantasma.

Numa ilha, o alvo costuma ser uma div com um identificador próprio, no meio de uma página que o Svelte não escreveu. O CSS escopado do componente continua valendo ali dentro, porque o selo do compilador vai nas tags. O que não funciona é contar com o CSS da página para estilizar o componente: os dois mundos vivem separados, e é essa separação que impede a ilha de quebrar o resto.

8. Quando dá errado

As três mensagens abaixo saíram do renderizador desta versão, copiadas como estão.

Erro 1 — mount() no servidor

mount é uma função de navegador: ela cria elementos no documento. No servidor não existe documento, e o Svelte recusa com um erro próprio.

<script>
  import { mount } from 'svelte';

  const app = mount();
</script>

<p>montado</p>
Erro ao renderizar: lifecycle_function_unavailable
`mount(...)` is not available on the server
https://svelte.dev/e/lifecycle_function_unavailable

A mensagem tem três linhas: o código do erro, a explicação ("mount(...) não está disponível no servidor") e o endereço da documentação. A correção é chamar mount no main.js, que só roda no navegador, ou dentro de um onMount.

Erro 2 — procurar o alvo no corpo do componente

document também é do navegador. Buscar o alvo no topo do <script> faz o componente funcionar no navegador e quebrar no servidor.

<script>
  let alvo = document.getElementById('app');
</script>

<p>{alvo ? 'achei' : 'não achei'}</p>
Erro ao renderizar: document is not defined

"document is not defined" é o mesmo aviso para window, localStorage e qualquer API do navegador. A busca do alvo pertence ao main.js, onde o documento já existe.

Erro 3 — flushSync sem importar

A função não é global: ela vem do pacote svelte. Esquecer o import deixa o nome desconhecido.

<script>
  flushSync();
</script>

<p>ok</p>
Erro ao renderizar: flushSync is not defined

"flushSync is not defined" quer dizer que o nome não existe no arquivo. As duas funções desta aula vêm do mesmo lugar: import { flushSync, mount, unmount, hydrate } from 'svelte'.

9. Cuidados que economizam uma tarde

O primeiro cuidado é a ordem. O main.js roda quando a página carrega; se ele rodar antes de a div#app existir, o alvo é null. Colocar o script no fim do body, como no exemplo da seção 2, resolve o caso mais comum. A alternativa é esperar o evento de documento pronto.

O segundo é a repetição. Uma função de inicialização chamada duas vezes monta dois componentes no mesmo alvo. Guarde a instância e verifique se ela já existe antes de montar de novo; ou desmonte antes de montar.

O terceiro é a memória. Temporizador, ouvinte de evento e observador criados pelo componente precisam ser limpos quando ele é desmontado. O unmount cuida do que o Svelte conhece — efeitos, por exemplo —, mas não adivinha o que você criou por fora. Use onDestroy ou a função de limpeza do $effect para o que você mesmo abriu.

O quarto é não confundir flushSync com "desenhar mais rápido". Ele não acelera nada: ele só antecipa o desenho para o meio do seu código. Na maioria das vezes, o certo é não medir o DOM — guardar a informação no estado e deixar o Svelte desenhar quando for a hora.

O quinto é escolher entre main.js e onMount. O main.js é o dono da montagem e roda uma vez por página; o onMount roda a cada componente que aparece, inclusive quando são dez iguais. Trabalho de página vai no primeiro; trabalho de componente vai no segundo. Misturar os dois é a receita para buscar os mesmos dados dez vezes.
