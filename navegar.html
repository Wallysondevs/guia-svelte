SvelteKit · Navegando com goto

A Ana tem um botão "ver os pães" no fim da página de contato. Um cliente clicou, a tela piscou branca, o menu sumiu por meio segundo e voltou — porque o navegador tinha jogado tudo fora para buscar a próxima página no servidor. No SvelteKit isso não precisa acontecer: o clique pode trocar só o miolo, mantendo o menu e o estado. Nesta aula você vai ver o link que já faz isso sozinho, o goto que faz o mesmo por código, e as três formas de errar que o terminal mostra com todas as letras.

Você vai aprender
  • O que é navegação no cliente e por que ela parece instantânea.
  • Que um <a href> comum já navega sem recarregar.
  • Como chamar goto de $app/navigation para navegar por código.
  • Por que o goto só pode rodar no navegador, nunca durante o desenho no servidor.
  • A diferença entre goto('/x') e goto('/x', { replace: true }).
  • Quando usar parâmetro de rota e quando usar query string.
  • O redirect, que é o irmão do goto no servidor.
  • O que mais existe em $app/navigation: invalidate, preloadData, beforeNavigate.
  • As três falhas reais desta aula, com o texto do terminal.
  • Boas práticas: link para navegar, botão para agir.

1. A ideia: trocar a gaveta sem sair do balcão

Quando você clica num link comum, o navegador começa tudo de novo: joga fora a página atual, pede o documento ao servidor, espera, monta o HTML, carrega o CSS, carrega o JavaScript, e só então mostra algo. É como sair da padaria, atravessar a rua, entrar de novo e pedir outro pão — a cada troca de gaveta.

Navegação no cliente é outra coisa: o JavaScript que já está na página percebe o clique, pede ao servidor apenas os dados da próxima página e troca o conteúdo na tela. O menu não é redesenhado, o CSS não é recarregado, o estado que estava na memória continua lá. É como o atendente girar o balcão: você não sai do lugar.

No SvelteKit, isso já vem pronto para links internos. O que a aula acrescenta é o controle: goto permite trocar de página sem um link — depois de um formulário, ao terminar um pedido, quando o usuário escolhe uma opção num menu. E o custo dessa facilidade é uma regra que você precisa respeitar: o goto é uma função de navegador, e o seu código também roda no servidor. Chamá-lo na hora errada é o erro mais comum da aula.

2. No dia a dia × no SvelteKit

Na padariaNo SvelteKit

Uma distinção que vale desde já: link é para navegar; botão é para agir. Se o resultado do clique é "ir para outra página", o elemento certo é <a href> — ele funciona com o botão do meio do mouse, abre em nova aba, é lido em voz alta por leitores de tela e o robô de busca o encontra. O goto é para quando não existe link: um envio de formulário, um redirecionamento condicional, uma navegação depois de uma limpeza de dados.

3. O link que já navega sozinho

Este é o botão que a Ana tinha na página de contato, e o jeito como ele ficou depois de virar link:

<h1>Contato</h1>
<p>Pedido pronto? Então já pode ir.</p>
<a href="/paes">ver os pães</a>

Nenhum JavaScript no arquivo. O SvelteKit instala um ouvinte de cliques no documento e, quando o clique é num link interno, impede o comportamento padrão do navegador e faz a troca pelo caminho rápido. O HTML que o servidor manda mostra que o link é um link de verdade:

ana@notebook:~/loja/kit$ curl -s localhost:4173/contato | sed -e 's/<!--[^>]*-->//g' | grep -o '<main.*</main>'
<main><h1>Contato</h1> <p>Pedido pronto? Então já pode ir.</p> <a href="/paes">ver os pães</a></main>

Esse detalhe é o que faz a página funcionar mesmo antes do JavaScript carregar: o link existe no HTML. Se o JavaScript falhar, o clique ainda leva para /paes — só que do jeito lento. É a chamada "melhoria progressiva", e o SvelteKit entrega isso sem você pedir.

A rapidez extra vem do src/app.html, o molde que envolve o site. Ele traz, na tag <body>, o atributo data-sveltekit-preload-data="hover": quando o mouse passa por cima de um link, o SvelteKit já começa a buscar os dados daquela página. Até o clique chegar, metade do trabalho está feito.

4. goto: navegar por código

Quando não existe link para clicar, entra o goto, importado de $app/navigation:

<script>
	import { goto } from '$app/navigation';
</script>

<h1>Contato</h1>
<p>Pedido pronto? Então já pode ir.</p>
<button onclick={() => goto('/paes')}>ver os pães</button>
$app/navigation
um módulo do SvelteKit com as funções de navegação. Não é um arquivo do projeto: o import é resolvido pela ferramenta.
goto
a função que troca de página. Devolve uma promessa, que resolve quando a navegação termina.
'/paes'
o destino, começando pela barra. Pode ser um endereço com query string: '/paes?tamanho=grande'.
onclick={() => goto(…)}
a chamada dentro do evento. O goto precisa rodar no navegador, e o clique é o lugar em que isso acontece.

O HTML que o servidor manda é igual ao do link, com uma diferença que importa: o clique não funciona sem JavaScript, porque a navegação está no onclick. Em troca, você ganha a possibilidade de decidir na hora: só navegar se o campo estiver preenchido, navegar para um endereço montado com o que a pessoa digitou, navegar depois de esperar uma resposta do servidor.

Para saber se o clique realmente troca de página sem recarregar, o guia automatizou o teste num navegador de verdade: abriu /contato, deixou uma marca no objeto window, clicou no botão e esperou a URL virar /paes. Resultado: caminho /paes, título Pães e a marca ainda lá. Se a página tivesse recarregado, a marca teria desaparecido.

5. goto só existe no navegador

Aqui está a pedra no caminho. O mesmo componente é executado duas vezes: uma no servidor, para gerar o HTML, e outra no navegador, para continuar a partir dele. Se você chamar goto na parte de cima do <script>, ela roda também no servidor — e lá não existe navegador para navegar. O terminal do servidor de desenvolvimento mostra:

ana@notebook:~/loja/kit$ npm run dev -- --port 5183

> kit@0.0.1 dev
> vite dev --port 5183

SvelteKit error: server_api_unavailable
Cannot call `goto(...)` on the server
https://svelte.dev/e/kit/server_api_unavailable
    at eval (src/routes/sobre/+page.svelte:3:2)
    at eval (node_modules/svelte/src/internal/server/renderer.js:416:11)
    at Renderer.child (node_modules/svelte/src/internal/server/renderer.js:305:18)
    at Renderer.component (node_modules/svelte/src/internal/server/renderer.js:414:8)
    at _page (src/routes/sobre/+page.svelte:2:2)
500 GET /sobre

Leia a mensagem como um aviso de contexto: "não dá para chamar goto(...) no servidor". A posição 3:2 é a linha exata da chamada. A resposta foi 500, e a página de erro apareceu no lugar da página que você queria ver. O conserto é sempre o mesmo: mover a chamada para dentro de um evento (onclick, onsubmit) ou para dentro de um $effect, que só roda depois que a página está no navegador.

Existe uma função do Svelte, onMount, feita exatamente para o código que só pode rodar no navegador; ela aparece na aula onMount. Para navegação, o evento costuma ser suficiente.

Missão: o campo e o botão existem, mas clicar não leva a lugar nenhum. Faça o botão navegar para /paes/ mais o texto digitado: ao escrever queijo e clicar, a tela deve mostrar /paes/queijo.

<script>
  let destino = $state('/paes');
  let slug = $state('');
</script>

<input placeholder="qual pão?" oninput={(e) => (slug = e.currentTarget.value)} />
<button>ir</button>
<p>{destino}</p>
<script>
  let destino = $state('/paes');
  let slug = $state('');
</script>

<input placeholder="qual pão?" oninput={(e) => (slug = e.currentTarget.value)} />
<button onclick={() => (destino = '/paes/' + slug)}>ir</button>
<p>{destino}</p>

No projeto de verdade, destino não seria uma variável: a última linha seria goto('/paes/' + slug). A caixa usa uma variável para você ver o valor que seria passado ao goto — o mesmo texto, sem o servidor no meio.

6. replace: quando voltar não deve voltar para cá

Cada navegação nova entra na história do navegador. O botão "voltar" desempilha uma por uma. Isso é o que a pessoa espera — menos em alguns casos: uma tela de confirmação que já foi concluída, um endereço que só serve para redirecionar, uma busca que não deve reaparecer ao voltar.

Para esses casos existe a opção replace, que troca a entrada atual em vez de empilhar uma nova:

<script>
	import { goto } from '$app/navigation';
</script>

<h1>Pedido confirmado</h1>
<button onclick={() => goto('/paes', { replace: true })}>voltar ao balcão</button>

Com replace: true, quem clicar em "voltar" depois vai para a página anterior a /pedido, não para /pedido de novo. Sem a opção, o navegador guarda mais uma entrada e o botão "voltar" fica parecendo quebrado. A tabela resume quando usar cada forma:

ChamadaO que acontece na história do navegadorQuando usar
goto('/paes')empilha uma entrada novanavegação normal, escolhida pela pessoa
goto('/paes', { replace: true })troca a entrada atualdepois de concluir algo que não deve voltar
<a href="/paes">empilha uma entrada novasempre que existir link

7. Parâmetro de rota × query string

Existem duas maneiras de levar informação no endereço, e elas não competem. O caminho /paes/queijo usa o parâmetro de rota [slug] — o valor faz parte da identidade do recurso. Já /paes?tamanho=grande usa a query string: o que vem depois do ? é opcional, não muda qual página responde e serve para filtros, ordenação e preferências.

<script>
	import { goto } from '$app/navigation';
	import { page } from '$app/state';

	let tamanho = $state('grande');
</script>

<h1>Pães</h1>
<p>filtro: {page.url.searchParams.get('tamanho') ?? 'todos'}</p>
<button onclick={() => goto('/paes?tamanho=' + tamanho)}>aplicar</button>

A leitura é feita com page.url.searchParams.get('tamanho'), que devolve null quando o parâmetro não está na URL — daí o ?? com o texto de reserva. O goto aceita a string completa, com o ? e os pares chave=valor separados por & quando há mais de um.

Missão: o botão aplica o filtro sem o tamanho escolhido. Monte o endereço com a query string: ao escolher pequeno e clicar, a tela deve mostrar /paes?tamanho=pequeno.

<script>
  let tamanho = $state('grande');
  let caminho = $state('/paes');
</script>

<select onchange={(e) => (tamanho = e.currentTarget.value)}>
  <option value="grande">grande</option>
  <option value="pequeno">pequeno</option>
</select>
<button onclick={() => (caminho = '/paes')}>aplicar</button>
<p>{caminho}</p>
<script>
  let tamanho = $state('grande');
  let caminho = $state('/paes');
</script>

<select onchange={(e) => (tamanho = e.currentTarget.value)}>
  <option value="grande">grande</option>
  <option value="pequeno">pequeno</option>
</select>
<button onclick={() => (caminho = '/paes?tamanho=' + tamanho)}>aplicar</button>
<p>{caminho}</p>

O select dispara change quando a escolha muda, e a caixa aproveita o mesmo evento para guardar o valor. Repare que a URL não muda enquanto o botão não é clicado: escolher no campo é estado do componente; aplicar é navegação. Separar as duas coisas deixa o comportamento previsível — e o botão "voltar" do navegador continua fazendo sentido.

8. redirect: o irmão do goto no servidor

O goto só funciona no navegador porque só lá existe história para empilhar. No servidor, o equivalente é o redirect, de @sveltejs/kit: ele responde ao navegador com um status 3xx e um endereço novo, e o navegador refaz o pedido sozinho. O primeiro argumento é o status, que precisa estar entre 300 e 308.

import { redirect } from '@sveltejs/kit';

export function load({ cookies }) {
	if (!cookies.get('cliente')) {
		redirect(303, '/entrar');
	}
	return {};
}

O 303 quer dizer "olhe em outro lugar, e use o método GET". O 307 preserva o método original — útil quando um formulário precisa ser reenviado para outro endereço. Para quem começa, 303 resolve a maioria dos casos de "leve a pessoa para a página de login".

Onde você estáFerramentaEfeito
Navegador, dentro de um eventogoto('/x')troca a página sem recarregar
Navegador, sem querer empilhargoto('/x', { replace: true })troca a entrada atual da história
Servidor, dentro de loadredirect(303, '/x')responde 3xx e o navegador refaz o pedido
Link na marcação<a href="/x">navega (rápido se o JS carregou)

Um aviso que evita um bug silencioso: não capture o erro do redirect. Ele funciona lançando um objeto especial que o SvelteKit intercepta. Um try/catch em volta engole o redirecionamento e a pessoa fica parada na página. Se precisar tratar erros, trate só os seus.

9. O resto de $app/navigation

goto é a função mais usada do módulo, mas não é a única. As outras aparecem quando o site cresce; reconhecer os nomes economiza pesquisa.

FunçãoPara que serve
beforeNavigate(fn)roda antes de sair da página: dá para cancelar (por exemplo, com dados não salvos)
afterNavigate(fn)roda depois que a nova página apareceu
invalidate(url)manda o load que depende daquela URL rodar de novo
refreshAll()manda todos os load rodarem de novo
preloadData(url)busca os dados de uma página antes do clique
pushState(url, estado)muda a URL e o page.state sem rodar load

Repare no par invalidate e refreshAll: eles existem porque o SvelteKit guarda o resultado dos load para não pedir de novo a cada navegação. Quando você sabe que o dado mudou — salvou um pedido, por exemplo — pedir a atualização é sua responsabilidade. Sem isso, a pessoa vê o dado velho e acha que o site está quebrado.

10. Quando dá errado

As três saídas abaixo são do projeto da Ana. A primeira é do build, a segunda do terminal do servidor de desenvolvimento e a terceira mostra um erro que só aparece na hora do pedido.

Erro 1 — nome do módulo com uma letra a mais

A Ana escreveu $app/navigations, no plural. O módulo não existe, e o build para antes de gerar qualquer coisa:

ana@notebook:~/loja/kit$ npm run build
vite v8.4.0 building ssr environment for production...
transforming...
✓ 144 modules transformed.
✗ Build failed in 424ms
error during build:
Build failed with 1 error:
[UNLOADABLE_DEPENDENCY] Could not load node_modules/@sveltejs/kit/src/runtime/app/navigations
   ╭─[ src/routes/sobre/+page.svelte:2:22 ]
   │
 2 │ import { goto } from '$app/navigations';
   │                      ─────────┬────────
   │                               ╰────────── No such file or directory (os error 2)
───╯

O desenho embaixo do import marca exatamente o texto errado. "No such file or directory" é literal: o SvelteKit transforma $app/algo num caminho de arquivo dentro do próprio pacote, e esse arquivo não existe. Os módulos que existem são $app/state, $app/navigation, $app/forms, $app/environment e $app/paths.

Erro 2 — goto no topo do script

Este é o erro da seção 5, na versão completa. O componente compila, o build passa e o erro só aparece quando alguém pede a página:

SvelteKit error: server_api_unavailable
Cannot call `goto(...)` on the server
https://svelte.dev/e/kit/server_api_unavailable
    at eval (src/routes/sobre/+page.svelte:3:2)
500 GET /sobre

A pista está no nome: server_api_unavailable, "API de servidor indisponível". A função existe, mas foi desligada do lado do servidor de propósito — não há navegador ali. Para testar durante o desenvolvimento, abra a página: o erro aparece no terminal a cada requisição, e a página de erro na tela.

Erro 3 — goto dentro do +error.svelte

Parece razoável: se a página de erro aparecer, redirecione para o início. Só que a página de erro também é desenhada no servidor, e o goto roda de novo no lugar errado. O resultado é cruel: um 404 vira 500.

ana@notebook:~/loja/kit$ curl -s -o /dev/null -w '%{http_code}\n' localhost:5183/nao-existe
500
SvelteKit error: server_api_unavailable
Cannot call `goto(...)` on the server
    at eval (src/routes/+error.svelte:4:27)
500 GET /nao-existe

Para redirecionar de verdade a partir de um erro, o lugar é o load, com redirect(303, '/'). No componente, navegação só dentro de um evento — e uma página de erro raramente precisa de navegação automática: um link de volta resolve melhor.

11. Experimente: não navegar quando falta informação

Um dos motivos para usar goto em vez de link é poder decidir antes de sair. A caixa abaixo tem um campo e um botão; a missão é impedir a navegação quando o campo está vazio e avisar a pessoa.

Missão: com o campo vazio, o botão navega para /paes/ e não avisa nada. Faça ele não navegar nesse caso e mostrar informe o pão.

<script>
  let slug = $state('');
  let destino = $state('/paes');
  let aviso = $state('');

  function ir() {
    destino = '/paes/' + slug;
  }
</script>

<input placeholder="qual pão?" oninput={(e) => (slug = e.currentTarget.value)} />
<button onclick={ir}>ir</button>
<p>{destino}</p>
<p>{aviso}</p>
<script>
  let slug = $state('');
  let destino = $state('/paes');
  let aviso = $state('');

  function ir() {
    if (slug === '') {
      aviso = 'informe o pão';
      return;
    }
    destino = '/paes/' + slug;
  }
</script>

<input placeholder="qual pão?" oninput={(e) => (slug = e.currentTarget.value)} />
<button onclick={ir}>ir</button>
<p>{destino}</p>
<p>{aviso}</p>

O return cedo é a peça central: ele sai da função antes de mexer no destino. Esse padrão tem nome — guard clause, cláusula de guarda — e vale para qualquer função que precise recusar uma entrada inválida. No projeto real, a linha do destino seria o goto('/paes/' + slug), e o resto ficaria igual.

12. Referência rápida

Você quer…EscrevaOnde

Duas regras que resolvem a maioria dos casos: se existe um endereço para ir, use link; se a navegação depende de algo que só o navegador sabe, use goto dentro de um evento. E se o código precisa rodar uma vez só, no navegador, procure onMount — o goto no corpo do componente é sempre suspeito.

13. O caminho até aqui

O site da Ana agora troca de página sem piscar. O menu continua onde estava, o rodapé nem se mexe, e o clique parece instantâneo por causa do preloadData que o app.html já traz. O botão de contato virou link; o envio de pedido usa goto; o redirecionamento de quem não entrou ficou no load, com redirect.

Ficou faltando juntar rotas que compartilham um comportamento sem que a pasta apareça na URL — o caso do painel restrito. É o assunto de Grupos de Rotas. E se você quiser rever como o endereço se liga ao arquivo, Rotas por Arquivo tem o mapa; para o valor que vem na URL, Parâmetros de Rota.
