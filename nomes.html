Svelte · Nomes e Convenções

A Ana tem uma pasta com quarenta arquivos: cartao.svelte, Cartao.svelte, cartao-novo.svelte, cartaoFINAL.svelte. Ela sabe o que cada um faz — até o dia em que precisa mexer no preço e abre o arquivo errado três vezes seguidas. Nome de arquivo, de variável e de função não é enfeite: é a primeira coisa que você e o compilador leem. Nesta aula, a Ana aprende as convenções que o Svelte cobra e as que ele só combina com você.

Você vai aprender
  • Por que o computador também depende do nome, não só você.
  • A diferença entre Cartao, cartao e cartao-de-preco.
  • Por que componente começa com maiúscula e variável com minúscula.
  • Como escrever nomes compostos com camelCase sem inventar abreviação.
  • O que fazer com nomes que o Svelte já usa, como class e onclick.
  • A regra prática para nomear booleanos, funções e listas.
  • Como renomear um arquivo no terminal e o que muda na importação.
  • O aviso real do compilador quando o componente fica em minúscula.
  • Os três erros de nome desta aula, com a mensagem copiada do compilador.

1. A ideia: o nome é uma etiqueta que o computador lê

Na padaria, a Ana cola etiqueta em tudo: “farinha”, “açúcar”, “sonho”. Se ela escrever “farinha” num pote de sal, o erro não é de português — é de operação: alguém vai salgar o pão doce. Nome errado custa tempo e dinheiro, mesmo quando está escrito corretamente.

Com código é igual, com um agravante. O nome de uma variável não serve só para você se achar: ele é a chave que o compilador usa para ligar o valor ao lugar da tela. Quando você escreve {preco} no HTML, o compilador procura uma variável chamada exatamente preco. Se ela se chama Preco, a ligação não acontece — e o erro que aparece na tela não fala de maiúscula, fala de “is not defined”.

Existe ainda um segundo nível: o Svelte usa a forma do nome para decidir o que ele é. Nome com maiúscula no começo é componente; nome com minúscula é variável, função ou tag do HTML. Essa é a convenção mais importante do guia inteiro, e a única que o compilador avisa quando você quebra.

Na padariaNo componente
Etiqueta do pote de farinhaO nome da variável: precoUnitario

Duas etiquetas “farinha” em potes diferentesDuas variáveis com o mesmo nome: erro na hora

Repare que nenhuma dessas convenções é capricho de estilo. As duas primeiras linhas são regras do compilador: quebram o programa. As duas últimas são acordos entre pessoas: o programa roda, mas o próximo a ler sofre — e esse próximo pode ser você em duas semanas.

2. As três famílias de nomes

Antes de escrever qualquer coisa, separe o que você está nomeando. No Svelte existem três famílias, e cada uma tem um formato próprio:

O que éFormatoExemplo
Componente (arquivo e importação)PascalCase: cada palavra com maiúscula, sem espaço e sem hífenCartaoDePreco.svelte
Variável, função, propriedadecamelCase: primeira palavra minúscula, as seguintes com maiúsculaprecoUnitario, calcularTroco()
Tag do HTMLminúscula, como o navegador já conhecebutton, input, section

O nome CartaoDePreco tem três pedaços colados: Cartao, De, Preco. Cada pedaço começa com maiúscula. Já precoUnitario tem dois pedaços, e só o segundo começa com maiúscula. A isso damos o nome de camelCase (corcunda de camelo: as maiúsculas no meio parecem corcovas).

Fique de olho numa armadilha de português: nada de acento em nome de código. A linguagem aceita preço — o compilador não reclama —, mas cada teclado, cada editor e cada colega vai digitar isso de um jeito, e você vai perder minutos procurando preço com cedilha contra preco sem. Escreva preco. O texto que aparece na tela continua sendo “preço”, com acento, porque aí é texto e não nome.

3. Maiúscula para componente, minúscula para o resto

Comece pelo componente que a Ana usa para mostrar um preço na vitrine. Ele tem um nome comprido e chato de digitar — e é assim mesmo: nome comprido e claro vale mais do que nome curto e obscuro.

<script>
  let { titulo = 'Pão francês', preco = 0.9 } = $props();
</script>

<article>
  <h2>{titulo}</h2>
  <p>R$ {preco.toFixed(2)}</p>
</article>

E aqui está o mesmo componente com dados de verdade, como o compilador o entrega:

<article><h2>Pão francês</h2> <p>R$ 0.90</p></article>

Repare no que o nome do arquivo fez: nada dentro do HTML. O compilador não escreve CartaoDePreco em lugar nenhum. O nome do arquivo serve para você importar:

<script>
  import CartaoDePreco from './CartaoDePreco.svelte';
</script>

<h1>Loja da Ana</h1>
<CartaoDePreco titulo="Pão francês" preco={0.9} />

Aqui o nome importado e a tag que você usa são o mesmo, os dois com maiúscula. Essa repetição é de propósito: quem lê o HTML sabe que <CartaoDePreco /> é um componente seu, e não uma tag que o navegador inventou. Uma tag do HTML tem sempre nome conhecido — div, p, button —, então qualquer tag com maiúscula no meio é, por definição, código de alguém.

Maiúscula é a fronteira

O compilador decide assim: se a tag começa com minúscula, é HTML; se começa com maiúscula, é componente. Não existe lista para consultar — a regra é a primeira letra. É a única do guia em que a forma do nome muda o significado do código.

4. A anatomia de um nome composto

Um nome bom responde três perguntas sem que ninguém precise abrir o arquivo: o que é, de quem é e para que serve. Veja o script da Ana, que calcula o total de uma compra:

<script>
  let precoUnitario = $state(0.9);
  let quantidade = $state(3);
  let total = $state(0);
</script>

<p>Total: R$ {(precoUnitario * quantidade).toFixed(2)}</p>
<p>Total: R$ 2.70</p>
let
diz que o valor pode mudar. Nome de variável que muda começa em minúscula, sempre.
precoUnitario
duas palavras coladas: preco (o que é) e Unitario (de quem é, de uma unidade só). A maiúscula do meio marca onde uma palavra termina.
quantidade
uma palavra só, minúscula. Não precisa inventar qtd: abreviação economiza três letras e custa uma consulta ao dicionário mental de quem lê.
total
o resultado que a tela mostra. Nome curto é bom quando o significado é óbvio no contexto.
{(precoUnitario * quantidade).toFixed(2)}
a conta dentro das chaves. Repare que total foi declarado e não foi usado: o valor dele é 0, e a tela mostra a conta, não a variável.

Esse último ponto merece atenção, porque é um erro de nome disfarçado de erro de conta. A Ana declarou total pensando “o total vai aparecer aqui”, mas escreveu a multiplicação na tela. Funciona — e continua funcionando quando quantidade muda —, só que agora existem duas ideias de total no arquivo: a variável parada em zero e a conta viva no HTML. Quem lê não sabe qual é a verdadeira. O certo é escolher uma: ou total é uma variável calculada, ou não existe.

5. camelCase na prática

Vamos ver a convenção trabalhando num caso com decisão de verdade. A Ana precisa saber se há troco a devolver:

<script>
  let temTroco = $state(false);
  let valorPago = $state(10);
  let precoTotal = $state(10);
</script>

{#if temTroco}
  <p>Devolver R$ {(valorPago - precoTotal).toFixed(2)}</p>
{:else}
  <p>Sem troco</p>
{/if}
<p>Sem troco</p>

Três nomes, três decisões. temTroco começa com um verbo (“tem”) porque guarda sim ou não: lê-se como uma pergunta, e a resposta está no valor. valorPago diz de que lado do balcão vem o dinheiro. precoTotal diz o outro lado. Se a Ana tivesse chamado os dois de valor, a subtração valor - valor daria zero e ninguém entenderia por quê.

temTroco
booleano (verdadeiro ou falso). Comece com tem, eh, pode ou mostra — o nome já conta que a resposta é sim ou não.
valorPago
número com origem clara. O sufixo Pago evita a confusão com o preço.
precoTotal
o prefixo preco agrupa os nomes que falam de dinheiro; quem lê o arquivo acha todos juntos.

Agora a pergunta que sempre aparece: camelCase ou snake_case? Snake é tem_troco, com underline. O JavaScript aceita os dois, e o compilador do Svelte também:

<script>
  let tem_troco = $state(false);
</script>

{#if tem_troco}
  <p>Devolver o troco</p>
{:else}
  <p>Sem troco</p>
{/if}
<p>Sem troco</p>

Compila e roda igual. Então por que o guia insiste em camelCase? Porque o resto do mundo Svelte já usa camelCase: as runas ($state), as propriedades (onclick, bind:value), as funções da linguagem (toFixed, querySelector). Misturar os dois estilos no mesmo arquivo faz o olho tropeçar a cada linha. O custo de escolher snake_case é pequeno no começo e cresce com o projeto — cada arquivo novo é uma decisão repetida.

Missão: a lista deveria mostrar o nome de cada produto, e a tela saiu vazia. O problema está no nome usado dentro do {#each}: a lista se chama produtos, mas um produto sozinho se chama produto. Conserte.

<script>
  let produtos = $state([
    { nome: 'Pão francês', preco: 0.9 },
    { nome: 'Sonho', preco: 2.5 }
  ]);
</script>

<ul>
  {#each produtos as produto}
    <li>{produtos.nome}</li>
  {/each}
</ul>
<script>
  let produtos = $state([
    { nome: 'Pão francês', preco: 0.9 },
    { nome: 'Sonho', preco: 2.5 }
  ]);
</script>

<ul>
  {#each produtos as produto}
    <li>{produto.nome}</li>
  {/each}
</ul>

O nome no singular e no plural é uma convenção que economiza explicação: produtos é a lista inteira, produto é o item da vez. Com esses dois nomes, {#each produtos as produto} lê-se em voz alta: “para cada produto da lista de produtos, chame este de produto”. Sem eles, você precisa de comentário.

6. Nomes que já têm dono

Alguns nomes não são seus. class, onclick, value, id são atributos do HTML, e o Svelte trata cada um de um jeito. Se você quiser receber um deles como propriedade do componente, precisa renomear na chegada:

<script>
  let { class: classe = 'destaque' } = $props();
</script>

<p class={classe}>Pão francês</p>
<p class="destaque">Pão francês</p>
class: classe
dois-pontos: “o nome lá fora é class, aqui dentro chame de classe”. Do lado esquerdo fica o nome do atributo, do lado direito o nome que você usa no código.
= 'destaque'
valor padrão. Se ninguém passar class, o componente usa destaque — e a saída confirma isso.
class={classe}
no HTML, o atributo volta a se chamar class, agora com o valor que veio de fora.

Esse class: classe não é só uma questão de bonito. class é palavra reservada da linguagem: escrever let class = 'destaque' no script é recusado pelo compilador com a mensagem Unexpected keyword 'class'. Renomear na chegada é o caminho legal para usar o nome.

Não renomeie à toa

Renomear tem custo: quem usa o componente precisa saber que a propriedade se chama class e que lá dentro virou classe. Faça isso só quando o nome for obrigatório — atributos do HTML, palavras reservadas e nomes de runas. Para o resto, escolha um nome livre e pronto.

Missão: o título não aparece porque a propriedade foi escrita com maiúscula, e maiúscula é para componente. Deixe o nome em minúscula e dê o valor padrão 'Padaria da Ana' para o título aparecer.

<script>
  let { Titulo } = $props();
</script>

<h1>{Titulo}</h1>
<script>
  let { titulo = 'Padaria da Ana' } = $props();
</script>

<h1>{titulo}</h1>

Repare no que a caixa mostra: o código inicial não dá erro nenhum, só desenha um h1 vazio. Propriedade que não chega vale undefined, e o Svelte desenha undefined como nada. É por isso que valor padrão é tão comum em componente: ele transforma “não veio” em “veio o combinado”.

7. Nomes de arquivo: PascalCase, sem hífen, sem acento

A regra do arquivo é a mesma do componente, porque são a mesma coisa: o arquivo CartaoDePreco.svelte é o componente CartaoDePreco. A Ana começou com hífen, que é o padrão de nome de arquivo na web, e teve de renomear:

ana@notebook:~/loja$ ls src/lib
cartao-de-preco.svelte
ana@notebook:~/loja$ mv src/lib/cartao-de-preco.svelte src/lib/CartaoDePreco.svelte
ana@notebook:~/loja$ ls src/lib
CartaoDePreco.svelte

O comando mv quer dizer mover, e mover um arquivo para o mesmo lugar com outro nome é renomear. Repare que o terminal não responde nada quando dá certo — silêncio é sucesso. O ls depois é a prova: o arquivo agora se chama CartaoDePreco.svelte.

Por que hífen atrapalha? Porque hífen não pode aparecer em nome de variável. Se o arquivo se chamasse cartao-de-preco.svelte, você teria de importar assim:

<script>
  import CartaoDePreco from './cartao-de-preco.svelte';
</script>

<CartaoDePreco titulo="Sonho" preco={2.5} />

Funciona — o nome do arquivo pode ter hífen —, mas agora existem dois nomes para a mesma coisa: o do disco e o do código. Cada arquivo novo é uma chance de errar a importação. Com PascalCase nos dois, o nome é um só.

ArquivoFunciona?Observação

8. O aviso que o compilador dá quando o nome é minúsculo

Vamos quebrar a regra de propósito para ver o que acontece. A Ana renomeou o componente para minúscula e usou a tag em minúscula:

<script>
  import cartao from './lib/cartao.svelte';
</script>

<h1>Loja da Ana</h1>
<cartao titulo="Pão francês" preco={0.9} />

O código compila. O aviso aparece no terminal, durante a montagem do projeto:

Leia a frase com calma: “<cartao> será tratado como um elemento HTML, a menos que comece com letra maiúscula”. O compilador está dizendo que a tag virou uma tag desconhecida do navegador, que não desenha nada visível e não recebe as propriedades. O componente importado fica no script sem uso.

O aviso também mostra a linha e a coluna exatas (src/App.svelte:6:0) e um trecho de contexto — as linhas 4 a 7 com o acento circunflexo embaixo do problema. Isso volta na aula de depuração: esse tipo de trecho é o mapa do erro.

Aviso não é erro — e é pior por isso

O build terminou com sucesso mesmo com o aviso. A tela saiu sem o cartão, e nada no navegador explica o motivo. Erro de compilação para o trabalho; aviso passa batido e vira bug. Leia os dois.

9. Nomes de função, de lista e de evento

Falta a família mais numerosa: as funções. A convenção é começar com um verbo, no infinitivo, e continuar com o objeto da ação:

NomeO que conta
calcularTroco()verbo + objeto: devolve um valor, não muda a tela
adicionarAoCarrinho()verbo + destino: muda o estado
formatarPreco()verbo + formato: devolve texto pronto para a tela
somarClique()nome do que aconteceu, não do que o botão é

Quando a função é usada direto num evento, o nome aparece duas vezes: na declaração e no onclick. Se os dois nomes não batem, o componente quebra na hora de desenhar:

Missão: o botão não faz nada porque o onclick aponta para Somar, com maiúscula, e a função se chama somar. Conserte o nome no atributo para o clique contar.

<script>
  let cliques = $state(0);

  function somar() {
    cliques++;
  }
</script>

<button onclick={Somar}>Cliques: {cliques}</button>
<script>
  let cliques = $state(0);

  function somar() {
    cliques++;
  }
</script>

<button onclick={somar}>Cliques: {cliques}</button>

O erro que a caixa mostra ao rodar é Somar is not defined. Repare: o compilador aceitou o arquivo, porque Somar poderia ser uma função global que existe em outro lugar. Quem descobre que não existe é o navegador, na hora de desenhar. Nome de função errado é quase sempre isso: compila, e quebra na tela.

Para listas, use plural na lista e singular no item — a regra que você já viu na caixa do {#each}. Para o que guarda várias informações da mesma coisa, agrupe num objeto com nome no singular: produto = $state({ nome, preco }). Assim produto.nome e produto.preco já dizem de quem são.

10. Quando dá errado

As três mensagens abaixo saíram do compilador desta versão, copiadas como estão. Todas as três são erros de nome, e nenhuma delas é erro de digitação no sentido de “letra trocada”.

Erro 1 — nome que começa com número

Nome de variável não pode começar com algarismo. O compilador lê o número e espera um operador depois dele.

<script>
  let 2nome = $state('Ana');
</script>

<p>{2nome}</p>
Erro de compilação (linha 2, coluna 8): Identifier directly after number

“Identificador logo depois de um número”: o 2 foi lido como número, e o que veio depois não faz sentido. A correção é começar por letra — nome2 ou, melhor, um nome que diga o que é: segundoNome.

Erro 2 — dois nomes iguais no mesmo script

A Ana copiou uma linha para testar outro valor e esqueceu de apagar a antiga. O compilador não escolhe por você.

<script>
  let nome = $state('Ana');
  let nome = $state('Bia');
</script>

<p>{nome}</p>
Erro de compilação (linha 3, coluna 6): Identifier 'nome' has already been declared

“O identificador ‘nome’ já foi declarado”. A linha apontada é a segunda — a primeira declaração é a que vale. Aqui o erro está na coluna 6, exatamente onde o nome repetido começa.

Erro 3 — nome que a tela usa e o script não declara

Este compila: o compilador supõe que contadorr venha de fora. O erro aparece na hora de desenhar.

<script>
  let contador = $state(0);
</script>

<button onclick={() => contador++}>Cliques: {contador}</button>
<p>{contadorr}</p>
contadorr is not defined

Uma letra a mais no segundo contador, e o componente inteiro para de desenhar — inclusive o botão, que estava certo. Quando a tela fica em branco sem erro de compilação, a primeira suspeita é nome que não existe. Volte ao <script> e confira letra por letra.

Resumo

  • O nome é lido pelo compilador, não só por você: ele liga valor e tela.
  • Maiúscula no começo = componente; minúscula = variável, função ou tag do HTML.
  • Arquivo de componente em PascalCase: CartaoDePreco.svelte, sem hífen e sem acento.
  • Variáveis, funções e propriedades em camelCase: precoUnitario, calcularTroco.
  • Booleano se lê como pergunta: temTroco, ehMaior, podePagar.
  • Lista no plural, item no singular: produtos / produto.
  • Nomes que já têm dono (class, onclick) entram renomeados: let { class: classe } = $props().
  • snake_case compila, mas mistura de estilos custa leitura; o projeto escolhe um padrão.
  • O aviso component_name_lowercase não impede o build e deixa a tela vazia — é o mais perigoso dos avisos.
  • Nome repetido e nome começando com número param na compilação; nome inexistente quebra na tela com … is not defined.
