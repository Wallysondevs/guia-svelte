Svelte · onMount

A Ana quer pendurar uma faixa na vitrine da padaria, mas antes precisa saber a largura exata do vidro. Ela não mede a parede antes da vitrine existir: espera a obra terminar e só então passa a trena. Com componente é igual. O código escrito no topo do arquivo roda antes de existir tela, e é por isso que ler a largura da janela ali dá errado. Esta aula ensina o momento certo: onMount, a função que roda uma vez, depois que o componente já está no navegador.

Você vai aprender

  • Como importar e usar onMount, com o código completo da Ana e a saída real.
  • Por que a mesma tela mostra 0 no servidor e o valor de verdade no navegador.
  • A ordem exata em que o componente nasce, do primeiro cálculo do script até o onMount.
  • Como medir um elemento da tela com bind:this dentro do onMount.
  • A diferença entre rodar uma vez (onMount) e rodar sempre ($effect).
  • O que a função devolvida pelo onMount faz — e por que ela é o assunto da próxima aula.
  • Os três erros reais desta aula, com a mensagem que o compilador mostra.
  • Como conferir tudo isso no projeto da Ana, com npm run dev e npm run build.

1. A ideia: só dá para medir o que já está na parede

Na padaria da Ana, a vitrine é de vidro e tem uma moldura de madeira. Para encomendar a faixa de pano, ela precisa da largura interna em centímetros. Se ela medir a parede antes do vidraceiro instalar a vitrine, vai medir o vazio: o número não serve para nada. O trabalho tem uma ordem, e medir vem depois de instalar.

Um componente Svelte tem a mesma ordem, e essa é a única ideia desta aula. O arquivo tem um bloco <script> com as variáveis, um HTML que mostra essas variáveis e, quando o navegador monta o componente, um elemento de verdade aparece na tela. Só que o script roda primeiro. Quando a primeira linha do script executa, não existe nenhum elemento na tela, não existe document, não existe window: existe apenas o texto que o compilador gerou. É por isso que perguntar a largura da janela ali devolve erro, e não um número.

A solução é uma função chamada onMount — "na montagem", em inglês. Você entrega a ela um pedaço de código, e o Svelte se compromete a chamar esse código uma vez, depois que o componente está montado no navegador, com o HTML já na tela. É a trena entregue depois da obra pronta.

Três palavras aparecem o tempo todo quando o assunto é esse. Montagem é o momento em que o Svelte cria os elementos no navegador e liga os valores do estado a eles. DOM é o nome técnico do que o navegador tem na memória: a árvore de elementos da página, com altura, largura e posição. E renderização no servidor (SSR, de server-side rendering) é quando o mesmo componente é transformado em HTML por um programa rodando fora do navegador — num servidor, sem janela, sem tela e sem window.

Na padariaNo componente
Medir a parede antes de instalar a vitrineLer window.innerWidth no topo do <script>
Esperar a vitrine estar instaladaEsperar a montagem do componente
Passar a trena depois da obraChamar onMount com a sua função
Anotar a medida no cadernoGuardar o valor numa variável $state
A faixa é cortada com a medida do cadernoA tela mostra o valor atualizado sozinha

Repare que o onMount não cria a tela: ele espera a tela. Quem cria a tela é o Svelte, a partir do HTML do arquivo. O papel do onMount é dizer "quando você terminar de montar, faça isto aqui". Essa distinção parece pequena e é a origem de quase todo erro de quem está começando: a pessoa lê a documentação, copia o onMount e esquece de guardar o resultado numa variável de estado, então o valor é lido e nunca aparece.

2. O primeiro onMount da Ana

O componente abaixo faz uma coisa só: pergunta ao navegador a largura da janela e mostra o número. Ele é o exemplo mínimo de leitura do navegador, e vai servir de base para o resto da aula.

<script>
  import { onMount } from 'svelte';

  let largura = $state(0);

  onMount(() => {
    largura = window.innerWidth;
  });
</script>

<p>A vitrine tem {largura} pixels de largura.</p>

Se você mandar esse arquivo para o renderizador, ele devolve um texto que decepciona:

A vitrine tem 0 pixels de largura.

Zero. E o zero não é um bug: é a resposta honesta de um programa que rodou fora do navegador. Quem transformou o componente em HTML foi o Node, um programa de terminal que não tem janela, não tem tela e não tem window. Nesse ambiente o onMount não é chamado — ele é uma promessa para o navegador, e o Node não é o navegador. O HTML entregue tem o valor inicial, 0. Quando o navegador recebe esse HTML e monta o componente, a função passa a valer e o número na tela vira a largura real.

É por isso que o valor inicial importa tanto. Ele é o que aparece no primeiro instante, antes de qualquer leitura do navegador, e é o que aparece para quem recebe a página sem JavaScript (ou com a rede lenta). Escolher 0 para uma largura é razoável; escolher '' para a hora da Ana também, desde que a tela saiba mostrar um traço em vez de um espaço vazio.

A anatomia do onMount

import { onMount } from 'svelte'
o onMount não é uma palavra da linguagem: é uma função que vem da biblioteca svelte. Sem essa linha, o nome não existe no arquivo e o componente quebra ao ser executado.
let largura = $state(0)
o estado que vai guardar a medida. O zero é o valor de partida, o que a tela mostra antes de o navegador responder. $state é o que permite a tela acompanhar quando o valor mudar.
onMount(() => { … })
registra a função para ser chamada uma vez, depois da montagem. O => é a seta que separa "o que entra" (nada, por isso os parênteses vazios) de "o que acontece".
largura = window.innerWidth
a leitura do navegador. window.innerWidth é a largura da janela em pixels. Aqui é o único lugar do arquivo em que window pode ser tocado com segurança.
<p>A vitrine tem {largura}…
o HTML que mostra o estado. Quando largura muda dentro do onMount, este parágrafo é redesenhado sem ninguém escrever document.querySelector.

A ordem das linhas também ensina. O import vem primeiro porque é uma declaração de dependência; o estado vem depois, porque o onMount vai usá-lo; e o registro do onMount vem por último, quando todas as peças que ele usa já existem. Se você inverter e chamar onMount antes de declarar largura, o JavaScript reclama de variável usada antes de existir.

O nome do arquivo não muda nada

Chamar o arquivo de Vitrine.svelte, App.svelte ou Medida.svelte não interfere no onMount. O que importa é que o componente comece com letra maiúscula, para o compilador saber que é um componente seu e não uma tag do HTML.

3. Por que o servidor não vê a vitrine

Quando a Ana abre http://localhost:5173/, acontecem duas coisas em lugares diferentes. Primeiro, um programa no seu computador — o servidor de desenvolvimento — transforma o componente em HTML. Depois, o navegador recebe esse HTML, desenha a página e só então executa o JavaScript que monta o componente de verdade, liga os cliques e chama o onMount.

Essa divisão em duas etapas é o que faz o Svelte ser rápido na primeira visita: o visitante vê o conteúdo antes de o JavaScript terminar de carregar. O preço é que o código do componente precisa sobreviver a dois ambientes diferentes. Um deles tem window, document e localStorage; o outro não tem nada disso. O onMount é a fronteira entre os dois: tudo o que só existe no navegador vai para dentro dele.

O terminal da Ana mostra o servidor no ar, pronto para responder:

> loja@0.0.1 dev
> vite

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose

A linha ready in 579 ms é o tempo que o Vite levou para preparar tudo. Local é o endereço que só existe dentro da sua máquina; nada foi publicado na internet. Enquanto esse comando estiver rodando, cada arquivo salvo é recompilado e o navegador recarrega sozinho.

Para ver a diferença entre as duas etapas com os próprios olhos, abra a página e use "Exibir código-fonte" (não o inspetor de elementos). No fonte, o parágrafo vem com o texto que o servidor gerou. No inspetor, o mesmo parágrafo já mostra o número que o onMount escreveu. É o mesmo componente, em dois momentos.

4. A ordem em que o componente nasce

Vale decorar esta ordem, porque ela explica todos os erros desta aula. São cinco etapas, sempre nesta sequência, e cada uma tem um conjunto diferente de coisas disponíveis.

EtapaO que já existeO que ainda não existe
1. O import e as declarações do scriptas funções importadas, os valores iniciaisnenhum elemento, nenhum document
2. O cálculo do HTML (no servidor ou no navegador)o estado com os valores iniciaiso onMount ainda não rodou
3. A montagem no navegadoros elementos no DOM, com altura e posiçãoas medidas do onMount
4. O onMounttudo: window, document, o elemento do bind:thisnada que importe
5. As atualizações seguintesos efeitos e os valores derivados, a cada mudança—

O item 2 é o que surpreende. O HTML é calculado com os valores iniciais, e o onMount ainda não rodou porque ele pertence à etapa 4. Isso significa que a primeira pintura da tela é sempre "sem navegador". Se o valor inicial for feio (um zero solto, um traço, um "carregando"), ele vai aparecer por um instante. Vale escolher esse valor com carinho, e não deixá-lo como sobra.

O item 3 é onde o bind:this se encaixa: é o Svelte quem entrega, para a sua variável, a referência do elemento de verdade. Só depois disso offsetHeight, focus() e scrollIntoView() passam a fazer sentido.

5. Experimente: ler o navegador e mostrar na tela

A caixa abaixo compila e roda de verdade no seu navegador — é o compilador do Svelte, não uma imitação. O componente começa mostrando um traço no lugar do tema, porque ninguém foi ao navegador perguntar qual é. Sua missão é fazer essa pergunta na hora certa.

Missão: o parágrafo mostra Tema: —. Pergunte ao navegador, dentro do onMount, se ele prefere tema claro ou escuro, e mostre a resposta.

<script>
  let tema = $state('—');
</script>

<p>Tema: {tema}</p>
<script>
  import { onMount } from 'svelte';

  let tema = $state('—');

  onMount(() => {
    const prefereEscuro = window.matchMedia('(prefers-color-scheme: dark)').matches;
    tema = prefereEscuro ? 'escuro' : 'claro';
  });
</script>

<p>Tema: {tema}</p>

A pergunta é feita com window.matchMedia, que consulta uma preferência do sistema operacional. Repare nas duas peças: a leitura mora dentro do onMount e o resultado entra numa variável $state. Uma peça sem a outra não resolve — a leitura fora do onMount quebra no servidor, e o valor sem $state não avisa a tela quando muda depois.

Esse segundo problema não gera mensagem nenhuma. O componente compila, roda, e mostra o valor antigo em silêncio. É o tipo de falha em que a única defesa é o hábito: todo valor que aparece na tela e pode mudar nasce com $state.

Um detalhe real que confunde na hora de testar

Se você guardar o valor numa variável comum e atribuir dentro do onMount, o número novo pode até aparecer na primeira pintura, porque a montagem termina antes de o texto do parágrafo ser desenhado. Isso é sorte da ordem interna, não contrato: na mudança seguinte a tela não acompanha. Confiar nesse acaso é o caminho mais curto para um bug que só aparece em produção.

6. Medir um elemento com bind:this

Ler a janela é fácil. O problema de verdade da Ana é outro: ela quer pendurar a faixa na placa de preços, e a placa tem uma altura que depende do texto e da fonte. Para medir aquele elemento, você precisa de uma referência a ele. No Svelte, isso é o bind:this.

<script>
  import { onMount } from 'svelte';

  let placa;
  let altura = $state(0);

  onMount(() => {
    altura = placa.offsetHeight;
  });
</script>

<div bind:this={placa} class="placa">PÃO FRANCÊS — R$ 0,90</div>
<p>Altura medida: {altura} pixels</p>
<div class="placa">PÃO FRANCÊS — R$ 0,90</div> <p>Altura medida: 0 pixels</p>

De novo o zero, e de novo com razão: no servidor não há elemento para medir, então placa continua vazia e o onMount nem é chamado. No navegador, o bind:this preenche placa com o elemento real antes do onMount rodar, e aí offsetHeight devolve um número em pixels.

A anatomia da referência

let placa;
uma variável sem $state, de propósito: ela guarda um elemento, não um valor que muda. Quem vai redesenhar a tela é altura, não ela.
bind:this={placa}
a diretiva que diz "guarde nesta variável o elemento de verdade deste <div>". Ela é preenchida pelo Svelte no momento da montagem.
placa.offsetHeight
a altura do elemento em pixels, já contando o espaço interno. Existem offsetWidth, clientHeight e getBoundingClientRect() para outras medidas.
altura = $state(0)
o valor que a tela lê. Estado de verdade, porque ele muda depois da montagem e o parágrafo precisa acompanhar.

Existe uma alternativa a bind:this: procurar o elemento com document.querySelector('.placa'). Funciona, e é o que você faria em JavaScript puro. O custo é que o seletor vira uma combinação frágil de texto: mudar a classe no HTML quebra o código do script, e dois componentes com a mesma classe passam a brigar pelo mesmo elemento. O bind:this não tem esse problema, porque a referência é daquele elemento e de mais nenhum.

8. Rodar uma vez, rodar sempre: onMount e $effect

O onMount roda uma vez e acabou. Se você quiser reagir a cada mudança de um valor, o instrumento é outro: o $effect, que o guia apresenta em detalhe em outra aula. A diferença prática é simples de sentir: o onMount é a trena passada uma vez; o $effect é o funcionário que mede de novo toda vez que a vitrine muda de lugar.

<script>
  import { onMount } from 'svelte';

  let cliques = $state(0);

  onMount(() => {
    console.log('montei uma vez');
  });

  $effect(() => {
    console.log('cliques agora vale', cliques);
  });
</script>

<button onclick={() => cliques++}>cliques: {cliques}</button>
InstrumentoQuando rodaPara que serve
onMount(fn)uma vez, depois da montagem, só no navegadorler o navegador, medir, iniciar um timer, buscar dados
$effect(fn)uma vez na montagem e de novo a cada valor que ele lê mudaracompanhar mudanças e sincronizar algo de fora
$derived(…)quando um valor que ele usa mudacalcular um valor a partir de outros, sem efeito colateral
onDestroy(fn)uma vez, quando o componente sai da teladesligar o que o onMount ligou

Uma pegadinha de leitura: o $effect também não roda no servidor. Os dois são código de navegador. A diferença é que o $effect conhece as suas dependências e se repete, enquanto o onMount não conhece nada e roda uma vez. Se o seu problema é "ao abrir, faça isso", use onMount. Se é "sempre que este valor mudar, faça aquilo", use $effect.

10. A função que o onMount devolve

Existe uma última peça no onMount, e ela é o assunto da próxima aula. Se a função que você entrega ao onMount devolver outra função, o Svelte guarda essa segunda função e a chama quando o componente sai da tela. É o lugar de desligar o que você ligou.

<script>
  import { onMount } from 'svelte';

  let segundos = $state(0);

  onMount(() => {
    const id = setInterval(() => {
      segundos++;
    }, 1000);

    return () => {
      clearInterval(id);
    };
  });
</script>

<p>Na padaria há {segundos} segundos.</p>
<p>Na padaria há 0 segundos.</p>

Sem o return, cada vez que o componente aparecesse e desaparecesse um setInterval novo ficaria rodando para sempre — eventualmente dezenas deles, todos escrevendo na mesma variável. O custo de esquecer a limpeza não aparece no primeiro teste; aparece quando o usuário navega várias vezes e a página começa a ficar lenta.

11. Quando dá errado

As três mensagens abaixo saíram das ferramentas reais deste guia, com o componente quebrado escrito num arquivo e executado. Não são exemplos inventados: é o texto que aparece.

Erro 1 — document no topo do script

O código parece inocente e roda perfeitamente no seu computador de desenvolvimento. No servidor, ele nem chega a desenhar a página.

<script>
  let largura = document.documentElement.clientWidth;
</script>

<p>Largura: {largura}</p>
Erro ao renderizar: document is not defined

A tradução é literal: "document não está definido". Não é erro de Svelte, é o JavaScript avisando que essa variável global não existe naquele ambiente. A correção é mover a leitura para dentro de um onMount, como no componente da seção 2.

Erro 2 — const no estado que o onMount altera

Este é o erro de digitação mais comum da aula: trocar let por const achando que "estado é constante". Estado é justamente o que muda.

<script>
  import { onMount } from 'svelte';

  const largura = $state(0);

  onMount(() => {
    largura = window.innerWidth;
  });
</script>

<p>Largura: {largura}</p>
Erro de compilação (linha 7, coluna 4): Cannot assign to constant

"Cannot assign to constant" quer dizer "não posso atribuir a uma constante". Repare que o compilador aponta a linha 7, a da atribuição dentro do onMount, e não a linha 4, onde está o const. A dica é ler a mensagem ao contrário: o problema está onde você tentou escrever.

Erro 3 — esqueceu o import

Sem a linha de import, o nome onMount não existe. O erro não é de sintaxe: o arquivo compila e só falha na execução.

<script>
  let largura = $state(0);

  onMount(() => {
    largura = window.innerWidth;
  });
</script>

<p>Largura: {largura}</p>
Erro ao renderizar: onMount is not defined

A mensagem "onMount is not defined" e o seu irmão "document is not defined" têm a mesma forma: um nome que o JavaScript não conhece. Quando o erro cita um nome de função do Svelte, a primeira coisa a conferir é a lista de import no topo do script.
