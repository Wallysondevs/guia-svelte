Svelte · Ordenar e Filtrar

A Ana agora tem quarenta produtos no quadro de preços da padaria, e o quadro virou uma parede. Para achar o pão de queijo ela passa o dedo por três fileiras; para saber qual é o produto mais barato do dia, precisa ler todos. Ela quer duas coisas: digitar uma palavra e ver só os produtos com aquela palavra, e escolher se a lista aparece do mais barato para o mais caro ou ao contrário. Esta aula ensina filtrar e ordenar, e como juntar as duas operações.

Você vai aprender
  • O que é filtrar uma lista e o que é ordenar uma lista — são coisas diferentes.
  • Como usar filter para deixar só os produtos que combinam com uma busca.
  • Como usar sort com uma função que compara dois itens.
  • Por que sort embaralha a lista original e como evitar esse estrago.
  • A juntar filtro e ordenação numa única variável $derived.
  • Como ligar um campo de texto ao estado com bind:value.
  • Como ordenar texto com acento usando localeCompare.
  • Como mostrar preço em reais com Intl.NumberFormat.
  • O que fazer quando o filtro não encontra nada.
  • Os três erros reais desta aula, com a mensagem do compilador.

1. A ideia: a lista de compras que se arruma sozinha

Filtrar e ordenar são operações antigas, feitas antes de existir computador. Quando a Ana vai ao mercado com a lista de compras, ela risca o que já colocou no carrinho — isso é filtrar: de todos os itens da lista, interessam só os que faltam comprar. E quando ela organiza a lista pela ordem dos corredores do mercado, para não voltar duas vezes ao mesmo lugar — isso é ordenar: os mesmos itens, em outra sequência.

As duas operações mudam a lista de um jeito diferente. Filtrar tira itens: a lista fica menor, e a ordem dos que sobraram continua a mesma. Ordenar não tira ninguém: a lista fica do mesmo tamanho, em outra sequência. Guarde a distinção: filtro decide quem entra, ordenação decide quem vem primeiro.

No componente, as duas operações são funções de JavaScript que recebem a lista e devolvem uma lista nova. O Svelte não inventa nada aqui: filter e sort são do JavaScript, e a única coisa que o Svelte acrescenta é o aviso de que a lista mudou, para o HTML se desenhar de novo. O trabalho de verdade acontece nas funções que você escreve.

Na padariaNo componente
A lista inteira de quarenta produtosA variável produtos, criada com $state
Riscar o que já foi compradoprodutos.filter(...) — devolve uma lista menor
Reorganizar a lista pelo corredor[...produtos].sort(...) — devolve a mesma lista em outra ordem
Trocar a régua de ordenação: preço, nome, validadeA função de comparação dentro de sort
Anotar o resultado num papel à parteGuardar o resultado em $derived
Reler a lista quando algo mudaO $derived se recalcula sozinho

O vocabulário desta aula: lista é uma sequência de valores entre colchetes; item é um valor dessa sequência; filtrar é escolher itens por uma condição; ordenar é pôr os itens numa sequência decidida por você; e derivado é o valor que se calcula a partir de outro. Quatro palavras que você vai ver em todo código de tela com lista.

2. O ponto de partida: três produtos na tela

Comece com três produtos, para caber na cabeça. Se o {#each} ainda não é familiar, a aula Seu Primeiro Componente mostra o começo dessa história. Cada produto é um objeto — um pacote com três informações: um número de identidade, o nome e o preço. A lista é a sequência desses pacotes, e o {#each} percorre um por um.

<script>
  let produtos = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9 },
    { id: 2, nome: 'Bolo de fubá', preco: 12.5 },
    { id: 3, nome: 'Pão de queijo', preco: 4 }
  ]);
</script>

<ul>
  {#each produtos as p (p.id)}
    <li>{p.nome} — R$ {p.preco}</li>
  {/each}
</ul>

O compilador transforma esse arquivo no HTML abaixo. Note que as chaves desapareceram: cada item virou uma linha de verdade, com o nome e o preço no lugar.

<ul><li>Pão francês — R$ 0.9</li><li>Bolo de fubá — R$ 12.5</li><li>Pão de queijo — R$ 4</li></ul>
let produtos = $state([ ])
a lista guardada como estado: quando ela muda, a tela se redesenha. Os colchetes abrem a lista, e cada { ... } dentro dela é um objeto.
{ id: 1, nome: '…', preco: 0.9 }
um objeto: um pacote com campos separados por vírgula. O id é o número que identifica o produto; serve para o Svelte reconhecer cada linha.
{#each produtos as p (p.id)}
para cada item de produtos, chame esse item de p e desenhe o que está entre as tags. O (p.id) é a chave: a identidade de cada linha.
{p.nome}
o campo nome do item atual. O ponto lê um campo de dentro do objeto: p.preco lê o preço.
{/each}
fecha o bloco repetido. Tudo o que está entre {#each} e {/each} se repete uma vez por item.

Essa é a lista crua, na ordem em que foi escrita. A ordem do arquivo é a ordem da tela: primeiro o pão francês, depois o bolo, depois o pão de queijo. Isso parece óbvio e é justamente o que vai mudar nas próximas seções.

O preço não tem duas casas

O HTML saiu com R$ 0.9 porque o valor guardado é o número 0.9. Guardar número é certo; mostrar é outro assunto, e a seção 8 resolve isso com uma função de formatação.

3. Filtrar: só entra quem combina

Filtrar é entregar à função filter uma condição — uma pergunta que se responde com sim ou não para cada item. O JavaScript pergunta item por item e monta uma lista nova só com os que responderam sim. A lista original fica intacta.

<script>
  let produtos = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9 },
    { id: 2, nome: 'Bolo de fubá', preco: 12.5 },
    { id: 3, nome: 'Pão de queijo', preco: 4 }
  ]);

  let busca = $state('pão');
  let visiveis = $derived(
    produtos.filter((p) => p.nome.toLowerCase().includes(busca.toLowerCase()))
  );
</script>

<p>{visiveis.length} produto(s) encontrado(s)</p>

<ul>
  {#each visiveis as p (p.id)}
    <li>{p.nome}</li>
  {/each}
</ul>

O resultado são dois produtos, porque dois nomes contêm a palavra "pão":

<p>2 produto(s) encontrado(s)</p> <ul><li>Pão francês</li><li>Pão de queijo</li></ul>

Leia a condição em voz alta: p.nome.toLowerCase().includes(busca.toLowerCase()) quer dizer "o nome do produto, em minúsculas, contém a busca, também em minúsculas?". Sem o toLowerCase() dos dois lados, buscar "pão" não acharia "Pão francês": o P e o p são caracteres diferentes para o computador, e é por isso que busca de site não liga para maiúsculas.

Missão: a busca está presa em "bolo" e só o bolo aparece. Faça a lista mostrar o pão francês e o pão de queijo, sem mexer na condição do filtro — só no valor da busca.

<script>
  let produtos = $state(['Pão francês', 'Bolo de fubá', 'Pão de queijo']);
  let busca = $state('bolo');
  let encontrados = $derived(produtos.filter((p) => p.toLowerCase().includes(busca)));
</script>

<p>{encontrados.join(', ')}</p>
<script>
  let produtos = $state(['Pão francês', 'Bolo de fubá', 'Pão de queijo']);
  let busca = $state('pão');
  let encontrados = $derived(produtos.filter((p) => p.toLowerCase().includes(busca)));
</script>

<p>{encontrados.join(', ')}</p>

A caixa mostra um detalhe: encontrados não guarda a lista inteira, guarda o resultado do filtro. Quando busca muda, o $derived recalcula e a tela mostra outra lista, sem você escrever código para limpar a antiga.

4. Ordenar: quem vem primeiro

Ordenar é diferente de filtrar: ninguém sai da lista. O que muda é a sequência. O JavaScript tem uma função para isso, chamada sort, e ela aceita uma função de comparação — uma função que recebe dois itens e responde qual deles vem antes. A resposta é um número: negativo se o primeiro vem antes, positivo se vem depois, zero se tanto faz.

Quando você chama sort() sem função nenhuma, o JavaScript compara os itens como se fossem texto. E aí aparece a pegadinha que trava todo mundo na primeira vez:

<script>
  let precos = $state([12.5, 0.9, 4]);
  let ordenados = $derived([...precos].sort());
</script>

<p>{ordenados.join(' · ')}</p>

Do mais barato para o mais caro, a resposta certa seria 0.9, 4, 12.5. Veja o que sai:

<p>0.9 · 12.5 · 4</p>

O 0.9 veio antes do 12.5 porque o texto "0.9" começa com a letra "0", que vem antes do "1" de "12.5". Comparando texto, "12.5" é menor que "4" pelo mesmo motivo: o primeiro caractere é "1", que vem antes do "4". A função fez exatamente o que prometeu — comparou texto —, e é isso que você não queria.

A correção é dar a ela a régua numérica. A função (a, b) => a - b devolve a diferença entre os dois preços: se a for menor, a diferença é negativa e a vem antes; se for maior, positiva e ele vai para depois. Para inverter a ordem, troque a subtração: b - a.

<script>
  let precos = $state([12.5, 0.9, 4]);
  let ordenados = $derived([...precos].sort((a, b) => a - b));
</script>

<p>{ordenados.join(' · ')}</p>
<p>0.9 · 4 · 12.5</p>
[...precos]
os três pontos copiam a lista para uma lista nova. Sem isso, o sort mexe na lista original — e mexer no estado por baixo do pano é o que causa tela que não atualiza.
.sort(...)
ordena a lista que recebeu e devolve a mesma lista, agora na ordem nova. Não é uma cópia: é a lista de entrada, modificada.
(a, b) =>
a função de comparação: recebe dois itens por vez. O Svelte não chama essa função; quem chama é o sort, quantas vezes precisar.
a - b
a régua: número negativo põe a antes, positivo põe depois, zero mantém. Para texto, use localeCompare, que vem na seção 7.

Missão: a lista sai na ordem do texto ("0.9 · 12.5 · 4"). Faça sair do menor preço para o maior — 0.9 · 4 · 12.5 — mudando só a chamada do sort.

<script>
  let precos = $state([12.5, 0.9, 4]);
  let ordenados = $derived([...precos].sort());
</script>

<p>{ordenados.join(' · ')}</p>
<script>
  let precos = $state([12.5, 0.9, 4]);
  let ordenados = $derived([...precos].sort((a, b) => a - b));
</script>

<p>{ordenados.join(' · ')}</p>
Por que a cópia importa tanto

Se você escrever produtos.sort(...) dentro de um $derived, o sort reordena a própria lista que está no $state. Em modo de desenvolvimento o Svelte avisa que você está alterando estado durante um cálculo; em produção o código roda e a tela pode ficar com a ordem antiga na cabeça. A cópia custa uma lista nova na memória e economiza uma tarde de depuração.

5. As duas coisas juntas, com $derived

Na vida real a Ana quer as duas operações ao mesmo tempo: os produtos que contêm "pão", do mais barato para o mais caro. Isso é uma corrente: o filtro entrega uma lista menor, e o sort recebe essa lista menor. A ordem da corrente importa — filtrar antes de ordenar evita ordenar quarenta itens para mostrar dois.

<script>
  let produtos = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9 },
    { id: 2, nome: 'Bolo de fubá', preco: 12.5 },
    { id: 3, nome: 'Pão de queijo', preco: 4 }
  ]);

  let busca = $state('pão');
  let visiveis = $derived(
    produtos
      .filter((p) => p.nome.toLowerCase().includes(busca.toLowerCase()))
      .sort((a, b) => a.preco - b.preco)
  );
</script>

<ul>
  {#each visiveis as p (p.id)}
    <li>{p.nome} — R$ {p.preco.toFixed(2)}</li>
  {/each}
</ul>

O resultado mostra os dois pães, o mais barato primeiro:

<ul><li>Pão francês — R$ 0.90</li><li>Pão de queijo — R$ 4.00</li></ul>

Repare numa coisa: aqui sort está sendo chamado direto no resultado do filtro, sem colchetes e sem três pontos. Isso é seguro porque o filtro já devolveu uma lista nova, que ninguém mais está usando — não existe estado original para estragar. A cópia só é necessária quando a lista que você ordena é a que está guardada no $state.

let visiveis = $derived(…)
o valor é calculado, não guardado: sempre que produtos ou busca mudam, o Svelte recalcula e a tela acompanha.
produtos
o ponto de partida da corrente: a lista inteira, do jeito que está no estado.
.filter(…)
a primeira peneira: devolve uma lista nova, menor. O que não passar na condição não chega ao próximo passo.
.sort(…)
a segunda peneira não tira ninguém: reordena a lista que o filtro devolveu.
as quebras de linha
um ponto no começo da linha continua a expressão da linha anterior. Serve só para o olho ler a corrente em degraus.

Esse componente já é útil: se a busca mudar, a lista se refaz. Falta o campo onde a Ana digita, e o terminal abaixo mostra o servidor de desenvolvimento da padaria rodando.

6. O campo de busca: bind:value

Até agora a busca estava escrita no código. Para a Ana digitar, o campo de texto precisa estar ligado à variável busca nos dois sentidos: o que ela digita vira o valor da variável e o valor da variável aparece no campo. No Svelte isso é a palavra bind depois de dois pontos.

<script>
  let produtos = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9 },
    { id: 2, nome: 'Bolo de fubá', preco: 12.5 },
    { id: 3, nome: 'Pão de queijo', preco: 4 }
  ]);

  let busca = $state('pão');
  let visiveis = $derived(
    produtos.filter((p) => p.nome.toLowerCase().includes(busca.toLowerCase()))
  );
</script>

<label for="busca">Buscar no balcão</label>
<input id="busca" bind:value={busca} placeholder="pão" />

<p>{visiveis.length} produto(s)</p>

Na primeira renderização o campo já nasce com o valor que estava no estado:

<label for="busca">Buscar no balcão</label> <input id="busca" value="pão" placeholder="pão"/> <p>2 produto(s)</p>

O value="pão" no HTML gerado é a prova de que a ligação existe nos dois sentidos. Sem bind, você escreveria um oninput que lê event.target.value e atribui à variável: mais código para o mesmo resultado.

Existe um custo, e ele vale para toda ligação de duas vias: o valor do campo passa a ser a fonte da verdade. Se você formatar o que a pessoa digita (tirar espaços, trocar vírgula por ponto), precisa fazer isso na leitura, não no valor guardado, senão o cursor pula para o fim a cada letra. Para busca isso raramente incomoda; para dinheiro, incomoda muito.

7. Texto com acento: localeCompare

Ordenar nome de produto com a - b não funciona: subtrair texto dá NaN, que quer dizer "não é número", e a lista fica na ordem em que veio. Para texto existe localeCompare, uma função que sabe as regras do idioma — inclusive onde ficam as letras acentuadas.

<script>
  let nomes = $state(['Bolo de fubá', 'Água de coco', 'Pão francês']);
  let ordenados = $derived([...nomes].sort((a, b) => a.localeCompare(b, 'pt-BR')));
</script>

<ul>
  {#each ordenados as nome}
    <li>{nome}</li>
  {/each}
</ul>

A lista sai em ordem alfabética portuguesa, com "Água" antes de "Bolo":

<ul><li>Água de coco</li><li>Bolo de fubá</li><li>Pão francês</li></ul>

O segundo argumento, 'pt-BR', escolhe as regras do português do Brasil. Sem ele, o navegador usa o idioma do sistema de quem abriu a página, e a mesma lista pode sair em ordem diferente no computador da Ana e no celular da cliente. Para quem programa no Brasil e escreve em português, dizer o idioma é uma linha de código que evita uma reclamação.

Missão: o botão "inverter" muda a variável crescente, mas a lista não muda de ordem. Faça o primeiro clique mostrar Pão, Broa, Bolo — a ordem alfabética de trás para a frente.

<script>
  let nomes = $state(['Pão', 'Bolo', 'Broa']);
  let crescente = $state(true);
  let ordenados = $derived([...nomes].sort((a, b) => a.localeCompare(b, 'pt-BR')));
</script>

<ul>
  {#each ordenados as nome}
    <li>{nome}</li>
  {/each}
</ul>

<button onclick={() => (crescente = !crescente)}>inverter</button>
<script>
  let nomes = $state(['Pão', 'Bolo', 'Broa']);
  let crescente = $state(true);
  let ordenados = $derived(
    [...nomes].sort((a, b) => (crescente ? 1 : -1) * a.localeCompare(b, 'pt-BR'))
  );
</script>

<ul>
  {#each ordenados as nome}
    <li>{nome}</li>
  {/each}
</ul>

<button onclick={() => (crescente = !crescente)}>inverter</button>

A solução multiplica o resultado da comparação por 1 ou por -1. Multiplicar por -1 troca o sinal: o que era negativo vira positivo, e a ordem se inverte inteira. É o mesmo truque do b - a da seção 4, escrito de um jeito que serve tanto para número quanto para texto.

8. Mostrar dinheiro com Intl.NumberFormat

O preço guardado é número; o preço na parede é dinheiro. O JavaScript tem um formatador pronto, que conhece o símbolo do real, a vírgula decimal e o ponto de milhar. Ele se chama Intl.NumberFormat e não precisa de biblioteca nenhuma.

<script>
  let preco = 0.9;
  let reais = new Intl.NumberFormat('pt-BR', {
    style: 'currency',
    currency: 'BRL'
  }).format(preco);
</script>

<p>{reais}</p>
<p>R$ 0,90</p>

Aquele 0,90 com vírgula é o formatador trabalhando: ele sabe que em português a casa decimal se separa por vírgula. O espaço entre R$ e o número também vem dele.

O custo é que a função é verbosa: quatro linhas de configuração para um preço. Com dez lugares mostrando dinheiro, ninguém quer repetir isso dez vezes. A saída é criar o formatador uma vez e guardar a função pronta:

<script>
  let produtos = $state([
    { nome: 'Pão francês', preco: 0.9 },
    { nome: 'Bolo de fubá', preco: 12.5 }
  ]);

  const reais = new Intl.NumberFormat('pt-BR', {
    style: 'currency',
    currency: 'BRL'
  });
</script>

<ul>
  {#each produtos as p}
    <li>{p.nome} — {reais.format(p.preco)}</li>
  {/each}
</ul>

O HTML gerado é o mesmo de antes, porque o resultado é o mesmo — só o custo de criar o formatador caiu de uma vez por item para uma vez por página:

<ul><li>Pão francês — R$ 0,90</li><li>Bolo de fubá — R$ 12,50</li></ul>

Esse padrão — preparar a ferramenta uma vez, usar muitas — volta na aula Evitando Trabalho Repetido, onde ele aparece com um contador de chamadas na tela para você ver a diferença com os próprios olhos.

9. Quando o filtro não acha nada

Uma lista vazia é o caso mais comum de todos e o mais esquecido. A Ana digita "torta", não existe torta no quadro, e a tela mostra… nada. Um espaço em branco faz a pessoa achar que o site quebrou. O componente precisa dizer, com palavras, que a busca não encontrou nada.

<script>
  let produtos = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9 },
    { id: 2, nome: 'Bolo de fubá', preco: 12.5 }
  ]);

  let busca = $state('torta');
  let visiveis = $derived(
    produtos.filter((p) => p.nome.toLowerCase().includes(busca.toLowerCase()))
  );
</script>

{#if visiveis.length === 0}
  <p>Nenhum produto com "{busca}".</p>
{:else}
  <ul>
    {#each visiveis as p (p.id)}
      <li>{p.nome}</li>
    {/each}
  </ul>
{/if}
<p>Nenhum produto com "torta".</p>

O {#if} olha o tamanho da lista: zero é falso, qualquer outro número é verdadeiro. Repare que a mensagem cita a busca — "{busca}" — para a pessoa ver o que ela digitou e corrigir o erro de digitação. Uma mensagem genérica ("nenhum resultado") obriga a pessoa a reler o campo; uma mensagem com o termo mostra o problema na hora.

O mesmo cuidado vale para a lista que ainda está carregando: "carregando" e "nenhum resultado" são situações diferentes, e mostrar a segunda enquanto os dados vêm da rede faz a pessoa desistir de um produto que existe.

10. Quando dá errado

As três mensagens abaixo saíram do compilador e do renderizador desta versão, copiadas como estão. Cada uma representa um erro que aparece na primeira semana de quem começa a mexer com listas.

Erro 1 — parêntese que não fecha

A condição do filtro tem muitos parênteses: os da função, os da comparação, os da chamada. Faltando um, o compilador não consegue ler a expressão e aponta o último pedaço que entendeu.

<script>
  let produtos = $state([{ nome: 'Pão', preco: 0.9 }]);
</script>

<p>{produtos.filter((p) => p.preco > 0}</p>
Erro de compilação (linha 5, coluna 38): Unexpected token

"Unexpected token" quer dizer "achei um pedaço de código que não encaixa aqui". A posição apontada é o fim da linha, não o parêntese que falta — por isso a dica é contar os pares: cada ( aberto precisa de um ) fechado, na mesma ordem.

Erro 2 — runa sem parênteses

Quem vem de outro framework tenta tratar $derived como uma palavra que se usa com sinal de igual. A runa é uma chamada de função: abre parêntese, recebe a expressão, fecha parêntese.

<script>
  let produtos = $state(['Pão']);
  let visiveis = $derived = produtos;
</script>

<p>{visiveis.length}</p>
Erro de compilação (linha 3, coluna 17): Cannot use rune without parentheses

A mensagem é direta: a runa precisa de parênteses. O certo é let visiveis = $derived(produtos). Repare que o = continua ali, mas ele é a atribuição normal de uma variável — o que vai entre parênteses é o que a runa calcula.

Erro 3 — filtrar o que não é lista

Este compila: o erro só aparece na hora de desenhar a tela. Se produtos é um objeto com um produto só, ele não tem a função filter, e o navegador avisa.

<script>
  let produtos = $state({ nome: 'Pão' });
</script>

<p>{produtos.filter((p) => p.preco > 0).length}</p>
Erro ao renderizar: produtos.filter is not a function

let busca = $state('pão');

  produtos.((p) => p.nome.includes(busca))

// só os produtos cujo nome contém a busca entram na lista

Resumo

  • Filtrar escolhe quem entra na lista; ordenar decide quem vem primeiro. São operações independentes.
  • lista.filter((p) => condição) devolve uma lista nova, menor, sem tocar na original.
  • lista.sort((a, b) => a - b) ordena número; sem a régua, o JavaScript compara como texto e a ordem sai errada.
  • sort altera a lista de entrada. Copie antes com [...lista] ou use toSorted.
  • $derived recalcula a lista sozinho quando o estado de que ela depende muda.
  • Corrente de operações: filtrar primeiro e ordenar depois evita trabalho à toa.
  • bind:value liga o campo de texto ao estado nos dois sentidos.
  • a.localeCompare(b, 'pt-BR') ordena texto com acento nas regras do português.
  • Intl.NumberFormat formata dinheiro; crie o formatador uma vez e reuse.
  • Lista vazia merece uma mensagem com o termo buscado, para a pessoa entender o que aconteceu.
  • A saída desta aula é a do compilador de verdade: mesmo código, mesmo HTML.
