SvelteKit · Parâmetros de Rota

A Ana tem doze pães no balcão e quer uma página para cada um: /paes/frances, /paes/queijo, /paes/forma. Copiar a pasta doze vezes funcionaria, e ela quase fez isso. O sobrinho dela mostrou uma pasta com um nome estranho, [slug], entre colchetes: um arquivo só, que responde por todos os pães, e uma variável que chega pronta com o pedaço do endereço que a pessoa escolheu. Nesta aula você vê esse arquivo funcionando, com o servidor devolvendo queijo quando alguém pede /paes/queijo.

Você vai aprender
  • O que os colchetes no nome da pasta fazem.
  • Como ler o valor capturado com page.params de $app/state.
  • Por que um único arquivo atende muitos endereços (e o que isso economiza).
  • Como montar o endereço de destino a partir do valor digitado.
  • Dois parâmetros no mesmo caminho, e a ordem em que eles aparecem.
  • O parâmetro que engole o resto do caminho: [...resto].
  • Por que todo parâmetro chega como texto, nunca como número.
  • Achar o item da lista a partir do slug com find.
  • Buscar antes de desenhar com +page.js e load({ params }).
  • Os três erros reais desta aula: parâmetro vazio, rota em conflito e 404 por caminho comprido.

1. A ideia: a ficha em branco

No balcão da Ana existe um caderno de encomendas com uma página em branco por cliente. Se ela fizer uma página por cliente, o caderno vira uma pilha. Se fizer uma página com um espaço em branco no topo — "Pedido de ______" — e preencher o nome na hora, o mesmo papel serve para qualquer pessoa. O espaço em branco é o que o SvelteKit chama de parâmetro: uma parte do endereço que não é fixa, e cujo valor o servidor entrega ao componente.

A diferença entre uma rota fixa e uma rota com parâmetro não está no conteúdo do arquivo, está no nome da pasta. A pasta sobre só atende /sobre. A pasta [slug] atende qualquer coisa naquela posição: /paes/frances, /paes/queijo, /paes/bolo-de-fubá. Os colchetes são a instrução "aqui entra um valor, e eu quero saber qual foi".

O nome entre colchetes é seu, não do SvelteKit. Você poderia escrever [nome], [pao], [id] — o que estiver entre colchetes vira uma chave no objeto de parâmetros. A convenção do mundo SvelteKit é [slug] para pedaços de texto amigáveis na URL, e [id] para números de identificação. Escolher um nome claro é meio caminho para o código ficar legível.

A analogia tem um limite que vale dizer: no papel, o espaço em branco está no texto; no SvelteKit, ele está no nome da pasta. Isso significa que a captura acontece antes de qualquer código seu rodar. Quando o componente é montado, o valor já está pronto — você não precisa procurar na URL nem separar texto por barra.

3. A pasta com colchetes

Este é o arquivo da Ana. Ele mora em src/routes/paes/[slug]/+page.svelte, e um único arquivo atende todos os pães do balcão:

<script>
	import { page } from '$app/state';
</script>

<h1>{page.params.slug}</h1>
<p>Você pediu o pão {page.params.slug}.</p>
<a href="/paes">voltar</a>
[slug]
o nome da pasta com colchetes. É a marca de "aqui entra um valor". O nome slug é a chave que você vai usar para ler.
$app/state
um módulo que o SvelteKit fornece pronto. Não é um arquivo do projeto: o import é resolvido pela ferramenta.
import { page }
o objeto reativo que descreve a página atual: endereço, parâmetros, status, erro.
page.params
o objeto com os valores capturados. Para /paes/queijo, é { slug: 'queijo' }.
page.params.slug
o valor daquela chave. Se a rota não tiver [slug], é undefined — e a tela mostra vazio.

Repare no que não aparece: nenhuma função para separar a URL, nenhum window.location, nenhuma promessa. O SvelteKit já fez esse trabalho antes de chamar o componente, e o mesmo valor serve no servidor (para montar o HTML) e no navegador (para continuar a partir dele). É por isso que a página funciona com JavaScript desligado: o valor não depende do navegador.

4. Um arquivo, muitos endereços

Para conferir, o jeito é pedir dois endereços diferentes ao servidor e ver o mesmo arquivo responder com valores distintos. A Ana usou o curl na versão de produção, na porta 4173:

ana@notebook:~/loja/kit$ curl -s localhost:4173/paes/queijo | grep -o '<h1>.*</h1>'
<h1>queijo</h1>
ana@notebook:~/loja/kit$ curl -s localhost:4173/paes/forma | grep -o '<h1>.*</h1>'
<h1>forma</h1>

Um arquivo, dois resultados. O grep recorta só o título porque o HTML completo passa de 3.900 caracteres. Se você olhasse o código do componente, veria {page.params.slug} nos dois casos — o que muda é o valor que o roteador colocou ali. Essa é a economia: doze pães, um arquivo, zero cópias para manter.

O ganho cresce quando o conteúdo muda. Se amanhã a Ana quiser mostrar o preço embaixo do nome, ela edita um arquivo e os doze endereços mudam juntos. Com doze pastas, seriam doze edições e a certeza de esquecer uma.

Missão: o campo existe, mas digitar não muda nada. Faça o parágrafo montar o endereço com o que foi digitado: ao escrever queijo, a tela deve mostrar link: /paes/queijo.

<script>
  let slug = $state('');
</script>

<input placeholder="qual pão?" />
<p>link: /paes/{slug}</p>
<script>
  let slug = $state('');
</script>

<input placeholder="qual pão?" oninput={(e) => (slug = e.currentTarget.value)} />
<p>link: /paes/{slug}</p>

O oninput dispara a cada tecla. O e.currentTarget é o elemento que recebeu o evento — o próprio campo —, e .value é o texto dentro dele. Sem o oninput, o Svelte desenha o campo uma vez e nunca mais olha para ele: o estado slug continua vazio e a tela mostra link: /paes/. No SvelteKit, esse endereço seria o href de um link: href="/paes/{slug}".

5. Dois parâmetros no mesmo caminho

Nada impede duas pastas com colchetes, uma dentro da outra. A Ana criou src/routes/paes/[slug]/[tamanho]/+page.svelte para vender pão grande e pequeno. O endereço passa a ter dois pedaços variáveis, e o objeto de parâmetros ganha duas chaves.

<script>
	import { page } from '$app/state';
</script>

<h1>{page.params.slug} — {page.params.tamanho}</h1>
<p>params: {JSON.stringify(page.params)}</p>

O JSON.stringify aparece aqui só para você ver o objeto inteiro, do jeito que ele chega. No site da Ana ele não ficaria; em página de verdade, você lê as chaves que precisa. O servidor respondeu assim:

ana@notebook:~/loja/kit$ curl -s localhost:4173/paes/queijo/grande | grep -o '<h1>.*</p>'
<h1>queijo — grande</h1> <p>params: {"slug":"queijo","tamanho":"grande"}</p>

Leia o objeto com atenção: as chaves são os nomes que estavam entre colchetes, e os valores vieram na ordem em que os pedaços apareceram na URL. O SvelteKit casa pedaço por pedaço, da esquerda para a direita. Se a URL tivesse um pedaço a mais, não haveria rota para ela:

ana@notebook:~/loja/kit$ curl -s -o /dev/null -w '%{http_code}\n' localhost:4173/paes/queijo/grande/mais
404

Isso é o comportamento certo: a rota declara exatamente dois pedaços variáveis depois de paes. Um terceiro pedaço não é "quase igual", é outro endereço. O roteador não tenta adivinhar.

6. O parâmetro que engole o resto: [...resto]

Existe uma variação com três pontos dentro dos colchetes. Em vez de capturar um pedaço do caminho, ela captura todos os que sobrarem, inclusive as barras. A Ana usou isso para uma página de busca interna, onde o caminho depois de /loja pode ter qualquer tamanho:

<script>
	import { page } from '$app/state';
</script>

<h1>resto: {page.params.resto}</h1>
ana@notebook:~/loja/kit$ curl -s localhost:4173/loja/paes/do-dia/3 | grep -o '<h1>.*</h1>'
<h1>resto: paes/do-dia/3</h1>
ana@notebook:~/loja/kit$ curl -s -o /dev/null -w '%{http_code}\n' localhost:4173/loja
200

Duas coisas para guardar. Primeiro: o valor vem com as barras dentro, paes/do-dia/3, porque a rota engoliu três pedaços de uma vez. Segundo: /loja sozinho também responde 200, com valor vazio — o spread aceita zero pedaços. É a diferença entre "opcional" e "obrigatório": [slug] exige um pedaço, [...resto] aceita nenhum.

7. Todo parâmetro chega como texto

Esta é a armadilha número um de quem começa. Mesmo que a URL pareça um número, o valor chega como texto. Em /loja/3, o parâmetro é a string "3", não o número 3. Some "3" + 1 e você ganha "31", não 4. A regra é converter na entrada do dado, com Number(...), e conferir se o resultado é um número de verdade.

Há um motivo bom para o SvelteKit entregar texto: a URL não é digitada só por humanos. Robôs de busca, links antigos e planilhas colam qualquer coisa ali. Se o roteador convertesse automaticamente, /loja/abc viraria erro em vez de página; entregando texto, o seu código decide o que fazer com o valor estranho — buscar, converter ou responder 404 com uma mensagem clara.

Missão: o parâmetro slug vale queijo, mas o componente mostra sempre o primeiro pão da lista. Faça o item ser escolhido pelo slug.

<script>
  let paes = [
    { slug: 'frances', nome: 'Pão francês' },
    { slug: 'queijo', nome: 'Pão de queijo' }
  ];
  let slug = $state('queijo');
  let escolhido = paes[0];
</script>

<h1>{escolhido.nome}</h1>
<p>pedido: {slug}</p>
<script>
  let paes = [
    { slug: 'frances', nome: 'Pão francês' },
    { slug: 'queijo', nome: 'Pão de queijo' }
  ];
  let slug = $state('queijo');
  let escolhido = paes.find((p) => p.slug === slug);
</script>

<h1>{escolhido.nome}</h1>
<p>pedido: {slug}</p>

find percorre a lista e devolve o primeiro item em que a função devolve true. Aqui, o item cujo slug é igual ao slug pedido. Se nenhum casar, o resultado é undefined — e aí escolhido.nome derruba o componente. Guarde essa frase: no site de verdade, o caso "não achei" não pode ser esquecido; ele vira error(404, …), como você vê na seção 9.

8. Buscar antes de desenhar: +page.js com load

Ler page.params dentro do componente funciona, mas tem um limite: o componente já está sendo desenhado quando você descobre que o pão não existe. Aí é tarde para responder 404 — o navegador já recebeu 200. O lugar certo para essa decisão é o load, uma função que roda antes do componente:

import { error } from '@sveltejs/kit';

export function load({ params }) {
	if (params.slug === 'queijo') {
		error(404, 'O pão de queijo acabou');
	}
	return { slug: params.slug };
}

A função recebe um objeto com params (o mesmo que você leu no componente, só que antes do desenho) e devolve um objeto. Esse objeto chega ao componente como prop data. O error(...) interrompe tudo: o SvelteKit para de montar a página, responde com o status pedido e mostra a página de erro — que no projeto da Ana é o src/routes/+error.svelte. O terminal prova as duas metades:

ana@notebook:~/loja/kit$ curl -s localhost:4173/paes/queijo | grep -o '<h1>.*</a>'
<h1>404</h1> <p>O pão de queijo acabou</p> <a href="/">voltar para o início</a>
ana@notebook:~/loja/kit$ curl -s localhost:4173/paes/forma | grep -o '<h1>.*</a>'
<h1>forma</h1> <p>Você pediu o pão forma.</p> <a href="/paes">voltar</a>

O primeiro endereço caiu na página de erro, com o status 404 e a mensagem que a Ana escreveu. O segundo seguiu o caminho normal e desenhou a página do pão. A mensagem do error é para humanos: ela aparece na tela e não deve conter detalhe interno, senha ou nome de tabela.

9. Quando dá errado

As três mensagens a seguir saíram do projeto da Ana. Duas são mensagens de verdade do roteador e do compilador; a terceira é a ausência de mensagem, que é o caso mais traiçoeiro.

Erro 1 — ler um parâmetro que a rota não tem

A Ana copiou o componente do pão para a página /sobre e esqueceu de tirar o page.params.slug. A rota sobre não tem colchetes, então não existe chave nenhuma. O componente compila, a página responde 200 e a tela mostra um buraco:

ana@notebook:~/loja/kit$ curl -s localhost:4173/sobre | grep -o '<h1>.*</h1>'
<h1>slug: </h1>

Não há erro no terminal, porque tecnicamente não houve erro: page.params.slug é undefined, e o Svelte desenha undefined como nada. Quando um valor aparece vazio na tela, a primeira pergunta é "esta rota tem essa chave?". Confira o nome da pasta antes de procurar o problema no JavaScript.

Erro 2 — maiúscula e minúscula criam rotas diferentes

Para deixar o nome bonito, a Ana criou [Slug] com S maiúsculo. O SvelteKit respeita a diferença: [Slug] e [slug] são nomes distintos, e as duas pastas casam com o mesmo endereço. O build para com conflito de rota:

ana@notebook:~/loja/kit$ npm run build

> kit@0.0.1 build
> vite build

error during build:
SvelteKit error: route_conflict
The `/paes/[Slug]` and `/paes/[slug]` routes conflict with each other
https://svelte.dev/e/kit/route_conflict

O conserto é apagar uma das duas pastas e manter o nome em minúsculas, que é a convenção: endereços são minúsculos, e o parâmetro também. O erro só aparece no build porque é ali que o SvelteKit monta o mapa completo de rotas — no servidor de desenvolvimento, o aviso vem no terminal e a página passa a responder 500.

Erro 3 — um pedaço a mais no caminho

O link de um cliente tinha uma barra sobrando no fim: /paes/queijo/grande/. A rota declara dois parâmetros; o caminho trazia um terceiro pedaço vazio. O servidor respondeu 404, e o motivo não estava em nenhum arquivo do projeto:

ana@notebook:~/loja/kit$ curl -s -o /dev/null -w '%{http_code}\n' localhost:4173/paes/queijo/grande/mais
404

Antes de mexer no componente, conte os pedaços do endereço e compare com a profundidade das pastas. Rota com dois colchetes atende exatamente dois pedaços extras; nem um a mais, nem um a menos. Se você precisa de "qualquer coisa depois daqui", o caminho é o [...resto].

10. O que o load recebe, além de params

Vale conhecer o formato do objeto que chega ao load, porque você vai usá-lo muito nas próximas aulas. A tabela abaixo lista o que interessa agora; o resto é assunto do grupo de aulas sobre dados.

CampoO que éExemplo
paramsos valores capturados pelos colchetes{ slug: 'queijo' }
urlo endereço completo, com a query stringurl.searchParams.get('tam')
fetchuma versão do fetch que o SvelteKit controlaawait fetch('/api/paes')
routeo identificador da rota, com os colchetes{ id: '/paes/[slug]' }

O return do load vira prop data no componente. É por isso que você vai ver, em projetos alheios, um +page.svelte começando com let { data } = $props(). O componente não sabe de onde o dado veio: ele recebe pronto, do mesmo jeito que recebia page.params.

Missão: o objeto de parâmetros chegou vazio e o título ficou em branco. Faça o componente mostrar nenhum pão escolhido quando não houver slug.

<script>
  // no SvelteKit este objeto vem pronto: page.params
  let { params = { slug: '' } } = $props();
</script>

<h1>{params.slug}</h1>
<script>
  // no SvelteKit este objeto vem pronto: page.params
  let { params = { slug: '' } } = $props();
</script>

<h1>{params.slug || 'nenhum pão escolhido'}</h1>

O || funciona porque texto vazio conta como falso em JavaScript. Se params.slug for '', o lado direito entra. Se fosse undefined, também. A diferença em relação ao ?? da aula anterior: ?? só cai no lado direito quando o valor é nulo ou indefinido; || cai também para 0 e ''. Para texto, || é o que você quer; para número, cuidado, porque 0 é um preço válido.

Duas armadilhas de nomenclatura para fechar a referência. A primeira: o nome do parâmetro não pode ter barra nem colchete dentro; [slug-do-pao] vale, [slug/pao] não. A segunda: uma pasta com colchetes não pode conviver com outra que case com o mesmo endereço — foi o erro 2. Se você tem [slug] e quer um caso especial como /paes/promocao, crie a pasta promocao com o +page.svelte dela: rota fixa ganha da variável.

12. O caminho até aqui

O site da Ana agora tem um arquivo que responde por doze endereços. O caderno de encomendas deixou de ser uma pilha de folhas iguais e virou uma ficha com espaço em branco. Ela aprendeu três coisas que valem para o resto do guia: o valor mora no nome da pasta, o valor chega pronto no componente e o valor é texto até você dizer o contrário.

Também aprendeu onde fica a decisão de "esse item não existe": no load, antes do desenho, com error(404, …). Colocar essa decisão dentro do componente é possível, mas a resposta HTTP já foi enviada como 200 — e aí o robô de busca indexa uma página vazia como se fosse conteúdo.

O próximo passo é dar uma moldura comum a todas essas páginas, para o menu não precisar ser copiado em cada uma: +layout.svelte. Se você quiser ver antes como o roteador escolhe entre rotas fixas e variáveis, a aula Rotas por Arquivo tem o mapa completo. E quando o assunto for URL com query string (?tamanho=grande), a diferença em relação ao parâmetro de rota vai aparecer em Navegando com goto.

Resumo

  • Colchetes no nome da pasta viram parâmetro: um pedaço variável da URL.
  • O valor chega pronto em page.params.NOME, importado de $app/state.
  • Um arquivo dentro de [slug] atende todos os endereços daquela posição.
  • Dois colchetes no caminho capturam dois pedaços, com duas chaves no objeto.
  • [...resto] captura todos os pedaços restantes, inclusive as barras, e aceita zero.
  • O parâmetro é sempre texto; converta com Number antes de calcular.
  • Rota sem colchetes não tem chave: page.params.slug é undefined e a tela fica vazia.
  • Nomes com maiúsculas são outros nomes: [Slug] e [slug] conflitam.
  • Um pedaço a mais no caminho não é "quase igual": responde 404.
  • +page.js com load({ params }) decide antes do desenho; error(404, …) responde o status certo.
  • O que o load devolve chega ao componente como prop data.
