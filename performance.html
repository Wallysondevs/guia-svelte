Svelte · Medindo Performance

A Ana quis deixar a vitrine mais rápida e começou pelo lugar errado: reescreveu a lista, trocou os nomes das funções, mexeu no CSS. Nada mudou. Quando finalmente rodou o build e olhou o tamanho do arquivo, descobriu que a biblioteca de ordenação que ela importou pesava mais que o site inteiro. Nesta aula ela aprende a medir antes de mexer.

1. A ideia: performance é o tempo de quem usa

Performance não é sobre o código bonito nem sobre o número que aparece no relatório. É sobre quanto tempo a Ana espera até ver o preço na tela, e quanto tempo o celular dela gasta de bateria para isso. Duas medidas, ambas do lado de quem usa.

A primeira é o download: quantos bytes o navegador precisa baixar antes de desenhar algo. A segunda é o trabalho: quanto cálculo e quanta atualização de tela acontecem depois. A primeira se mede no build; a segunda, no navegador.

Existe uma regra que vale para as duas: medir antes de mexer. Sem número, otimização é opinião. E otimização sem número costuma deixar o código mais difícil de ler sem deixar a página mais rápida — o pior dos dois mundos.

2. Onde o tempo vai

Antes de otimizar, saiba em qual das quatro etapas o tempo está sendo gasto. Cada uma tem uma ferramenta e um conserto diferente:

EtapaO que aconteceComo se mede
Baixaro navegador busca HTML, CSS e JavaScriptbuild, aba Network do navegador
Interpretaro navegador lê e monta o JavaScriptaba Performance do navegador
Desenharo navegador pinta os elementos na telaaba Performance, contagem de elementos
Recalcularo Svelte atualiza valores quando o estado mudacontador no console, $inspect

Na maioria dos projetos pequenos, a etapa que mais pesa é a primeira — e ela é a mais fácil de medir, porque o build imprime os números no terminal. Se o site baixa 200 kB de JavaScript para mostrar uma lista de dez preços, o problema não está no laço: está no que você importou.

O comando de produção imprime o tamanho de cada arquivo gerado. É a medida mais barata que existe: um comando, uma tela de números.

Leia três números. 111 módulos: quantos arquivos entraram no pacote, contando o Svelte, o seu componente e cada dependência. 41.11 kB: o tamanho do JavaScript gerado. gzip: 15.82 kB: quanto isso ocupa depois da compressão que todo servidor faz — é esse número que o visitante baixa.

Guarde a linha do gzip. Ela é a que importa para quem está no celular com internet ruim, e é a que muda quando você adiciona uma biblioteca. O tamanho sem compressão serve para comparar entre builds; o comprimido serve para imaginar a espera real.

A lição não é “nunca use biblioteca”. É: saiba quanto custa antes de importar. Uma biblioteca de datas com fuso horário, idioma e calendário pode valer cada kB; uma função de ordenar dois números, não. O build responde em quinze segundos, e a resposta é um número.

O [...produtos] não é decoração

sort muda a lista original. Copiar com [...produtos] antes de ordenar evita mexer no estado que a tela está usando. Sem a cópia, a lista de origem muda de ordem sem que ninguém peça.

5. Contando quantas vezes o cálculo roda

A segunda medida é de trabalho, não de bytes. Para saber quantas vezes uma função é chamada, conte dentro dela e imprima o total. O componente abaixo mostra quatro valores e usa a função duas vezes por linha:

<script>
  let itens = $state([1, 2, 3]);
  let execucoes = 0;

  function dobrar(valor) {
    execucoes += 1;
    return valor * 2;
  }

  function adicionar() {
    itens = [...itens, 4];
  }

  $effect(() => {
    console.log('tela com', itens.length, 'itens: dobrar rodou', execucoes, 'vezes');
  });
</script>

<button onclick={adicionar}>Adicionar item</button>

{#each itens as item}
  <p>{dobrar(item)} - {dobrar(item)}</p>
{/each}

Na criação, o console mostra seis execuções (três itens, duas chamadas cada). Depois de um clique, mostra oito:

console do navegador:

tela com 3 itens: dobrar rodou 6 vezes
tela com 4 itens: dobrar rodou 8 vezes

Oito, e não quatorze. O Svelte refez o desenho só da linha que mudou, e essa linha chama a função duas vezes. As três linhas antigas não foram tocadas. Isso contraria a intuição de quem imagina que “a tela inteira é redesenhada”: o Svelte atualiza o que depende do valor que mudou.

Agora a mesma tela com o cálculo numa runa derivada:

<script>
  let itens = $state([1, 2, 3]);
  let execucoes = 0;

  let dobrados = $derived.by(() => {
    execucoes += itens.length;
    return itens.map((item) => item * 2);
  });

  function adicionar() {
    itens = [...itens, 4];
  }

  $effect(() => {
    console.log('tela com', itens.length, 'itens: o cálculo rodou', execucoes, 'vezes');
  });
</script>

<button onclick={adicionar}>Adicionar item</button>

{#each dobrados as valor}
  <p>{valor} - {valor}</p>
{/each}
console do navegador:

tela com 3 itens: o cálculo rodou 3 vezes
tela com 4 itens: o cálculo rodou 7 vezes

Três, depois sete: o $derived refez a lista inteira, quatro itens de uma vez. É o oposto do caso anterior. Nenhum dos dois está errado — e é justamente por isso que medir importa: o custo não está onde a intuição diz.

EscolhaO que se repeteQuando vale
função no HTMLsó nos pedaços que mudaramcálculo barato, usado uma vez
$derivedo cálculo inteiro, uma vez por mudançacálculo caro, usado em vários lugares

O critério prático: se o mesmo valor calculado aparece em três pontos da tela, o $derived cobra uma vez; a função no HTML cobra três por linha. Se cada linha mostra um valor diferente, a função no HTML já está no melhor lugar — e o $derived só troca o custo de lugar.

6. O valor calculado não se guarda em $effect

Existe um padrão que parece organizado e é uma armadilha de performance: usar $effect para copiar o resultado de um cálculo para uma variável de estado. Veja o que acontece quando o efeito escreve na variável que ele mesmo lê:

<script>
  let precos = $state([0.9, 2.5]);
  let total = $state(0);

  $effect(() => {
    total = total + 1;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>

O efeito muda total, o que agenda o efeito de novo, que muda total outra vez. O Svelte corta o laço com um erro:

console do navegador:

Uncaught Error: https://svelte.dev/e/effect_update_depth_exceeded

effect_update_depth_exceeded quer dizer “o efeito se atualizou fundo demais”: um laço de atualizações. O mesmo desenho, sem laço e sem trabalho repetido, é uma runa derivada:

<script>
  let precos = $state([0.9, 2.5]);
  let total = $derived(precos.reduce((soma, p) => soma + p, 0));
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 3.40</p>

Uma linha em vez de cinco, e nenhuma chance de laço. O $derived não guarda um segundo valor: ele sabe calcular o valor a partir do que já existe. Isso é menos estado para o navegador acompanhar — e menos estado é sempre mais rápido de manter coerente.

Missão: o componente quebra com um laço de atualizações, porque o $effect escreve na variável que ele mesmo lê. Troque o efeito por um $derived que soma os preços da lista.

<script>
  let precos = $state([0.9, 2.5]);
  let total = $state(0);

  $effect(() => {
    total = total + 1;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<script>
  let precos = $state([0.9, 2.5]);
  let total = $derived(precos.reduce((soma, p) => soma + p, 0));
</script>

<p>Total: R$ {total.toFixed(2)}</p>

7. O total que envelhece

Outro jeito de guardar duas verdades: um total fixo que só está certo no começo. A cada item novo, ele fica mais velho.

<script>
  let precos = $state([0.9, 2.5]);
  let total = $state(3.4);

  function adicionar() {
    precos = [...precos, 4];
  }
</script>

<button onclick={adicionar}>Adicionar item</button>
<p>Total: R$ {total.toFixed(2)}</p>

Depois do clique, a lista tem três preços e o total continua 3.40. Ninguém vê erro nenhum: só um número errado. Além de ser um bug, é trabalho desperdiçado — alguém vai precisar lembrar de atualizar o total em cada lugar que mexe na lista.

Missão: a lista ganha um item novo no clique, mas o total ficou preso em 3.40. Faça o total acompanhar a lista, sem atualizar à mão.

<script>
  let precos = $state([0.9, 2.5]);
  let total = $state(3.4);

  function adicionar() {
    precos = [...precos, 4];
  }
</script>

<button onclick={adicionar}>Adicionar item</button>
<p>Total: R$ {total.toFixed(2)}</p>
<script>
  let precos = $state([0.9, 2.5]);
  let total = $derived(precos.reduce((soma, p) => soma + p, 0));

  function adicionar() {
    precos = [...precos, 4];
  }
</script>

<button onclick={adicionar}>Adicionar item</button>
<p>Total: R$ {total.toFixed(2)}</p>

O ganho aqui não é de milissegundos: é de garantia. Com o total derivado, não existe estado em que a lista tenha três itens e o total diga dois. Em tela pequena, essa diferença não se mede; em código grande, ela evita a classe de bug mais difícil de achar.

8. Ordenar uma vez, não a cada desenho

Ordenar dentro do HTML funciona e é fácil de ler. O problema é quando a mesma ordenação precisa valer para dois lugares — a lista e o texto “o mais barato é…”. Aí ela roda duas vezes, com dois resultados possíveis se alguém mudar um dos lados.

<script>
  let precos = $state([2.5, 0.9, 4]);
</script>

{#each precos as preco}
  <p>{preco.toFixed(2)}</p>
{/each}
<p>2.50</p><p>0.90</p><p>4.00</p>

A lista sai na ordem em que os preços foram guardados. Para sair do mais barato ao mais caro, ordenar uma vez numa runa derivada resolve para todos os usos:

<script>
  let precos = $state([2.5, 0.9, 4]);
  let ordenados = $derived([...precos].sort((a, b) => a - b));
</script>

{#each ordenados as preco}
  <p>{preco.toFixed(2)}</p>
{/each}
<p>0.90</p><p>2.50</p><p>4.00</p>

Missão: a lista sai na ordem em que os preços foram guardados. Faça ela sair do mais barato ao mais caro, numa runa derivada que ordena uma vez só.

<script>
  let precos = $state([2.5, 0.9, 4]);
</script>

{#each precos as preco}
  <p>{preco.toFixed(2)}</p>
{/each}
<script>
  let precos = $state([2.5, 0.9, 4]);
  let ordenados = $derived([...precos].sort((a, b) => a - b));
</script>

{#each ordenados as preco}
  <p>{preco.toFixed(2)}</p>
{/each}

Repare na cópia [...precos] de novo. Ela existe porque sort embaralha a lista original, e a lista original é o estado que a tela acompanha. Ordenar o estado por dentro faria a ordem dos dados depender da ordem em que a tela foi desenhada — o tipo de efeito colateral que aparece só em produção.

9. Lista longa e a chave do {#each}

Quando a lista muda — um item entra, outro sai, a ordem troca —, o Svelte precisa decidir quais pedaços de tela reaproveitar. Sem chave, ele reaproveita por posição: o primeiro item continua no primeiro lugar, o segundo no segundo. Com chave, ele reaproveita pelo identificador.

<script>
  let produtos = $state([
    { id: 1, nome: 'Pão francês' },
    { id: 2, nome: 'Sonho' }
  ]);
</script>

{#each produtos as produto (produto.id)}
  <p>{produto.nome}</p>
{/each}
<p>Pão francês</p><p>Sonho</p>

A diferença aparece quando a ordem muda ou um item do meio sai. Sem chave, o texto do primeiro lugar é reescrito com o dado do novo primeiro item — a tela fica certa, mas todo o conteúdo daquele pedaço é substituído. Com chave, o Svelte move o pedaço inteiro, junto com o que estava dentro dele: um campo de texto digitado, por exemplo.

Situação da listaChave é…
lista curta, que só cresce no fimopcional
lista que reordena ou filtrarecomendada, com o id
itens com campo de texto ou checkbox dentroobrigatória na prática, senão o valor digitado pula de linha

Uma ressalva que só aparece quando se mede: a chave custa um pouco. O Svelte mantém um mapa de identificadores, e para listas de milhares de itens isso tem preço. A regra é começar sem chave nas listas simples e adicionar quando houver reordenação, remoção no meio ou campos dentro do item.

10. Quando dá errado

As três saídas abaixo são reais: as duas primeiras vêm do renderizador desta versão, a terceira do console do navegador. Repare que nenhuma delas fala em “performance” — mas todas são trabalho demais para o que a tela precisava.

Erro 1 — o dado não tem a forma esperada

O objeto tem uma lista dentro, e o código chamou map no objeto. O erro diz exatamente qual valor não tem a função.

<script>
  let dados = $state({ itens: [1, 2, 3] });
  let dobrados = $derived(dados.map((n) => n * 2));
</script>

{#each dobrados as valor}
  <p>{valor}</p>
{/each}
dados.map is not a function

A correção é dados.itens.map(...). Antes de otimizar, vale conferir a forma do dado com console.log(dados): metade das “lentidões” suspeitas é dado com formato diferente do que o código supõe.

Erro 2 — trabalho sem fim

Uma função que chama a si mesma sem condição de parada enche a pilha de chamadas. Não é lentidão: é trabalho infinito.

<script>
  function contar(n) {
    return contar(n + 1);
  }

  let resultado = $state(contar(1));
</script>

<p>{resultado}</p>
Maximum call stack size exceeded

“Tamanho máximo da pilha de chamadas excedido”. Toda recursão precisa de um caso que para — if (n > 10) return n;, por exemplo. Sem ele, nenhuma otimização ajuda, porque o cálculo nunca termina.

Erro 3 — o efeito que se alimenta

Este não aparece no HTML: acontece no navegador, quando um efeito escreve na variável que ele lê. O Svelte detecta o laço e para o componente.

<script>
  let total = $state(0);

  $effect(() => {
    total = total + 1;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>
console do navegador:

Uncaught Error: https://svelte.dev/e/effect_update_depth_exceeded

“Profundidade de atualização do efeito excedida”. A saída é tirar o valor do efeito e deixá-lo como $derived: valor calculado não precisa de lugar próprio.

Resumo

  • Performance é o tempo de quem usa: baixar, interpretar, desenhar e recalcular.
  • npm run build dá o número mais barato de todos: módulos, tamanho e gzip.
  • Uma biblioteca inteira por causa de uma função pode triplicar o peso do site.
  • Contar execuções com console.log mostra o trabalho real, sem palpite.
  • Função no HTML roda só nos pedaços que mudaram; $derived refaz o cálculo inteiro.
  • $effect que escreve no que lê gera effect_update_depth_exceeded.
  • Valor calculado é $derived, nunca um segundo $state sincronizado à mão.
  • Ordene e filtre numa runa derivada, com cópia da lista antes de sort.
  • Chave no {#each} vale quando a lista reordena, perde item do meio ou tem campo dentro.
  • Meça, mude uma coisa, meça de novo — e guarde os dois números.
