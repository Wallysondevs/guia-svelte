Svelte · Primeiro Componente

A Ana tem uma padaria e um problema pequeno: ela escreve o preço do pão num papelão, e toda vez que o preço muda ela precisa escrever outro papelão. O sobrinho dela disse que existe um jeito de escrever uma vez e o número se atualizar sozinho na parede. É disso que trata esta aula: um pedaço de tela que tem nome, guarda um valor e se redesenha quando o valor muda. O nome disso é componente.

1. A ideia: um pedaço de tela com nome

Antes de existir programação, a Ana já fazia componentização sem saber. Na parede da padaria tem uma placa de "PÃO FRANCÊS — R$ 0,90". Aquela placa tem um nome (pão francês), um valor (R$ 0,90) e um visual (a cor, a fonte, o lugar na parede). Quando o preço do trigo sobe, ela não faz outra placa do zero: ela apaga só o número e escreve outro.

Um componente Svelte é essa placa, mas com uma diferença importante: o número não fica escrito à mão. Ele fica guardado numa variável, e a placa mostra o que estiver na variável naquele momento. Se a variável muda, a placa muda — sozinha, sem ninguém apagar nada. Essa é a única ideia desta aula, e o resto é consequência dela.

O ganho aparece quando a padaria cresce. Com dez placas escritas à mão, mudar o preço do pão significa lembrar das dez. Com um componente, você muda o valor num lugar e todas as placas que mostram aquele valor se atualizam. O computador faz o trabalho chato; você fica com a parte que exige cabeça.

Repare no vocabulário: componente é o arquivo, estado é o que pode mudar dentro dele, e reativo é o adjetivo para o que se atualiza sozinho. Três palavras que você vai ler o guia inteiro. Elas não são sinônimos: o componente é a caixa, o estado é o conteúdo, e a reatividade é o que acontece quando o conteúdo muda.

2. O primeiro componente da Ana

Um componente Svelte é um arquivo com a extensão .svelte. Dentro dele existe HTML normal — as mesmas tags que você já viu em qualquer página — mais dois blocos opcionais: um para o JavaScript e outro para o CSS. Comece pelo menor componente possível da padaria:

<script>
  let nome = 'Ana';
</script>

<h1>Olá, {nome}</h1>
<p>Bem-vinda à padaria.</p>

Se você pedir ao compilador do Svelte o HTML que esse arquivo produz, ele devolve exatamente isto:

<h1>Olá, Ana</h1> <p>Bem-vinda à padaria.</p>

Duas coisas aconteceram que merecem atenção. Primeiro: {nome} desapareceu e no lugar ficou Ana — as chaves são um buraco no HTML por onde o valor entra. Segundo: o arquivo que o navegador recebe não tem o <script> do componente. O compilador leu o script, calculou o valor e escreveu o resultado direto no HTML. Quem monta a página final é ele, não você.

A anatomia do arquivo

<script>
o bloco de JavaScript: onde os valores nascem. Fica no topo do arquivo, e tudo o que é declarado aqui pode ser usado mais abaixo, no HTML.
let nome
uma variável chamada nome. let quer dizer "isto pode mudar depois" (é o contrário de uma constante).
= 'Ana'
o valor inicial. Texto vai entre aspas simples ou duplas; número vai sem aspas.
<h1>Olá, {nome}</h1>
HTML com um buraco. As chaves podem conter qualquer expressão: um nome de variável, uma conta, uma chamada de função.
</script>
fecha o bloco. O que vem depois é HTML comum, sem document.getElementById, sem innerHTML: o Svelte liga o valor ao lugar sozinho.

Esse é o primeiro choque de quem vem do JavaScript "puro". Em JS você escreveria document.querySelector('h1').textContent = 'Olá, ' + nome. No Svelte você escreve {nome} e o compilador gera o código que faz a ligação. A quantidade de código que você não precisou escrever é o motivo de o Svelte existir.

Nome de arquivo com maiúscula

Componentes começam com letra maiúscula: App.svelte, Cartao.svelte, ListaDeTarefas.svelte. Não é capricho: é assim que o compilador distingue "um componente meu" de "uma tag do HTML". <app /> é uma tag desconhecida; <App /> é o seu componente.

3. O valor que muda sozinho: $state

Até aqui a placa está escrita à mão, só que com o valor vindo de uma variável. Falta o principal: quando o valor mudar, a tela acompanhar. No Svelte 5 isso é uma palavra só — $state:

<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>
<button onclick={() => (nome = 'Bia')}>trocar o nome</button>
<h1>Olá, Ana</h1> <button>trocar o nome</button>

Chama-se $state, com cifrão na frente, e é uma runa — um comando especial que o compilador do Svelte reconhece. Ela diz: "guarde este valor e me avise toda vez que ele mudar". Quem escuta o aviso é o HTML que usa a variável; quando chega o aviso, ele se redesenha.

Sem $state, a variável continua sendo uma variável comum: o valor está lá, mas ninguém avisa o HTML de que ele mudou. É a diferença entre uma placa de papel e uma lousa com alguém de plantão apagando e reescrevendo. No papel, o preço novo só aparece quando alguém troca o papel.

Missão: o componente cumprimenta o mundo. Troque o valor para que ele cumprimente a Ana e clique em Verificar.

<script>
  let nome = $state('mundo');
</script>

<h1>Olá, {nome}</h1>
<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>

Enquanto você edita, o componente é compilado de novo a cada Rodar — com o compilador de verdade do Svelte, o mesmo que compila o projeto da Ana. Se você escrever algo impossível, a caixa mostra a mensagem do compilador, não um aviso inventado pelo guia.

4. O clique: onclick

Um botão que não faz nada é um enfeite. Para ele fazer algo, você diz o que fazer quando alguém clicar. No Svelte 5 isso é um atributo comum, com o nome do evento:

<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>
<button onclick={() => (nome = 'Bia')}>trocar o nome</button>

A parte da direita é uma função: um pedaço de código guardado para ser executado depois. Os parênteses vazios dizem que ela não precisa de informação nenhuma para trabalhar; a seta => separa "o que entra" de "o que acontece"; e o que acontece é nome = 'Bia' — a variável de estado recebe outro valor, o aviso é disparado e a tela se atualiza.

onclick
o evento. O nome sempre começa com on e segue o nome do evento em minúsculas: oninput, onsubmit, onkeydown.
{…}
o valor do atributo é uma expressão JavaScript, não uma string. Repare que não há aspas em volta.
() => …
a função que roda no clique. O Svelte chama essa função quando o evento acontece.
nome = 'Bia'
a mudança de estado. Só variáveis criadas com $state avisam a tela.

Missão: o botão troca para Bia e não volta mais. Faça ele alternar: um clique vai para Bia, outro clique volta para Ana.

<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>
<button onclick={() => (nome = 'Bia')}>trocar</button>
<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>
<button onclick={() => (nome = nome === 'Ana' ? 'Bia' : 'Ana')}>trocar</button>

A solução usa uma expressão condicional: nome === 'Ana' ? 'Bia' : 'Ana' lê-se "se o nome for Ana, use Bia; senão, use Ana". Três pontinhos de sintaxe que voltam na aula de condicionais, com calma. O importante agora é que a tela obedece ao valor, e o valor obedece ao clique.

5. Os três blocos de um arquivo .svelte

Todo componente pode ter até três blocos, sempre nesta ordem: <script>, o HTML, e <style>. Só o HTML é obrigatório — um componente com uma linha de texto é um componente válido.

<script>
  let titulo = $state('Pão francês');
  let preco = $state(0.9);
</script>

<h2>{titulo}</h2>
<p>R$ {preco.toFixed(2)}</p>

<style>
  h2 {
    color: #2e7d32;
  }
</style>
<h2 class="svelte-11u2pyd">Pão francês</h2> <p>R$ 0.90</p>

6. Número com duas casas: toFixed

O preço da Ana é noventa centavos, mas o componente mostrou R$ 0.9. Para uma placa na parede isso está errado: dinheiro tem duas casas. O JavaScript resolve com um método de número chamado toFixed, e o Svelte não muda nada nisso — é JavaScript normal dentro das chaves.

<script>
  let preco = $state(0.9);
</script>

<p>R$ {preco.toFixed(2)}</p>
<p>R$ 0.90</p>

O toFixed(2) arredonda para duas casas decimais: 0.9 vira "0.90", 2.345 vira "2.35". E aqui vem o detalhe que morde: depois de toFixed o valor é uma string, não um número. Se você tentar somar "0.90" + 0.10, o resultado é "0.900.1" — texto colado, não soma. A regra é sempre a mesma: calcule com número, formate só na hora de mostrar.

Missão: o preço guardado é 0.9 e a placa mostra R$ 0.9. Formate para sair com duas casas — R$ 0.90 — sem trocar o valor guardado.

<script>
  let preco = $state(0.9);
</script>

<p>R$ {preco}</p>
<script>
  let preco = $state(0.9);
</script>

<p>R$ {preco.toFixed(2)}</p>

Repare que o estado continua sendo um número: quem virou texto foi só o que aparece na tela. Essa separação entre o dado e a forma de mostrar o dado é uma das ideias mais úteis da programação, e volta em toda aula em que a Ana precisa mostrar dinheiro.

7. Estilo que não vaza

Se você escrever h1 { color: green } dentro de um componente, o Svelte faz uma coisa esperta: renomeia o seletor para que ele só valha ali dentro. Veja o CSS que o compilador gerou para o componente com estilo da Ana:

<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>
<button onclick={() => (nome = 'Bia')}>trocar</button>

<style>
  h1 {
    color: #2e7d32;
    font-family: system-ui, sans-serif;
  }
  button {
    padding: 6px 12px;
  }
</style>
h1.svelte-1n46o8q {
    color: #2e7d32;
    font-family: system-ui, sans-serif;
  }
  button.svelte-1n46o8q {
    padding: 6px 12px;
  }

Aquele svelte-1n46o8q é um selo que o compilador inventou para este componente, e ele também foi colocado nas tags do HTML gerado:

É por isso que a regra "todo h1 verde" do Cartao.svelte não pinta os h1 do resto do site. Em CSS tradicional isso dá dor de cabeça: nomes de classe inventados à mão, BEM, prefixos, disciplina. Aqui o problema simplesmente não existe — o escopo é do arquivo.

O preço é que às vezes você quer atingir algo de fora. Para isso existe :global(…), que desliga o escopo naquele seletor. Use com parcimônia: cada :global é uma porta que você abre no isolamento.

8. Rodando no computador da Ana

O projeto da Ana fica em ~/loja e tem três comandos. O primeiro liga o servidor de desenvolvimento, que recompila a cada arquivo salvo:

ana@notebook:~/loja$ npm run dev

> loja@0.0.1 dev
> vite

  VITE v7.3.8  ready in 436 ms

  ➜  Local:   http://localhost:5173/
  ➜  Network: use --host to expose

O endereço http://localhost:5173/ é a sua máquina falando com você mesma: nada foi para a internet. Enquanto esse comando estiver rodando, cada Ctrl+S no arquivo aparece no navegador em menos de um segundo.

Quando o trabalho está pronto, o comando de build gera a versão de produção — arquivos menores, sem nada de desenvolvimento:

ana@notebook:~/loja$ npm run build
vite v7.3.8 building client environment for production...
transforming...
✓ 111 modules transformed.
rendering chunks...
computing gzip size...
dist/index.html                 0.25 kB │ gzip:  0.19 kB
dist/assets/index-D4Bgwu4I.js  33.60 kB │ gzip: 12.93 kB
✓ built in 625ms

Duas lições neste segundo terminal. A primeira: "111 modules transformed" é o Svelte compilando cada .svelte em JavaScript que o navegador entende. A segunda: o CSS e o JS viraram um arquivo com hash no nome (index-D4Bgwu4I.js) — é o que permite o navegador guardar em cache para sempre, porque se o conteúdo mudar o nome muda junto.

Não abra o dist/ clicando duas vezes

Os arquivos gerados usam módulos ES, e abrir dist/index.html direto do disco (file://) faz o navegador bloquear o carregamento por CORS. Para conferir o build, use npm run preview, que serve a pasta por http — o mesmo motivo pelo qual as caixas deste guia rodam num servidor de verdade.

9. Quando dá errado

As três mensagens abaixo saíram do compilador desta versão, copiadas como estão. Não são exemplos inventados: é o texto que você vai ver.

Erro 1 — $state sem let

A runa precisa estar na declaração de uma variável. Sem o let, o compilador não tem onde guardar o estado.

<script>
  contador = $state(0);
</script>

<button>{contador}</button>
Erro de compilação (linha 2, coluna 13): `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

A mensagem é comprida porque o Svelte aceita $state em três lugares diferentes. Para quem está começando, a tradução é uma só: escreva let antes do nome. E repare no "linha 2, coluna 13" — a posição exata do problema, que você usa para ir direto ao ponto.

Erro 2 — bloco aberto e não fechado

Toda chave que abre precisa fechar. Um {#if sem {/if} deixa o compilador esperando o resto do arquivo.

<script>
  let nome = $state('Ana');
</script>

{#if nome === 'Ana'}
  <p>oi</p>
Erro de compilação (linha 5, coluna 0): Block was left open

"Block was left open" quer dizer "um bloco ficou aberto". Repare que a linha apontada é a última do arquivo, não o começo do bloco — o compilador só repara que falta o fecho quando o arquivo acaba. A dica prática é contar os pares: cada {#if} pede um {/if}, cada {#each} pede um {/each}, cada {#snippet} pede um {/snippet}.

Erro 3 — variável que não existe

Este não é erro de compilação: o arquivo compila, e o componente quebra na hora de desenhar. A mensagem vem do navegador.

<script>
  let nome = $state('Ana');
</script>

<h1>{naoExiste}</h1>
naoExiste is not defined

Quase sempre é um nome digitado diferente do declarado — nome contra Name, preco contra preço. O compilador não tem como adivinhar a intenção: para ele, naoExiste seria uma variável global que alguém esqueceu de declarar. Confira letra por letra.

  • Os erros desta aula: $state sem let, bloco aberto sem fechar e variável que não existe.
  • preco.toFixed(2) formata dinheiro; o valor guardado continua número, o que aparece é texto.
  • A saída mostrada no guia é a do compilador de verdade — se o seu resultado for diferente, o código é diferente.
