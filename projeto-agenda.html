Projetos · Agenda

A Ana anota os compromissos da padaria num caderno: "8:30 retirar bolo da Dona Bia", "10:00 encomenda de 30 pães". O caderno tem dois defeitos que nenhum papel resolve. Ela não consegue riscar um item sem sujar a página, e a ordem das linhas é a ordem em que ela lembrou — não a ordem do dia. Nesta aula a agenda vira uma tela em três versões, com concluir, cadastrar e agrupar por período. A ordem das horas é o problema mais interessante, e ele aparece no terminal de verdade.

Você vai aprender
  • Como marcar e desmarcar um item com um clique, sem apagar nada.
  • Por que um contador calculado com let comum não se atualiza.
  • A diferença entre mudar um item da lista e trocar a lista inteira.
  • Como validar uma hora digitada com expressão regular.
  • Por que ordenar horário como texto coloca 10:00 antes de 8:30.
  • Como transformar "8:30" em número de minutos para comparar.
  • O que $derived.by resolve quando há agrupamento.
  • Como {@const} e {#snippet} deixam a lista mais limpa.
  • O que o terminal mostra quando o build roda.
  • As três mensagens de erro que esta agenda provoca de verdade.

1. O caderno e o que ele não faz

Um caderno de compromissos guarda três informações por linha: a hora, o que fazer e se já foi feito. O papel aceita as três, mas não sabe responder a duas perguntas simples. "Quantos ainda faltam hoje?" exige contar à mão. "Qual é o próximo?" exige varrer as linhas com o dedo, porque a ordem é a de escrita.

Na tela, cada linha vira um objeto com três campos, e as duas perguntas viram valores derivados: uma contagem e uma lista ordenada. Nada disso é guardado — é calculado a partir da lista de compromissos. Essa é a diferença central da aula: o caderno guarda linhas; a agenda calcula respostas.

No cadernoNo componente
Uma linha escrita à mãoUm objeto { hora, nome, feito }
O risco de caneta sobre o item feitoA classe feito com class:feito
Contar as linhas não riscadas$derived com filter e length
Reescrever o dia em ordem de horasort com a função de minutos
Separar a manhã da tarde$derived.by devolvendo dois grupos

2. Versão 1 — a lista com "concluir"

A primeira versão guarda três compromissos e deixa marcar cada um como feito. O botão muda de texto conforme o estado do item, e o contador do topo diz quantos faltam.

<script>
  let itens = $state([
    { id: 1, hora: '8:30', nome: 'Retirar bolo da Dona Bia', feito: false },
    { id: 2, hora: '9:00', nome: 'Abrir a padaria', feito: false },
    { id: 3, hora: '10:00', nome: 'Encomenda de 30 pães', feito: false }
  ]);

  let pendentes = $derived(itens.filter((i) => !i.feito).length);
</script>

<p>{pendentes} pendente(s) hoje</p>

<ul>
  {#each itens as item (item.id)}
    <li>
      <button onclick={() => (item.feito = !item.feito)}>
        {item.feito ? 'refazer' : 'concluir'}
      </button>
      {item.hora} — {item.nome}
    </li>
  {/each}
</ul>

Como nada foi marcado ainda, o contador mostra três e todos os botões dizem "concluir":

<p>3 pendente(s) hoje</p> <ul><li><button>concluir</button> 8:30 — Retirar bolo da Dona Bia</li><li><button>concluir</button> 9:00 — Abrir a padaria</li><li><button>concluir</button> 10:00 — Encomenda de 30 pães</li></ul>

O !i.feito do filtro é o "não feito": o ponto de exclamação inverte um booleano. Quem está com feito: false sobra na lista de pendentes, e o .length no fim devolve o número em vez da lista.

A anatomia da versão 1

let itens = $state([...])
uma lista de objetos. O $state deixa o Svelte observar também o que está dentro de cada objeto.
item.feito = !item.feito
troca o valor do item dentro da lista. Não é preciso criar outra lista: o objeto é observado.
{item.feito ? 'refazer' : 'concluir'}
o texto do botão depende do estado do item. Uma condicional curta dentro das chaves.
{#each itens as item (item.id)}
a chave é o id: quando a lista muda, o Svelte sabe qual <li> corresponde a qual item.
$derived(itens.filter(...).length)
recalcula sozinho quando algum feito muda. É a contagem do caderno, feita pelo computador.

3. Por que o contador precisa ser derivado

Este é o erro de raciocínio mais comum de quem vem de outra linguagem. Se você escrever let pendentes = itens.filter((i) => !i.feito).length, sem $derived, o valor é calculado uma vez, quando o componente nasce. Marcar um item como feito muda a lista, mas não muda pendentes: ninguém mandou recalcular.

Em JavaScript puro, esse valor é uma foto do momento. Em Svelte 5, $derived é uma receita: "sempre que algo aqui dentro mudar, refaça". A diferença aparece na tela no primeiro clique — o risco do item aparece, o número do topo continua velho.

EscritaO que acontece no cliqueQuando serve
let pendentes = itens.filter(…)o número fica parado no valor inicialquase nunca
let pendentes = $derived(itens.filter(…))o número é recalculadosempre que deriva de estado
let pendentes = $state(0) e atualizar à mãofunciona, mas você tem de lembrar em todo lugarquando o valor não deriva de nada

</script>

4. Versão 2 — cadastrar com hora

A segunda versão acrescenta o formulário. Dois campos, uma regra de formato para a hora, uma regra de conteúdo para o nome, e a lista sempre ordenada por horário — mesmo que os itens tenham sido digitados fora de ordem.

<script>
  let itens = $state([
    { id: 1, hora: '8:30', nome: 'Retirar bolo da Dona Bia', feito: false },
    { id: 2, hora: '10:00', nome: 'Encomenda de 30 pães', feito: false }
  ]);
  let hora = $state('');
  let nome = $state('');
  let erro = $state('');

  function minutos(h) {
    const [hh, mm] = h.split(':').map(Number);
    return hh * 60 + (mm || 0);
  }

  function adicionar() {
    erro = '';
    if (!/^\d{1,2}:\d{2}$/.test(hora)) {
      erro = 'Hora no formato 9:30';
      return;
    }
    if (nome.trim() === '') {
      erro = 'Escreva o compromisso';
      return;
    }
    itens = [...itens, { id: Date.now(), hora, nome, feito: false }];
    hora = '';
    nome = '';
  }

  let ordenados = $derived(
    [...itens].sort((a, b) => minutos(a.hora) - minutos(b.hora))
  );
</script>

<form onsubmit={(e) => { e.preventDefault(); adicionar(); }}>
  <input bind:value={hora} placeholder="9:30">
  <input bind:value={nome} placeholder="Compromisso">
  <button>Adicionar</button>
</form>

{#if erro}
  <p class="erro">{erro}</p>
{/if}

<ul>
  {#each ordenados as item (item.id)}
    <li class:feito={item.feito}>
      {item.hora} — {item.nome}
    </li>
  {/each}
</ul>

<style>
  .erro { color: #b3261e; font-weight: 600; }
  .feito { text-decoration: line-through; color: #777; }
</style>

Na tela, os campos não aparecem por conteúdo — só o botão e as duas linhas:

Adicionar 8:30 — Retirar bolo da Dona Bia 10:00 — Encomenda de 30 pães

Duas decisões de projeto estão nesse código. A primeira: itens = [...itens, {...}] cria uma lista nova em vez de usar itens.push(...). As duas funcionam no Svelte 5, mas a lista nova deixa claro que o valor mudou, e é o que você vai encontrar em todo exemplo de código que precisa avisar outro sistema. A segunda: [...itens] antes do sort copia a lista antes de ordenar, porque sort embaralha o array original.

A anatomia da versão 2

/^\d{1,2}:\d{2}$/
expressão regular que exige um ou dois dígitos, dois pontos e dois dígitos. O ^ e o $ prendem o começo e o fim, então "às 9:30" não passa.
.test(hora)
devolve true ou false. O ! na frente inverte: o erro aparece quando o teste falha.
h.split(':').map(Number)
quebra "8:30" em ['8', '30'] e converte cada pedaço em número: [8, 30].
hh * 60 + (mm || 0)
converte a hora em minutos desde a meia-noite. O || 0 cobre a hora sem minutos, como "9".
[...itens]
cópia rasa da lista. O sort mexe nessa cópia, não na lista de estado.
Date.now()
um número que muda a cada milissegundo. Serve como id temporário para o item novo.

Missão: o botão aceita um compromisso em branco e cria uma linha vazia. Faça ele recusar e mostrar "Escreva o compromisso".

<script>
  let itens = $state(['Pão às 8h']);
  let novo = $state('');
</script>

<input bind:value={novo} placeholder="Compromisso">
<button onclick={() => (itens = [...itens, novo])}>Adicionar</button>

<ul>
  {#each itens as i}
    <li>{i}</li>
  {/each}
</ul>

      return;

</ul>

5. O horário é texto, não número

Ordenar horário com o sort padrão é uma armadilha silenciosa: sem função de comparação, o JavaScript compara os itens como texto, caractere por caractere. "10:00" começa com "1", "8:30" começa com "8", e o "1" vem antes do "8" na tabela de caracteres. O resultado é 10:00 primeiro. O terminal mostra isso sem rodeio:

ana@notebook:~/loja$ node
Welcome to Node.js v22.23.5.
Type ".help" for more information.
> ['10:00', '9:00', '8:30'].sort()
[ '10:00', '8:30', '9:00' ]
> const minutos = (h) => { const [hh, mm] = h.split(':').map(Number); return hh * 60 + (mm || 0); }
undefined
> ['10:00', '9:00', '8:30'].sort((a, b) => minutos(a) - minutos(b))
[ '8:30', '9:00', '10:00' ]

O undefined na terceira linha é o resultado da declaração: uma função não devolve nada ao ser criada, e o console registra isso. Na última linha, a função de comparação devolve a diferença em minutos, e aí a ordem sai certa.

Guardar a hora como texto tem um custo. Cada comparação precisa converter de novo, e formatos diferentes ("9:30" e "09:30") são textos diferentes. A alternativa é guardar minutos desde a meia-noite e formatar na hora de mostrar — o mesmo princípio da aula de preço, em que o número fica guardado e o texto é só a roupa.

Missão: a lista sai na ordem errada. Faça os horários aparecerem em ordem de verdade: 8:30, 9:00, 10:00.

<script>
  let horarios = $state(['10:00', '9:00', '8:30']);
  let ordenados = $derived([...horarios].sort());
</script>

<ul>
  {#each ordenados as h}
    <li>{h}</li>
  {/each}
</ul>
<script>
  let horarios = $state(['10:00', '9:00', '8:30']);

  function minutos(h) {
    const [hh, mm] = h.split(':').map(Number);
    return hh * 60 + (mm || 0);
  }

  let ordenados = $derived([...horarios].sort((a, b) => minutos(a) - minutos(b)));
</script>

<ul>
  {#each ordenados as h}
    <li>{h}</li>
  {/each}
</ul>

6. Versão 3 — agrupar por período

A terceira versão responde à pergunta que o caderno não responde: "o que é de manhã e o que é de tarde?". O cálculo tem dois passos — filtrar e depois separar em dois grupos —, e é aí que entra $derived.by. A linha de cada compromisso vira um snippet, porque ela aparece em dois lugares.

<script>
  let itens = $state([
    { id: 1, hora: '8:30', nome: 'Retirar bolo da Dona Bia', feito: false },
    { id: 2, hora: '9:00', nome: 'Abrir a padaria', feito: true },
    { id: 3, hora: '10:00', nome: 'Encomenda de 30 pães', feito: false },
    { id: 4, hora: '15:00', nome: 'Entregar cesta da firma', feito: false }
  ]);
  let soPendentes = $state(false);

  function minutos(h) {
    const [hh, mm] = h.split(':').map(Number);
    return hh * 60 + (mm || 0);
  }

  function alternar(item) {
    item.feito = !item.feito;
  }

  let visiveis = $derived(
    itens
      .filter((i) => (soPendentes ? !i.feito : true))
      .sort((a, b) => minutos(a.hora) - minutos(b.hora))
  );

  let periodos = $derived.by(() => [
    { titulo: 'manhã', lista: visiveis.filter((i) => minutos(i.hora) < 12 * 60) },
    { titulo: 'tarde', lista: visiveis.filter((i) => minutos(i.hora) >= 12 * 60) }
  ]);
</script>

{#snippet linha(item)}
  <li class:feito={item.feito}>
    <button onclick={() => alternar(item)}>{item.feito ? 'refazer' : 'concluir'}</button>
    {item.hora} — {item.nome}
  </li>
{/snippet}

<label>
  <input type="checkbox" bind:checked={soPendentes}>
  só o que falta fazer
</label>

{#if visiveis.length === 0}
  <p>Tudo em ordem: nenhum compromisso pendente.</p>
{:else}
  {#each periodos as periodo}
    {#if periodo.lista.length > 0}
      <h3>{periodo.titulo}</h3>
      <ul>
        {#each periodo.lista as item (item.id)}
          {@render linha(item)}
        {/each}
      </ul>
    {/if}
  {/each}
{/if}

<style>
  .feito { text-decoration: line-through; color: #777; }
</style>

Com a caixinha desmarcada, os quatro compromissos aparecem, separados pela hora do meio-dia:

só o que falta fazer manhã concluir 8:30 — Retirar bolo da Dona Bia refazer 9:00 — Abrir a padaria concluir 10:00 — Encomenda de 30 pães tarde concluir 15:00 — Entregar cesta da firma

Repare que "Abrir a padaria" aparece com o botão "refazer", porque já está marcado como feito. E repare no que não aparece: nenhum título "tarde" vazio. O {#if periodo.lista.length > 0} impede o cabeçalho de um grupo sem itens — um detalhe pequeno que separa uma tela polida de uma tela com um "tarde" solto no rodapé.

A anatomia da versão 3

$derived.by(() => [ … ])
para cálculos de vários passos. Aqui devolve uma lista de grupos, cada um com título e itens.
soPendentes ? !i.feito : true
quando a caixinha está marcada, só passa quem não foi feito; senão, passa todo mundo.
minutos(i.hora) < 12 * 60
antes do meio-dia é manhã. Comparar em minutos evita comparar texto.
{#snippet linha(item)}
a marcação de uma linha, com nome. Chamada duas vezes, uma em cada grupo.
{@render linha(item)}
desenha o snippet com o item da vez. A chave (item.id) continua valendo.
alternar(item)
uma função para o clique. O mesmo código serve para os quatro itens, em qualquer grupo.

9. Quando dá errado

Erro 1 — ler uma propriedade de null

Compila e quebra ao desenhar. Este é o erro de lista mais comum: um item vazio no meio dos dados.

<script>
  let itens = $state([null]);
</script>

<ul>
  {#each itens as item}
    <li>{item.nome}</li>
  {/each}
</ul>
Erro ao renderizar: Cannot read properties of null (reading 'nome')

A mensagem diz exatamente qual leitura falhou. Se a lista pode começar vazia, comece com [] — lista vazia não tem item nenhum para quebrar.

Erro 2 — {@const} no lugar errado

O {@const} só pode ser filho direto de um bloco. Colocá-lo solto no meio do HTML faz o compilador listar todos os lugares onde ele seria aceito.

<script>
  let horarios = $state(['10:00', '9:00']);
</script>

<p>{@const primeiro = horarios[0]}</p>
Erro de compilação (linha 5, coluna 3): `{@const}` must be the immediate child of `{#snippet}`, `{#if}`, `{:else if}`, `{:else}`, `{#each}`, `{:then}`, `{:catch}`, `<svelte:fragment>`, `<svelte:boundary>` or `<Component>`

A lista comprida é uma ajuda, não um castigo: são os blocos que criam um escopo onde a constante pode viver. Dentro de um {#each}, o {@const} é aceito e costuma simplificar contas repetidas.

Erro 3 — {@render} de snippet que não existe

O componente compila; o erro aparece na hora de desenhar, porque o nome não foi declarado em nenhum lugar.

<script>
  let nome = $state('Ana');
</script>

<p>{@render linha(nome)}</p>
Erro ao renderizar: linha is not defined

Para usar {@render linha(item)}, a página precisa de um {#snippet linha(item)} … {/snippet} no mesmo arquivo. O nome é uma variável como qualquer outra: se não existe, o JavaScript reclama.

Resumo

  • Um compromisso é um objeto com hora, nome e um booleano de "feito".
  • item.feito = !item.feito marca e desmarca sem tirar o item da lista.
  • Valor calculado uma vez (let comum) não acompanha o estado; $derived acompanha.
  • Toda vez que um valor é consequência de outro, ele é derivado — e não deve ser estado.
  • Hora como texto precisa de conversão para minutos antes de qualquer comparação.
  • sort() sem função compara texto; com função, compara o que você mandar.
  • [...itens] copia a lista para o sort não alterar o estado.
  • $derived.by organiza cálculos de vários passos, como separar manhã e tarde.
  • Cabeçalho de grupo vazio se evita com {#if lista.length > 0}.
  • Lista que pode começar vazia começa com [], nunca com um item nulo.
