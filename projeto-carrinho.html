Svelte · Projeto Carrinho de Compras

A Ana vende pão por unidade, sonho por unidade e bolo por fatia. No caderno de fiado ela escreve "6 pão 0,90" e depois soma tudo na calculadora; quando erra, o prejuízo é dela. O carrinho é o primeiro projeto em que o número final não é digitado: ele é calculado a partir dos itens, e muda sozinho quando a quantidade muda. As três versões abaixo foram compiladas e rodadas de verdade — inclusive os erros.

Você vai aprender
  • A guardar itens com preço e quantidade num array de objetos.
  • Por que {item.preco} mostra 0.9 e como chegar em 0.90 com toFixed.
  • A somar uma lista inteira com reduce, sem laço escrito à mão.
  • Como calcular subtotal, desconto, total e quanto falta para o frete com quatro $derived.
  • Como impedir quantidade zero ou negativa com Math.max.
  • Por que uma tabela em Svelte precisa de <tbody> em volta das linhas.
  • O que o compilador faz com o seletor td, th dentro do <style>.
  • As três sessões de terminal: dev, build e preview com curl.
  • O erro de compilação do <tr> e o erro de execução do toFixed.

1. A ideia: preço vezes quantidade

Todo carrinho é a mesma conta repetida: preço × quantidade, item por item, e a soma de tudo no fim. No caderno de fiado, a Ana faz essa conta com a calculadora e escreve o resultado à mão. No componente, ela escreve a conta uma vez e o resultado aparece — e continua certo quando a quantidade muda, porque ninguém digitou o total.

A diferença entre um contador e um carrinho é a quantidade de valores envolvidos. O contador tem um número; o carrinho tem uma lista de objetos, cada um com o seu preço e a sua quantidade, mais quatro números que dependem da lista inteira. O Svelte lida com isso do mesmo jeito que lidava com um número: você declara o que muda com $state e o que é calculado com $derived.

Existe uma armadilha específica de dinheiro que aparece já na primeira versão. O JavaScript guarda 0.9 como você escreveu, mas mostra 0.9 na tela — e a placa da padaria precisa de R$ 0,90 ou, no padrão do guia, R$ 0.90 com duas casas. Formatar é uma operação de exibição, não de cálculo: o valor guardado continua número, quem ganha casas é o texto.

2. Versão 1: a lista com preço cru

A primeira versão é só a lista desenhada. Sem controles, sem total: o objetivo é ver os dados na tela e descobrir o problema da formatação.

<script>
  let itens = $state([
    { nome: 'Pão francês', preco: 0.9, qtd: 6 },
    { nome: 'Sonho', preco: 4.5, qtd: 1 }
  ]);
</script>

<h1>Carrinho da padaria</h1>

<ul>
  {#each itens as item}
    <li>{item.qtd}× {item.nome} — R$ {item.preco}</li>
  {/each}
</ul>

A saída mostra o preço como o JavaScript escreve: 0.9 e 4.5. Para uma placa de padaria isso está errado, e não é culpa do Svelte — é o comportamento normal de número em JavaScript.

<h1>Carrinho da padaria</h1> <ul><li>6× Pão francês — R$ 0.9</li><li>1× Sonho — R$ 4.5</li></ul>

A anatomia da versão 1

let itens = $state([{ … }, { … }])
uma lista de objetos. As chaves { } aqui são as do JavaScript, não as do HTML: elas montam um valor com campos nomeados.
nome, preco, qtd
os campos de cada item. preco é número (sem aspas); nome é texto (com aspas).
item.qtd × item.nome
o ponto lê um campo do objeto. × e — são só texto decorativo no meio da frase.
{item.preco}
mostra o número como ele é. Nenhuma casa extra, nenhum símbolo de moeda automático — o R$ foi escrito por você, antes das chaves.

Missão: a linha mostra R$ 5.4 em vez de R$ 5.40. Formate o resultado da conta com duas casas decimais.

<script>
  let item = $state({ nome: 'Pão francês', preco: 0.9, qtd: 6 });
</script>

<p>{item.qtd}× {item.nome} — R$ {item.preco * item.qtd}</p>
<script>
  let item = $state({ nome: 'Pão francês', preco: 0.9, qtd: 6 });
</script>

<p>{item.qtd}× {item.nome} — R$ {(item.preco * item.qtd).toFixed(2)}</p>

Os parênteses em volta da conta são obrigatórios: sem eles, o ponto do toFixed grudaria no qtd — item.qtd.toFixed(2) formataria a quantidade e multiplicaria texto por número. O resultado seria outro, e o compilador não tem como saber que não era o que você queria.

3. Versão 2: quantidade, subtotal e total

A segunda versão acrescenta os controles e o total. Aqui aparece o reduce, que é o jeito de somar uma lista inteira sem escrever um laço: você entrega uma função que recebe a soma parcial e o item, e devolve a soma nova.

<script>
  let itens = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9, qtd: 6 },
    { id: 2, nome: 'Sonho', preco: 4.5, qtd: 1 }
  ]);

  let total = $derived(itens.reduce((soma, item) => soma + item.preco * item.qtd, 0));

  function mudarQtd(item, delta) {
    item.qtd = Math.max(1, item.qtd + delta);
  }

  function remover(id) {
    itens = itens.filter((item) => item.id !== id);
  }
</script>

<h1>Carrinho da padaria</h1>

{#each itens as item (item.id)}
  <p>
    {item.nome} — R$ {item.preco.toFixed(2)}
    <button onclick={() => mudarQtd(item, -1)}>-</button>
    {item.qtd}
    <button onclick={() => mudarQtd(item, 1)}>+</button>
    <button onclick={() => remover(item.id)}>remover</button>
  </p>
{/each}

<p>Total: R$ {total.toFixed(2)}</p>

O total já sai formatado e certo: seis pães a noventa centavos dão cinco e quarenta, mais um sonho de quatro e cinquenta, nove e noventa.

<h1>Carrinho da padaria</h1> <p>Pão francês — R$ 0.90 <button>-</button> 6 <button>+</button> <button>remover</button></p><p>Sonho — R$ 4.50 <button>-</button> 1 <button>+</button> <button>remover</button></p> <p>Total: R$ 9.90</p>

Repare que os botões não têm texto de valor: - e + são fixos. Quem muda é o número do meio, que vem de {item.qtd}. A função mudarQtd recebe o item inteiro, não o índice, e isso é o que permite usá-la dentro do {#each} sem se preocupar com a posição.

A anatomia da versão 2

itens.reduce((soma, item) => …, 0)
percorre a lista guardando uma soma parcial. O 0 no fim é o valor inicial; sem ele, reduce começaria pelo primeiro item e quebraria numa lista vazia.
item.qtd = Math.max(1, item.qtd + delta)
muda o campo de um objeto que está dentro de uma lista $state. O Svelte enxerga a mudança e atualiza só aquele trecho.
mudarQtd(item, -1)
passa o item e a direção. A mesma função serve aos dois botões, e a regra de "nunca menos de um" fica num lugar só.
{#each itens as item (item.id)}
a chave pelo id mantém cada linha ligada ao item certo quando a lista encolhe.

Missão: o botão soma um sonho, mas o total continua R$ 4.50. Faça o total acompanhar a quantidade.

<script>

</script>

O sintoma é sempre o mesmo: a quantidade muda e o total não. A causa é que a conta rodou uma vez, na montagem, e o resultado ficou guardado numa variável comum. $derived transforma essa conta numa conta que o Svelte reexecuta quando itens muda — inclusive quando muda um campo de um item da lista.

4. Versão 3: tabela, cupom e frete

A versão pronta é a que a Ana mostraria no balcão. Ela tem tabela com cabeçalho, um campo de cupom, o desconto de dez por cento quando o cupom é PAO10 e o aviso de quanto falta para o frete grátis. São quatro contas encadeadas: subtotal, desconto, total e falta.

<script>
  let itens = $state([
    { id: 1, nome: 'Pão francês', preco: 0.9, qtd: 6 },
    { id: 2, nome: 'Sonho', preco: 4.5, qtd: 1 }
  ]);
  let cupom = $state('');

  const freteMinimo = 30;

  let subtotal = $derived(itens.reduce((soma, item) => soma + item.preco * item.qtd, 0));
  let desconto = $derived(cupom.trim().toUpperCase() === 'PAO10' ? subtotal * 0.1 : 0);
  let total = $derived(subtotal - desconto);
  let faltaParaFrete = $derived(Math.max(0, freteMinimo - total));

  function mudarQtd(item, delta) {
    item.qtd = Math.max(1, item.qtd + delta);
  }

  function remover(id) {
    itens = itens.filter((item) => item.id !== id);
  }
</script>

5. O que muda quando a quantidade muda

Vale acompanhar a versão 3 passo a passo, porque é aqui que as quatro contas encadeadas mostram o valor delas. A tabela usa os valores iniciais do componente e o cupom vazio.

O encadeamento é a parte que costuma confundir. desconto depende de subtotal, total depende de subtotal e de desconto, e faltaParaFrete depende de total. O Svelte resolve a ordem sozinho: quando subtotal muda, ele recalcula o que depende dele na sequência certa, sem você ordenar as linhas. A única exigência é declarar cada $derived depois das variáveis que ele lê.

Quando a conta cresce, $derived com uma expressão comprida começa a ficar ilegível. Aí entra $derived.by, que aceita uma função com várias linhas e devolve o resultado no return. O comportamento é o mesmo; o que muda é o espaço para escrever a regra com calma.

6. Botão pequeno, dedo grande

Numa tabela de carrinho, os botões de mais e menos costumam ficar do tamanho de uma unha. No tablet da padaria, isso vira clique errado: a Ana quer dois pães e põe três. Duas decisões resolvem a maior parte do problema e nenhuma delas mexe na lógica.

A primeira é dar área de toque ao botão. Quarenta e quatro pixels é a medida que as diretrizes de acessibilidade recomendam para o dedo; no CSS do componente isso é min-width: 44px; min-height: 44px aplicado a button. Como o estilo é escopado, a regra vale só para os botões deste componente, e não estraga o resto do site.

A segunda é dizer, em palavras, o que cada botão faz. Um botão com - é lido por leitor de tela como "menos", e "menos" não informa de qual item. aria-label="tirar um pão francês" resolve — e como o rótulo depende do nome do item, ele entra no molde do {#each}: aria-label={"tirar um " + item.nome}, com chaves, do mesmo jeito que qualquer outro valor dinâmico.

8. Quando dá errado

O primeiro erro abaixo é de compilação e é específico de tabela. O segundo compila e quebra na hora de desenhar, porque é um erro de tipo — texto onde se esperava número. As duas mensagens foram copiadas das execuções.

Erro 1 — <tr> filho direto de <table>

Em HTML, o navegador "conserta" uma tabela malformada movendo elementos de lugar. O Svelte se recusa a compilar quando a estrutura é inválida, porque o conserto do navegador quebraria as contas dele sobre onde cada pedaço está.

<script>
  let itens = $state([{ id: 1, nome: 'Pão francês', preco: 0.9, qtd: 6 }]);
</script>

<table>
  <tr><th>Item</th><th>Preço</th></tr>
  {#each itens as item (item.id)}
    <tr><td>{item.nome}</td><td>R$ {item.preco.toFixed(2)}</td></tr>
  {/each}
</table>
Erro de compilação (linha 6, coluna 2): `<tr>` cannot be a child of `<table>`. `<table>` only allows these children: `<caption>`, `<colgroup>`, `<tbody>`, `<thead>`, `<tfoot>`, `<style>`, `<script>`, `<template>`. The browser will 'repair' the HTML (by moving, removing, or inserting elements) which breaks Svelte's assumptions about the structure of your components.

A correção é pôr as linhas dentro de <thead> e <tbody>, como na versão 3. A mensagem é longa porque explica o motivo, mas a lista de filhos permitidos já entrega a solução: <tr> não está nela, <tbody> está.

Erro 2 — preço guardado como texto

O preço foi escrito entre aspas, com vírgula: '0,90'. Isso é texto, e texto não tem toFixed. O arquivo compila — o compilador não olha o conteúdo dos dados — e a página quebra ao desenhar.

<script>
  let itens = $state([{ nome: 'Pão francês', preco: '0,90', qtd: 6 }]);
</script>

<ul>
  {#each itens as item}
    <li>{item.nome} — R$ {item.preco.toFixed(2)}</li>
  {/each}
</ul>
Erro ao renderizar: item.preco.toFixed is not a function

"is not a function" quer dizer que o valor existe, mas não é do tipo que tem aquele método. A cura é guardar número — preco: 0.9, sem aspas e com ponto — e deixar a vírgula só para o texto que aparece: se a Ana precisa ver R$ 0,90 com vírgula, troque o ponto na hora de mostrar, com .replace('.', ','), nunca no dado guardado.

Resumo

  • Um carrinho é uma lista de objetos com nome, preco e qtd, mais contas derivadas dela.
  • toFixed(2) formata dinheiro na hora de mostrar; o valor guardado continua número.
  • Conta com toFixed precisa de parênteses: {(a * b).toFixed(2)}.
  • reduce(fn, 0) soma a lista inteira; a semente 0 evita quebra com lista vazia.
  • Quatro $derived encadeados bastam para subtotal, desconto, total e frete.
  • Math.max(1, …) trava a quantidade mínima; Math.max(0, …) trava o frete.
  • Linhas de tabela ficam dentro de <tbody>; <tr> solto dentro de <table> não compila.
  • O seletor td, th vira dois seletores com o selo svelte-1n46o8q, e só os elementos atingidos ganham a classe.
  • Erros desta aula: `<tr>` cannot be a child of `<table>` e item.preco.toFixed is not a function.
