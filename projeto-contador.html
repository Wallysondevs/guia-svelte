Svelte · Projeto Contador

A Ana conta pães com um pedaço de giz num papelão: cada pão riscado é um traço, e a cada dez traços ela faz um risco maior. Funciona até alguém esbarrar no papelão. O sobrinho dela pendurou um tablet velho no balcão e pediu uma tela com dois botões: um que soma, um que zera. Esta aula é o primeiro projeto do guia, e ele aparece em três versões: a que funciona, a que não deixa a conta furar e a que ela mostraria para um cliente. Cada versão foi compilada e rodada de verdade, e o que você vê aqui é a saída real.

Você vai aprender
  • A montar um contador que soma e zera, começando pelo menor componente possível.
  • Por que $state é o que faz o número na tela acompanhar o clique.
  • Como impedir que a conta fique negativa com Math.max, e como parar no limite com Math.min.
  • O que $derived economiza quando um número depende de outro.
  • Como desligar um botão com o atributo disabled ligado a uma expressão.
  • Como ler um <select> com bind:value sem escrever ouvinte de evento.
  • O que muda num componente quando ele guarda uma lista ($state([])) e a empurra com push.
  • As três sessões de terminal do projeto: dev, build e preview.
  • Os dois erros que aparecem de verdade ao montar esse contador, com a mensagem do compilador.

1. A ideia antes do código: contar sem perder a conta

Contar é a operação mais antiga da padaria. A Ana não precisa de um programa para saber quantos pães vendeu às nove da manhã — precisa de um lugar onde o número não se perca. O papelão falha por três motivos: alguém esbarra, a caneta falha, e ninguém sabe se o traço que está ali é de hoje ou de ontem. Um contador na tela resolve os três de uma vez, porque o número fica guardado num lugar só e a tela mostra o que está guardado.

Repare que já existe uma separação importante nessa frase: o lugar onde o número fica guardado e a parte da tela que mostra o número. Em programação, o lugar chama-se estado (aquilo que pode mudar) e a parte da tela é o HTML. O trabalho do Svelte é manter os dois de acordo: você muda o estado, ele redesenha o pedaço de tela que usa aquele estado. Nenhum document.getElementById, nenhum innerHTML.

Um contador parece bobo, e é justamente por isso que ele serve de primeiro projeto. Ele tem tudo o que os projetos grandes têm, em miniatura: um valor que muda, um evento que muda o valor, um limite que não pode ser passado, um cálculo que depende do valor e um histórico do que aconteceu. Quem entende essas cinco peças num contador reconhece as mesmas cinco num carrinho de compras.

Na padariaNo componente
O número riscado no papelãolet cliques = $state(0)
Fazer mais um traçoonclick={() => cliques++}
Raspar o papelão e começar de novocliques = 0
O aviso "não passes de vinte"Math.min(maximo, …)
A régua que mostra quanto faltalet restantes = $derived(maximo - cliques)

O custo de fazer isso em Svelte é baixo: o arquivo inteiro cabe em quinze linhas. O custo de fazer isso em JavaScript puro é maior do que parece, porque você teria de criar o elemento, guardar uma referência, escrever o ouvinte de clique e atualizar o texto na mão — e lembrar de fazer o mesmo em cada lugar onde o número aparece.

2. Três versões, um mesmo problema

O guia inteiro segue a mesma escada: primeiro o componente que funciona, depois o que se comporta bem, depois o que se explica sozinho. Não é enfeite. Cada degrau resolve um problema que o anterior deixou aparecer, e é mais fácil aprender vendo o problema nascer do que recebendo a solução pronta.

VersãoO que ela resolveO que entra de novo
v1 — simplessomar e zerar$state, onclick, { }
v2 — melhornão deixa a conta furar: nem negativo, nem acima do limite$derived, Math.max, Math.min, disabled
v3 — prontao caixa escolhe o passo e vê o que já foi contadobind:value, lista em $state, função com parâmetro, <style>

As três versões ficam no mesmo arquivo do projeto, sempre chamado src/App.svelte. Trocar de versão é trocar o conteúdo do arquivo e salvar: o servidor de desenvolvimento recarrega sozinho. Guarde os três textos num lugar à mão (um bloco de notas serve) para poder voltar e comparar — comparar versões é o jeito mais rápido de aprender a ler código.

3. Versão 1: o menor contador que funciona

Comece pelo arquivo completo. Ele tem o bloco de script, dois parágrafos de HTML e dois botões. Nada mais:

<script>
  let cliques = $state(0);
</script>

<h1>Placar de pães</h1>
<p>Cliques: {cliques}</p>
<button onclick={() => cliques++}>+1</button>
<button onclick={() => (cliques = 0)}>zerar</button>

O compilador transforma esse arquivo no HTML abaixo. Note que o <script> desapareceu: quem monta a página é ele, e o valor que estava na variável já vem escrito no lugar certo.

<h1>Placar de pães</h1> <p>Cliques: 0</p> <button>+1</button> <button>zerar</button>

Se você lesse esse HTML sozinho, sem saber o que é Svelte, concluiria que a página mostra um zero fixo. É aí que entra a segunda metade: o navegador recebe também o JavaScript que liga o botão ao número. Quando o clique acontece, o valor muda e o trecho Cliques: 0 é reescrito. O HTML acima é o primeiro desenho, não o único.

A anatomia da versão 1

<script>
o bloco onde o estado nasce. Fica no topo e roda uma vez, quando o componente é criado.
let cliques = $state(0)
declara a variável cliques com valor inicial 0 e avisa o compilador de que ela pode mudar. $state é uma runa: uma palavra que só existe dentro de arquivos .svelte.
{cliques}
o buraco no HTML por onde o valor entra. Toda vez que o valor muda, o Svelte reescreve só esse pedaço.
onclick={() => cliques++}
o atributo de evento. A função da direita roda no clique; cliques++ soma um ao valor guardado.
onclick={() => (cliques = 0)}
a mesma ideia, atribuindo outro valor. Os parênteses em volta mantêm a seta e a atribuição na mesma linha.

O nome do atributo é o nome do evento com on na frente, tudo em minúsculas: onclick, oninput, onsubmit. Quem vem de versões antigas do Svelte escreve on:click, com dois pontos. Essa forma ainda compila nesta versão, mas o compilador avisa que ela está fora de moda — é o primeiro assunto da próxima caixa.

Missão: o botão soma, mas a tela continua mostrando Cliques: 0 · dobro: 0. Faça o número subir para 1 e o dobro para 2 com um clique.

<script>
  let cliques = 0;
  let dobro = $derived(cliques * 2);
</script>

<p>Cliques: {cliques} · dobro: {dobro}</p>
<button onclick={() => cliques++}>+1</button>
<script>
  let cliques = $state(0);
  let dobro = $derived(cliques * 2);
</script>

<p>Cliques: {cliques} · dobro: {dobro}</p>
<button onclick={() => cliques++}>+1</button>

O que aconteceu ali merece nome. A variável existia, o clique rodava, o valor dentro dela até mudava — mas nada avisava a tela. Sem $state, uma variável é uma caixa muda. Com $state, ela é uma caixa que avisa. É a diferença entre escrever o preço num papel e escrever numa lousa com alguém de plantão.

4. Versão 2: o limite e o botão que desliga

A versão 1 tem um defeito que a Ana descobriria no primeiro dia: o botão de menos não existe, e o de mais não tem fim. Se o tablet ficar na mão de uma criança, o número chega a quatrocentos. A versão 2 põe dois limites — nunca abaixo de zero, nunca acima de dez — e mostra quanto falta:

<script>
  let cliques = $state(0);
  const maximo = 10;

  let restantes = $derived(maximo - cliques);
</script>

<h1>Placar de pães</h1>
<p>Cliques: {cliques} de {maximo} · faltam {restantes}</p>

<button onclick={() => (cliques = Math.max(0, cliques - 1))} disabled={cliques === 0}>-1</button>
<button onclick={() => (cliques = Math.min(maximo, cliques + 1))} disabled={cliques === maximo}>+1</button>
<button onclick={() => (cliques = 0)}>zerar</button>

A saída real mostra o começo da contagem e, no HTML, um detalhe que não aparece na tela: o botão de menos já vem com o atributo disabled vazio, porque zero é o limite de baixo. Atributo vazio em HTML quer dizer "ligado".

<h1>Placar de pães</h1> <p>Cliques: 0 de 10 · faltam 10</p> <button disabled="">-1</button> <button>+1</button> <button>zerar</button>

Duas runas novas aparecem aqui. $derived diz "este valor não é guardado: ele é calculado a partir de outro, e deve ser recalculado quando o outro mudar". const maximo = 10 continua sendo uma constante comum — ela não muda, então não precisa avisar ninguém. A regra prática: o que muda vira $state, o que é calculado a partir do que muda vira $derived, o que nunca muda fica const.

A anatomia da versão 2

const maximo = 10
uma constante de configuração. Fica fora do estado de propósito: ninguém muda o limite pelo clique, então não há o que avisar.
$derived(maximo - cliques)
o valor é recalculado sempre que cliques muda. Você escreve a conta uma vez e nunca mais precisa lembrar de atualizar restantes na mão.
Math.max(0, cliques - 1)
devolve o maior entre os dois números. Com 0 na frente, o resultado nunca fica negativo: se cliques for zero, a conta dá -1, e Math.max escolhe o 0.
Math.min(maximo, cliques + 1)
o espelho: devolve o menor entre os dois, então o número para em 10 mesmo que alguém clique mais.
disabled={cliques === 0}
o atributo recebe uma expressão. Quando ela é verdadeira, o HTML ganha disabled e o botão não recebe clique; quando é falsa, o atributo some.

Repare que existem duas proteções para o mesmo problema, e as duas são necessárias. A conta com Math.max é a proteção de verdade: mesmo que o clique chegue, o valor não passa do limite. O disabled é a proteção visível: o botão fica apagado e a Ana entende, sem tentar, que ali não há mais o que somar. Programas bons costumam ter as duas — a regra no cálculo e o aviso na tela.

Missão: o botão de menos está deixando a conta ficar -1. Faça o valor parar em 0 quando alguém clicar nele.

<script>
  let cliques = $state(0);
</script>

<p>Cliques: {cliques}</p>
<button id="menos" onclick={() => cliques--}>-1</button>
<script>
  let cliques = $state(0);
</script>

<p>Cliques: {cliques}</p>
<button id="menos" onclick={() => (cliques = Math.max(0, cliques - 1))}>-1</button>

O seletor #menos na meta da caixa aponta para o botão pelo id. É assim que o guia diz "clique neste botão e não naquele" quando o componente tem mais de um. Você vai usar o mesmo truque nos seus testes manuais: um id em cada botão que precisa ser encontrado.

5. Versão 3: passo, histórico e estilo

A versão pronta é a que a Ana deixaria no balcão. Ela acrescenta três coisas que parecem pequenas e mudam o uso: o passo (contar de dois em dois, de cinco em cinco, como ela faz com os pães de fermentação longa), o histórico do que já foi contado e uma faixa verde na lateral para o placar não se confundir com o resto da tela.

<script>
  let cliques = $state(0);
  let passo = $state(1);
  let historico = $state([]);

  const maximo = 20;
  let restantes = $derived(maximo - cliques);
  let podeSomar = $derived(cliques < maximo);
  let podeSubtrair = $derived(cliques > 0);

  function mover(direcao) {
    const novo = Math.min(maximo, Math.max(0, cliques + direcao * passo));
    if (novo === cliques) return;
    cliques = novo;
    historico.push(novo);
  }
</script>

<div class="placar">
  <h1>Placar de pães</h1>
  <p>Cliques: <strong>{cliques}</strong> de {maximo} · faltam {restantes}</p>
</div>

<label>
  Passo
  <select bind:value={passo}>
    <option value={1}>1</option>
    <option value={2}>2</option>
    <option value={5}>5</option>
  </select>
</label>

<button onclick={() => mover(-1)} disabled={!podeSubtrair}>-{passo}</button>
<button onclick={() => mover(1)} disabled={!podeSomar}>+{passo}</button>
<button onclick={() => (cliques = 0, historico = [])}>zerar</button>

{#if historico.length > 0}
  <p>Histórico: {historico.join(' → ')}</p>
{:else}
  <p>Nenhum clique ainda.</p>
{/if}

<style>
  .placar {
    border-left: 4px solid #2e7d32;
    padding-left: 12px;
  }
  p {
    margin: 4px 0;
  }
</style>

O HTML gerado mostra o selo do escopo em dois lugares — na div e no p — e o <select> já vem com a primeira opção marcada, porque passo vale 1:

<div class="placar svelte-1n46o8q"><h1>Placar de pães</h1> <p class="svelte-1n46o8q">Cliques: <strong>0</strong> de 20 · faltam 20</p></div> <label>Passo <select><option value="1" selected="">1</option><option value="2">2</option><option value="5">5</option></select></label> <button disabled="">-1</button> <button>+1</button> <button>zerar</button> <p class="svelte-1n46o8q">Nenhum clique ainda.</p>

E este é o CSS que o compilador gerou para o bloco <style>. O svelte-1n46o8q é o selo deste arquivo: ele aparece tanto no seletor quanto nas tags, e é o que impede que o p da padaria pinte os parágrafos do resto do site.

.placar.svelte-1n46o8q {
    border-left: 4px solid #2e7d32;
    padding-left: 12px;
  }
  p.svelte-1n46o8q {
    margin: 4px 0;
  }

Há três ideias novas nesta versão. A primeira é historico.push(novo): um array guardado em $state continua reativo quando você o modifica no lugar, sem precisar criar outro array. A segunda é bind:value={passo}: o <select> e a variável ficam ligados nos dois sentidos, e o valor que chega é número porque as <option> usam value={1} com chaves, não value="1" com aspas. A terceira é a função mover(direcao), que recebe -1 ou 1 e faz a conta uma vez só, em vez de repetir a expressão em dois botões.

Missão: depois de um clique, o placar mostra Cliques: 1 mas continua dizendo faltam 10. Faça o número que falta acompanhar a contagem.

<script>
  let cliques = $state(0);
  const maximo = 10;
  let faltam = maximo - cliques;
</script>

<p>Cliques: {cliques} · faltam {faltam}</p>
<button onclick={() => cliques++}>+1</button>
<script>
  let cliques = $state(0);
  const maximo = 10;
  let faltam = $derived(maximo - cliques);
</script>

<p>Cliques: {cliques} · faltam {faltam}</p>
<button onclick={() => cliques++}>+1</button>

A conta maximo - cliques está certa nas duas versões do código. O que muda é quando ela é feita: sem $derived, ela roda uma vez, quando o componente nasce, e o resultado fica congelado. Com $derived, o Svelte anota de quais valores a conta depende e refaz quando algum deles muda.

6. O que o navegador mostra a cada clique

Uma tabela vale mais que três parágrafos quando o assunto é comportamento. Abaixo, o texto que aparece na tela da versão 3 depois de cada ação, na ordem em que a Ana usaria o tablet. A coluna da direita é o que o estado guarda naquele momento.

AçãoTexto na telaEstado
abrir a páginaCliques: 0 de 20 · faltam 20cliques = 0, histórico vazio
um clique em +1Cliques: 1 de 20 · faltam 19cliques = 1, histórico [1]
escolher passo 5 e clicar em -5Cliques: 0 de 20 · faltam 20 — o botão de menos apagacliques = 0, histórico [1, 0]
passo 5 e quatro cliques em +5Cliques: 20 de 20 · faltam 0 — o botão de mais apagacliques = 20, histórico com cinco números
zerarCliques: 0 de 20 · faltam 20 e Nenhum clique ainda.cliques = 0, histórico []

Duas coisas dessa tabela não são óbvias e valem a explicação. A primeira: quando o passo é 5 e o valor é 18, o botão de mais leva a 20, não a 23 — o Math.min corta no teto. A segunda: zerar aparece com duas atribuições separadas por vírgula dentro dos parênteses. A vírgula executa as duas, da esquerda para a direita, e o valor da expressão é o da última. Quando o corpo da função cresce, é hora de trocar a seta por uma function de verdade, como mover faz.

7. As três sessões de terminal do projeto

O projeto da Ana tem três comandos, e cada um serve a um momento diferente. O primeiro é o do dia a dia, enquanto se escreve o código:

ana@notebook:~/loja$ npm run dev

> padaria@0.0.1 dev
> vite

A linha ready in 562 ms é o tempo que o Vite levou para preparar a primeira versão da página. Depois disso ele não prepara mais nada do zero: cada arquivo salvo vira uma atualização pequena, e o navegador mostra o resultado em menos de um segundo. O endereço localhost:5173 só existe na sua máquina — nada foi publicado na internet.

8. Quando dá errado

Os dois erros abaixo saíram do compilador desta versão, copiados como estão. O primeiro é o mais comum de todos quando se usa <select>, e o segundo é o que aparece quando alguém cola um exemplo antigo de tutorial.

Erro 1 — bind apontando para um nome que não existe

O <select> foi ligado a passos, no plural, mas a variável declarada é passo. O compilador não tenta adivinhar: ele exige que o alvo do bind seja estado ou propriedade declarada.

<script>
  let passo = $state(1);
</script>

<select bind:value={passos}>
  <option value={1}>1</option>
  <option value={2}>2</option>
</select>
Erro de compilação (linha 5, coluna 20): Can only bind to state or props

A tradução: "só posso ligar a um estado ou a uma propriedade". A linha e a coluna apontam para o lugar exato do nome errado, dentro das chaves. Corrigir é trocar passos por passo — e vale conferir se a variável foi declarada com $state, porque bind em variável comum também cai nesta mesma mensagem.

Erro 2 — export let num componente com runas

Este arquivo mistura os dois mundos: usa $state (runas) e também export let (a forma antiga de declarar propriedade). O Svelte 5 não aceita a mistura.

<script>
  let cliques = $state(0);
  export let maximo = 10;
</script>

<p>Cliques: {cliques} de {maximo}</p>
Erro de compilação (linha 3, coluna 2): Cannot use `export let` in runes mode — use `$props()` instead

"Cannot use export let in runes mode" quer dizer que, num componente que já usa runas, a porta de entrada de valores de fora é $props(). Se o contador fosse um componente reutilizável, ele começaria com let { maximo = 10 } = $props(). Repare que o erro aponta a linha 3 e a coluna 2 — o começo da declaração, não o fim do arquivo.

Resumo

  • Um contador é estado ($state), um evento que muda o estado (onclick) e um buraco na tela que mostra o estado ({ }).
  • A versão 1 é a menor que funciona: sete linhas de Svelte e dois botões.
  • A versão 2 põe limites com Math.max e Math.min e desliga o botão com disabled; a regra fica no cálculo, o aviso fica na tela.
  • A versão 3 acrescenta passo com bind:value, histórico em $state([]) e um bloco <style> com selo svelte-1n46o8q.
  • $derived é para o que é calculado a partir do que muda; const é para o que nunca muda.
  • npm run dev serve em localhost:5173; npm run build gera dist/ e informa o tamanho comprimido; npm run preview serve o build em localhost:4173.
  • O build deixa dist/index.html e um único JS com hash no nome; abrir o arquivo por file:// não funciona.
  • Os erros desta aula: Can only bind to state or props e Cannot use `export let` in runes mode.
  • Antes de publicar, rode as três versões e clique em tudo — inclusive no botão que já deveria estar desligado.
