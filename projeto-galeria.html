Svelte · Projeto Galeria

A Ana fotografou a vitrine com o celular e quer mostrar as fotos no site. Uma lista de três imagens lado a lado não serve: ela quer que a cliente toque numa miniatura e veja a foto grande, com uma animação que não pareça um estalo. Esta aula monta a galeria em três versões: a grade que troca a foto, a caixa que abre com transição e a versão com teclado, contador e botões. Cada versão foi compilada e rodada de verdade, e as caixas abaixo rodam no seu navegador.

Você vai aprender
  • Como guardar a foto escolhida num estado e mostrar a certa na tela.
  • Como ligar cada miniatura ao índice que ela representa.
  • O que uma função de transição devolve: duração e CSS.
  • Como abrir e fechar uma caixa com {#if} e transition:.
  • Por que o servidor manda o HTML sem a caixa e o navegador a cria no clique.
  • Como usar {#key} para animar a troca de foto.
  • Como dar a volta na lista com o operador de resto (%).
  • Como ler o teclado com <svelte:window> no lugar certo.
  • O que o build e o preview mostram quando a galeria está pronta.
  • Os dois erros reais de transição e de animação, com a mensagem do compilador.

1. A ideia: uma foto de cada vez

A vitrine da Ana cabe numa parede, mas não cabe numa tela de celular. Se as três fotos aparecerem lado a lado, cada uma fica do tamanho de um selo. A solução é a mesma de um álbum: uma foto grande no centro e as outras em miniatura, esperando a vez. Tocar numa miniatura troca a foto grande — e a cliente vê o detalhe que queria sem abrir outra página.

O estado da galeria é um número: o índice da foto escolhida. Zero é a primeira, um é a segunda, dois é a terceira. O HTML lê esse número e mostra a foto correspondente. Quando o número muda, a tela muda. Todo o resto — a grade, a caixa preta, os botões — é desenho em volta desse número.

O custo aparece quando a galeria cresce. Com três fotos, o índice é fácil de conferir. Com trezentas, você precisa de rolagem, de carregamento sob demanda e de uma forma de voltar ao começo. Esta aula fica nas três primeiras, mas escreve o código de um jeito que não precisa ser jogado fora quando a quarta chegar: a lista é um array, e o índice é calculado, não escrito à mão.

2. Três versões, um mesmo problema

As três versões resolvem o mesmo pedido com níveis diferentes de cuidado. A primeira prova que a troca funciona. A segunda transforma a foto grande numa caixa que abre por cima da página. A terceira deixa a cliente navegar sem voltar para a grade.

VersãoO que resolveO que entra de novo
v1 — simplestrocar a foto grande pela miniatura$state, {#each}, style com variável CSS
v2 — melhorver a foto por cima, com animação de entrada e saídatransition:, função de transição, {#if}
v3 — prontapassar para a próxima sem fechar a caixa{#key}, $derived, %, <svelte:window>

As três versões moram no mesmo arquivo, src/App.svelte, uma de cada vez. Guarde as anteriores num bloco de notas: comparar o antes e o depois é o jeito mais rápido de entender o que cada linha nova resolve.

3. Versão 1: a grade e a foto grande

Comece pelo arquivo inteiro. Ele tem a lista de fotos, o índice escolhido, a foto grande e a grade de miniaturas. Cada "foto" é um retângulo colorido com o título — assim a aula não depende de arquivo de imagem e o comportamento fica visível:

<script>
  const fotos = [
    { titulo: 'Pão na vitrine', cor: '#f4c17a' },
    { titulo: 'Bolo de cenoura', cor: '#d98e63' },
    { titulo: 'Café da manhã', cor: '#9fc4a6' }
  ];
  let escolhida = $state(0);
</script>

<h1>Galeria da padaria</h1>

</div>

    <button
      style="--cor: {foto.cor}"
      aria-label="ver {foto.titulo}"
      onclick={() => (escolhida = i)}

O texto tem o título e a legenda, nessa ordem. As miniaturas são botões vazios: o conteúdo delas é a cor de fundo, e o nome vem do aria-label, que não aparece na tela mas é anunciado pelo leitor de tela. Um detalhe importante: o HTML que o servidor manda é o primeiro desenho, com o índice zero. Os outros dois só existem depois do clique.

A anatomia da versão 1

const fotos = [ … ]
a lista não muda, então é const. Cada item tem titulo e cor; um objeto com dois campos é mais fácil de ler do que dois arrays paralelos.
let escolhida = $state(0)
o único valor que muda: o índice da foto no palco. Começa em zero, a primeira da lista.
{fotos[escolhida].titulo}
o colchete busca o item pela posição. Se escolhida for 1, o título é o do bolo; se for 2, o do café.
{#each fotos as foto, i}
o bloco repete a miniatura para cada foto. O segundo nome, i, é o índice da repetição — é ele que o clique guarda.
style="--cor: {foto.cor}"
uma variável CSS vinda do JavaScript. O CSS usa var(--cor) e cada miniatura ganha a sua cor sem uma classe por foto.

O style com variável é o truque que evita escrever três regras de CSS iguais. O valor entra como texto, e o navegador o trata como uma propriedade daquele elemento. Se a cor vier de um dado, esse é o caminho — e não um class="cor-1" por foto.

4. Versão 2: a caixa que abre com transição

A versão 1 troca a foto no lugar. A versão 2 abre uma caixa por cima da página, com fundo escuro, e anima a entrada. O código novo é uma função e um bloco:

<script>
  const fotos = [
    { titulo: 'Pão na vitrine', cor: '#f4c17a' },
    { titulo: 'Bolo de cenoura', cor: '#d98e63' },
    { titulo: 'Café da manhã', cor: '#9fc4a6' }
  ];
  let aberta = $state(null);

  function surgir() {
    return {
      duration: 300,
      css: (t) => `opacity: ${t}; transform: scale(${0.92 + 0.08 * t})`
    };
  }
</script>

<h1>Galeria da padaria</h1>

<div class="grade">
  {#each fotos as foto, i}
    <button
      style="--cor: {foto.cor}"
      aria-label="abrir {foto.titulo}"
      onclick={() => (aberta = i)}
    ></button>
  {/each}
</div>

{#if aberta !== null}
  <div class="fundo" transition:surgir>
    <figure>
      <div class="foto-grande" style="--cor: {fotos[aberta].cor}"></div>
      <figcaption>{fotos[aberta].titulo}</figcaption>
    </figure>
    <button id="fechar" onclick={() => (aberta = null)}>fechar</button>
  </div>
{/if}

<style>

  .grade button { width: 64px; height: 64px; background: var(--cor); border: 0; }

O texto inicial é só o título. A caixa não existe no HTML até alguém clicar:

Galeria da padaria

Essa ausência é intencional. O {#if aberta !== null} só desenha o bloco quando a condição é verdadeira, e no servidor ela começa falsa. O servidor não vê transição nenhuma: ele manda o HTML, e a animação é assunto do navegador. Quem confere a transição é o olho — ou a caixa desta aula, que espera o tempo da animação antes de conferir o texto.

A anatomia da transição

let aberta = $state(null)
null quer dizer "nenhuma foto aberta". Zero seria uma foto válida, e por isso a comparação é !== null, não uma condição de verdadeiro e falso.
function surgir()
a transição é uma função que devolve uma configuração. O Svelte a chama quando o elemento entra e quando sai.
duration: 300
quanto tempo a animação dura, em milissegundos. Curta demais parece um estalo; longa demais atrapalha quem quer fechar.
css: (t) => …
a função que recebe t, um número de 0 a 1, e devolve o CSS daquele instante. No começo é 0; no fim, 1.
transition:surgir
liga a função ao elemento. Ela vale para a entrada e para a saída; se você quiser comportamentos diferentes, use in: e out:.

A função css é o coração. opacity: ${t} faz a caixa aparecer devagar. scale(${0.92 + 0.08 * t}) começa em 92% do tamanho e chega a 100%. A conta é escrita uma vez; o Svelte a chama sessenta vezes por segundo enquanto a transição roda.

Transição não é enfeite de tempo

Uma animação de 300 ms muda a percepção de continuidade: a cliente entende que a foto veio de algum lugar, e não que a tela piscou. Acima de 500 ms, a mesma animação começa a parecer lenta. O tempo é uma decisão de quem usa, não de quem programa.

5. Versão 3: navegação, teclado e contador

A versão pronta deixa a cliente passar de foto em foto sem fechar a caixa. Ela acrescenta três coisas: os botões de anterior e próxima, o contador de posição e a leitura do teclado. A troca é animada por {#key}.

<script>
  const fotos = [
    { titulo: 'Pão na vitrine', cor: '#f4c17a' },
    { titulo: 'Bolo de cenoura', cor: '#d98e63' },
    { titulo: 'Café da manhã', cor: '#9fc4a6' }
  ];
  let aberta = $state(false);
  let atual = $state(0);
  let total = $derived(fotos.length);

  function ir(passo) {
    atual = (atual + passo + total) % total;
  }

  function surgir() {
    return {
      duration: 250,
      css: (t) => `opacity: ${t}; transform: translateY(${(1 - t) * 12}px)`
    };
  }
</script>

<svelte:window
  onkeydown={(evento) => {
    if (!aberta) return;
    if (evento.key === 'Escape') aberta = false;
    if (evento.key === 'ArrowRight') ir(1);
    if (evento.key === 'ArrowLeft') ir(-1);
  }}
/>

        atual = i;

Três ideias novas nesta versão. A primeira é {#key atual}: quando o índice muda, o Svelte joga fora o bloco antigo e cria outro, e é isso que dispara a transição de entrada. Sem a chave, o mesmo elemento seria atualizado no lugar, sem animação. A segunda é (atual + passo + total) % total: somar o total antes evita índice negativo quando o passo é -1; o resto da divisão traz o número de volta para a faixa. A terceira é <svelte:window onkeydown>, que ouve o teclado na janela inteira — e por isso precisa checar if (!aberta) return, para não interceptar as setas quando a caixa está fechada.

Missão: abra a primeira foto e clique em anterior. A galeria deve dar a volta e mostrar a última, com o contador 3 de 3.

6. O caminho de um clique

Uma tabela vale mais que três parágrafos quando o assunto é ordem. Abaixo, o que acontece na versão 3 desde o toque na miniatura até o contador mudar:

PassoO que mudaO que a tela mostra
abrir a páginaaberta = false, atual = 0só a grade e o título
tocar na segunda miniaturaatual = 1, aberta = truecaixa escura com o bolo, 2 de 3
tocar em próximaatual = 2café da manhã, 3 de 3; o bloco é recriado e anima
tocar em próxima de novoatual = 0pão na vitrine, 1 de 3
tocar em anterior no primeiroatual = 2café da manhã, 3 de 3
apertar Escaberta = falsea caixa sai com a transição e some

Repare que o contador mostra atual + 1, e não atual. O índice começa em zero porque arrays começam em zero; a pessoa começa em um porque aprendeu assim. A conversão é feita na hora de mostrar, não no estado — guardar o número já somado faria a conta do resto errar.

8. Quando dá errado

Os dois erros abaixo vieram do compilador desta versão, copiados como estão. Os dois são de animação, e os dois aparecem quando a galeria começa a reordenar ou a combinar efeitos.

Erro 1 — animate:flip num {#each} sem chave

O flip anima a troca de posição dos itens, mas só funciona quando o bloco sabe identificar cada item. Sem a chave, o compilador recusa.

<script>
  import { flip } from 'svelte/animate';
  let fotos = $state(['pão', 'bolo', 'café']);
</script>

{#each fotos as foto}
  <p animate:flip>{foto}</p>
{/each}
Erro de compilação (linha 7, coluna 5): An element that uses the `animate:` directive must be the only child of a keyed `{#each ...}` block. Did you forget to add a key to your each block?

A tradução: "um elemento que usa a diretiva animate: tem de ser o único filho de um bloco {#each} com chave. Você esqueceu de adicionar a chave?". O conserto é {#each fotos as foto (foto.titulo)} — o parêntese no fim identifica cada item. Na galeria, a chave natural é o título ou um id; nunca use o índice, porque ele muda quando a lista é reordenada.

Erro 2 — transition: junto com in:

Um elemento pode ter uma transição geral ou um par de entrada e saída, mas não as duas coisas ao mesmo tempo. O compilador aponta a coluna exata.

<script>
  function surgir() {
    return { duration: 300, css: (t) => `opacity: ${t}` };
  }
</script>

{#if true}
  <p transition:surgir in:surgir>oi</p>
{/if}
Erro de compilação (linha 8, coluna 23): Cannot use `transition:` alongside existing `in:` directive

Se você quer entradas e saídas diferentes, escolha in:surgir e out:sumir, com duas funções. Se quer a mesma animação nos dois sentidos, use só transition:surgir. O erro não é de sintaxe: é de intenção — o compilador não sabe qual das duas diretivas deve valer.
