Projetos · Painel com Filtros

Na parede da padaria, a Ana pendura um quadro com os produtos mais vendidos da semana. Ela olha aquele quadro antes de encomendar farinha. O problema é que o quadro é de papel: para ver só os bolos, ela precisa passar o dedo por cima da lista inteira. Nesta aula o quadro vira uma tela com busca, filtro por categoria e ordenação — em três versões, cada uma rodando de verdade. Você vai ver a saída do compilador e o que o navegador mostrou a cada clique.

Você vai aprender
  • A diferença entre um dado de estado e um dado derivado.
  • Como filtrar uma lista com filter e includes.
  • Por que comparar texto sem baixar a caixa nunca encontra o que se procura.
  • Como três filtros se somam sem virar um emaranhado de if.
  • O que reduce faz e por que ele é o irmão de filter.
  • Quando usar $derived.by em vez de $derived.
  • Como ordenar sem estragar a lista original.
  • O que mostrar quando nenhum produto passa pelos filtros.
  • O que fazer quando a porta 5173 já está ocupada.
  • As três mensagens de erro que este painel provoca de verdade.

1. O quadro de vendas e a pergunta certa

Quem trabalha com números faz sempre duas perguntas diferentes. A primeira é "quais são os dados?" — a lista de produtos, com nome, categoria e quantidade vendida. A segunda é "quais desses eu quero ver agora?" — só os bolos, só o que vendeu mais de cinquenta, só o que acabou no estoque. A lista de dados quase nunca muda; a pergunta muda o tempo todo.

Separar as duas é o que torna o painel fácil de escrever. Os dados ficam guardados uma vez, e cada pergunta vira uma expressão derivada: um valor calculado a partir dos dados e das escolhas do usuário. No Svelte 5, essa expressão é $derived. Ela não guarda memória própria — ela se recalcula quando algo de que depende muda.

Na padariaNo componente
O caderno com todos os produtosA lista produtos
O dedo da Ana passando pela listaO filtro em $derived
A palavra escrita no papel de buscabusca, criada com $state
O total somado no fim do diareduce dentro de outro $derived
Reordenar a lista do maior para o menorsort antes de devolver

Repare no vocabulário, porque ele volta o resto da aula. Estado é o que o usuário controla: o texto da busca, a categoria escolhida, a ordem. Derivado é o que o computador calcula a partir do estado: a lista visível, o total vendido, a contagem. Quem tenta guardar o derivado num $state acaba com dois valores que discordam entre si na primeira atualização.

2. Versão 1 — a lista e a busca

A primeira versão tem uma caixa de busca e uma lista. A lista mostra o resultado do filtro, e o filtro lê o texto digitado. São quatro produtos fixos, porque o objetivo aqui é entender o mecanismo antes de plugar uma fonte de dados de verdade.

<script>
  let busca = $state('');

  let produtos = [
    { id: 1, nome: 'Pão francês', categoria: 'pães', vendidos: 120 },
    { id: 2, nome: 'Bolo de chocolate', categoria: 'bolos', vendidos: 34 },
    { id: 3, nome: 'Pão de queijo', categoria: 'salgados', vendidos: 88 },
    { id: 4, nome: 'Bolo de cenoura', categoria: 'bolos', vendidos: 21 }
  ];

  let visiveis = $derived(
    produtos.filter((p) => p.nome.includes(busca))
  );
</script>

<input bind:value={busca} placeholder="Buscar produto">

<ul>
  {#each visiveis as produto (produto.id)}
    <li>{produto.nome} — {produto.vendidos} vendidos</li>
  {/each}
</ul>

Com a busca vazia, includes('') é verdadeiro para todo texto — então todos os produtos passam. O compilador entrega a lista completa:

<input value="" placeholder="Buscar produto"/> <ul><li>Pão francês — 120 vendidos</li><li>Bolo de chocolate — 34 vendidos</li><li>Pão de queijo — 88 vendidos</li><li>Bolo de cenoura — 21 vendidos</li></ul>

O undefined que você poderia temer não aparece: não há classe, não há atributo estranho. O {#each} desenhou quatro <li> e o $derived não deixou rastro no HTML — ele é cálculo, não marcação.

A anatomia da versão 1

let busca = $state('')
o texto digitado. É estado porque quem muda é o usuário.
let produtos = [...]
a lista de dados. Aqui é uma constante de exemplo; num app de verdade viria de um arquivo ou de uma API.
let visiveis = $derived(...)
a lista filtrada. Não é estado: ninguém atribui valor a ela, ela se recalcula.
produtos.filter((p) => ...)
percorre a lista e devolve uma lista nova só com os itens em que a função devolveu verdadeiro.
p.nome.includes(busca)
verdadeiro quando o nome contém o texto da busca. É a busca "em qualquer pedaço", não só no começo.
{#each visiveis as produto (produto.id)}
o parêntese no fim é a chave: o Svelte usa o id para saber qual item é qual quando a lista muda de ordem.

O custo desta versão aparece no primeiro uso real. A busca diferencia maiúsculas: digitar PÃO não encontra Pão francês. E não há como ver só os bolos. É o que as versões 2 e 3 resolvem.

3. Estado × derivado

A confusão mais comum de quem começa é tratar o resultado do filtro como estado. Se você escrever let visiveis = $state(produtos) e tentar atualizar a lista dentro de uma função, cria duas fontes de verdade: a lista original e a filtrada. Na primeira vez que alguém esquecer de atualizar uma delas, a tela mostra um número e a lista mostra outro.

PerguntaRespostaComo escrever
Quem muda este valor?o usuário, digitando ou clicando$state
Quem muda este valor?o próprio código, a partir de outro valor$derived
Preciso atribuir a este valor?sim$state
Preciso atribuir a este valor?não, só ler$derived

Missão: digitar PÃO em maiúsculas não encontra nada. Faça a busca ignorar maiúsculas e minúsculas e encontrar "Pão francês".

<script>
  let busca = $state('');
  let produtos = ['Pão francês', 'Bolo de chocolate', 'Pão de queijo'];
  let visiveis = $derived(produtos.filter((p) => p.includes(busca)));
</script>

<input bind:value={busca} placeholder="Buscar">

<ul>
  {#each visiveis as p}
    <li>{p}</li>
  {/each}
</ul>
<script>
  let busca = $state('');
  let produtos = ['Pão francês', 'Bolo de chocolate', 'Pão de queijo'];
  let visiveis = $derived(
    produtos.filter((p) => p.toLowerCase().includes(busca.toLowerCase()))
  );
</script>

<input bind:value={busca} placeholder="Buscar">

<ul>
  {#each visiveis as p}
    <li>{p}</li>
  {/each}
</ul>

A solução baixa a caixa dos dois lados: o nome do produto e o texto digitado. Baixar só um lado não resolve — é a comparação que precisa acontecer entre iguais. Esse mesmo cuidado vale para acentos: Pão não é igual a Pao, e resolver isso exige normalizar o texto antes de comparar.

4. Versão 2 — três filtros que se somam

A segunda versão acrescenta categoria, um aviso de estoque e dois números no topo. O segredo está no corpo do filter: cada condição que reprova o produto faz return false na hora. Quem sobrevive a todas as condições chega ao return true do fim.

<script>
  let busca = $state('');
  let categoria = $state('todas');
  let soAcabou = $state(false);

  let produtos = [
    { id: 1, nome: 'Pão francês', categoria: 'pães', vendidos: 120, estoque: 40 },
    { id: 2, nome: 'Bolo de chocolate', categoria: 'bolos', vendidos: 34, estoque: 0 },
    { id: 3, nome: 'Pão de queijo', categoria: 'salgados', vendidos: 88, estoque: 12 },
    { id: 4, nome: 'Bolo de cenoura', categoria: 'bolos', vendidos: 21, estoque: 0 }
  ];

  let visiveis = $derived(
    produtos.filter((p) => {
      if (!p.nome.toLowerCase().includes(busca.toLowerCase())) return false;
      if (categoria !== 'todas' && p.categoria !== categoria) return false;
      if (soAcabou && p.estoque > 0) return false;
      return true;
    })
  );

  let totalVendido = $derived(
    visiveis.reduce((soma, p) => soma + p.vendidos, 0)
  );
</script>

<div class="filtros">
  <input bind:value={busca} placeholder="Buscar produto">
  <select bind:value={categoria}>
    <option value="todas">todas as categorias</option>
    <option value="pães">pães</option>
    <option value="bolos">bolos</option>
    <option value="salgados">salgados</option>
  </select>
  <label><input type="checkbox" bind:checked={soAcabou}> só o que acabou</label>
</div>

<p class="resumo">{visiveis.length} produto(s) · {totalVendido} vendidos</p>

{#if visiveis.length === 0}
  <p>Nenhum produto com esses filtros.</p>
{:else}
  <ul>
    {#each visiveis as produto (produto.id)}
      <li class:acabou={produto.estoque === 0}>
        {produto.nome} — {produto.vendidos} vendidos
      </li>
    {/each}
  </ul>
{/if}

<style>
  .filtros { display: flex; gap: 8px; flex-wrap: wrap; margin-bottom: 8px; }
  .resumo { font-size: .9rem; color: #555; }
  .acabou { color: #b3261e; }
</style>

Sem nenhum filtro aplicado, os quatro produtos aparecem e o total é a soma de todos os vendidos. O compilador confirma:

<div class="filtros svelte-1n46o8q"><input value="" placeholder="Buscar produto"/> <select><option value="todas" selected="">todas as categorias</option><option value="pães">pães</option><option value="bolos">bolos</option><option value="salgados">salgados</option></select> <label><input type="checkbox"/> só o que acabou</label></div> <p class="resumo svelte-1n46o8q">4 produto(s) · 263 vendidos</p> <ul><li class="svelte-1n46o8q">Pão francês — 120 vendidos</li><li class="svelte-1n46o8q acabou">Bolo de chocolate — 34 vendidos</li><li class="svelte-1n46o8q">Pão de queijo — 88 vendidos</li><li class="svelte-1n46o8q acabou">Bolo de cenoura — 21 vendidos</li></ul>

Dois detalhes valem atenção. O selected="" está na opção "todas" porque categoria começa valendo 'todas'. E os dois bolos saíram com a classe extra acabou, porque o estoque deles é zero — a classe condicional class:acabou={...} não é um teste no CSS, é uma decisão tomada na hora de desenhar.

A anatomia da versão 2

filter((p) => { … })
com chaves, o corpo pode ter várias linhas. Sem chaves, cabe só uma expressão.
return false
a reprovação imediata daquele item. O filter passa para o próximo sem testar o resto.
categoria !== 'todas' && …
a primeira metade evita que "todas" filtre alguma coisa. As duas condições precisam ser verdadeiras.
bind:checked={soAcabou}
liga a caixinha a um booleano: marcada é true, desmarcada é false.
reduce((soma, p) => soma + p.vendidos, 0)
percorre a lista carregando um acumulador. O 0 do fim é o valor inicial.
class:acabou={condição}
acrescenta a classe só quando a condição é verdadeira. A classe não existe no HTML quando é falsa.

5. Filtrar escolhe, somar acumula

filter e reduce recebem uma função e percorrem a lista, mas devolvem coisas diferentes: filter devolve uma lista de itens escolhidos; reduce devolve um valor só, o acumulado. Os dois são derivados, e é comum um depender do outro — o total aqui é calculado sobre a lista já filtrada, não sobre a lista inteira. Mude a categoria e o total muda junto, sem nenhuma linha extra.

Essa ligação em cadeia é o que dá a sensação de "painel vivo". O Svelte não refaz os cálculos na ordem em que você escreveu; ele acompanha quem depende de quem. Se totalVendido depende de visiveis, e visiveis depende de busca, então digitar na busca atualiza os dois na ordem certa, uma vez só.

Missão: o número do topo mostra sempre o tamanho da lista inteira. Faça ele mostrar quantos sobraram depois da busca: digite "chocolate" e a tela tem de começar com "1 de 3".

<script>
  let busca = $state('');
  let produtos = ['Pão francês', 'Bolo de chocolate', 'Pão de queijo'];
  let visiveis = $derived(produtos.filter((p) => p.includes(busca)));
</script>

<p>{produtos.length} de {produtos.length}</p>
<input bind:value={busca} placeholder="Buscar">

<ul>
  {#each visiveis as p}
    <li>{p}</li>
  {/each}
</ul>

A diferença entre produtos.length e visiveis.length é a diferença entre "quantos eu tenho" e "quantos eu estou vendo". Os dois números são úteis, e um painel bom mostra os dois lado a lado — por isso a frase da solução mantém o total no fim.

6. Versão 3 — ordenar e não repetir

A terceira versão acrescenta a ordenação. Aqui o cálculo deixa de caber numa expressão só, porque são dois passos: filtrar e depois ordenar. Para isso existe $derived.by, que recebe uma função e usa o que ela devolver.

<script>
  let busca = $state('');
  let categoria = $state('todas');
  let ordem = $state('vendidos');

  let produtos = [
    { id: 1, nome: 'Pão francês', categoria: 'pães', vendidos: 120, estoque: 40 },
    { id: 2, nome: 'Bolo de chocolate', categoria: 'bolos', vendidos: 34, estoque: 0 },
    { id: 3, nome: 'Pão de queijo', categoria: 'salgados', vendidos: 88, estoque: 12 },
    { id: 4, nome: 'Bolo de cenoura', categoria: 'bolos', vendidos: 21, estoque: 0 }
  ];

  let visiveis = $derived.by(() => {
    let lista = produtos.filter((p) => {
      if (!p.nome.toLowerCase().includes(busca.toLowerCase())) return false;
      if (categoria !== 'todas' && p.categoria !== categoria) return false;
      return true;
    });
    if (ordem === 'nome') lista.sort((a, b) => a.nome.localeCompare(b.nome));
    else lista.sort((a, b) => b.vendidos - a.vendidos);
    return lista;
  });

  let totalVendido = $derived(
    visiveis.reduce((soma, p) => soma + p.vendidos, 0)
  );
</script>

{#snippet linha(produto)}
  <li class:acabou={produto.estoque === 0}>
    {produto.nome} — <strong>{produto.vendidos}</strong> vendidos
  </li>
{/snippet}

<div class="filtros">
  <input bind:value={busca} placeholder="Buscar produto">
  <select bind:value={categoria}>
    <option value="todas">todas as categorias</option>
    <option value="pães">pães</option>
    <option value="bolos">bolos</option>
    <option value="salgados">salgados</option>
  </select>
</div>

<div class="ordem">
  <button class:ativo={ordem === 'vendidos'} onclick={() => (ordem = 'vendidos')}>
    mais vendidos
  </button>
  <button class:ativo={ordem === 'nome'} onclick={() => (ordem = 'nome')}>
    por nome
  </button>
</div>

<p class="resumo">{visiveis.length} produto(s) · {totalVendido} vendidos</p>

{#if visiveis.length === 0}
  <p>Nenhum produto com esses filtros.</p>
{:else}
  <ul>
    {#each visiveis as produto (produto.id)}
      {@render linha(produto)}
    {/each}
  </ul>
{/if}

<style>
  .filtros { display: flex; gap: 8px; flex-wrap: wrap; margin-bottom: 8px; }
  .ordem { display: flex; gap: 6px; margin-bottom: 8px; }

A ordem inicial é por quantidade vendida, do maior para o menor. É isso que o texto da tela mostra:

todas as categorias pães bolos salgados mais vendidos por nome 4 produto(s) · 263 vendidos Pão francês — 120 vendidos Pão de queijo — 88 vendidos Bolo de chocolate — 34 vendidos Bolo de cenoura — 21 vendidos

Compare com a versão 2: lá a lista saía na ordem do arquivo (pão francês, bolo de chocolate, pão de queijo…). Aqui o pão de queijo subiu para segundo, porque tem 88 vendidos e o bolo de chocolate tem 34. A ordenação acontece dentro do derivado, antes de o {#each} receber a lista.

A anatomia da versão 3

$derived.by(() => { … })
para cálculos de vários passos. A função roda de novo quando qualquer valor lido dentro dela muda.
let lista = produtos.filter(...)
uma lista nova, só com o que passou nos filtros. O filter nunca altera a lista original.
lista.sort((a, b) => …)
ordena a lista nova no lugar. O número negativo devolvido pela função diz "a vem antes de b".
a.nome.localeCompare(b.nome)
compara texto respeitando acentos e maiúsculas do idioma. Melhor que > e < para nomes.
b.vendidos - a.vendidos
a subtração invertida (b menos a) produz a ordem do maior para o menor.
{@render linha(produto)}
desenha o snippet com um produto. Se a linha mudar, muda num lugar só.

7. O que o navegador mostrou

As saídas acima são do primeiro desenho. Abaixo está o que a versão 3 mostrou de verdade no navegador, com o texto lido da tela depois de cada ação.

AçãoTexto que apareceu

digitar "bolo" na busca… 2 produto(s) · 55 vendidos Bolo de chocolate — 34 vendidos Bolo de cenoura — 21 vendidos
clicar em "por nome"… Bolo de cenoura — 21 vendidos Bolo de chocolate — 34 vendidos Pão de queijo — 88 vendidos Pão francês — 120 vendidos
escolher a categoria "bolos"… 2 produto(s) · 55 vendidos Bolo de cenoura — 21 … Bolo de chocolate — 34 …

Três coisas para guardar dessa tabela. A primeira: o total mudou junto com a lista, sem nenhuma linha de código ligando os dois — é o encadeamento de derivados. A segunda: "bolo" com minúscula encontrou "Bolo de chocolate" porque a versão 3 compara os dois lados em minúsculas. A terceira: ao ordenar por nome, "Bolo de cenoura" veio antes de "Bolo de chocolate" — o localeCompare olha letra por letra, e c vem antes de ch.

9. Quando dá errado

Erro 1 — filtrar algo que não é lista

Este compila e quebra na hora de desenhar. $state({}) cria um objeto vazio, e objeto não tem filter.

<script>
  let produtos = $state({});
  let visiveis = $derived(produtos.filter((p) => p.vendidos > 0));
</script>

<p>{visiveis.length}</p>
Erro ao renderizar: produtos.filter is not a function

A mensagem diz onde: produtos. Se o valor inicial precisa ser uma lista vazia, escreva $state([]) — colchetes para lista, chaves para objeto.

Erro 2 — bind:checked em campo de texto

Cada tipo de bind tem um dono. bind:checked pertence à caixinha de marcar; num campo de texto, o compilador recusa.

<script>
  let busca = $state('');
</script>

<input type="text" bind:checked={busca}>
Erro de compilação (linha 5, coluna 19): `bind:checked` can only be used with `<input type="checkbox">`

Para texto, o certo é bind:value. A coluna aponta o começo do atributo, e a mensagem já diz qual é o elemento compatível.

Erro 3 — o {/each} incompleto

Faltou uma chave no fechamento do bloco. O compilador reclama no fim do arquivo, esperando o token que não veio.

<script>
  let lista = $state([{ nome: 'pão' }, { nome: 'bolo' }]);
</script>

<ul>
  {#each lista as item}
    <li>{item.nome}</li>
  {/each
</ul>
Erro de compilação (linha 9, coluna 0): Expected token }

"Expected token }" é "eu esperava uma chave aqui". O fechamento de bloco é sempre {/each}, com as duas chaves.

Resumo

  • $state é o que o usuário controla; $derived é o que o código calcula.
  • filter devolve lista; reduce devolve um valor só.
  • includes('') é sempre verdadeiro, e por isso a busca vazia mostra tudo.
  • Comparar texto sem baixar a caixa dos dois lados não encontra o que se procura.
  • Vários return false dentro do filter somam filtros sem if aninhado.
  • $derived.by serve para cálculos de vários passos, com variáveis locais.
  • Um derivado pode depender de outro: a lista filtrada alimenta o total.
  • sort ordena a lista nova; localeCompare compara nomes respeitando o idioma.
  • Lista vazia pede mensagem: o vazio sem explicação parece defeito.
