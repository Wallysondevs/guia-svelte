Svelte · Projeto Quiz

O filho da Ana está aprendendo a tabuada e ela quer uma forma de ele treinar sem caderno. Um quiz é o projeto perfeito para isso: uma pergunta por vez, um botão por alternativa, um acerto que vira ponto e uma tela final que diz como foi. Nas três versões desta aula o quiz cresce da pergunta única até o jogo com três perguntas que reinicia. Tudo o que está escrito aqui saiu do compilador e do navegador de verdade.

Você vai aprender
  • A montar uma pergunta com alternativas e mostrar o resultado do clique.
  • Por que a resposta certa precisa ser comparada, e não atribuída.
  • A guardar perguntas em lista e avançar com um índice.
  • Como somar pontos sem perder a conta quando a pergunta muda.
  • O que $derived resolve quando a pergunta atual vem de uma lista.
  • Como desligar as alternativas depois da resposta para ninguém responder duas vezes.
  • Como calcular progresso em porcentagem com Math.round.
  • Como terminar o jogo, mostrar o resultado e reiniciar sem recarregar a página.
  • Dois erros reais: índice fora da lista e onclick escrito como texto.

1. A ideia: uma pergunta, várias alternativas, um ponto

Um quiz é uma máquina de estados pequena. Existe a pergunta atual, o que o jogador escolheu e quantos pontos ele já fez. Quando ele clica, a escolha é guardada e comparada com a certa; quando ele avança, a pergunta troca e a escolha volta ao nada. Nada além disso — e é essa simplicidade que faz do quiz um bom segundo projeto.

A diferença em relação à lista de tarefas é que aqui existe uma posição. A lista de tarefas mostra tudo ao mesmo tempo; o quiz mostra uma pergunta por vez, e para isso precisa de um número que diga qual. Esse número é o índice, e quase todo bug de quiz nasce dele: avançar quando já era a última, voltar para uma pergunta que não existe, mostrar "pergunta 4 de 3".

A terceira peça é a comparação. O jogador escolhe a alternativa de índice 0 ou 1; a pergunta guarda qual é a certa. Acertar é escolha === certa. É tentador escrever escolha = certa — parece a mesma coisa e faz outra: em vez de comparar, atribui. O programa passa a dizer que todo mundo acertou.

2. Versão 1: uma pergunta só

Uma pergunta, duas alternativas, uma frase de resultado. O estado é só a escolha: null enquanto ninguém respondeu, 0 ou 1 depois. O {#if} usa esse null para não mostrar nada antes do primeiro clique.

<script>
  let escolha = $state(null);
  const certa = 1;
</script>

<h1>Quiz da padaria</h1>
<p>Qual é o pão mais crocante da vitrine?</p>

<button onclick={() => (escolha = 0)}>Sonho</button>
<button onclick={() => (escolha = 1)}>Pão francês</button>

{#if escolha !== null}
  <p>{escolha === certa ? 'Acertou!' : 'Errou, tente de novo.'}</p>
{/if}

A saída inicial não tem a frase de resultado, porque escolha ainda é null: o bloco {#if} nem desenha o parágrafo.

<h1>Quiz da padaria</h1> <p>Qual é o pão mais crocante da vitrine?</p> <button>Sonho</button> <button>Pão francês</button>

A anatomia da versão 1

let escolha = $state(null)
o estado começa em null, que quer dizer "nada escolhido". Poderia ser -1, mas null lê melhor e não se confunde com um índice válido.
const certa = 1
o índice da alternativa certa. Constante, porque a resposta não muda durante o jogo.
onclick={() => (escolha = 0)}
cada botão sabe o próprio índice. Poderia guardar o texto, mas índice é mais curto de comparar.
{#if escolha !== null}
mostra o resultado só depois do clique. !== é "diferente de".
escolha === certa ? … : …
o === compara. O == solto também compara, mas converte tipos no caminho; em JavaScript, usar === é a regra.

3. Versão 2: a lista de perguntas e o índice

Com duas perguntas, escrever dois blocos de HTML já fica repetitivo. A versão 2 guarda as perguntas num array e usa um índice para mostrar só a atual. O $derived faz a ponte: pergunta é sempre perguntas[atual], recalculada quando atual muda.

<script>
  let perguntas = $state([
    { texto: 'Qual é o pão mais crocante?', opcoes: ['Sonho', 'Pão francês'], certa: 1 },
    { texto: 'Quanto custa um sonho?', opcoes: ['R$ 4.50', 'R$ 9.00'], certa: 0 }
  ]);
  let atual = $state(0);
  let pontos = $state(0);
  let resposta = $state(null);

  let pergunta = $derived(perguntas[atual]);
  let respondeu = $derived(resposta !== null);

  function responder(indice) {
    resposta = indice;
    if (indice === pergunta.certa) pontos += 1;
  }

  function proxima() {
    atual += 1;
    resposta = null;
  }
</script>

<h1>Quiz da padaria</h1>
<p>Pergunta {atual + 1} de {perguntas.length} · {pontos} ponto(s)</p>

<p>{pergunta.texto}</p>

{#each pergunta.opcoes as opcao, i}
  <button onclick={() => responder(i)} disabled={respondeu}>{opcao}</button>
{/each}

{#if respondeu}
  <p>{resposta === pergunta.certa ? 'Acertou!' : 'Errou: a certa é ' + pergunta.opcoes[pergunta.certa]}</p>
  {#if atual < perguntas.length - 1}
    <button onclick={proxima}>próxima</button>
  {/if}
{/if}

Na saída, os dois botões vêm colados, sem espaço entre eles no HTML: o {#each} gera um <button> por alternativa, sem texto entre um e outro. Isso não muda o que aparece na tela, mas muda o HTML que você vê.

<h1>Quiz da padaria</h1> <p>Pergunta 1 de 2 · 0 ponto(s)</p> <p>Qual é o pão mais crocante?</p> <button>Sonho</button><button>Pão francês</button>

A anatomia da versão 2

let pergunta = $derived(perguntas[atual])
a pergunta da vez. Sem $derived, ela ficaria presa na primeira para sempre.
let respondeu = $derived(resposta !== null)
um apelido booleano para "já clicou". Serve para desligar os botões e para o {#if} do resultado.
responder(indice)
recebe o índice da alternativa clicada, guarda como resposta e soma um ponto se for a certa. A comparação usa pergunta.certa, que já aponta para a pergunta atual.
disabled={respondeu}
depois do clique, as alternativas ficam apagadas. Sem isso, o jogador clicaria três vezes e ganharia três pontos.
{#each pergunta.opcoes as opcao, i}
o segundo nome depois da vírgula é o índice da volta. É ele que vai para responder(i).

Missão: acertando as duas perguntas, o placar fica em 1 ponto(s). Faça cada acerto valer um ponto, sem apagar o anterior.

<script>
  let perguntas = $state([
    { texto: 'Pão francês é doce?', certa: 1 },
    { texto: 'Sonho é doce?', certa: 0 }

  let pontos = $state(0);

    if (indice === perguntas[atual].certa) pontos = 1;
    atual = Math.min(atual + 1, perguntas.length - 1);

</script>

4. Versão 3: progresso, tela final e reinício

A versão pronta tem três perguntas, uma barra de progresso, o botão que vira "ver resultado" na última e a tela final com a nota. O estado ganha uma variável a mais: terminou, que decide qual das duas telas aparece.

<script>
  let perguntas = $state([
    { id: 1, texto: 'Qual é o pão mais crocante?', opcoes: ['Sonho', 'Pão francês'], certa: 1 },
    { id: 2, texto: 'Quanto custa um sonho?', opcoes: ['R$ 4.50', 'R$ 9.00'], certa: 0 },
    { id: 3, texto: 'Quantos pães há numa dúzia?', opcoes: ['10', '12'], certa: 1 }
  ]);
  let atual = $state(0);
  let pontos = $state(0);
  let resposta = $state(null);
  let terminou = $state(false);

  let pergunta = $derived(perguntas[atual]);
  let respondeu = $derived(resposta !== null);
  let progresso = $derived(Math.round((atual / perguntas.length) * 100));
  let ultima = $derived(atual === perguntas.length - 1);
  let aprovado = $derived(pontos >= 2);

  function responder(indice) {
    if (respondeu) return;
    resposta = indice;
    if (indice === pergunta.certa) pontos += 1;
  }

  function proxima() {
    if (ultima) {
      terminou = true;
      return;
    }
    atual += 1;
    resposta = null;
  }

  function reiniciar() {
    atual = 0;
    pontos = 0;
    resposta = null;
    terminou = false;
  }
</script>

<h1>Quiz da padaria</h1>

{#if terminou}
  <p>{pontos} de {perguntas.length} · {aprovado ? 'Aprovada!' : 'Vale tentar de novo.'}</p>
  <button onclick={reiniciar}>jogar outra vez</button>
{:else}
  <p>Pergunta {atual + 1} de {perguntas.length} · {pontos} ponto(s)</p>
  <progress value={progresso} max="100">{progresso}%</progress>

  <p>{pergunta.texto}</p>

  {#each pergunta.opcoes as opcao, i (i)}
    <button class:certa={respondeu && i === pergunta.certa} onclick={() => responder(i)} disabled={respondeu}>
      {opcao}
    </button>
  {/each}

  {#if respondeu}
    <p>{resposta === pergunta.certa ? 'Acertou!' : 'Errou: a certa é ' + pergunta.opcoes[pergunta.certa]}</p>
    <button onclick={proxima}>{ultima ? 'ver resultado' : 'próxima'}</button>
  {/if}
{/if}

<style>
  .certa {
    border-color: #2e7d32;
    font-weight: bold;
  }
</style>

A saída mostra a barra de progresso com value="0" e o texto de dentro dela. O elemento <progress> é HTML comum: o Svelte só preenche o valor.

<h1>Quiz da padaria</h1> <p>Pergunta 1 de 3 · 0 ponto(s)</p> <progress value="0" max="100">0%</progress> <p>Qual é o pão mais crocante?</p> <button class="svelte-1n46o8q">Sonho</button><button class="svelte-1n46o8q">Pão francês</button>

Repare que a conta usa atual, não atual + 1: na primeira pergunta o progresso é zero por cento, e na última é setenta e cinco — a barra só completa quando o jogador termina. Se você quiser que a barra comece em vinte e cinco, a conta é ((atual + 1) / total) * 100. As duas escolhas são defensáveis; o importante é a barra nunca passar de cem.

5. Embaralhar as alternativas sem perder a certa

A primeira melhoria que todo mundo pede num quiz é embaralhar: se a resposta certa é sempre a segunda, o aluno aprende a clicar na segunda. Embaralhar é fácil; o que exige cuidado é manter o vínculo com a alternativa certa depois da mistura.

A forma mais simples é guardar a alternativa como objeto, e não como texto: { texto: 'Pão francês', certa: true }. Depois de embaralhar, a alternativa continua sabendo de si mesma, e a comparação passa a ser opcao.certa em vez de i === pergunta.certa. O índice deixa de carregar significado — o que é bom, porque o índice muda quando a ordem muda.

O sorteio em si costuma ser escrito com sort(() => Math.random() - 0.5). Funciona, com um senão honesto: o resultado não é uniformemente aleatório, porque o algoritmo de ordenação compara pares e o embaralhamento fica enviesado. Para um quiz de tabuada, tanto faz. Para um sorteio de verdade, use o algoritmo de Fisher-Yates, que troca posições de trás para a frente.

E há um cuidado extra quando o componente é renderizado no servidor, como no SvelteKit: sortear durante o desenho faz o HTML do servidor sair diferente do HTML do navegador. Nesse caso, sorteie só depois da montagem, dentro de um onMount. No projeto desta aula, que roda todo no navegador, o problema não aparece.

6. O caminho de um clique, passo a passo

Vale seguir a versão 3 do começo ao fim, porque é aqui que o quiz se comporta como um jogo e não como uma tela parada. A tabela mostra o texto visível depois de cada ação.

Três decisões dessa tabela merecem nome. A primeira é a guarda if (respondeu) return; dentro de responder: o botão já está desligado, mas a função também se protege — quem chama a função por outro caminho não ganha ponto duas vezes. A segunda é o resposta = null ao avançar: sem ele, a pergunta nova nasceria com a resposta da anterior e o jogador veria "Acertou!" antes de clicar. A terceira é o reiniciar, que zera as quatro variáveis de uma vez; esquecer uma delas é o que faz o segundo jogo começar no meio.

Existe ainda uma escolha de projeto em aprovado = pontos >= 2: a nota de corte está numa linha só, fácil de mudar. Se ela estivesse dentro do HTML, no meio de um ternário, mudar de dois para três exigiria caçar o número no lugar certo.

O quiz cabe num arquivo só?

Cabe, e para aprender é o certo. Quando o quiz tiver vinte perguntas e duas telas, vale separar: um arquivo perguntas.js só com os dados e um componente Pergunta.svelte que recebe a pergunta por $props(). Separar cedo demais atrapalha; separar tarde dói. A regra prática é separar quando o arquivo passa de umas duzentas linhas ou quando a mesma pergunta aparece em dois lugares.

8. Quando dá errado

O primeiro erro abaixo acontece em execução e é o campeão de reclamações em quiz. O segundo é de compilação e aparece quando alguém escreve o clique como se fosse HTML antigo. As duas mensagens são cópias das execuções.

Erro 1 — o índice passou do fim da lista

O botão "próxima" soma um ao índice sem conferir se ainda existe pergunta. Na última, o índice aponta para uma posição vazia e o acesso a .texto quebra.

<script>
  let perguntas = $state([
    { texto: 'Qual é o pão mais crocante?', opcoes: ['Sonho', 'Pão francês'] }
  ]);
  let atual = $state(1);
</script>

<p>{perguntas[atual].texto}</p>
Erro ao renderizar: Cannot read properties of undefined (reading 'texto')

A tradução: "não consigo ler a propriedade texto de algo que não existe". perguntas[1] é undefined porque a lista tem um item só. A defesa é a mesma da versão 3: antes de avançar, pergunte se ainda há para onde ir — if (ultima) { terminou = true; return; }.

Erro 2 — onclick escrito como texto

Em HTML antigo, um atributo de evento podia ser uma string de código. Em Svelte 5, atributo de evento é expressão: ou o nome de uma função, ou uma função seta. Aspas em volta transformam tudo em texto e o compilador recusa.

<script>
  let pontos = $state(0);
  const certa = 1;

  function responder(indice) {
    if (indice === certa) pontos += 1;
  }
</script>

<button onclick="responder(0)">Sonho</button>
<button onclick="responder(1)">Pão francês</button>
<p>{pontos} ponto(s)</p>
Erro de compilação (linha 10, coluna 8): Event attribute must be a JavaScript expression, not a string

A correção é tirar as aspas e usar chaves: onclick={() => responder(0)}. Note a diferença entre responder(0) e () => responder(0): a primeira chama a função na hora de desenhar; a segunda entrega a função para ser chamada no clique. Quando o retorno não importa, a forma com seta é a que você quer.
