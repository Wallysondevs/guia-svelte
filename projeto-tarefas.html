Svelte · Projeto Lista de Tarefas

Na parede da padaria existe um quadro de avisos com um pedaço de papel para cada coisa a fazer: comprar farinha, assar o pão, passar o café. Quando a Ana termina uma, ela risca o papel — mas o papel continua lá, e é isso que a incomoda: ela quer riscar, apagar, e ver só o que falta. Esta aula transforma o quadro de avisos num componente, em três versões: a lista simples, a lista com checkbox e a lista com filtros. Cada saída mostrada aqui foi compilada e rodada de verdade.

Você vai aprender
  • Como guardar uma lista num componente e desenhá-la com {#each}.
  • Como o bind:value do campo de texto acompanha o que a Ana digita.
  • Por que a versão 2 troca textos por objetos com id e feita.
  • O que bind:checked faz num checkbox dentro de uma lista.
  • Como remover um item sem quebrar a contagem, usando filter.
  • Para que serve a chave entre parênteses no {#each … (tarefa.id)}.
  • Como contar o que falta com $derived e mostrar uma frase para a lista vazia.
  • O que o build do Vite faz quando o componente tem <style>: um arquivo CSS separado.
  • Os dois erros de lista que o compilador desta versão mostra de verdade.

1. A ideia: uma lista é um estado com vários valores

Um contador guarda um número. Uma lista guarda vários, e essa diferença muda o desenho do componente: em vez de um buraco {cliques} na tela, você precisa de um molde que se repita para cada item. O Svelte chama esse molde de {#each} — "para cada item da lista, desenhe este pedaço de HTML".

O quadro de avisos da Ana tem outra propriedade que a lista precisa imitar: cada papel é independente. Riscar o papel do café não pode riscar o papel da farinha. Num componente, isso quer dizer que cada tarefa precisa de um valor próprio que diga se ela está feita, e esse valor precisa ser reativo — mudar um e só um.

Por último, a ordem importa. A Ana põe o papel novo embaixo, e o mais urgente em cima. Uma lista em programação é ordenada por natureza: o primeiro item que entra é o primeiro que aparece. Quando a ordem precisa mudar, você ordena antes de desenhar — e o desenho continua sendo o mesmo molde.

No quadro de avisosNo componente
Um papel para cada coisa a fazerlet tarefas = $state([...])
Ler os papéis de cima para baixo{#each tarefas as tarefa}
Escrever um papel novotarefas.push({ … })
Riscar um papeltarefa.feita = true ou bind:checked
Jogar um papel no lixotarefas = tarefas.filter(…)
Pôr os feitos numa pilha separadaum $derived que filtra

2. Versão 1: a lista simples

A primeira versão guarda só textos, na ordem em que a Ana digitou. O campo de texto usa bind:value: o que está no campo é o que está na variável, sem ouvinte de evento escrito na mão.

<script>
  let tarefas = $state(['comprar farinha', 'assar o pão']);
  let nova = $state('');

  function adicionar() {
    tarefas.push(nova);
    nova = '';
  }
</script>

<h1>Lista da padaria</h1>

<input bind:value={nova} placeholder="o que fazer?" />
<button onclick={adicionar}>adicionar</button>

<ul>
  {#each tarefas as tarefa}
    <li>{tarefa}</li>
  {/each}
</ul>

O HTML gerado tem dois itens, um <li> para cada texto da lista. Repare no campo de texto: o atributo value aparece vazio, porque nova começa como texto vazio.

<h1>Lista da padaria</h1> <input value="" placeholder="o que fazer?"/> <button>adicionar</button> <ul><li>comprar farinha</li><li>assar o pão</li></ul>

Três coisas merecem atenção nesse resultado. A primeira: o {#each} sumiu do HTML, como o {cliques} sumia no contador — o molde virou tantos <li> quantos itens existiam. A segunda: o bind:value não deixa rastro no HTML; ele é uma ligação de mão dupla que o Svelte monta em JavaScript. A terceira: tarefas.push(nova) funciona porque a lista foi criada com $state. Se ela fosse uma variável comum, o array mudaria e a tela não saberia.

A anatomia da versão 1

let tarefas = $state([...])
uma lista reativa. Os colchetes guardam os itens; as aspas dizem que cada item é texto.
bind:value={nova}
liga o campo à variável nos dois sentidos: digitar muda nova, e mudar nova muda o campo. Sem bind, você precisaria ler evento.target.value.
{#each tarefas as tarefa}
o molde. Para cada item da lista, o nome tarefa vale o item daquela volta. O {/each} fecha o bloco.
tarefas.push(nova)
acrescenta um item no fim. push é método de array e devolve o novo tamanho — não é o caso de guardar esse retorno aqui.
nova = ''
limpa o campo depois de adicionar. Como o bind é de mão dupla, limpar a variável limpa o que está escrito na tela.

Missão: o componente mostra só o primeiro papel do quadro. Faça os dois textos aparecerem, um em cada linha.

<script>
  let tarefas = $state(['comprar farinha', 'assar o pão']);
</script>

<ul>
  <li>{tarefas[0]}</li>
</ul>
<script>
  let tarefas = $state(['comprar farinha', 'assar o pão']);
</script>

<ul>
  {#each tarefas as tarefa}
    <li>{tarefa}</li>
  {/each}
</ul>

tarefas[0] é o primeiro item; tarefas[1] seria o segundo. Escrever um <li> para cada índice funciona enquanto a lista tem tamanho fixo — e deixa de funcionar no instante em que a Ana adiciona o terceiro papel. O {#each} é o que faz o molde acompanhar o tamanho da lista.

3. Versão 2: cada tarefa vira um objeto

Texto sozinho não guarda "esta tarefa está feita". A versão 2 troca cada item por um objeto com três campos: id (um número único), texto (o que a Ana escreveu) e feita (verdadeiro ou falso). Com isso, o checkbox consegue mexer num item sem tocar nos outros, e o botão de remover consegue achar exatamente qual apagar.

<script>
  let tarefas = $state([
    { id: 1, texto: 'comprar farinha', feita: false },
    { id: 2, texto: 'assar o pão', feita: true }
  ]);
  let nova = $state('');

  let abertas = $derived(tarefas.filter((t) => !t.feita).length);

  function adicionar() {
    const texto = nova.trim();
    if (!texto) return;
    tarefas.push({ id: Date.now(), texto, feita: false });
    nova = '';
  }

  function remover(id) {
    tarefas = tarefas.filter((t) => t.id !== id);
  }
</script>

<h1>Lista da padaria</h1>

<input bind:value={nova} placeholder="o que fazer?" />
<button onclick={adicionar}>adicionar</button>

<p>{abertas} aberta(s)</p>

<ul>
  {#each tarefas as tarefa}
    <li>
      <input type="checkbox" bind:checked={tarefa.feita} />
      <span class:feita={tarefa.feita}>{tarefa.texto}</span>
      <button onclick={() => remover(tarefa.id)}>remover</button>
    </li>
  {/each}
</ul>

Na saída, o segundo checkbox vem marcado e o segundo <span> vem com a classe feita. É o estado de cada tarefa aparecendo no HTML, item por item:

<h1>Lista da padaria</h1> <input value="" placeholder="o que fazer?"/> <button>adicionar</button> <p>1 aberta(s)</p> <ul><li><input type="checkbox"/> <span>comprar farinha</span> <button>remover</button></li><li><input type="checkbox" checked=""/> <span class="feita">assar o pão</span> <button>remover</button></li></ul>

O Date.now() gera um número enorme, os milissegundos desde 1970, e serve como id porque dois cliques não acontecem no mesmo milissegundo. É uma solução de projeto pequeno: numa lista que vem de um servidor, o id vem do banco e você não inventa.

A anatomia da versão 2

{ id, texto, feita }
o formato de uma tarefa. Três campos, cada um com um papel: identificar, mostrar, marcar.
bind:checked={tarefa.feita}
liga o checkbox àquele campo daquele item. Marcar na tela muda tarefa.feita; mudar tarefa.feita marca na tela.
class:feita={tarefa.feita}
põe ou tira a classe feita conforme o valor. Quando é falso, a classe nem aparece no HTML.
tarefas.filter((t) => !t.feita)
cria uma lista nova só com as que faltam; .length conta quantas são. A lista original não é tocada.
tarefas = tarefas.filter(…)
para remover, o filtro cria a lista sem o item e a atribuição troca a lista inteira. Trocar a lista é o que avisa a tela.
push funciona, mas trocar a lista é mais previsível

Guardado em $state, um array avisa a tela tanto quando você chama push quanto quando atribui um array novo. Para remover, porém, filter já devolve outro array — usar o retorno é mais curto do que procurar o índice e chamar splice. Nas duas formas, o resultado na tela é o mesmo.

4. Versão 3: filtros, chave e a lista vazia

A versão pronta responde à pergunta que a Ana faz cinquenta vezes por dia: "o que ainda falta?". Ela tem três botões de filtro, uma lista que muda conforme o filtro, Enter para adicionar sem tirar a mão do teclado e uma frase para quando não há nada para mostrar.

<script>
  let tarefas = $state([
    { id: 1, texto: 'comprar farinha', feita: false },
    { id: 2, texto: 'assar o pão', feita: true },
    { id: 3, texto: 'passar o café', feita: false }
  ]);
  let nova = $state('');
  let filtro = $state('todas');

  let abertas = $derived(tarefas.filter((t) => !t.feita).length);
  let visiveis = $derived(
    tarefas.filter((t) => filtro === 'todas' || (filtro === 'abertas' ? !t.feita : t.feita))
  );

  function adicionar() {
    const texto = nova.trim();
    if (!texto) return;
    tarefas.push({ id: Date.now(), texto, feita: false });
    nova = '';
  }

  function adicionarComEnter(evento) {
    if (evento.key === 'Enter') adicionar();
  }
</script>

<h1>Lista da padaria</h1>

<div class="entrada">
  <input bind:value={nova} onkeydown={adicionarComEnter} placeholder="o que fazer?" />
  <button onclick={adicionar}>adicionar</button>
</div>

<div class="filtros">
  <button class:ativo={filtro === 'todas'} onclick={() => (filtro = 'todas')}>todas</button>
  <button class:ativo={filtro === 'abertas'} onclick={() => (filtro = 'abertas')}>abertas</button>
  <button class:ativo={filtro === 'feitas'} onclick={() => (filtro = 'feitas')}>feitas</button>
</div>

<p>{abertas} de {tarefas.length} em aberto</p>

{#if visiveis.length === 0}
  <p class="vazio">Nada aqui.</p>
{:else}
  <ul>
    {#each visiveis as tarefa (tarefa.id)}
      <li class:feita={tarefa.feita}>
        <input type="checkbox" bind:checked={tarefa.feita} />
        {tarefa.texto}
      </li>
    {/each}
  </ul>
{/if}

<style>
  .feita {
    text-decoration: line-through;
    color: #666;
  }
  .ativo {
    font-weight: bold;
  }
  .vazio {
    font-style: italic;
  }
</style>

Aqui a saída tem uma lição escondida. O selo svelte-1n46o8q aparece nos botões de filtro, no <p> da contagem e nos <li>, mas não aparece na div.entrada nem na div.filtros: o compilador só marca os elementos que algum seletor do <style> pode atingir.

<h1>Lista da padaria</h1> <div class="entrada"><input value="" placeholder="o que fazer?"/> <button>adicionar</button></div> <div class="filtros"><button class="svelte-1n46o8q ativo">todas</button> <button class="svelte-1n46o8q">abertas</button> <button class="svelte-1n46o8q">feitas</button></div> <p>2 de 3 em aberto</p> <ul><li class="svelte-1n46o8q"><input type="checkbox"/> comprar farinha</li><li class="svelte-1n46o8q feita"><input type="checkbox" checked=""/> assar o pão</li><li class="svelte-1n46o8q"><input type="checkbox"/> passar o café</li></ul>
Filtro escolhidoO que visiveis devolveTexto do parágrafo
todasas três tarefas2 de 3 em aberto
abertasfarinha e café2 de 3 em aberto (a contagem não muda com o filtro)

A chave (tarefa.id) no {#each} diz ao Svelte para reconhecer cada item pelo id, e não pela posição. A diferença aparece quando a lista muda no meio: sem chave, remover o primeiro item faz o Svelte reaproveitar os elementos do HTML e redistribuir os textos entre eles; com chave, cada item leva o seu elemento junto. Em lista com checkbox, isso evita o clássico "marquei uma e a outra apareceu marcada".

O texto da frase que não muda com o filtro também é uma decisão de projeto: abertas conta a lista inteira, não a lista visível. Se a Ana filtrar "feitas" e ler "2 de 3 em aberto", ela sabe que ainda há dois papéis esperando — que é a informação útil.

5. A lista que não tem nada para mostrar

Toda lista chega um dia no estado vazio, e esse é o momento em que a maioria das telas fica estranha: aparece uma caixa em branco e a Ana não sabe se o programa travou. A defesa é um {#if} antes do {#each}, com uma frase curta que explica o que fazer.

O detalhe importante é que a condição olha para a lista filtrada, não para a original. Se a condição fosse tarefas.length === 0, filtrar por "feitas" numa lista sem nenhuma feita deixaria a tela em branco: a lista original tem três itens, então o {#if} diria que há o que mostrar, e o {#each} não desenharia nada. Com visiveis.length === 0, a frase aparece exatamente quando não há o que desenhar.

Missão: o botão "abertas" muda o filtro, mas a lista continua mostrando o pão, que já está feito. Faça a lista obedecer ao filtro.

<script>
  let tarefas = $state([
    { id: 1, texto: 'comprar farinha', feita: false },
    { id: 2, texto: 'assar o pão', feita: true }
  ]);
  let filtro = $state('todas');
</script>

<button id="abertas" onclick={() => (filtro = 'abertas')}>abertas</button>

<ul>
  {#each tarefas as t}
    <li>{t.texto}</li>
  {/each}
</ul>
<script>
  let tarefas = $state([
    { id: 1, texto: 'comprar farinha', feita: false },
    { id: 2, texto: 'assar o pão', feita: true }
  ]);
  let filtro = $state('todas');
  let visiveis = $derived(tarefas.filter((t) => filtro === 'todas' || !t.feita));
</script>

<button id="abertas" onclick={() => (filtro = 'abertas')}>abertas</button>

<ul>
  {#each visiveis as t}
    <li>{t.texto}</li>
  {/each}
</ul>

Note que a solução não filtra dentro do {#each}, e sim antes, num $derived. Filtrar antes tem três vantagens: a lista visível pode ser usada em outros lugares, o {#if} da lista vazia enxerga o mesmo valor e o código de filtro fica num lugar só, fácil de achar quando a regra mudar.

6. Rótulos: o que o leitor de tela lê

Quem usa leitor de tela não vê o desenho: ouve o que está escrito. Um campo de texto sem rótulo é anunciado como "campo de edição" e nada mais, e um checkbox sem rótulo é anunciado como "caixa de seleção" — sem dizer de qual tarefa. Como a Ana vai usar esse tablet com o filho pequeno no colo, vale escrever o rótulo certo desde já.

A forma mais simples é envolver o campo num <label>: o texto que está dentro do rótulo passa a valer para o campo de dentro. Para o checkbox que fica ao lado do texto da tarefa, o <label> em volta do <input> e do texto resolve a associação sem id nenhum. Quando o texto visível já descreve o botão — "adicionar", "remover" —, não é preciso mais nada: o leitor de tela lê o próprio texto do botão.

O caso que costuma escapar é o botão só com símbolo. Um <button>×</button> é anunciado como "vezes" e não diz o que faz. Aí entra aria-label="remover tarefa", que troca o que é falado sem trocar o que aparece. O custo é manter dois textos em sincronia; o benefício é a tela funcionar para quem não vê.

Em projeto pequeno dá para ignorar por um tempo. Em projeto que cresce, limpar esses avisos é o que mantém o CSS legível.

8. Quando dá errado

Os dois erros abaixo são de lista, e os dois aparecem no mesmo lugar: entre o {#each} e o {/each}. As mensagens foram copiadas do compilador desta versão.

Erro 1 — esqueceu o {/each}

Sem o fechamento do bloco, o compilador continua lendo o HTML de dentro do {#each} — inclusive o </ul>, que passa a fechar um elemento que ele não abriu dentro do bloco.

<script>
  let tarefas = $state(['comprar farinha', 'assar o pão']);
</script>

<ul>
  {#each tarefas as tarefa}
    <li>{tarefa}</li>
</ul>
Erro de compilação (linha 8, coluna 0): `</ul>` attempted to close an element that was not open

A mensagem fala do </ul>, mas o problema está uma linha acima. Quando o erro apontar uma tag que "não estava aberta", conte os blocos: cada {#each} pede um {/each}, cada {#if} pede um {/if}. O erro aponta o sintoma, não a causa.

Erro 2 — {:else} sem {#if}

É o erro de quem quis mostrar "lista vazia" e escreveu só a segunda metade. {:else} não existe sozinho: ele pertence a um bloco que começou antes.

<script>
  let visiveis = $state([]);
</script>

<ul>
  {#each visiveis as t}
    <li>{t.texto}</li>
  {/each}
</ul>
{:else}
  <p>Nada aqui.</p>
Erro de compilação (linha 10, coluna 1): {:...} block is invalid at this position (did you forget to close the preceding element or block?)

A pergunta da mensagem é a dica: "você esqueceu de fechar o elemento ou bloco anterior?". Aqui o {:else} ficou fora do {#if} que deveria envolvê-lo. A correção é abrir o {#if} antes do <ul> e fechar depois do {:else}, como na versão 3.

Resumo

  • Lista reativa é let tarefas = $state([...]); o molde é {#each tarefas as tarefa} e fecha com {/each}.
  • bind:value liga o campo de texto à variável nos dois sentidos; bind:checked faz o mesmo com o checkbox de cada item.
  • A versão 2 troca textos por objetos com id, texto e feita — sem id não há como remover o item certo.
  • filter devolve lista nova; atribuir o retorno é a forma mais curta de remover e a mais fácil de ler.
  • class:feita={tarefa.feita} põe e tira a classe conforme o valor, sem if no HTML.
  • A chave (tarefa.id) faz o Svelte reconhecer o item pela identidade, não pela posição.
  • A frase de lista vazia fica num {#if} antes do {#each} e olha para a lista filtrada.
  • Com <style>, o build gera também um CSS: dist/assets/index-CgDT-uRh.css neste projeto.
  • Os erros desta aula: `</ul>` attempted to close an element that was not open e {:...} block is invalid at this position.
  • Testar uma lista significa testar três estados: com itens, com o filtro aplicado e sem nada para mostrar.
