Svelte · Duas mãos no mesmo valor: $bindable

A Ana e a sobrinha anotam o troco no mesmo caderno. Se só a Ana escreve, a sobrinha precisa perguntar o valor toda vez. Se as duas escrevem no mesmo lugar, qualquer uma atualiza e a outra vê na hora — mas é preciso combinar que aquele número é de ambas. Em Svelte, uma prop comum é o caderno de uma mão só: o pai escreve, o filho lê. Para o filho também poder escrever, a prop precisa ser declarada com $bindable(). Nesta aula você vai ver os dois lados dessa combinação e o que acontece quando ela é feita pela metade.

Você vai aprender

  • Como o pai liga os dois lados com bind:valor.
  • O que a saída real mostra quando o valor é o mesmo dos dois lados.
  • Por que a mudança do filho não chega ao pai sem bind:.
  • Como funciona o valor padrão dentro de $bindable(...).
  • O que vale a prop quando o pai não passa nada.
  • Quando $bindable é a ferramenta certa e quando é excesso.
  • A relação com bind:value de um campo de formulário.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • O que o build do projeto da Ana mostra com uma prop de duas mãos.

1. A ideia: quem pode escrever

Toda prop tem um dono. Por padrão, o dono é o pai: ele calcula o valor e passa; o filho lê e desenha. Isso mantém o fluxo numa direção só, e é o que torna o componente previsível — se o filho mexesse no valor, o pai ficaria com uma cópia velha e ninguém saberia qual é a verdade.

Mas existem casos em que o filho precisa escrever. Um campo de texto com máscara, um seletor de quantidade com botões de mais e menos, um componente de data que ajusta o dia. Nesses casos, o valor mora no pai — porque outras partes da tela também o usam — e o filho precisa alterá-lo. A solução é um contrato: o filho declara a prop como gravável, e o pai autoriza a ligação com bind:.

O nome vem de "bind", que em programação quer dizer "ligar" — no sentido de amarrar duas pontas. Com a ligação, o pai e o filho passam a olhar para o mesmo valor: quando o pai muda, o filho recebe; quando o filho muda, o pai recebe. Não são duas cópias sincronizadas por código: é uma ligação declarada, que o compilador transforma em atualização nos dois sentidos.

Uma observação sobre o escopo: $bindable só existe para props de componente. Ligação com elementos do HTML — bind:value num <input> — é assunto da aula de bind:, e funciona com qualquer variável de estado. São duas coisas diferentes com a mesma palavra "bind", e vale não misturar.

2. O filho que aceita escrever

Do lado do filho, a mudança é de uma palavra. Em vez de receber a prop direto, ela é declarada como valor de $bindable(), com o padrão dentro dos parênteses.

<script>
  let { valor = $bindable(0) } = $props();
</script>

<p>No filho: {valor}</p>
<button onclick={() => valor++}>+1 no filho</button>

Montado sem nada, o componente mostra o valor padrão e o botão que o altera:

<p>No filho: 0</p> <button>+1 no filho</button>

Até aqui, parece uma variável de estado comum. A diferença aparece quando o pai entra em cena: o $bindable() avisa ao Svelte que aquela prop aceita ser ligada. Sem ele, o pai pode passar o valor, mas não pode usar bind: para compartilhar a escrita.

A anatomia do $bindable

let { valor = $bindable(0) } = $props()
a prop vem de $props() como sempre; o que muda é o valor padrão, que passa a ser uma chamada de $bindable.
$bindable(0)
o 0 é o valor usado quando o pai não passa nada. Sem argumento, a prop vale undefined.
valor++
dentro do filho, a prop gravável é tratada como estado: pode ser atribuída, somada, comparada.
{valor}
na marcação, ela continua sendo lida como qualquer outro valor reativo.

Repare numa consequência: como o valor padrão vira $bindable(...), a prop deixa de ter um padrão "simples". Se você quer um valor inicial e a possibilidade de ligação, o padrão vai dentro dos parênteses: $bindable(0) é o mesmo que "começa em 0 e aceita ligação".

Só declare como bindable o que o filho muda

Uma prop que o filho apenas lê não precisa de $bindable, e declarar todas como bindable enfraquece o contrato: qualquer criança pode escrever em qualquer coisa, e o pai perde a noção de quem manda no valor. Trate $bindable como uma porta que você abre de propósito.

3. O pai que liga os dois lados

Do lado do pai, a ligação é um atributo com bind: antes do nome da prop. O valor à direita é uma variável de estado do pai — sem chaves em volta do nome, porque o alvo da ligação precisa ser uma variável, não uma expressão.

<script>
  import Filho from './Filho.svelte';
  let valor = $state(0);
</script>

<p>No pai: {valor}</p>
<Filho bind:valor />
<button onclick={() => valor++}>+1 no pai</button>

Na primeira renderização, os dois lados mostram o mesmo valor: o pai criou valor = 0 e passou para o filho pela ligação. Depois disso, quem manda no número é a variável do pai, e o filho escreve nela quando o usuário clica no botão dele. A resposta do compilador para esse par de arquivos, na renderização inicial, é esta: <p>No pai: 0</p> <p>No filho: 0</p>, seguida dos dois botões.

Três detalhes que evitam confusão. O primeiro: bind:valor não é uma prop chamada "bind" — é a prop valor com a marca de ligação. O segundo: se o filho não declarar $bindable, o componente ainda compila, mas a escrita do filho fica só nele; o pai não fica sabendo. O terceiro: o pai precisa de uma variável de estado no alvo, senão o compilador recusa — é o erro Can only bind to state or props.

4. Experimente: a runa no lugar errado

A caixa abaixo usa $bindable() fora da desestruturação de $props() e o compilador recusa o arquivo. Sua missão é colocar a runa no lugar certo.

Missão: o compilador recusa com `$bindable()` can only be used inside a `$props()` declaration. Transforme a variável solta numa prop gravável e faça o clique chegar a Cliques: 1.

<script>
  let valor = $bindable(0);
</script>

<button onclick={() => valor++}>Cliques: {valor}</button>
<script>
  let { valor = $bindable(0) } = $props();
</script>

<button onclick={() => valor++}>Cliques: {valor}</button>

A solução não muda o botão: muda a origem do valor. Antes era uma variável do componente; agora é uma prop gravável que, sozinha, usa o padrão 0. O clique continua somando um, e a tela acompanha nos dois casos — o que o compilador cobrava era só a forma da declaração.

Esse é o tipo de erro que acontece quando você aprende a runa e sai usando em todo lugar. A regra é curta: $bindable() só aparece como valor padrão de um nome que veio de $props().

5. O valor padrão dentro do $bindable

O padrão que você passa para o $bindable é o valor que o filho usa quando o pai não passa nada. Ele também precisa ser do tipo que o componente espera: número para contas, texto para exibição.

<script>
  let { valor = $bindable(10) } = $props();
</script>

<button onclick={() => valor++}>+1</button>
<p>Total: {valor.toFixed(2)}</p>
<button>+1</button> <p>Total: 10.00</p>

Sem pai, o filho começa em 10 e mostra o total formatado. Isso é útil de um jeito específico: o componente pode ser usado sozinho, num teste ou numa demonstração, sem que ninguém precise montar um pai só para ele. E quando o pai aparece e passa um valor, o padrão sai de cena — mas continua documentando qual é o valor inicial esperado.

Sem argumento nenhum, $bindable() deixa a prop valendo undefined:

<script>
  let { valor = $bindable() } = $props();
</script>

<p>Valor: {valor}</p>
<p>Valor: </p>

O texto sai com dois-pontos e nada depois. Se você já viu essa forma num componente de biblioteca, é isso: o autor deixou a prop sem padrão de propósito, para o pai ser obrigado a passar o valor. Em código de aula, prefira sempre um padrão explícito — é uma linha a mais que evita uma tela vazia.

6. Experimente: o padrão que faltou

A caixa abaixo declara a prop gravável sem valor padrão, e a tela fica sem número. Sua missão é dar o padrão 0.

Missão: a tela mostra Valor: e nada mais, porque $bindable() sem argumento vale undefined. Passe o padrão 0 para o $bindable.

<script>
  let { valor = $bindable() } = $props();
</script>

<p>Valor: {valor}</p>
<script>
  let { valor = $bindable(0) } = $props();
</script>

<p>Valor: {valor}</p>

É a menor correção desta aula: dois caracteres. E o efeito é grande na confiança do componente: com o padrão, ele funciona sozinho; sem, ele depende que alguém sempre passe o valor, e qualquer esquecimento aparece como uma tela com um buraco.

7. Experimente: comece em dez

A caixa abaixo começa o total em zero. Sua missão é fazer o componente abrir com o total 10.00, mantendo o botão de somar.

Missão: o total abre em 0.00. Troque o valor padrão dentro de $bindable(...) para o total começar em dez reais.

<script>
  let { valor = $bindable(0) } = $props();
</script>

<button onclick={() => valor++}>+1</button>
<p>Total: {valor.toFixed(2)}</p>
<script>
  let { valor = $bindable(10) } = $props();
</script>

<button onclick={() => valor++}>+1</button>
<p>Total: {valor.toFixed(2)}</p>

Repare que o toFixed continua funcionando: o valor é número nos dois casos. O padrão dentro de $bindable não é texto e não é uma "configuração" — é o valor inicial de verdade, do mesmo tipo que o pai passaria. Se você colocar '10' entre aspas, a soma vira concatenação e o total vira 101.00 depois do primeiro clique. Vale testar para ver o estrago.

8. Quando o pai não usa bind:

Se o pai passa o valor sem a marca de ligação, o filho recebe o número e desenha. Ao escrever — no clique do botão, por exemplo — a mudança acontece no filho, mas o pai não é avisado. O valor do pai continua o de antes, e as duas telas passam a discordar.

É por isso que o contrato tem duas partes: o filho declara $bindable, o pai escreve bind:. Faltando uma delas, cada lado fica com o seu número e o defeito aparece como "a tela do pai não atualiza" — um dos sintomas mais comuns em quem está começando com componentes.

Você querUsePor quê
O filho só mostrarprop comumo valor é do pai, e só dele
O filho alterar o valor do pai$bindable + bind:as duas mãos no mesmo valor
O filho avisar que algo aconteceuprop de função (aoMudar)o pai decide o que fazer com o aviso
O filho guardar um valor só dele$state no filhonão é assunto do pai

A terceira linha merece atenção. Muita gente usa $bindable para tudo, e acaba com um componente que escreve em cinco props do pai sem que o pai saiba onde. Uma prop de função é mais explícita: o filho chama aoMudar(3) quando o usuário escolhe 3, e o pai decide se guarda, se valida, se manda para o servidor. Custa mais linhas e ganha em clareza.

bind em elemento é outra história

<input bind:value={nome}> liga o campo a uma variável de estado do próprio componente, e funciona com qualquer $state. Você vai ver isso em detalhe na aula de bind:value. O $bindable desta aula é o mesmo conceito aplicado a uma prop de componente — a ligação entre dois componentes.

9. Lendo o valor dentro do filho

Uma prop gravável é lida como qualquer outra: aparece na marcação, entra em contas, serve de argumento para um snippet. O que muda é que ela também pode ser atribuída.

Existe um detalhe de estilo que vale desde já: quando o filho muda o valor, é boa prática mudar de forma previsível e mínima. valor++ é fácil de entender; valor = valor * 2 + 1 dentro de um onclick deixa quem lê o pai sem saber o que esperar. Se a regra é complicada, dê um nome a ela numa função do <script> — avancarUm(), limpar() — e chame essa função no onclick. O componente fica legível e a regra ganha um lugar só, como nas aulas anteriores.

Ao escrever essa função, lembre do que ela altera: a prop gravável é compartilhada com o pai, então cada atribuição aparece do outro lado. Uma função de filho que muda o valor é, na prática, uma alteração no estado do pai — e vale a mesma disciplina: mudar uma vez, com uma regra clara, e deixar o resto da tela reagir.

Também vale saber que a ligação não é "mágica de texto": o pai e o filho compartilham a mesma célula de estado. Se o pai tiver um $derived que usa esse valor, ele recalcula quando o filho escreve. Se outra parte da tela mostra o mesmo valor, ela acompanha. É por isso que o valor deve morar no pai: ele é a fonte única, e a ligação é o cano.

11. Quando dá errado

As três mensagens abaixo saíram do compilador desta versão, copiadas como estão. As duas primeiras são sobre o lugar e a forma da runa; a terceira, sobre o alvo da ligação.

Erro 1 — $bindable() fora de $props()

A runa só faz sentido como valor padrão de uma prop. Numa variável solta, ela seria uma promessa de ligação que ninguém pode cumprir.

<script>
  let { titulo = 'Comanda' } = $props();
  let valor = $bindable(0);
</script>

<p>{titulo}: {valor}</p>
Erro de compilação (linha 3, coluna 14): `$bindable()` can only be used inside a `$props()` declaration

A mensagem é curta e diz o lugar certo: "só pode ser usada dentro de uma declaração $props()". A coluna 14 aponta o começo da chamada. Mova o nome para a desestruturação — e a variável solta desaparece.

Erro 2 — $bindable com dois argumentos

A runa aceita zero ou um argumento: o valor padrão. Não existe objeto de opções.

<script>
  let { valor = $bindable(0, { fallback: 10 }) } = $props();
</script>

<p>{valor}</p>
Erro de compilação (linha 2, coluna 16): `$bindable` must be called with zero or one arguments

A mensagem diz exatamente a regra: "deve ser chamada com zero ou um argumentos". A coluna 16 aponta a chamada. Se você viu { fallback: 10 } em algum exemplo, era de outra versão ou de outra runa — aqui o segundo argumento é recusado.

Erro 3 — bind: num valor que não pode mudar

O alvo de uma ligação precisa poder receber valor novo. Uma constante, por definição, não pode.

<script>
  const valor = 0;
</script>

<input bind:value={valor} />
<p>{valor}</p>
Erro de compilação (linha 5, coluna 7): Cannot bind to constant

"Cannot bind to constant" é literal. A coluna 7 aponta o alvo da ligação. Troque const por let ... = $state(...) — e lembre que essa regra vale para qualquer bind:, em elemento ou em componente.

Resumo

  • Prop comum é de mão única: o pai passa, o filho lê.
  • $bindable(valorPadrão) marca a prop como gravável pelo filho e ligável pelo pai.
  • O pai liga com bind:valor={x} ou, se o nome é o mesmo, bind:valor.
  • Faltando bind: ou $bindable, cada lado fica com o seu valor e as telas discordam.
  • O argumento de $bindable é o padrão usado quando o pai não passa nada; sem argumento, vale undefined.
  • O padrão precisa ser do tipo certo: texto onde se espera número gera concatenação, não soma.
  • O alvo de bind: tem de ser variável de estado ou prop, nunca constante ou conta.
  • $bindable() só existe como valor padrão dentro de $props(), com zero ou um argumento.
  • bind:value em elemento HTML é assunto da aula de bind:value; $bindable é entre componentes.
  • Para avisos e regras complicadas, prefira prop de função a uma prop gravável.
