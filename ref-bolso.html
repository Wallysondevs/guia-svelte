1. Como usar esta folha

As tabelas foram escritas em ordem de frequência: a linha de cima é a que você mais vai usar. Cada célula tem o mínimo para reconhecer e copiar — a explicação de por que funciona está nas outras aulas, e o fim de cada seção aponta o caminho.

Três convenções valem para a página inteira. Primeira: o que aparece em fonte de código é para digitar como está, trocando só os nomes. Segunda: os exemplos usam a Ana, a padaria e o caderno de pedidos, para você reconhecer o contexto. Terceira: toda saída mostrada aqui saiu de uma execução de verdade, com o compilador e o servidor reais — nenhuma linha de terminal foi inventada.

Se você é iniciante absoluto, esta folha não substitui a primeira aula. O caminho natural é: montar o primeiro componente, entender o que é estado, aprender os blocos, e só então usar a folha como consulta. Quem chega aqui cedo demais encontra uma parede de tabelas; quem chega na hora certa encontra atalhos.

2. O esqueleto de um componente

Um componente é um arquivo .svelte com até três partes, sempre nesta ordem. Só a do meio é obrigatória.

<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>
<h1>Olá, Ana</h1>
<script>
a lógica: variáveis, funções, importações. Roda uma vez, quando o componente é criado.
a marcação
o HTML com chaves. É a única parte obrigatória; sem ela, o componente não mostra nada.
<style>
o CSS, que fica restrito ao componente: as regras não vazam para os vizinhos.
{expressão}
um buraco no HTML onde entra um valor de JavaScript.
$state(…)
a runa que marca o valor como reativo: mudou, a tela redesenha.

O arquivo precisa começar com o bloco <script> se houver script — o compilador não aceita script depois da marcação. O <style> também fica no fim, e o compilador carimba cada regra com um selo svelte-xxxxxx para que ela atinja só este componente. Se você abrir o CSS gerado, vê o selo no seletor.

Para criar um componente novo, crie um arquivo com a primeira letra maiúscula: Cartao.svelte, ListaPedidos.svelte. Minúscula funciona em alguns casos, mas o Svelte trata maiúscula como componente e minúscula como tag HTML — a confusão custa uma tarde.

3. Runas: a cola completa

Runas são funções especiais que só podem ser escritas em posições específicas — quase sempre como valor inicial de um let, no topo do <script>. Elas começam com $ e não precisam de import.

RunaComo se escreveO que devolve
$statelet n = $state(0)valor reativo; mudou, a tela atualiza
$state.rawlet lista = $state.raw([1, 2])reativo só quando você troca a lista inteira
$state.snapshot$state.snapshot(estado)cópia comum, sem reatividade
$derivedlet dobro = $derived(n * 2)valor calculado a partir de outros
$derived.bylet total = $derived.by(() => { … })cálculo de várias linhas
$effect$effect(() => { … })nada; roda depois de desenhar
$effect.pre$effect.pre(() => { … })nada; roda antes de desenhar
$propslet { nome } = $props()as entradas que o pai passou
$bindablelet { valor = $bindable(0) } = $props()prop que o pai pode ligar com bind:
$inspect$inspect(nome)nada; registra no console em desenvolvimento
$hostconst eu = $host()o elemento hospedeiro, em custom element
$props.idconst id = $props.id()um identificador único para o componente

Duas regras resolvem a maioria dos tropeços. A primeira: runa não vai dentro de função, laço ou condição — só no topo do componente. A segunda: sem $state, a variável muda no JavaScript mas a tela não fica sabendo; é o erro número um de quem vem de outra linguagem.

Missão: o botão conta cliques, mas o número não sai do lugar. Faça o contador chegar a 1 depois de um clique.

<script>
  let tema = $state('claro');
  let n = 0;
</script>

<button onclick={() => n++}>{n}</button>
<script>
  let tema = $state('claro');
  let n = $state(0);
</script>

<button onclick={() => n++}>{n}</button>

Esta caixa guarda a pegadinha mais desconcertante do Svelte 5. Sozinha, a linha let n = 0 seria reativa: num arquivo sem nenhuma runa, o componente entra em modo legado e o let comum atualiza a tela quando você atribui. Mas a primeira linha (let tema = $state('claro'), que nem aparece na tela) coloca o componente no modo moderno, e ali o let comum perde essa reatividade: n++ muda a memória e a tela fica parada. Ou seja, um componente antigo funciona bem — e no dia em que você acrescenta a primeira runa, os outros let param de atualizar. É por isso que se converte um arquivo inteiro de uma vez, nunca uma linha solta.

4. Blocos de marcação

Blocos abrem com {# e fecham com {/. Todo bloco aberto precisa ser fechado, na ordem certa — é a causa de metade dos erros de compilação de quem está começando.

BlocoEscrevaFecha com
condição{#if ativo} … {:else if pausado} … {:else} … {/if}{/if}
lista{#each pedidos as pedido} … {/each}{/each}
lista com índice{#each pedidos as pedido, i} … {/each}{/each}
lista com chave{#each pedidos as pedido (pedido.id)} … {/each}{/each}
lista vazia{#each pedidos as p} … {:else} Nenhum pedido {/each}{/each}
promessa{#await p} … {:then v} … {:catch e} … {/await}{/await}
recomeço{#key filtro} … {/key}{/key}
trecho{#snippet linha(pedido)} … {/snippet}{/snippet}
desenhar trecho{@render linha(pedido)}—
HTML cru{@html textoComTags}—
constante no bloco{@const total = itens.length}—
depurador{@debug pedido}—

O bloco {#each} aceita as três formas juntas: {#each pedidos as pedido, i (pedido.id)} — item, índice e chave. A chave só é necessária quando a lista é reordenada e você quer que o Svelte reaproveite os elementos certos; com animate: ela é obrigatória.

<ul>
  {#each ['pão', 'leite'] as item, i (item)}
    <li>{i + 1}. {item}</li>
  {/each}
</ul>
<ul><li>1. pão</li><li>2. leite</li></ul>

Repare que o HTML gerado fica numa linha só: os espaços e quebras do arquivo servem para você, não para o navegador. O texto na tela seria 1. pão 2. leite, e é por isso que quem usa out: nas metas de caixa precisa tomar cuidado com espaço extra.

5. Diretivas e atributos

O Svelte estende o HTML com prefixos. Cada prefixo tem um papel fixo, e trocar dois de lugar costuma dar erro de compilação com mensagem clara.

DiretivaExemploPara que serve
onclickonclick={() => n++}evento, na forma atual
on:clickon:click={somar}evento, forma antiga (ainda compila, com aviso)
bind:valuebind:value={nome}liga um campo a uma variável, nos dois sentidos
bind:checkedbind:checked={pago}liga uma caixa de seleção a um booleano
bind:groupbind:group={escolha}liga vários rádios a uma variável só
bind:thisbind:this={caixa}guarda o elemento numa variável
class:ativoclass:ativo={pago}põe a classe quando a condição é verdadeira
style:colorstyle:color={cor}define uma propriedade de estilo
use:acaouse:clicarForaroda uma função quando o elemento entra
transition:fadetransition:fadeanimação de entrada e saída
in: / out:in:fly={{ y: 20 }}animação só ao entrar ou só ao sair
animate:flipanimate:flipanima a troca de posição numa lista com chave

As diretivas de evento merecem um parágrafo: a forma antiga on:click continua funcionando, mas o compilador avisa que ela está obsoleta. A forma atual é onclick, sem dois-pontos, e o valor precisa ser uma função — não uma chamada. onclick={somar} passa a função; onclick={somar()} chama na hora de desenhar, o que quase nunca é o que você quer.

A ligação de duas vias é o que faz formulário funcionar sem código extra. O valor do campo vai para a variável e a variável volta para o campo.

<script>
  let pedido = $state({ item: 'pão', preco: 8 });
</script>

<input bind:value={pedido.item} aria-label="item">
<p>{pedido.item}: R$ {pedido.preco}</p>
<input value="pão" aria-label="item"/> <p>pão: R$ 8</p>

No HTML gerado aparece value="pão": o valor inicial foi escrito no próprio elemento, para o navegador mostrar antes de o JavaScript rodar. Isso é o que permite o formulário chegar preenchido mesmo antes da hidratação.

6. Valores calculados sem $effect

Para um valor que depende de outros, $derived é a resposta. Ele se recalcula quando a base muda e nunca é atribuído à mão. $effect serve para outra coisa: efeitos colaterais, como registrar no console ou falar com uma API — e não para calcular o que aparece na tela.

Missão: o campo aceita um preço, mas o total fica congelado no valor inicial. Digite 20 e faça o total mostrar 18 (desconto de 10%).

<script>
  let preco = $state(10);
  let total = preco - preco / 10;
</script>

<input type="number" bind:value={preco} aria-label="preço">
<p>Total {total}</p>
<script>
  let preco = $state(10);
  let total = $derived(preco - preco / 10);
</script>

<input type="number" bind:value={preco} aria-label="preço">
<p>Total {total}</p>

A diferença entre os dois códigos é uma palavra. Sem $derived, a conta foi feita uma vez, quando o componente nasceu, e nunca mais. Com $derived, a conta é refeita toda vez que preco muda. Se a conta tiver várias linhas, use $derived.by(() => { … return resultado; }).

Um detalhe que confunde: atribuir a um $derived não dá erro — o valor simplesmente volta ao calculado no próximo desenho. Por isso, se você vê um valor que "não obedece", confira se ele não nasceu de uma runa derivada.

Uma das mais comuns é a de bloco não fechado, porque a mensagem aponta a tag, não o bloco. O exemplo abaixo tem uma lista sem {/each}, e o compilador reclama da </ul>:

O conserto é fechar o laço antes de fechar a lista. Leia a mensagem como "esta tag não devia estar aqui": quando uma tag parece certa, o problema está num bloco aberto acima dela.

Já os avisos não impedem a página de rodar. Os mais úteis: non_reactive_update (você atualiza uma variável que não é $state), state_referenced_locally (leu o valor de uma runa uma vez só, e ele não vai acompanhar mudanças) e event_directive_deprecated (usou on:click). Aviso é dica; erro é parede.

Quando a tela não mostra o que você espera, siga esta ordem. Cada passo custa segundos e elimina uma classe de problema.

Para ver valores sem poluir a tela, use $inspect: ele registra no console em desenvolvimento e some na build de produção. console.log dentro de um $effect também funciona, mas roda a cada mudança — útil para acompanhar, perigoso para esquecer ligado.

E lembre do {@debug}: colocado antes de uma expressão, ele pausa o depurador do navegador quando aquele valor muda. É a pausa cirúrgica, no lugar do monte de console.log.

10. Os cinco suspeitos de "não atualiza"

Quase todo relato de "o Svelte não atualiza" cai em uma destas cinco causas. Vale decorar a lista.

1. Falta $state. A variável muda, a tela não fica sabendo. É a causa da caixa da seção 3.

2. Componente em modo legado. Se o arquivo não tem nenhuma runa, o let comum é reativo; no momento em que você acrescenta $state em outro lugar, essa reatividade implícita desaparece. Misturar os dois mundos é o tropeço mais comum de quem copia exemplo antigo.

3. Objeto mutado sem trocar a referência. Com $state.raw, mutar um campo não redesenha; só substituir o objeto inteiro redesenha. Com $state comum, mutar campo funciona — mas mutar dentro de uma função assíncrona antiga pode escapar.

4. Conta feita uma vez. let total = preco * 2 é uma foto, não uma fórmula. Para fórmula, $derived.

5. Atributo em vez de diretiva. class="ativo" é texto fixo; class:ativo={pago} é condição. E style="color: red" não muda com variável — quem muda é style:color={cor}.

Regra de bolso

Se o valor depende de outro, é $derived. Se o valor é a fonte da verdade, é $state. Se serve para falar com o mundo de fora, é $effect. Não há quarta categoria.

Resumo

  • Componente: <script> com a lógica, marcação com chaves, <style> restrito.
  • $state é a fonte da verdade; $derived é o valor calculado; $effect é o efeito colateral.
  • Runa só no topo do <script>, como valor inicial de um let.
  • Todo bloco fechado com {/…}; lista com chave quando houver reordenação.
  • Evento com onclick={fn}: função, não chamada.
  • Formulário com bind:value, bind:checked, bind:group.
  • Mensagem que fala em tag costuma apontar bloco aberto acima.
  • npm run dev desenvolve, build empacota, preview confere.
  • "Não atualiza" quase sempre é falta de $state ou conta feita uma vez.
