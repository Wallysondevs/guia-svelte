Svelte · Diretivas

A Ana colou etiquetas coloridas nas gavetas da padaria. Verde quer dizer "conferido", amarela "falta repor", vermelha "vence hoje". A etiqueta não muda a gaveta: ela diz ao funcionário o que fazer com ela. No Svelte, as diretivas são essas etiquetas: atributos com dois-pontos no nome (bind:, class:, style:, use:, transition:) que dizem ao compilador para tratar aquele elemento de um jeito especial. Esta página é o mural com todas as etiquetas que existem.

Você vai aprender
  • O que o dois-pontos muda num atributo comum.
  • bind:value, bind:checked, bind:group e bind:this.
  • Como o bind: aparece no HTML gerado — quando aparece.
  • class: e style:, com e sem valor.
  • use: para rodar uma função quando o elemento é montado.
  • {@attach}, o jeito novo de fazer o mesmo trabalho.
  • transition:, in:, out: e animate:.
  • Por que use: e transição não mudam o HTML do servidor.
  • As mensagens reais quando a diretiva é usada no elemento errado.

1. A ideia: um atributo que o compilador trata diferente

Um atributo comum vai para o HTML como está: title="Salvar" vira title="Salvar" no arquivo final. Uma diretiva não vai: ela é uma instrução para o compilador, que gera código em vez de atributo. Você escreve bind:value={nome} e o navegador nunca vê esse texto — vê um input que já vem preenchido e um evento ligado.

O dois-pontos é o sinal. À esquerda fica o nome da diretiva, à direita o alvo (o evento, a classe, a propriedade). É uma sintaxe curta para algo que em JavaScript puro exigiria três ou quatro linhas: pegar o elemento, ler o valor, escutar a mudança, escrever de volta.

DiretivaFormaFaz o quê
bind:bind:value={nome}mantém valor e variável iguais nos dois sentidos
class:class:ativo={pago}liga ou desliga uma classe
style:style:color={cor}aplica uma propriedade de estilo
use:use:focarroda uma função quando o elemento é montado
transition:transition:fadeanima entrada e saída
in: / out:in:fly, out:fadeanima só a entrada ou só a saída
animate:animate:flipanima itens de uma lista com chave

Repare que todas terminam em dois-pontos, nunca em on:. O on:click do Svelte 4 é o único caso que você vai encontrar em código antigo; no Svelte 5 ele ainda compila, mas o compilador avisa que está fora de moda. O substituto é o atributo comum onclick, sem dois-pontos.

Vale entender o custo dessa escolha. Uma diretiva não é "mágica": ela é uma abreviação que o compilador expande. Quando você escreve bind:value, o resultado é um trecho de código que lê o campo, escuta o evento e escreve na variável; quando escreve class:ativo, o resultado é uma instrução que adiciona ou remove a classe conforme o valor. Saber disso ajuda no dia em que a diretiva não funciona: o problema quase sempre está no valor ligado, não na diretiva.

Há também um custo de leitura. Uma pessoa que abre o arquivo e vê bind:value={nome} entende em um segundo que campo e variável andam juntos. A mesma ligação escrita à mão ocupa quatro linhas e exige que o leitor reconstrua a intenção. Código curto que diz o que faz é a razão de as diretivas existirem.

2. bind:value: a via de mão dupla

O caso mais comum de todos: um campo de texto e uma variável que devem estar sempre iguais. Sem bind, você escuta o evento e copia o valor à mão. Com bind, o compilador escreve essa ligação para você.

<script>
  let nome = $state('Ana');
</script>

<input bind:value={nome} />
<p>Olá, {nome}</p>
<input value="Ana"/> <p>Olá, Ana</p>

O HTML gerado já traz value="Ana": o campo nasce preenchido com o valor da variável. A outra metade da ligação — do campo para a variável — não aparece no HTML porque é comportamento, não marcação: o compilador ligou um oninput interno que atualiza nome a cada tecla.

bind:value
a propriedade ligada. Para <input>, é o valor digitado; para <select>, a opção escolhida.
={nome}
a variável dos dois lados. Precisa ser declarada com $state para a tela acompanhar.
/>
o fim da tag. Em Svelte, elemento sem conteúdo pode fechar em si mesmo, como no XML.

Missão: o campo começa com Ana, mas digitar não muda o parágrafo. Faça o parágrafo acompanhar o que você digita, sem escrever oninput.

<script>
  let nome = $state('Ana');
</script>

<input value={nome} />
<p>Olá, {nome}</p>
<script>
  let nome = $state('Ana');
</script>

<input bind:value={nome} />
<p>Olá, {nome}</p>

Clique no campo, apague e digite Bia. A diferença entre os dois códigos é de quatro caracteres e de comportamento: no primeiro, o valor digitado fica só no campo; no segundo, ele volta para a variável e o parágrafo se redesenha.

3. bind:checked, bind:group e bind:value no select

Campo de texto é só o começo. Cada tipo de controle tem a propriedade que faz sentido ligar: caixa de seleção liga em checked, rádio liga em group, lista suspensa liga em value.

<script>
  let pago = $state(true);
</script>

<label>
  <input type="checkbox" bind:checked={pago} />
  Pago
</label>
<p>{pago ? 'pedido pago' : 'falta pagar'}</p>
<label><input type="checkbox" checked=""/> Pago</label> <p>pedido pago</p>

Atributo booleano aparece vazio quando é verdadeiro e desaparece quando é falso. É a mesma regra do disabled: presença significa sim.

Missão: a caixa começa marcada e o texto diz pedido pago. Ao desmarcar, o texto deve virar falta pagar.

<script>
  let pago = $state(true);
</script>

<input type="checkbox" checked={pago} />
<p>{pago ? 'pedido pago' : 'falta pagar'}</p>
<script>
  let pago = $state(true);
</script>

<input type="checkbox" bind:checked={pago} />
<p>{pago ? 'pedido pago' : 'falta pagar'}</p>

Agora os dois primos. O bind:group junta vários rádios numa variável só — a escolha vira o valor do rádio selecionado:

<script>
  let tamanho = $state('médio');
</script>

<label><input type="radio" value="pequeno" bind:group={tamanho} /> pequeno</label>
<label><input type="radio" value="médio" bind:group={tamanho} /> médio</label>
<p>{tamanho}</p>
<label><input type="radio" value="pequeno"/> pequeno</label> <label><input type="radio" value="médio" checked=""/> médio</label> <p>médio</p>

O checked="" apareceu no rádio que combina com o valor inicial. E no <select>, o valor ligado põe selected na opção certa:

<script>
  let sabor = $state('queijo');
</script>

<select bind:value={sabor}>
  <option value="queijo">queijo</option>
  <option value="frango">frango</option>
</select>
<p>{sabor}</p>
<select><option value="queijo" selected="">queijo</option><option value="frango">frango</option></select> <p>queijo</p>

4. bind:this e as medidas do elemento

Às vezes você precisa do elemento em si, não do valor dele: para chamar focus(), medir a largura, montar um gráfico. O bind:this guarda a referência numa variável:

<script>
  let campo;
</script>

<input bind:this={campo} placeholder="nome" />
<button onclick={() => campo.focus()}>focar</button>
<input placeholder="nome"/> <button>focar</button>

A variável campo não tem $state de propósito: ninguém precisa redesenhar a tela quando a referência muda. Ela vale undefined até o elemento existir — e no servidor nunca existe, porque não há DOM. Por isso o HTML gerado não mostra nada de bind:this.

A mesma ideia serve para medidas. bind:clientWidth escreve na variável a largura interna do elemento e atualiza quando ela muda:

<script>
  let caixa;
  let largura = $state(0);
</script>

<div bind:this={caixa} bind:clientWidth={largura}>
  <p>{largura}px</p>
</div>
<div><p>0px</p></div>

Zero é o valor inicial, e é o que o servidor consegue saber: sem navegador, não há layout. No navegador a medida chega no primeiro quadro e o número aparece. Existem variantes para altura (clientHeight), para o tamanho total com borda (offsetWidth) e para a posição (clientTop).

5. class:: uma classe que liga e desliga

Trocar classe por condição é o pão de cada dia do CSS. Em vez de montar o texto da classe com ? e +, você usa class::

<script>
  let negrito = $state(true);
  let ativo = $state(false);
</script>

<p class:negrito class:ativo>Pão</p>

<style>
  .negrito { font-weight: bold; }
  .ativo { color: #2e7d32; }
</style>
<p class="svelte-1nuilkk negrito">Pão</p>

Sem valor depois do nome, a diretiva usa a variável de mesmo nome como condição: class:negrito vale porque negrito é true, e class:ativo não vale porque ativo é false. Com valor, você escolhe outra variável: class:negrito={preco > 10}.

Repare na ordem das classes no HTML: primeiro o selo do estilo escopado, depois a classe da diretiva. Se você também escrever um class="…" comum, ele vem antes do selo. A ordem não importa para o CSS; importa apenas para quem compara texto de HTML — como as caixas deste guia.

class:nome não é class="nome"

class:nome sem valor liga a classe nome quando a variável nome for verdadeira. Se você queria só escrever a classe, use class="nome". O compilador aceita as duas formas e não avisa — a diferença aparece quando a variável fica falsa e a classe some sozinha.

6. style:: a propriedade que acompanha o valor

style: faz com estilo o que class: faz com classe: liga uma propriedade a um valor. Serve para números que mudam (uma barra de progresso, uma cor escolhida pelo cliente):

<script>
  let cor = $state('#2e7d32');
  let grande = $state(true);
</script>

<p style:color={cor} style:font-size={grande ? '20px' : '12px'}>Pão</p>
<p style="color: #2e7d32; font-size: 20px;">Pão</p>

O compilador juntou as duas diretivas num único atributo style, na ordem em que foram escritas. Quando um valor vira null ou undefined, a propriedade sai do atributo — é a forma de "desligar" um estilo sem escrever uma string vazia.

O nome da propriedade segue o CSS e aceita hífen: style:font-size, style:background-color. Também é possível usar style:--minha-variavel para variáveis CSS. O que não pode é deixar o nome vazio, como na seção de erros.

7. use:: uma função quando o elemento nasce

Existem tarefas que só fazem sentido no navegador: dar foco, iniciar um mapa, medir, escutar um evento global. A diretiva use: entrega o elemento para uma função sua no momento em que ele é montado:

<script>
  function focar(node) {
    node.focus();
    return {
      destroy() {
        console.log('saiu');
      }
    };
  }
</script>

<input use:focar placeholder="nome" />
<input placeholder="nome"/>

A função recebe o elemento e pode devolver um objeto com destroy — o código de limpeza, que roda quando o elemento sai da tela. Devolver update também é possível: ele roda quando os parâmetros da ação mudam (use:medir={largura}). No servidor, a ação não roda e o HTML sai limpo, como acima.

Uma ação bem escrita devolve sempre a limpeza do que criou. Sem isso, cada elemento que sai deixa um ouvinte de evento pendurado na memória — o tipo de vazamento que só aparece depois de meia hora de uso.

A ação pode receber parâmetro: use:medir={largura} entrega largura como segundo argumento da função. Quando esse parâmetro muda, o Svelte chama update(novoValor) se a ação devolver essa função no objeto. É assim que uma biblioteca de gráficos redesenha quando os dados mudam, sem que o componente precise desmontar e montar de novo.

O nome "ação" (action) vem do Svelte 3 e continua valendo. A função não tem acesso a estado reativo por conta própria: ela recebe o nó e os parâmetros, e devolve funções de ciclo de vida. Para observar estado dentro de uma ação, você lê o valor no momento da chamada ou usa uma closure que o componente atualiza.

8. {@attach}: o parente novo do use:

O Svelte 5 acrescentou uma forma mais simples de fazer o mesmo trabalho: em vez de uma diretiva com nome, uma expressão anexada ao elemento. O resultado é o mesmo, e a função pode ser passada de qualquer jeito — inclusive vinda de outro módulo:

<script>
  function pintar(node) {
    node.style.background = '#e8f5e9';
  }
</script>

<p {@attach pintar}>Pão</p>
<p>Pão</p>

No servidor, a função não roda e o HTML sai sem estilo — a cor aparece no navegador. A vantagem sobre use: é que {@attach} aceita qualquer expressão que devolva uma função, então dá para escolher a função por condição. A desvantagem é que ele não tem nome no HTML, o que torna a leitura um pouco menos autoexplicativa.

Na prática, a regra de escolha é simples. Se a função tem nome fixo e recebe parâmetros que mudam, use: é mais direto e mais fácil de achar com uma busca no projeto. Se a função vem de uma expressão, de um objeto ou muda conforme o estado, {@attach} resolve sem gambiarra. As duas formas convivem no mesmo componente sem conflito.

Existe ainda um detalhe de ordem que confunde: o anexo roda depois que o elemento existe, mas antes de algumas medidas estarem prontas. Se a função precisa da largura final, meça no próximo quadro com requestAnimationFrame — ou use bind:clientWidth, que já cuida disso.

Missão: a função esticar existe mas ninguém a usa. Anexe-a ao parágrafo com {@attach} para a tela mostrar Pão!.

<script>
  function esticar(node) {
    node.textContent = node.textContent + '!';
  }
</script>

<p>Pão</p>
<script>
  function esticar(node) {
    node.textContent = node.textContent + '!';
  }
</script>

<p {@attach esticar}>Pão</p>

A caixa acima é honesta sobre o que o anexo faz: ele mexe no DOM depois que o Svelte desenhou. Funciona para dar foco, medir, iniciar biblioteca — e é uma porta para sair do fluxo normal do componente. Prefira class: e style: quando o efeito é visual e pode ser descrito em CSS.

9. Transições: transition:, in:, out: e animate:

Transição é animação de entrada e saída. Você importa uma função pronta de svelte/transition e aplica no elemento:

<script>
  import { fade } from 'svelte/transition';
  let visivel = $state(true);
</script>

{#if visivel}
  <p transition:fade>Pão quentinho</p>
{/if}
<button onclick={() => (visivel = !visivel)}>alternar</button>
<p>Pão quentinho</p> <button>alternar</button>

No HTML do servidor, o parágrafo sai sem nenhum sinal de transição. A animação é comportamento de navegador: o elemento entra e sai com opacidade gradual, controlada pelo runtime. Se o JavaScript não carregar, o conteúdo continua lá — o que é o comportamento certo para uma página pública.

As variantes servem para animar só um lado: in:fly anima a entrada, out:fade anima a saída. E animate:flip é diferente das outras: ele anima itens de uma lista quando a ordem muda, e exige um {#each} com chave:

<script>
  import { flip } from 'svelte/animate';
  let lista = $state([{ id: 1, nome: 'pão' }, { id: 2, nome: 'leite' }]);
</script>

<ul>
  {#each lista as item (item.id)}
    <li animate:flip>{item.nome}</li>
  {/each}
</ul>
<ul><li>pão</li><li>leite</li></ul>

10. Quando dá errado

As quatro mensagens abaixo saíram do compilador desta versão. Cada uma aponta o que a diretiva precisa e onde ela não pode ficar.

Erro 1 — bind:value em elemento que não tem valor

Só campo de formulário tem valor para ligar. Uma <div> ou um <span> não têm.

<script>
  let nome = $state('Ana');
</script>

<span bind:value={nome}>{nome}</span>
Erro de compilação (linha 5, coluna 6): `bind:value` can only be used with `<input>`, `<textarea>`, `<select>`

A mensagem já entrega a lista: "só pode ser usada com input, textarea, select". Para mostrar um valor em texto, use {nome}; para editar, use um campo.

Erro 2 — diretiva entre aspas

O alvo de uma diretiva é um nome ou uma expressão, nunca uma string. Entre aspas, o compilador espera um sinal de igual.

<input use:"focar" />
Erro de compilação (linha 1, coluna 11): Expected token =

"Expected token =" quer dizer "esperava um sinal de igual". Escreva use:focar (sem aspas) ou use:focar={parametro} quando a ação recebe parâmetro.

Erro 3 — nome de estilo vazio

style: precisa do nome da propriedade CSS. Sem nome, não há o que aplicar.

<p style:>Pão</p>
Erro de compilação (linha 1, coluna 3): `style:` name cannot be empty

"Name cannot be empty" é literal: o nome não pode ficar vazio. O formato é style:cor={valor}, com o nome da propriedade logo depois dos dois-pontos.

Erro 4 — animate: em lista sem chave

Animar a reordenação exige que o compilador saiba qual item é qual. Sem chave no {#each}, ele não sabe — e a mensagem explica o que fazer.

<script>
  import { flip } from 'svelte/animate';
  let lista = $state([1, 2]);
</script>

{#each lista as n}
  <p animate:flip>{n}</p>
{/each}
Erro de compilação (linha 7, coluna 5): An element that uses the `animate:` directive must be the only child of a keyed `{#each ...}` block. Did you forget to add a key to your each block?

A tradução: "um elemento que usa animate: precisa ser o único filho de um bloco {#each} com chave; esqueceu de adicionar a chave?". A correção é {#each lista as n (n)}.

Resumo

  • Diretiva é atributo com dois-pontos: o compilador gera código em vez de escrever o atributo no HTML.
  • bind:value liga campo e variável nos dois sentidos; o HTML sai com value já preenchido.
  • bind:checked para caixa, bind:group para rádios, bind:value também no <select>.
  • bind:this guarda o elemento; bind:clientWidth e parentes medem — no servidor, medida é zero.
  • class:nome sem valor usa a variável de mesmo nome como condição; class:nome={outra} escolhe a condição.
  • style:propriedade={valor} junta tudo num atributo style; valor nulo remove a propriedade.
  • use:funcao roda quando o elemento monta e pode devolver destroy e update.
  • {@attach funcao} é a forma nova, com expressão em vez de nome fixo.
  • Transições (transition:, in:, out:) e animate: são comportamento de navegador; o HTML do servidor sai limpo.
  • Erro de diretiva costuma vir com a lista de onde ela pode ser usada — leia a lista antes de tentar outra coisa.
