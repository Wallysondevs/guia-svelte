Svelte · Glossário

A Ana tem um caderno com as palavras que ouve dos clientes e o que cada uma quer dizer na padaria: "fiado", "encomenda", "fornada". Sem esse caderno, o funcionário novo passa a semana perguntando. Este é o caderno de palavras do Svelte. Cada termo tem uma definição curta, dita em português de gente, e uma pista de onde ele aparece no código. Quando você encontrar uma palavra que não conhece numa aula, volte aqui.

Você vai aprender
  • O vocabulário mínimo para ler qualquer aula do guia.
  • A diferença entre estado, derivado e prop — a confusão mais comum.
  • O que é runa, diretiva, bloco e snippet, e por que cada um tem nome próprio.
  • O significado das siglas: SSR, DOM, SPA, FLIP.
  • O que muda entre compilação, execução e aviso.
  • Os comandos que aparecem nos terminais do guia.
  • Os pares de termos que parecem sinônimos e não são.
  • Onde encontrar a aula completa de cada assunto.

1. Como usar este glossário

As definições são curtas de propósito: o glossário serve para desbloquear a leitura, não para substituir a aula. Se um termo aparecer no meio de um exercício e você não lembrar o que ele faz, leia a linha aqui, siga o exercício e depois volte à aula indicada para o exemplo completo.

A ordem é alfabética dentro de seis faixas. Cada faixa tem uma tabela com três colunas: o termo, o que ele é em uma frase, e onde você o encontra. Termos em inglês ficam com o original entre parênteses, porque a documentação oficial usa o inglês e uma hora você vai precisar procurar lá.

No fim da página há duas seções diferentes: os pares que confundem, com a diferença explicada em duas colunas, e a tabela de siglas e comandos, que é a que você mais vai consultar no terminal.

2. O componente por dentro: o mapa mínimo

Antes das letras, o desenho da peça central. Um componente é um arquivo .svelte com até três blocos, e tudo o que o glossário define depois é uma parte desse desenho:

<script>
  let nome = $state('Ana');
</script>

<h1>Olá, {nome}</h1>

<style>
  h1 { color: #2e7d32; }
</style>
<h1 class="svelte-1ekmh8m">Olá, Ana</h1>

O HTML que o navegador recebe não tem o script nem o estilo: tem só o h1 com o valor já resolvido e um selo de classe. O CSS gerado para esse componente é este:

h1.svelte-1ekmh8m { color: #2e7d32; }
componente
o arquivo inteiro. Nome em maiúscula (Saudacao.svelte) e uma responsabilidade só.
estado
nome, criado com $state: o valor que, ao mudar, redesenha a tela.
marcação
o <h1> com chaves. As chaves são a porta por onde o estado entra no HTML.
CSS escopado
o <style>, que virou h1.svelte-1ekmh8m. O selo é a garantia de que a regra não vaza.

Guarde duas coisas desse desenho. Primeira: o estado mora no script e aparece na marcação por chaves — o caminho é sempre de cima para baixo. Segunda: o estilo não viaja; ele fica preso ao componente pelo selo. Todo o resto do vocabulário do Svelte é uma variação dessas duas ideias: um valor que desce para a tela, ou uma instrução que o compilador reescreve.

Agora as letras. Cada entrada é uma frase curta com a palavra-chave em negrito — a mesma que você vai ver no código. Onde houver duas palavras parecidas, a seção 9 desfaz a confusão com uma tabela de pares.

Repare que callback e children são os dois jeitos de um componente conversar com outro: um manda função, o outro manda marcação. Quando você se pegar procurando "evento de componente" ou "slot", é aqui que a resposta está — esses nomes saíram de moda no Svelte 5.

Missão: o termo estado quer dizer que a tela acompanha o valor. Faça o botão chegar a Cliques: 1 com um clique.

<script>
  let nome = $state('Ana');
  let cliques = 0;
</script>

<button onclick={() => cliques++}>Cliques: {cliques}</button>
<script>
  let nome = $state('Ana');
  let cliques = $state(0);
</script>

<button onclick={() => cliques++}>Cliques: {cliques}</button>

4. De D a E

Aqui ficam as palavras que mais aparecem em mensagem de erro: derivado, diretiva, efeito e estado. Se o compilador reclamar de uma delas, a definição abaixo diz onde ela pode morar.

Estado e derivado são primos, não sinônimos: estado é o que você digita, derivado é o que se calcula. Guardar o total como estado e atualizar à mão em cada lugar é a origem de metade dos bugs de tela que mostram número errado.

Missão: o termo derivado pede duas casas no dinheiro. Faça a tela mostrar Total: R$ 1.80 usando um valor derivado formatado.

<script>
  let { preco = 0.9, qtd = 2 } = $props();
</script>

<p>Total: R$ {preco * qtd}</p>
<script>
  let { preco = 0.9, qtd = 2 } = $props();
  let total = $derived(preco * qtd);
</script>

<p>Total: R$ {total.toFixed(2)}</p>

Instância é uma palavra que vale a pena fixar: o arquivo Cartao.svelte é um só, mas cada uso cria uma instância com estado independente. Dois cartões na tela têm duas cópias do $state, e mudar um não muda o outro — a não ser que o valor venha de uma prop ou de um contexto.

A palavra prop é abreviação de property, propriedade. No guia ela aparece sempre no feminino — "a prop" — para não confundir com a propriedade de um objeto JavaScript, que é outra coisa.

7. De Q a S

Esta é a faixa da reatividade e da renderização: runa, snippet, SSR, store. São termos que aparecem em documentação oficial e em conversa de equipe, e quase todos têm uma aula própria no guia.

TermoO que éOnde aparece
reatividadecapacidade de redesenhar a tela quando um valor muda$state, $derived
renderizaçãotransformar componente em HTML (servidor) ou DOM (navegador)render(), mount()
rotaendereço que corresponde a um arquivo de página no SvelteKitsrc/routes/
runapalavra com cifrão que o compilador reconhece e reescreve$state, $props
snippettrecho de marcação com nome, declarado e renderizado no componente{#snippet}, {@render}
slotmecanismo antigo de receber conteúdo; substituído por snippetscódigo do Svelte 4
SPAaplicação de uma página só, que troca conteúdo sem recarregarnavegação no cliente
SSRrenderização no servidor: o HTML chega pronto ao navegadorrender(), SvelteKit

<svelte:element>elemento especial que escolhe a tag em tempo de execuçãothis={tag}

Uma distinção que evita confusão em conversa: SSR é o que acontece no servidor (o HTML sai pronto), hidratação é o que acontece no navegador logo depois (o HTML ganha vida). Um projeto pode ter SSR e mesmo assim não hidratar — nesse caso, a página é só leitura.

O termo reatividade quando falta a runa

A tela deveria acompanhar cliques, mas a variável não foi declarada com $state. O compilador avisa com o nome do problema — e o nome está neste glossário.

non_reactive_update: `cliques` is updated, but is not declared with `$state(...)`. Changing its value will not correctly trigger updates

Traduzindo com os termos desta página: a atualização não é reativa. O valor muda no script, mas nenhum desenho é disparado. Conserto: declarar como estado.

Missão: o termo ligação de duas vias (bind) resolve este caso. Faça o parágrafo acompanhar o que você digita no campo.

<script>
  let nome = $state('Ana');
</script>

<input value={nome} />
<p>{nome}</p>
<script>
  let nome = $state('Ana');
</script>

<input bind:value={nome} />
<p>{nome}</p>

8. De T a Z

O fim do alfabeto tem o vocabulário de ferramenta: tag, tick, transição, Vite. São palavras que você vai ouvir em reunião e ler no terminal, mais do que escrever no componente.

TermoO que éOnde aparece
tagelemento do HTML, com abertura e fechamento<p>…</p>
tickpromessa que resolve no próximo desenho da telaawait tick()
transiçãoanimação de entrada e saída de um elementotransition:fade
tree-shakingdescarte do código que ninguém usa no buildnpm run build

valor padrãoo que vale quando a prop não é passadalet { x = 1 } = $props()

Tree-shaking é o nome bonito de uma ideia simples: se ninguém importa uma função, ela não vai para o arquivo final. É por isso que o tamanho do build não cresce com o tamanho da biblioteca, só com o que você usa dela.

O Vite merece um parágrafo próprio porque o nome aparece em toda saída de terminal do guia. Ele é o servidor de desenvolvimento e o empacotador: no npm run dev, mantém os arquivos em memória e recarrega o navegador a cada mudança; no npm run build, junta tudo em poucos arquivos com hash no nome. O Svelte é o compilador dos arquivos .svelte; o Vite é quem orquestra o resto. Confundir os dois leva a procurar configuração de Svelte num arquivo que é do Vite.

9. Pares que confundem

Estes são os termos que mais aparecem trocados em conversa de equipe e em mensagem de erro. A diferença é curta e vale decorar.

ParUm é…O outro é…
estado × derivadoo dado que você digita e mudaa conta que se refaz a partir dele
prop × estadoo que vem de fora e não pertence ao componenteo que nasce dentro e é do componente
compilação × execuçãoantes de a página existir; erro com linha e colunacom a página montada; erro no console, sem posição
erro × avisoimpede o arquivo de virar JavaScriptdeixa passar e esconde um bug
componente × snippetarquivo com identidade, estado e ciclo de vidapedaço de marcação dentro de um componente
bind × callbackduas vias: o filho muda o valor do paiuma via: o filho avisa, o pai decide
SSR × hidrataçãoo HTML nasce no servidoro HTML ganha comportamento no navegador
store × contextoestado compartilhado por importação, global ao móduloestado compartilhado pela árvore de componentes

Uma regra de bolso para não errar: se o valor precisa aparecer em lugares que não têm relação de pai e filho, provavelmente é store; se ele pertence a uma parte da tela, é contexto; se pertence a um componente só, é estado.

11. Referência rápida: onde está a aula

O glossário define; a aula ensina. A tabela liga cada grupo de termos à página do guia que mostra o exemplo completo.

Resumo

  • Componente é o arquivo .svelte, com script, marcação e estilo; a tag usa o nome do arquivo em maiúscula.
  • Estado é o que muda e redesenha; derivado é o que se calcula a partir dele.
  • Prop vem de fora, callback avisa o pai, children traz marcação.
  • Runa é símbolo do compilador ($state, $props), não função importada.
  • Diretiva tem dois-pontos; bloco abre com {#; snippet tem nome e é renderizado com {@render}.
  • CSS escopado ganha um selo (svelte-1ekmh8m) que impede vazamento de estilo.
  • SSR é o HTML nascendo no servidor; hidratação é ele ganhando vida no navegador.
  • Compilação erra com linha e coluna; execução erra no console, sem posição.
  • Aviso não bloqueia e esconde bug; trate como erro quando o assunto é reatividade.
  • npm run dev serve, npm run build gera, npm run preview confere.
