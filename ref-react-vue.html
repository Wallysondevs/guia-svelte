Svelte · Vindo de React ou Vue

A Ana trocou o caderno de papel por um aplicativo de pedidos. Ela já sabia anotar pedido, somar troco e riscar o que saiu — o que mudou foi o lugar onde se escreve. Quem vem de React ou de Vue está na mesma situação: o problema (tela que acompanha dado) é o mesmo, os nomes é que mudam. Esta página é a tabela de tradução, com o código dos três e a saída real do lado do Svelte.

Você vai aprender
  • O que o compilador do Svelte faz que React e Vue deixam para o navegador.
  • useState → $state, useMemo → $derived, useEffect → $effect.
  • Como props, children e listas com chave aparecem nos três.
  • ref, computed, watch e v-model traduzidos para runas.
  • Por que bind:value dispensa o par valor + onChange.
  • O que não tem equivalente direto, e o que você deixa de precisar.
  • Onde o Svelte cobra um preço diferente das outras duas.
  • As mensagens reais quando alguém traz um hábito antigo para o arquivo novo.

1. A ideia: o compilador conhece o seu componente

Em React e em Vue, o componente é uma função que roda de novo a cada mudança, e a biblioteca compara o resultado com o anterior para decidir o que atualizar. No Svelte, o compilador lê o seu arquivo e escreve código que atualiza só o pedaço que mudou — sem comparação, sem rodar a função inteira de novo. É por isso que não existe useMemo: não há trabalho repetido para evitar.

Essa diferença muda o que você escreve. Em React, você declara dependências em arrays e reza para não esquecer uma; em Svelte, o compilador descobre as dependências lendo o seu código. Em Vue, você lembra de usar .value nos refs; em Svelte, a variável é a variável. O preço é que o arquivo .svelte não é JavaScript puro: ele precisa do compilador, e o jeito de escrever tem regras próprias (as runas).

<script>
  let cliques = $state(0);
</script>

<button onclick={() => cliques++}>Cliques: {cliques}</button>
<button>Cliques: 0</button>

Em React, o mesmo contador tem três linhas de importação e um setState:

import { useState } from 'react';

export default function Contador() {
  const [cliques, setCliques] = useState(0);
  return <button onClick={() => setCliques(cliques + 1)}>Cliques: {cliques}</button>;
}

Em Vue, o mesmo contador usa ref e .value dentro do script:

<script setup>
import { ref } from 'vue';
const cliques = ref(0);
</script>

<template>
  <button @click="cliques++">Cliques: {{ cliques }}</button>
</template>
let cliques = $state(0)
o estado. Substitui useState(0) e ref(0) ao mesmo tempo.
cliques++
a mutação. Não existe setCliques nem .value: a variável é a variável.
onclick
o evento como atributo comum. Substitui onClick do React e @click do Vue.
{cliques}
a interpolação. Uma chave, sem {{ }} duplo e sem {} de JSX com return.

2. De React: useState vira $state

A tradução mais direta é a do estado. A diferença de comportamento aparece em objetos e listas: no React, você sempre cria um valor novo e chama o setter; no Svelte, você pode mutar o objeto direto, porque o estado é profundo.

ReactSvelte 5Diferença prática
useState(0)$state(0)sem setter; atribui direto
setN(n + 1)n++ ou n = n + 1a variável é o próprio valor
setLista([...lista, x])lista.push(x)mutar já notifica
useRef(0) (valor mutável sem render)let x = 0variável comum não redesenha
useState(() => caro())$state(caro())roda uma vez, na criação

A última linha merece atenção: no React, passar uma função para useState significa "calcule só na primeira vez". Em Svelte, $state(caro()) já roda uma vez só, porque o script do componente é executado uma vez por instância — não a cada mudança, como a função do React.

O hábito de criar um valor novo a cada mudança não é errado no Svelte: funciona perfeitamente. Só é mais código. A exceção é $state.raw, que exige a troca do valor inteiro para avisar a tela.

Missão: o código escuta o evento mas esquece de guardar o valor, como um onChange do React sem setState. Faça o parágrafo acompanhar o campo.

<script>
  let nome = $state('Ana');
  function aoDigitar(evento) {
    evento.target.value;
  }
</script>

<input oninput={aoDigitar} />
<p>{nome}</p>
<script>
  let nome = $state('Ana');
</script>

<input bind:value={nome} />
<p>{nome}</p>

A solução não tem função nenhuma: bind:value já escreve no estado a cada tecla. É a diferença de mentalidade — em vez de "escuto e atualizo", você diz "estes dois andam juntos".

3. De React: useMemo e useEffect

Valor calculado e efeito colateral são duas coisas que o React trata com funções e arrays de dependência. No Svelte, são duas runas e o compilador cuida das dependências.

// React
const total = useMemo(() => preco * qtd, [preco, qtd]);

useEffect(() => {
  document.title = `Total: ${total}`;
}, [total]);

No Svelte, a conta vira $derived e o efeito vira $effect. Nenhum array de dependência:

<script>
  let total = $state(0);
  $effect(() => {
    document.title = `Total: ${total}`;
  });
</script>

<p>{total}</p>
<p>0</p>

O efeito não desenha nada: a saída é só o parágrafo. No navegador, o título da aba muda quando total muda, e o compilador sabe que a dependência é total porque ele lê o código. Se você escrever uma leitura condicional, o compilador acompanha o que foi lido naquela execução — mais preciso do que a lista fixa do React.

ReactSvelte 5Observação
useMemo(fn, [deps])$derived(expr)a conta é refeita quando preciso, com cache
useMemo com laço$derived.by(() => { … })quando a conta tem mais de uma linha
useEffect(fn, [])onMount(fn)só no navegador, uma vez
useEffect(fn, [x])$effect(() => { … x … })dependência lida do código
useEffect(() => {…; return cleanup}, [])$effect(() => { …; return cleanup })a limpeza continua sendo retorno
useLayoutEffect$effect.pre(fn)roda antes do desenho

Missão: a conta é feita uma vez só, como uma variável comum. Faça o total acompanhar a quantidade — usando um valor derivado, sem efeito.

<script>
  let qtd = $state(2);
  let preco = 0.9;
  let total = preco * qtd;
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<button onclick={() => qtd++}>somar</button>
<script>
  let qtd = $state(2);
  let preco = 0.9;
  let total = $derived(preco * qtd);
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<button onclick={() => qtd++}>somar</button>

Quem vem do React costuma resolver isso com efeito: "quando qtd mudar, recalcule total". Funciona e é o caminho errado — cria um segundo dono do dado e uma rodada extra de desenho. Derivado não é efeito; é conta.

4. De React: props, children e listas

Props em React chegam como objeto da função; em Svelte, chegam por $props() desestruturado. O conteúdo entre as tags (o children do React) é um snippet, renderizado com {@render}.

// React
function Cartao({ titulo = 'Pão francês', children }) {
  return (
    <section>
      <h2>{titulo}</h2>
      {children}
    </section>
  );
}
<script>
  let { titulo = 'Pão francês', children } = $props();
</script>

<section>
  <h2>{titulo}</h2>
  {@render children?.()}
</section>
<section><h2>Pão francês</h2> </section>

Repare que o cartão sozinho mostra o título e nada mais: o conteúdo não existe, e o ?. evita a chamada. Com <Cartao><p>Feito na hora.</p></Cartao>, o parágrafo aparece no lugar de {@render children()}.

Listas seguem a mesma lógica, com uma diferença de sintaxe importante: no React, a chave vai no elemento (key={item.id}); no Svelte, vai no bloco ((item.id), entre parênteses, depois do item).

<script>
  let tarefas = $state([
    { id: 1, nome: 'assar o pão' },
    { id: 2, nome: 'abrir a caixa' }
  ]);
</script>

<ul>
  {#each tarefas as tarefa (tarefa.id)}
    <li>{tarefa.nome}</li>
  {/each}
</ul>
<ul><li>assar o pão</li><li>abrir a caixa</li></ul>
ReactSvelte 5
function X({ a, b = 1 })let { a, b = 1 } = $props()
{children}{@render children?.()}
props.onSave(v)onSave(v) — prop de função
key={item.id}{#each l as item (item.id)}
{cond && <p>…</p>}{#if cond}<p>…</p>{/if}
dangerouslySetInnerHTML{@html texto}
className="x"class="x" e class:ativo
style={{ color }}style:color={cor}

Missão: a tela mostra as tags escritas. Faça o navegador desenhar o negrito de verdade — o equivalente ao dangerouslySetInnerHTML do React.

<script>
  let texto = $state('<b>pão quentinho</b>');
</script>

<p>{texto}</p>
<script>
  let texto = $state('<b>pão quentinho</b>');
</script>

<p>{@html texto}</p>

O aviso é o mesmo nos dois mundos: {@html} é porta aberta para injeção. Só use com texto que você gerou; nunca com o que veio digitado por outra pessoa sem limpeza antes.

5. De Vue: ref, computed e watch

Quem vem de Vue tem uma vantagem: o modelo mental é parecido. A composição de funções, o valor reativo e o cálculo derivado existem nos dois. O que muda é o nome e o .value.

Vue 3Svelte 5Diferença
ref(0) e n.value++$state(0) e n++sem .value
reactive({})$state({})um só jeito para tudo
computed(() => a * b)$derived(a * b)sem .value na leitura
watch(x, fn)$effect(() => { … x … })dependência automática
watchEffect(fn)$effect(fn)praticamente igual
onMounted(fn)onMount(fn)mesmo nome, mesma ideia
onUnmounted(fn)onDestroy(fn) ou retorno do efeitolimpeza explícita
props / defineProps$props()desestruturação direta
provide / injectsetContext / getContextchave como endereço

A diferença que mais rende linha de código é o .value. Em Vue, dentro do script, todo ref precisa dele; no template, não. Em Svelte, a variável é sempre ela mesma, e não há dois mundos para lembrar. Quem programa em Vue sabe o tempo que se perde com um .value esquecido.

// Vue 3 — script setup
import { ref, computed } from 'vue';
const qtd = ref(2);
const preco = 0.9;
const total = computed(() => preco * qtd.value);
<script>
  let qtd = $state(2);
  let preco = 0.9;
  let total = $derived(preco * qtd);
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 1.80</p>

6. De Vue: v-if, v-for, v-model e slots

As diretivas de template do Vue têm primos próximos no Svelte. v-if vira {#if}, v-for vira {#each}, v-model vira bind:value e slot vira snippet.

Vue 3Svelte 5Tipo
v-if="aberta"{#if aberta}bloco
v-else-if / v-else{:else if} / {:else}seção de bloco
v-for="x in lista"{#each lista as x}bloco
:key="x.id"{#each lista as x (x.id)}chave no bloco
v-model="nome"bind:value={nome}ligação
:class="{ ativo }"class:ativodiretiva
:style="{ color }"style:color={cor}diretiva
<slot />{@render children()}conteúdo
<slot name="topo" />{@render topo()}snippet nomeado

Um detalhe de v-for que confunde: em Vue, v-for="x in lista" aceita lista, objeto e número. Em Svelte, {#each} precisa de algo iterável; um número não é lista. Se você tem o número 5 e quer cinco itens, gere a lista antes: {#each Array.from({ length: 5 }, (_, i) => i) as i}.

7. As três diferenças de modelo

Depois da tradução de sintaxe, restam três diferenças que mudam decisões de projeto. Elas aparecem em entrevista e em discussão de arquitetura, e é melhor conhecê-las antes de defender o Svelte numa reunião.

Primeira: quem sabe das dependências. Em React, você declara o array e o hook compara; em Vue, a reatividade é por proxy em tempo de execução; em Svelte, o compilador lê o código e gera a lista. A consequência é que erros de dependência faltando praticamente não existem no Svelte — e, em troca, o arquivo precisa ser compilado.

Segunda: quando o componente roda. Em React, a função do componente roda muitas vezes; em Svelte, o script roda uma vez e o compilador atualiza pedaços. Isso significa que código no topo do <script> é executado uma vez — o que dispensa useMemo, mas exige cuidado com trabalho caro no corpo do componente: ele não repete, mas também não se atualiza.

Terceira: o CSS. React não tem opinião sobre estilo: CSS Modules, styled-components, Tailwind, global. Vue tem <style scoped>. Svelte já entrega escopo por padrão, com o selo no seletor. Se você vem de React e usava CSS global, vai estranhar no começo: o estilo do componente não alcança o que está fora, e é preciso :global(…) quando a intenção é global.

8. O que não tem equivalente direto

Nem tudo traduz. Estes são os pontos em que o Svelte resolveu o problema de outro jeito, e você precisa reaprender em vez de traduzir:

Eventos de componente. React passa onSave como prop desde sempre; Vue emite eventos com emit. No Svelte 5, é prop de função — igual ao React. O createEventDispatcher do Svelte 4 continua existindo por compatibilidade, mas não é o caminho novo.

Slots. O Vue tem slots nomeados e com escopo; o Svelte 5 trocou por snippets, que são funções de marcação. A vantagem é que um snippet pode ser passado como qualquer prop, inclusive para componentes que não são filhos diretos.

Portais, useContext, provide/inject. Contexto existe nos três, com nomes diferentes. O que não existe no Svelte é o portal como componente embutido: para desenhar fora da árvore, use uma ação ou mount num elemento separado.

Hooks com regras. Não há regra de "só no topo" para runas — há regra de lugar: $state na declaração, $props no topo, $effect na inicialização. O compilador recusa o resto, e a mensagem diz onde a runa pode morar.

9. Quando dá errado

Quem traz hábito antigo costuma encontrar estas três mensagens. Todas saíram do compilador desta versão.

Erro 1 — prop no estilo antigo

export let era o jeito do Svelte 4. Em componente com runa, ele não vale mais.

<script>
  export let nome = 'Ana';
  let total = $state(0);
</script>

<p>{nome}: {total}</p>
Erro de compilação (linha 2, coluna 2): Cannot use `export let` in runes mode — use `$props()` instead

O equivalente ao parâmetro de props do React é let { nome = 'Ana' } = $props();.

Erro 2 — {@render} como se fosse slot

Em Vue, o slot aparece sozinho no template. No Svelte, o trecho é uma função e precisa ser chamado.

<script>
  let { children } = $props();
</script>

<div>{@render children}</div>
Erro de compilação (linha 5, coluna 14): `{@render ...}` tags can only contain call expressions

"Só podem conter chamadas": {@render children()}. Com conteúdo opcional, {@render children?.()}.

Erro 3 — runa sem declaração

Quem vem de React escreve cliques = 0 pensando em atribuição, e quem vem de Vue escreve $state(0) solto.

<script>
  contador = $state(0);
</script>

<button>{contador}</button>
Erro de compilação (linha 2, coluna 13): `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

A runa precisa de uma declaração: let contador = $state(0).

10. O que você deixa de precisar

A lista do que sai é tão útil quanto a do que entra, porque metade do código de um projeto React existe para contornar o modelo de execução:

Arrays de dependência. Não existem. O compilador lê as dependências no código e o aviso de "exhaustive-deps" nunca aparece, porque não há lista para ficar incompleta.

useCallback e useMemo para evitar render. Não há render do componente inteiro para evitar: só o pedaço que usa o valor é atualizado. Função criada no script roda uma vez.

key para forçar remontagem. Existe, mas com nome próprio: {#key}. E é usado quando a identidade do conteúdo muda, não como desculpa para "atualizar".

Biblioteca de CSS-in-JS. O <style> do componente já tem escopo. Você pode continuar usando Tailwind se quiser; só não precisa de solução para vazamento.

Provider para tudo. Contexto existe, mas a maioria dos casos se resolve com props e callbacks. Publicar contexto é para valor que atravessa muitos níveis.

Resumo

  • O compilador do Svelte gera atualizações por pedaço; React e Vue decidem em tempo de execução.
  • useState e ref viram $state, sem setter e sem .value.
  • useMemo e computed viram $derived; com laço, $derived.by.
  • useEffect e watch viram $effect; sem array de dependências.
  • Props viram $props(); children vira {@render children()}.
  • key vai no bloco do each, entre parênteses, e não no elemento.
  • v-model vira bind:value; v-if vira {#if}; v-for vira {#each}.
  • Não existem arrays de dependência, regras de hooks nem useCallback.
  • O CSS já tem escopo; :global() é a saída explícita.
  • Hábito antigo vira erro claro: export let, {@render} sem chamada e runa sem let.
