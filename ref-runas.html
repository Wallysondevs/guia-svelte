Svelte · Todas as Runas

A Ana comprou uma máquina de café expresso para a padaria. No painel existem sete botões, cada um com um símbolo e uma função: um acende a luz, outro mói o grão, outro solta a água. A máquina só reconhece aqueles símbolos — se ela colar um adesivo com o desenho de uma xícara, nada acontece. As runas são os símbolos do Svelte: palavras com cifrão na frente que o compilador reconhece e que não funcionam em nenhum outro lugar. Esta página é o manual do painel: o que cada botão faz, o que ele devolve e onde pode ser apertado.

Você vai aprender
  • O que é uma runa e por que ela não é uma função comum.
  • $state e as duas variantes: $state.raw e $state.snapshot.
  • $derived para contas de uma linha e $derived.by para contas com laço.
  • A família de efeitos: $effect, $effect.pre, $effect.tracking e $effect.root.
  • $props, $props.id e $bindable: o que vem de fora do componente.
  • $inspect e $inspect.trace para olhar valores sem parar a página.
  • $host, a runa que só existe em componente de elemento customizado.
  • Onde cada runa pode ser escrita — e o que acontece quando você erra o lugar.
  • As mensagens reais do compilador para os erros mais comuns de runa.

1. A ideia: runa é símbolo do compilador, não função

Uma função você chama e recebe uma resposta: Math.round(2.6) devolve 3. Uma runa parece uma chamada, mas não é. Quando o compilador do Svelte encontra $state(0), ele não procura uma função chamada $state — ele reescreve aquele pedaço de código para criar um valor observável. É por isso que $state fora de um componente não roda: não existe função para chamar, existe uma transformação que só acontece em arquivos que o compilador processa.

O nome "runa" vem disso: são símbolos que só têm significado dentro de um arquivo .svelte ou de um módulo .svelte.js. Você não importa $state de lugar nenhum nem instala pacote: ele já está lá.

Hoje o Svelte 5 tem dez runas, e cada uma resolve um pedaço do problema de manter a tela igual ao dado. Nenhuma é opcional por capricho: se você escrever let nome = 'Ana' sem runa, o valor existe, mas a tela nunca fica sabendo que ele mudou. A tabela abaixo é o mapa do painel; as seções seguintes abrem cada botão.

Duas linhas dessa tabela explicam quase todos os erros de quem começa: $state precisa estar na inicialização de uma variável, e $props() só pode ser chamado no topo do componente. Guarde as duas; voltamos a elas na seção 10.

2. $state: o valor que avisa a tela

É a runa do dia a dia. Ela marca uma variável como observável: quando o valor muda, todo lugar que mostra aquele valor é redesenhado. O exemplo mais curto possível:

<script>
  let nome = $state('Ana');
</script>

<p>Olá, {nome}</p>
<p>Olá, Ana</p>

O HTML gerado não mostra nenhum sinal de runa — e é assim que deve ser. A runa é uma instrução para o compilador, não um enfeite para o navegador. Quem lê o arquivo final vê apenas o valor já resolvido.

let nome
a declaração. O let é obrigatório: $state precisa de uma variável para guardar o valor.
= $state('Ana')
a runa com o valor inicial. O que está entre parênteses é o ponto de partida, não um limite: pode mudar depois.
{nome}
o consumidor. Toda expressão que lê a variável entra na lista de quem deve ser redesenhado.
nome = 'Bia'
a troca, em qualquer lugar do script ou de um evento. A tela acompanha sozinha.

Vocabulário: estado é o dado guardado; reativo é o que acontece quando ele muda. $state cria as duas coisas juntas.

Quando não usar

Se o valor nunca muda depois de criado, não precisa de runa. const meses = ['jan', 'fev'] é mais honesto do que $state: o código diz "isto é fixo" e o compilador não gasta trabalho observando.

Missão: o botão soma no script, mas o número na tela nunca muda. Faça a tela mostrar Cliques: 1 depois de um clique.

<script>
  let cliques = 0;
  let etiqueta = $state('Cliques');
</script>

<button onclick={() => cliques++}>{etiqueta}: {cliques}</button>
<script>
  let cliques = $state(0);
  let etiqueta = $state('Cliques');
</script>

<button onclick={() => cliques++}>{etiqueta}: {cliques}</button>

Rode os dois e compare. O valor da variável muda nos dois casos — a diferença é que, sem a runa, ninguém avisa o HTML de que mudou.

O compilador não deixa isso passar em silêncio. Ele avisa no terminal, com o nome da variável, e o aviso tem código próprio:

O aviso real de variável não reativa

O componente compila e a página abre. O aviso só aparece no terminal e no painel do Vite — mas é o recado mais útil que existe para quem esqueceu a runa.

non_reactive_update: `cliques` is updated, but is not declared with `$state(...)`. Changing its value will not correctly trigger updates

Tradução: "cliques é atualizado, mas não foi declarado com $state(...); mudar o valor não vai disparar as atualizações corretamente". Se você entender o que é "disparar atualização", entendeu o Svelte inteiro.

Uma pegadinha que vale conhecer agora: num componente sem nenhuma runa, o Svelte 5 entra no modo antigo e volta a tratar let como reativo, por compatibilidade com projetos do Svelte 4. Assim que uma runa aparece no arquivo, o modo é o novo e let comum deixa de avisar a tela. Foi por isso que a caixa acima tem etiqueta = $state('Cliques'): é ela que coloca o componente no modo novo.

3. $state.raw: quando vigiar cada item custa caro

$state é profundo: ele observa o objeto inteiro, cada propriedade e cada item de lista. Isso é cômodo e tem preço — em listas grandes, criar o observador de cada item demora. $state.raw faz o contrário: observa só a troca do valor, não o que acontece dentro dele.

<script>
  let pedido = $state.raw({ cliente: 'Ana', itens: ['pão', 'leite'] });
</script>

<p>{pedido.cliente}: {pedido.itens.length}</p>
<p>Ana: 2</p>

A saída é idêntica à de $state, porque a leitura é a mesma. A diferença aparece na escrita: com raw, pedido.itens.push('café') altera o array mas não redesenha a tela. Para atualizar, você troca o objeto inteiro por um novo:

<script>
  let pedido = $state.raw({ cliente: 'Ana', itens: ['pão', 'leite'] });

  function adicionar() {
    pedido = { ...pedido, itens: [...pedido.itens, 'café'] };
  }
</script>

<p>{pedido.cliente}: {pedido.itens.length} itens</p>
<button onclick={adicionar}>adicionar café</button>
<p>Ana: 2 itens</p> <button>adicionar café</button>

O ... é o espalhamento: copia as propriedades do objeto antigo para um novo. Essa cópia é justamente o que dispara o aviso, porque o valor guardado mudou de identidade. O custo é que você passa a escrever mais código; o ganho é que dados grandes e imutáveis ficam baratos.

Missão: com $state.raw, o botão empurra um item na lista e a tela continua dizendo Itens: 1. Faça chegar a Itens: 2 sem trocar a runa.

<script>

  function adicionar() {

</script>

A lição vale para qualquer runa do tipo raw: o aviso só sai quando a variável recebe um valor novo. Alterar o que está dentro é invisível para a tela.

4. $state.snapshot: a foto do valor

Um valor com $state é um objeto especial, cheio de ligações internas. Quando você o entrega para fora — para uma API, para o console.log, para uma biblioteca que não conhece Svelte — é melhor mandar uma cópia comum. $state.snapshot tira essa foto:

<script>
  let nome = $state('Ana');
  let copia = $state.snapshot(nome);
</script>

<p>{copia}</p>
<p>Ana</p>

Com um texto o resultado é banal. O valor da runa aparece com objetos e listas: a foto é uma estrutura nova, sem as ligações internas, segura para serializar com JSON.stringify e para guardar sem que ninguém mexa no original. O compilador, porém, deixa um recado quando você usa a foto fora de hora:

O aviso real do compilador

O aviso não impede a página de rodar. Ele aparece no terminal e no painel do Vite, e aponta que aquela leitura pegou só o valor do primeiro desenho.

state_referenced_locally: This reference only captures the initial value of `nome`. Did you mean to reference it inside a closure instead?

A tradução: "esta referência só captura o valor inicial de nome; você não queria referenciar dentro de uma função?" Se a intenção é acompanhar mudanças, use $derived; se é só uma foto do momento, o aviso pode ser ignorado — e o código fica mais claro com um comentário.

Na padaria, a foto aparece antes de enviar o pedido para o servidor: JSON.stringify($state.snapshot(pedido)). Sem ela, o objeto sai com as ligações internas do Svelte e o servidor recebe campos que não esperava.

5. $derived: a conta que se refaz sozinha

Metade dos valores de uma tela é conta feita a partir de outros: o total do pedido, o troco, a média da turma. $derived declara esse valor uma vez e deixa o compilador refazer a conta quando um ingrediente muda.

<script>
  let itens = $state([{ preco: 0.9, qtd: 2 }, { preco: 1.2, qtd: 1 }]);
  let total = $derived(itens.reduce((soma, i) => soma + i.preco * i.qtd, 0));
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 3.00</p>

A conta é 0.9 × 2 + 1.2 × 1 = 3.00, feita pelo reduce — um método de lista que percorre os itens acumulando um resultado. Se a Ana mudar a quantidade de pães, o total se refaz e o parágrafo se redesenha, sem nenhuma linha de código a mais.

A diferença em relação a $state é conceitual e importante: estado é o que você digita, derivado é o que você calcula. Guardar o total como estado e atualizá-lo à mão em cada lugar é a receita para o dia em que alguém esquece um lugar e a tela mostra um total que não fecha.

Não atribua a um derivado

total = 10 numa variável criada com $derived é uma contradição: o valor deveria vir da conta. O compilador desta versão aceita a atribuição em alguns casos, mas o resultado deixa de acompanhar os ingredientes. Se você precisa mudar o valor, ele não é derivado: é estado.

6. $derived.by: a conta com mais de uma linha

$derived recebe uma expressão — uma linha. Quando a conta precisa de um laço, de variáveis intermediárias ou de um if, você entrega uma função para $derived.by:

<script>
  let itens = $state([{ preco: 0.9, qtd: 2 }, { preco: 1.2, qtd: 1 }]);
  let total = $derived.by(() => {
    let soma = 0;
    for (const i of itens) soma += i.preco * i.qtd;
    return soma;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<p>Total: R$ 3.00</p>

Mesmo resultado, código mais legível quando a conta cresce. O return é obrigatório: o que a função devolve é o valor do derivado. O compilador observa quais variáveis foram lidas dentro da função e refaz a conta quando qualquer uma muda.

Agora o erro que quase todo mundo comete: usar $derived com uma função de várias linhas. O código compila, roda e mostra o texto da função na tela:

<script>
  let itens = $state([{ preco: 0.9, qtd: 2 }, { preco: 1.2, qtd: 1 }]);
  let total = $derived(() => {
    let soma = 0;
    for (const i of itens) soma += i.preco * i.qtd;
    return soma;
  });
</script>

<p>Total: R$ {total}</p>
Total: R$ () => { let soma = 0; for (const i of itens) soma += i.preco * i.qtd; return soma; }

Faz sentido quando você entende a regra: $derived devolve o que a expressão vale, e a expressão é uma função — logo, o derivado é a função, não o resultado dela. $derived.by existe exatamente para esse caso. A diferença em uma tabela:

FormaRecebeQuando usarSaída típica
$derived(expr)uma expressãoconta curta, uma linhaTotal: R$ 3.00
$derived.by(fn)uma funçãolaço, if, variáveis intermediáriasTotal: R$ 3.00
$derived(() => {…})uma função, por enganonuncao texto da função na tela

Missão: a tela mostra o texto da função em vez do total. Faça aparecer Total: R$ 3.00, mantendo o laço dentro da conta.

<script>
  let itens = $state([{ preco: 0.9, qtd: 2 }, { preco: 1.2, qtd: 1 }]);
  let total = $derived(() => {
    let soma = 0;
    for (const i of itens) soma += i.preco * i.qtd;
    return soma;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>
<script>
  let itens = $state([{ preco: 0.9, qtd: 2 }, { preco: 1.2, qtd: 1 }]);
  let total = $derived.by(() => {
    let soma = 0;
    for (const i of itens) soma += i.preco * i.qtd;
    return soma;
  });
</script>

<p>Total: R$ {total.toFixed(2)}</p>

Compare os dois exemplos desta seção. O primeiro mostra {total} e a tela exibe o texto da função, porque a função é o valor do derivado. A caixa pede {total.toFixed(2)} e quebra antes de desenhar: função não tem toFixed. O conserto é o mesmo nos dois casos, e a lição é uma só: depois de $derived vai uma expressão, não um bloco.

7. A família de efeitos: $effect e as variantes

Efeito é código que roda depois que a tela foi desenhada, para fazer algo fora do componente: falar com o servidor, medir um elemento, guardar no localStorage. É o lugar do trabalho que não pode acontecer durante o desenho.

<script>
  let total = $state(0);
  $effect(() => {
    console.log('o total mudou para', total);
  });
</script>

<p>{total}</p>
<p>0</p>

O parágrafo mostra 0 e nada mais: efeito não desenha. No navegador, a mensagem aparece no console a cada mudança de total; no servidor, efeito nem roda. Essa é a razão de a saída acima ser só o número — e a razão de você nunca depender de um efeito para montar o HTML.

As variantes existem porque "depois de desenhar" nem sempre é o momento certo:

FormaQuando rodaUso típico
$effect(fn)depois do desenho, e de novo quando o que ele leu mudachamar API, salvar preferência, medir
$effect.pre(fn)antes do desenholer a posição da rolagem antes de reposicionar
$effect.tracking()devolve true se está dentro de um efeitobibliotecas que precisam saber se são observadas
$effect.root(fn)cria um escopo próprio, fora do componenteiniciar um recurso global e poder pará-lo

O $effect.tracking() é o mais estranho dos quatro e o mais fácil de demonstrar, porque devolve um booleano de verdade:

<script>
  const dentro = $effect.tracking();
</script>

<p>Dentro de um efeito: {String(dentro)}</p>
<p>Dentro de um efeito: false</p>

Fora de um efeito, false. Dentro, true. Serve para uma função saber se está sendo observada e, com isso, decidir se cria ligações ou só calcula — detalhe de biblioteca, raramente de página.

Efeito que escreve estado pode girar para sempre

Se o efeito lê total e escreve total, cada escrita dispara o efeito de novo. O compilador avisa em alguns casos, mas não em todos. A regra é simple: efeito lê estado e escreve no mundo de fora; quem escreve estado são os eventos e as funções chamadas por eles.

<script>
  let n = $state(0);

  const parar = $effect.root(() => {
    $effect(() => console.log('n =', n));
    return () => console.log('limpo');
  });
</script>

<button onclick={() => n++}>somar</button>
<button>somar</button>

$effect.root devolve uma função que desmonta tudo o que foi criado lá dentro — o que uma biblioteca usa para ter reatividade fora de qualquer componente.

8. $props, $props.id e $bindable: o que vem de fora

Um componente que só mostra valores próprios serve para uma coisa só. Para reaproveitar, ele precisa aceitar valores de fora — as propriedades, ou props. No Svelte 5 elas chegam por $props(), desestruturadas como um objeto comum:

<script>
  let { titulo = 'Pão francês', preco = 0.9 } = $props();
</script>

<p>{titulo}: R$ {preco.toFixed(2)}</p>
<p>Pão francês: R$ 0.90</p>

O sinal de igual dentro das chaves é o valor padrão: se ninguém passar titulo, vale 'Pão francês'. É isso que faz o cartão funcionar sozinho, como na saída acima, e também aceitar <Cartao titulo="Pão de queijo" preco={1.5} />.

let { … } = $props()
a desestruturação: cada nome vira uma prop. O compilador passa a tratar esses nomes como valores que vêm de fora.
titulo = 'Pão francês'
o padrão, usado quando a prop não é passada. Sem padrão, a prop fica undefined.
$bindable(0)
marca a prop como ligável: quem usa o componente pode escrever bind:valor e receber as mudanças.
$props.id()
devolve um id único para a instância, útil para ligar <label> e campo sem inventar nome.
<script>
  let { valor = $bindable(0) } = $props();
</script>

<input type="number" bind:value={valor} />
<input type="number" value="0"/>

O $props.id() resolve um problema chato de formulário: ligar o <label> ao campo certo quando o mesmo componente aparece várias vezes na página. Ele devolve um identificador único por instância, com prefixo curto gerado pelo compilador:

<script>
  const id = $props.id();
</script>

<label for={id}>Nome</label>
<input id={id} />
<label for="s1">Nome</label> <input id="s1"/>

O s1 não é escolhido por você: o compilador numera as instâncias, e na segunda vez o id é outro. Escrever id="nome" à mão funciona uma vez e quebra na segunda.

Sem $bindable, a prop é somente leitura para quem está fora: o componente até pode usar o valor, mas não consegue devolver a mudança. Com ela, o pai escreve <Quantidade bind:valor={qtd} /> e as duas pontas ficam iguais. O custo é que agora existem dois donos do mesmo dado — e dono duplicado é fonte de confusão; use quando o campo é realmente compartilhado.

9. $inspect e $host: as runas de nicho

$inspect é o console.log que o compilador remove da versão de produção. Ele mostra o valor no console sempre que muda, sem que você precise lembrar de apagar a linha depois:

<script>
  let nome = $state('Ana');
  $inspect(nome);
</script>

<p>{nome}</p>
<p>Ana</p>

A saída não muda: o $inspect não desenha nada. No modo de desenvolvimento do navegador, ele imprime o valor com uma marca indicando que veio de inspeção; na build de produção, o compilador joga a linha fora. É a ferramenta certa para investigar um valor sem sujar a tela nem o código final.

Existe também $inspect.trace(), que imprime a pilha de chamadas que levou até ali — útil quando o valor muda e você não sabe quem mudou. E $inspect(nome).with(fn) troca o console.log por uma função sua, caso queira registrar em outro lugar.

A última runa da lista é a mais específica: $host devolve o elemento que envolve o componente quando ele foi compilado como elemento customizado (<meu-cartao> dentro de uma página que não é Svelte). Fora desse caso, ela nem compila:

<script>
  $host().style.border = '1px solid green';
</script>

<p>Cartão</p>
Erro de compilação (linha 2, coluna 2): `$host()` can only be used inside custom element component instances

A mensagem é literal: "só pode ser usada dentro de instâncias de componente de elemento customizado". Para 99% dos projetos, isso significa "não use". Ela está no catálogo para você reconhecer o nome quando encontrar em código de biblioteca.

10. As regras: onde cada runa pode aparecer

As runas não são livres. Cada uma tem um lugar permitido, e o compilador recusa o resto com uma mensagem específica. As três regras que resolvem quase tudo:

Primeira: $state e $derived só valem na inicialização de uma variável (ou num campo de classe). $state(1); solto no meio de uma função não cria estado nenhum — e o compilador reclama:

Erro 1 — runa solta no meio do código 
<script>
  let contador = $state(0);
  function somar() { $state(1); }
</script>

<p>{contador}</p>
Erro de compilação (linha 3, coluna 21): `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

Traduzindo: "$state só pode ser usado como inicialização de declaração de variável, declaração de campo de classe, ou a primeira atribuição a um campo de classe dentro do construtor". Na prática: sempre let nome = $state(valor).

Segunda: $props() é do topo do componente. Ele não pode ser chamado dentro de uma função nem de um bloco:

Erro 2 — $props() dentro de uma função 
<script>
  function somar() {
    let { a } = $props();
    return a;
  }
</script>

<p>{somar()}</p>
Erro de compilação (linha 3, coluna 16): `$props()` can only be used at the top level of components as a variable declaration initializer

"Só pode ser usado no topo dos componentes, como inicialização de declaração de variável." A correção é mover a linha para fora da função, no começo do <script>.

Terceira: $bindable só existe dentro de um $props(). Ele não é uma runa de estado; é uma marcação na prop:

Erro 3 — $bindable sem $props 
<script>
  let valor = $bindable(0);
</script>

<p>{valor}</p>
Erro de compilação (linha 2, coluna 14): `$bindable()` can only be used inside a `$props()` declaration

A mensagem diz onde ele pode morar: "dentro de uma declaração $props()". A forma certa é let { valor = $bindable(0) } = $props();.

Resumo

  • Runa é símbolo do compilador, não função: não se importa e não funciona fora de .svelte ou .svelte.js.
  • let x = $state(v) cria valor observável; sem a runa, a tela não é avisada.
  • $state.raw observa só a troca do valor: mexer dentro não redesenha, trocar o objeto sim.
  • $state.snapshot tira uma cópia comum, boa para console.log, JSON.stringify e envio ao servidor.
  • $derived é para conta de uma linha; $derived.by é para conta com laço ou if.
  • Nunca atribua a um derivado: se precisa mudar, é estado.
  • $effect roda depois do desenho, só no navegador; .pre roda antes; .tracking() diz se está dentro; .root() cria escopo próprio.
  • $props() só no topo do componente, com padrões à direita do =; $bindable só dentro dele.
  • $inspect mostra no console em desenvolvimento e desaparece na produção; $host só em elemento customizado.
  • As mensagens de erro dizem literalmente onde a runa pode morar — leia a frase inteira antes de procurar no Google.
