Svelte · Sintaxe do .svelte

A Ana guarda as receitas da padaria num caderno de capa dura. Cada receita tem três partes: os ingredientes, o modo de preparo e as anotações de apresentação ("assar em forno alto", "servir quente"). Um arquivo .svelte é o mesmo caderno, com as mesmas três partes e uma regra só: o que está escrito vale para aquele componente e para mais ninguém. Esta página é a folha de consulta da Ana: tudo o que pode aparecer dentro do arquivo, na ordem em que aparece, com a saída que o compilador realmente devolve.

Você vai aprender
  • As três camadas de um arquivo .svelte e o que vai em cada uma.
  • Onde as chaves { } podem entrar — e o que não pode ficar dentro delas.
  • As quatro formas de escrever um atributo: fixo, entre chaves, booleano e espalhado.
  • Como os eventos mudaram de cara no Svelte 5: onclick no lugar de on:click.
  • O que é comentário de HTML e o que é comentário de JavaScript.
  • As diretivas bind:, class:, style: e use: em uma tabela.
  • A diferença entre {texto} e {@html texto}, com a saída dos dois.
  • Por que o CSS ganha um selo svelte-xxxxx e o que isso protege.
  • Os erros de sintaxe mais comuns, com a mensagem copiada do compilador.

1. A ideia: três camadas, uma responsabilidade cada

Quem começa a programar tende a misturar tudo num lugar só: o texto da tela, a conta do preço e a cor da letra. Funciona no começo e vira um problema no mês seguinte, quando a Ana quer mudar o preço do pão e precisa caçar o número no meio da marcação. O arquivo .svelte evita isso separando o que é dado, o que é tela e o que é aparência.

Pense de novo no caderno de receitas. Os ingredientes ficam no alto, numa lista curta. O modo de preparo vem embaixo, em passos. As anotações de forno e de apresentação ficam na margem. Ninguém escreve "duas xícaras de farinha" no meio do passo 4: a lista de ingredientes é o lugar disso. No componente, a lista de ingredientes é o bloco <script>, os passos são o HTML e as anotações de margem são o bloco <style>.

A sintaxe existe para o compilador saber onde cada camada começa e termina. Fora dos blocos, tudo é HTML — e o HTML tem regras que você provavelmente já conhece: tag que abre, tag que fecha, atributo entre aspas. Dentro das chaves, tudo é JavaScript. Essa divisão é a única coisa que você precisa decorar; o resto se consulta.

No caderno da AnaNo arquivo .svelteO que o compilador faz
Lista de ingredientesbloco <script>lê, calcula e guarda os valores
Modo de preparoo HTML do arquivotransforma em marcação que o navegador entende
Anotação de forno e de apresentaçãobloco <style>renomeia os seletores e gera o CSS do componente
Uma receita só para o pão doceum arquivo PaoDoce.sveltecompila cada arquivo separadamente
"Serve 8 porções" escrito a lápislet porcoes = $state(8)liga o valor ao lugar onde ele aparece

Repare na última linha: o valor não está escrito na tela, ele está guardado com um nome. Toda a sintaxe do Svelte gira em volta dessa ideia — dar nomes às coisas e dizer onde elas aparecem. O resto desta página é o catálogo desses lugares.

2. O esqueleto: HTML puro já é um componente

O menor componente possível não tem script nem estilo. É só marcação, como uma página antiga. O compilador aceita, porque o único bloco obrigatório é o HTML:

<h1>Padaria da Ana</h1>
<p>Pão francês: R$ 0,90</p>
<h1>Padaria da Ana</h1> <p>Pão francês: R$ 0,90</p>

O que sai é quase idêntico ao que entrou, e isso é intencional: sem valor dinâmico, não há trabalho a fazer. O compilador só removeu a quebra de linha entre as duas tags e juntou tudo numa linha. Se você abrir o arquivo gerado verá uma função que cria essas tags uma vez e as pendura na página — mas esse é assunto de outra aula.

Nome do arquivo também é sintaxe. Componentes começam com letra maiúscula: Saudacao.svelte, PaoDoce.svelte, ListaDePedidos.svelte. A maiúscula não é estilo, é como o compilador distingue uma tag sua de uma tag do HTML. Escrever <saudacao /> faz o navegador criar um elemento desconhecido, sem conteúdo e sem aviso; escrever <Saudacao /> monta o seu componente.

Um arquivo, um componente

O nome do arquivo é o nome do componente. Se o arquivo é Cartao.svelte, a tag é <Cartao /> — nem mais, nem menos. Renomear o arquivo sem renomear quem o usa é uma das causas mais comuns de "não achei o componente".

Uma consequência prática: você pode ter src/Saudacao.svelte e src/Cartao.svelte no mesmo projeto, cada um com seu HTML, seu script e seu estilo. Nada de um vaza para o outro. É a mesma lógica de ter receitas separadas no caderno: mexer na receita do pão doce não altera a do pão francês.

3. As chaves: o buraco por onde o JavaScript entra

Tudo o que não é HTML fica entre chaves. Um par de chaves no meio do texto significa "calcule isto e escreva o resultado aqui". O conteúdo pode ser um nome, uma conta, uma chamada de método, uma decisão curta:

<script>
  let preco = $state(0.9);
  let quantidade = $state(3);
</script>

<p>{quantidade} pães = R$ {(preco * quantidade).toFixed(2)}</p>
<p>3 pães = R$ 2.70</p>

O compilador calculou 0.9 * 3, chamou toFixed(2) no resultado e escreveu 2.70. Note que a expressão tem parênteses em volta da conta: sem eles, o ponto do toFixed grudaria no 3 e a conta seria outra. Parênteses dentro de chaves são só parênteses de JavaScript, valem a regra de sempre.

{quantidade}
uma variável mostrada como texto. O valor vem do let quantidade = $state(3).
{(preco * quantidade).toFixed(2)}
uma expressão: primeiro a conta entre parênteses, depois o método que formata o número com duas casas.
R$
texto comum, fora das chaves. O cifrão não tem significado especial aqui: é só um caractere.
pães =
mais texto comum. O compilador não traduz nem corrige o que está fora das chaves.

Missão: a tela mostra ana em minúsculas. Use um método de texto dentro das chaves para a placa mostrar ANA — sem trocar o valor guardado.

<script>
  let nome = $state('ana');
</script>

<p>{nome}</p>
<script>
  let nome = $state('ana');
</script>

<p>{nome.toUpperCase()}</p>

Uma chave por expressão. Não dá para abrir uma chave e escrever um if, um for ou um let dentro: esses são comandos, e as chaves esperam um valor. Para decidir ou repetir existe a sintaxe de bloco, com {#if} e {#each}, que tem aula própria. A regra prática: se a resposta da pergunta "isto vira um valor?" for sim, cabe nas chaves.

Também não se escreve chave dentro de comentário de HTML esperando que ela seja avaliada. Comentário é comentário; o compilador ignora o conteúdo, inclusive as chaves.

4. Atributos: do fixo ao dinâmico

Atributo é o que fica dentro da tag, antes do >: title, href, disabled. No Svelte ele pode ser fixo (texto entre aspas) ou dinâmico (chaves). A diferença parece pequena e muda tudo: o fixo é escrito uma vez, o dinâmico acompanha o valor.

<script>
  let desabilitado = $state(true);
  let etiqueta = $state('Salvar pedido');
</script>

<button disabled={desabilitado} title={etiqueta}>{etiqueta}</button>
<button disabled="" title="Salvar pedido">Salvar pedido</button>

Dois detalhes que o HTML sozinho não explica. Primeiro: disabled="" aparece vazio no HTML gerado. Atributo booleano funciona por presença: se está lá, o botão está desabilitado; se não está, não está. Enquanto o valor for true, o compilador mantém o atributo. Quando virar false, ele tira o atributo inteiro.

Segundo: o mesmo nome de variável aparece duas vezes, uma como atributo e outra como conteúdo. Isso é normal e desejável. O title é o texto que aparece ao passar o mouse; o conteúdo é o que está escrito no botão. Os dois vêm de etiqueta, então mudar a variável muda os dois de uma vez.

FormaExemploQuando usar
fixotype="button"valor que nunca muda naquele lugar
dinâmicotitle={etiqueta}valor que vem de uma variável ou conta
booleanodisabled={desabilitado}presença ou ausência do atributo
espalhado{...attrs}quando os atributos já estão num objeto
classe condicionalclass:negrito={grande}liga e desliga uma classe pelo valor

O espalhamento merece um exemplo, porque é o jeito mais curto de repassar um monte de atributos de uma vez. Ele pega cada chave do objeto e vira um atributo:

<script>
  let attrs = $state({ type: 'button', disabled: true, title: 'Salvar pedido' });
</script>

<button {...attrs}>Salvar</button>
<button type="button" disabled="" title="Salvar pedido">Salvar</button>

Os três pontos antes do nome são a sintaxe de espalhamento do JavaScript, a mesma dos objetos e das listas. O compilador não copia atributo por atributo no seu código: ele repassa o objeto e deixa o navegador aplicar. Isso é ótimo para repassar opções de um botão para outro componente, e perigoso quando o objeto vem de fora sem controle — um atributo inesperado pode aparecer na tela.

Aspas e chaves não se misturam

title="etiqueta" escreve a palavra etiqueta na tela. title={etiqueta} escreve o valor da variável. A confusão entre os dois é o erro número um de quem está começando, e o compilador não reclama: para ele, as duas formas são válidas.

5. Eventos: onclick e os vizinhos

No Svelte 5, evento é atributo como qualquer outro, com o nome do evento em minúsculas depois de on. O valor tem de ser uma função — algo que o navegador possa chamar quando o evento acontecer:

<script>
  let cliques = $state(0);

  function somar() {
    cliques = cliques + 1;
  }
</script>

<button onclick={somar}>Cliques: {cliques}</button>
<button>Cliques: 0</button>

O HTML gerado não mostra o evento, e isso confunde na primeira leitura. O compilador não escreve onclick="..." no arquivo final: ele guarda a função e a liga ao elemento quando monta a página. Você vê o resultado do trabalho (o botão), não o mecanismo.

onclick
o nome do evento, tudo em minúsculas e sem dois-pontos. O antigo on:click do Svelte 4 ainda compila, mas o compilador avisa que está fora de moda.
{somar}
o valor: uma função já declarada. Sem parênteses, porque você não quer chamar agora — quer entregar a função para o navegador chamar depois.
{() => cliques++}
a mesma coisa em uma linha, uma função anônima. Útil quando a ação é curta.
cliques = cliques + 1
a mudança de estado. Só variáveis criadas com $state avisam a tela.

Os nomes seguem o padrão do navegador, sem tradução: oninput a cada tecla digitada, onchange quando o campo perde o foco, onsubmit no envio de um formulário, onkeydown na tecla pressionada, onmouseenter quando o mouse entra no elemento. Se você souber o nome do evento em JavaScript, sabe o nome do atributo: é o mesmo, com on na frente.

AtributoDispara quandoValor típico
onclicko elemento é clicado{() => n++}
oninputo conteúdo de um campo muda{(e) => texto = e.target.value}
onsubmito formulário é enviado{(e) => { e.preventDefault(); salvar(); }}
onkeydownuma tecla é pressionada{(e) => e.key === 'Enter' && salvar()}
onchangeo campo muda e perde o foco{validar}

Missão: o contador começa em 5 e o botão não soma. Faça o texto virar Cliques: 1 depois de um clique — começando do zero.

<script>
  let cliques = $state(5);
</script>

<button onclick={() => (cliques = cliques + 0)}>Cliques: {cliques}</button>
<script>
  let cliques = $state(0);
</script>

<button onclick={() => (cliques = cliques + 1)}>Cliques: {cliques}</button>

Depois de rodar, clique no botão e veja o número subir. O valor não está escrito no HTML: ele é lido da variável a cada desenho. É essa ligação que faz o contador funcionar.

6. Os três blocos e os dois tipos de comentário

Um componente pode ter um <script> no topo, HTML no meio e um <style> no fim. Só o HTML é obrigatório. A ordem importa para quem lê, não para o compilador, mas o guia usa sempre esta porque é a que o projeto da Ana segue.

<script>
  let titulo = $state('Pão francês');
</script>

<h2>{titulo}</h2>
<p>Assado às 5h.</p>

<style>
  h2 {
    color: #2e7d32;
  }
</style>
<h2 class="svelte-11u2pyd">Pão francês</h2> <p>Assado às 5h.</p>

Repare que só o h2 ganhou o selo da classe. O seletor do CSS era h2, então só as tags que casam com ele recebem o selo; o p ficou sem, porque nenhuma regra o alcança. A seção 9 volta a esse ponto.

Comentário tem duas sintaxes e elas não são intercambiáveis. <!-- assim --> é comentário de HTML: fica no arquivo, mas não chega ao navegador. Dentro do <script>, // assim e /* assim */ são comentários de JavaScript, lidos pelo compilador e jogados fora. O que não existe é comentário de Svelte com chaves: {/* texto */} dentro do HTML é lido como expressão e vira erro.

<!-- esta linha não chega ao navegador -->
<script>
  // comentário de JavaScript
  let nome = $state('Ana');
</script>

<h1>Padaria</h1>
<h1>Padaria</h1>

O comentário de HTML desapareceu do resultado porque o compilador não precisa dele. Isso é bom para o tamanho da página e ruim para quem esperava "esconder" uma senha num comentário: comentário não é lugar de segredo, nem de código desativado que você pretende reativar depois.

7. Diretivas: um dois-pontos que muda o comportamento

Diretiva é um atributo com : no nome, e cada uma liga um recurso do Svelte a um elemento. São poucas, e a tabela abaixo é a lista completa do que aparece no dia a dia:

DiretivaExemploO que faz
bind:value<input bind:value={nome} />mantém campo e variável iguais nos dois sentidos
bind:checked<input type="checkbox" bind:checked={pago} />liga a marcação do checkbox a um booleano
bind:this<canvas bind:this={tela} />guarda o elemento na variável para mexer nele
class:class:negrito={grande}liga uma classe quando o valor é verdadeiro
style:style:color={cor}aplica uma propriedade de estilo
use:use:clicarForaroda uma função quando o elemento é montado
transition:transition:flyanima a entrada e a saída do elemento

As duas mais usadas no começo são bind:value e class:. A primeira dispensa o oninput manual; a segunda troca o cálculo de nomes de classe por um booleano:

<script>
  let cor = $state('#2e7d32');
  let grande = $state(true);
</script>

<p style:color={cor} class:negrito={grande}>Pão quentinho</p>

<style>
  .negrito { font-weight: bold; }
</style>
<p class="svelte-10pdsnf negrito" style="color: #2e7d32;">Pão quentinho</p>

O resultado tem duas classes: o selo que o compilador colocou para o estilo escopado e a classe negrito que veio da diretiva. As duas convivem no mesmo atributo, na ordem em que o compilador as escreveu. Quando grande virar false, a classe sai e o texto perde o negrito sem que ninguém mexa no CSS.

Diretiva não é atalho mágico: é sintaxe que o compilador traduz para código comum. class:negrito={grande} vira uma instrução que adiciona ou remove a classe quando o valor muda. Saber disso ajuda quando algo não funciona — o problema está no valor, não na diretiva.

8. Texto ou HTML: {texto} e {@html texto}

Quando a Ana digita o nome de um produto, esse texto pode conter qualquer caractere, inclusive os que o HTML usa para marcar tags. Se o componente tratasse esse texto como marcação, alguém poderia digitar <b> e mudar a página inteira. Por isso o padrão é o seguro: chaves tratam o valor como texto.

<script>
  let texto = $state('<b>pão quentinho</b>');
</script>

<p>{texto}</p>
<p>&lt;b>pão quentinho&lt;/b></p>

As tags aparecem escritas na tela, porque o compilador trocou cada sinal de menor por &lt; — a entidade que o navegador desenha como o caractere <, sem abrir tag nenhuma. O navegador lê essas entidades como texto e desenha os caracteres, sem criar negrito nenhum. Essa é a proteção contra o que se chama de injeção de HTML.

Quando o HTML é de confiança, existe a forma explícita:

<script>
  let texto = $state('<b>pão quentinho</b>');
</script>

<p>{@html texto}</p>
<p><b>pão quentinho</b></p>

Agora as tags viraram tags de verdade e o pão ficou em negrito. {@html …} diz ao compilador "não escape isto, coloque cru na página". É uma porta aberta: use só com texto que você mesmo gerou, nunca com o que veio digitado por outra pessoa sem passar por uma biblioteca de limpeza.

Três sinais que pedem escape

Dentro de um arquivo .svelte você escreve < normalmente, porque o arquivo é HTML. O escape só é necessário nas páginas deste guia, que mostram código dentro de <pre>. No componente, quem precisa de cuidado é o texto que vem de fora: nome digitado, comentário de cliente, resultado de uma busca.

CaractereComo escrever na página do guiaPor quê
<&lt;senão o navegador começa uma tag
>&gt;fecha a tag que o navegador abriu
&&amp;senão vira o começo de uma entidade

Missão: a tela mostra o pão em negrito. Faça aparecer o texto das tags — <b>pão quentinho</b> escrito na tela — sem mudar o valor guardado.

<script>
  let texto = $state('<b>pão quentinho</b>');
</script>

<p>{@html texto}</p>
<script>
  let texto = $state('<b>pão quentinho</b>');
</script>

<p>{texto}</p>

9. O CSS e o selo svelte-xxxxx

O bloco <style> é CSS comum, com uma diferença que você vê no resultado: o compilador renomeia cada seletor com um selo. O selo é um código curto derivado do conteúdo do componente, e aparece tanto no CSS quanto nas tags do HTML.

<h1>Padaria da Ana</h1>
<p>Aberta das 6h às 13h</p>

<style>
  h1 {
    color: #2e7d32;
  }
  p {
    font-size: 14px;
  }
</style>
h1.svelte-1efiwzv {
  color: #2e7d32;
}
p.svelte-1efiwzv {
  font-size: 14px;
}

E o HTML que o navegador recebe carrega o mesmo selo:

<h1 class="svelte-1efiwzv">Padaria da Ana</h1> <p class="svelte-1efiwzv">Aberta das 6h às 13h</p>

Por que fazer isso? Porque CSS é global por natureza. Se dois componentes escrevem h1 { color: green } e h1 { color: red }, em CSS tradicional o último carregado ganha e a cor de um vaza para o outro. Com o selo, cada regra só alcança as tags daquele componente. Você deixa de precisar de nomes de classe inventados à mão para isolar estilos.

O preço é que às vezes você quer atingir algo de fora — o body, uma classe global do site, o conteúdo de um componente filho. Para isso existe :global(seletor), que desliga o escopo naquele seletor específico. Use pouco: cada :global é uma porta aberta no isolamento que o compilador construiu.

10. Quando dá errado

As quatro mensagens abaixo saíram do compilador desta versão, copiadas como estão. Repare que quase todas apontam linha e coluna: é o primeiro lugar para olhar.

Erro 1 — chave dinâmica em atributo com aspas

O valor de um evento tem de ser uma expressão JavaScript entre chaves. Entre aspas, ele é texto, e texto não é função.

<script>
  let cliques = $state(0);
</script>

<button onclick="cliques++">Cliques: {cliques}</button>
Erro de compilação (linha 5, coluna 8): Event attribute must be a JavaScript expression, not a string

A tradução é direta: "atributo de evento tem de ser uma expressão JavaScript, não uma string". Troque as aspas por chaves e escreva uma função.

Erro 2 — chaves que não fecham

Cada { precisa de um }. Quando o compilador chega ao fim do arquivo com uma chave aberta, ele reclama de bloco deixado aberto.

<script>
  let nome = $state('Ana');
</script>

{#if nome === 'Ana'}
  <p>oi</p>
Erro de compilação (linha 5, coluna 0): Block was left open

"Block was left open" quer dizer "bloco ficou aberto". A linha apontada é onde o bloco começou, não o fim do arquivo — o que ajuda: o problema está no {#if} sem {/if}.

Erro 3 — diretiva de texto vazia

{@html} sem valor não é uma expressão: falta o que colocar dentro. O compilador espera um espaço e um valor depois da diretiva.

<p>{@html}</p>
Erro de compilação (linha 1, coluna 9): Expected whitespace

"Expected whitespace" quer dizer "esperava um espaço". A correção é sempre a mesma: um valor depois de @html, como {@html texto}.

Erro 4 — nome que não existe

Este componente compila: o erro acontece na hora de desenhar, e a mensagem vem do JavaScript, não do compilador.

<script>
  let nome = $state('Ana');
</script>

<h1>{naoExiste}</h1>
naoExiste is not defined

"is not defined" quer dizer "não foi definido". O compilador não sabe adivinhar se você quis escrever nome, então trata o nome desconhecido como variável global — e ela não existe. Confira letra por letra.

Resumo

  • Um arquivo .svelte tem até três camadas: <script> (dados), HTML (tela) e <style> (aparência). Só o HTML é obrigatório.
  • Fora das chaves é HTML; dentro delas é JavaScript. Chaves esperam um valor, não um comando.
  • Atributo pode ser fixo (title="oi"), dinâmico (title={nome}), booleano (disabled={x}) ou espalhado ({...attrs}).
  • Evento é atributo com on na frente: onclick, oninput, onsubmit. O valor é uma função, nunca uma string.
  • Comentário de HTML (<!-- -->) não chega ao navegador; comentário de JavaScript fica dentro do <script>.
  • Diretivas têm dois-pontos no nome: bind:value, class:negrito, style:color, use:acao, transition:fly.
  • {texto} escapa os sinais de tag e mostra o texto; {@html texto} injeta marcação de verdade.
  • O CSS do componente ganha um selo (svelte-1efiwzv) no seletor e nas tags; é isso que impede o estilo de vazar.
  • Erro de sintaxe vem com linha e coluna; erro de nome vem na hora de desenhar, sem posição.
  • npm run dev mostra o erro na tela; npm run build gera a versão de produção em dist/.
