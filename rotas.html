SvelteKit · Rotas por Arquivo

A Ana vende pão, mas o site dela tinha uma página só. Quando alguém perguntava o preço do pão de queijo, ela mandava o link da página inicial e a pessoa tinha que rolar a tela inteira. O sobrinho dela apareceu com uma ideia estranha: no SvelteKit, para criar a página /paes, você não configura nada — você cria uma pasta chamada paes e põe um arquivo dentro. A pasta vira endereço. Nesta aula você vai ver esse mecanismo funcionando de verdade, com o servidor respondendo 200 para o que existe e 404 para o que não existe.

Você vai aprender
  • O que é uma rota e por que a pasta funciona como endereço.
  • O papel de src/routes: o mapa do site inteiro mora ali.
  • Como src/routes/+page.svelte atende a URL /.
  • Como criar /paes criando a pasta paes com um +page.svelte.
  • O que o + do começo do nome significa e por que ele existe.
  • Como conferir uma rota de verdade com curl, sem abrir o navegador.
  • Por que um endereço inexistente recebe 404 e não um erro feio.
  • O que acontece com pastas dentro de pastas: /paes/frances.
  • Os três erros reais desta aula: rota em conflito, bloco aberto e arquivo fora do lugar.
  • Quando usar +page.js ao lado de +page.svelte (e quando não precisa).

1. A ideia: cada página é uma gaveta com etiqueta

Na padaria da Ana existe um balcão com gavetas. Cada gaveta tem uma etiqueta colada na frente: "pães", "doces", "fiado". Quem chega pedindo doces não precisa explicar onde os doces ficam — a etiqueta resolve. Um endereço de site funciona igual: /paes é uma etiqueta, e o servidor precisa saber qual gaveta abrir quando alguém pede essa etiqueta.

Em muitos sistemas, essa ligação entre etiqueta e gaveta é escrita à mão numa lista de configuração. Você abre um arquivo, escreve "/paes": PaginaDePaes, salva, e reza para não esquecer de atualizar a lista quando criar a próxima página. O SvelteKit faz diferente: a lista é o seu disco. Se existe a pasta paes com um arquivo de página dentro, então a rota /paes existe. Se você apagar a pasta, a rota desaparece. Não há lista separada para manter em sincronia com a realidade — o que existe no disco e o que existe no site são a mesma coisa.

Isso tem um custo e um ganho. O ganho: nunca mais uma página esquecida, nunca mais uma configuração desatualizada; a estrutura de pastas do projeto é uma fotografia do site. O custo: os nomes das pastas deixam de ser livres. Uma pasta chamada coisas-velhas dentro de src/routes não é "só uma pasta" — ela cria o endereço /coisas-velhas, mesmo que ninguém vá lá. Você vai aprender a conviver com isso, e o + do começo dos nomes é justamente uma das regras que tornam essa convivência possível.

Uma palavra de vocabulário antes de continuar: rota é o par "endereço + arquivo que responde por ele". Quando este guia diz "a rota /paes", está falando de um endereço que existe no site e do arquivo que o servidor usa para montar a resposta. URL é o texto completo que aparece na barra do navegador; caminho (pathname) é só a parte depois do domínio: em http://localhost:4173/paes, o caminho é /paes.

2. No dia a dia × no SvelteKit

A tabela abaixo é o resumo que você vai reler quando esquecer onde cada arquivo mora. Repare que todas as linhas falam da mesma coisa: um arquivo num lugar do disco corresponde a um comportamento no site.

Na padariaNo SvelteKit
A etiqueta na gaveta: "pães"O endereço /paes
A gaveta com as coisas dentroA pasta src/routes/paes/
O que está escrito na etiqueta de dentroO arquivo +page.svelte daquela pasta
O balcão por onde todos passamsrc/routes/+layout.svelte
A placa de "não temos isso hoje"src/routes/+error.svelte (o 404)
Uma gaveta que não existeUm endereço sem pasta: resposta 404

Se você guardar só uma frase desta aula, guarde esta: o caminho do arquivo, tirando o +page.svelte do fim, é a URL. O arquivo src/routes/paes/+page.svelte vira /paes. O arquivo src/routes/+page.svelte vira /, porque não sobrou nenhuma pasta no caminho. O arquivo src/routes/paes/frances/+page.svelte vira /paes/frances, porque sobraram duas pastas.

3. A pasta src/routes é o mapa do site

Quando o projeto da Ana nasceu (a aula anterior mostra o comando que criou), o SvelteKit entregou uma pasta chamada src com um subdiretório routes dentro. É o único lugar do projeto em que o SvelteKit procura páginas. Tudo o que você criar fora dele — componentes reutilizáveis, funções, imagens importadas — não é rota, mesmo que tenha um nome bonito.

Esta é a árvore real do projeto da Ana, tirada do terminal dela. A pasta (painel) e a contato existem, mas ainda não interessam aqui; o que importa é o formato:

ana@notebook:~/loja/kit$ ls -R src/routes
src/routes:
(painel)
+error.svelte
+layout.svelte
+page.svelte
contato
paes
sobre

src/routes/paes:
+page.svelte
[slug]

src/routes/paes/[slug]:
+page.svelte

src/routes/sobre:
+page.svelte

Leia a saída como um mapa. Na raiz de src/routes há três arquivos que começam com + e três pastas. Cada pasta que tem um +page.svelte dentro é um endereço a mais no site. A pasta paes tem o arquivo dela e ainda uma subpasta [slug] — os colchetes são assunto de outra aula, mas já dá para ver que o mapa continua descendo.

Repare também no que não existe: nenhum arquivo de configuração listando rotas. Nenhum routes.json. A informação está toda ali, nas pastas. Se você copiar a pasta sobre para uma máquina e colar dentro de src/routes, a rota /sobre passa a existir. Se renomear a pasta para quem-somos, o endereço vira /quem-somos e o antigo passa a responder 404.

4. A raiz: src/routes/+page.svelte é a página de /

A primeira página de qualquer site é a que responde ao endereço mais curto: a barra sozinha, /. No SvelteKit, ela é o arquivo +page.svelte que fica direto em src/routes, sem pasta nenhuma no meio. Este é o arquivo da Ana:

<h1>Padaria da Ana</h1>
<p>Pão francês saindo do forno às 6h.</p>
<a href="/paes">ver os pães</a>

É um componente Svelte comum: HTML com um pedaço de texto. Não tem <script>, não tem <style>, não tem exportação, não tem função de inicialização. Você não escreve "esta é a página inicial" em lugar nenhum — o nome e a posição do arquivo já dizem isso. Essa é a graça: a informação que antes ficava numa configuração agora está no nome.

src/routes
a pasta onde o SvelteKit procura rotas. Fora dela, nada é página.
+page.svelte
o arquivo que diz "aqui existe uma página". O nome é fixo: o +, a palavra page e a extensão .svelte.
sem pasta no meio
porque a URL é o caminho do arquivo sem o +page.svelte. Sem pasta, sobra a barra: /.
<h1>…</h1>
o conteúdo da página, em HTML normal. O que está aqui é o que aparece dentro da área de conteúdo do site.
<a href="/paes">
um link comum. O SvelteKit intercepta o clique e troca a página sem recarregar o navegador (é o assunto de Navegando com goto).

O detalhe que costuma travar quem vem de outros mundos: não existe index.html em src/routes. O arquivo index.html do projeto (o da raiz, ao lado de package.json) é outra coisa — ele é o molde que envolve todas as páginas, e no SvelteKit ele se chama src/app.html. A página inicial de verdade é um componente como qualquer outro.

5. Uma pasta a mais, uma página a mais: /paes

Para criar a página que lista os pães, a Ana fez três coisas: criou a pasta paes dentro de src/routes, criou o arquivo +page.svelte dentro dela e escreveu o conteúdo. Nenhum registro, nenhuma linha em nenhum arquivo de configuração.

<h1>Pães</h1>
<ul>
	<li><a href="/paes/frances">Pão francês</a></li>
	<li><a href="/paes/forma">Pão de forma</a></li>
	<li><a href="/paes/queijo">Pão de queijo</a></li>
</ul>

Com o servidor de desenvolvimento rodando, o endereço http://localhost:5173/paes passa a responder. Para provar isso sem depender do navegador, o jeito é pedir a página com curl, um programa de terminal que faz exatamente o que o navegador faz na primeira requisição: pede o endereço e imprime a resposta. Aqui a Ana usou a versão de produção (npm run preview) servindo na porta 4173, e pediu só o pedaço que interessa com grep:

ana@notebook:~/loja/kit$ npm run preview

> kit@0.0.1 preview
> vite preview

  ➜  Local:   http://localhost:4173/
  ➜  Network: use --host to expose

ana@notebook:~/loja/kit$ curl -s localhost:4173/paes | grep -o '<h1>.*</h1>'
<h1>Pães</h1>

O -s quer dizer "silencioso": sem barras de progresso, só o conteúdo. O grep -o '<h1>.*</h1>' recorta do HTML só o trecho do título, porque a página inteira tem mais de 3.900 caracteres de marcação interna. O que importa é a segunda linha: o servidor devolveu <h1>Pães</h1> já escrito, pronto, antes de qualquer JavaScript rodar no navegador. Isso se chama renderização no servidor: o HTML nasce pronto e o navegador só continua a partir dele.

Se você trocar o endereço por um que não existe, o resultado é outro. Este é o mesmo comando aplicado a /nao-existe:

ana@notebook:~/loja/kit$ curl -s localhost:4173/nao-existe | grep -o '<h1>.*</a>'
<h1>404</h1> <p>Not Found</p> <a href="/">voltar para o início</a>

Duas informações em uma: o texto 404 e o <p>Not Found</p> vêm do arquivo src/routes/+error.svelte, que é a página de erro do projeto (assunto de +error.svelte). E a resposta HTTP também carrega o número. Veja os cabeçalhos, que são as "etiquetas" que o servidor manda junto com o conteúdo:

ana@notebook:~/loja/kit$ curl -s -i localhost:4173/nao-existe | head -4
HTTP/1.1 404 Not Found
content-type: text/html
x-sveltekit-page: true

(Cortei três cabeçalhos de controle de cache da saída para caber na aula.) O -i faz o curl mostrar os cabeçalhos junto com o corpo. A primeira linha é o veredito: 404 Not Found. Para uma rota que existe, a mesma linha vem com 200 OK. Guarde essa distinção, porque é ela que faz o Google e os navegadores tratarem a página certa como página e a errada como erro.

6. O + do começo do nome

Por que +page.svelte e não page.svelte? Porque dentro de src/routes você vai querer guardar outras coisas junto das páginas: um componente que só aquela pasta usa, uma imagem, uma função auxiliar. Sem uma marca, o SvelteKit não teria como saber o que é página e o que é bagunça. O + é essa marca: tudo o que começa com + tem significado especial para o roteador; o resto é só arquivo.

ArquivoPara que serve
+page.sveltea página daquele endereço. É o que aparece na tela.
+page.jso código que busca dados antes da página desenhar (roda no navegador e no servidor).
+page.server.jso mesmo, mas só no servidor — pode falar com banco de dados e segredos.
+layout.svelteo que envolve as páginas daquela pasta e das subpastas (menu, rodapé).
+error.svelteo que aparece quando algo dá errado naquela parte do site.
+server.jsuma resposta crua, sem página: para APIs e formulários.

Uma consequência prática que economiza tempo: você pode ter +page.svelte e +page.js na mesma pasta. Os dois formam uma rota: o .js busca os dados, o .svelte desenha. E pode ter só o .svelte — como nos exemplos acima — quando a página não precisa buscar nada. O SvelteKit não exige o par.

+
a marca de "arquivo especial". Sem ela, o arquivo é ignorado pelo roteador.
page
o tipo do arquivo. page é página; layout é moldura; error é erro.
.svelte
o formato. Um +page.svelte é um componente Svelte, com <script>, HTML e <style> se você quiser.
.js / .server.js
o formato de código puro. Não desenha nada: devolve dados para a página.

Missão: o caminho guardado é /nao-existe, que não está no mapa, e a tela fica vazia. Faça o componente mostrar 404 quando o caminho não existir. A caixa roda só o componente, sem o servidor do SvelteKit — é o mesmo papel do +error.svelte, com o caminho morando numa variável para você ver a ideia.

<script>
  let caminho = $state('/nao-existe');
  let paginas = {
    '/': 'Padaria da Ana',
    '/paes': 'Pães'
  };
</script>

<h1>{paginas[caminho]}</h1>
<script>
  let caminho = $state('/nao-existe');
  let paginas = {
    '/': 'Padaria da Ana',
    '/paes': 'Pães'
  };
</script>

<h1>{paginas[caminho] ?? '404'}</h1>

O ?? lê-se "se o da esquerda for nulo ou indefinido, use o da direita". paginas['/nao-existe'] não existe no objeto, então o valor é undefined e o ?? entra com '404'. É a versão de uma linha do que o SvelteKit faz quando não acha uma rota: em vez de mostrar um buraco, mostra a página de erro.

7. O que o servidor responde: 200, 404 e o resto

Programa que conversa com programa usa números para resumir o resultado. Esses números são os códigos de status, e você vai vê-los o tempo todo. Os três que importam agora:

CódigoNomeQuando aparece
200OKa rota existe e a página foi montada.
404Not Foundnão existe rota para aquele caminho.
500Internal Errora rota existe, mas o código quebrou no meio.

Um mesmo servidor, quatro endereços, quatro respostas. Este laço percorre a lista e imprime só o número, sem baixar o HTML:

ana@notebook:~/loja/kit$ for u in / /paes /paes/queijo /nao-existe; do printf '%-14s %s\n' "$u" "$(curl -s -o /dev/null -w '%{http_code}' localhost:4173$u)"; done
/              200
/paes          200
/paes/queijo   200
/nao-existe    404

O -o /dev/null joga o corpo da resposta no lixo, e -w '%{http_code}' manda o curl imprimir só o número. O printf formata a linha com o caminho à esquerda e o código à direita, para a leitura ficar alinhada. Três 200 e um 404: as três primeiras rotas existem no disco, a última não.

Note que /paes/queijo respondeu 200 mesmo sem existir uma pasta queijo. Quem atende esse endereço é a pasta paes/[slug], com colchetes no nome — é o assunto de Parâmetros de Rota. Por enquanto aceite o fato: o número de pastas no disco não é igual ao número de endereços possíveis quando há colchetes no caminho.

8. Experimente: um menu que troca de página

O site da Ana tem um menu no topo, com um link para cada rota. O componente que desenha esse menu é uma lista, e listas em Svelte se escrevem com {#each}. A caixa abaixo simula o menu com botões, porque um link de verdade dentro da caixa tentaria sair da página do guia — e a ideia é a mesma: cada item do menu aponta para um caminho, o caminho vira o conteúdo da tela.

Missão: os botões não fazem nada. Faça o clique trocar a página: ao clicar no botão /paes, o parágrafo deve mostrar página: /paes.

<script>
  let rotas = ['/', '/paes', '/sobre'];
  let caminho = $state('/');
</script>

{#each rotas as rota}
  <button data-rota={rota}>{rota}</button>
{/each}

<p>página: {caminho}</p>
<script>
  let rotas = ['/', '/paes', '/sobre'];
  let caminho = $state('/');
</script>

{#each rotas as rota}
  <button data-rota={rota} onclick={() => (caminho = rota)}>{rota}</button>
{/each}

<p>página: {caminho}</p>

O seletor da missão, button[data-rota='/paes'], é CSS puro: "o botão cujo atributo data-rota vale /paes". Atributos que começam com data- existem justamente para isso: guardar um dado no elemento sem inventar uma classe nova para cada caso. É um truque barato que você vai reaproveitar em testes e em menus.

Na versão de verdade, o menu não guarda o caminho numa variável: ele lê page.url.pathname do SvelteKit, que já sabe onde a pessoa está. A diferença importa: no site, o caminho é do navegador e ninguém pode "esquecer" de atualizar a variável. O componente só desenha o que o endereço diz.

9. Pastas dentro de pastas: /paes/frances

O mapa desce. Para criar /paes/frances, a Ana criou a pasta frances dentro de paes e pôs um +page.svelte lá dentro. O caminho do arquivo, lido de cima para baixo, forma o endereço: paes + frances → /paes/frances.

<h1>Pão francês</h1>
<p>Casca fina, miolo macio. Sai do forno às 6h e às 16h.</p>
<a href="/paes">voltar para a lista</a>

Não há limite de profundidade: src/routes/paes/frances/integral/+page.svelte atenderia /paes/frances/integral. Há, sim, um limite de paciência: endereços com quatro ou cinco níveis são difíceis de digitar e de lembrar. Quando a Ana percebeu que teria uma pasta por pão, ela parou e aprendeu os colchetes — porque um único arquivo [slug] atende todos os pães de uma vez.

src/routes
o começo de todo caminho. Não entra na URL.
paes
o primeiro pedaço do endereço. Vira /paes.
frances
o segundo pedaço. Vira /paes/frances.
+page.svelte
o arquivo que responde. Não entra na URL — é o "índice" daquela pasta.

Missão: o mapa tem a chave certa, mas o componente pega só o primeiro pedaço do caminho e mostra Pães. Faça o título mostrar Pão francês para o caminho /paes/frances.

<script>
  let caminho = $state('/paes/frances');
  let paginas = {
    '/': 'Padaria da Ana',
    '/paes': 'Pães',
    '/paes/frances': 'Pão francês'
  };
  let pedaco = caminho.split('/')[1];
</script>

<h1>{paginas[pedaco]}</h1>
<p>caminho: {caminho}</p>
<script>
  let caminho = $state('/paes/frances');
  let paginas = {
    '/': 'Padaria da Ana',
    '/paes': 'Pães',
    '/paes/frances': 'Pão francês'
  };
</script>

<h1>{paginas[caminho]}</h1>
<p>caminho: {caminho}</p>

caminho.split('/') corta o texto em pedaços e devolve uma lista: ['', 'paes', 'frances']. O [1] pega o segundo item, 'paes' — por isso a versão errada mostra a página de pães. Quando você usa o caminho inteiro como chave, a rota aninhada aparece. Guardar o endereço completo, sem pedaços, é o que o SvelteKit faz por dentro.

Repare que quem decide o endereço é a pasta, não o título dentro da página. Trocar o <h1> para "Pão de trigo" não muda a URL: continua /paes/frances. Isso confunde no começo, porque o título é o que a pessoa vê. A regra é: endereço vem do disco, texto vem do componente.

10. Quando dá errado

As três mensagens abaixo saíram do terminal do projeto da Ana, copiadas como estão. Duas vêm do npm run build (a versão de produção) e uma do compilador do Svelte. Onde a mensagem original traz o caminho completo da pasta do projeto, o recorte ficou só com o nome do arquivo, para não poluir a leitura.

Erro 1 — duas pastas querendo o mesmo endereço

A Ana criou src/routes/paes/[slug] e, por engano, também src/routes/paes/[nome]. Os dois casam com /paes/qualquer-coisa: o roteador não tem como escolher, e o build para.

ana@notebook:~/loja/kit$ npm run build

> kit@0.0.1 build
> vite build

error during build:
SvelteKit error: route_conflict
The `/paes/[nome]` and `/paes/[slug]` routes conflict with each other
https://svelte.dev/e/kit/route_conflict

A mensagem tem três partes úteis: o nome do erro (route_conflict), a frase que diz quais rotas brigaram e um endereço de documentação. Abaixo disso vem a pilha de chamadas internas do SvelteKit, que só interessa a quem mexe no SvelteKit. O conserto é escolher um nome e apagar o outro: um arquivo, uma rota.

Erro 2 — chave aberta e não fechada

Este é do compilador do Svelte, não do roteador. Um {#if} sem {/if} deixa o componente pela metade, e o build mostra o pedaço do arquivo com um acento circunflexo embaixo do ponto exato.

ana@notebook:~/loja/kit$ npm run build
vite v8.4.0 building ssr environment for production...
transforming...
✓ 143 modules transformed.
✗ Build failed in 166ms
error during build:
Build failed with 1 error:

RolldownError: src/routes/sobre/+page.svelte:5:0 Block was left open
https://svelte.dev/e/block_unclosed
 3 |  </script>
 4 |
 5 |  {#if temPao}
       ^
 6 |    <p>Tem pão na prateleira.</p>
 7 |

"Block was left open" quer dizer "o bloco ficou aberto". A posição 5:0 é linha 5, coluna 0 — a linha do {#if}, não a do fim do arquivo. A dica prática é contar os pares de olho: cada {#if} pede um {/if}, cada {#each} pede um {/each}.

Erro 3 — a página existe, mas o endereço não

Aqui não há mensagem de erro, e é justamente por isso que confunde. A Ana criou o arquivo +page.svelte com a página de contato, mas salvou em src/lib/ em vez de src/routes/. O componente compila, o build passa, e o site responde 404.

ana@notebook:~/loja/kit$ curl -s -o /dev/null -w '%{http_code}\n' localhost:4173/contato
404

A explicação está no mapa: src/lib é a pasta de código reaproveitável, não de rotas. O SvelteKit só procura páginas dentro de src/routes. O arquivo pode estar perfeito; se estiver fora da pasta certa, ele não é rota. Antes de mexer no código, confira o lugar do arquivo.

11. Rotas especiais que você vai encontrar

Além de +page.svelte, três arquivos aparecem em quase todo projeto e vale reconhecer de longe. Você não precisa dominar os três agora; precisa saber que existem e o que cada um faz, para não estranhar quando abrir um projeto alheio.

EndereçoQuem respondeDetalhe

/paessrc/routes/paes/+page.svelteuma pasta, uma página
/paes/francessrc/routes/paes/frances/+page.svelteduas pastas, duas barras

A segunda tabela é a das perguntas que sempre aparecem na primeira semana. Leia como um resumo de decisões, não como regra decorada.

PerguntaResposta curta
Onde crio a página /sobre?src/routes/sobre/+page.svelte
Preciso registrar a rota em algum arquivo?Não. A pasta é o registro.
Posso ter um componente junto da página?Pode. Sem o + no nome, ele não vira rota.
Onde ficam as imagens públicas?static/, servida na raiz do site.
Renomeei a pasta. E o link antigo?Vira 404. Link antigo é dívida: redirecione ou avise.

12. O caminho até aqui, em uma página

O site da Ana agora tem quatro endereços de verdade: /, /paes, /sobre e /contato — este último com a página dentro de contato/, no lugar certo depois do susto do erro 3. Todos compartilham o mesmo menu, porque o menu mora no +layout.svelte, que é o próximo assunto. Todos respondem 200. O endereço que ninguém criou responde 404 com uma página decente, não com a tela branca do navegador.

O que mudou na cabeça da Ana foi o modelo mental. Antes, ela pensava "preciso criar uma página e depois dizer ao sistema que ela existe". Agora ela pensa "preciso de uma gaveta nova; a etiqueta vem junto". O trabalho de manter duas listas — a do disco e a do sistema — desapareceu. Sobrou o trabalho de verdade: decidir quais endereços o site deve ter e o que cada um mostra.

E ficou uma pergunta sem resposta: como fazer uma página para cada pão, sem criar uma pasta por pão? A resposta está nos colchetes, e o endereço é Parâmetros de Rota. Antes disso, vale entender quem envolve todas essas páginas: o +layout.svelte.

// a pasta é o endereço; o arquivo é o conteúdo

Resumo

  • Rota é o par endereço + arquivo. No SvelteKit, o arquivo é a fonte da verdade.
  • O caminho do arquivo dentro de src/routes, sem o +page.svelte do fim, é a URL.
  • src/routes/+page.svelte atende /; src/routes/paes/+page.svelte atende /paes.
  • Não existe lista de rotas para manter: criar a pasta cria o endereço, apagar a pasta apaga o endereço.
  • Só arquivos que começam com + têm papel no roteamento; o resto é arquivo comum.
  • +page.js ao lado de +page.svelte forma uma rota: dados de um lado, desenho do outro.
  • Endereço inexistente responde 404 e mostra o +error.svelte; código quebrado responde 500.
  • Duas pastas que casam com o mesmo endereço derrubam o build com route_conflict.
  • Bloco aberto sem fechar é block_unclosed, com a linha exata marcada por um circunflexo.
  • Página salva fora de src/routes não é rota: compila, mas responde 404.
  • curl -s -i mostra cabeçalhos e código; -w '%{http_code}' mostra só o número.
