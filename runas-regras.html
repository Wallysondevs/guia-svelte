Svelte · As Regras das Runas

A Ana já conhece as runas uma por uma: guardar, calcular, reagir, receber. Agora ela quer saber por que às vezes o código é recusado antes de rodar. Runas não são funções que vêm de uma biblioteca: são palavras que o compilador reconhece e troca por código. Por isso elas têm regras de lugar, de forma e de nome — e conhecer essas regras economiza horas de mensagem vermelha.

Você vai aprender

  • As cinco runas do Svelte 5 e o papel de cada uma.
  • Em quais arquivos as runas existem: .svelte e .svelte.js.
  • Por que toda runa é uma chamada com parênteses.
  • Por que a runa precisa ser o valor inicial de uma declaração.
  • Que o cifrão é reservado para nomes de variável.
  • Como um componente entra no modo runas e o que muda nele.
  • Por que export let e $: não convivem com runas.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como o projeto da Ana compila um módulo .svelte.js.

1. A ideia: runas são palavras do compilador

Quando você escreve $state(0), o navegador nunca vê essa palavra. Antes de a página abrir, o compilador do Svelte leu o seu arquivo e trocou a runa por código de verdade. O mesmo vale para $derived, $effect e $props: são marcas que o compilador entende e traduz.

É por isso que elas não se comportam como funções comuns. Uma função comum pode ser chamada em qualquer lugar, guardada numa variável, passada como argumento, importada de um arquivo. Uma runa não: ela depende de saber onde está para gerar o código certo. $state(0) numa declaração vira um sinal reativo; $state(0) solto não tem onde se apoiar.

Comparando com a padaria: as runas são como as etiquetas oficiais da vigilância sanitária. Elas só valem na embalagem certa, no lugar certo, com o número certo. Colar a etiqueta num guardanapo não faz o guardanapo virar produto registrado.

Tem uma vantagem nisso. Como o compilador vê a runa antes de o código rodar, ele pode gerar código menor e mais direto do que uma biblioteca conseguiria: ele sabe exatamente quem depende de quem. E tem uma desvantagem: fora das posições reconhecidas, a runa não é traduzida — e aí você recebe uma mensagem de erro em vez de um comportamento estranho. Mensagem é melhor. O difícil é entender o que ela quer dizer.

Função comumRuna

2. As cinco runas do Svelte 5

O guia já usou quatro. A quinta aparece quando um componente precisa aceitar que o pai mude o valor de uma prop. Vale ter o mapa completo antes das regras:

RunaPara que serveDevolve
$state(valor)guarda um valor que avisa a telao valor, observável
$derived(conta)calcula a partir de outros valoreso resultado da conta
$effect(função)faz algo depois do desenhonada (só a limpeza, opcional)
$props()recebe o que o pai mandouum objeto com as props
$bindable(valor)marca uma prop que o filho pode escrevero valor, com permissão de volta

Existem ainda os sufixos e auxiliares: $state.raw, $state.snapshot, $derived.by, $effect.pre, $effect.root, $props.id. Todos obedecem às mesmas regras de lugar — são variações da mesma palavra, não palavras novas.

3. Onde as runas existem

Runa só funciona em arquivo que o Svelte compila: .svelte (componente) e .svelte.js ou .svelte.ts (módulo de estado). Num arquivo .js comum, o compilador do Svelte nem passa — e a runa chega ao navegador como uma palavra desconhecida.

O Svelte protege você desse caso com uma mensagem específica, que aparece no console do navegador quando um componente importa estado de um arquivo sem o sufixo:

Svelte error: rune_outside_svelte
The `$state` rune is only available inside `.svelte` and `.svelte.js/ts` files
https://svelte.dev/e/rune_outside_svelte

"A runa $state só está disponível dentro de arquivos .svelte e .svelte.js/ts". O módulo que causou o erro era este:

export let paes = $state(0);

export function somar() {
  paes += 1;
}

A correção é renomear o arquivo para carrinho.svelte.js — sem mudar uma linha do conteúdo. O sufixo não é enfeite: é o aviso ao Vite de que aquele módulo precisa passar pelo compilador do Svelte antes de ir para o navegador.

Um módulo .svelte.js é útil quando várias telas compartilham o mesmo estado — a cesta da Ana vista pela tela de venda e pela tela de caixa, por exemplo. Ele exporta funções e valores, e cada componente que importa participa do mesmo estado.

A forma do módulo é simples: as runas no nível de cima do arquivo, e funções exportadas para que os componentes leiam e mudem o estado. Nada de HTML, nada de export default: é um módulo de JavaScript, só que compilado pelo Svelte. O componente importa as funções e usa no HTML como qualquer outra função — a reatividade viaja junto.

4. Toda runa é uma chamada

A primeira regra de forma: runa tem parênteses. $state sozinho, $derived sozinho, $effect sozinho não são nada — o compilador recusa com a mesma mensagem para todos os casos:

<script>
  let qtd = $state(2);
  let total = $derived;
</script>

<p>Total: {total}</p>
Erro de compilação (linha 3, coluna 14): Cannot use rune without parentheses

"Não posso usar a runa sem parênteses". É uma mensagem fácil de resolver: coloque a conta dentro dos parênteses, $derived(qtd * 0.9), ou o valor inicial, $state(0).

Missão: a runa está sem a conta dentro. Conserte para a tela mostrar Total: 1.80 (dois pães a noventa centavos).

<script>
  let qtd = $state(2);
  let total = $derived;
</script>

<p>Total: {total}</p>
<script>
  let qtd = $state(2);
  let total = $derived(qtd * 0.9);
</script>

<p>Total: {total.toFixed(2)}</p>

Repare que a solução também formata o número com toFixed(2). A meta pede o texto Total: 1.80, e sem a formatação sairia Total: 1.8 — a diferença entre "a conta está certa" e "a tela está certa".

5. A runa precisa de dono

A segunda regra de forma: a runa é o valor inicial de uma declaração. Ela precisa estar do lado direito de um let, de um const ou de um campo de classe. Sozinha, ela não tem onde guardar o resultado:

<script>
  $state(0);
</script>

<p>Pães: 0</p>
Erro de compilação (linha 2, coluna 2): `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

"$state(...) só pode ser usado como valor inicial de uma declaração de variável, campo de classe, ou primeira atribuição a um campo de classe no construtor". A mensagem é longa porque cobre os três lugares possíveis. Na prática: dê um nome ao estado.

A anatomia de uma chamada de runa

let
o dono. Pode ser let, const ou um campo de classe. Sem ele, a runa não tem onde guardar nada.
paes
o nome do estado. Escolha um nome que diga o que o valor significa; x não diz nada.
= $state(
a runa ocupando o valor inicial. É esta posição, do lado direito do sinal, que o compilador reconhece.
0
o argumento. Um só, sempre: o valor inicial, a conta, a função — depende da runa.
)
o fechamento. Faltando, o erro é de sintaxe e nem chega a falar de runa.

Missão: o estado foi criado sem nome e o componente nem compila. Dê um nome a ele e mostre o valor no parágrafo, mantendo o texto Pães: 0.

<script>
  $state(0);
</script>

<p>Pães: 0</p>
<script>
  let paes = $state(0);
</script>

<p>Pães: {paes}</p>

Esse erro é o mais comum de todos, porque $state(0) parece uma chamada que "cria" o estado, como se o compilador guardasse o valor em algum lugar secreto. Não existe lugar secreto: o estado mora na variável que você declara.

6. O cifrão é reservado

Terceira regra: você não pode inventar nomes que começam com $. O cifrão é do compilador — ele usa esse sinal para reconhecer runas e, no modo antigo, leituras de store. Tentar declarar uma variável com cifrão dá erro imediato:

<script>
  let $paes = 1;
</script>

<p>{$paes}</p>
Erro de compilação (linha 2, coluna 6): The $ prefix is reserved, and cannot be used for variables and imports

"O prefixo $ é reservado e não pode ser usado para variáveis e importações". A correção é simples: tire o cifrão do nome. O valor não muda de comportamento; paes é uma variável comum, e se você quiser que ela avise a tela, embrulhe-a com $state.

Missão: o nome da variável usa o cifrão reservado. Renomeie para que o componente compile e mostre 1.

<script>
  let $paes = 1;
</script>

<p>{$paes}</p>
<script>
  let paes = 1;
</script>

<p>{paes}</p>

Um detalhe que confunde: no modo antigo, $nome é uma forma legítima de ler uma store — o compilador transforma em assinatura. É justamente por isso que o prefixo é reservado: se você pudesse declarar $nome, o compilador não saberia distinguir a sua variável da leitura de store.

7. O que entra no modo runas

Um componente entra no modo runas na primeira runa que aparece. A partir daí, valem as regras novas — e as antigas param de funcionar. Não existe meio-termo: o arquivo é inteiro de um mundo ou do outro.

É por isso que export let e $: dão erro num componente que já usa $state. Eles pertencem ao modo antigo, e o compilador prefere recusar a mistura a adivinhar a intenção:

Erro de compilação (linha 2, coluna 2): Cannot use `export let` in runes mode — use `$props()` instead

"Não posso usar export let no modo runas — use $props() em vez disso". A mensagem entrega a solução. O mesmo acontece com a reatividade antiga:

Erro de compilação (linha 3, coluna 2): `$:` is not allowed in runes mode, use `$derived` or `$effect` instead

"$: não é permitido no modo runas; use $derived ou $effect". Note que a mensagem te dá a escolha: se a linha calculava um valor, é $derived; se ela fazia algo, é $effect.

Modo antigoModo runas
export let nomelet { nome } = $props()
let x = 0 (reativo por atribuição)let x = $state(0)
$: total = a * blet total = $derived(a * b)
$: { … } para efeitos$effect(() => { … })
on:click={…}onclick={…}

O modo antigo tem aula própria, com as regras dele e o motivo de ainda existir. O guia inteiro ensina o modo runas; quando você encontrar código antigo num projeto, a tabela acima é o mapa da tradução.

Como saber em qual modo está um arquivo que você abriu? Procure uma runa. Se houver qualquer $state, $derived, $effect ou $props no script, o componente é do modo novo. Se não houver nenhuma, ele é do modo antigo — e é por isso que um componente simples com let contador = 0 e um onclick ainda funciona hoje: ele nunca entrou no modo runas.

8. As regras que resolvem quase tudo

Se você guardar cinco frases, escapa da maioria das mensagens de erro deste guia:

  1. Runa é chamada. Sempre com parênteses: $state(0), $derived(conta), $props().
  2. Runa tem dono. Sempre como valor inicial de let, const ou campo de classe.
  3. Runa mora no topo. No <script> do componente ou no nível de cima de um módulo .svelte.js; dentro de funções valem as exceções, e $props não tem exceção.
  4. Runa não se importa. Não existe import { $state } from 'svelte'; ela já está disponível em qualquer arquivo compilado.
  5. Runa e modo antigo não se misturam. Um componente é de um mundo só.

A terceira regra merece um exemplo, porque é a que mais aparece em código copiado de outro lugar. $props() só pode ser chamado no topo do componente: dentro de um if, de uma função ou de um laço, o compilador recusa. O motivo é o mesmo de sempre — as props precisam existir antes de o corpo do componente rodar.

Vale guardar também o que não é regra, para não inventar limitações. Não é proibido ter várias variáveis de estado no mesmo componente; não é proibido usar a mesma runa em componentes diferentes; não é proibido misturar estado, derivado e efeito no mesmo arquivo. As regras são sobre onde e como a runa aparece, não sobre quantas você usa.

10. Quando dá errado

Três mensagens de compilação, cada uma de uma regra diferente. Repare que todas dizem o que fazer — nenhuma delas é um mistério.

1. export let no modo runas. O componente usa $state e tenta declarar prop do jeito antigo:

<script>
  export let nome = 'Ana';
  let paes = $state(0);
</script>

<p>{nome}: {paes} pães</p>
Erro de compilação (linha 2, coluna 2): Cannot use `export let` in runes mode — use `$props()` instead

A correção é trocar a linha por let { nome = 'Ana' } = $props(). A mensagem é literal: "use $props() instead".

2. A reatividade antiga com runas. O $: do Svelte 4 não funciona no modo novo:

<script>
  let a = $state(1);
  $: b = a * 2;
</script>

<p>{b}</p>
Erro de compilação (linha 3, coluna 2): `$:` is not allowed in runes mode, use `$derived` or `$effect` instead

Aqui a linha calcula um valor, então o substituto é let b = $derived(a * 2). Se a linha fizesse algo (um console.log, uma chamada), o substituto seria $effect.

3. $props() dentro de um if. A runa das props só existe no topo do componente:

<script>
  if (true) {
    let { nome } = $props();
  }
</script>

<p>Padaria</p>
Erro de compilação (linha 3, coluna 19): `$props()` can only be used at the top level of components as a variable declaration initializer

"$props() só pode ser usado no nível de cima dos componentes, como valor inicial de uma declaração de variável". Tire a linha de dentro do if e deixe no topo do script.

Resumo

  • Runa é uma palavra que o compilador reconhece e troca por código; não é função de biblioteca.
  • As cinco runas: $state, $derived, $effect, $props e $bindable.
  • Elas existem em .svelte e .svelte.js/.ts; em .js comum o erro é rune_outside_svelte, em tempo de execução.
  • Toda runa é chamada: sem parênteses, Cannot use rune without parentheses.
  • Toda runa tem dono: é o valor inicial de let, const ou campo de classe.
  • O cifrão é reservado: nomes começando com $ são recusados.
  • Um componente entra no modo runas na primeira runa que usa, e não volta atrás.
  • No modo runas, export let e $: dão erro; os substitutos são $props(), $derived e $effect.
  • $props() só pode ser chamado no topo do componente, e uma vez só.
  • Ler a mensagem inteira, com linha e coluna, é mais rápido do que procurar o erro a olho.
