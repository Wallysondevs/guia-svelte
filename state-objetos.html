Svelte · $state com Objetos e Listas

A cesta da Ana não é um número: é uma coisa só, com pães, preço e a lista de itens dentro. Guardar cada pedaço numa variável separada vira um novelo — muda um, esquece o outro. Nesta aula, o objeto inteiro é o estado: um $state só, que avisa a tela quando qualquer pedaço lá dentro muda, inclusive os mais fundos.

Você vai aprender
  • Como guardar um objeto inteiro em $state.
  • Por que mexer numa propriedade (cesta.paes = 3) já atualiza a tela.
  • Como listas reativas funcionam com push, splice e índice.
  • O que muda em objetos com dois ou três níveis.
  • As três armadilhas: desmontar, copiar e usar $state.raw.
  • Quando trocar o objeto inteiro com { ...cesta } compensa.
  • Como tirar uma cópia segura com $state.snapshot.
  • O custo de vigiar objetos grandes.
  • Os três erros reais desta aula, com a mensagem do compilador.
  • Como o projeto da Ana compila um componente com objeto reativo.

1. A ideia: a cesta é uma coisa só

Na padaria, a cesta é um objeto físico: ela tem pães dentro, tem um preço por unidade e tem um lugar na prateleira. Se a Ana anotar "2 pães" num papel e "0,90" em outro, os dois papéis podem se perder ou discordar. Se ela anotar tudo na mesma etiqueta, a cesta e a sua descrição andam juntas.

Em JavaScript, essa etiqueta com vários campos se chama objeto: um valor único que guarda outros valores, cada um com um nome. Uma lista (ou array) é a versão sem nome: os valores ficam numa fila, acessados por posição. E aqui está a boa notícia do Svelte 5: um $state com um objeto dentro vigia o objeto por dentro. Mover um pão de lugar já avisa a tela.

Esse comportamento se chama reatividade profunda. É o que permite escrever cesta.paes = 3 e ver o número mudar, em vez de reconstruir o objeto inteiro a cada mudança. O preço é um pouco de trabalho do compilador, que embrulha cada objeto e cada lista que entram no estado.

Um motivo prático para guardar tudo junto: os valores de um objeto sempre combinam entre si. Se a Ana mudar a quantidade e esquecer de mudar o total guardado noutra variável, a tela mostra uma conta que não fecha. Com a cesta inteira num estado só, qualquer mudança passa pelo mesmo lugar, e a tela recalcula o que depende dela.

2. O primeiro objeto reativo

Um objeto literal se escreve entre chaves, com pares nome: valor separados por vírgula. Embrulhado em $state, ele vira estado reativo de ponta a ponta:

<script>
  let cesta = $state({ paes: 2, preco: 0.9 });
</script>

<p>{cesta.paes} pães: R$ {(cesta.paes * cesta.preco).toFixed(2)}</p>
<p>2 pães: R$ 1.80</p>

Duas leituras com ponto, uma conta e um texto. Quando cesta.paes mudar, o parágrafo inteiro é recalculado — não só a parte que mostra o número. Isso importa: a conta e o texto andam sempre juntos.

A anatomia do objeto reativo

{ paes: 2, preco: 0.9 }
o objeto: campos com nome, separados por vírgula. Objeto não é lista; a ordem dos campos não significa nada.
$state(…)
a runa embrulha o objeto inteiro, não cada campo.
cesta.paes
a leitura de um campo. O ponto é o "de" do português: os pães da cesta.
cesta.paes = 3
a escrita de um campo. O Svelte é avisado e redesenha o que usa aquele campo.
{ ...cesta }
a cópia do objeto com os campos espalhados. Objeto novo, mesmo conteúdo — e a ligação com o estado é refeita.
Uma runa para o objeto, não para os campos

Você já viu a mensagem de erro que aparece quando $state é usado num campo: $state(...) can only be used as a variable declaration initializer…. A regra é simples: a runa embrulha o valor inteiro. Os campos ficam reativos por consequência.

3. Mexer por dentro

Com o objeto em $state, você muda um campo e pronto. Não é preciso criar um objeto novo nem chamar nada:

<script>
  let cesta = $state({ paes: 2, preco: 0.9 });
</script>

<p>{cesta.paes} pães: R$ {(cesta.paes * cesta.preco).toFixed(2)}</p>
<button onclick={() => cesta.paes++}>mais um pão</button>

O botão não mexe no parágrafo. Ele mexe no campo, e o Svelte faz a ponte. No texto gerado, o parágrafo continua o mesmo:

<p>2 pães: R$ 1.80</p> <button>mais um pão</button>

O que muda está no JavaScript compilado: cada campo lido no HTML vira uma dependência daquele pedaço da tela. Quando o campo muda, só aquele pedaço é atualizado. Num objeto com vinte campos e uma lista embaixo, isso é a diferença entre redesenhar tudo e redesenhar o que mudou.

4. Listas reativas

Uma lista é um objeto com posições numeradas. O $state vigia a lista do mesmo jeito que vigia um objeto: qualquer método que mude o conteúdo avisa a tela.

<script>
  let itens = $state(['pão', 'café']);
</script>

<p>Itens: {itens.join(', ')}</p>
<p>Itens: pão, café</p>

join(', ') transforma a lista num texto com vírgulas. É só apresentação: a lista continua sendo lista. Para adicionar um item, itens.push('leite'); para tirar o último, itens.pop(); para mudar uma posição, itens[0] = 'pão de queijo'.

O detalhe que surpreende quem vem do Svelte antigo: no Svelte 4, push não atualizava a tela; era preciso reatribuir (itens = [...itens, 'leite']). No Svelte 5, com $state, o push funciona. Os dois jeitos continuam válidos; o importante é que, com $state, você não é obrigado a reconstruir a lista.

Para mostrar a lista na tela, o caminho natural é o bloco {#each}, que percorre os itens e repete um pedaço de HTML para cada um. Com $state, a lista que o {#each} percorre também se atualiza sozinha quando um item entra ou sai. Essa combinação — lista reativa mais repetição — é o que faz uma lista de compras de verdade funcionar; o bloco tem aula própria nesta trilha.

Missão: o botão empurra um item para a lista, mas a tela fica em 1. Faça a contagem subir para 2 sem mexer no botão.

<script>
  let itens = ['pão'];
</script>

<p>Itens: {itens.length}</p>
<button onclick={() => itens.push('café')}>mais um</button>
<script>
  let itens = $state(['pão']);
</script>

<p>Itens: {itens.length}</p>
<button onclick={() => itens.push('café')}>mais um</button>

A lista sem runa é uma lista comum: o push acontece de verdade, mas ninguém avisa a tela. Esse é o mesmo papel contra lousa da aula de $state, agora com vários itens dentro.

5. Objetos dentro de objetos

A profundidade não é um problema. O $state embrulha o objeto inteiro, e cada objeto ou lista encontrado no caminho é embrulhado na hora em que é lido. Na prática, você mexe no caminho completo e a tela acompanha:

<script>
  let loja = $state({ cesta: { paes: 2 } });
</script>

<p>Pães: {loja.cesta.paes}</p>
<p>Pães: 2</p>

loja.cesta.paes é o caminho: da loja, para a cesta, até o número de pães. Três níveis, um $state. Se a Ana precisar de quatro, funciona igual — e se algum nível faltar, o erro aparece na hora de desenhar, como você vai ver nos cenários.

Missão: a loja foi declarada com $state.raw e o clique não muda nada. Faça a tela ir para Pães: 3.

<script>
  let loja = $state.raw({ cesta: { paes: 2 } });
</script>

<p>Pães: {loja.cesta.paes}</p>
<button onclick={() => loja.cesta.paes++}>mais um</button>
<script>
  let loja = $state({ cesta: { paes: 2 } });
</script>

<p>Pães: {loja.cesta.paes}</p>
<button onclick={() => loja.cesta.paes++}>mais um</button>

A diferença entre as duas versões do exercício está numa palavra: .raw. No raw, o Svelte não embrulha o conteúdo; o objeto é guardado cru e só a troca do valor inteiro avisa a tela. Para quem precisa vigiar o que está dentro, é o $state comum.

6. As três cópias que perdem a reatividade

Quase todo problema de "a tela não atualiza" em objeto vem de uma cópia feita no lugar errado. As três mais comuns:

1. Desmontar o objeto numa variável. let { paes } = cesta copia o valor do campo para uma variável nova. A variável tem o número 2, e esse número não acompanha mais o objeto. Para continuar ligado, leia o caminho no HTML: {cesta.paes}.

2. Copiar o objeto com let apelido = cesta. Aqui não há cópia — há dois nomes para o mesmo objeto. O perigo é o oposto do que parece: você acha que está mexendo numa cópia e está mexendo no original.

<script>
  let cesta = $state({ paes: 2 });
  let apelido = cesta;
  cesta.paes = 3;
</script>

<p>Original: {cesta.paes} · Apelido: {apelido.paes}</p>
<p>Original: 3 · Apelido: 3</p>

Os dois nomes apontam para o mesmo objeto, então os dois mostram 3. Se você quisesse mesmo uma cópia independente, precisaria criar outro objeto — com { ...cesta } ou com $state.snapshot.

3. Usar o objeto em $state.raw. Como você viu, o raw não vigia o conteúdo. Ele é para listas grandes que são trocadas inteiras, não para o caderno que muda item por item.

Missão: o valor foi copiado para paes e a tela ficou congelada. Mostre o valor vivo da cesta depois do clique.

<script>
  let cesta = $state({ paes: 2 });
  let { paes } = cesta;
</script>

<p>Pães: {paes}</p>
<button onclick={() => cesta.paes++}>mais um</button>
<script>
  let cesta = $state({ paes: 2 });
</script>

<p>Pães: {cesta.paes}</p>
<button onclick={() => cesta.paes++}>mais um</button>

A solução apaga a linha da desmontagem. Quando o HTML lê cesta.paes, o Svelte registra aquela leitura como dependência — e o clique avisa exatamente esse pedaço da tela.

7. Trocar o objeto inteiro com { ...cesta }

Existe um segundo jeito de mudar um objeto: construir um novo, com os campos antigos espalhados e um deles trocado. Os três pontinhos copiam os campos para o objeto novo.

<script>
  let cesta = $state({ paes: 2, preco: 0.9 });

  function somar() {
    cesta = { ...cesta, paes: cesta.paes + 1 };
  }
</script>

<p>Pães: {cesta.paes}</p>
<button onclick={somar}>mais um</button>
<p>Pães: 2</p> <button>mais um</button>

Funciona e tem um uso legítimo: quando você quer que o objeto antigo continue intacto em outro lugar (um histórico de estados, um desfazer). O custo é criar um objeto novo a cada mudança e jogar fora o antigo — em listas grandes, isso pesa.

JeitoVantagemCusto
cesta.paes++mínimo de trabalho; só o campo mudao objeto antigo é mutado — quem guardou referência vê a mudança
cesta = { ...cesta, paes: 3 }objeto novo; o antigo fica intactocopia todos os campos a cada mudança
cesta = structuredClone(cesta)cópia profunda, sem compartilhar filhoscaro; e o Svelte não rastreia o clone até você reatribuir

8. Tirar uma foto: $state.snapshot

Quando o objeto precisa sair do componente — para uma API, para o localStorage, para uma biblioteca que não conhece o Svelte —, o embrulho reativo atrapalha. A função $state.snapshot devolve uma cópia comum, sem embrulho:

<script>
  let cesta = $state({ paes: 2, preco: 0.9 });
  const copia = $state.snapshot(cesta);
</script>

<p>{copia.paes} pães</p>
<p>2 pães</p>

A foto é do momento: se a cesta mudar depois, a cópia não muda. É o comportamento que você quer ao enviar dados para fora — o que vai junto é o valor, não a ligação. Para o HTML, continue lendo o estado vivo.

O caso clássico é o botão de finalizar pedido: você junta os itens da cesta num objeto comum, envia para o servidor e continua mexendo na cesta na tela sem que o pedido enviado mude junto. Sem a foto, o envio carregaria o embrulho reativo — e o servidor receberia um objeto cheio de detalhes internos do Svelte, que não servem para nada do outro lado.

9. O custo de vigiar objetos

Reatividade profunda tem preço, e vale saber onde ele aparece. O Svelte embrulha cada objeto e cada lista na primeira leitura, e mantém um registro de quem depende de quê. Num objeto pequeno, isso é invisível. Numa lista de dez mil itens que muda inteira a cada segundo, o registro vira trabalho.

Duas saídas para esse caso. A primeira é $state.raw, que não embrulha nada: você ganha velocidade e perde a atualização automática por dentro, trocando o valor inteiro quando precisa. A segunda é não guardar a lista enorme como estado: mantenha a lista numa variável comum e guarde no estado apenas o que a tela mostra (a página atual, o filtro, o total).

Para o caderno da Ana — algumas dezenas de itens, mudanças de um por vez — o $state comum é a escolha certa. Otimizar antes de medir costuma trocar um problema que existe por outro que não existe.

11. Quando dá errado

Dois erros de compilação e um de renderização, todos colhidos do compilador de verdade.

1. $state dentro do objeto. A runa embrulha o valor inteiro; colocar outra dentro de um campo não é permitido:

<script>
  let cesta = $state({ itens: $state(['pão']) });
</script>

<p>{cesta.itens.length}</p>
Erro de compilação (linha 2, coluna 30): `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

A correção é tirar a runa de dentro: let cesta = $state({ itens: ['pão'] }). O conteúdo já é reativo por estar dentro do objeto embrulhado.

2. $state dentro da lista. O mesmo vale para listas — a runa não é um enfeite por item:

<script>
  let lista = [$state(1), 2];
</script>

<p>{lista[0]}</p>
Erro de compilação (linha 2, coluna 15): `$state(...)` can only be used as a variable declaration initializer, a class field declaration, or the first assignment to a class field at the top level of the constructor.

Escreva let lista = $state([1, 2]). Um embrulho para a lista inteira resolve o problema de todos os itens.

3. O caminho que não existe. Este compila e quebra ao desenhar, porque loja.cesta é undefined:

<script>
  let loja = $state({});
</script>

<p>Pães: {loja.cesta.paes}</p>
Erro ao renderizar: Cannot read properties of undefined (reading 'paes')

"Não consigo ler propriedades de algo indefinido (lendo paes)". O caminho para no meio: não há cesta dentro de loja. A correção é começar com a estrutura completa ({ cesta: { paes: 0 } }) ou usar um valor de reserva antes de acessar.

A ideia que amarra a aula: um $state é um embrulho em volta de um valor. Objetos e listas ficam reativos por dentro porque o embrulho se estende aos filhos na primeira leitura. Toda vez que a tela parar de acompanhar, desconfie de uma cópia no caminho — desmontagem, apelido ou raw.

Resumo

  • Um $state embrulha o valor inteiro: objeto ou lista ficam reativos por dentro.
  • cesta.paes = 3 e cesta.paes++ atualizam a tela sem reconstruir o objeto.
  • Listas aceitam push, pop, splice e atribuição por índice com reatividade.
  • Caminhos fundos (loja.cesta.paes) funcionam igual; caminho faltando quebra na renderização.
  • Desmontar (let { paes } = cesta) copia o valor e perde a ligação.
  • let apelido = cesta não copia: cria dois nomes para o mesmo objeto.
  • $state.raw não vigia o conteúdo; é para valores grandes trocados inteiros.
  • { ...cesta, paes: 3 } troca o objeto inteiro, com o custo de copiar todos os campos.
  • $state.snapshot tira uma cópia comum para enviar o dado para fora.
  • Listas reativas combinam com {#each}: a repetição acompanha as mudanças da lista.
  • A runa não entra em campo nem em item de lista: ela embrulha o valor inteiro.
