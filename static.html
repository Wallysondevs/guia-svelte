SvelteKit · A Pasta static

Na porta da padaria a Ana tem um quadro de cortiça. Ali ficam coisas prontas: o cartaz do preço do pão, o aviso de que o banheiro é só para clientes, o cartão do eletricista. Ninguém escreve esses papeis de novo a cada cliente que passa. O static do SvelteKit é esse quadro: uma pasta de arquivos que saem exatamente como entraram, sem passar por componente, sem load, sem cálculo. Esta aula mostra o que vale a pena pregar ali — e o que acontece quando um arquivo e uma rota querem o mesmo endereço.

Você vai aprender
  • O que é a pasta static e por que ela existe separada de src.
  • Quais arquivos ganham com isso: robots.txt, favicon, PDF, imagem de divulgação.
  • Como o servidor entrega esses arquivos e quais cabeçalhos ele manda.
  • Quem ganha quando existe uma rota e um arquivo com o mesmo endereço.
  • Por que esses arquivos não passam pelo hooks.server.js.
  • O que acontece com um arquivo que não existe: o 404 de verdade.
  • A diferença entre arquivo em static/ e arquivo importado de src/lib/assets.
  • Como o build copia a pasta e o que muda no pacote final.
  • Os três tropeços reais: importar de static, perder para uma rota e linkar arquivo que não existe.

1. A ideia: o quadro de cortiça na porta

Uma padaria tem dois tipos de papel. O primeiro é o que muda com o cliente: a comanda do pedido, o troco, a nota. O segundo é o que já está pronto e serve para todos: o horário de funcionamento, a lista de preços impressa, o alvará. O primeiro precisa ser escrito na hora; o segundo pode ser impresso uma vez e pregado na parede.

No SvelteKit a divisão é a mesma. Tudo que precisa ser montado — HTML com dados do banco, página com login, formulário — mora em src/routes e passa pelo seu código. Tudo que já está pronto — imagem, PDF, arquivo de texto — mora em static e é entregue cru. A pasta fica na raiz do projeto, ao lado de src, e o nome do arquivo dentro dela é o endereço na web: static/logo.svg vira https://sualoja.com/logo.svg.

Esse “cru” tem consequência boa e ruim. Boa: é rápido e barato, porque não há código entre o pedido e o arquivo. Ruim: nada nele pode ser dinâmico. Se o preço do pão mudar, o PDF antigo continua no ar com o preço antigo até alguém trocar o arquivo e publicar de novo.

2. O que entra e o que não entra

A regra prática é uma pergunta: este arquivo é igual para todo mundo e não precisa de cálculo? Se sim, é candidato à pasta static. Se depende de quem pediu — nome do cliente, preço do dia, pedido do dia —, ele pertence a uma rota.

ArquivoVai em static?Por quê
robots.txtsimtexto fixo que os buscadores leem
favicon.svgsimtodo visitante vê o mesmo ícone
cardápio em PDFsimarquivo pronto para baixar
foto do pão do diadependese troca todo dia, o arquivo muda a cada publicação
lista de pedidos do clientenãodepende de quem está logado
preço calculado com impostonãoprecisa rodar código no pedido

Não existe penalidade por colocar arquivo demais em static: eles só ocupam espaço no pacote final. O problema é o contrário — colocar lá algo que deveria ser calculado e descobrir tarde que o dado congelou. O build copia a pasta uma vez; o que está dentro não muda até o próximo build.

3. O primeiro arquivo: robots.txt

O projeto criado pelo sv create já vem com um arquivo em static, e ele é um bom primeiro exemplo. A função dele é conversar com os robôs dos buscadores: dizer o que pode ser visitado. O conteúdo é texto puro, sem HTML:

# allow crawling everything by default
User-agent: *
Disallow:
# allow crawling…
linha de comentário. O # faz o robô ignorar o resto da linha; serve para quem lê o arquivo depois.
User-agent: *
“vale para todos os robôs”. O asterisco é o curinga; um nome específico limitaria a regra àquele robô.
Disallow:
vazio de propósito: nada está proibido. Se você escrevesse Disallow: /conta, o robô deixaria de visitar a área logada.

O arquivo é servido na raiz do site, sem pasta: /robots.txt. Não é /static/robots.txt — o nome da pasta não aparece na URL. Essa é a parte que mais confunde no começo: static é o nome no disco, não o nome no endereço.

A pasta da Ana, depois de algum tempo, tem esta cara:

ana@notebook:~/loja$ ls static
aviso.txt  logo.svg  produtos  robots.txt  sobre.html

Note dois detalhes. produtos é uma pasta com index.html dentro; sobre.html é um arquivo com extensão no nome. Os dois são servidos, mas em endereços diferentes, e isso vai importar na seção 6.

4. Como o servidor entrega esses arquivos

Para ver o que acontece de verdade, nada melhor do que pedir os arquivos ao servidor de desenvolvimento e olhar a resposta. O comando abaixo pede só o cabeçalho de cada endereço:

ana@notebook:~/loja$ for u in /logo.svg /aviso.txt /naoexiste.svg; do printf '%s -> ' "$u"; curl -s -o /dev/null -w '%{http_code}\n' "http://localhost:5173$u"; done
/logo.svg -> 200
/aviso.txt -> 200
/naoexiste.svg -> 404

Os dois primeiros saíram do disco. O terceiro não existe, e o servidor respondeu 404 — mas não com um texto seco: respondeu com a página de erro do SvelteKit, porque o pedido caiu no roteador do app depois que o arquivo não foi encontrado. A resposta completa mostra os cabeçalhos de um arquivo estático:

ana@notebook:~/loja$ curl -s -D - -o /dev/null http://localhost:5173/logo.svg
HTTP/1.1 200 OK
Vary: Origin
Content-Length: 221
Content-Type: image/svg+xml
Last-Modified: Thu, 26 Nov 2026 17:00:35 GMT
ETag: W/"221-1795712435396"
Cache-Control: no-cache
Date: Thu, 26 Nov 2026 17:19:40 GMT
Connection: keep-alive
Keep-Alive: timeout=5

O Content-Type vem da extensão: .svg é imagem vetorial, .txt é texto, .pdf é PDF. Errar a extensão é o erro clássico: um arquivo chamado logo sem extensão é servido como binário genérico, e o navegador não mostra a imagem. O ETag e o Last-Modified permitem que o navegador pergunte “mudou?” em vez de baixar de novo. O Cache-Control: no-cache é do servidor de desenvolvimento; em produção quem manda é o adaptador e as regras da plataforma.

5. Caixa 1: montando o endereço

Todo arquivo em static ganha um endereço começando com barra. Montar esse endereço à mão é onde nasce o link quebrado, então vale treinar. A caixa abaixo escreve o nome do arquivo sem a barra inicial.

Missão: digite logo.svg no campo e o texto deve virar URL: /logo.svg. Cuide para não duplicar a barra se alguém digitar /logo.svg.

<script>
	let arquivo = $state('logo.svg');
</script>

<input oninput={(e) => (arquivo = e.currentTarget.value)} />
<p>URL: {arquivo}</p>
<script>
	let arquivo = $state('logo.svg');
	let url = $derived('/' + arquivo.replace(/^\//, ''));
</script>

<input oninput={(e) => (arquivo = e.currentTarget.value)} />
<p>URL: {url}</p>

A expressão /^\// procura uma barra no começo do texto, e o replace troca por nada. Assim, tanto logo.svg quanto /logo.svg produzem /logo.svg. Esse cuidado pequeno evita o endereço com duas barras, que o servidor trata como outro caminho e devolve 404.

A mesma conta, dentro de um componente que recebe o nome do arquivo por propriedade, fica assim:

<script>
	let { arquivo = 'logo.svg' } = $props();

	const url = $derived('/' + arquivo.replace(/^\//, ''));
</script>

<p>URL: {url}</p>
<p>URL: /logo.svg</p>

O valor padrão da propriedade é logo.svg, então o componente já mostra algo útil mesmo antes de alguém passar um nome. É a mesma ideia do valor padrão numa função: quem chama pode omitir, e o componente não quebra.

6. Rota e arquivo com o mesmo nome

Aqui está o ponto que mais surpreende. A Ana colocou static/produtos/index.html com um cardápio bonito e também tem uma rota /produtos que lista os produtos do banco. Quem responde quando alguém pede /produtos? O teste abaixo mostra a resposta:

ana@notebook:~/loja$ for u in /produtos /produtos/ /produtos/index.html /sobre /sobre.html; do printf '%s -> ' "$u"; curl -s -o /dev/null -w '%{http_code}\n' "http://localhost:5173$u"; done
/produtos -> 200
/produtos/ -> 308
/produtos/index.html -> 200
/sobre -> 200
/sobre.html -> 200

O /produtos devolveu 200, mas não é o arquivo: é a rota. O SvelteKit procura primeiro nas rotas, e só entrega o arquivo estático quando nenhuma rota casa. Para ver a diferença, o conteúdo do h1 resolve:

ana@notebook:~/loja$ curl -s http://localhost:5173/produtos | grep -o '<h1>[^<]*</h1>'
<h1>Produtos</h1>
ana@notebook:~/loja$ curl -s http://localhost:5173/produtos/index.html | grep -o '<h1>[^<]*</h1>'
<h1>cardapio estatico</h1>

Mesma pasta, dois endereços, dois conteúdos. O arquivo só aparece quando o nome dele está na URL, com index.html no fim. E o /produtos/ com barra no fim recebeu 308: um redirecionamento permanente para o endereço sem barra, decidido pela configuração de trailingSlash. O navegador refaz o pedido sozinho e o cliente não percebe.

Com static/sobre.html acontece o mesmo, e o resultado é mais sutil: /sobre mostra a rota do SvelteKit e /sobre.html mostra o arquivo. Dois endereços vivos para o mesmo assunto — e o buscador pode indexar os dois. Quando isso não for intencional, o certo é escolher um.

7. Caixa 2: rota ou arquivo?

Saber quem responde por um endereço é o que evita passar meia hora procurando um texto que não aparece. A caixa abaixo tem a lista de rotas do projeto e um campo para o caminho; ela diz “arquivo” sempre.

Missão: se o caminho estiver na lista de rotas, mostre rota; senão, arquivo. Teste /produtos e /logo.svg.

<script>
	const rotas = ['/produtos', '/conta'];
	let caminho = $state('/produtos');
</script>

<input oninput={(e) => (caminho = e.currentTarget.value)} />
<p>{caminho}: arquivo</p>
<script>
	const rotas = ['/produtos', '/conta'];
	let caminho = $state('/produtos');
	let ehRota = $derived(rotas.includes(caminho));
</script>

<input oninput={(e) => (caminho = e.currentTarget.value)} />
<p>{caminho}: {ehRota ? 'rota' : 'arquivo'}</p>

includes é a função de lista que responde “este item está aqui?”. Funciona para texto e para número, e é o mesmo teste que o SvelteKit faz internamente ao escolher entre rota e arquivo — só que ele tem uma tabela de rotas de verdade, montada a partir dos arquivos de src/routes.

8. Arquivos que não passam pelo hooks.server.js

Esta é uma descoberta que economiza depuração. O hooks.server.js roda a cada requisição ao app — mas não roda para arquivo estático. A prova está no terminal: o servidor da Ana registra cada pedido, e o /logo.svg não aparece no registro.

GET / → 200 (92 ms)
200 GET /
[erro 404] GET /naoexiste.svg: Not Found
GET /naoexiste.svg → 404 (20 ms)
404 GET /naoexiste.svg

Três pedidos foram feitos nessa sessão: a página inicial, o logotipo e um arquivo inventado. O registro mostra dois. O /logo.svg foi entregue antes de o app ser chamado, então não passou pelo hook. Já o /naoexiste.svg não achou arquivo, caiu no app, passou pelo hook e virou página de erro 404.

Isso tem duas consequências práticas. A primeira: contagem de acesso por hook subestima o tráfego, porque imagem e PDF não entram na conta. A segunda: proteção por hook não alcança arquivo estático — se o PDF confidencial está em static, ele está público, mesmo que você tenha escrito uma regra de login no handle. Arquivo que precisa de permissão não mora em static.

9. Arquivo em static ou importado de src?

Existem dois jeitos de usar uma imagem no projeto, e eles não são equivalentes. O primeiro é o que esta aula mostra: o arquivo em static e o endereço escrito à mão no HTML.

<h1>Arquivos da pasta static</h1>
<img src="/logo.svg" alt="Logo da padaria" width="80" height="80" />
<p><a href="/robots.txt">robots.txt</a> e <a href="/logo.svg">logo.svg</a> vêm da pasta static.</p>

O segundo é importar o arquivo do código, como o projeto faz com o favicon no +layout.svelte: import favicon from '#lib/assets/favicon.svg'. Nesse caso o Vite processa a imagem, dá um nome com hash e devolve o endereço pronto. Se a imagem for pequena, ele pode até embutir o conteúdo direto no JavaScript para economizar um pedido.

static/logo.svgimportado de src/lib/assets
Endereçofixo: /logo.svggerado, com hash no nome
Passa pelo Vitenãosim, com otimização
Cache do navegadordepende dos cabeçalhospode ser eterno: nome novo, arquivo novo
Erro de caminho errado404 só na hora do acessofalha no build
Bom pararobots.txt, PDF, download diretoimagens usadas por componentes

A diferença que mais importa no dia a dia é a última linha da tabela. Caminho importado errado quebra o build, com mensagem e linha. Caminho em static errado não quebra nada: vira um 404 silencioso, que você só descobre clicando. Por isso o hábito de conferir os links antes de publicar vale tanto.

10. Caixa 3: links que não existem

Um link quebrado numa página de padaria é um cliente que desiste. A caixa abaixo tem três links, sendo um deles para um arquivo que ninguém colocou na pasta, e diz “ok” para todos.

Missão: mostre ok só para os arquivos que existem. O /cardapio.pdf tem existe: false e precisa aparecer como faltando.

<script>
	const links = [
		{ href: '/logo.svg', existe: true },
		{ href: '/aviso.txt', existe: true },
		{ href: '/cardapio.pdf', existe: false }
	];
</script>

<ul>
	{#each links as l}
		<li>{l.href} ok</li>
	{/each}
</ul>
<script>
	const links = [
		{ href: '/logo.svg', existe: true },
		{ href: '/aviso.txt', existe: true },
		{ href: '/cardapio.pdf', existe: false }
	];
</script>

<ul>
	{#each links as l}
		<li>{l.href} {l.existe ? 'ok' : 'faltando'}</li>
	{/each}
</ul>

O condicional dentro de { } decide o texto de cada linha. Numa aplicação de verdade essa marcação costuma virar uma classe CSS — class:falta={!l.existe} — para o link faltando ficar vermelho e chamar atenção. O importante é que a informação “não existe” esteja no dado, não na sua memória.

11. Quando dá errado

Os três casos abaixo são de execuções reais: dois saíram do build e um saiu do servidor. Nenhuma mensagem foi reescrita.

Erro 1 — importar arquivo de dentro de static

A pasta static não é uma pasta de módulos: o Vite não a processa como origem de importação. Quem tenta importar recebe um erro de resolução.

<script>
	import logo from '../../static/logo.svg';
</script>

<img src={logo} alt="logo" />
transforming...
✓ 202 modules transformed.
✗ Build failed in 322ms
error during build:
Build failed with 1 error:

[UNRESOLVED_IMPORT] Could not resolve '../../static/logo.svg' in src/routes/importa/+page.svelte
   ╭─[ src/routes/importa/+page.svelte:2:18 ]
   │
 2 │ import logo from '../../static/logo.svg';
   │                  ───────────┬───────────  
   │                             ╰───────────── Module not found.
───╯

A saída é uma das duas: escrever <img src="/logo.svg"> e deixar o arquivo onde está, ou mover a imagem para src/lib/assets e importar de lá. O erro Module not found é literal: naquele caminho não há módulo, só um arquivo parado.

Erro 2 — o arquivo existe, mas a rota responde no lugar dele

Não há mensagem de erro neste caso, e é por isso que ele é perigoso. A Ana colocou o cardápio em static/produtos/index.html e pediu /produtos. A resposta veio 200, mas o conteúdo era o da rota.

ana@notebook:~/loja$ curl -s http://localhost:5173/produtos | grep -o '<h1>[^<]*</h1>'
<h1>Produtos</h1>
ana@notebook:~/loja$ curl -s http://localhost:5173/produtos/index.html | grep -o '<h1>[^<]*</h1>'
<h1>cardapio estatico</h1>

A rota venceu, e o arquivo ficou acessível só no endereço com index.html. Se a intenção era o arquivo, o nome dele precisa ser outro — cardapio.html, por exemplo — ou a rota precisa sair do caminho. Dois donos para o mesmo endereço nunca dá certo.

Erro 3 — o arquivo que ninguém colocou

Um pedido a um arquivo inexistente não fica sem resposta: ele cai no app e vira a página de erro 404. O cabeçalho mostra o status e o tipo de conteúdo, e a mensagem aparece no terminal por causa do hook de erro.

ana@notebook:~/loja$ curl -s -i http://localhost:5173/naoexiste.svg | head -4
HTTP/1.1 404 Not Found
Vary: Origin
content-length: 1462
content-type: text/html

Repare no content-type: text/html: o pedido era de uma imagem vetorial e a resposta foi uma página HTML. Navegador nenhum desenha isso como imagem, então o que aparece é o ícone de imagem quebrada. No terminal do servidor, a linha [erro 404] GET /naoexiste.svg: Not Found registra o mesmo fato.

Exercícios

1. O arquivo static/cardapio.pdf fica em qual endereço?

2. Existe a rota /produtos e o arquivo static/produtos/index.html. O que /produtos devolve?

3. Por que o /logo.svg não aparece no registro do hooks.server.js?

Complete o código

<!-- src/routes/static/+page.svelte -->
<img src="" alt="Logo da padaria" />

// o arquivo mora em static/logo.svg, na raiz do projeto

Resumo

  • static é a pasta de arquivos prontos: sai daqui exatamente o que entrou, sem componente e sem load.
  • O nome do arquivo vira endereço na raiz do site: static/logo.svg responde em /logo.svg.
  • robots.txt, favicon, PDF e imagens de divulgação são os moradores naturais da pasta.
  • O Content-Type vem da extensão; arquivo sem extensão é servido como binário genérico.
  • Rota e arquivo no mesmo endereço: a rota vence, e o arquivo só responde com o caminho completo.
  • /produtos/ com barra no fim responde 308, um redirecionamento permanente para o endereço sem barra.
  • Arquivo estático não passa pelo hooks.server.js; arquivo que não existe passa, e vira 404.
  • Importar de dentro de static não funciona: o erro é UNRESOLVED_IMPORT com Module not found.
  • Importar de src/lib/assets gera nome com hash e quebra o build quando o caminho está errado.
  • O build copia a pasta uma vez; o conteúdo não muda até a próxima publicação.
