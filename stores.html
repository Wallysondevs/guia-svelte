Svelte · Stores

A Ana tem seis placas na parede da padaria e cada uma mostra um número que também aparece em outra placa: o preço do pão na vitrine, o mesmo preço no cardápio do balcão, o total do pedido no caixa. Quando o preço muda, ela precisa lembrar de todas as placas — e sempre esquece uma. O sobrinho dela sugeriu um quadro de avisos no fundo da loja: as placas passam a ser uma janela para o quadro, e quem muda o número muda uma vez só. No Svelte esse quadro tem nome: store.

Você vai aprender
  • O que é um store e por que ele existe quando $state não resolve.
  • Criar um store com writable e ler o valor no HTML com o cifrão $.
  • As quatro formas de escrever num store: set, update, $x = … e $x += ….
  • Guardar o store num módulo .js para dois componentes verem o mesmo valor.
  • O contrato que todo store cumpre: um subscribe que avisa quem está olhando.
  • Como fazer uma conta acompanhar o store com $derived.
  • A diferença entre writable, readable e readonly.
  • Ler o valor de fora do HTML com get() — e por que isso não é reativo.
  • Os três erros reais desta aula, com a mensagem que o compilador ou o navegador mostra.
  • O que o terminal da Ana imprime quando ela procura onde o store é usado.

1. A ideia: um quadro de avisos no fundo da padaria

Imagine que a Ana trocou as seis placas por um quadro grande no fundo da loja. Cada placa agora tem um visor, e o visor mostra o que está escrito no quadro. Quando o preço do pão sobe, ela escreve uma vez no quadro com um giz, e todas as placas que mostram aquele campo mudam no mesmo instante.

Essa é a ideia inteira de um store. Ele é um valor que mora fora do componente — num arquivo separado, normalmente — e os componentes não guardam uma cópia dele: eles assinam o quadro. Quem assina é avisado toda vez que alguém escreve. O componente que mostra o número se redesenha sozinho; o componente que escreve nem sabe quem está olhando.

Por que não usar $state para tudo, então? Porque $state mora dentro de um componente. Se a placa da vitrine e o painel do caixa são componentes diferentes, um não enxerga o estado do outro: o número só chegaria passando de pai para filho, prop por prop, por cada andar da árvore. O store tira o valor de dentro da árvore e o coloca ao lado dela — a diferença entre um caderno na gaveta de um funcionário e o quadro na parede, que todos leem.

Repare no vocabulário, porque ele volta o guia inteiro: store é o quadro; assinar (subscribe) é pendurar um visor no quadro; escrever (set) é usar o giz; e o cifrão $ é o atalho do Svelte para "mostre aqui o que está no quadro agora".

A última linha é a que mais confunde. get() não pendura visor nenhum: ele lê o quadro uma vez e devolve o que estava escrito naquele instante. Se o valor mudar depois, a sua variável continua com o número velho. Guarde essa frase, porque ela volta na seção 9.

3. O primeiro store da Ana

Um store se cria com uma função chamada writable — "escrevível", em inglês — importada de svelte/store. O argumento é o valor inicial. Uma vez criado, o valor é lido no HTML com um cifrão na frente do nome:

<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);
</script>

<p>Cliques: {$cliques}</p>
<button onclick={() => $cliques = $cliques + 1}>+1</button>

O compilador do guia renderiza esse componente e devolve exatamente isto:

<p>Cliques: 0</p> <button>+1</button>

Duas coisas para notar. Primeiro: o valor aparece como 0, o valor inicial que você passou para writable. Segundo: o botão não tem nenhum código de atualização na saída, porque esse código roda no navegador, no clique. O HTML mostra o estado de agora; quem faz o resto é o JavaScript que o compilador gerou.

import { writable } from 'svelte/store'
svelte/store é um módulo separado do svelte. Store não é runa: é uma biblioteca pequena que vem junto com o Svelte.
const cliques
o nome do store. Note que é const, não let: você nunca troca o store, só o valor dentro dele.
writable(0)
cria o store com o valor inicial 0. Pode ser número, texto, lista, objeto — qualquer coisa.
{$cliques}
o cifrão pede ao Svelte: "assine esse store e mostre o valor". Quando o valor muda, este pedaço do HTML se redesenha.
$cliques = $cliques + 1
lê o valor atual, soma um e escreve de volta. O Svelte traduz isso para cliques.set(…).

O cifrão é o único lugar do guia em que uma variável começa com $ e isso é permitido. Ele não faz parte do nome do store: o store se chama cliques; $cliques é a leitura assinada dele. É por isso que a linha const cliques = writable(0) não tem cifrão nenhum.

Por que const e não let

Um erro comum de quem começa é escrever let cliques = writable(0) pensando que vai "trocar o valor". O valor não é trocado: ele é escrito dentro do store, com set. A caixinha continua a mesma a vida inteira — let não dá erro, mas sugere uma troca que não existe.

4. Escrever: set, update e o cifrão

Existem quatro formas de escrever num store writable, e todas terminam no mesmo lugar. A diferença está em quanto você precisa saber sobre o valor atual:

<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);

  function zerar() {
    cliques.set(0);
  }

  function somar() {
    cliques.update((n) => n + 1);
  }
</script>

<p>Cliques: {$cliques}</p>
<button onclick={somar}>+1</button>
<button onclick={zerar}>zerar</button>
<p>Cliques: 0</p> <button>+1</button> <button>zerar</button>

set recebe o valor novo e pronto. update recebe uma função que transforma o valor velho no novo, com o Svelte passando o valor atual para ela. Usar update evita o bug clássico de ler um valor que já mudou.

FormaO que você escreveQuando usar
setcliques.set(0)quando o valor novo não depende do velho
updatecliques.update((n) => n + 1)quando o valor novo depende do velho
cifrão com =$cliques = 0atalho de set, dentro do componente
cifrão com +=$cliques += 1atalho de update, dentro do componente

As duas últimas linhas só existem dentro de um componente .svelte: o compilador reconhece a atribuição e a traduz. Num arquivo .js comum não há $cliques para atribuir — lá você usa set e update, que são métodos do próprio store e funcionam em qualquer lugar.

Missão: o set escreve 1 a cada clique, então dois cliques mostram Cliques: 1. Troque-o por update para o valor novo sair do valor que já está no store: dois cliques devem mostrar Cliques: 2.

<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);

  function somar() {
    cliques.set(1);
  }
</script>

<p>Cliques: {$cliques}</p>
<button onclick={somar}>+1</button>
<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);

  function somar() {
    cliques.update((n) => n + 1);
  }
</script>

<p>Cliques: {$cliques}</p>
<button onclick={somar}>+1</button>

A caixa importa svelte/store como qualquer componente do projeto: o writable é o da biblioteca. Clique duas vezes no código inicial e a tela para em 1: set(1) escreve o mesmo número toda vez, porque não lê o valor que já estava lá.

5. O store mora fora do componente

Store dentro de um componente só serve para aquele componente — e para isso $state já bastava. O ganho aparece quando o store vai para um lugar que não é de ninguém: um módulo .js, importado por quem precisa. A padaria da Ana tem dois lugares que mostram a contagem de cliques: o placar da vitrine e o painel do caixa. Os dois leem o mesmo store.

import { writable } from 'svelte/store';

export const cliques = writable(0);
<script>
  import { cliques } from './contador.js';
</script>

<p>Cliques: {$cliques}</p>
<script>
  import Placar from './Placar.svelte';
</script>

<Placar />
<Placar />

Três arquivos, um valor. Cada Placar que monta assina o mesmo store, e o App não precisa passar prop nenhuma de um para o outro. Quando um clique acontecer, os dois vão mostrar o mesmo número, porque não existem dois valores: existe uma lista de funções inscritas dentro do store, e cada Placar colocou a sua lá.

Para você ver o efeito sem montar um projeto de três arquivos, o Svelte permite declarar o store dentro de <script module>. Esse bloco roda uma vez para o arquivo inteiro, e não uma vez por componente. Aqui o mesmo componente lê o store em dois lugares diferentes:

<script module>
  import { writable } from 'svelte/store';

  export const cliques = writable(0);
</script>

<p>Cliques: {$cliques}</p>
<p>Cliques: {$cliques}</p>
<p>Cliques: 0</p> <p>Cliques: 0</p>

Os dois parágrafos mostram o mesmo número porque leem o mesmo store, mesmo estando em arquivos diferentes — um deles em Placar.svelte, que aparece duas vezes. A saída é idêntica porque o que está no <script module> não é copiado junto com o componente.

export const cliques
o export é o que torna o store visível para outros arquivos. Sem ele, o módulo existe mas ninguém alcança o valor.
./contador.js
caminho relativo ao arquivo que importa. ./ quer dizer "na mesma pasta"; ../ sobe uma pasta.
src/lib/
a convenção do Svelte: código que não é componente (módulos, stores, funções) fica em lib; componentes em lib também.
import { cliques } from './contador.js'
traga só o que está exportado com esse nome. Se o nome não bater, o navegador reclama na hora.

Para saber onde o store é usado, a Ana usa o terminal. Este é o comando e a saída de verdade no projeto dela:

ana@notebook:~/loja$ grep -rn "cliques" src

O grep -rn procura um texto em todos os arquivos de uma pasta e mostra arquivo:linha. O -r é de "recursivo" (entra nas subpastas) e o -n mostra o número da linha. Ler essa saída é o jeito mais rápido de descobrir quem depende do store antes de mudar o valor inicial dele.

6. O contrato: um subscribe que avisa

Aqui vai a parte que separa quem decora de quem entende. Um store não é uma classe mágica: é um objeto com um método subscribe, e é só isso que o compilador exige. O writable é uma fábrica que monta esse objeto com três peças: o valor guardado, o conjunto de quem está inscrito e os métodos para escrever e avisar.

Para ver as três peças soltas, aqui está o mesmo store escrito à mão. Ele não importa nada e cumpre o contrato:

<script>
  let valor = 0;
  const inscritos = new Set();

  const contador = {
    subscribe(fn) {
      fn(valor);
      inscritos.add(fn);
      return () => inscritos.delete(fn);
    },
    set(novo) {
      valor = novo;
      inscritos.forEach((fn) => fn(valor));
    }
  };
</script>

<p>Cliques: {$contador}</p>
<button onclick={() => contador.set($contador + 1)}>+1</button>
subscribe(fn)
quem quer ser avisado chama este método e entrega uma função fn. O store guarda essa função na lista de inscritos.
fn(valor)
o primeiro aviso é imediato: o store entrega o valor atual na hora, para o visor não nascer vazio.
return () => inscritos.delete(fn)
o subscribe devolve uma função para desassinar. O Svelte chama essa função quando o componente sai da tela, e assim não fica ninguém inscrito num componente que não existe mais.
inscritos.forEach((fn) => fn(valor))
a parte que quase todo mundo esquece: escrever não basta, é preciso avisar cada inscrito com o valor novo.

Guardar os inscritos, avisar cada um e devolver o cancelamento: as três peças são o que o writable monta quando você escreve writable(0). Por isso o set de fábrica nunca esquece de avisar.

A caixa roda o writable de verdade

Nas caixas desta aula, o import de svelte/store é o do projeto: writable chega da biblioteca, e o mesmo vale para derived, get e readonly. O objeto à mão acima serve para reconhecer o que tem dentro dele.

7. A conta que acompanha o store

Mostrar $cliques é fácil: o compilador sabe assinar. O problema aparece quando você quer mostrar uma conta feita com o valor do store. Uma variável comum calculada uma vez não acompanha nada:

<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);
  let dobro = $cliques * 2;
</script>

<p>Cliques: {$cliques} · dobro: {dobro}</p>

Aqui dobro é uma variável normal: ela recebe 0 * 2 no momento em que o componente é montado e nunca mais é recalculada. O $cliques dentro do HTML se atualiza; o dobro fica congelado no primeiro valor. A correção é pedir a conta de novo a cada mudança, com $derived:

<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);
  const dobro = $derived($cliques * 2);
</script>

<p>Cliques: {$cliques} · dobro: {dobro}</p>
<p>Cliques: 0 · dobro: 0</p>

$derived marca a conta como dependente: quando $cliques avisa que mudou, a conta é refeita e o HTML se redesenha. O store continua sendo a fonte da verdade; o $derived é só o cálculo que olha para ela. A diferença entre let dobro e const dobro = $derived(…) é a diferença entre uma foto e um espelho.

Missão: o clique muda o contador, mas o dobro fica em 0. Faça a conta acompanhar o store para o clique mostrar Cliques: 1 · dobro: 2.

<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);
  let dobro = $cliques * 2;
</script>

<p>Cliques: {$cliques} · dobro: {dobro}</p>
<button onclick={() => cliques.set($cliques + 1)}>+1</button>
<script>
  import { writable } from 'svelte/store';

  const cliques = writable(0);
  const dobro = $derived($cliques * 2);
</script>

<p>Cliques: {$cliques} · dobro: {dobro}</p>
<button onclick={() => cliques.set($cliques + 1)}>+1</button>

São duas linhas de diferença: let dobro calcula no nascimento do componente; const dobro = $derived(…) recalcula a cada aviso. Rode o inicial e clique: Cliques sobe, dobro fica no zero.

8. readable: o valor que só o dono escreve

Nem todo valor deve poder ser escrito por qualquer um. O horário de abertura da padaria é decidido pela Ana, não pelo componente que mostra a placa. Para esses casos existe readable: um store que nasce com um valor e não tem set nem update.

<script>
  import { writable, readable } from 'svelte/store';

  const abertura = readable('06:00');
  const fila = writable([]);
</script>

<p>Abre às {$abertura}</p>
{#each $fila as pedido}
  <p>{pedido}</p>
{:else}
  <p>fila vazia</p>
{/each}
<p>Abre às 06:00</p> <p>fila vazia</p>

O readable também aceita uma função de início como segundo argumento. Ela roda na primeira assinatura e devolve uma função de limpeza, chamada quando o último inscrito vai embora. É o lugar certo para um relógio, um setInterval ou uma conexão que só deve existir enquanto alguém olha. O primeiro argumento é o valor inicial.

Existe ainda readonly, que embrulha um store existente e entrega só a parte de leitura: um componente recebe esse embrulho e não consegue escrever no valor original, mesmo que queira. A chamada a set num store readonly falha com r.set is not a function — a propriedade simplesmente não existe no objeto.

FunçãoQuem escreveUso típico
writable(valor)qualquer um que tenha o storecarrinho, filtro, contador, lista de pedidos

9. get(): ler o valor sem o cifrão

Dentro do HTML, o cifrão resolve. Mas e quando você precisa do valor dentro de uma função, de um cálculo no <script> ou de um arquivo .js que nem é componente? Aí entra get(), também de svelte/store:

<script>
  import { writable, get } from 'svelte/store';

  const cliques = writable(0);
  const comecou = get(cliques);
</script>

<p>Começou em {comecou}; agora: {$cliques}</p>
<button onclick={() => $cliques = $cliques + 1}>+1</button>
<p>Começou em 0; agora: 0</p> <button>+1</button>

No projeto da Ana o store vem de ./contador.js; o get funciona igual, porque só precisa do objeto.

get(cliques) devolve o valor que está no quadro naquele instante e não cria nenhuma ligação. Se o valor mudar depois, comecou continua 0: é uma foto, não um visor. Isso é uma qualidade, não um defeito — dentro de uma função você quase sempre quer o valor de agora, não uma assinatura que dispara renderizações.

O lugar em que get() brilha é fora do componente. Veja a Ana testando o store direto no terminal, sem abrir o navegador:

ana@notebook:~/loja$ node --input-type=module -e "import { get } from 'svelte/store'; import { cliques } from './src/lib/contador.js'; cliques.set(3); console.log('get:', get(cliques));"
get: 3

Três coisas aconteceram nessa linha comprida. O node rodou um módulo ES direto (--input-type=module), importou o svelte/store do projeto, escreveu 3 no store com set e leu de volta com get. O store funciona sem componente nenhum, porque ele é só JavaScript. É por isso que ele é um bom lugar para guardar dados que precisam durar mais do que uma tela.

get() dentro do componente raramente é o que você quer

Se o valor precisa acompanhar mudanças no HTML, use $cliques. Se precisa acompanhar dentro do script, use $derived. get() é para ler uma vez: número inicial, checagem, teste, arquivo que não é componente.

10. Store com objeto e com lista

Um store guarda qualquer valor, inclusive objetos e listas. O acesso é o de sempre, com o cifrão antes do nome e o ponto depois:

<script>
  import { writable } from 'svelte/store';

  const pedido = writable({ pao: 2, bolo: 1 });
</script>

<p>{$pedido.pao} pães e {$pedido.bolo} bolo</p>
<p>2 pães e 1 bolo</p>

Aqui mora a pegadinha mais cara desta aula. Quando o valor do store é uma lista, mexer na lista não avisa ninguém: o store só sabe que algo mudou quando set ou update é chamado. Um push deixa todos os visores mostrando a lista velha — para mudar uma lista, monte uma lista nova.

Missão: o botão usa push e a tela continua com um pão só. Faça a lista mostrar os dois itens — pão e bolo — avisando quem está inscrito.

<script>
  import { writable } from 'svelte/store';

  const lista = writable(['pão']);
</script>

<ul>
  {#each $lista as item}
    <li>{item}</li>
  {/each}
</ul>
<button onclick={() => $lista.push('bolo')}>adicionar</button>
<script>
  import { writable } from 'svelte/store';

  const lista = writable(['pão']);
</script>

<ul>
  {#each $lista as item}
    <li>{item}</li>
  {/each}
</ul>
<button onclick={() => lista.update((l) => [...l, 'bolo'])}>adicionar</button>

A solução troca $lista.push('bolo') por lista.update((l) => [...l, 'bolo']). Os três pontinhos espalham os itens antigos dentro de uma lista nova, e o 'bolo' entra no fim. Como é uma lista nova, o writable avisa todo mundo e a tela se redesenha. Com set a ideia é a mesma: lista.set([...$lista, 'bolo']) — as duas versões escrevem uma lista nova, que é o único jeito de o store perceber a mudança.

11. Quando dá errado

As três mensagens abaixo são reais. As duas primeiras vêm do compilador e a terceira, do renderizador que executa o componente. Elas não foram reescritas: é esse o texto que aparece.

Erro 1 — cifrão no nome da variável

Declarar o store já com $ no nome é o engano mais comum de quem traduz "ler com cifrão" para "declarar com cifrão". O compilador reserva o prefixo:

<script>
  import { writable } from 'svelte/store';
  let $contador = writable(0);
</script>

<p>Cliques: {$contador}</p>
Erro de compilação (linha 3, coluna 6): The $ prefix is reserved, and cannot be used for variables and imports

"O prefixo $ é reservado e não pode ser usado para variáveis e imports." A tradução prática: o nome do store é contador, sem cifrão. O cifrão só aparece onde o valor é lido, e o compilador cuida da assinatura sozinho.

Erro 2 — o cifrão dentro de <script module>

O bloco <script module> roda uma vez, fora do componente, e não tem onde pendurar um visor. Um $contador ali é recusado:

<script module>
  import { writable } from 'svelte/store';
  export const contador = writable(0);
  const dobro = $contador * 2;
</script>

<p>{$contador}</p>
Erro de compilação (linha 4, coluna 16): Cannot reference store value inside `<script module>`

"Não é possível referenciar o valor de um store dentro de <script module>." O valor muda com o tempo, e o bloco de módulo não tem um componente para redesenhar. Ali dentro, use get(contador) — e saiba que essa leitura não acompanha nada.

Erro 3 — cifrão num valor que não é store

O compilador aceita $contador em qualquer nome; quem confere se aquilo é um store é o tempo de execução. Este componente compila e quebra ao desenhar:

<script>
  let contador = 0;
</script>

<p>Cliques: {$contador}</p>
Erro ao renderizar: store.subscribe is not a function

"store.subscribe não é uma função." O cifrão supõe um objeto com subscribe; um número não tem esse método. Quando essa mensagem aparecer, procure a declaração do nome: quase sempre é um let valor = 0 que deveria ser writable(0) — ou um store que não foi importado.

Exercícios

1. Por que usar um store em vez de $state?

2. O que o cifrão em {$cliques} faz?

3. Qual é o mínimo que um objeto precisa ter para o Svelte aceitar o cifrão?

Complete o código

import { } from 'svelte/store';

const cliques = writable();

<p>Cliques: {$cliques}</p>

// o store começa em zero e qualquer componente que usar $cliques acompanha

Resumo

  • Store é um valor que mora fora do componente e avisa quem está inscrito quando muda.
  • writable(valor) cria um store que aceita escrita; readable cria um que só o dono muda.
  • O cifrão assina: {$cliques} mostra o valor atual e se redesenha quando ele muda.
  • set(valor) escreve um valor pronto; update((velho) => novo) escreve a partir do valor atual.
  • Dentro do componente, $cliques = 0 e $cliques += 1 são atalhos para set e update.
  • Para compartilhar, crie o store num módulo .js com export e importe onde precisar.
  • O contrato é só um: subscribe(fn) entrega o valor atual, guarda fn e devolve a função de cancelamento.
  • $derived($store * 2) refaz a conta a cada mudança; um let comum calcula uma vez e congela.
  • get(store) lê o valor naquele instante, sem assinar: é uma foto, não um visor.
  • Para mudar lista ou objeto guardado, escreva um valor novo ([...lista, item]); push não avisa ninguém.
  • Os erros desta aula: cifrão no nome, cifrão dentro de <script module> e cifrão num valor que não tem subscribe.
