Svelte · tick()

Na padaria da Ana, o pedido é escrito no caderno e só depois vira comanda na cozinha. Entre uma coisa e outra existe um intervalo, curto mas real. Dentro de um componente acontece igual: você muda o valor, e o HTML só acompanha no passo seguinte. Quando o seu código precisa do HTML já atualizado — para medir, focar ou contar elementos — existe uma função que espera esse passo: tick().

Você vai aprender

  • O que o Svelte faz entre a sua linha e o desenho da tela.
  • Como esperar a atualização com await tick().
  • Por que a função que usa tick() precisa ser async.
  • Os três casos em que tick() é necessário de verdade.
  • Como medir um elemento que acabou de aparecer na tela.
  • O que é flushSync e qual é o custo dele.
  • A diferença entre tick(), $effect e $derived nessa fila.
  • Os três erros reais desta aula, com a mensagem do compilador.

1. A ideia: o caderno e a comanda

A Ana anota o pedido do cliente no caderno, e a cozinha só começa a trabalhar quando a folha chega lá. Ela não consegue perguntar "o pão já está no forno?" no mesmo segundo em que escreveu: primeiro a folha precisa chegar. O intervalo é pequeno, mas existe, e quem confunde os dois momentos se atrapalha.

Um componente tem exatamente essa divisão. O seu código mexe nas variáveis de estado; o Svelte, em outro momento, lê essas variáveis e atualiza o HTML. O motivo é eficiência: se cada mudança desenhasse a tela na hora, uma função que troca cinco valores faria cinco desenhos. O Svelte junta as mudanças do mesmo passo e desenha uma vez só. Esse desenho agrupado se chama flush — "despejo", numa tradução livre: é quando a fila de mudanças é aplicada.

Quase sempre você não percebe esse intervalo, porque ninguém escreve código que dependa dele. O problema aparece quando o seu código, logo depois de mudar um valor, precisa ler a tela: contar quantos itens existem, medir a altura de uma caixa que acabou de aparecer, colocar o cursor num campo criado naquele instante. Aí o HTML ainda está no estado antigo, e a leitura devolve o número errado.

A solução é pedir para esperar: await tick(). A função tick devolve uma promessa que se resolve quando o próximo desenho terminou. Traduzindo: "espere a folha chegar na cozinha e depois continue".

2. O componente que conta os itens da tela

O exemplo da Ana conta quantos itens existem no HTML depois de adicionar um. Não é a mesma coisa que contar o tamanho da lista: um erro no {#each} pode deixar a lista maior que a tela, e é justamente isso que o teste pega.

<script>
  import { tick } from 'svelte';

  let itens = $state(['pão']);
  let naTela = $state(0);

  async function adicionar() {
    itens = [...itens, 'leite'];
    await tick();
    naTela = document.querySelectorAll('li').length;
  }
</script>

<ul>
  {#each itens as item}
    <li>{item}</li>
  {/each}
</ul>
<button onclick={adicionar}>adicionar</button>
<p>Itens na tela: {naTela}</p>
pão adicionar Itens na tela: 0

O texto acima é o que o renderizador produz fora do navegador: a lista com o primeiro item, o botão e o contador ainda em zero. naTela começa em zero e só muda no clique, depois de o tick resolver — e no servidor não há clique.

O ponto delicado está na ordem das duas linhas:

<script>
  let itens = $state(['pão']);
  let naTela = $state(0);

  function adicionar() {
    itens = [...itens, 'leite'];
    naTela = document.querySelectorAll('li').length;
  }
</script>

<ul>
  {#each itens as item}
    <li>{item}</li>
  {/each}
</ul>
<button onclick={adicionar}>adicionar</button>
<p>Itens na tela: {naTela}</p>
pão adicionar Itens na tela: 0

As duas versões produzem o mesmo HTML inicial, e é por isso que esse erro passa despercebido em qualquer conferência de marcação. A diferença aparece no clique: a segunda versão mostra 1 depois de adicionar o segundo item, porque contou o DOM antes de ele mudar. A primeira mostra 2.

A anatomia do await tick()

import { tick } from 'svelte'
tick é uma função importada, como onMount. Sem essa linha, o nome não existe no arquivo.
async function adicionar()
a palavra async autoriza o await dentro da função. Só funções assim podem esperar promessas; fora delas, o compilador recusa o await.
await tick()
espera o próximo desenho terminar. A partir da linha seguinte, o DOM já contém o item novo. tick devolve uma promessa: sem o await, você não espera nada.
document.querySelectorAll('li').length
a leitura da tela, agora confiável. Contar elementos do DOM é o jeito mais direto de provar que o HTML acompanhou.

Uma confusão comum: tick() não é "espere um tempo". Não há relógio, não há atraso artificial. Ele espera um passo do próprio Svelte, que dura o tempo de aplicar as mudanças pendentes — normalmente menos de um milissegundo. Usar setTimeout no lugar funciona por acidente e cobra caro: às vezes o passo do Svelte ainda não aconteceu, às vezes já aconteceu há muito tempo, e o código fica imprevisível.

3. Quando tick() é necessário

Existem três famílias de caso. Fora delas, quase sempre há um caminho melhor — e vale conhecer os dois lados, porque usar tick onde não precisa deixa o código mais difícil de ler sem ganho nenhum.

Você querPrecisa de tick()?Caminho
medir a altura de um elemento que acabou de aparecersimawait tick() e então offsetHeight
colocar o cursor num campo criado agorasimawait tick() e então campo.focus()
rolar a lista até o último itemsimawait tick() e então scrollIntoView()
calcular um valor a partir de outronão$derived
reagir a uma mudança de estadonão$effect
mostrar na tela um valor que veio do cliquenãoo próprio $state resolve

Repare que os três casos que pedem tick têm algo em comum: todos precisam de uma medida ou de um comando que só faz sentido no elemento já desenhado. Se o seu problema é calcular ou mostrar, o instrumento é outro. O tick é a ponte entre o mundo dos valores e o mundo dos elementos.

5. Medir a caixa que acabou de aparecer

O caso da medida é o mais delicado, porque o erro não devolve um número errado: devolve um erro de execução. Se o elemento ainda não existe, a variável do bind:this está vazia, e ler offsetHeight de undefined quebra o componente.

<script>
  import { tick } from 'svelte';

  let mostra = $state(false);
  let caixa = $state();
  let altura = $state(0);

  async function abrir() {
    mostra = true;
    await tick();
    altura = caixa.offsetHeight;
  }
</script>

<button onclick={abrir}>abrir comanda</button>
{#if mostra}
  <div bind:this={caixa} style="height: 40px">comanda</div>
{/if}
<p>Altura: {altura} px</p>
abrir comanda Altura: 0 px

Aqui aparece uma escolha nova: let caixa = $state(), e não let caixa. O motivo é técnico e vale saber, porque o compilador avisa: quando uma variável é escrita por uma função que também é lida na tela, declarar sem $state faz o compilador emitir o aviso non_reactive_update, dizendo que a atualização de caixa não vai disparar redesenho. Com $state, o bind:this e a leitura ficam combinados.

Missão: o botão faz a comanda aparecer, mas a medida estoura porque a caixa ainda não existe. Espere o desenho e mostre Altura: 40 px.

O mesmo desenho serve para focus() e para scrollIntoView(): são comandos que precisam do elemento na tela, e nenhum deles tem como funcionar antes do desenho. Guarde a regra: estado muda agora, DOM muda no próximo passo.

6. flushSync: quando você não pode esperar

Existe uma segunda ferramenta, para quem precisa do HTML atualizado na mesma linha, sem await. É o flushSync: ele força o desenho pendente a acontecer agora.

<script>
  import { flushSync } from 'svelte';

  let n = $state(0);

  function somar() {
    flushSync(() => {
      n++;
    });
    console.log(document.querySelector('output').textContent);
  }
</script>

<button onclick={somar}>somar</button>
<output>{n}</output>
<button>somar</button> <output>0</output>

O flushSync recebe uma função, aplica as mudanças dela e desenha antes de devolver o controle. O custo é o inverso do benefício: você perde o agrupamento e pode provocar vários desenhos seguidos, cada um recalculando posições na tela. Em uma lista grande, isso aparece como travamento. A recomendação do guia é preferir await tick() e deixar o flushSync para os casos em que o código não pode ser assíncrono — uma biblioteca de terceiros que exige a medida na hora, por exemplo.

Missão: o clique soma, mas a leitura do <output> pega o valor velho: lido: 0. Faça a leitura enxergar o valor novo, sem transformar a função em assíncrona.

<script>
  let n = $state(0);
  let lido = $state('—');

  function somar() {
    n++;
    lido = document.querySelector('output').textContent;
  }
</script>

<button onclick={somar}>somar</button>
<output>{n}</output>
<p>lido: {lido}</p>
<script>
  import { flushSync } from 'svelte';

  let n = $state(0);
  let lido = $state('—');

  function somar() {
    flushSync(() => { n++; });
    lido = document.querySelector('output').textContent;
  }
</script>

<button onclick={somar}>somar</button>
<output>{n}</output>
<p>lido: {lido}</p>

Se você resolver essa missão com async e await tick(), a meta também é cumprida — as duas formas levam ao mesmo resultado. O que muda é o custo: o tick espera o agrupamento normal, o flushSync o atropela.

7. tick(), $effect e $derived na fila

É comum a dúvida: se o $effect roda depois das mudanças, ele substitui o tick? Não substitui, e a diferença está no que cada um enxerga. O $effect é chamado depois de o DOM ser atualizado, então dentro dele a medida já é confiável. O problema é que ele roda sempre que uma dependência muda, e você perde o controle sobre quando a leitura acontece.

InstrumentoQuando rodaO DOM já está atualizado?
o corpo do seu evento (onclick)no cliquenão
await tick()quando o desenho pendente terminasim
$effectna montagem e a cada dependência alteradasim, mas em todo ciclo
$deriveddurante o cálculo do desenhonão se aplica: é valor, não efeito

O tick devolve uma promessa, e isso permite um uso elegante: {#await tick()}. No servidor, a promessa não resolve e o bloco mostra o conteúdo de espera; no navegador, resolve no primeiro desenho. Veja o componente:

<script>
  import { tick } from 'svelte';
</script>

{#await tick()}
  <p>esperando</p>
{:then}
  <p>pronto</p>
{/await}
esperando

É um exemplo didático, e não um padrão recomendado: usar tick como promessa de dados confunde o leitor, porque o bloco {#await} foi feito para esperar dados, não o desenho. Para carregar dados existe a aula de {#await}. Guarde esta seção pelo diagnóstico: se a sua tela mostra "esperando" e nunca muda, o problema é a promessa que nunca resolve no servidor.

9. Quando dá errado

As três mensagens abaixo saíram da execução dos componentes quebrados neste guia, copiadas como estão.

Erro 1 — await numa função que não é async

O compilador do Svelte usa o parser do JavaScript, e o parser recusa await fora de função assíncrona antes mesmo de olhar o Svelte.

<script>
  import { tick } from 'svelte';

  let n = $state(0);

  function somar() {
    n++;
    await tick();
  }
</script>

<button onclick={somar}>{n}</button>
Erro de compilação (linha 8, coluna 4): Cannot use keyword 'await' outside an async function

A correção é uma palavra: async function somar(). A mensagem aponta a linha do await, e não a da declaração da função — leia com calma para não corrigir o lugar errado.

Erro 2 — await no topo do componente

Quem tenta esperar o desenho no nível do script esbarra numa regra do modo com runas: o topo do componente não pode ser assíncrono, a menos que o projeto ligue a opção experimental de assincronismo.

<script>
  import { tick } from 'svelte';

  let itens = $state([]);
  const depois = await tick();
</script>

<p>{itens.length}</p>
Erro de compilação (linha 5, coluna 17): Cannot use `await` in deriveds and template expressions, or at the top level of a component, unless the `experimental.async` compiler option is `true`

A tradução útil: "await só dentro de função". Mova a espera para a função que precisa dela — no caso, a que adiciona itens e lê o DOM.

Erro 3 — tick() mostrado como se fosse valor

Este não quebra nada: ele publica a promessa na tela. A saída é literalmente o texto que o JavaScript usa para representar uma promessa.

<script>
  import { tick } from 'svelte';
</script>

<p>{tick()}</p>
<p>[object Promise]</p>

[object Promise] é o sintoma de uma promessa tratada como texto. Sempre que ele aparecer, o diagnóstico é o mesmo: falta await ou falta {#await}. O mesmo acontece com qualquer função que devolve promessa, não só com tick.

Resumo

  • Mudar o estado não muda o HTML no mesmo instante: o Svelte agrupa e desenha no passo seguinte.
  • tick() devolve uma promessa que resolve quando o desenho pendente termina.
  • Use await tick() dentro de uma função async.
  • Os três casos clássicos: medir, focar e rolar até um elemento que acabou de aparecer.
  • tick não é espera de tempo; é espera de passo.
  • flushSync(fn) desenha na hora, ao custo de perder o agrupamento.
  • $effect roda depois do desenho; $derived calcula durante o desenho.
  • await fora de função async é erro de compilação.
  • [object Promise] na tela significa promessa tratada como texto.
  • O mesmo HTML inicial pode esconder um erro de ordem: só o clique revela.
