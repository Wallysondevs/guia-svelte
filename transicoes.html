Svelte · Transições

A porta da padaria da Ana não abre num estalo: ela tem um amortecedor que leva meio segundo, e é por isso que ninguém leva a porta na cara. Um aviso na tela merece o mesmo cuidado. Quando ele aparece de repente, o leitor se assusta; quando some de repente, ele acha que perdeu alguma coisa. O Svelte chama esse amortecedor de transição, e ele se escreve com uma palavra antes do nome da animação.

1. A ideia: a porta com amortecedor

Uma transição é uma animação curta que roda quando um elemento entra ou sai da tela. Ela não muda o conteúdo nem o layout no fim: quando a animação termina, o elemento está exatamente onde estaria sem ela. O que muda é o caminho — a opacidade subindo, o elemento descendo alguns pixels, a altura crescendo.

Isso importa porque o olho humano precisa de continuidade. Quando algo aparece do nada, o cérebro procura a causa e perde o fio do que estava lendo. Meio segundo de fade resolve: o elemento "chega", e a leitura continua de onde estava. É o mesmo motivo do amortecedor na porta.

O Svelte dá três diretivas para isso, e a diferença entre elas é só quando a animação roda. transition: vale para os dois sentidos; in: só para a entrada; out: só para a saída. Você pode usar in: e out: juntos com animações diferentes, mas não pode misturar transition: com nenhum dos dois.

Um detalhe que confunde no começo: no servidor, nenhuma transição roda. O HTML que sai do compilador é o mesmo com ou sem transição — o elemento aparece pronto. A animação é coisa do navegador, e é por isso que as saídas desta aula mostram o conteúdo final.

3. transition:fade: a primeira transição

O elemento precisa ser criado ou destruído por um bloco para a transição ter o que animar. Na prática isso quer dizer: dentro de um {#if}, de um {#each} ou de um {#await}. Um parágrafo fixo no HTML não tem entrada nem saída — ele simplesmente está lá.

<script>
  import { fade } from 'svelte/transition';

  let visivel = $state(true);
</script>

{#if visivel}
  <p transition:fade>Pão quentinho</p>
{/if}
<button onclick={() => visivel = !visivel}>trocar</button>
<p>Pão quentinho</p> <button>trocar</button>
import { fade } from 'svelte/transition'
as transições de fábrica vêm de svelte/transition, um módulo separado. Sem o import, o nome não existe.
transition:fade
a diretiva. Ela vale para a entrada e para a saída do elemento, com os mesmos parâmetros nos dois sentidos.
{#if visivel}
o bloco que cria e destrói. É a mudança de visivel que dá ao Svelte um momento de entrada e outro de saída.
o parágrafo na saída
o HTML gerado não guarda sinal da transição: no servidor, o elemento sai pronto, sem animação.

No navegador, o clique em "trocar" não remove o parágrafo na hora: ele começa a ficar transparente e só é removido quando a animação termina. Esse intervalo é observável — e é a base das metas das caixas desta aula.

A transição não é um estado

Ela não fica guardada em nenhuma variável e não atrasa o seu código: o visivel já vale false no primeiro milissegundo. Quem espera é só o DOM, que segura o elemento antigo enquanto ele desaparece.

Missão: o parágrafo some no mesmo instante do clique, sem animação nenhuma. Importe fade de svelte/transition e ponha transition:fade={{ duration: 400 }} no parágrafo, para oi ainda estar na tela um instante depois do clique.

<script>
  let visivel = $state(true);
</script>

{#if visivel}<p>oi</p>{/if}
<button onclick={() => visivel = !visivel}>trocar</button>
<script>
  import { fade } from 'svelte/transition';

  let visivel = $state(true);
</script>

{#if visivel}<p transition:fade={{ duration: 400 }}>oi</p>{/if}
<button onclick={() => visivel = !visivel}>trocar</button>

A verificação espera 100 milissegundos e confere que o texto ainda está lá, depois espera mais e confere que sumiu. Sem a diretiva, o texto já teria desaparecido na primeira conferência.

4. in:, out: e os parâmetros

Quando a entrada e a saída precisam ser diferentes, use as duas diretivas separadas. Cada uma recebe os seus parâmetros, num objeto entre chaves duplas:

<script>
  import { fly } from 'svelte/transition';

  let visivel = $state(true);
</script>

{#if visivel}
  <p in:fly={{ y: 20, duration: 300 }} out:fly={{ y: -20 }}>Aviso do dia</p>
{/if}
<button onclick={() => visivel = !visivel}>trocar</button>
<p>Aviso do dia</p> <button>trocar</button>

O fly desloca o elemento no eixo que você escolher: y: 20 quer dizer "comece vinte pixels abaixo" na entrada e "termine vinte pixels abaixo" na saída. O duration é o tempo em milissegundos; o padrão da biblioteca é 400. Sem out:fly, a saída usaria o padrão do in: — e no caso de in: e out: diferentes, o Svelte usa exatamente o que você escreveu em cada um.

TransiçãoO que fazParâmetros úteis
fadeopacidade de 0 a 1duration, delay
flydesloca e aparecex, y, duration, opacity
slideabre e fecha a alturaduration, axis
scalecresce de um pontostart, duration, opacity
blurdesfoque e opacidadeamount, duration
drawdesenha o traço de um SVGduration, speed

O delay também é parâmetro de todas: ele adia o começo da animação, sem mexer na duração. Servir para entrada em cascata numa lista — cada item com um delay um pouco maior que o anterior. O limite é o bom senso: atraso de mais de 300 milissegundos já parece travamento, e a pessoa clica de novo antes de o primeiro item aparecer.

Todas aceitam easing: uma função que muda a velocidade ao longo do tempo. A biblioteca svelte/easing tem dezenas prontas — cubicOut começa rápido e freia, bounceOut quica no fim. O padrão é uma curva suave o suficiente para quase tudo.

5. Uma transição escrita à mão

A transição de fábrica é conveniência, não requisito. Uma transição é uma função que recebe o elemento e os parâmetros e devolve um objeto com duration e css. O Svelte chama a função css a cada quadro, com um número de 0 a 1, e aplica o que ela devolver como estilo:

<script>
  function minha(node, { duracao = 500 } = {}) {
    return { duration: duracao, css: (t) => `opacity: ${t}` };
  }
  let v = $state(true);
</script>

{#if v}<p transition:minha={{ duracao: 200 }}>oi</p>{/if}
<button onclick={() => (v = !v)}>trocar</button>
<p>oi</p> <button>trocar</button>
function minha(node, params)
a função da transição. node é o elemento; params é o objeto que você passou depois do =.
{ duracao = 500 } = {}
parâmetros com valor padrão. O = {} protege o caso em que ninguém passa nada.
return { duration, css }
o contrato. duration em milissegundos; css devolve o estilo de cada quadro.
(t) => `opacity: ${t}`
t vai de 0 (sumido) a 1 (inteiro) na entrada, e o contrário na saída.

Essa é a peça que permite entender o resto: o fade de fábrica faz exatamente isso, com uma curva de opacidade e os parâmetros que você passa. Escrever a sua continua valendo para o efeito que a biblioteca não tem — e a caixa da seção 3 importa svelte/transition de verdade, o mesmo módulo que o projeto da Ana importa.

6. Duração: o tempo é o assunto

A transição mais bonita do mundo não conserta um tempo ruim. Curto demais e ninguém vê; longo demais e a tela parece travada. A faixa que funciona na maioria dos casos fica entre 150 e 400 milissegundos para elementos pequenos e até 600 para blocos grandes.

Missão: a transição existe, mas dura 40 milissegundos e o parágrafo some antes de alguém perceber. Faça a saída durar 400 milissegundos, sem trocar de transição.

<script>
  import { fade } from 'svelte/transition';

  let visivel = $state(true);
</script>

{#if visivel}<p transition:fade={{ duration: 40 }}>oi</p>{/if}
<button onclick={() => visivel = !visivel}>trocar</button>
<script>
  import { fade } from 'svelte/transition';

  let visivel = $state(true);
</script>

{#if visivel}<p transition:fade={{ duration: 400 }}>oi</p>{/if}
<button onclick={() => visivel = !visivel}>trocar</button>

Repare que a solução não troca de transição: muda só o número. O fade continua o mesmo, e o {{ duration: 400 }} decide quanto tempo ele leva. É assim que se reaproveita uma transição em lugares com tempos diferentes — cada uso decide o seu.

Respeite quem pediu menos animação

Existe gente que sente desconforto com movimento na tela, e o sistema operacional tem uma opção para reduzir animações. Uma transição curta e discreta é aceitável; uma explosão de movimento não. Se o seu projeto se importa com isso, a consulta a prefers-reduced-motion é o caminho — e o tema é de acessibilidade, com aula própria mais adiante.

7. Transições em listas

Dentro de um {#each}, cada item tem a sua própria entrada e saída. Quando a lista muda, só os itens que entram e saem animam; os que ficam não são recriados:

<script>
  import { fade } from 'svelte/transition';

  let itens = $state(['pão', 'bolo']);
</script>

{#each itens as item (item)}
  <p transition:fade>{item}</p>
{/each}
<button onclick={() => (itens = itens.filter((i) => i !== 'bolo'))}>tirar bolo</button>
<p>pão</p><p>bolo</p> <button>tirar bolo</button>

A chave (item) é o que permite ao Svelte saber qual item é qual. Sem ela, mudar a ordem da lista faz o Svelte reaproveitar os elementos na posição errada, e a transição anima o texto errado. Com chave, cada item é uma identidade — e animações de lista só fazem sentido assim.

Missão: ao tirar o bolo, o parágrafo dele desaparece num piscar. Faça os itens da lista saírem com transition:fade={{ duration: 400 }}, para o bolo ainda estar na tela um instante depois do clique.

<script>
  let itens = $state(['pão', 'bolo']);
</script>

{#each itens as item (item)}
  <p>{item}</p>
{/each}
<button onclick={() => itens = itens.filter((i) => i !== 'bolo')}>tirar bolo</button>
<script>
  import { fade } from 'svelte/transition';

  let itens = $state(['pão', 'bolo']);
</script>

{#each itens as item (item)}
  <p transition:fade={{ duration: 400 }}>{item}</p>
{/each}
<button onclick={() => itens = itens.filter((i) => i !== 'bolo')}>tirar bolo</button>

O efeito é o mesmo do {#if}, aplicado por item: o elemento que sai continua no DOM até a animação acabar, e o que fica não é tocado. É por isso que listas com transição parecem mais suaves do que listas que mudam de uma vez.

8. O que a saída ainda não mostra

Vale repetir porque é a fonte de metade das dúvidas: no servidor não há transição. O HTML que o compilador gera é idêntico ao de um componente sem diretiva nenhuma. Toda a animação acontece depois, no navegador, quando o JavaScript assume o controle.

Isso tem uma consequência prática para quem vai publicar: a página aparece pronta para quem tem JavaScript desligado ou para um robô de busca, e a transição é um enfeite que só quem vê a página animada aproveita. Nada do conteúdo depende dela — e é assim que deve ser.

Há um terceiro efeito, menos óbvio: como a animação segura o elemento antigo no DOM, dois elementos com o mesmo texto podem coexistir por alguns milissegundos durante a troca. Se o seu código procura um elemento por texto ou conta quantos existem, essa sobreposição aparece como um número a mais. É passageiro, mas é real — e é o tipo de coisa que só se descobre olhando o DOM durante a animação.

Também explica por que os testes automatizados de transição são chatos: você precisa esperar o tempo passar. Nas caixas desta aula, esse tempo é dado pelo passo depois:, que espera os milissegundos pedidos antes de conferir o texto.

9. Quando dá errado

As três mensagens abaixo são do compilador desta versão, copiadas da execução. Todas acontecem antes de a página abrir.

Erro 1 — transição num componente

Diretivas de transição valem para elementos do DOM, não para componentes. Um componente pode desenhar dez elementos; o Svelte não saberia qual animar:

<script>
  import Cartao from './Cartao.svelte';
</script>

<Cartao transition:fade />
Erro de compilação (linha 5, coluna 8): This type of directive is not valid on components

"Este tipo de diretiva não é válido em componentes." A correção é mover a diretiva para dentro do componente, no elemento que deve animar — ou envolver o componente num elemento e animar o elemento.

Erro 2 — transition: junto com in:

transition: já significa "entrada e saída". Misturar com uma das duas metades é ambíguo, e o compilador recusa:

<script>
  import { fade } from 'svelte/transition';
  import { fly } from 'svelte/transition';

  let v = $state(true);
</script>

{#if v}<p transition:fade in:fly>x</p>{/if}
Erro de compilação (linha 8, coluna 26): Cannot use `transition:` alongside existing `in:` directive

"Não é possível usar transition: junto com uma diretiva in: existente." Escolha um dos dois estilos: ou transition:, ou o par in: e out:.

Erro 3 — duas transições no mesmo elemento

Cada elemento tem uma transição de entrada e uma de saída. Declarar transition: duas vezes não é "somar animações": é erro:

<script>
  import { fade, fly } from 'svelte/transition';
</script>

<p transition:fade transition:fly>oi</p>
Erro de compilação (linha 5, coluna 19): Cannot use multiple `transition:` directives on a single element

"Não é possível usar múltiplas diretivas transition: num único elemento." Se você quer combinar efeitos, escreva uma transição própria que devolva os dois estilos no mesmo css — é uma linha de css a mais, não uma diretiva a mais.

10. Transição, animação e {#key}

Três coisas parecidas, três papéis diferentes. Confundir uma com a outra é o segundo motivo mais comum de "a animação não funciona":

FerramentaQuando agePara que serve
transition:quando o elemento entra ou sai do DOMfade, fly, slide na entrada e na saída
animate:quando o item muda de lugar numa listareordenar sem salto (aula de animações)
{#key}quando a chave mudadestruir e recriar um bloco para a transição rodar

O {#key} merece um exemplo, porque resolve um caso teimoso: trocar o texto de um parágrafo não dispara transição nenhuma, porque o elemento não saiu nem entrou. Envolvendo o parágrafo num {#key texto}, mudar o texto destrói o bloco antigo e cria um novo — e aí a transição roda:

<script>
  import { fade } from 'svelte/transition';

  let texto = $state('Pão francês');
</script>

{#key texto}
  <p transition:fade>{texto}</p>
{/key}
<button onclick={() => (texto = 'Bolo de cenoura')}>trocar</button>
<p>Pão francês</p> <button>trocar</button>

Sem o {#key}, o texto simplesmente muda, sem animação. Com ele, o parágrafo antigo sai com fade enquanto o novo entra — o efeito de "troca de cartaz" que a vitrine da Ana faz à mão.

Exercícios

1. Qual diretiva anima só a saída do elemento?

2. O que uma função de transição precisa devolver?

3. Por que a saída do servidor não mostra a transição?

Complete o código

import { fade } from '';

{#if visivel}
  <p >Pão quentinho</p>
{/if}

// a diretiva anima a entrada e a saída do parágrafo

Resumo

  • transition: anima entrada e saída; in: e out: animam uma de cada vez.
  • Só há transição quando o elemento entra ou sai do DOM: dentro de {#if}, {#each} ou {#key}.
  • As transições de fábrica vêm de svelte/transition: fade, fly, slide, scale, blur, draw.
  • Parâmetros vão num objeto: transition:fade={{ duration: 300, delay: 100 }}.
  • duration é em milissegundos; entre 150 e 400 funciona para a maioria dos casos.
  • Uma transição é uma função que devolve { duration, css }; css(t) roda a cada quadro com t de 0 a 1.
  • No servidor não há animação: o HTML sai pronto, com ou sem transição.
  • Listas com transição precisam de chave no {#each}.
  • {#key} força a troca de elemento quando só o texto muda.
  • Os erros desta aula: diretiva em componente, transition: com in: e duas transition: no mesmo elemento.
