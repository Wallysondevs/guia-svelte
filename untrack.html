Svelte · untrack()

A Ana tem um caderno com os preços do mês passado. Ela consulta o caderno para comparar, mas não quer que a consulta vire uma promessa de trabalho: olhar o preço antigo não deve fazer ninguém refazer a conta. Dentro de um $effect acontece algo parecido. Tudo o que o efeito lê vira dependência, inclusive coisas que só estavam ali para serem mostradas. untrack é a função que diz "leia este valor, mas não fique de olho nele".

  • Como contar quantas vezes um efeito rodou sem criar dependência no contador.

1. A ideia: consultar sem acordar o fornecedor

Na padaria, a Ana tem dois cadernos. O caderno do dia é o que ela usa para trabalhar: quando alguém anota um pedido ali, a cozinha precisa saber. O caderno do mês passado é só consulta: ela abre, compara, fecha, e ninguém na cozinha é avisado. Os dois são cadernos de papel, com a mesma letra e a mesma caneta, mas o efeito de abrir um é diferente do efeito de abrir o outro.

Um $effect funciona assim: ele anota, em segredo, cada variável de estado que lê durante a execução. Essas variáveis viram dependências — o efeito promete rodar de novo quando qualquer uma delas mudar. Isso é o que faz a reatividade funcionar: o efeito sabe exatamente do que depende, sem você declarar uma lista.

O problema aparece quando o efeito lê algo que não deveria ser motivo para rodar de novo. Dois casos típicos. No primeiro, o efeito escreve numa variável que ele também lê: cada execução muda o valor, o valor mudado pede outra execução, e o ciclo não termina. No segundo, o efeito precisa consultar um valor só para montar uma mensagem, mas a mudança desse valor não deveria provocar trabalho nenhum.

untrack resolve os dois. Ele recebe uma função, executa essa função com o "radar" de dependências desligado e devolve o resultado. Tudo o que for lido lá dentro não vira dependência; tudo o que for lido fora continua valendo. É o caderno do mês passado: você consulta, fecha, e a cozinha nem fica sabendo.

Existe uma segunda imagem que ajuda: a agenda de contatos. Quando a Ana abre a agenda para procurar o telefone do padeiro, ninguém liga para ninguém — mas se ela abrisse a agenda e, ao mesmo tempo, prometesse retornar todas as ligações que aparecessem ali, o dia estaria perdido. A leitura é a mesma; a promessa é que muda. Um efeito registra as leituras e assume o compromisso de rodar de novo quando qualquer uma delas mudar. untrack existe para que você escolha quais leituras entram nesse compromisso.

Guardar essa distinção também evita um mal-entendido comum: reatividade não é "atualizar sempre que qualquer coisa muda". É "atualizar quando a dependência declarada muda". Um componente com dez efeitos e vinte variáveis tem, no máximo, a lista de dependências de cada efeito — não uma varredura da página inteira a cada mudança. É por isso que o Svelte consegue ser preciso e rápido ao mesmo tempo.

2. Toda leitura dentro do efeito conta

O componente abaixo conta quantas vezes o efeito rodou. O contador é uma variável de tela, e a leitura dele está protegida: sem essa proteção, o efeito se veria mudando o próprio contador e rodaria para sempre.

<script>
  import { untrack } from 'svelte';

  let nome = $state('Ana');
  let rodadas = $state(0);

  $effect(() => {
    const n = nome;
    rodadas = untrack(() => rodadas) + 1;
  });
</script>

<p>Olá, {nome} — rodadas: {rodadas}</p>
Olá, Ana — rodadas: 0

O texto mostra rodadas: 0 porque efeitos não rodam na renderização fora do navegador. No navegador, a primeira execução do efeito acontece logo depois da montagem e o número vira 1; a cada troca de nome, vira 2, 3, e assim por diante. O contador reflete o trabalho, e não provoca trabalho.

A anatomia do untrack

import { untrack } from 'svelte'
vem da biblioteca, junto de onMount e tick. Não é runa: não começa com cifrão e não precisa de posição especial no arquivo.
untrack(fn)
recebe uma função de zero argumentos, executa e devolve o que ela devolver. Durante a execução, nenhuma leitura é registrada como dependência.
() => rodadas
a leitura protegida. Só o que está dentro desta função fica fora do radar; nome, lido fora dela, continua sendo dependência.
rodadas = … + 1
a escrita continua normal. untrack protege a leitura, não a atribuição: quem lê rodadas na tela continua sendo avisado.

Repare no que untrack não faz: ele não impede que a variável mude, não congela valor para sempre e não desliga a reatividade do componente. Ele só decide o que entra na lista de dependências daquele efeito, naquela execução. A tela continua acompanhando rodadas, porque o parágrafo lê a variável normalmente.

3. O ciclo que não termina

Sem a proteção, o efeito escreve e lê a mesma variável. O Svelte detecta o laço e interrompe com um erro. O componente abaixo é a versão sem untrack:

<script>
  let n = $state(0);

  $effect(() => {
    n = n + 1;
  });
</script>

<p>{n}</p>
0

Fora do navegador, a saída é inocente: 0. O erro só aparece quando o efeito roda de verdade. No navegador, o console mostra Uncaught Error: https://svelte.dev/e/effect_update_depth_exceeded — o nome do erro, effect update depth exceeded, é a descrição exata do problema: a profundidade de atualizações do efeito passou do limite.

Vale entender por que o Svelte não tenta "resolver" isso sozinho. Um efeito que muda o próprio valor não tem solução geral: qualquer número de repetições é plausível, e o resultado seria imprevisível. O limite existe para transformar um travamento da página num erro legível, que aponta o componente e a linha.

Há três saídas possíveis, e escolher a certa é a parte importante:

SituaçãoSaídaPor quê
o efeito precisa contar as próprias execuçõesuntrack na leitura do contadoro contador é registro, não gatilho
o valor pode ser calculado a partir de outros$derivednão há efeito colateral, nada a repetir
o efeito está escrevendo no que deveria só lerrepensar o desenhountrack esconderia o problema

A terceira linha é a mais comum e a mais ignorada. Muitos ciclos não são falta de untrack: são um efeito fazendo o trabalho de um $derived. Se o valor pode ser calculado, calcule; efeito é para o que sai do componente — rede, armazenamento, foco, log.

4. Experimente: o contador que quebra o efeito

A caixa abaixo reproduz o ciclo. O botão deveria trocar o nome e somar uma rodada, mas o componente nem chega a montar.

Missão: o efeito quebra com effect update depth exceeded ao ler o contador que ele mesmo escreve. Faça ele montar e mostrar rodadas: 2 depois de um clique.

<script>
  let nome = $state('Ana');
  let rodadas = $state(0);

  $effect(() => {
    const n = nome;
    rodadas = rodadas + 1;
  });
</script>

<button onclick={() => (nome = nome === 'Ana' ? 'Bia' : 'Ana')}>trocar nome</button>
<p>Olá, {nome} — rodadas: {rodadas}</p>
<script>
  import { untrack } from 'svelte';

  let nome = $state('Ana');
  let rodadas = $state(0);

  $effect(() => {
    const n = nome;
    rodadas = untrack(() => rodadas) + 1;
  });
</script>

<button onclick={() => (nome = nome === 'Ana' ? 'Bia' : 'Ana')}>trocar nome</button>
<p>Olá, {nome} — rodadas: {rodadas}</p>

O resultado esperado é rodadas: 2 depois de um clique: uma execução na montagem e outra na troca de nome. Se aparecer 3, alguma outra leitura entrou na lista; se aparecer 1, o efeito não está reagindo ao nome.

5. Experimente: histórico sem gatilho

O segundo uso de untrack é o histórico. O efeito registra cada troca de nome, mas lê um "modo" que só serve para a mensagem. Sem a proteção, trocar o modo também acrescenta uma linha no histórico — e o registro deixa de significar "trocas de nome".

Missão: clique em trocar nome duas vezes e depois em trocar modo. O histórico deve ter só as trocas de nome: Ana · Bia · Ana.

<script>
  let nome = $state('Ana');
  let modo = $state('curto');
  let log = [];
  let naTela = $state('');

  $effect(() => {
    const n = nome;
    const m = modo;
    log.push(n);
    naTela = log.join(' · ');
  });
</script>

<button onclick={() => (nome = nome === 'Ana' ? 'Bia' : 'Ana')}>trocar nome</button>
<button id="modo" onclick={() => (modo = modo === 'curto' ? 'longo' : 'curto')}>trocar modo: {modo}</button>
<p>registros: {naTela}</p>
<script>
  import { untrack } from 'svelte';

  let nome = $state('Ana');
  let modo = $state('curto');
  let log = [];
  let naTela = $state('');

  $effect(() => {
    const n = nome;
    const m = untrack(() => modo);
    log.push(n);
    naTela = log.join(' · ');
  });
</script>

<button onclick={() => (nome = nome === 'Ana' ? 'Bia' : 'Ana')}>trocar nome</button>
<button id="modo" onclick={() => (modo = modo === 'curto' ? 'longo' : 'curto')}>trocar modo: {modo}</button>
<p>registros: {naTela}</p>

O detalhe que faz esse exemplo funcionar é o log ser uma variável comum, e não $state. Se ele fosse reativo, a leitura de log dentro do efeito criaria outra dependência e o histórico voltaria a se repetir. A tela lê naTela, que é $state e é escrita — nunca lida — dentro do efeito, então não gera ciclo.

É um padrão útil e um pouco chato de ler. Sempre que ele aparecer, vale perguntar se o histórico não deveria viver num store ou num módulo compartilhado, com o efeito só empurrando dados para lá. O guia tem aulas sobre isso adiante.

6. O custo: valor congelado

untrack desliga o radar. Usar no lugar errado produz um valor que nunca mais se atualiza, e o sintoma é pior que o ciclo: não há mensagem, só um número parado. O componente abaixo calcula uma soma com untrack dentro do $derived.

<script>
  import { untrack } from 'svelte';

  let a = $state(1);
  let b = $state(2);
  let soma = $derived(untrack(() => a + b));
</script>

<p>{a} + {b} = {soma}</p>
1 + 2 = 3

A saída parece certa, e é: na primeira execução, a soma é três. O problema vem depois. Quando a muda para 2, o $derived não tem dependência nenhuma — untrack escondeu a e b — então ele nunca recalcula. A tela mostra 2 + 2 = 3. Num teste rápido, ninguém nota; num relatório de vendas, é um desastre silencioso.

Missão: a soma mostra 2 + 2 = 3 depois do clique, porque o $derived está protegido demais. Faça a conta acompanhar: 2 + 2 = 4.

<script>
  import { untrack } from 'svelte';

  let a = $state(1);
  let b = $state(2);
  let soma = $derived(untrack(() => a + b));
</script>

<button onclick={() => (a++)}>somar a</button>
<p>{a} + {b} = {soma}</p>
<script>
  let a = $state(1);
  let b = $state(2);
  let soma = $derived(a + b);
</script>

<button onclick={() => (a++)}>somar a</button>
<p>{a} + {b} = {soma}</p>

A solução é remover, não acrescentar. Esse é o teste que separa uso bom de uso ruim: se o valor deve mudar quando a fonte muda, untrack está errado. Se o valor precisa apenas ser consultado naquele instante, está certo.

7. Onde untrack não é necessário

Fora de um efeito ou de um derivado, nada é rastreado. Um onclick pode ler quantas variáveis quiser: o clique já aconteceu, e não há lista de dependências a manter. O mesmo vale para o corpo de uma função auxiliar chamada de dentro de um evento.

<script>
  let a = $state(1);
  let b = $state(2);
  let soma = $state(0);

  function calcular() {
    soma = a + b;
  }
</script>

<button onclick={calcular}>calcular</button>
<p>{soma}</p>
<button>calcular</button> <p>0</p>

Não há untrack aqui, e não deve haver: dentro do evento, ler a e b é exatamente o que se espera. Colocar untrack em código de evento é ruído — não muda o comportamento e faz o leitor procurar um problema que não existe.

No template, o rastreamento é ainda mais direto: cada {valor} é uma leitura acompanhada. Se você proteger um valor que aparece na tela, o texto desenha uma vez e não muda mais — o mesmo congelamento da seção 6, só que no HTML em vez do script. O template não tem "gatilho" nem "consulta": tudo o que ele mostra é, por definição, algo que a tela precisa acompanhar.

A regra prática: só existe dependência dentro de $effect, $derived e do template. Em template, aliás, o rastreamento é o que faz a tela acompanhar; proteger leituras ali costuma ser um erro. Use untrack na dúvida entre "isto é gatilho" e "isto é consulta", e prefira resolver o desenho quando o efeito estiver escrevendo no que só deveria ler.

9. Quando dá errado

As três mensagens abaixo saíram da execução real dos componentes quebrados, copiadas como estão.

Erro 1 — untrack() sem a função

O untrack espera uma função para executar. Sem argumento, ele tenta chamar undefined.

<script>
  import { untrack } from 'svelte';

  let n = $state(1);
  const valor = untrack();
</script>

<p>{valor}</p>
Erro ao renderizar: fn is not a function

"fn is not a function" é a mensagem interna do Svelte: fn é o nome do parâmetro que ele esperava. A correção é passar () => n, e não n: o valor é lido dentro da função, para o radar ser desligado no momento certo.

Erro 2 — untrack sem import

Como onMount e tick, untrack não é palavra da linguagem: é função importada.

<script>
  let n = $state(1);
  const valor = untrack(() => n);
</script>

<p>{valor}</p>
Erro ao renderizar: untrack is not defined

A mensagem "… is not defined" com um nome do Svelte é quase sempre import faltando. Confira a lista do topo do <script>.

Erro 3 — importar do módulo errado

O Svelte tem vários submódulos, e svelte/reactivity não exporta untrack. O código compila e quebra ao carregar o módulo.

<script>
  import { untrack } from 'svelte/reactivity';

  let n = $state(1);
  const valor = untrack(() => n);
</script>

<p>{valor}</p>
Erro ao renderizar: The requested module 'svelte/reactivity' does not provide an export named 'untrack'

A mensagem diz exatamente o que falta: aquele módulo não tem esse nome. untrack, onMount, tick e createEventDispatcher vêm todos de 'svelte', sem barra e sem sufixo.

Resumo

  • Dentro de $effect, $derived e do template, toda leitura de estado vira dependência.
  • Um efeito que lê o que escreve entra em ciclo e o Svelte aborta com effect_update_depth_exceeded.
  • untrack(fn) executa a função sem registrar leituras e devolve o resultado.
  • untrack protege a leitura, não a escrita: a tela continua acompanhando o valor.
  • Fora de efeito e derivado não há rastreamento; untrack em evento é ruído.
  • Usar untrack no lugar errado congela o valor sem nenhuma mensagem.
  • Contar execuções de efeito é um uso legítimo: o contador é registro, não gatilho.
  • Histórico em variável comum, espelho em $state, evita ciclo e mantém a tela viva.
  • Efeitos não rodam na renderização fora do navegador: a saída do servidor mostra o valor inicial.
  • Os erros desta aula: untrack() sem função, import ausente e import do módulo errado.
